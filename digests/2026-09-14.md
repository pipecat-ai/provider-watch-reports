# Provider watch — 2026-09-14

- Two dated deadlines need a decision now: `perplexity/llm`'s Sonar Chat Completions endpoint retires 2026-09-27 with no mechanical interim fix — reparenting onto the Agent/Responses surface changes the base class, the `Settings` shape and the model slugs (`reports/perplexity/llm/2026-09-14.md`) — and `aws/realtime`'s first-generation `amazon.nova-sonic-v1:0` reaches Bedrock EOL today while the service still carries the `ready.wav` trigger path and documents the model in its constructor and examples.
- Four services fail on their shipped defaults, and each needs a call rather than a patch: `openai/llm` (`temperature` and `max_tokens` draw a 400 from every current model, after which the service is marked unusable), `google/image` (default `imagen-4.0-generate-001` was retired 2026-08-17 and every request 404s; the replacement is only reachable through `generate_content`, which drops `number_of_images` and `negative_prompt`), `heygen/video` (default `INTERACTIVE_AVATAR`'s `/v1/streaming.*` endpoints 404), and `azure/image` (still calls the retired `images/generations:submit` preview endpoint).
- `speechmatics/stt` cannot transcribe at all: `StartRecognition` against `/v2/agent` is rejected with a schema validation error on both eu2 and global, and reproduces with `speechmatics-agent-stt` 0.1.0 and its own default config, no Pipecat involved. Server-side, so it needs Speechmatics rather than a Pipecat change.
- A cluster of STT services accept settings that silently do nothing or break the session, and these are self-contained fixes: `gladia/stt` and `together/stt` never send `Settings.language`, `nvidia/stt` never applies its locale map so `Language.EN` is rejected, `deepgram/stt`'s `extra`/`addons` keys kill the connection and leave `filler_words` and `measurements` unreachable, and documented auto-detect yields no transcript on `fal/stt` and an `ErrorFrame` per utterance on `groq/stt`.
- Eight units had no live probe, so their findings rest on docs and source alone: `BLAND_API_KEY`, `GRADIUM_API_KEY` and `META_API_KEY` are unset, `CAMB_API_KEY` and `CRUSOE_API_KEY` are rejected with 401, `AZURE_REALTIME_BASE_URL` does not resolve and is still in the retired preview URL form, and Neuphonic answered HTTP 500 to every synthesis request on both its WebSocket and SSE paths.

The same branch swallows the undocumented `init_ack`, which logs `Ignoring message from unavailable context: <uuid>` on every healthy connect. — *needs a call: whether an `error_code` frame should push an ErrorFrame and close the context, or only be logged*
- [aws/other](https://github.com/pipecat-ai/provider-watch-reports/blob/main/reports/aws/other/2026-09-14.md) — `invoke_agent_runtime` is called without `runtimeSessionId`, so turns are not pinned to one AgentCore session (since 2026-08-31, 2 weeks) — AWS makes `runtimeSessionId` (the `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` header) the mechanism for maintaining context across requests and recommends a UUID; without a consistent ID each request may land on a new microVM with cold-start latency. The default payload transformer sends only the latest user message, so with no session ID the agent has neither Pipecat-side history nor AgentCore-side continuity. The request header is min 33 / max 256 characters; the response carries the session ID back in the same header, so an echo-back scheme is possible too, but the processor reads neither. — *needs a call: Where the ID comes from — a constructor argument, one generated per conversation, or the ID echoed from the first response — and whether teardown should call StopRuntimeSession.*
