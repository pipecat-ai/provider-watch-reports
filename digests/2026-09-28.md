# Provider watch — 2026-09-28

- `speechmatics/stt` is the worst unit of the date: three separate ways to a permanently dead session, none of them a patch. `punctuation_overrides` — documented on docs.pipecat.ai as a working setting — is rejected by the Agent STT schema as a `protocol_error`, which the service classes as permanent; any pipeline that is not 16 kHz is rejected outright with no resampling path (pipecat-ai/pipecat#5717, open 2 weeks), so telephony cannot connect; and `Settings(turn_detection_mode="vad")` raises `AttributeError` while processing StartFrame because the dataclass coerces nothing. On the brighter side, the long-standing regional split finally moved — `global`, `eu`, `us` and `au` all now transcribe end to end on `/agent`, so the undocumented `eu2` default is now a routing choice rather than the only host that works (`reports/speechmatics/stt/2026-09-28.md`).
- Three more services fail on a configuration their own docs recommend. `speechmatics/tts` builds `output_format=pcm_{sample_rate}` while the API serves only 16 kHz, so the default "adopt the pipeline rate" gets `Service unavailable [422]` and no audio at the common 24 kHz. `xai/realtime`'s `AudioOutput(speed=1.2)` — the documented way to slow the bot down — leaves `format=None`, which `_ensure_audio_config` never backfills, so the service raises on every assistant audio delta. And `simli/video` turns a transient P2P connect failure into a missing-dependency error, because simli-ai's retry switches to the LiveKit transport that `pipecat-ai[simli]` does not install.
- `together/llm`'s shipped default reasons before every answer: on a scheduling prompt `zai-org/GLM-5.2` spent 8770-27475 ms before its first answer token and one of three turns blew the 30 s timeout, against 239-615 ms and 3/3 clean with `reasoning={"enabled": false}`. pipecat-ai/pipecat#5939 exposes the toggle; whether the default should follow `DeepSeekLLMService` and ship reasoning off is the call that actually fixes voice latency here (`reports/together/llm/2026-09-28.md`).
- A cluster of settings are accepted and then quietly do nothing, which is worse than an error. `aws/stt` logs "Converting from 24000 Hz to 16000 Hz" and declares 16000 in the presigned URL while forwarding the bytes untouched — the docs page repeats the claim, and the clamp is not even needed, since 24000 and 48000 were both accepted. `together/stt` never sends `Settings.language`, and its interim path is unreachable twice over (the delta handler reads `transcript` where the event carries `delta`, under a hard-coded `turn_detection=none` that emits no deltas at all) although docs.pipecat.ai advertises interim results. `xai/realtime`'s `SessionResumption.enabled` caches turns server-side that nothing ever replays. `aws/other` omits `runtimeSessionId` on every `invoke_agent_runtime`, so an AgentCore agent has neither Pipecat-side history nor provider-side continuity.
- 16 PRs are open across the date, 10 of them raised on this run and most of them one-field pass-throughs. Review the two that fix real breakage first — pipecat-ai/pipecat#5581 (Together TTS odd-length audio frames, which also takes down the shared `detect_speech_onset` scanner) and #5940 (escaping the voice in the Together TTS WebSocket URL) — then the two default bumps that change behavior for everyone, #5933 (AssemblyAI to `universal-3-6-pro`) and #5935 (documenting only Nova 2 Sonic, whose first-generation code path is now unreachable since Bedrock rejects the only model that selects it). `aws/stt`'s #2849 is still a community PR untouched since 2025-10-16.
