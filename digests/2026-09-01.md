## Changes to consider

**High**

- [asyncai/tts](https://github.com/pipecat-ai/provider-watch-reports/blob/main/reports/asyncai/tts/2026-09-01.md) — Server error frames are dropped by the websocket receive loop — Async's documented error frame is `{error_code, message, extra}` with no `context_id`. `_receive_messages` handles only `final` and `audio`, so the frame falls through the context check, is logged as `Ignoring message from unavailable context: None` and nothing is pushed upstream: the turn yields no audio and the app sees no error. The same branch swallows the undocumented `init_ack` the server sends after init — harmless, but it logs an unavailable-context line on every connect (observed again this run through the real class). — *needs a call: whether an `error_code` frame should push an ErrorFrame and close the context, or only be logged*
- [aws/other](https://github.com/pipecat-ai/provider-watch-reports/blob/main/reports/aws/other/2026-09-01.md) — `invoke_agent_runtime` is called without `runtimeSessionId`, so turns are not pinned to one AgentCore session — AWS: "By providing the same session identifier across multiple requests, you can maintain conversation context, allowing the agent to reference previous interactions", and without a consistent ID each request may be routed to a new microVM with cold-start latency.
