# Provider watch — 2026-11-09

- Four dated deadlines land between 2026-11-17 and 2026-12-01, two of them on a shipped default. `google/tts`'s `gemini-3.1-flash-tts-preview` shuts down on the Gemini API on 2026-11-17, eight days out, and Cloud Text-to-Speech serves no Gemini 3.8 model at all, so #6643 makes the default follow the backend — the one PR this run with a hard date behind it (`reports/google/tts/2026-11-09.md`). `smallest/tts` carries two: `lightning_v3.1` retires 2026-11-30 and `sophia`, the default voice of the `LIGHTNING_V3_1` enum member, exists only in the retiring catalogue, while on 2026-11-28 the Pro checkpoint promoted to `lightning_v3.1_pro` — the service's own default configuration for en/es/hi — stops emitting word timestamps for `meher` (`reports/smallest/tts/2026-11-09.md`). Then on 2026-12-01 `gemini-2.5-flash` and `gemini-2.5-pro` start being served by Gemini 3 models while `_THINKING_DEFAULTS` keeps sending those names a `thinking_budget` the new family may ignore or reject (`reports/google/llm/2026-11-09.md`).
- The `google/vertex-llm` default bump is now three consecutive runs of the same regression, and the reason given for it still does not exist. `gemini-3.8-flash` measures TTFAT 2782 ms against 724 ms for `gemini-3.6-flash` on a reasoning prompt (medians of 5, `thinking_ms` 0 throughout), and the fifth run produced no further chunk and tripped the 20 s `stream_idle_timeout_secs` with `LLM completion timeout` — a shipped default that intermittently never answers. Google's deprecations page still lists `gemini-3.6-flash` with no shutdown date, `gemini-3.7-flash` is no faster on Vertex, and `google/llm` still defaults to 3.6, so the two units disagree. `google/interactions-vertex-llm` splits the same way (1072 ms against 699 ms): both Vertex classes ship 3.8, both Gemini API classes ship 3.6 (`reports/google/vertex-llm/2026-11-09.md`).
- Several services still fail on configurations the providers' own pages hand you, none of them new this run. `speechmatics/stt` has both six-week-old routes to a permanently dead session — `punctuation_overrides` is rejected as a `protocol_error`, and `Settings(turn_detection_mode="vad")` raises `AttributeError` while processing StartFrame, which is the form Speechmatics' own Pipecat page passes. `speechmatics/tts` 422s every request with no audio when the caller passes `sample_rate=None` to adopt the pipeline rate, after only a warning at construction. `smallest/stt` never sends `close_stream`, and for the third probe run in a row the final transcript came back truncated at the same mid-sentence point. And `google/vertex-realtime`'s `pipecat init` snippet is, nine weeks on, still the only one of 108 `SERVICE_CONFIGS` entries that fails `compile()`.
- `google-genai` 3.0.0 (2026-11-06) is outside the `<3` pin for five Google units at once, and no one owns the move. `google/realtime` probed what raising it costs: the release switches the Gemini Developer API default from v1beta to v1, where the Live connect 404s three times and then fails fatally unless the service names v1beta, and that service's deprecated `generation_config` wrapper is the real migration blocker. For the Vertex classes the v1 change does not apply and the cost is the switch to httpx2 plus the OS trust store; `google/tts` additionally serves its Extended Voice Library from `GET /v1beta/voices`. The same pin also floors at 1.68.0 on the 3.13/Linux leg for `vonage-video-connector`, so this is one coordinated change across the google extra rather than five unit-level ones.
- Six PRs were raised this run and all are new; five are Google. The one with user-visible breakage behind it is `moonshine/stt`'s #6639 — Arabic, Chinese, Japanese, Korean and Ukrainian run under Moonshine's Latin-script `max_tokens_per_second` cap of 6.5, which truncates valid output. The rest document or retarget a model: #6640 (`nebius/llm`), #6641 (`google/llm`), #6642 (`google/realtime`), #6643 (`google/tts`), #6644 (`google/vertex-realtime`). Nothing needs an owner beyond review — `smallest/stt`'s #5518 was closed unmerged on 2026-11-07 with both halves already in the code. One unit could not probe: `gradium/stt` had no `GRADIUM_API_KEY` in the run environment, so its findings are documentation-only and two of its items say so explicitly.
