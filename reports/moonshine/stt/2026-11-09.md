# Moonshine STT — 2026-11-09

Moonshine documents that Arabic, Chinese, Japanese, Korean and Ukrainian need
`max_tokens_per_second` raised to 13.0 or valid output is cut off; the service
never sets it, so those five of our ten languages run with the Latin-script
default of 6.5. Branch ready. Otherwise the unit is current: moonshine-voice
0.1.6 (2026-11-06) is bugfixes plus a requantization of the English streaming
models, the catalogue is structurally unchanged, and `small-streaming` stays the
right default.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6639 — Raise the Moonshine token-rate cap for non-Latin languages

### To consider
- **Keyterm biasing** (medium, since 2026-09-01) — `Transcriber.set_keyterms(["Kubernetes", ...])` and `set_context(passage, max_terms)` bias decoding toward domain terms between segments, with `keyterm_boost` for strength; the service calls neither. — *Needs a call: both raise `MoonshineError` on non-streaming architectures (`tiny`, `base`), so exposing them needs a stance on what happens when the configured model cannot bias.*
- **Alphanumeric spelling mode** (medium, since 2026-09-01) — `get_model_for_language` already best-effort downloads the language's `spelling_cnn.ort` on every run, but `Transcriber` is constructed without `spelling_model_path` and transcribe calls use the default `flags=0`, so the digit/letter fusion is dead weight. — *Needs a call: whether spelling fusion should be a Settings flag or on by default, and whether it costs latency on the CPU path.*
- **Streaming partials** (medium, since 2026-09-01) — `SegmentedSTTService` transcribes each VAD segment in one `transcribe_without_streaming` call; Moonshine's `add_audio` plus listener path emits interim text every `update_interval` and would cut the wait after end-of-turn. 0.1.6 adds `create_stream`/`get_default_stream` and fixes VAD state leaking between streams, so concurrent streams are now supported upstream. — *Needs a call: whether Moonshine gets a second, streaming service class alongside the segmented one.*
- **Speaker diarization** (low, since 2026-09-14) — the `identify_speakers` option plus `diarization_model_dir` from `get_diarization_model()` clusters speakers locally and fills `TranscriptLine.speaker_spans`; Deepgram and Speechmatics expose the equivalent in Pipecat, Moonshine does not. Each VAD segment is one speaker by construction, so this only pays off on multi-speaker audio. — *Needs a call: `TranscriptionFrame` cannot carry speaker spans, so surfacing them needs a stance like Speechmatics' speaker-label formatting, plus an opt-in for the 8.2 MB model download.*
- **Word timestamps** (low, since 2026-09-01) — `get_model_for_language(..., include_word_timestamps=True)` fetches the attention decoder the `word_timestamps` option needs to fill `TranscriptLine.words`; neither is requested. — *Needs a call: `TranscriptionFrame` has nowhere to carry word timings, so this needs a frame-level decision first.*
- **No Moonshine TTS service** (low, since 2026-09-01) — the same package ships on-device TTS with a voice catalog, voice cloning and a streaming synthesizer; Pipecat exposes only the STT half. — *Needs a call: whether a local Moonshine TTS service is wanted next to Kokoro.*

The licensing gap is closed: pipecat-ai/pipecat#5745 merged on 2026-09-14 and the
class docstring now says the models are MIT except the legacy non-streaming
non-English ones.

English's catalogue default is still `medium-streaming`, not the service's
`small-streaming`. 0.1.6 claims medium decode is ~20% faster after untying the
decoder output projection, so it was re-measured: medium is still 53% slower at
the median (below), so the default stands and this is not a gap. The catalogue
is otherwise identical to the last run — same ten languages, same architectures;
only the English streaming URLs moved to the `quantized_26_11_02` republish.
`Model.BASE_STREAMING` remains in the enum and in no language's catalogue; the
fallback to the language's best model covers it.

The pin `moonshine-voice>=0.1.5` admits 0.1.6, so nothing blocks the new release.

| medium-streaming | MoonshineSTTService | ✅ | TTFB 1766 ms (median of 5) | spread 1439–2390 ms; English's catalogue default, still 53% slower           |
| small-streaming  | MoonshineSTTService | ✅ | TTFB 723 ms                | from the branch; Latin path unchanged, no options passed                     |
| ja default       | MoonshineSTTService | ✅ | TTFB 959 ms                | from the branch; Japanese model loads and transcribes with the raised cap    |

The Japanese probe sends the bundled English clip, so its text is meaningless;
what it establishes is that the real C API accepts the option on the model the
branch changes. An ad-hoc load with a bogus option name failed with
`Unknown transcriber option`, so `moonshine_load_transcriber_from_files`
validates option names and acceptance of `max_tokens_per_second` confirms the
key. The truncation the raised cap prevents was not reproduced — no non-Latin
audio is available in this environment — so the value comes from Moonshine's own
documentation, quoted in Sources.
