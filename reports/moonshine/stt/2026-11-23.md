### To consider
- **Keyterm biasing** (medium, since 2026-09-01) — `Transcriber.set_keyterms(["Kubernetes", ...])` and `set_context(passage, max_terms)` bias decoding toward domain terms between segments, with `keyterm_boost` for strength; the service calls neither. — *Needs a call: both raise `MoonshineError` on non-streaming architectures (`tiny`, `base`), so exposing them needs a stance on what happens when the configured model cannot bias.*
- **Alphanumeric spelling mode** (medium, since 2026-09-01) — `get_model_for_language` best-effort downloads the language's `spelling_cnn.ort` on every run (this run's probe log shows the 1.59 MB fetch), but `Transcriber` is constructed without `spelling_model_path` and transcribe calls use the default `flags=0`, so the digit/letter fusion is dead weight. — *Needs a call: whether spelling fusion should be a Settings flag or on by default, and whether it costs latency on the CPU path.*
- **Streaming partials** (medium, since 2026-09-01) — `SegmentedSTTService` transcribes each VAD segment in one `transcribe_without_streaming` call; Moonshine's `add_audio` plus listener path emits interim text every `transcription_interval` (0.5 s) and would cut the wait after end-of-turn. 0.1.6's `create_stream`/`get_default_stream` make concurrent streams safe upstream. — *Needs a call: whether Moonshine gets a second, streaming service class alongside the segmented one.*
- **Speaker diarization** (low, since 2026-09-14) — the `identify_speakers` option plus `diarization_model_dir` from `get_diarization_model()` clusters speakers locally and fills `TranscriptLine.speaker_spans`; Deepgram and Speechmatics expose the equivalent in Pipecat, Moonshine does not. Each VAD segment is one speaker by construction, so this only pays off on multi-speaker audio. — *Needs a call: `TranscriptionFrame` cannot carry speaker spans, so surfacing them needs a stance like Speechmatics' speaker-label formatting, plus an opt-in for the 8.2 MB model download.*
- **Word timestamps** (low, since 2026-09-01) — `get_model_for_language(..., include_word_timestamps=True)` fetches the attention decoder the `word_timestamps` option needs to fill `TranscriptLine.words`; neither is requested. — *Needs a call: `TranscriptionFrame` has nowhere to carry word timings, so this needs a frame-level decision first.*
- **No Moonshine TTS service** (low, since 2026-09-01) — the same package ships on-device TTS with a voice catalog, voice cloning and a streaming synthesizer, and the November docs added a Phonon backend next to Kokoro and Piper; Pipecat exposes only the STT half. — *Needs a call: whether a local Moonshine TTS service is wanted next to Kokoro.*

Checked and not gaps this run:

- `ort_providers` / `coreml_cache_dir`, which the service never sets, are not a
  missing knob: Moonshine ships CPU-only builds on every platform and
  `docs/execution-providers.md` calls that "a measured decision, not an
  omission" — its fused `com.microsoft` operators fragment CoreML and NNAPI
  graphs into 1.3–6.8-node partitions, so `cpu` is "the only value any shipped
  build accepts".
- English's catalogue default is still `medium-streaming` rather than the
  service's `small-streaming`; the 2026-11-09 run re-measured medium at 53%
  slower after 0.1.6's decode speedup, and nothing upstream has changed since,
  so the default stands.
- The transcriber option table is unchanged for STT. `docs/api/options.md` was
  last touched on 2026-11-05 by "Added support for Phonon TTS", which added only
  TTS keys.
- docs.pipecat.ai does not yet carry the non-Latin token-rate sentence #6639
  added to the class docstring. That is generation lag behind the 1.17.0
  release, not a code gap.
