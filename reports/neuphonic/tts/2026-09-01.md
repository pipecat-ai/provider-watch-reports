# Neuphonic TTS — 2026-09-01

Nothing is broken or retiring: both classes synthesize against the live API today. The one clear-cut change is exposing Neuphonic's documented `temperature` parameter; a branch is ready.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5578 — Pass Neuphonic's `temperature` through from TTS settings

### To consider
- **WebSocket audio contexts are never closed** (medium, since 2026-09-01) — Neuphonic's socket messages carry `stop` and `context_id` (both read by the official `neuphonic-js` client), and its socket accepts a `context_id` on send; `_receive_messages` reads only `data.audio`, and the service never calls `remove_audio_context`, so contexts close only through the base class's fallbacks. Every other WebSocket TTS service in Pipecat closes the context on the provider's end-of-generation signal. — *Needs a call: keying audio contexts off Neuphonic's `context_id`/`stop` changes interruption and turn behavior, not just a value, so the shape is a maintainer's decision.*
- **Language map is 10 of 36 codes, Hindi is uppercase** (low, since 2026-09-01) — Neuphonic documents 36 language codes; `LANGUAGE_MAP` verifies 10, and maps `Language.HI` to `HI` where every other entry is lowercase. Unmapped languages still reach the API through `resolve_language(..., use_base_code=True)` with a warning, and a probe with `lang_code=HI` returned audio, so both are hygiene rather than breakage. — *Needs a call: the map is meant to be the hand-verified set, so expanding it means verifying the other 26 codes with a matching voice.*
- **Default sample rate 22050 vs Neuphonic's 24000** (low, since 2026-09-01) — both classes hard-default `sample_rate=22050`; Neuphonic accepts 8000/16000/22050/24000 and its SDKs default to 24000 (pyneuphonic 3.1.0, "New sample rate"). — *Needs a call: raising the shipped default changes audio output for every existing user.*
- **`Settings(model=...)` is a silent no-op** (low, since 2026-09-01) — the store sets `model=None` and neither the socket URL nor the SSE payload carries a model, so a user-supplied model is dropped without a warning. Neuphonic's current API has no model parameter (its SDK `TTSConfig` has none; the model follows the voice). — *Needs a call: reject a model in `Settings`, document it as unsupported, or leave the no-op.*

- https://docs.neuphonic.com/build-group/languages — the 36 supported language codes, all lowercase
- https://docs.neuphonic.com/sitemap.xml — the docs site has no API reference section; the SDKs are the parameter reference
- https://github.com/neuphonic/pyneuphonic `pyneuphonic/models.py` — `TTSConfig`: `speed`, `temperature` (0–1), `lang_code`, `voice_id`, `sampling_rate`, `encoding`, `output_format`; `<STOP>` is still the completion signal
- https://github.com/neuphonic/neuphonic-js `src/common.ts`, `src/tts.ts`, `src/config.ts` — same `TtsConfig` fields; socket messages carry `stop` and `context_id`; base URL is still `api.neuphonic.com`
- https://github.com/neuphonic/pyneuphonic commits — 2026 majors are client-side only (Python 3.10 floor, longform inference removed, local interruption handling removed) plus the 24000 sample rate; the `pipecat-ai[neuphonic]` extra pins no SDK, so none of it constrains us
- https://docs.livekit.io/agents/models/tts/neuphonic/ — still documents a `model` parameter defaulting to `neu_hq`, which the current Neuphonic SDKs no longer carry
- probe.py list-models / sdk-versions — no catalogue for neuphonic, no SDK dependency in the extra
