# Neuphonic TTS — 2026-11-23

The only movement at Neuphonic is naming: the docs now say the cloud API runs on NeuTTS-Max, with no model parameter to pass, so the service is current and the five open items are unchanged.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Word timings are not requested or surfaced** (medium, since 2026-10-12) — `timestamps=true` on the TTS websocket makes each audio message carry an `alignment` (word units, start times, durations, character offsets), or `null` plus `alignment_unavailable` for voices without them. Pipecat consumes word timings through `TTSService.add_word_timestamps`, but `NeuphonicTTSService` derives from `InterruptibleTTSService`, documented as the base "for TTS services that don't support word timestamps", which handles interruption by tearing down and reopening the socket. — *Needs a call: using the timings means re-basing the websocket class on word-timestamp interruption handling, so it is a structural change rather than a parameter.*
- **WebSocket protocol signals go unused** (medium, since 2026-09-01) — Neuphonic's socket messages carry `stop` and `context_id`, its send side accepts a per-message `context_id`, and a `<RESET>` message discards buffered text and carried-over prosody without closing the connection. `_receive_messages` reads only `data.audio` and the service never calls `remove_audio_context`, so contexts close only through the base class's fallbacks, and interruption always reconnects. — *Needs a call: keying audio contexts off `context_id`/`stop` changes interruption and turn behavior, so the shape is a maintainer's decision.*
- **Language map is 10 of 44 codes** (low, since 2026-09-01) — the docs list the same 44 lowercase codes as last run, and `GET /voices` now reports exactly those 44 across 120 voices, so the catalogue no longer carries the undocumented `ms`. `LANGUAGE_MAP` verifies 10. Unmapped languages still reach the API via `resolve_language(..., use_base_code=True)` with a warning, so this is hygiene rather than breakage. — *Needs a call: the map is the hand-verified set, so expanding it means probing each added code against a voice that supports it.*
- **Default sample rate 22050 vs Neuphonic's 24000** (low, since 2026-09-01) — both classes hard-default `sample_rate=22050`; Neuphonic accepts 8000/16000/22050/24000 and documents 24000 as its default. — *Needs a call: raising the shipped default changes audio output for every existing user.*
- **`Settings(model=...)` is a silent no-op** (low, since 2026-09-01) — the store sets `model=None` and neither the socket query string nor the SSE body carries a model. The docs now name NeuTTS-Max as "the model behind the Neuphonic cloud API" and still document no model parameter, so a model in `Settings` has nowhere to go. — *Needs a call: reject a model in `Settings`, document it as unsupported, or leave the no-op.*

The Emily voice both examples hard-code (`fc854436-2dac-4d21-aa69-ae17b54e98eb`) is still in the live catalogue, so nothing under `examples/` has gone stale.
