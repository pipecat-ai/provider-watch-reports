# Neuphonic TTS — 2026-09-14

Nothing changed on the provider's side since 2026-09-01, and the `temperature` PR merged; but no probe produced audio today — every synthesis call, down to a minimal one, came back 500 while the same key listed voices fine.

## What's new for Pipecat

### PRs
Nothing. https://github.com/pipecat-ai/pipecat/pull/5578 (`temperature` pass-through) merged on 2026-09-02, closing that gap.

### To consider
- **WebSocket audio contexts are never closed** (medium, since 2026-09-01) — Neuphonic's socket messages carry `stop` and `context_id` (both read by the official `neuphonic-js` client), and its socket accepts a `context_id` on send; `_receive_messages` reads only `data.audio`, and the service never calls `remove_audio_context`, so contexts close only through the base class's fallbacks. Every other WebSocket TTS service in Pipecat closes the context on the provider's end-of-generation signal. — *Needs a call: keying audio contexts off Neuphonic's `context_id`/`stop` changes interruption and turn behavior, not just a value, so the shape is a maintainer's decision.*
- **Language map is 10 of 36 codes, Hindi is uppercase** (low, since 2026-09-01) — the docs still list 36 codes, all lowercase, including `hi`; `LANGUAGE_MAP` verifies 10 and maps `Language.HI` to `HI`. Unmapped languages still reach the API through `resolve_language(..., use_base_code=True)` with a warning, and the 2026-09-01 probe with `lang_code=HI` returned audio, so both are hygiene rather than breakage. Fixing the casing alone would be a one-line PR, but today's outage left no way to probe it. — *Needs a call: the map is meant to be the hand-verified set, so expanding it means verifying the other 26 codes with a matching voice.*
- **Default sample rate 22050 vs Neuphonic's 24000** (low, since 2026-09-01) — both classes hard-default `sample_rate=22050`; Neuphonic accepts 8000/16000/22050/24000 and documents 24000 as the default. — *Needs a call: raising the shipped default changes audio output for every existing user.*
- **`Settings(model=...)` is a silent no-op** (low, since 2026-09-01) — the store sets `model=None` and neither the socket URL nor the SSE payload carries a model, so a user-supplied model is dropped without a warning. Neuphonic has no model parameter: `GET /models` is 404 and the model follows the voice. — *Needs a call: reject a model in `Settings`, document it as unsupported, or leave the no-op.*
