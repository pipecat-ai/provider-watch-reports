# Neuphonic TTS — 2026-11-09

Nothing moved at Neuphonic this cycle — no changelog entries since September, same docs pages, same SDK — and last run's branch merged, so the only open items are the five that need a maintainer's call.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Word timings are not requested or surfaced** (medium, since 2026-10-12) — September 2026 added `timestamps=true` to the TTS websocket; each audio message then carries an `alignment` of parallel arrays (word units, start times, durations, character offsets), or `null` plus `alignment_unavailable` for voices without them. Pipecat consumes word timings through `TTSService.add_word_timestamps`, but `NeuphonicTTSService` derives from `InterruptibleTTSService`, documented as the base "for TTS services that don't support word timestamps", which handles interruption by tearing down and reopening the socket. — *Needs a call: using the timings means re-basing the websocket class on word-timestamp interruption handling, so it is a structural change rather than a parameter.*
- **WebSocket protocol signals go unused** (medium, since 2026-09-01) — Neuphonic's socket messages carry `stop` and `context_id`, its send side accepts a per-message `context_id`, and a `<RESET>` message discards buffered text and prosody without closing the connection. `_receive_messages` reads only `data.audio` and the service never calls `remove_audio_context`, so contexts close only through the base class's fallbacks, and interruption always reconnects. — *Needs a call: keying audio contexts off `context_id`/`stop` changes interruption and turn behavior, so the shape is a maintainer's decision.*
- **Language map is 10 of 44 codes** (low, since 2026-09-01) — the docs list 44 lowercase codes, unchanged from last run; `GET /voices` reports 45 distinct `lang_code` values across 122 voices, the extra one being `ms`. `LANGUAGE_MAP` verifies 10. Unmapped languages still reach the API via `resolve_language(..., use_base_code=True)` with a warning, so this is hygiene rather than breakage. — *Needs a call: the map is the hand-verified set, so expanding it means probing each added code against a voice that supports it.*
- **Default sample rate 22050 vs Neuphonic's 24000** (low, since 2026-09-01) — both classes hard-default `sample_rate=22050`; Neuphonic accepts 8000/16000/22050/24000 and documents 24000 as its default. — *Needs a call: raising the shipped default changes audio output for every existing user.*
- **`Settings(model=...)` is a silent no-op** (low, since 2026-09-01) — the store sets `model=None` and neither the socket query string nor the SSE body carries a model; the docs state `voice_id` determines which models are used. — *Needs a call: reject a model in `Settings`, document it as unsupported, or leave the no-op.*

Last run's two `pr` gaps are closed: https://github.com/pipecat-ai/pipecat/pull/6139 merged on 2026-10-12, and the code now carries the `ipa_key` Settings field on both classes and `Language.HI: "hi"` in the language map.
