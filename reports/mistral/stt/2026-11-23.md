# Mistral STT — 2026-11-23

Two of last run's gaps are fixed in main; the deprecated default still has no successor worth bumping to — realtime 3 is Public Preview and this run measured it 3.7x slower than the model it replaces.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model deprecated** (high, since 2026-11-09) — `voxtral-mini-transcribe-realtime-2602` was deprecated on 2026-10-31 and retires 2027-04-30; Mistral's named alternative is `voxtral-mini-transcribe-realtime-3`, still Public Preview. It transcribes correctly through `MistralSTTService` with no code change, but its TTFB was 4421 ms against the default's 1198 ms (medians of 5) — a wider gap than the 2955 vs 1310 ms measured on 2026-11-09, so the preview model is not converging on the old one. A bump would also need `MISTRAL_TTFS_P99` (1.89 s) re-measured. — *Needs a call: wait for realtime 3 to reach GA and get faster, or bump early and accept the latency, given the retirement date.*
- **Realtime 3 session fields unexposed** (medium, since 2026-11-09) — with the pin now `mistralai>=2.0.0,<4`, 3.8.0's `connect()` accepts `context_bias`, `diarize`, `speaker_references` and `turn_detection`; the service sends none of them. `context_bias` is a list of keyphrases that fixes spelling of names and jargon, and is the one that maps cleanly onto a `Settings` field; `diarize` and `speaker_references` produce speaker-labelled text that `TranscriptionFrame` has nowhere to carry. — *Needs a call: the locked environment is still 2.10.1, where a new field would be dropped silently, so a pass-through needs either the `inspect.signature` gate `language` already uses or the lockfile moved first.*
- **Provider-side turn detection unused** (medium, since 2026-11-09) — realtime 3 scores end-of-turn while transcribing and emits `turn.start`, `turn.eager_end`, `turn.resume` and `turn.end`, configured by a `turn_detection` session object that must be sent before the first audio chunk and cannot be combined with `diarize`. The service flushes audio on `VADUserStoppedSpeakingFrame` and ignores these events. — *Needs a call: letting a provider turn signal drive a user turn start/stop strategy is a design question, not a Settings field.*
- **Lockfile behind the pin** (low, since 2026-11-23) — `pyproject.toml` allows `mistralai<4` and PyPI's latest is 3.8.0, but `uv.lock` holds 2.10.1, so a fresh user install runs 3.x while our tests run 2.x. The `language` hint path only fires on 3.7+, and the unit tests cover it with a mocked `connect`. An isolated 3.8.0 check found every symbol `stt.py` imports and the whole `RealtimeConnection` surface it uses present and unchanged. — *Needs a call: whether to refresh the lock for mistralai alone, since it also moves `MistralTTSService`'s runtime.*
- **`target_streaming_delay_ms` not in Settings** (low, since 2026-09-01) — the provider's accuracy/latency knob (multiples of 80 from 80 to 1200, or 2400; default 480 ms) is a constructor argument only. Realtime 3 locks session fields once audio starts, but `_update_settings` already reconnects, so a Settings field would behave correctly. — *Needs a call: adding it to Settings duplicates the constructor argument, so it needs a stance on deprecating that argument.*

Closed since 2026-11-09: the `mistralai>=2.0.0,<3` pin now reads `<4`, and commit `212fcb728` forwards `MistralSTTSettings.language` to the session when the model and installed SDK support it — both were gaps in the last report and are dropped here.
