# Mistral TTS — 2026-11-09

The shipped default is deprecated: Mistral retires `voxtral-mini-tts-2603` on 2027-04-30 and names Voxtral TTS 3 as its alternative, but `voxtral-mini-tts-3-0` measured 14-26% slower TTFB on the one voice both models accept, so the bump is a maintainer call rather than a branch.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default is deprecated; Voxtral TTS 3 is the named successor** (high, since 2026-11-09) — Mistral's model overview lists `voxtral-mini-tts-2603` under deprecated models (deprecation 2026-10-31, retirement 2027-04-30, alternative "Voxtral TTS 3"), and `voxtral-mini-tts-3-0` is the current Premier TTS model. It runs through `MistralTTSService` with no code change. Latency is the blocker: on the saved cloned voice both models accept, TTS 3 was 725 ms vs 2603's 576 ms and, in a second round, 859 ms vs 752 ms — worse than the 10% tolerance. On a TTS 3 preset voice (`gb_jane_neutral`, rejected by 2603 with "voice is not supported for speech v1") TTS 3 was 580 ms, so the slower figure looks like the cloned-voice path, not the model. Bumping would also switch the shipped default onto the Voxtral 3 expression adapter, which today only engages when a user names a `voxtral-mini-tts-3*` model. — *Needs a call: bump now and accept the slower cloned-voice TTFB, or hold while 26.03 is still served and re-measure.*
- **SDK pin behind the current major** (medium, since 2026-11-09) — `mistralai>=2.0.0,<3` excludes 3.7.0 (2026-11-01). The speech event types we import are unchanged across the major, but 3.0.0 swaps HTTPX for HTTPX2 and the whole `[mistral]` extra moves together. — *Needs a call: whether the HTTPX2 switch is safe for every Mistral service sharing the extra.*
- **Voxtral 3 speech parameters** (medium, since 2026-11-09) — `expressiveness`, `phoneme_hints` and `conversation_history` are new request fields in the 3.x `SpeechRequest`; `MistralTTSSettings` has no fields for them and our pin cannot reach them. — *Needs a call: the pin has to move first, and `conversation_history` only works with preset `pvc` voices.*
- **Reference-audio voice cloning** (medium, since 2026-09-01) — the speech request accepts `ref_audio`, a base64 clip that clones a voice zero-shot without first creating a saved voice; Pipecat users must pre-register a voice through `audio.voices.create`. A field plus a pass-through in `run_tts` is the shape. — *Needs a call: `run_tts` requires a voice (`assert_given(self._settings.voice)`), so exposing `ref_audio` means making voice optional and deciding precedence when both are set.*
- **`language` is a no-op** (low, since 2026-09-01) — the speech endpoint has no language parameter, so the inherited field is stored and never sent, while the `MistralTTSSettings` docstring still lists it as "Language for speech synthesis". — *Needs a call: document the field as unsupported here or drop it from the docstring.*
- **Realtime TTS model has no service** (low, since 2026-11-09) — Mistral's audio overview lists `voxtral-mini-tts-realtime-3-0` for live conversations and the 3.x SDK ships realtime speech session types; the model is not in our account's catalogue and would need a new websocket service class. — *Needs a call: whether a realtime Mistral TTS service is wanted, and whether the model is reachable yet.*
