# Mistral TTS — 2026-11-23

Nothing new shipped at Mistral since the last run; the open question is still the deprecated default, and this run's latency measurements no longer back the reason the bump was held.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default is deprecated; Voxtral TTS 3 is the named successor** (high, since 2026-11-09) — the model overview still lists `voxtral-mini-tts-2603` as deprecated 10/31/2026, retiring 4/30/2027, alternative "Voxtral TTS 3". `voxtral-mini-tts-3-0` runs through `MistralTTSService` with no code change. Two interleaved rounds of 5 on the cloned voice from `examples/voice/voice-mistral.py` put TTS 3 at 570 ms vs 657 ms and 515 ms vs 503 ms — within tolerance or ahead — where 2026-11-09 measured it 725 ms vs 576 ms and 859 ms vs 752 ms on the same voice. Bumping would also switch the shipped default onto the Voxtral 3 expression adapter, which today only engages when a user names a `voxtral-mini-tts-3*` model. — *Needs a call: the two runs disagree on the same comparison, so the bump is a maintainer's decision rather than a measurement.*
- **Voxtral 3 speech parameters** (medium, since 2026-11-09) — the SDK-pin blocker is gone (`mistralai>=2.0.0,<4` since commit 212fcb728), and `expressiveness` does not even need 3.x: sent through `complete_async(additional_properties={"expressiveness": ...})` on the locked 2.10.1 it reaches the API, which enforces the documented minimum of 1.0. The catch is the model: `voxtral-mini-tts-2603` answers 400 `expressiveness is not supported for this model`, so a Settings field would be a parameter the shipped default rejects. `phoneme_hints` and `conversation_history` are larger shapes with their own restrictions. — *Needs a call: expose it now with model-dependent behavior, or wait until the default is Voxtral TTS 3.*
- **Reference-audio voice cloning** (medium, since 2026-09-01) — the speech request accepts `ref_audio`, a base64 clip that clones a voice zero-shot; Pipecat users must pre-register a voice through `audio.voices.create`. A field plus a pass-through in `run_tts` is the shape. — *Needs a call: `run_tts` requires a voice (`assert_given(self._settings.voice)`), so exposing `ref_audio` means making voice optional and deciding precedence when both are set.*
- **`language` is a no-op** (low, since 2026-09-01) — the speech endpoint has no language parameter, so the inherited field is stored and never sent, while the `MistralTTSSettings` docstring still lists it as "Language for speech synthesis". — *Needs a call: document the field as unsupported here or drop it from the docstring.*
- **Realtime TTS model has no service** (low, since 2026-11-09) — realtime TTS is a websocket session on `/v1/audio/speech/realtime`; the model is not in our account's catalogue and would need a new service class. — *Needs a call: whether a realtime Mistral TTS service is wanted, and whether the model is reachable yet.*

Dropped since 2026-11-09: the `mistralai` pin gap — commit 212fcb728 widened the extra to `mistralai>=2.0.0,<4`, so 3.8.0 installs. `uv.lock` still resolves 2.10.1, and the symbols the TTS service imports (`mistralai.client.Mistral`, `SpeechStreamAudioDelta`, `SpeechStreamDone`) are present in both, so the service works either way.
