# Camb TTS — 2026-11-09

Camb has not moved since the last run — same five models, same request schema, same SDK surface — `mars-flash` stays the right default; the credential is dead for the seventh run, so nothing could be verified and no branch was left.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **MARS 8.1 beta sample rates** (medium, since 2026-08-31) — `mars-8.1-flash-beta` and `mars-8.1-pro-beta` are in the SDK's `speech_model` literal and are the streaming endpoint's documented default, but `MODEL_SAMPLE_RATES` knows only the three GA models, so both betas fall back to 22050 Hz against Camb's documented 48 kHz — audio labelled at less than half its real rate. Two table entries would do it. Camb also lists `mars-flash` as "22.05kHz/48kHz", which one entry cannot express. — *Needs a call: a live probe must confirm the betas' actual stream rate (blocked), and whether beta models belong in the table at all.*
- **`voice_settings` pass-through** (medium, since 2026-08-31) — the endpoint takes `voice_settings` with `speaking_rate` (default 1, documented as the only pacing control), `maintain_source_accent` and `enhance_reference_audio_quality`; `run_tts` never builds the object, so there is no speed control. — *Needs a call: whether to expose `speaking_rate` alone or the whole nested object, and a probe with it set (blocked).*
- **Requested sample rate never reaches Camb** (medium, since 2026-08-31) — `output_configuration` has a documented `sample_rate` field; the service sets only `format="pcm_s16le"` and, when the caller passes `sample_rate=`, logs a warning while still tagging frames at the caller's rate over a stream at the model's native rate. The same object's `apply_enhancement` (true for most models, false for `mars-flash` and `mars-8.1-flash-beta`) is likewise unreachable. — *Needs a call: request the rate from Camb, or keep warning-only.*
- **`inference_options` pass-through** (low, since 2026-08-31) — the SDK's `tts()` accepts a `StreamTtsInferenceOptions` object the service never builds; documented as MARS-8-family-only and unsupported on the two 8.1 betas, and the endpoint's published schema still carries it in prose and an example rather than in the schema itself. — *Needs a call: what to do when the selected model ignores them.*
- **`enhance_named_entities_pronunciation`** (low, since 2026-08-31) — top-level boolean, default false, not exposed; the docs also mark it unsupported on the two 8.1 betas. — *Needs a call: a probe with the field set, which the rejected credential blocks.*
- **No expression adapter for the 8.1 betas' inline tags** (low, since 2026-11-09) — the endpoint documents six non-verbal tags (`[laughter]`, `[sigh]`, `[confirmation]`, `[question]`, `[surprise]`, `[dissatisfaction]`) and bracketed CMU phoneme overrides, inline in `text`, on `mars-8.1-flash-beta` and `mars-8.1-pro-beta`. Pipecat has no `camb_adapter.py` and `CambTTSService` does not override `get_expression_adapter()`. An adapter also needs an example and a manifest entry per AGENTS.md, so it is not a one-line change. Earlier runs saw the inline controls and set them aside as text-level; with the adapter framework in place they are now a reachable capability. — *Needs a call: whether a beta-only capability earns an adapter, and universal names for `confirmation`, `question`, `surprise` and `dissatisfaction`, which have none today.*
