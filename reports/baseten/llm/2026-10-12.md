# Baseten LLM — 2026-10-12

`zai-org/GLM-5.3` is still Baseten's current GLM and still the shipped default; the reasoning-latency alarm from last month does not reproduce, so nothing needs changing in the code.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **GLM-5.3 reasons by default** (medium, since 2026-09-14) — the September measurement (TTFAT 2167 ms median, 1470 ms of it thinking) does not reproduce. Two independent `--repeat 5` runs today put GLM-5.3 at 858 ms and 1029 ms median TTFAT with **zero** thinking time on the trivial prompt, and 1313 ms with 199 ms thinking on a reasoning-triggering one. Baseten's serverless capacity is slower across the board today — GLM-5.2, the comparison model, measures 1160–1665 ms on the same trivial prompt (it was 363 ms in September) and 389 ms on the reasoning prompt. Baseten's reasoning page now states explicitly that `reasoning_effort: none` is treated as `low` for the GLM 5.3 family and does not disable reasoning; the documented switch is `chat_template_args.enable_thinking: false`, which a user reaches today as `Settings.extra={"extra_body": {"chat_template_args": {"enable_thinking": False}}}` (a bare `extra={"chat_template_args": ...}` fails, since `extra` entries become `create()` keyword arguments). With thinking off that way, TTFAT is 1148 ms — inside the default's spread, so there is no latency case for shipping it. What is left of the item is quality: aiewf-eval's `aiwf_medium_context` still carries only glm-5.3 (low reasoning, Z.AI) at 98.7% / 2376 ms against glm-5.2 (none, Baseten) at 99.7% / 936 ms. — *Needs a call: whether that Z.AI-measured row is reason enough to revisit the default, now that the latency argument behind the item has collapsed.*

Last run's second gap is closed: https://docs.pipecat.ai/api-reference/server/services/llm/baseten now documents `zai-org/GLM-5.3` as the default, and no longer recommends the retired `moonshotai/Kimi-K2.6`. Baseten's 2026-09-25 retirement executed — GLM 4.7, Kimi K2.6, Kimi K2.7, Inkling, Inkling Small and DeepSeek v4 Pro are gone from the catalogue — and nothing in `src/`, `examples/` or the tests pinned any of those strings, so no fixes are needed. One catalogue addition, `deepseek-ai/DeepSeek-V4.1-Flash-Fast` (2026-10-08), needs no code change: the service passes `model` through untouched. The 2026-10-01 `b10_` prefix on newly created API keys is a format change only; keys travel through as opaque strings.
