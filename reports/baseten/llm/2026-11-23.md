# Baseten LLM — 2026-11-23

`zai-org/GLM-5.3` stays the default: it is absent from Baseten's 2026-12-18 retirement list and this run measures it at parity with the catalogue's fast models, reversing the latency argument the last two reports carried.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Cross-family default change** (low, since 2026-09-14) — re-measuring today contradicts the 2026-11-09 report, so both numbers are here. Two interleaved `--repeat 5` runs put GLM-5.3 at **TTFAT 872 ms median** (trivial prompt) and **1009 ms** (reasoning-triggering prompt), where the last run saw 1745 ms; `deepseek-ai/DeepSeek-V4-Pro-0813` measured 687 ms and 1710 ms on the same two prompts in the same runs, so GLM-5.3 is now the faster of the two once a prompt actually triggers thinking. Only the leaderboard gap survives: aiewf-eval's `aiwf_medium_context` has deepseek-v4-pro-0813 (low, Baseten) at 98.4% / 755 ms against glm-5.3 (low, Z.AI) at 97.7% / 2376 ms. The candidate the last run favoured, `deepseek-ai/DeepSeek-V4-Flash-0731` (98.6%), is itself retiring on 2026-12-18, and its designated replacement `deepseek-ai/DeepSeek-V4.1-Flash-1017` has no leaderboard row yet. — *Needs a call: whether 0.7 points of pass rate, with latency at parity, justifies moving the default across families when Baseten designates no successor to GLM-5.3.*
- **Reasoning content is not replayed on later turns** (low, since 2026-11-09) — unchanged from the last run. `reflection/Beam-1.0` and `meta-models/muse-spark-open` reason unconditionally per Baseten's reasoning docs, and Beam's announcement asks callers to preserve `reasoning_content` from prior assistant turns; the shared OpenAI chat-completions path neither surfaces nor replays it, and `DeepSeekLLMAdapter` is the precedent for a provider that needs it. — *Needs a call: whether a thin wrapper should carry an adapter for models that are not its default; this is adapter work in the shared OpenAI path, not a one-line setting.*
- **Pipecat's Baseten docs page names a family that is going away** (low, since 2026-11-23) — the page lists gpt-oss among the families Model APIs serves, and `openai/gpt-oss-120b` is retired on 2026-12-18 along with `nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B`. — *Needs a call: the page lives in the docs repository, not this one.*

Baseten published a retirement list on 2026-11-20: `deepseek-ai/DeepSeek-V4.1-Flash`, `deepseek-ai/DeepSeek-V4.1-Flash-Fast`, `deepseek-ai/DeepSeek-V4-Flash-0731`, `zai-org/GLM-5.2-Fast`, `nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B` and `openai/gpt-oss-120b` all start returning errors at 5pm PT on 2026-12-18, each with a named replacement. The shipped default is not on the list, and nothing in `src/`, `examples/` or `tests/` pins any of the six — `examples/function-calling/function-calling-baseten.py` takes the service default and sets only a system instruction — so there is no string to fix here.

The catalogue grew by two slugs, both decision models (`decision-models/baseten-bison-latest`, `decision-models/baseten-groundhog-latest`, 2026-11-20). Like the three that preceded them they are served from `https://inference.baseten.co/v1/systemone` with a `questions` body rather than chat completions, so they are out of reach of this service by design. No chat model was added this cycle. Team-scoped Model APIs (2026-11-18) change which team a key bills and rate-limits against, not the base URL or the request format, so a `BASETEN_API_KEY` keeps working as before.

The request schema is unchanged: the published OpenAPI spec still declares `ChatCompletionRequest` with `additionalProperties: false` and the same Baseten-specific fields (`reasoning`, `reasoning_effort`, `chat_template_args`, `documents`, `chat_template`, and the vLLM-style generation controls), all reachable from `Settings.extra={"extra_body": {...}}` — `BaseOpenAILLMService` merges `extra` into the request parameters directly.
