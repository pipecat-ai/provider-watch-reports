# Baseten LLM — 2026-11-09

`zai-org/GLM-5.3` is safe to keep shipping — still served, nothing deprecated — but it is the slowest realistic choice in Baseten's catalogue today, and that is now the only open question for this unit.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The GLM-5.3 default is slow** (medium, since 2026-09-14) — last run's item was "GLM-5.3 reasons by default"; that attribution no longer holds (thinking 0 ms on a trivial prompt, 151 ms on a reasoning-triggering one), but the latency it pointed at does. Interleaved `--repeat 5` measures GLM-5.3 at **TTFAT 1745 ms median** against **521 ms** for `deepseek-ai/DeepSeek-V4-Flash-0731` on the same prompt in the same run. The leaderboard agrees on quality as well as speed: aiewf-eval's `aiwf_medium_context` now has deepseek-v4-flash-0731 (high reasoning, Baseten) at 98.6% / 773 ms TTFAT P50 above glm-5.3 (low reasoning, Z.AI) at 97.7% / 2376 ms, with deepseek-v4-pro-0813 (low, Baseten) at 98.4% / 755 ms between them. Baseten has shipped no GLM after 5.3, so there is no in-family bump to make. — *Needs a call: Baseten designates no successor to GLM-5.3, so moving the default across families is a deliberate choice about which open-weights model Pipecat recommends.*
- **Reasoning content is not replayed on later turns** (low, since 2026-11-09) — Baseten's Beam-1.0 announcement says to preserve `reasoning_content` from prior assistant turns, and both `reflection/Beam-1.0` and `meta-models/muse-spark-open` reason unconditionally. Pipecat's shared OpenAI chat-completions path neither surfaces that field nor sends it back, so a user who points `BasetenLLMService` at either model loses it between turns. `DeepSeekLLMAdapter` is the precedent for a provider that needs `reasoning_content` on assistant messages. — *Needs a call: whether a thin wrapper should carry an adapter for models that are not its default; this is adapter work in the shared OpenAI path, not a one-line setting.*

Eight slugs joined the catalogue since the last run and none needs code: `reflection/Beam-1.0` (2026-10-16), `meta-models/muse-spark-open` and `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B` (2026-10-15), `moonshotai/Kimi-K3.1-Pro` (2026-11-04), the two `DeepSeek-V4.1-Flash-1017` variants, and three `decision-models/*` classifiers (elephant-1, mammoth-1 2026-10-21, joey-1 2026-11-01) that are served from Baseten's System One endpoint rather than chat completions. The service passes `model` through untouched, and the three chat models probed clean. Nothing was retired this cycle and nothing in `src/`, `examples/` or the tests pins a stale slug.

Three platform changes affect accounts rather than code. Baseten APIs return `401 Unauthorized` instead of `403 Forbidden` for missing, invalid or expired credentials as of 2026-10-28 — Pipecat checks neither status, and the OpenAI SDK already maps both. New personal API keys expire after at most 90 days (7/30/90 at creation), and from 2026-10-24 keys that have not authenticated a request in 30 days are revoked automatically and cannot be restored; long-lived `BASETEN_API_KEY` values in CI or deployments will need rotating. Separately, the Responses and Messages formats went GA for Model APIs on 2026-11-09; Chat Completions, which this service speaks, is unaffected, and reaching the Responses format would mean a new service class rather than a change here.
