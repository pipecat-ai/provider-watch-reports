# Ollama LLM — 2026-11-23

Service is current: one Ollama release since the last run, touching nothing Pipecat sends, and the carried `llama2` default is the only open item.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`llama2` default** (medium, since 2026-09-01) — `OLLamaLLMService()` with no settings asks for a July-2023, 4K-context model with no tools capability, so function calling silently cannot work; llama2 is now #26 by pulls while Pipecat's own eval judge and CLI agent templates default to `gemma4:12b`. No in-tree caller relies on the default, and aiewf-eval (50 rows) still has no Ollama-served row to rank a candidate with. — *Needs a call: Ollama designates no successor and a local runtime only serves models the user pulled, so the choice is between an opinionated modern default and making `model` required.*

Not gaps: v0.40.17's tool-definition fix (tool schemas now keep JSON Schema keywords Ollama doesn't model instead of dropping them) makes the schemas Pipecat's adapter already sends survive intact — an upstream improvement needing no change here. v0.40.17 also made disabling thinking fall back to a model's lowest supported reasoning level rather than being ignored; `reasoning_effort` / `reasoning.effort` remain reachable through `Settings.extra` and their values stay model-defined (read from `/api/show`), so a typed field would still need an allowlist we cannot source, and the shared `_THINKING_DEFAULTS` tables are a Responses/Anthropic/Gemini surface this chat-completions wrapper doesn't use. `tool_choice`, `n`, `logprobs`, `logit_bias` and `user` remain unsupported by Ollama but Pipecat never sends them. No model Pipecat hardcodes was removed: `llama3.1` (#1), `llama3.2` (#4) and `gemma4` (#10) are all still listed; cloud gained `hy4` and `inkling-2-small` and dropped `deepseek-v4-pro` and `kimi-k2.6`, none of which Pipecat names.
