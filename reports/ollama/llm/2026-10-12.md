# Ollama LLM — 2026-10-12

Service is current: nine Ollama releases since the last run changed nothing on the OpenAI-compatible chat-completions path, and the same two items need a maintainer's call.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`llama2` default** (medium, since 2026-09-01) — `OLLamaLLMService()` with no settings asks for a July-2023 model whose library page carries no `tools` tag, so function calling silently cannot work; llama2 is now #24 by pulls while Ollama's quickstart is `ollama run gemma4` and Pipecat's own eval judge defaults to `gemma4:12b`. No in-tree caller relies on the default, and aiewf-eval still has no Ollama-served row to rank a candidate with. — *Needs a call: Ollama designates no successor and a local runtime only serves models the user pulled, so the choice is between an opinionated modern default and making `model` required.*
- **Ollama Cloud unreachable** (medium, since 2026-09-01) — `api_key` is hardcoded to `"ollama"`, so passing a real key raises `TypeError: got multiple values for keyword argument 'api_key'`; Cloud serves glm-5.3, kimi-k3, mistral-large-4 and gpt-oss over the same `/v1` surface with `OLLAMA_API_KEY`. — *Needs a call: the fix adds a constructor parameter, which the automatic-PR rules exclude, so someone has to decide whether cloud is in scope for this class.*

Not gaps: v0.35.0's `/v1/systemone` decision-model endpoint is a new surface, not a chat-completions parameter. `typical_p` is deprecated since v0.34.1 (warn-only since v0.35.0) but Pipecat never sends it — no occurrence anywhere in `src/`. v0.40.2's background model upgrades and v0.40.0's MLX-by-default on Apple Silicon are runtime-side. `reasoning_effort` / `reasoning.effort` stay reachable through `Settings.extra`, and their values are model-defined (read from `/api/show`), so a typed field would need an allowlist we cannot source; `tool_choice`, `n`, `logprobs`, `logit_bias` and `user` remain unsupported by Ollama but Pipecat never sends them. `deepseek-v4-flash`, `glm-5.1` and `qwen3.8` dropped off the catalogue pages since the last run; none is a string Pipecat hardcodes.
