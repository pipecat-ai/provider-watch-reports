# Ollama LLM — 2026-11-09

Service is current: thirteen Ollama releases since the last run touched nothing Pipecat sends, and the Cloud gap was fixed in-tree, leaving one item for a maintainer.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`llama2` default** (medium, since 2026-09-01) — `OLLamaLLMService()` with no settings asks for a July-2023 model whose library page carries no `tools` tag, so function calling silently cannot work; llama2 is now #25 by pulls while Ollama's quickstart is `ollama run gemma4` and Pipecat's own eval judge and CLI agent templates default to `gemma4:12b`. No in-tree caller relies on the default, and aiewf-eval (50 rows) still has no Ollama-served row to rank a candidate with. — *Needs a call: Ollama designates no successor and a local runtime only serves models the user pulled, so the choice is between an opinionated modern default and making `model` required.*

Closed since the last report: "Ollama Cloud is unreachable because api_key is hardcoded" (first seen 2026-09-01) — commit 4a45be11a (2026-10-16) added an `api_key` constructor parameter defaulting to the placeholder a local Ollama ignores, so `OLLamaLLMService(base_url="https://ollama.com/v1", api_key=...)` now constructs and keeps `supports_developer_role = False`.

Not gaps: v0.40.14 stopped the OpenAI-compatible endpoints overriding a model's packaged sampler defaults — Pipecat leaves `temperature`/`top_p` at `NOT_GIVEN` unless a user sets them, so Ollama-served models now use their own defaults, which is the intended behavior. v0.40.11's `/v1/audio/speech` and the `/v1/responses` fixes in v0.40.5, v0.40.7, v0.40.9 and v0.40.16 are other surfaces. v0.40.7's `renderer`/`parser`/`template_source` come from model info, not chat parameters. `reasoning_effort` / `reasoning.effort` stay reachable through `Settings.extra`, and their values are model-defined (read from `/api/show`), so a typed field would need an allowlist we cannot source. `tool_choice`, `n`, `logprobs`, `logit_bias` and `user` remain unsupported by Ollama but Pipecat never sends them. No model Pipecat hardcodes was removed: `llama3.1` (#1), `llama3.2` (#4) and `gemma4` (#10) are all still listed.
