# Ollama LLM — 2026-09-01

`base_url` and the OpenAI-compat surface are still correct; two judgment calls to make — a `llama2` default that cannot call tools, and Ollama Cloud being unreachable through this class.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`llama2` default** (medium, since 2026-09-01) — `OLLamaLLMService()` with no settings asks for a July-2023 model that Ollama's library gives no `tools` tag, so function calling silently cannot work; Ollama's quickstart is `ollama run gemma4` and Pipecat's own eval judge defaults to `gemma4:12b`. No in-tree caller relies on the default. — *Needs a call: Ollama designates no successor and a local runtime only serves models the user pulled, so the choice is between an opinionated modern default and making `model` required.*
- **Ollama Cloud unreachable** (medium, since 2026-09-01) — `api_key` is hardcoded to `"ollama"`, so passing a real key raises `TypeError: got multiple values for keyword argument 'api_key'`; Ollama Cloud serves glm-5.3, kimi-k3, qwen3.5 and gpt-oss over the same `/v1` surface with `OLLAMA_API_KEY`. — *Needs a call: the fix adds a constructor parameter, which the automatic-PR rules exclude, so someone has to decide whether cloud is in scope for this class.*

Not gaps: Ollama's `/v1/chat/completions` accepts `reasoning_effort` and `reasoning`, both already reachable through `Settings.extra` (that is how `src/pipecat/evals/services.py` sends `reasoning_effort: none`); `tool_choice`, `n`, `logprobs`, `logit_bias` and `user` are unsupported by Ollama but Pipecat never sends them.
