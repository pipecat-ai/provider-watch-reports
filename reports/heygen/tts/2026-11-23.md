# HeyGen TTS — 2026-11-23

Nothing is retired or renamed; the one clear-cut gap — the HTTP service's empty `Settings` — has a branch, and audio tags are the notable capability Pipecat still can't reach.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6969 — Expose HeyGen's speech controls on HeyGenHttpTTSService

### To consider
- **Audio tags** (medium, since 2026-11-23) — HeyGen performs 201 bracketed tags (`[laughs]`, `[whispers]`) on public and instant voices across all three models, and Pipecat has no HeyGen expression adapter in `src/pipecat/adapters/tts/services/`, so expressive-conversation markup reaches HeyGen as literal text. — *Needs a call: which tags map to the universal `ExpressionDelivery`/`ExpressionSound` names, and whether the adapter is selected by model or by voice, since professional voices perform none.*
- **Pronunciation dictionaries** (medium, since 2026-11-23) — `pronunciation_dictionary` (up to 100 term-to-IPA entries) is documented on the HTTP endpoint but is not a `Settings` field; a live request with it on the default public voice returned `400 invalid_parameter: Pronunciation supports instant voices on heygen-voice-1 and heygen-voice-1-turbo only`. — *Needs a call: whether to expose a field the default public voice rejects, plus an instant clone to probe it against.*
- **Sentence-to-sentence continuity** (low, since 2026-11-23) — `previous_request_ids` / `next_request_ids` let consecutive HTTP requests continue one another's prosody; `HeyGenHttpTTSService` synthesizes a sentence per request and keeps no request IDs. — *Needs a call: carrying IDs between requests is design work, not a pass-through field.*
