# HeyGen Video — 2026-09-01

HeyGen retired the Interactive Avatar streaming API that `HeyGenVideoService` still defaults to, and LiveAvatar deprecated the VP8 encoding Pipecat asks for; the branch fixes the second, the first needs a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5539 — Default LiveAvatar sessions to H264 video

### To consider
- **Legacy Interactive Avatar backend is dead** (high, since 2026-09-01) — `HeyGenVideoService` with no `service_type` argument builds a `HeyGenApi` against `https://api.heygen.com/v1/streaming.*`, and every one of those endpoints now returns a plain 404 while other HeyGen v1/v2/v3 endpoints answer normally with the same key. HeyGen announced the Interactive Avatar → LiveAvatar migration with a grace period ending 2026-03-31; the reference pages the module docstrings link to (`docs.heygen.com/reference/new-session`, `/reference/start-session`, `/reference/close-session`, `/reference/streaming-token`, `/docs/interactive-avatar-realtime-api`) are all 404. Pipecat's own examples and HeyGen's Pipecat plugin page both already pass `service_type=ServiceType.LIVE_AVATAR`, so the default is the only thing pointing at the dead API. — *Needs a call: flip the default to `LIVE_AVATAR`, or deprecate `ServiceType.INTERACTIVE_AVATAR` and `api_interactive_avatar.py` on the normal cycle.*
- **Unexposed LITE session fields** (medium, since 2026-09-01) — `max_session_duration` (seconds, capped by subscription tier) and `agora_config` (Agora instead of LiveKit as the avatar transport) are in LiveAvatar's LITE schema but not on `LiveAvatarNewSessionRequest`. Sending `max_session_duration` on a raw request is validated by the API, so it is a straight pass-through. — *Needs a call: the probe hit this account's 60 s sandbox cap so a non-default value is unverified, and nothing in Pipecat consumes an Agora-hosted avatar today.*
- **Commands sent before the session reports `connected`** (medium, since 2026-09-01) — LiveAvatar's LITE events page: "Wait for `session.state_updated` with state `connected` before sending any command events." `HeyGenClient` logs that event and nothing more; `agent.speak` goes out as soon as TTS audio is queued after the WebSocket opens. — *Needs a call: gating means buffering or dropping the first audio, which changes startup timing.*
- **`avatar_persona` on a LITE request does nothing** (low, since 2026-09-01) — LiveAvatar's LITE token schema has no `avatar_persona`; a probe request carrying one with a nonexistent `voice_id` still returned a session token. In LITE mode Pipecat supplies the audio, so voice, context and language belong to the pipeline, not the avatar. — *Needs a call: drop the field, or document it as FULL-mode only.*
- **`agent.speak_started` / `agent.speak_ended` unhandled** (low, since 2026-09-01) — both are documented LITE response events echoing the `event_id` of the `agent.speak` that triggered them; `_handle_ws_server_event` traces them as unknown and instead branches on `agent.state`, which is absent from LiveAvatar's current event list. — *Needs a call: whether avatar-speech metrics should come from these events rather than from the first `BotStartedSpeakingFrame` off the LiveKit track.*

## Verification

`probe.py run` has no video tier (exit 3), so these are ad-hoc calls: a sandbox LiveAvatar LITE session created through `LiveAvatarApi`, joined the way `HeyGenClient` joins it (LiveKit room, RGB24 conversion), held 12 s, then stopped.

| config | class | ok | latency | note |
| ------ | ----- | -- | ------- | ---- |
| LITE, encoding H264, quality high | LiveAvatarApi + livekit rtc | ✅ | first video frame 823 ms | 290 video frames, 1179 audio frames in 12 s, 1280x720, session start 1873 ms |
| LITE, encoding VP8, quality high | LiveAvatarApi + livekit rtc | ✅ | first video frame 980 ms | 285 video frames, 1194 audio frames in 12 s, 1280x720, session start 1515 ms |
| LITE + `max_session_duration=180` | LiveAvatarApi | ❌ | — | 400 `max_session_duration (180s) exceeds the maximum allowed (60s)` — field is real and validated, this account's cap is 60 s |
| LITE + `avatar_persona` (bogus voice_id) | raw `POST /v1/sessions/token` | ✅ | — | 200 with a session token: the field is accepted and ignored in LITE mode |
| `POST /v1/streaming.new` (Interactive Avatar, `Shawn_Therapist_public`, v2) | HeyGenApi endpoint | ❌ | — | HTTP 404 HTML; same for `streaming.create_token` and `streaming.stop`, while `/v2/avatars`, `/v1/voice.list` and `/v3/users/me` return 200 with the same key |
