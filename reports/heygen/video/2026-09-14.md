# HeyGen Video — 2026-09-14

LiveAvatar rebuilt the LITE WebSocket event envelope on 2026-09-08; the branch fixes the one event name the server now rejects and adds the `max_session_duration` session field, and the retired Interactive Avatar default is still the open decision.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5753 — Track LiveAvatar's LITE session updates

The previous run's H264 branch merged as https://github.com/pipecat-ai/pipecat/pull/5539, so the VP8 default is gone.

### To consider
- **Legacy Interactive Avatar backend is dead** (high, since 2026-09-01) — unchanged from the last run and re-probed today: `HeyGenVideoService` with no `service_type` argument builds a `HeyGenApi` against `https://api.heygen.com/v1/streaming.*`, and those endpoints return 404 while `/v2/avatars` answers 200 with the same key. Pipecat's examples and HeyGen's own Pipecat page both pass `service_type=ServiceType.LIVE_AVATAR`, so the default is the only thing pointing at the dead API. — *Needs a call: flip the default to `LIVE_AVATAR`, or deprecate `ServiceType.INTERACTIVE_AVATAR` and `api_interactive_avatar.py` on the normal cycle.*
- **`error` and `warning` events go nowhere** (medium, since 2026-09-14) — the 2026-09-08 envelope added both. A probe sent a bad command and got back `{"type": "error", "error": {"type": "invalid_request_error", ...}}`; `_handle_ws_server_event` has no branch for it and logs it at trace level as unknown. `warning` carries `video_starvation` when LiveAvatar's video generation cannot keep up with the audio Pipecat feeds it — the avatar visibly degrades and the pipeline never learns. — *Needs a call: whether these become `push_error` and with what fatality, given that `video_starvation` is expected under load and would be noisy as an `ErrorFrame`.*
- **Commands sent before the session reports `connected`** (medium, since 2026-09-01) — LiveAvatar's LITE events page still warns: "Wait for `session.state_updated` with state `connected` before sending any command events." `HeyGenClient` logs that event and nothing more; `agent.speak` goes out as soon as TTS audio is queued after the WebSocket opens. — *Needs a call: gating means buffering or dropping the first audio, which changes startup timing.*
- **`agora_config` unexposed** (low, since 2026-09-01) — the remaining LITE session field Pipecat cannot set; it swaps LiveKit for Agora as the avatar transport. — *Needs a call: nothing in Pipecat consumes an Agora-hosted avatar, so the field would be unreachable from the service.*
- **`avatar_persona` on a LITE request does nothing** (low, since 2026-09-01) — `LiteSDKSessionTokenConfigDataSchema` still has no `avatar_persona`. In LITE mode Pipecat supplies the audio, so voice, context and language belong to the pipeline. — *Needs a call: drop the field, or document it as FULL-mode only.*
- **`agent.speak_started` / `agent.speak_ended` unhandled** (low, since 2026-09-01) — both fired in order during the probe session, each echoing the utterance id as `source_event_id`, which is exactly the correlation TTFB metrics would want. Today TTFB stops on the first `BotStartedSpeakingFrame` decoded off the LiveKit track. — *Needs a call: whether avatar-speech metrics should come from these events instead.*
- **No 429 handling** (low, since 2026-09-14) — LiveAvatar began enforcing 10 req/s per API key and 5 req/s per session token on `sessions/start`, `stop` and `keep-alive` on 2026-09-01, returning 429 with `Retry-After`. `LiveAvatarApi._request` raises `LiveAvatarApiError` on any non-ok status, so a 429 while creating a session is a setup failure. — *Needs a call: whether the retry belongs in the service or in the application spawning sessions; one bot never approaches the limit.*

`probe.py run` has no video tier ("research-only, no probe"), so these are ad-hoc calls: one sandbox LiveAvatar LITE session, its WebSocket driven the way `HeyGenClient` drives it (speak, speak_end, interrupt), plus session-token requests.
