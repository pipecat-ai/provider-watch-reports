# Hume TTS — 2026-11-09

Hume's TTS API stops serving on 2026-11-13 and `HumeTTSService` is already deprecated for it (#6556, removal in 2.0.0) — nothing left to do for this unit; the one live item is Hume's unrelated Audio Decisions API, whose minimum clip length dropped to 1 second.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Audio Decisions minimum clip length** (medium, since 2026-11-09) — Hume's changelog (2026-11-07) and the decisions reference both now say a clip may be 1 second to 5 minutes, down from 5 seconds; `HumeAudioClassifier.min_audio_secs` still returns `5.0`, and the class docstring, the property docstring and `examples/expressive-conversation/expressive-conversation-hume-audio-decisions.py` all repeat the 5-second floor, so `PerceptionReader` keeps padding a short turn with the audio before it. This is the classifier, not the TTS service, and the inventory has no unit for it — hume/tts is the only Hume unit watched. — *Needs a call: whether a 1-second clip classifies well enough to drop the padding, since padding was a deliberate choice about what Hume hears.*

Dropped since last run: all five previous gaps (voice by name and `provider`, Octave version selection, the `hume>=0.11.2,<1` floor, websocket streaming input, generation `context`). Each was an improvement to an API that stops serving on 2026-11-13; the service is deprecated with no replacement, and the `hume` extra now exists for the classifier. The SDK pin is unchanged and still admits the latest release (0.14.1, 2026-08-17).
