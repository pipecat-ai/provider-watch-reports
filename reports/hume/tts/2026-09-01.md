# Hume TTS — 2026-09-01

No model or default drift: the service's Octave-version logic still matches Hume's documented constraint (`description` is Octave 1 only). One branch adds the `temperature` parameter Hume shipped in May 2026.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5540 — Add a temperature setting to HumeTTSService

### To consider
- **Voice by name and provider** (medium, since 2026-09-01) — `run_tts` always builds `PostedUtteranceVoiceWithId`, but Hume's utterance voice also accepts a name and a `provider` (`HUME_AI` / `CUSTOM_VOICE`); the docstring documents the ID-only restriction rather than lifting it. — *Needs a call: how one `voice` string expresses name vs id, and where `provider` would live.*
- **Octave version selection** (medium, since 2026-09-01) — the request version is inferred (`version = "1" if description else "2"`) and `Settings.model` is unused, so a caller cannot pin Octave 1 for a legacy voice nor opt out of the Octave 2 preview. — *Needs a call: whether `Settings.model` should carry `"1"`/`"2"` and which version the service defaults to.*
- **SDK floor** (medium, since 2026-09-01) — `hume>=0.11.2,<1` admits SDKs whose `synthesize_json_streaming` has neither `version` (0.11.7+) nor `include_timestamp_types` (0.12.0+), both of which the service passes on every request; `temperature` needs 0.13.13+. Latest is 0.14.1 (2026-08-17), inside the pin; the lockfile sits at 0.14.0. — *Needs a call: whether Pipecat raises extras floors to the SDK version the code actually calls.*
- **Websocket streaming input** (medium, since 2026-09-01) — one HTTP JSON stream per utterance; probes measured TTFB 720-760 ms where Hume advertises sub-200 ms for Octave 2 instant mode. `hume.tts.stream_input` is a persistent websocket for streaming text in and audio out. — *Needs a call: whether a websocket-backed Hume path is wanted; it is a connection lifecycle change, not a settings change.*
- **Generation context** (low, since 2026-09-01) — Hume's `context` (a prior `generation_id` or prior utterances) keeps prosody consistent across consecutive generations; every utterance is currently sent standalone. — *Needs a call: tracking generation ids across turns and clearing them on interruption.*
