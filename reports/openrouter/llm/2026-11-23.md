# OpenRouter LLM — 2026-11-23

Nothing moved in OpenRouter's favour this run: the `gpt-4.1` shutdown date stands, the successor OpenAI names still loses on both bump criteria, and no PR qualifies.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model retiring** (high, since 2026-09-01) — OpenAI's deprecations page is unchanged for this unit: `gpt-4.1` (`gpt-4.1-2025-04-14`) leaves the API on 2027-01-14, recommended replacement `gpt-6-luna`. On OpenRouter the slug is now served by two endpoints (OpenAI and Azure; the Azure Sweden Central endpoint present last run is gone), both at 100% uptime with no sunset notice, so the slug probably keeps working past that date even though a request routed to OpenAI will not. The designated successor still fails both bump criteria: aiewf-eval `aiwf_medium_context` puts `gpt-6-luna (low)` at 91.8% / 917 ms against `gpt-4.1` at 95.9% / 743 ms, and this run's probe measures 867 ms against 752 ms median TTFAT. The leaderboard is otherwise unchanged for the OpenAI rows; the models scoring above gpt-4.1 are `gpt-5.6-terra (medium)` 99.9%, `gpt-5.5 (none)` 98.2%, `gpt-5.4 (low)` 97.7% and `gpt-5.6-sol (none)` 96.9%, none of which OpenAI positions as gpt-4.1's successor. — *Needs a call: which successor to take when the designated one regresses and every candidate probes slower, and whether `OpenRouterLLMService` should track `OpenAILLMService`'s default rather than move on its own.*
- **Normalized `reasoning` field** (medium, since 2026-09-01) — `reasoning` with `effort: "none"` is the one knob that turns thinking off the same way across the catalogue, reachable today only through `extra={"extra_body": {"reasoning": ...}}`. The November 11 schema update confirms `context`, `enabled`, `exclude` and `mode` on `ChatRequest.reasoning`, alongside `effort`, `max_tokens` and `summary`, and `GET /models` publishes `supported_efforts`, `default_effort` and `mandatory` so a client can tell which models reject `none`. This bears on the item above: the model OpenAI names as our default's successor reasons by default. — *Needs a call: OpenAI-family models accept `reasoning_effort` through `extra` and OpenRouter documents it as a top-level shorthand for `reasoning.effort`, so a first-class field has to define which one wins.*
- **Model-level fallback** (medium, since 2026-09-01) — `models: [...]` lets OpenRouter retry the next model when the first errors; a long-running call would benefit, and the field is not reachable from `Settings`. The companion `route` field stays marked deprecated, superseded by `provider.sort.partition`, so only the array matters. — *Needs a call: how a fallback list should interact with `Settings.model` and with runtime model updates.*
- **`service_tier` has no Settings field** (medium, since 2026-10-28) — `BaseOpenAILLMService` puts `service_tier` in the request from the constructor argument it caches as `self._service_tier`; `OpenAILLMSettings` still carries no equivalent, so the only path is the deprecated `InputParams`/constructor one, it cannot be changed at runtime, and it disappears when `InputParams` is removed in 2.0.0. — *Needs a call: the field sits in the OpenAI base that every compatible service shares, so promoting it is a base-class change rather than an OpenRouter one.*
- **`plugins`** (low, since 2026-09-01) — a plain pass-through array with no `Settings` equivalent, spanning auto-router, auto-beta-router, pareto-router, switchyard-router, jev-router, moderation, web, web-fetch, file-parser, response-healing, context-compression, fusion, alignment and armor; `cost_quality_tradeoff` inside the router plugins remains deprecated in favour of `cost_tier`. — *Needs a call: whether a plugin list belongs in a voice pipeline, or stays an `extra` escape-hatch feature.*
- **Caching and sticky routing** (low, since 2026-10-12) — `prompt_cache_options` (`mode: explicit` plus a `ttl`), `prompt_cache_key`, `cache_control` and `session_id` affect cost and latency as a call's context grows, reachable today only through `extra`. — *Needs a call: whether prompt caching deserves first-class fields here rather than in the OpenAI base settings every compatible service shares.*
- **Stale docs example** (low, since 2026-09-01) — the API reference page still names `anthropic/claude-sonnet-4`, which is not in `GET /models`; OpenRouter's oldest Sonnet is `anthropic/claude-sonnet-4.5`. — *Needs a call: the page lives in pipecat-ai/docs and cannot be fixed from this repo.*

The catalogue grew from 428 slugs to 441, the additions being the `openai/gpt-6.2-astra` and `openai/gpt-6.2-sol` families and new third-party models; `openai/gpt-4.1` and every slug the service mentions are still served, and the service has no allowlist, so new slugs work as-is. The GPT-6.2 models are not positioned as gpt-4.1's successor and have no aiewf-eval row, so they do not bear on the default. OpenRouter's November breaking changes touch endpoints Pipecat does not call (`deferred_tools.scope` dropping `"client"`, workspace, guardrail, image and SCIM schemas) and the `ReasoningFormat` rename, which only affects clients comparing response strings. `OpenRouterLLMService` inherits from the chat-completions `OpenAILLMService`, which keeps no `_THINKING_DEFAULTS` table, so research step 2's reasoning-defaults check does not apply to this unit; the `reasoning` gap above is how thinking would be controlled here. Neither example pins a model literal, so both follow the default. No decisions are in force for this unit, and the digest comments carry none about it.
