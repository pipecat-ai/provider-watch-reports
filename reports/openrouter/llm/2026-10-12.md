# OpenRouter LLM — 2026-10-12

`openai/gpt-4.1` is healthy and not retiring; the one actionable item is a one-line fix for an error the merged `provider` setting logs on every service start.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6137 — Initialize OpenRouterLLMService's provider setting to None

### To consider
- **Normalized `reasoning` field** (medium, since 2026-09-01) — OpenRouter's `reasoning={enabled, effort, max_tokens, exclude}` is the one knob that turns thinking off the same way across all 458 catalogue models, which is what a voice pipeline wants; reaching it today requires `extra={"extra_body": {"reasoning": ...}}`. — *Needs a call: OpenAI-family models also accept `reasoning_effort` through `extra`, so a first-class field has to define which one wins.*
- **Model-level fallback** (medium, since 2026-09-01) — `models: [...]` lets OpenRouter retry the next model when the first errors; a long-running call would benefit, and the field is not reachable from `Settings`. The companion `route` field stays marked deprecated in the API reference, superseded by `provider.sort.partition`, so only the array matters. — *Needs a call: how a fallback list should interact with `Settings.model` and with runtime model updates.*
- **`plugins`** (low, since 2026-09-01) — a plain pass-through array (auto-router, auto-beta-router, moderation, web, file-parser, fusion, response-healing, context-compression, pareto-router, plus the beta alignment plugin) with no `Settings` equivalent. `transforms` no longer appears in the request schema; middle-out compression is now the `context-compression` plugin, so the pair of fields this item used to cover has become one. — *Needs a call: whether a plugin list belongs in a voice pipeline, or stays an `extra` escape-hatch feature.*
- **Default model age** (low, since 2026-09-01) — the catalogue added `openai/gpt-6-luna`, `openai/gpt-6-sol` and `openai/gpt-6.1-sol` this run, none of them benchmarked by aiewf-eval; `gpt-6.1-sol` probes at 1458 ms median TTFAT against gpt-4.1's 710 ms. gpt-4.1 stays GA, absent from OpenAI's deprecation table, and at 96.3% on `aiwf_medium_context`. — *Needs a call: whether quality alone justifies the latency cost, and whether this wrapper should track `OpenAILLMService`'s default (also gpt-4.1) instead of moving on its own.*
- **Caching and sticky routing** (low, since 2026-10-12) — `prompt_cache_options` and `session_id` are OpenRouter-side fields affecting cost and latency as a call's context grows, reachable today only through `extra`. — *Needs a call: whether prompt caching deserves first-class fields here rather than in the OpenAI base settings every compatible service shares.*
- **Stale docs examples** (low, since 2026-09-01) — the API reference page names `google/gemini-pro` and `anthropic/claude-sonnet-4-20250514`, neither of which is in `GET /models`. — *Needs a call: the page lives in pipecat-ai/docs and cannot be fixed from this repo.*

Closed since last run: the `provider` routing gap. PR #5550 merged on 2026-09-28, and `OpenRouterLLMSettings.provider` now carries OpenRouter's full provider-preference object.

The `provider` setting it added is what the branch fixes: `__init__` builds its defaults without it, so `Settings.validate_complete()` logs an error naming `provider` at every service start. The request body is identical either way.
