# OpenRouter LLM — 2026-10-28

OpenAI put `gpt-4.1` on a shutdown date (2027-01-14) this month; the replacement it names, `gpt-6-luna`, scores below gpt-4.1 on aiewf-eval and probes slower, so no default bump qualifies and the choice is a maintainer's.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model retiring** (high, since 2026-09-01) — OpenAI's deprecations page gained a GPT-4 series table on 2026-10-14: `gpt-4.1` (`gpt-4.1-2025-04-14`) is removed from the API on 2027-01-14, recommended replacement `gpt-6-luna`. On OpenRouter the slug is served by Azure as well as OpenAI, and Azure's gpt-4.1 lifecycle extends past that date, so the slug probably keeps working — but a request routed to the OpenAI endpoint will not. The designated successor is a regression on both axes the bump criteria use: aiewf-eval `aiwf_medium_context` puts `gpt-6-luna (low)` at 91.8% / 917 ms against `gpt-4.1` at 95.9% / 743 ms, and our own probe measures 1123 ms median TTFAT against 844 ms, widening to 2238 ms against 640 ms on a reasoning prompt where gpt-6-luna thinks for 811 ms. `gpt-5.6-sol (none)` is the nearest model scoring above gpt-4.1 (96.9% / 765 ms) and probes 958 ms, 13% worse. — *Needs a call: which successor to take when the designated one regresses and every candidate probes slower, and whether `OpenRouterLLMService` should track `OpenAILLMService`'s default rather than move on its own.*
- **Normalized `reasoning` field** (medium, since 2026-09-01) — `reasoning={enabled, effort, max_tokens, exclude}` with `effort: "none"` is the one knob that turns thinking off the same way across all 464 catalogue models, reachable today only through `extra={"extra_body": {"reasoning": ...}}`. This now bears on the item above: the model OpenAI names as our default's successor reasons by default. — *Needs a call: OpenAI-family models also accept `reasoning_effort` through `extra`, so a first-class field has to define which one wins.*
- **Model-level fallback** (medium, since 2026-09-01) — `models: [...]` lets OpenRouter retry the next model when the first errors; a long-running call would benefit, and the field is not reachable from `Settings`. The companion `route` field stays marked deprecated, superseded by `provider.sort.partition`, so only the array matters. — *Needs a call: how a fallback list should interact with `Settings.model` and with runtime model updates.*
- **`service_tier` has no Settings field** (medium, since 2026-10-28) — `BaseOpenAILLMService` puts `service_tier` in the request from the constructor argument it caches as `self._service_tier`; `OpenAILLMSettings` carries no equivalent, so the only path is the deprecated `InputParams`/constructor one, it cannot be changed at runtime, and it disappears when `InputParams` is removed in 2.0.0. OpenRouter adds `fast`, `scale` and `ultrafast` to OpenAI's tier vocabulary, and `service_tier=ultrafast` probes fine. — *Needs a call: the field sits in the OpenAI base that every compatible service shares, so promoting it is a base-class change rather than an OpenRouter one.*
- **`plugins`** (low, since 2026-09-01) — a plain pass-through array with no `Settings` equivalent; the roster has grown to auto-router, auto-beta-router, moderation, web, web-fetch, file-parser, fusion, response-healing, context-compression, pareto-router, switchyard-router, jev-router, alignment and armor, and `cost_quality_tradeoff` inside it is now deprecated in favour of `cost_tier`. — *Needs a call: whether a plugin list belongs in a voice pipeline, or stays an `extra` escape-hatch feature.*
- **Caching and sticky routing** (low, since 2026-10-12) — `prompt_cache_options` (which gained a `ttl` of `30m` or `12h` on 2026-10-21), `prompt_cache_key`, `cache_control` and `session_id` affect cost and latency as a call's context grows, reachable today only through `extra`. — *Needs a call: whether prompt caching deserves first-class fields here rather than in the OpenAI base settings every compatible service shares.*
- **Stale docs example** (low, since 2026-09-01) — the API reference page names `anthropic/claude-sonnet-4`, which is not in `GET /models`; OpenRouter's oldest Sonnet is now `anthropic/claude-sonnet-4.5`. The page's `google/gemini-pro` example has been corrected to `google/gemini-2.5-pro`, which is live. — *Needs a call: the page lives in pipecat-ai/docs and cannot be fixed from this repo.*

Closed since last run: the `provider` NOT_GIVEN error. PR #6137 merged on 2026-10-13, and `__init__` now builds its defaults with `provider=None`, so `Settings.validate_complete()` no longer logs at service start. The previous report's "default model age" item is the same gap as the first item above, now carrying a date.

`OpenRouterLLMService` inherits from the chat-completions `OpenAILLMService`, which keeps no `_THINKING_DEFAULTS` table, so research step 2's reasoning-defaults check does not apply to this unit; the `reasoning` gap above is how thinking would be controlled here.
