# OpenRouter LLM — 2026-11-09

Nothing changed in OpenRouter's favour this run: the `gpt-4.1` shutdown date stands, the successor OpenAI names still loses on both bump criteria, and no PR qualifies.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model retiring** (high, since 2026-09-01) — OpenAI's deprecations page is unchanged since the 2026-10-14 entry: `gpt-4.1` (`gpt-4.1-2025-04-14`) leaves the API on 2027-01-14, recommended replacement `gpt-6-luna`. On OpenRouter the slug is served by OpenAI, Azure and Azure Sweden Central, all at 100% uptime with no sunset notice, so the slug probably keeps working past that date even though a request routed to OpenAI will not. The designated successor still fails both bump criteria: aiewf-eval `aiwf_medium_context` puts `gpt-6-luna (low)` at 91.8% / 917 ms against `gpt-4.1` at 95.9% / 743 ms, and this run's probe measures 926 ms against 738 ms median TTFAT. The leaderboard has gained `gpt-5.4 (low)` at 97.7% / 932 ms and `gpt-5.6-terra (none)` at 92.7%; the models scoring above gpt-4.1 are `gpt-5.6-terra (medium)` 99.9%, `gpt-5.5 (none)` 98.2%, `gpt-5.4 (low)` 97.7% and `gpt-5.6-sol (none)` 96.9%, none of which OpenAI positions as gpt-4.1's successor. — *Needs a call: which successor to take when the designated one regresses and every candidate probes slower, and whether `OpenRouterLLMService` should track `OpenAILLMService`'s default rather than move on its own.*
- **Normalized `reasoning` field** (medium, since 2026-09-01) — `reasoning={enabled, effort, max_tokens, exclude}` with `effort: "none"` is the one knob that turns thinking off the same way across the catalogue, reachable today only through `extra={"extra_body": {"reasoning": ...}}`. It has grown `context` (`auto`/`all_turns`/`current_turn`) and `mode` (`standard`/`pro`) for GPT-5.6 and newer, and `GET /models` now publishes per-model `supported_efforts`, `default_effort`, `default_enabled`, `supports_max_tokens` and `mandatory`, so a client can tell which models reject `none`. This still bears on the item above: the model OpenAI names as our default's successor reasons by default. — *Needs a call: OpenAI-family models accept `reasoning_effort` through `extra` and OpenRouter now documents it as a top-level shorthand for `reasoning.effort`, so a first-class field has to define which one wins.*
- **Model-level fallback** (medium, since 2026-09-01) — `models: [...]` lets OpenRouter retry the next model when the first errors; a long-running call would benefit, and the field is not reachable from `Settings`. The companion `route` field stays marked deprecated, superseded by `provider.sort.partition`, so only the array matters. — *Needs a call: how a fallback list should interact with `Settings.model` and with runtime model updates.*
- **`service_tier` has no Settings field** (medium, since 2026-10-28) — `BaseOpenAILLMService` puts `service_tier` in the request from the constructor argument it caches as `self._service_tier`; `OpenAILLMSettings` still carries no equivalent, so the only path is the deprecated `InputParams`/constructor one, it cannot be changed at runtime, and it disappears when `InputParams` is removed in 2.0.0. — *Needs a call: the field sits in the OpenAI base that every compatible service shares, so promoting it is a base-class change rather than an OpenRouter one.*
- **`plugins`** (low, since 2026-09-01) — a plain pass-through array with no `Settings` equivalent, spanning auto-router, auto-beta-router, pareto-router, switchyard-router, jev-router, moderation, web, web-fetch, file-parser, response-healing, context-compression, fusion, alignment and armor; `cost_quality_tradeoff` inside the router plugins remains deprecated in favour of `cost_tier`. — *Needs a call: whether a plugin list belongs in a voice pipeline, or stays an `extra` escape-hatch feature.*
- **Caching and sticky routing** (low, since 2026-10-12) — `prompt_cache_options` (`mode: explicit`, `ttl` of `30m` or `12h`, OpenAI GPT-5.6 and newer), `prompt_cache_key`, `cache_control` and `session_id` affect cost and latency as a call's context grows, reachable today only through `extra`. — *Needs a call: whether prompt caching deserves first-class fields here rather than in the OpenAI base settings every compatible service shares.*
- **Stale docs example** (low, since 2026-09-01) — the API reference page still names `anthropic/claude-sonnet-4`, which is not in `GET /models`; OpenRouter's oldest Sonnet is `anthropic/claude-sonnet-4.5`. — *Needs a call: the page lives in pipecat-ai/docs and cannot be fixed from this repo.*

The catalogue shrank from 464 slugs to 428 this run, mostly older snapshots; `openai/gpt-4.1` and every slug the service or its examples mention are still served. `OpenRouterLLMService` inherits from the chat-completions `OpenAILLMService`, which keeps no `_THINKING_DEFAULTS` table, so research step 2's reasoning-defaults check does not apply to this unit; the `reasoning` gap above is how thinking would be controlled here. Neither example pins a model literal, so both follow the default. No decisions are in force for this unit, and the digest comments carry none about it.
