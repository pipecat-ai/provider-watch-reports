# Qwen LLM — 2026-11-09

`qwen-turbo` has stopped serving — every call returns 429 while sibling models answer normally — so
the turn-completion manifest row is dead, not just doomed; nothing else about the service changed.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`qwen-turbo` is decommissioned and the manifest row no longer runs** (high, since 2026-10-12) —
  `evals/turn-completion/manifest.yaml` still runs a `qwen/qwen-turbo` row through
  `QwenLLMService`. Three probes of `qwen-turbo` — one interleaved, two isolated 45 s and 65 s
  later — all returned HTTP 429 "You have exceeded your current request limit", while `qwen-plus`
  and `qwen-flash` on the same key answered normally in the same window. That is the state
  Alibaba's decommission policy describes: a retired model's QPM/TPM is wound down before the id
  stops resolving. On 2026-10-12 the same probe still returned a completion at 979 ms, so this is
  new since last run. Alibaba names no single successor, only "the latest Qwen3.7/3.6 series
  models"; `qwen-flash` is the surviving alias at the same tier (TTFAT 647 ms). — *Needs a call:
  drop the row or repoint it, and to which model — swapping a benchmark row changes what the corpus
  measures.*
- **Default `qwen-plus` trails the current generation** (medium, since 2026-09-01) — nothing moved.
  The alias is still equivalent to `qwen-plus-2025-12-01`, has no deprecation notice, keeps thinking
  off by default and probed at 946 ms TTFAT. Alibaba has released no new text model since
  `qwen3.8-max-0902`; the September and October entries on the new-models page are omni, audio and
  image. aiewf-eval's medium-context leaderboard was rejudged on 2026-10-19 but still has no
  DashScope-hosted row at all. — *Needs a call: which successor to adopt, and whether a hosted model
  with no aiewf-eval row can replace a default that has no row either.*
- **Thinking has no first-class control** (medium, since 2026-09-01) — the deep-thinking page's
  default-on list now covers the whole 3.5-3.8 plus/flash/max line plus `qwen3.8-omni-flash`, and
  `enable_thinking` / `thinking_budget` remain non-standard parameters reachable from the Python SDK
  only through `extra_body`; `reasoning_effort` is documented for `qwen3.8-omni-flash` alone. The
  cost shows on the dense tier a Pipecat example might pick: `qwen3.8-27b` spent 577 ms thinking on
  "What is the capital of France?", TTFAT 1467 ms against 946 ms for `qwen-plus`. The workaround
  (`extra={"extra_body": {"enable_thinking": False}}`) still works and is still undiscoverable. Any
  default bump depends on settling this, as do the aiewf-eval rows, which are all thinking-off. —
  *Needs a call: add `enable_thinking`/`thinking_budget` Settings fields, or follow
  pipecat-ai/pipecat#5446's Anthropic precedent and disable thinking by default for thinking-capable
  Qwen models.*
- **Two examples pin `qwen3.6-27b`** (low, since 2026-09-01) —
  `examples/function-calling/function-calling-qwen.py` and `examples/update-settings/llm/llm-qwen.py`.
  The model still serves and is on no retirement list. aiewf-eval rejudged both dense rows under its
  2026-10-19 recovery-context migration: `qwen3.8-27b` 96.0% and `qwen3.6-27b` 92.1% on
  `aiwf_medium_context`, both thinking off — the gap is wider than the 98.2 / 97.3 the previous
  report quoted. — *Needs a call: whether examples track the newest dense model, and it carries the
  same thinking-off question.*
