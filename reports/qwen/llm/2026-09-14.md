# Qwen LLM — 2026-09-14

Nothing broke and nothing retired, but the case for moving off `qwen-plus` firmed up: Alibaba's
docs now hand the "balanced" recommendation to `qwen3.8-flash`. Still no branch — the same two
questions block it.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Default `qwen-plus` is four generations behind** (medium, since 2026-09-01) — the alias still
  resolves to `qwen-plus-2025-07-28`, a Qwen3-generation snapshot. What changed since the last run:
  Alibaba's model pages now position `qwen3.8-flash` (GA 2026-08-26) as the balanced
  general-purpose choice, the slot `qwen-plus` used to hold. `qwen-plus` is still documented,
  still serves, and appears on no retirement list, and aiewf-eval's medium-context leaderboard
  still has no row for it or for any DashScope-hosted plus/max/flash tier — its only Qwen rows are
  self-hosted dense models. — *Needs a call: which successor to adopt, and whether a hosted model
  with no aiewf-eval row can replace a default that has no row either.*
- **Thinking is on by default on every Qwen3.5+ model** (medium, since 2026-09-01) — the candidate
  successor behaves like the rest: `qwen3.8-flash` spent 372 ms thinking on "What is the capital of
  France?", against 0 ms for `qwen-plus`, and earlier probes put `qwen3.7-plus` at 1897 ms on the
  same prompt and `qwen3.8-27b` at 4981 ms on an arithmetic one. DashScope takes `enable_thinking`
  in `extra_body`, reachable today only as
  `settings=QwenLLMService.Settings(extra={"extra_body": {"enable_thinking": False}})` — it works
  (qwen3.8-flash thinking 372 ms → 0 ms) but is undiscoverable. Any default bump depends on
  settling this, as do the aiewf-eval rows, which are all "thinking off". — *Needs a call: add an
  `enable_thinking` Settings field, or follow pipecat-ai/pipecat#5446's Anthropic precedent and
  disable thinking by default for thinking-capable Qwen models.*
- **Function-calling example pins `qwen3.6-27b`** (low, since 2026-09-01) — the model still serves;
  its successor `qwen3.8-27b` scores 98.2% on aiewf-eval's `aiwf_medium_context` against 97.3% for
  `qwen3.6-27b`, both thinking off. — *Needs a call: whether examples track the newest dense model,
  and it carries the same thinking-off question.*

The previous report's note that our `openai` pin trailed a major no longer holds: the pin now reads
`openai>=1.74.0,<4` and PyPI's latest is 3.13.0. It was never a Qwen-specific gap.
