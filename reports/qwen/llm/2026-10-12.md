# Qwen LLM — 2026-10-12

The 2026-10-10 retirement wave spared everything the Qwen service ships, and `qwen-plus` quietly
got younger — but the wave took `qwen-turbo`, which our turn-completion manifest still calls.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`qwen-turbo` is decommissioned and still referenced** (medium, since 2026-10-12) —
  `evals/turn-completion/manifest.yaml` runs a `qwen/qwen-turbo` row through `QwenLLMService`.
  `qwen-turbo` was in the intl catalogue on 2026-09-14 and is absent today; Alibaba's depreciation
  table puts it in the 2026-10-10 batch together with `qwq-plus`, `qwen-vl-max` and `qwen-vl-plus`
  (all of which also vanished from the catalogue). The endpoint still answers — a probe returned a
  normal completion at 979 ms TTFAT — so nothing is broken yet, but the row will start failing
  whenever the intl region finishes the sunset. Alibaba names no single successor, only "the latest
  Qwen3.7/3.6 series models"; `qwen-flash` is the surviving alias at the same tier. — *Needs a call:
  drop the row or repoint it, and to which model — swapping a benchmark row changes what the corpus
  measures.*
- **Default `qwen-plus` trails the current generation** (medium, since 2026-09-01) — less stale than
  it read last run: the alias page now says `qwen-plus` is functionally equivalent to
  `qwen-plus-2025-12-01`, where the 2026-09-14 report found 2025-07-28. It is still a
  Qwen3-generation snapshot while Alibaba ships 3.8, but it is on no retirement list, still keeps
  thinking off by default (probe: 0 ms thinking on both a trivial and an arithmetic prompt), and is
  the faster of the two candidates measured below. aiewf-eval's medium-context leaderboard is
  unchanged and still carries no DashScope-hosted row at all. — *Needs a call: which successor to
  adopt, and whether a hosted model with no aiewf-eval row can replace a default that has no row
  either.*
- **Thinking has no first-class control** (medium, since 2026-09-01) — Alibaba's deep-thinking page
  now spells out the default-on list (`qwen3.8-max`, `qwen3.8-flash`, `qwen3.8-27b`, and the
  3.5/3.6/3.7 plus and flash tiers) and documents two parameters the OpenAI SDK can only pass in
  `extra_body`: `enable_thinking` and `thinking_budget`. The cost is visible — `qwen3.8-flash` spent
  511 ms thinking on "What is the capital of France?" and 1267 ms on a bat-and-ball prompt, pushing
  TTFAT to 1716 ms and 2397 ms against 1070 ms and 1125 ms for `qwen-plus`. The workaround still
  works (`extra={"extra_body": {"enable_thinking": False}}` → 1107 ms, 0 ms thinking) and is still
  undiscoverable. Any default bump depends on settling this, as do the aiewf-eval rows, which are
  all thinking-off. — *Needs a call: add `enable_thinking`/`thinking_budget` Settings fields, or
  follow pipecat-ai/pipecat#5446's Anthropic precedent and disable thinking by default for
  thinking-capable Qwen models.*
- **Two examples pin `qwen3.6-27b`** (low, since 2026-09-01) —
  `examples/function-calling/function-calling-qwen.py` and `examples/update-settings/llm/llm-qwen.py`
  (the previous report counted only the first). The model still serves and survived the 2026-10-10
  wave; its successor `qwen3.8-27b` scores 98.2% on aiewf-eval's `aiwf_medium_context` against 97.3%
  for `qwen3.6-27b`, both thinking off. — *Needs a call: whether examples track the newest dense
  model, and it carries the same thinking-off question.*
