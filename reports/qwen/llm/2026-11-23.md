# Qwen LLM — 2026-11-23

`qwen-turbo` has finished retiring — the id 404s — and Alibaba's new flagship `qwen4-max` reasons by
default and probes slower than `qwen-plus`, so the service's default does not move.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`qwen-turbo` is gone and the manifest row 404s** (high, since 2026-10-12) —
  `evals/turn-completion/manifest.yaml` still runs a `qwen/qwen-turbo` row through
  `QwenLLMService`. The probe now returns HTTP 404 "Model not exist", the end state of the
  decommission this item has tracked for three runs (completion at 979 ms on 2026-10-12, HTTP 429 on
  2026-11-09, 404 today). Alibaba's `qwen-turbo` documentation page no longer mentions the model,
  and the model overview's recommended text lineup is `qwen4-max` / `qwen3.7-plus` /
  `qwen3.8-flash`. `qwen-flash` remains the surviving alias at the same tier. — *Needs a call: drop
  the row or repoint it, and to which model — swapping a benchmark row changes what the corpus
  measures.*
- **Default `qwen-plus` trails the current generation** (medium, since 2026-09-01) — Alibaba shipped
  `qwen4-max` on 2026-11-16 (`qwen4-max-preview` on 2026-11-11), its first new Qwen text model since
  `qwen3.8-max-0902`, and the model overview now recommends `qwen4-max`, `qwen3.7-plus` and
  `qwen3.8-flash` without listing `qwen-plus`. `qwen-plus` itself did not change: equivalent to
  `qwen-plus-2025-12-01`, no deprecation notice, thinking off by default, 1061 ms TTFAT. Neither
  candidate is a latency-safe swap — `qwen4-max` 1761 ms TTFAT (2023 ms even with thinking forced
  off), `qwen3.7-plus` 4018 ms with 2609 ms of thinking — and aiewf-eval's medium-context
  leaderboard still has no DashScope-hosted row of any kind. — *Needs a call: which successor to
  adopt, and whether a hosted model with no aiewf-eval row can replace a default that has no row
  either.*
- **Thinking has no first-class control** (medium, since 2026-09-01) — this is now what blocks the
  default: every model Alibaba recommends reasons by default, and the thinking-off aliases are the
  ones dropping off the recommendation list. `qwen4-max`'s model page documents `reasoning_effort`
  (`low` | `high` | `xhigh`, default `high`) next to `enable_thinking` (default `true`) and
  `thinking_budget` (default 131072), while the deep-thinking page documents `reasoning_effort` for
  `qwen3.8-omni-flash` alone; `Settings` exposes none of them, and `enable_thinking` /
  `thinking_budget` remain non-standard parameters the OpenAI SDK can only carry in `extra_body`.
  The workaround `extra={"extra_body": {"enable_thinking": False}}` turns `qwen4-max` thinking off
  (thinking 0 ms, probed) and is still undiscoverable. — *Needs a call: add
  `enable_thinking`/`thinking_budget` Settings fields, or follow pipecat-ai/pipecat#5446's Anthropic
  precedent and disable thinking by default for thinking-capable Qwen models.*
- **Two examples pin `qwen3.6-27b`** (low, since 2026-09-01) —
  `examples/function-calling/function-calling-qwen.py` and `examples/update-settings/llm/llm-qwen.py`.
  The model still serves and is on no retirement list, but it reasons by default: 2418 ms of
  thinking on "What is the capital of France?", TTFAT 3628 ms, which is what an example user feels
  first. aiewf-eval's rows are unchanged — `qwen3.8-27b` 96.0% against `qwen3.6-27b` 92.1% on
  `aiwf_medium_context`, both thinking off. — *Needs a call: whether examples track the newest dense
  model, and it carries the same thinking-off question.*
