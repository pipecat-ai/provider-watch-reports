# OpenAI Live (realtime) — 2026-10-12

`gpt-live-1` is still the only live model OpenAI publishes and carries no deprecation notice, so the default stands; the one change this run is a branch adding the `store` session field, which this account now permits and which probes end to end.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6135 — Add a store setting to OpenAILiveLLMService

### To consider

- **Mid-session developer and system messages go nowhere** (medium, since 2026-09-14) — `_handle_context` forwards nothing from a context after the first, because user and assistant messages there cannot be distinguished from the service's own transcript recordings. Developer and system messages can only come from the app, and the docs make `instructions` appendable for the life of a session; `events.SessionInstructionsAppendEvent` exists and the service never sends it, so an app injecting context mid-call is silently ignored. — *Needs a call: whether to diff each incoming context for new developer/system messages, and whether they belong in instructions or in the thinking channel.*
- **No server-side input mute** (low, since 2026-09-14) — `session.input_audio.mute` / `.unmute` and their acknowledgments are absent from events.py, so pausing input means the pipeline stopping audio, which leaves a gap in the session timeline rather than a mute the server confirms. — *Needs a call: whether withholding audio is good enough, and if not whether the surface is a service method or a frame.*
- **Sessions are always 24 kHz PCM16** (low, since 2026-09-14) — `events.AudioFormat` covers `audio/pcm`, `audio/pcmu` and `audio/pcma`, but `audio.format` is never sent; input is resampled to 24 kHz and output frames are hard-coded to it, so a telephony bot resamples G.711 in both directions. — *Needs a call: whether an 8 kHz G.711 session justifies threading the format through the input resampler and the output frame rate.*
- **No session forking** (low, since 2026-09-14) — a stored session is resumed by connecting to `.../v1/live/sessions/{id}/fork`, which restores saved state and can override `store`, the delegation settings and the audio format; `reset_conversation` opens a fresh session seeded from the context instead. With `store` on the branch, the blocker left is identity: the service keeps the id from `session.started` to itself. — *Needs a call: where a fork's source session id comes from and how an app hands it back.*

The stored-session row answers the previous run's two open questions: this project's data policy now permits persistence (`store: true` no longer fails with `session_storage_not_allowed`), and a stored session finalizes in 2.4 s, well inside `SESSION_CLOSE_TIMEOUT_SECS` (10 s), so no timeout change is needed. `probe.py` classifies the unit as `realtime` now, so its check is connect-only and reports no latency; the ad-hoc script is what drives a real spoken turn.
