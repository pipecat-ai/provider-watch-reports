# OpenAI LLM — 2026-09-14

gpt-4.1 stays the default — gpt-6-astra is GA but five times slower on a short turn — and `temperature`/`max_tokens` still 400 on everything OpenAI currently recommends.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`temperature` and `max_tokens` 400 on current models** (high, since 2026-09-01) — `Settings.temperature=0.7` returns `unsupported_value` ("Only the default (1) value is supported") and `Settings.max_tokens=200` returns `unsupported_parameter` ("Use 'max_completion_tokens' instead"); the pipeline then marks the service unusable. Re-probed today on gpt-5.6-terra and on the new gpt-6-astra — both reject temperature, so the whole recommended lineup is affected. Both fields are inherited `LLMSettings`, so any user who sets them and picks a current model hits this. — *Needs a call: whether the service should drop `temperature` and map `max_tokens` to `max_completion_tokens` for reasoning models, or surface a clearer error.*
- **Default is a generation behind** (medium, since 2026-09-01) — OpenAI's models page now leads with gpt-6-astra (GA 2026-09-03, flagship) alongside gpt-5.6-sol/terra/luna; gpt-4.1 does not appear, though it is not deprecated and the API still serves it. astra is not a voice candidate: 2701 ms median TTFAT against gpt-4.1's 521 ms on a trivial turn, it is $10/$50 per Mtok, and aiewf-eval has not benchmarked it (so it is re-checked, not ruled out, when a row appears). The live candidate is unchanged from last run: aiewf-eval medium-context has gpt-5.6-terra (medium) at 97.8% / 927 ms vs gpt-4.1 at 96.3% / 536 ms, luna (none) at 88.3%, below the current default. — *Needs a call: whether roughly doubled TTFAT on short turns buys enough quality, and which gpt-5.6 tier becomes the default.*
- **No typed reasoning-effort setting** (low, since 2026-09-14) — `reasoning_effort` is reachable only through `Settings.extra`, which is how last run's latency probes had to set it; the Responses service has a typed `reasoning` field instead. — *Needs a call: `OpenAILLMService.Settings` is `BaseOpenAILLMService.Settings`, shared by every OpenAI-compatible service, and the accepted values differ per model (gpt-6-astra has no `none`) and per provider, so a pass-through field needs a decision on where it belongs.*
- **gpt-4o pinned in an example** (low, since 2026-09-01) — `examples/transports/transports-moq.py` is the only example that passes `model=` to `OpenAILLMService`, and it names gpt-4o. — *Needs a call: whether examples should pin a model at all rather than track the service default.*

Closed since the last report: the SDK pin item. `pyproject.toml` now reads `openai>=1.74.0,<4` (PR 5620, "Support the openai 3 SDK"), which admits the current 3.13.0, so the HTTPX2 blocker is gone.
