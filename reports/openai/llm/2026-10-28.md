# OpenAI LLM — 2026-10-28

gpt-4.1 now has a shutdown date, 2027-01-14, and OpenAI names gpt-6-luna as its replacement — but gpt-6-luna scores below gpt-4.1 on aiewf-eval, so which model takes over is a maintainer's call that has a deadline on it.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6433 — Stop pinning a retiring model in the MoQ transport example

### To consider

- **Default gpt-4.1 shuts down 2027-01-14** (high, since 2026-09-01) — raised from medium: the September finding was that gpt-4.1 had dropped off the models page; OpenAI has now dated its removal. The deprecations table reads `GPT-4.1 (gpt-4.1-2025-04-14) → gpt-6-luna`, with developers notified on 2026-10-14. `gpt-4.1` is the alias for that one snapshot, so the default stops resolving on that date. The named replacement is not a drop-in: gpt-6-luna sits at 91.8% / 917 ms (low effort) on aiewf-eval medium-context against gpt-4.1's 95.9% / 743 ms, and its `none` configuration completed 0 of 30 conversations, so the rule in #5447 blocks the bump. Our own probes agree on latency — 1166 ms vs 589 ms median TTFAT on a trivial turn, 1767 ms vs 532 ms on a reasoning-triggering one. The alternatives: gpt-6.1-terra, released 2026-10-26 at $1/$5 and the only GPT-6 tier besides Luna that accepts `none` effort, which aiewf-eval has not benchmarked (869 ms / 1065 ms median TTFAT here); or gpt-5.6-terra at medium effort, benchmarked at 99.9% / 1004 ms but from the GPT-5 generation OpenAI is retiring tier by tier. — *Needs a call: which model replaces gpt-4.1 before 2027-01-14 — the named gpt-6-luna at a lower pass rate, the unbenchmarked gpt-6.1-terra, or gpt-5.6-terra.*
- **`temperature` and `max_tokens` 400 on current models** (high, since 2026-09-01) — `Settings.temperature=0.7` returns `unsupported_value` ("Only the default (1) value is supported") and `Settings.max_tokens=200` returns `unsupported_parameter` ("Use 'max_completion_tokens' instead"); the pipeline then marks the service unusable. Re-probed today on gpt-6.1-terra, OpenAI's newest chat model, so the finding covers the whole recommended lineup. Both fields are inherited `LLMSettings`, so any user who sets them and picks a current model hits this — and the retirement above pushes everyone onto those models. — *Needs a call: whether the service should drop `temperature` and map `max_tokens` to `max_completion_tokens` for reasoning models, or surface a clearer error.*
- **No typed reasoning-effort setting** (medium, since 2026-09-14) — with the recommended lineup reasoning by default, effort is what decides whether a model can hold a voice turn, and the only way to reach it is the untyped `extra` dict: `extra={"reasoning_effort": "none"}` takes gpt-6.1-terra from 1065 ms to 887 ms median TTFAT on the same prompt. The Responses service has a typed `reasoning` field instead. — *Needs a call: `OpenAILLMService.Settings` is `BaseOpenAILLMService.Settings`, shared by every OpenAI-compatible service, and the accepted values differ per model (gpt-6-astra and gpt-6.1-sol have no `none`) and per provider, so a pass-through field needs a decision on where it belongs.*

Nothing from the previous report is unaccounted for. The `service_tier: "ultrafast"` tier added in October stays Responses- and Agents-only: chat completions rejects it with `Invalid service_tier argument`, so the service's docstring list is still right.
