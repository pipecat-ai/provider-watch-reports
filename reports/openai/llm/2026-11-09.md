# OpenAI LLM — 2026-11-09

Nothing moved: gpt-4.1 still retires on 2027-01-14, gpt-6-luna is still the named replacement and still scores below it, and aiewf-eval still has no gpt-6.1-terra row — so the successor is the same open call, now two months from the deadline.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6658 — Stop naming a retiring model in OpenAI LLM usage examples

### To consider

- **Default gpt-4.1 shuts down 2027-01-14** (high, since 2026-09-01) — the deprecations page is unchanged: `GPT-4.1 (gpt-4.1-2025-04-14) → gpt-6-luna`, announced 2026-10-14, and `gpt-4.1` is the alias for that one snapshot. The leaderboard was re-read today and still has no row for gpt-6.1-terra, so the bump candidates are the same three: gpt-6-luna (91.8% / 917 ms at low, `none` completed 0 of 30) against gpt-4.1's 95.9% / 743 ms, which #5447's rule blocks; gpt-6.1-terra, unbenchmarked; or gpt-5.6-terra at medium, 99.9% / 1004 ms, from the GPT-5 generation. Latency re-measured here agrees with last run's ordering. Whatever is chosen also settles the `gpt-4.1` pins in `evals/turn-completion/manifest.yaml` and the flows examples, which go on the same date. — *Needs a call: which model replaces gpt-4.1 before 2027-01-14.*
- **`temperature` and `max_tokens` 400 on current models** (high, since 2026-09-01) — `Settings.temperature=0.7` returns `unsupported_value` and `Settings.max_tokens=200` returns `unsupported_parameter`; both are inherited `LLMSettings`, both 400s are classified permanent, and the worker then marks the service unusable for the session. The 2026-11-05 content-filter fix (#6565) only exempts `content_filter`. Re-probed today on gpt-6.1-terra. — *Needs a call: drop `temperature` and map `max_tokens` to `max_completion_tokens` for reasoning models, or surface a clearer error.*
- **No typed reasoning-effort setting** (medium, since 2026-09-14) — on a reasoning-triggering prompt gpt-6.1-terra takes 3173 ms median TTFAT at its default effort and 808 ms with `extra={"reasoning_effort": "none"}` — a 2.4 s gap reachable only through the untyped `extra` dict. The Responses service has a typed `reasoning` field. — *Needs a call: `BaseOpenAILLMService.Settings` is shared by every OpenAI-compatible service and the accepted values differ per model and per provider, so a pass-through field needs a decision on where it belongs.*
- **`pipecat eval`'s OpenAI default is gpt-4o** (medium, since 2026-11-09) — `DEFAULT_OPENAI_MODEL = "gpt-4o"` in `src/pipecat/evals/services.py` backs any judge, classifier or persona block that names `service: openai` without a model, and gpt-4o goes on 2027-01-14 with the rest of the GPT-4 series. It is a one-line constant, but it decides eval verdicts, which is why it is not on the branch. — *Needs a call: which model judges and plays personas once gpt-4o is gone.*

The MoQ example pin from the previous report is closed: #6433 merged on 2026-10-28. Nothing else from that report is unaccounted for. No new chat-completions parameters appeared in the October–November changelog; gpt-6-rosalind (2026-10-30) and gpt-6-cyber (2026-11-05) are access-restricted specialist models and do not show in the catalogue.
