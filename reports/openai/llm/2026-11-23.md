# OpenAI LLM — 2026-11-23

GPT-6.2 landed as OpenAI's recommended lineup and is unusable for function calling through this class — which removes it as a successor candidate rather than adding one; gpt-4.1 still retires on 2027-01-14 with nothing benchmarked to replace it.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Default gpt-4.1 shuts down 2027-01-14** (high, since 2026-09-01) — the deprecations page is unchanged: `GPT-4.1 (gpt-4.1-2025-04-14) → gpt-6-luna`. GPT-6.2 Astra and Sol (2026-11-17) are now OpenAI's recommended tier, and the models page says to start with Astra, but both reject function tools on chat completions (see below), so neither can be this service's default. The leaderboard was re-read today and still has no row for any gpt-6.1 or gpt-6.2 model, so the candidates are the same three as a fortnight ago: gpt-6-luna (91.8% / 917 ms at low, `none` completed 0 of 30) against gpt-4.1's 95.9% / 743 ms, which #5447's rule blocks; gpt-6.1-terra, unbenchmarked; or gpt-5.6-terra at medium, 99.9% / 1004 ms, from the generation OpenAI is retiring tier by tier. Latency measured here puts gpt-4.1 at 459 ms against gpt-6.2-sol's 1053 ms and gpt-6.2-astra's 1481 ms. Seven weeks left. — *Needs a call: which model replaces gpt-4.1 before 2027-01-14.*
- **`temperature` and `max_tokens` 400 on current models** (high, since 2026-09-01) — `Settings.temperature=0.7` returns `unsupported_value` and `Settings.max_tokens=200` returns `unsupported_parameter`; both are inherited `LLMSettings`, both 400s are classified permanent, and the worker then marks the service unusable for the session. Re-probed today on gpt-6.2-sol. — *Needs a call: drop `temperature` and map `max_tokens` to `max_completion_tokens` for reasoning models, or surface a clearer error.*
- **GPT-6.2 cannot call functions through this class** (medium, since 2026-11-23) — a user who follows OpenAI's own "if you're not sure where to start, use GPT-6.2 Astra" and sets `model="gpt-6.2-astra"` on `OpenAILLMService` gets plain text fine and a hard 400 the moment the context carries a tool: `Function tools with reasoning_effort are not supported for gpt-6.2-astra in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'.` The remedy the error names is not available — probed, both 6.2 models reject `reasoning_effort: none` and accept only low/medium/high/xhigh — so function calling on GPT-6.2 exists only on `OpenAIResponsesLLMService`. — *Needs a call: document the limit and point at the Responses service, or detect the combination and raise before the request.*
- **No typed reasoning-effort setting** (medium, since 2026-09-14) — `extra={"reasoning_effort": ...}` remains the only route to the setting that governs both latency and, on GPT-6.2, whether tools are accepted at all. The Responses service has a typed `reasoning` field. — *Needs a call: `BaseOpenAILLMService.Settings` is shared by every OpenAI-compatible service and the accepted values differ per model and per provider, so a pass-through field needs a decision on where it belongs.*
- **`pipecat eval`'s OpenAI default is gpt-4o** (medium, since 2026-11-09) — `DEFAULT_OPENAI_MODEL = "gpt-4o"` in `src/pipecat/evals/services.py` backs any judge, classifier or persona block that names `service: openai` without a model, and gpt-4o goes on 2027-01-14. A one-line constant that decides eval verdicts, which is why it is not on a branch. — *Needs a call: which model judges and plays personas once gpt-4o is gone.*
- **Turn-completion benchmark pins gpt-5-mini** (medium, since 2026-11-23) — `evals/turn-completion/manifest.yaml` runs `OpenAILLMService` with `model: gpt-5-mini` and `extra: {reasoning_effort: minimal}`; gpt-5-mini shuts down 2026-12-11, eighteen days out — the nearest OpenAI deadline this repo touches. The named replacement gpt-6.1-terra does not take `minimal`, so the effort value moves with the model and the row stops being comparable to its own history. — *Needs a call: which model the gpt-5-mini row becomes, and at which effort.*

#6658, the branch from the previous report, merged on 2026-11-09, so the retiring gpt-4o-mini is out of the `OpenAILLMService` usage examples; that gap is dropped. Nothing else from that report is unaccounted for. One new feature deprecation (Jan 11, 2027) retires `service_tier: fast | priority` for GPT-5.2/5.4/5.4-mini under EU data residency only — the service passes `service_tier` straight through and nothing in the repo sets that combination, so it is not a gap. No decisions file exists for this unit and the digest-comments file carries no comments.
