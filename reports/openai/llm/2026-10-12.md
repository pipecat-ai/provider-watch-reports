# OpenAI LLM — 2026-10-12

gpt-4.1 stays the default: OpenAI now recommends GPT-6 for production, but every GPT-6 tier reasons by default and none is on the aiewf-eval leaderboard; `temperature`/`max_tokens` still 400 on all of them.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`temperature` and `max_tokens` 400 on current models** (high, since 2026-09-01) — `Settings.temperature=0.7` returns `unsupported_value` ("Only the default (1) value is supported") and `Settings.max_tokens=200` returns `unsupported_parameter` ("Use 'max_completion_tokens' instead"); the pipeline then marks the service unusable. Re-probed today on gpt-6-luna and gpt-6.1-sol — the September finding now covers the whole GPT-6 lineup OpenAI recommends, and both fields are inherited `LLMSettings`, so any user who sets them and picks a current model hits this. — *Needs a call: whether the service should drop `temperature` and map `max_tokens` to `max_completion_tokens` for reasoning models, or surface a clearer error.*
- **Default is a generation behind** (medium, since 2026-09-01) — OpenAI shipped gpt-6-sol and gpt-6-luna (2026-09-22) and gpt-6.1-sol (2026-09-29); the models page now lists only gpt-6-astra, gpt-6.1-sol and gpt-6-luna, and the Oct 7 changelog recommends GPT-6 for production. gpt-4.1 is still served and still absent from the deprecation list. None of the GPT-6 tiers is a voice candidate at its defaults: all three reason, and on a reasoning-triggering turn gpt-6-luna takes 5353 ms to a first answer token against gpt-4.1's 394 ms. aiewf-eval medium-context has no gpt-6 row, so the rule in #5447 leaves the bump here; the only benchmarked model above the default is still gpt-5.6-terra (medium) at 97.8% / 927 ms vs gpt-4.1's 96.3% / 536 ms. — *Needs a call: wait for a GPT-6 row on the leaderboard, or bump to gpt-5.6-terra now and accept roughly doubled TTFAT.*
- **No typed reasoning-effort setting** (medium, since 2026-09-14) — raised from low: with the recommended lineup reasoning by default, effort is what decides whether a model can hold a voice turn. Setting `extra={"reasoning_effort": "none"}` cuts gpt-6-luna from 5353 ms to 758 ms median TTFAT on the same prompt — a 7x change reachable only through an untyped dict. The Responses service has a typed `reasoning` field instead. — *Needs a call: `OpenAILLMService.Settings` is `BaseOpenAILLMService.Settings`, shared by every OpenAI-compatible service, and the accepted values differ per model (gpt-6-astra has no `none`) and per provider, so a pass-through field needs a decision on where it belongs.*
- **gpt-4o pinned in an example** (low, since 2026-09-01) — `examples/transports/transports-moq.py` is the only example that passes `model=` to `OpenAILLMService`, and it names gpt-4o. The base alias is not retiring (only `gpt-4o-2024-05-13`, on 2026-10-23). — *Needs a call: whether examples should pin a model at all rather than track the service default.*

Nothing from the previous report is unaccounted for. The 2026-10-23 shutdown of `gpt-4.1-nano` touches no live code path — the examples moved off it earlier, and the remaining occurrences are string fixtures in `tests/test_settings.py` that make no API call.
