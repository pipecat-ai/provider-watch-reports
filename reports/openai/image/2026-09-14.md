# OpenAI Image — 2026-09-14

Nothing new to merge: PR 5546 is still the fix for a service that cannot generate an image on `main`, and this run confirms its `gpt-image-2` default is still the right one.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5546 — Fix OpenAIImageGenService against OpenAI's current image models: decode inline base64 responses and default to gpt-image-2 (open since 2026-09-01)

OpenAI shipped GPT Image 2.5 on 2026-09-08 (`gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`), which raised the question of whether the open PR should retarget its default. It should not: both 2.5 models work through the PR's class but generate slower than `gpt-image-2` at default settings, so the PR can merge as it stands. `gpt-image-2` is not deprecated.

No new branch this run — the open PR covers the only changes that qualify.

### To consider
- **Images API parameters** (medium, since 2026-09-01) — `Settings` carries only `model` and `image_size`; `quality`, `background`, `output_format`, `output_compression`, `moderation`, `n` and the streaming pair `stream`/`partial_images` are not reachable. `quality` is the lever that matters most here, since a single generation measures 13-26 s. GPT Image 2.5 adds `xhigh` and `max` quality tiers that the pinned SDK's `Literal` does not yet list. — *Needs a call: which of the set to expose, and how an unset field maps onto the SDK — the service sends `size=None` today rather than omitting the parameter.*
- **GPT Image 2.5** (low, since 2026-09-14) — `gpt-image-2.5-flare` and `gpt-image-2.5-sunburst` are GA and reachable today via `Settings(model=...)`; nothing in the service blocks them. The docs position flare as the everyday-generation choice, but it measured 24.3 s median against 14.2 s for `gpt-image-2` (3 samples each, default quality), so it does not clear the latency bar for a default bump. — *Needs a call only if the numbers change: re-measure next run, and consider whether an explicit `quality` would close the gap before revisiting the default.*

Dropped since the last report: the `openai` pin is now `>=1.74.0,<4` and PyPI is at 3.13.0, so the SDK-major gap no longer holds.
