# OpenAI Image — 2026-11-23

Current: PR 6657 merged, so `complexity` is in `OpenAIImageGenSettings`, and OpenAI shipped nothing new for image generation in the two weeks since. The three open items all still need a maintainer's call; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model vs. GPT Image 2.6** (medium, since 2026-11-09) — `gpt-image-2.6-flare` runs through `OpenAIImageGenService` unchanged and generated in 4.2 s against 8.3 s for the current default on the same prompt. OpenAI's deprecations page now names the 2.6 pair as the replacement for every image model it has scheduled: `gpt-image-1-mini`, `gpt-image-1.5` and `chatgpt-image-latest` on 2026-12-01, and — new since the last run — `gpt-image-2` and `gpt-image-2-2026-04-21` on 2027-02-10. Still no deprecation for 2.5: its model page reads "Fast, high-quality everyday image generation" with no successor pointer, and the generation guide's examples remain on `gpt-image-2.5-sunburst`. The API reference still restricts `quality` values `xhigh` and `max` to the 2.5 models. — *Needs a call: whether to move the default while 2.5-flare is still current, accepting that callers setting `quality="xhigh"` or `"max"` would start getting rejected.*
- **Remaining Images API parameters** (medium, since 2026-09-01) — `background`, `output_format`, `output_compression`, the streaming pair `stream`/`partial_images` and `n` are still unreachable, each with a coupling: `background=transparent` needs a `png`/`webp` format, `output_compression` needs `webp`/`jpeg`, and `n`/`stream` change the frames the generator yields (it sends `n=1` and reads `data[0]`). The 2.6 controls `output_format=svg|gif`, the `svg` object (`svg.model`, `svg.reasoning.effort`), `frame_count` and `frame_duration_ms` produce output `run_image_gen` cannot turn into a `URLImageRawFrame` at all, since it decodes through PIL into a single RGB frame. — *Needs a call: whether image generation should ever yield more than one frame per prompt, and whether non-raster output is in scope.*
- **`safety_identifier`** (low, since 2026-10-28) — OpenAI's abuse-monitoring identifier, and the documented replacement for the deprecated `user` parameter, is not reachable. Mechanically it is a bare optional string; `SpeechifyTTSService` already exposes one, so there is a shape to copy. — *Needs a call: the OpenAI LLM, STT and TTS services take the same parameter and none exposes it, so adding it to image generation alone would set the cross-service pattern by accident.*

Closed since the last report: PR 6657 merged on 2026-11-09, so the `complexity` gap is gone — the field is in `OpenAIImageGenSettings` and reaches the API through `extra_body`. Nothing in the service, its examples or its tests names a model with a shutdown date.
