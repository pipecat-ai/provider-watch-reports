# OpenAI Image — 2026-11-09

GPT Image 2.6 Flare and Sunburst shipped on 2026-11-04; one branch adds the `complexity` setting they introduce, and the default bump to `gpt-image-2.6-flare` needs a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6657 — Expose OpenAI image generation complexity

`complexity` (`low`, `medium`, `high`) is how much the model plans before rendering; OpenAI documents it as separate from `quality`, with no extra fee and no interaction with the output format. The field is optional and unset by default. It travels in `extra_body` because `images.generate` only grew a named `complexity` argument in openai 3.46.0 (2026-11-05), above the `openai>=1.74.0,<4` floor pipecat supports; the request is byte-identical to the named argument. The API accepts it on the 2.6 models only — 2.5-flare answers `400 Complexity 'low' is not supported for this image model`, which the field's docstring states.

### To consider
- **Default model vs. GPT Image 2.6** (medium, since 2026-11-09) — `gpt-image-2.6-flare` is out and works through `OpenAIImageGenService` unchanged (6.6 s vs 8.2 s for the current default on the same prompt), and OpenAI's deprecations page now names the 2.6 pair as the replacement for `gpt-image-1-mini`, `gpt-image-1.5` and `chatgpt-image-latest` when they shut down on 2026-12-01. But `gpt-image-2.5-flare` is not deprecated, its model page still calls it "our fastest model for high-quality, everyday image generation", and the guide's own examples stay on 2.5. The API reference also restricts `quality` values `xhigh` and `max` to the 2.5 models. — *Needs a call: whether to move the default while 2.5-flare is still current, accepting that callers setting `quality="xhigh"` or `"max"` would start getting rejected.*
- **Remaining Images API parameters** (medium, since 2026-09-01) — `background`, `output_format`, `output_compression`, the streaming pair `stream`/`partial_images` and `n` are still unreachable, each with a coupling: `background=transparent` needs a `png`/`webp` format, `output_compression` needs `webp`/`jpeg`, and `n`/`stream` change the frames the generator yields (it sends `n=1` and reads `data[0]`). 2.6 adds `output_format=svg|gif` with `svg` (model plus reasoning effort), `frame_count` and `frame_duration_ms` — output that `run_image_gen` cannot turn into a `URLImageRawFrame` at all, since it decodes through PIL into a single RGB frame. — *Needs a call: whether image generation should ever yield more than one frame per prompt, and whether non-raster output is in scope.*
- **`safety_identifier`** (low, since 2026-10-28) — OpenAI's abuse-monitoring identifier, and the documented replacement for the deprecated `user` parameter, is not reachable. Mechanically it is a bare optional string; `SpeechifyTTSService` already exposes one, so there is a shape to copy. — *Needs a call: the OpenAI LLM, STT and TTS services take the same parameter and none exposes it, so adding it to image generation alone would set the cross-service pattern by accident.*

Closed since the last report: PR 6432 merged on 2026-10-28, so the `moderation` gap is gone — the field is in `OpenAIImageGenSettings` and reaches the API. `gpt-image-1` has left the catalogue after its 2026-10-23 shutdown; nothing in the service or its example named it.
