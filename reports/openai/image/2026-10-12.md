# OpenAI Image — 2026-10-12

The service is healthy: PR 5546 merged on 2026-09-28 and the default is `gpt-image-2.5-flare`, which OpenAI names as the replacement for every retiring image model. One branch is ready, adding the `quality` setting.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6141 — Expose OpenAI image generation quality

`quality` is the one Images API parameter that passes straight through with no other decisions attached, and it is the lever that matters in a live pipeline: on `gpt-image-2.5-flare` the same prompt took 7.8 s at `low` and 18.6 s at `xhigh` against 10.0 s unset. The field is optional and unset by default, so nothing changes for existing callers. The installed `openai` SDK's `quality` Literal now lists the GPT Image 2.5 tiers `xhigh` and `max`, which it did not at the last run.

### To consider
- **Remaining Images API parameters** (medium, since 2026-09-01) — `background`, `output_format`, `output_compression`, `moderation`, `n` and the streaming pair `stream`/`partial_images` are still unreachable. None is a bare pass-through: `background=transparent` is only valid with a `png`/`webp` output format, the output format decides how `run_image_gen` decodes the response bytes, and `n` and `stream` change the frames the generator yields — it sends `n=1` and reads `data[0]` today. — *Needs a call: whether image generation should ever yield more than one frame per prompt, which decides whether `n` and the streaming pair are in scope at all.*

Closed since the last report: PR 5546 merged (retired `dall-e-3` default and the unreadable base64 responses — both gaps gone), and a follow-up commit moved the default to `gpt-image-2.5-flare`, which settles last run's low-priority "GPT Image 2.5 measures slower" item. Flare measured 10.0 s this run against the 24.3 s median recorded on 2026-09-14, so the latency objection no longer holds either.

## Verification

`probe.py run` has no image tier ("research-only, no probe"), so these are real generations through `OpenAIImageGenService.run_image_gen` on the branch, timed end to end; image services emit no TTFB metric. Same prompt, size unset.
