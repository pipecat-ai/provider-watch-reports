# OpenAI Image — 2026-09-01

`OpenAIImageGenService` cannot generate an image with any model today; the branch fixes the retired default and the response handling.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5546 — Fix OpenAIImageGenService against OpenAI's current image models: decode inline base64 responses and default to gpt-image-2

Two independent failures, one commit each:

- The shipped default `dall-e-3` was deprecated on 2025-11-14 and removed from the API on 2026-05-12; it is absent from the catalogue and a request naming it returns `The model 'dall-e-3' does not exist`. The commit defaults to `gpt-image-2`, OpenAI's current image model and the first replacement its deprecation notice names.
- The GPT Image models return the image inline as `b64_json` and never populate `url`, which is the only field `run_image_gen` read — so even a valid model produced `ErrorFrame("Image generation failed")`. The commit decodes whichever form the response carries.

### To consider
- **Images API parameters** (medium, since 2026-09-01) — `Settings` carries only `model` and `image_size`; `quality`, `background`, `output_format`, `output_compression`, `moderation` and `n` are not reachable. `quality="low"` is the lever that matters most here, since a single generation takes 13-40 s. — *Needs a call: which of the set to expose, and how an unset field maps onto the SDK — the service sends `size=None` today rather than omitting the parameter.*
- **openai SDK pin behind the current major** (medium, since 2026-09-01) — `pyproject.toml` pins `openai>=1.74.0,<3` while PyPI is at 3.6.0 (2026-08-28); nothing on the Images API path is blocked by it. — *Needs a call: the openai 3.x bump is repo-wide and shared by every OpenAI service, not a decision this unit can make.*
