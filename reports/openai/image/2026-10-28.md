# OpenAI Image — 2026-10-28

Nothing is retiring and the catalogue has not moved since 2026-09-08. One branch is ready, adding the `moderation` setting.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6432 — Expose OpenAI image generation moderation level

`moderation` is the one remaining Images API parameter that passes straight through with nothing else attached: two documented values (`low`, `auto`), no interaction with the output format or with what `run_image_gen` yields. The field is optional and unset by default, so the request is unchanged for existing callers. Last run's gap item lumped it in with the coupled parameters; it does not belong there.

### To consider
- **Remaining Images API parameters** (medium, since 2026-09-01) — `background`, `output_format`, `output_compression` and the streaming pair `stream`/`partial_images`, plus `n`, are still unreachable, and each carries a decision: `background=transparent` is only valid with a `png`/`webp` output format, `output_compression` only with `webp`/`jpeg`, and `n` and `stream` change the frames the generator yields — it sends `n=1` and reads `data[0]` today. — *Needs a call: whether image generation should ever yield more than one frame per prompt, which decides whether `n` and the streaming pair are in scope at all.*
- **`safety_identifier`** (low, since 2026-10-28) — OpenAI's abuse-monitoring identifier, and the documented replacement for the deprecated `user` parameter, is not reachable. Mechanically it is a bare optional string; `SpeechifyTTSService` already exposes one, so there is a shape to copy. — *Needs a call: the OpenAI LLM, STT and TTS services take the same parameter and none exposes it, so adding it to image generation alone would set the cross-service pattern by accident.*

Closed since the last report: PR 6141 merged on 2026-10-13, so the `quality` gap is gone — the field is in `OpenAIImageGenSettings` and reaches the API.

## Verification

`probe.py` has no image tier, so these are real generations through `OpenAIImageGenService.run_image_gen` on the branch, timed end to end; image services emit no TTFB metric. Same prompt, size and quality unset.

| model               | class                          | ok | latency | note                        |
| ------------------- | ------------------------------ | -- | ------- | --------------------------- |
| gpt-image-2.5-flare | OpenAIImageGenService          | ✅ | 6.5 s   | moderation unset            |
| gpt-image-2.5-flare | OpenAIImageGenService (branch) | ✅ | 5.8 s   | `moderation="low"`          |
| gpt-image-2.5-flare | OpenAIImageGenService (branch) | ✅ | 6.3 s   | `moderation="auto"`         |

All three returned a 1254x1254 RGB frame. Single samples: these establish that `moderation` reaches the API and is accepted, not a default-bump comparison. `tests/test_openai_image_gen.py` passes on the branch (7 tests), as do the repo's pre-commit hooks.
