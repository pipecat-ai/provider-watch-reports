# OpenAI TTS — 2026-10-12

OpenAI has put a shutdown date on the models this service calls. On 2026-10-01 it deprecated `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts-2025-03-20` and `gpt-4o-mini-tts-2025-12-15` — removal 2027-01-06 — and the only migration instruction is "Migrate to `gpt-realtime-2.1-mini` before the shutdown date". That model is not servable from `/v1/audio/speech` (probed: 404), so there is nothing to bump and the question is strategic.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`/v1/audio/speech` model lineup retiring 2027-01-06** (high, since 2026-10-12) — the deprecation table covers both dated snapshots of our default alias plus the whole `tts-1` family, with `gpt-realtime-2.1-mini` as the recommended replacement. The alias `gpt-4o-mini-tts` is *not* listed and still works (TTFB 1115 ms this run), and the API reference still advertises it, so the endpoint is not dead yet — but every concrete model behind it has a date. `gpt-realtime-2.1-mini` returned `404 Invalid URL (POST /v1/audio/speech)` through `OpenAITTSService`, and Pipecat already reaches it from `OpenAIRealtimeLLMService` (`src/pipecat/services/openai/realtime/llm.py`, default `gpt-realtime-2.1`), which is a speech-to-speech service and not a drop-in for a TTS node in a pipeline. — *Needs a call: whether `OpenAITTSService` gets deprecated in favour of the Realtime service, or we wait for OpenAI to re-point the `gpt-4o-mini-tts` alias at something that survives the shutdown.*
- **Custom voices blocked by the allowlist** (medium, since 2026-09-01) — `/v1/audio/speech` accepts a custom voice object `{"id": "voice_1234"}` alongside the 13 built-in names, and openai 3.24.0 added the creation endpoints for them. `run_tts` checks `voice not in VALID_VOICES` and yields an `ErrorFrame` before building the request, so a custom voice ID never reaches OpenAI. — *Needs a call: whether to pass unknown voice strings (and the `{id: ...}` shape) through and drop the client-side typo check; there is no way to probe a real custom voice from this account.*
- **Default voice** (low, since 2026-09-01) — the text-to-speech guide recommends `marin` or `cedar` for best quality; we default to `alloy`. Both are in the allowlist already, so this is only a default. — *Needs a call: changing it changes what existing users hear.*

No Pipecat code or example pins `tts-1`/`tts-1-hd` or a dated `gpt-4o-mini-tts` snapshot, so the retirement reaches users only through the default alias. Nothing else changed: the catalogue's speech subset is identical to last run, the `/v1/audio/speech` request schema is unchanged (input, model, voice, instructions, response_format, speed, stream_format), and `stream_format="sse"` is still not a simple `Settings` pass-through because `run_tts` reads raw PCM bytes from the streaming response.
