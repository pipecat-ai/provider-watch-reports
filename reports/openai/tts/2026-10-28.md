# OpenAI TTS — 2026-10-28

The retirement got more concrete: OpenAI's deprecation table and its text-to-speech guide both name `gpt-4o-mini-tts` — our default, the alias, not only its dated snapshots — as shutting down 2027-01-06. There is still nothing to bump to, so the decision is unchanged and strategic.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`/v1/audio/speech` model lineup retiring 2027-01-06** (high, since 2026-10-12) — last run read the table as covering only the snapshots; its rows actually read `gpt-4o-mini-tts | gpt-4o-mini-tts-2025-03-20` and `gpt-4o-mini-tts | gpt-4o-mini-tts-2025-12-15`, and the guide has since gained the notice in plain words: "The tts-1, tts-1-hd, and gpt-4o-mini-tts models are deprecated and will shut down on January 6, 2027." The guide also now says outright that `gpt-realtime-2.1-mini` "isn't a supported model for /v1/audio/speech", confirming the 404 probed last run, and that "existing integrations can use the Speech API workflows shown below" until then. The alias still serves (TTFB 867 ms, median of 3). The endpoint itself carries no deprecation. Pipecat reaches `gpt-realtime-2.1-mini` only from `OpenAIRealtimeLLMService` (`src/pipecat/services/openai/realtime/llm.py`, default `gpt-realtime-2.1`), a speech-to-speech service that is not a drop-in for a TTS node. — *Needs a call: whether `OpenAITTSService` gets deprecated in favour of the Realtime service, or we keep it serving to the shutdown date and wait for OpenAI to offer a speech-API successor.*
- **Custom voices blocked by the allowlist** (medium, since 2026-09-01) — the SDK types `voice` as `Union[str, Literal[...], VoiceID]` with `VoiceID = {"id": "voice_1234"}`; `run_tts` checks `voice not in VALID_VOICES` and yields an `ErrorFrame` before building the request, so a custom voice ID never reaches OpenAI. OpenAI's 2026-10-16 prompt-to-voice launch does not widen this: prompt-created voices are Live-only, and only audio-sample custom voices are servable from `/v1/audio/speech`. — *Needs a call: whether to pass unknown voice strings (and the `{id: ...}` shape) through and drop the client-side typo check; there is no way to probe a real custom voice from this account.*
- **Default voice** (low, since 2026-09-01) — the guide still recommends `marin` or `cedar` for best quality; we default to `alloy`. Both are in the allowlist, so this is only a default. — *Needs a call: changing it changes what existing users hear.*

Nothing else moved. The catalogue's speech subset is identical to the last two runs; the `/v1/audio/speech` request schema is unchanged (`input`, `model`, `voice`, `instructions`, `response_format`, `speed`, `stream_format`), and `stream_format="sse"` is still not a simple `Settings` pass-through because `run_tts` reads raw PCM bytes off the streaming response. No Pipecat source, test or example pins `tts-1`/`tts-1-hd` or a dated snapshot, so the retirement reaches users only through the default alias.
