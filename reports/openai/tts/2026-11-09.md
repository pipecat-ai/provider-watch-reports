# OpenAI TTS — 2026-11-09

No change since the last run: the shutdown is still scheduled for 2027-01-06, OpenAI still offers no `/v1/audio/speech` successor, and the request schema is untouched.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`/v1/audio/speech` model lineup retiring 2027-01-06** (high, since 2026-10-12) — the deprecations page now renders five separate rows (`tts-1`, `tts-1-hd`, `gpt-4o-mini-tts`, `gpt-4o-mini-tts-2025-03-20`, `gpt-4o-mini-tts-2025-12-15`), all shutting down 2027-01-06, all pointing at `gpt-realtime-2.1-mini`; the TTS guide repeats that `gpt-realtime-2.1-mini` is not supported on `/v1/audio/speech` and that existing Speech API integrations keep working until the date. Pipecat reaches that model only from `OpenAIRealtimeLLMService` (`src/pipecat/services/openai/realtime/llm.py`), a speech-to-speech service that is not a drop-in for a TTS node, so there is still nothing to bump to. The default alias serves normally (TTFB 1372 ms, median of 3). — *Needs a call: whether `OpenAITTSService` gets deprecated in favour of the Realtime service, or we keep it serving to the shutdown date and wait for OpenAI to offer a speech-API successor.*
- **Custom voices blocked by the allowlist** (medium, since 2026-09-01) — `run_tts` checks `voice not in VALID_VOICES` and yields an `ErrorFrame` before building the request, so neither an unknown voice string nor the documented `{"id": "voice_1234"}` object can reach OpenAI, though the SDK and the API reference both accept them. — *Needs a call: whether to pass unknown voice strings (and the `{id: ...}` shape) through and drop the client-side typo check; there is no way to probe a real custom voice from this account.*
- **Default voice** (low, since 2026-09-01) — the guide still recommends `marin` or `cedar` for best quality; we default to `alloy`. Both are in the allowlist, so this is only a default. — *Needs a call: changing it changes what existing users hear.*

Nothing else moved. The catalogue's speech subset is identical to the last three runs. The `/v1/audio/speech` request body is unchanged (`input`, `model`, `voice`, `instructions`, `response_format`, `speed`, `stream_format`), and `stream_format="sse"` is still not a simple `Settings` pass-through because `run_tts` reads raw PCM bytes off the streaming response. OpenAI's changelog for the period carries no speech item at all. No Pipecat source, test or example pins `tts-1`/`tts-1-hd` or a dated snapshot — the retirement reaches users only through the default alias.
