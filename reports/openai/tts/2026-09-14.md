# OpenAI TTS — 2026-09-14

Nothing to do. `gpt-4o-mini-tts` is still the model OpenAI calls its newest and most reliable, no speech model or `/v1/audio/speech` parameter is deprecated, and the request schema is unchanged since the last run. The two open items are both maintainer calls carried forward.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Custom voices blocked by the allowlist** (medium, since 2026-09-01) — `/v1/audio/speech` accepts a custom voice object `{"id": "voice_1234"}` alongside the 13 built-in names. `run_tts` checks `voice not in VALID_VOICES` and yields an `ErrorFrame` before building the request, so a custom voice ID never reaches OpenAI. — *Needs a call: whether to pass unknown voice strings (and the `{id: ...}` shape) through and drop the client-side typo check; there is no way to probe a real custom voice from this account.*
- **Default voice** (low, since 2026-09-01) — the text-to-speech guide recommends `marin` or `cedar` for best quality; we default to `alloy`. Both are in the allowlist already, so this is only a default. — *Needs a call: changing it changes what existing users hear.*

Closed since the last report: the `openai>=1.74.0,<3` pin gap. `pyproject.toml` now pins `openai>=1.74.0,<4` (pipecat-ai/pipecat#5620), which admits the current 3.13.0.

Still not gaps: `gpt-4o-mini-tts-2025-12-15` remains the snapshot behind the alias, so the default needs no pinning; `stream_format="sse"` is not a simple `Settings` pass-through, since `run_tts` reads raw PCM bytes from the streaming response. OpenAI's audio work since the last run — the transcription deprecations on 2026-08-26 and GPT-Live 1 GA on 2026-09-10 — touches other units, not this one.
