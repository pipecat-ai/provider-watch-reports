# OpenAI STT — 2026-09-01

`gpt-4o-transcribe`, the `OpenAISTTService` default, shuts down on 2027-02-26; the branch moves it to `gpt-transcribe`, which is also faster (TTFB 884 ms vs 1040 ms, median of 5). The realtime class needs a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5549 — Move OpenAI STT off the retiring gpt-4o-transcribe onto gpt-transcribe

The branch carries two commits: the default bump (with the `include_prob_metrics` response-format table, which `gpt-transcribe` rejects as `verbose_json`, plus the docstrings and the `voice-openai-http.py` example) and the `voice-openai-turn-detection.py` example, whose `gpt-4o-transcribe` is the model that gives the realtime session server-side VAD.

### To consider
- **Realtime default** (medium, since 2026-09-01) — OpenAI's realtime transcription guide now lists only `gpt-live-transcribe` (recommended) and `gpt-transcribe`; `gpt-realtime-whisper` has quietly dropped out of it but is absent from the deprecation table. `gpt-live-transcribe` is slower in our probe (TTFB 2452 ms vs 1846 ms, median of 3) and rejects `turn_detection` exactly as `gpt-realtime-whisper` does, so it buys nothing today. — *Needs a call: follow the docs onto `gpt-live-transcribe` despite ~600 ms more TTFB, or hold until `gpt-realtime-whisper` is deprecated.*
- **`keywords` and `languages`** (medium, since 2026-09-01) — the two features OpenAI led with when it shipped `gpt-transcribe` (keyword hints for product names and acronyms, and a list of expected input languages) have no `Settings` field on either class; both the Audio API and the realtime transcription session accept them, and the pinned openai SDK already types them. — *Needs a call: how `languages` coexists with the singular `language` the service always sends, and whether these should be dropped per-model the way `prompt` already is.*
- **Realtime `delay` control** (medium, since 2026-09-01) — the realtime transcription guide documents `delay` (`minimal`/`low`/`medium`/`high`/`xhigh`) as the latency-versus-accuracy knob; `OpenAIRealtimeSTTSettings` has only `prompt` and `noise_reduction`. — *Needs a call: which models honour it — probing requires the field to exist first.*
- **Empty-buffer commit on session start** (medium, since 2026-09-01) — audio appended before our `session.update` takes effect is processed under the session's default turn detection, so the server auto-commits and our explicit commit on `VADUserStoppedSpeakingFrame` hits an empty buffer: `_handle_error` raises, an `ErrorFrame` goes upstream and the websocket reconnects mid-turn. Both realtime models are affected; isolated sessions never hit it (0/6), back-to-back ones almost always do (9/10). — *Needs a call: whether `run_stt` should hold audio until `_session_ready`, and whether an empty-buffer commit deserves an error frame.*
- **openai pin behind the 3.x major** (low, since 2026-09-01) — `openai>=1.74.0,<3` against 3.6.0 on PyPI. Nothing STT-specific is blocked. — *Needs a call: none here; the shared pin is tracked in openai/responses-llm.*
