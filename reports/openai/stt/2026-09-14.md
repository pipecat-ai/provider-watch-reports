# OpenAI STT — 2026-09-14

`gpt-transcribe` is current for both the REST class and OpenAI's file-transcription recommendation; the branch exposes two documented request fields that probes confirm reach the API. The realtime class still has the same three open calls as last run.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5750 — Add OpenAI's transcription keyword hints and the realtime delay control to Settings

Two commits: `keywords` on `OpenAISTTService.Settings` (Audio API), and `delay` on `OpenAIRealtimeSTTService.Settings` (realtime transcription session). Both are optional and unset by default.

### To consider
- **Realtime default** (medium, since 2026-09-01) — the realtime transcription guide now calls `gpt-live-transcribe` "the recommended model" and names `gpt-transcribe` only for post-commit transcription or detected-language output; `gpt-realtime-whisper` appears in neither list, but is also absent from the deprecation table and is still the faster of the two (TTFB 2061 ms vs 2947 ms, median of 3 isolated sessions). — *Needs a call: follow the docs onto `gpt-live-transcribe` despite ~900 ms more TTFB, or hold until `gpt-realtime-whisper` is deprecated.*
- **`languages`, and realtime `keywords`** (medium, since 2026-09-01) — `languages` is accepted by both APIs but overlaps the singular `language` the services always send; realtime `keywords` works on `gpt-transcribe` and `gpt-live-transcribe` but not on the default `gpt-realtime-whisper`, so it needs the per-model omission `_omit_unsupported_prompt` already performs for `prompt`. — *Needs a call: whether `languages` coexists with or replaces `language`, and whether realtime `keywords` should be silently dropped for models that reject it.*
- **Empty-buffer commit on session start** (medium, since 2026-09-01) — unchanged and still reproducible: audio appended before our `session.update` takes effect is processed under the session's default turn detection, the server auto-commits, and our commit on `VADUserStoppedSpeakingFrame` hits an empty buffer, so `_handle_error` raises and the websocket reconnects mid-turn. Isolated sessions were clean 6/6; interleaved `--repeat 5` runs succeeded 2/5 and 1/5, and one surviving run returned a truncated transcript. — *Needs a call: whether `run_stt` should hold audio until `_session_ready`, and whether an empty-buffer commit deserves an error frame.*
- **Streaming file transcription** (low, since 2026-09-14) — `gpt-transcribe` supports `stream` on the Audio API, emitting partial text while transcribing; `OpenAISTTService` awaits the whole response, so each segment's ~880 ms is dead time. The realtime class already serves users who want partials. — *Needs a call: whether `SegmentedSTTService` should push interim frames from a streamed response, which is more than a `Settings` field.*

Closed since last run: the `gpt-4o-transcribe` default retirement (PR #5549 merged 2026-09-03, `gpt-transcribe` now ships) and the `openai` pin gap (the pin is now `openai>=1.74.0,<4`, which admits the current 3.13.0).
