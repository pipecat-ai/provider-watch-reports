# OpenAI Realtime — 2026-11-23

`gpt-realtime-2.1` stays the default — OpenAI has still shipped no Realtime model or changelog entry since July, and the GA schema has not moved a byte in three weeks. Both PRs from the last run merged; one branch adds `idle_timeout_ms`, the half of the server-VAD gap that carries no hazard.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6972 — Expose OpenAI Realtime's server-VAD idle timeout

  `TurnDetection` had no `idle_timeout_ms`, and because pydantic drops unknown keys a user passing it today loses it silently — confirmed live: `main`'s model serialized `{"type": "server_vad", "threshold": 0.5, "prefix_padding_ms": 300, "silence_duration_ms": 500}` and the server echoed `idle_timeout_ms: null`. From the branch the same code sends `idle_timeout_ms: 8000` and the server echoes it back. OpenAI documents it as the way to prompt a silent caller on a phone call, counted from the end of the last response's audio, and the server drives the prompting itself — it emits `input_audio_buffer.timeout_triggered` (unmodeled, so skipped) plus the ordinary response events the service already handles, so nothing else in the service needs to change. `create_response` and `interrupt_response` stay out: they change who drives responses, and remain a "To consider" item.

### To consider
- **MCP tools still hang the session** (high, since 2026-09-01) — unchanged. The server's `conversation.item.added` carries an `mcp_list_tools` item while `ConversationItem.type` is still a three-value `Literal`, so validation fails, the exception leaves `_receive_task_handler` (no try/except), and the bot goes silent with no `ErrorFrame`. GA's item union has nine members, including `mcp_call` and `mcp_approval_request`. — *Needs a call: model the MCP item types (and surface approval requests), or make the receive loop log and skip anything that fails validation, not just unmodeled types.*
- **Lawful GA payloads our models reject** (medium, since 2026-10-28) — re-checked against `openai` 3.58.0, whose `types/realtime/` is byte-identical to 3.46.0: `conversation.item.input_audio_transcription.delta` requires `content_index` and `delta` where GA has both optional; that event's `failed` sibling uses our `RealtimeError`, which requires `type` and `message` where GA's per-event Error has every field optional (so a partial failure report kills the session it reports on); `ItemContent.type` is required where GA marks the user-message content type optional; `RealtimeConversation` requires `id` and `object` where `conversation.created` marks both optional. These models are shared with client events and the `error` event. — *Needs a call: split the shared models so the server side can be permissive, or stop the receive loop raising on validation failure at all — the latter subsumes the MCP item-type gap too.*
- **`create_response` / `interrupt_response` under server VAD** (medium, since 2026-09-01) — the remainder of the server-VAD gap after the branch above. GA's `ServerVad` carries both and `SemanticTurnDetection` already does; `TurnDetection` does not. — *Needs a call: under server VAD the service never sends `response.create` itself, so `create_response=false` leaves the bot permanently silent — does the pass-through ship with that documented, or with handling?*
- **`parallel_tool_calls`** (medium, since 2026-09-01) — now the *only* one of GA's 14 session fields with no home in `SessionProperties`, `truncation` having landed. `gpt-realtime-2.1` accepts it, `gpt-realtime-1.5` fails the session with `invalid_value`, the same reasoning-model-only hazard `_strip_unsupported_reasoning` absorbs for `reasoning`. — *Needs a call: whether that stripping generalizes to a second capability-gated field.*
- **`tool_choice` cannot name a tool** (low, since 2026-09-01) — ours is `Literal["auto", "none", "required"]` on both session and response properties; GA also accepts an object forcing one function or MCP tool. — *Needs a call: whether forcing a tool is meaningful on a service that drives its own responses.*
- **Custom voices** (low, since 2026-09-01) — `AudioOutput.voice` is `str | None`, covering all built-in voices but not GA's `{"id": "voice_1234"}` object. October's prompt-to-voice voices are Live-only; Realtime custom voices must come from audio samples. — *Needs a call: whether Pipecat exposes OpenAI custom voices at all; no other OpenAI service here does.*
- **Safety identifier has no setting** (low, since 2026-10-12) — `_auth_headers()` lets a subclass add `OpenAI-Safety-Identifier` without reimplementing `_connect`, but the hook is private and undocumented, so there is still no configured path to the header the Realtime guide documents. — *Needs a call: whether the hook is answer enough, or the identifier deserves a named setting — a constructor argument is outside the automatic-PR rules, and a Settings field would be the first that configures the connection rather than the session.*
- **Out-of-band responses** (low, since 2026-11-09) — `send_client_event` is public, so a `ResponseCreateEvent` can be sent, but `ResponseProperties` models seven fields and not GA's `conversation` (`"none"` for a response that adds nothing to the conversation) or `input` (a fresh item list for that response alone, which may cite session items by reference). — *Needs a call: whether out-of-band responses are a pattern Pipecat wants on a service that drives its own responses, and if so whether they belong on `ResponseProperties` or on a dedicated API.*

Dropped from the previous report: **GPT-Live 1 is GA but unreachable** — Pipecat now ships `OpenAILiveLLMService` (`src/pipecat/services/openai/live/`, with three `examples/realtime/realtime-openai-live-*.py` bots), so GPT-Live is its own unit (`openai/live-llm`) and no longer a gap here. `gpt-live-1.1` (2026-11-19) is that unit's business. The two PRs the last report carried, #5547 and #6659, both merged; `truncation`, the transcription `delay`/`keywords`/`languages` fields and `noise_reduction.strength` are all in `main`.
