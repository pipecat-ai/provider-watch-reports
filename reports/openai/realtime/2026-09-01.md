# OpenAI Realtime — 2026-09-01

`gpt-realtime-2.1` is exactly what OpenAI's deprecation table names as the replacement for the retiring realtime models, so the default stays. The finding that needs a maintainer is a hang: pass an MCP tool and the session goes silent.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5547 — Expose OpenAI Realtime conversation truncation and input-transcription settings

### To consider
- **MCP tools hang the session** (high, since 2026-09-01) — `SessionProperties.tools` accepts provider-native dicts, so OpenAI's `{"type": "mcp", ...}` tool config reaches the server. The server answers with a `conversation.item.added` carrying an `mcp_list_tools` item; `ConversationItem.type` is `Literal["message", "function_call", "function_call_output"]`, so validation fails, `parse_server_event` raises, and `_receive_task_handler` exits. Probed live on `gpt-realtime-2.1`: no audio for 25 s and no `ErrorFrame` — the failure is silent. The same shape applies to every unmapped server event, since `parse_server_event` raises on anything not in `_server_event_types`. — *Needs a call: support MCP tools end to end (item types plus the `mcp_*` events), or make the receive loop log and skip unknown events instead of raising.*
- **server_vad idle timeout and response controls** (medium, since 2026-09-01) — `TurnDetection` exposes only `threshold`, `prefix_padding_ms` and `silence_duration_ms`. The API also takes `idle_timeout_ms` (the model prompts a user who has gone quiet — OpenAI's developer notes call it out for phone calls) plus `create_response` and `interrupt_response`, which `SemanticTurnDetection` already has. — *Needs a call: `idle_timeout_ms` makes the server emit `input_audio_buffer.timeout_triggered`, which the event map does not know, so the unknown-event decision above has to land first.*
- **`parallel_tool_calls`** (medium, since 2026-09-01) — a documented session field with no home in `SessionProperties`. Probed live: `gpt-realtime-2.1` accepts it, `gpt-realtime-1.5` rejects it with `invalid_value` on `session.parallel_tool_calls` and the session dies — the same reasoning-model-only hazard that `_strip_unsupported_reasoning` exists to absorb for `reasoning`. — *Needs a call: whether that stripping generalizes to a second capability-gated field.*
- **`tool_choice` cannot name a tool** (low, since 2026-09-01) — ours is `Literal["auto", "none", "required"]`; the API also accepts an object forcing one function or MCP tool. — *Needs a call: whether forcing a tool is meaningful on a service that drives its own responses.*
- **Custom voices** (low, since 2026-09-01) — `AudioOutput.voice` is `str | None`, which covers all ten built-in voices but not the API's `{"id": "voice_1234"}` custom-voice object. — *Needs a call: whether Pipecat exposes OpenAI custom voices at all; no other OpenAI service here does.*

Realtime probes are connect-only through `probe.py`, and `--setting` validates keys against the `Settings` dataclass, so nested `SessionProperties` fields cannot be reached from the CLI. The rows above that set session fields come from `.pw-scratch/rt_probe.py`, which builds the service directly and reuses `probe.py`'s `_run_pipeline`, sending an `LLMContextFrame` and waiting for `TTSAudioRawFrame`. TTFB varies session to session; the numbers show acceptance, not a ranking.
