# OpenAI Responses LLM — 2026-11-09

`gpt-4.1` is still the default and still leaves the API on 2027-01-14, with no new evidence to settle the replacement; the one branch this run removes reasoning defaults for four o-series models that OpenAI has already shut down.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6660 — Drop reasoning defaults for the retired o-series models

OpenAI's shutdown of `o1`, `o1-pro`, `o3-mini` and `o4-mini` on 2026-10-23 has taken effect: all four are gone from `GET /v1/models` and a live turn through `OpenAIResponsesHttpLLMService` returns 404 for each. `_THINKING_DEFAULTS` still carried a `"low"` entry for all four; the branch removes them, leaving `o3` and `o3-pro` as the only o-series entries, and probes from the branch confirm those two still take the effort the table sends. The `gpt-5` family (`gpt-5`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5-pro`) and `o3` / `o3-pro` shut down on **2026-12-11**, so the next run is expected to retire six more entries.

### To consider
- **Default model** (high, since 2026-08-25) — unchanged and still dated: OpenAI's 2026-10-14 deprecation removes `gpt-4.1` (`gpt-4.1-2025-04-14`) from the API on **2027-01-14** and names `gpt-6-luna` as the replacement. aiewf-eval's medium-context leaderboard has not been re-run since the last report — `gpt-6-luna (low)` 91.8% and `gpt-6-luna (none)` 0 of 30 completed, against `gpt-4.1` at 95.9% — so OpenAI's own choice still fails the quality gate, and the only model above `gpt-4.1` remains `gpt-5.6-sol` at `effort="none"` (96.9%, TTFAT P50 765 ms vs 743 ms), which OpenAI positions as the successor to `gpt-5` and `o3`. The two models released since (`gpt-6.1-terra`, `gpt-6.1-sol`) have no leaderboard row. Five examples (`examples/flows/yaml/*/bot.py`) pin `gpt-4.1` explicitly. — *Needs a call: which model replaces `gpt-4.1` before 2027-01-14 — OpenAI's choice or the one that benchmarks at parity — and that `openai/llm` shares the same default.*
- **`gpt-6-luna` runs at `effort="none"` by default** (medium, since 2026-10-28) — unchanged: `_THINKING_DEFAULTS` holds each model's lowest documented effort, which for `gpt-6-luna` is `none`, the configuration that completed none of aiewf-eval's 30 multi-turn conversations. — *Needs a call: whether a model's documented lowest effort should give way to a working one when the lowest degrades multi-turn behavior, or whether a docstring note is enough.*
- **Mid-turn and long-running-work controls** (medium, since 2026-09-14) — unchanged: async tool calling (`async: true`, results tagged INTERRUPT / WHEN_IDLE / SILENT), mid-turn steering, and the `configuration_update` input item that changes `reasoning.effort` mid-conversation on the gpt-6 family. None is a pass-through parameter. — *Needs a call: whether any of them is worth designing for now, and which one voice users need first.*
- **Responses knobs only reachable via `extra`** (low, since 2026-08-25) — the installed SDK (3.46.0) adds one top-level request field since the last run, `image` with a single member `context_compression` (`auto` / `enabled` / `disabled`), which is the first of these knobs with a bearing on the unit's vision examples. `_build_response_params` ends with `params.update(self._settings.extra)`, so nobody is blocked. — *Needs a call: named fields versus `extra` as the documented answer.*
- **`service_tier` is construction-time only** (low, since 2026-08-25) — unchanged; choosing a tier per model still means rebuilding the service, while every other request knob is runtime-updatable through `Settings`. — *Needs a call: whether `service_tier` should move into `Settings`, which would leave two ways to set it.*
- **gpt-6-astra rejects `temperature` / `top_p`** (low, since 2026-09-14) — unchanged; both default to `NOT_GIVEN`, so only users who set them are affected. — *Needs a call: whether per-model parameter support is worth tracking in the service, or the provider's error message is good enough.*
- **Approval-gated reasoning models have no table entry** (low, since 2026-11-09) — `gpt-6-rosalind` (2026-10-30, life sciences) and `gpt-6-cyber` (2026-11-05, vulnerability work) are Responses models behind trusted-access approval. Neither is in our catalogue, neither can be probed, and OpenAI publishes no effort list for either, so there is no documented lowest effort to put in `_THINKING_DEFAULTS`. — *Needs a call: whether approval-gated specialist models belong in the table at all.*
