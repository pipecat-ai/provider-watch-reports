# OpenAI Responses LLM — 2026-10-28

`gpt-4.1`, this service's default, was deprecated on 2026-10-14 and leaves the API on 2027-01-14 — the default has to move, and OpenAI's own replacement is not the obvious choice. The one branch this run is unrelated: a reasoning default for `gpt-6.1-terra`, released 2026-10-26.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6434 — Send the lowest reasoning effort for gpt-6.1-terra

`gpt-6.1-terra` (Responses and Chat Completions, 2026-10-26) is a reasoning model with no `_THINKING_DEFAULTS` entry, so a bot that leaves `reasoning` unconfigured runs it at OpenAI's `medium` default and the service logs a warning about the unlisted model. Its model page lists `none` among its efforts; a live turn with `reasoning.effort="none"` is accepted, and a probe from the branch confirms the service now sends it.

### To consider
- **Default model** (high, since 2026-08-25) — the item has a date on it now: OpenAI's 2026-10-14 deprecation covers the GPT-4 series, `gpt-4.1` (`gpt-4.1-2025-04-14`) included, with removal from the API on **2027-01-14** and `gpt-6-luna` named as the replacement. `gpt-6-luna` does not clear the quality gate: aiewf-eval's medium-context leaderboard now has a `gpt-6-luna (low)` row at 91.8% against `gpt-4.1`'s 95.9%, and the `gpt-6-luna (none)` configuration — the one the service's reasoning default sends — completed 0 of 30 conversations (fixed-900 25.0%, unranked). Our own probe agrees on latency: median TTFAT 701 ms for `gpt-6-luna` against 565 ms for `gpt-4.1`. The only benchmarked model above `gpt-4.1` is `gpt-5.6-sol` at `effort="none"` (96.9%, leaderboard TTFAT P50 765 ms vs 743 ms), which OpenAI positions as the successor to `gpt-5` and `o3` rather than to `gpt-4.1`. Five examples (`examples/flows/yaml/*/bot.py`) pin `gpt-4.1` explicitly and retire with it. — *Needs a call: which model replaces `gpt-4.1` before 2027-01-14 — OpenAI's choice or the one that benchmarks at parity — and that `openai/llm` shares the same default.*
- **`gpt-6-luna` runs at `effort="none"` by default** (medium, since 2026-10-28) — `_THINKING_DEFAULTS` holds each model's lowest documented effort, which for `gpt-6-luna` is `none`. aiewf-eval's refresh shows that exact configuration failing to complete any of 30 multi-turn conversations, while the same model at `low` ranks 91.8%. Anyone who follows OpenAI's recommendation and selects `gpt-6-luna` gets `none` unless they configure `reasoning`. — *Needs a call: whether a model's documented lowest effort should give way to a working one when the lowest degrades multi-turn behavior, or whether a docstring note is enough.*
- **Mid-turn and long-running-work controls** (medium, since 2026-09-14) — unchanged: async tool calling (`async: true`, results tagged INTERRUPT / WHEN_IDLE / SILENT), mid-turn steering, and the `configuration_update` input item that changes `reasoning.effort` mid-conversation on the gpt-6 family. None is a pass-through parameter. — *Needs a call: whether any of them is worth designing for now, and which one voice users need first.*
- **Responses knobs only reachable via `extra`** (low, since 2026-08-25) — the SDK's top-level request schema is unchanged this run except that `access_programs` (Cyber program only) has landed in the installed SDK. OpenAI's 2026-10-20 12-hour prompt caching makes `prompt_cache_retention` the field users are most likely to reach for; `_build_response_params` ends with `params.update(self._settings.extra)`, so nobody is blocked. `reasoning.context` stays the one that is not a clean pass-through. — *Needs a call: named fields versus `extra` as the documented answer.*
- **`service_tier` is construction-time only** (low, since 2026-08-25) — OpenAI now lets an organization or project restrict which tiers are usable (2026-10-21), on top of Ultrafast being access-controlled per model, so choosing a tier per model still means rebuilding the service. Every other request knob is runtime-updatable through `Settings`. — *Needs a call: whether `service_tier` should move into `Settings`, which would leave two ways to set it.*
- **gpt-6-astra rejects `temperature` / `top_p`** (low, since 2026-09-14) — unchanged; both default to `NOT_GIVEN`, so only users who set them are affected, and the service already warns in the analogous reasoning case via `_warn_if_reasoning_unsupported`. — *Needs a call: whether per-model parameter support is worth tracking in the service, or the provider's error message is good enough.*

Harness caveats: `probe.py run --model/--setting` never reach `OpenAIResponsesLLMService`, because `build_kwargs` reads `inspect.signature(cls.__init__)` and the WebSocket class's signature is `(*, ws_url=..., **kwargs)`, so both overrides are dropped — all rows above are the HTTP class. `--setting 'reasoning={...}'` fails with `'dict' object has no attribute 'model_dump'`, since the dataclass field wants an `OpenAIResponsesReasoningConfig`; `extra` was used instead.

Closed since last run: PR #6136 (the `ultrafast` service-tier docstring) merged on 2026-10-12. Nothing else from the previous report is unaccounted for.
