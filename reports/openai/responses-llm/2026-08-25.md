# OpenAI Responses LLM — 2026-08-25

Nothing is broken or retiring: gpt-4.1 is absent from OpenAI's deprecation table and gpt-5.6 models run through both classes unchanged. One branch adds the new `max` reasoning effort; the default-model and SDK-pin questions need a maintainer.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5432 — Accept "max" reasoning effort in the OpenAI Responses service

### To consider
- **Default model** (medium, since 2026-08-25) — gpt-5.6 sol/terra/luna went GA on 2026-07-09 and are OpenAI's recommended replacements across the deprecation table, but gpt-4.1 itself is not deprecated and still produced the earlier first token in our probe (454 ms vs 673 ms for luna over WebSocket). A bump would also switch the default onto the reasoning-capable path, where the service requests `effort="none"` automatically. — *Needs a call: which tier, whether slower first-token latency is acceptable, and that `openai/llm` shares the same gpt-4.1 default.*
- **SDK pin behind openai 3.x** (medium, since 2026-08-25) — `pyproject.toml` pins `openai>=1.74.0,<3` while PyPI is at 3.3.1 (2026-08-19). openai-python 3.0.0 made HTTPX2 the default HTTP client and dropped the automatic `httpx` dependency, which `_create_client` uses for `DefaultAsyncHttpxClient(limits=httpx.Limits(...))`. — *Needs a call: whether Pipecat migrates to HTTPX2 — until then the pin cannot simply be widened.*
- **Responses knobs only reachable via `extra`** (low, since 2026-08-25) — `text.verbosity`, `prompt_cache_key`/`prompt_cache_retention`, `context_management`, `truncation`, `tool_choice`, `parallel_tool_calls` have no named `Settings` field. A live turn with them set through `extra` succeeded, so users are not blocked. — *Needs a call: named fields versus `extra` as the documented answer.*
- **`service_tier` and the "fast" tier** (low, since 2026-08-25) — Ultrafast mode (up to 14x faster gpt-5.6 Sol, pitched at voice) is opted into per request with `service_tier="fast"`; our constructor takes `service_tier` but its docstring lists only "auto", "flex", "priority", and the value is fixed at construction. — *Needs a call: whether to document a limited-preview tier and whether `service_tier` belongs in `Settings`.*

Harness caveat for the next run: `probe.py run --model/--setting` never reach `OpenAIResponsesLLMService`. `build_kwargs` reads `inspect.signature(cls.__init__)`, and the WebSocket class's signature is `(*, ws_url=..., **kwargs)`, so neither `model` nor `settings` is in it and both overrides are silently dropped (the run then measures the default model). The WebSocket rows above come from `.pw-scratch/ws_probe.py`, which constructs the service directly and reuses `probe.py`'s pipeline harness; the HTTP class inherits a normal `settings=` parameter and works with `probe.py` as is.
