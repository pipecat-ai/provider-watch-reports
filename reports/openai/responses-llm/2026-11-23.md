# OpenAI Responses LLM — 2026-11-23

GPT-6.2 Astra and Sol arrived on 2026-11-17 and need reasoning-defaults entries — branch ready; `gpt-4.1` is still the default and still leaves the API on 2027-01-14 with nothing benchmarked above it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6973 — Send the lowest reasoning effort for the gpt-6.2 models

Both models reject `reasoning.effort` below `low`: a probe returns 400 `Unsupported value: 'minimal' is not supported with the 'gpt-6.2-sol' model. Supported values are: 'low', 'medium', 'high', 'xhigh', and 'max'.`, and `none` the same way. OpenAI's "Using GPT-6.2" guide says "Start with `medium` for a new integration. If you currently use `none` or `minimal`, use `low` instead." The branch gives both models a `"low"` entry, matching the existing `gpt-6-astra` and `gpt-6.1-sol` rows; probes from the branch with `reasoning` unconfigured succeed for both.

The `gpt-5` family (`gpt-5`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5-pro`) and `o3` / `o3-pro` shut down on **2026-12-11**, three weeks out. All six are still live and still accept the effort the table sends, so their entries are not yet stale; the next run is expected to retire them.

### To consider
- **Default model** (high, since 2026-08-25) — unchanged and still dated: OpenAI removes `gpt-4.1` (`gpt-4.1-2025-04-14`) on **2027-01-14** and names `gpt-6-luna` as the replacement. aiewf-eval's medium-context leaderboard has not moved since 2026-10-19 — `gpt-6-luna (low)` 91.8% and `gpt-6-luna (none)` 0 of 30 completed, against `gpt-4.1` at 95.9% — so OpenAI's own choice still fails the quality gate, and `gpt-5.6-sol (none)` (96.9%, TTFAT P50 765 ms vs 743 ms) remains the only benchmarked model above it. The newly released `gpt-6.2-sol` and `gpt-6.2-astra` have no leaderboard row, so neither can be proposed yet. — *Needs a call: which model replaces `gpt-4.1` before 2027-01-14 — OpenAI's choice or the one that benchmarks at parity — and that `openai/llm` shares the same default.*
- **`gpt-6-luna` runs at `effort="none"` by default** (medium, since 2026-10-28) — unchanged: `_THINKING_DEFAULTS` holds each model's lowest documented effort, which for `gpt-6-luna` is `none`, the configuration that completed none of aiewf-eval's 30 multi-turn conversations. — *Needs a call: whether a model's documented lowest effort should give way to a working one when the lowest degrades multi-turn behavior, or whether a docstring note is enough.*
- **Top-level `instructions` lands after the input on gpt-6.2** (medium, since 2026-11-23) — `OpenAIResponsesLLMAdapter.get_llm_invocation_params` puts the system instruction in top-level `instructions` whenever the input is non-empty; it already builds a leading `developer` message, but only for the empty-input case. OpenAI's GPT-6.2 guide says models from gpt-6.2 on place top-level `instructions` *after* `input`, and that stable rules belong in a first-item developer message to stay prompt-cacheable. Nothing is broken at the `gpt-4.1` default, but a bot on a gpt-6.2 model loses system-prompt caching and has its instruction read last. — *Needs a call: whether the adapter should always lead with a developer message or switch on the model family, since either changes the request shape for every Responses user.*
- **Mid-turn and long-running-work controls** (medium, since 2026-09-14) — unchanged: async tool calling (`async: true`, results tagged INTERRUPT / WHEN_IDLE / SILENT), mid-turn steering, and the `configuration_update` input item that changes `reasoning.effort` mid-conversation on the gpt-6 family. None is a pass-through parameter. — *Needs a call: whether any of them is worth designing for now, and which one voice users need first.*
- **Responses knobs only reachable via `extra`** (low, since 2026-08-25) — the SDK adds one top-level request field since the last run, `background_options` (the two- and eight-hour background completion windows), which a streaming voice turn has no use for. `_build_response_params` ends with `params.update(self._settings.extra)`, so nobody is blocked. — *Needs a call: named fields versus `extra` as the documented answer.*
- **`service_tier` is construction-time only** (low, since 2026-08-25) — unchanged; choosing a tier per model still means rebuilding the service. Its docstring also still lists `"flex"`, which OpenAI announced on 2026-11-17 is winding down and which new models will not support, with no shutdown date yet. — *Needs a call: whether `service_tier` should move into `Settings`, and whether the docstring should flag `"flex"` before OpenAI dates its removal.*
- **gpt-6-astra and both gpt-6.2 models reject `temperature` / `top_p`** (low, since 2026-09-14) — a probe setting `temperature` on `gpt-6.2-sol` returns 400 `Unsupported parameter: 'temperature' is not supported with this model.`, and OpenAI's GPT-6.2 guide tells integrations to omit `temperature`, `top_p` and `top_logprobs`. Both default to `NOT_GIVEN`, so only users who set them are affected. — *Needs a call: whether per-model parameter support is worth tracking in the service, or the provider's error message is good enough.*
- **Approval-gated reasoning models have no table entry** (low, since 2026-11-09) — `gpt-6-rosalind`, `gpt-6-cyber` and now `gpt-6.2-astra-law` (identifier added by openai SDK 3.53.0 on 2026-11-17; model page 404s) are Responses models behind trusted access. None is in our catalogue, none can be probed, and OpenAI publishes no effort list for any, so there is no documented lowest effort to record. — *Needs a call: whether approval-gated specialist models belong in the table at all.*
