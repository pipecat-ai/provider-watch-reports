# OpenAI Responses LLM — 2026-09-01

Nothing is broken or retiring: gpt-4.1 is still absent from OpenAI's deprecation table. One branch documents the `fast` service tier; the default-model question is now down to latency alone, and the SDK pin still needs a repo-wide call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5548 — Document the "fast" service tier in the OpenAI Responses service

### To consider
- **Default model** (medium, since 2026-08-25) — the aiewf-eval gate that last run could not evaluate now has the rows. At `effort="none"` — the configuration the service sends automatically for reasoning-capable models — gpt-5.6-sol scores 96.6% against gpt-4.1's 96.3%, so sol is the one gpt-5.6 tier that is not a quality regression (terra "none" 91.3%, luna "none" 88.3%; terra reaches 97.8% only at `effort="medium"`, which is not what our default path requests). Latency is now the sole blocker: over WebSocket sol's median TTFAT is 615 ms against gpt-4.1's 517 ms on a trivial turn and 678 ms against 362 ms on a reasoning-triggering one, both outside the 10% band. — *Needs a call: whether that first-token cost is an acceptable price for a current-generation default, and that `openai/llm` shares the same gpt-4.1 default.*
- **SDK pin behind openai 3.x** (medium, since 2026-08-25) — `pyproject.toml` pins `openai>=1.74.0,<3` while PyPI is at 3.6.0 (2026-08-28), six minors into the new major. openai-python 3.0.0 made HTTPX2 the default HTTP client and dropped the automatic `httpx` dependency, which `_create_client` uses for `DefaultAsyncHttpxClient(limits=httpx.Limits(...))`. — *Needs a call: whether Pipecat migrates to HTTPX2 — until then the pin cannot simply be widened.*
- **Responses knobs only reachable via `extra`** (low, since 2026-08-25) — `text.verbosity`, `prompt_cache_key`/`prompt_cache_retention`, `context_management`, `truncation`, `tool_choice`, `parallel_tool_calls` are in the SDK's `ResponseCreateParams` but have no named `Settings` field. `_build_response_params` ends with `params.update(self._settings.extra)`, so users are not blocked. — *Needs a call: named fields versus `extra` as the documented answer.*
- **`service_tier` is construction-time only** (low, since 2026-08-25) — Fast mode is GA and OpenAI pitches it at latency-sensitive workloads, but selecting a tier means rebuilding the service; every other request knob is runtime-updatable through `Settings`. — *Needs a call: whether `service_tier` should move into `Settings`, which would leave two ways to set it.*

Harness caveat, unchanged from last run: `probe.py run --model/--setting` never reach `OpenAIResponsesLLMService`. `build_kwargs` reads `inspect.signature(cls.__init__)`, and the WebSocket class's signature is `(*, ws_url=..., **kwargs)`, so neither `model` nor `settings` is in it and both overrides are silently dropped (the run then measures the default model). The WebSocket rows above come from `.pw-scratch/ws_probe.py`, which constructs the service directly and reuses `probe.py`'s `_run_pipeline`; the HTTP class inherits a normal `settings=` parameter and works with `probe.py` as is.

Closed since last run: PR #5432 (`max` reasoning effort) merged on 2026-08-25, and the Literal in `OpenAIResponsesReasoningConfig` now carries the value.
