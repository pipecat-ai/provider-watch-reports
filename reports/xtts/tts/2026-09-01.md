# XTTS TTS — 2026-09-01

Current by default: the provider is gone, the service is already deprecated for removal in 2.0.0, and nothing needs a code change to keep working.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Stale `pipecat-ai[xtts]` extra** (medium, since 2026-09-01) — `ServiceRegistry` still advertises `package="pipecat-ai[xtts]"` for `xtts_tts`, and `ServiceLoader.extract_extras_for_services({"tts": "xtts_tts", ...})` returns `xtts`, but `pyproject.toml` defines no such extra (it was removed once the service dropped Coqui's dependencies and needed only core `aiohttp`). A `pipecat init` project therefore installs with an "unknown extra" warning. — *Needs a call: drop XTTS from the CLI registry outright, since it is deprecated and disappears in 2.0.0, or just correct the package string to `pipecat-ai`.*
- **Arabic missing from the language map** (low, since 2026-09-01) — XTTS-v2 supports `ar`; `language_to_xtts_language`'s `LANGUAGE_MAP` lists the other 16 codes, so `Language.AR` reaches the server only via `resolve_language(..., use_base_code=True)` and logs a "not verified" warning. One map entry fixes it. — *Needs a call: whether a service scheduled for removal in 2.0.0 is worth editing, and there is no reachable XTTS server to probe the change against.*
