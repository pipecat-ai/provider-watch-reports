# Mem0 memory — 2026-09-01

Nothing is broken or retiring: the service already speaks the mem0 2.x API (filters-based search, `top_k`, no `api_version`), and the pin `mem0ai>=2,<3` covers the latest release 2.0.19. Four affordance gaps are open, all needing a maintainer's call.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Search options** (medium, since 2026-09-01) — `rerank`, `categories` and metadata filters are not reachable from `InputParams`. mem0 2.0.0 flipped the `rerank` default from true to false, so Pipecat users silently lost managed reranking on upgrade; both client classes accept the flag, and a `rerank: bool = False` field would pass straight through to `search()`. — *Needs a call: reranking costs 150-200 ms per turn on the retrieval path that sits in front of the LLM call, so someone has to say whether it is opt-in only or should become the default.*
- **Add options** (medium, since 2026-09-01) — `_store_messages` sends `messages` plus a fixed `metadata={"platform": "pipecat"}` and nothing else; mem0's `AddMemoryOptions` also carries `custom_instructions`, `agent_custom_instructions`, `infer`, `expiration_date`, `timestamp`, `custom_categories` and `structured_data_schema`. `custom_instructions` (what to extract) and `infer=False` (store verbatim) are the two users typically ask for. — *Needs a call: whether caller metadata merges with or replaces the `platform` tag, and which options to surface individually rather than accepting an options object.*
- **Entity-ID filter semantics differ between the two clients** (medium, since 2026-09-01) — with `local_config` set and more than one of `user_id`/`agent_id`/`run_id` configured, `_retrieve_memories` and `get_memories` pass flat filter keys, which mem0 treats as AND; mem0 documents that ANDing `user_id` and `agent_id` matches only records with both fields, which the default extraction path never produces, so recall returns nothing. The cloud path builds `{"OR": [...]}` and works. — *Needs a call: OSS `Memory.search` raises unless one of the entity IDs is a flat top-level key in `filters`, so aligning the local path on OR semantics needs a decision on the filter shape and a local-client run to confirm.*
- **Synchronous clients on a thread** (low, since 2026-09-01) — every store/search/get_all goes through `asyncio.to_thread` around the sync client; mem0ai 2.x ships `AsyncMemoryClient` and `AsyncMemory`. — *Needs a call: whether the rewrite is worth it, given `to_thread` already keeps the event loop free.*
