# Groq STT — 2026-09-14

Groq shipped no STT change since the last run: same two Whisper models, same request schema, nothing deprecated. The one item to act on is unchanged — the auto-language-detection path Pipecat documents still errors.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`language=None` errors instead of auto-detecting** (high, since 2026-09-01) — `GroqSTTService._transcribe` opens with `assert self._settings.language is not None`; re-probed today with `Settings(language=None)` and got zero `TranscriptionFrame`s and one `ErrorFrame` reading `Unknown error occurred: ` (the AssertionError has no message). Groq lists `language` as optional and Whisper detects the language when it is absent, and Pipecat's own docs page tells users to set `language=None` for exactly that. Dropping the assert and omitting the key when it is None is the shape of the fix. — *Needs a call: `openai/stt.py` has the identical assert, so this is either a Groq-only fix or a whisper-family one, and the gpt-4o transcribe models OpenAISTTService defaults to may not tolerate an omitted language the way Whisper does.*
- **`Settings.extra` never reaches the request** (medium, since 2026-09-01) — the kwargs dict in `_transcribe` covers `model`, `language`, `prompt` and `temperature` and nothing else. A probe setting `extra={"timestamp_granularities":["word"]}` transcribed normally instead of failing, which is how the API answers that combination when `response_format` is `json` — so `extra` was silently discarded. Groq's `timestamp_granularities[]`, an explicit `response_format`, and the `url` upload form have no path through the service; `response_format` is chosen solely by `include_prob_metrics`. — *Needs a call: whether `extra` should be spread into the whisper services' transcription requests at all, and whether word timestamps are worth exposing before `TranscriptionFrame` can carry them.*
- **10-second minimum billed length** (low, since 2026-09-01) — Groq bills every transcription request as at least 10 seconds, and `SegmentedSTTService` issues one request per utterance, so a bot with 1–3 s turns pays multiples of its audio duration. Nothing in the service docstring or the docs page says so. — *Needs a call: the note belongs in the docs repo; confirm the docs team wants it.*
