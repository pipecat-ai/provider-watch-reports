# Groq TTS — 2026-09-01

`canopylabs/orpheus-v1-english` is Groq's current English TTS model and the shipped default
is right; the shipped sample rate is not, and a branch fixes it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5538 — Run GroqTTSService at Groq's 24 kHz output rate

### To consider
- **`output_format` promises formats Orpheus rejects** (medium, since 2026-09-01) — the
  constructor's `GroqAudioFormat` alias offers `flac`, `mp3`, `mulaw` and `ogg`; a request for
  `mulaw` comes back `400 … response_format must be one of [wav]`, and `run_tts` decodes each
  chunk with `wave.open`, so nothing but WAV could be handled even if the API allowed it. A
  user who sets `output_format="mp3"` gets an `ErrorFrame` and no audio. — *Needs a call:
  narrowing the public alias to `Literal["wav"]` or dropping the argument is a breaking change,
  so the choice between narrowing, validating at construction, and documenting is a
  maintainer's.*
- **`Settings.speed` is inert** (low, since 2026-09-01) — Orpheus accepts any `speed` in the
  documented 0.5–5 range and returns byte-identical PCM (`speed=0.5` and the default share an
  md5). Only an inline comment in `run_tts` records this; the `Settings` docstring advertises a
  "Speech speed multiplier". — *Needs a call: document the no-op on the field, or warn when a
  user sets anything other than 1.0.*
- **200-character input limit is unenforced** (low, since 2026-09-01) — Groq's Orpheus page says
  to keep input under 200 characters per request, and Pipecat's sentence aggregation regularly
  exceeds that. A 252-character request synthesized without complaint (15.1 s of audio), so this
  is a quality guideline rather than a rejection. — *Needs a call: whether over-limit input
  actually degrades before adding splitting or a warning.*

The PlayAI models the service originally targeted are gone — `playai-tts` and `playai-tts-arabic`
shut down on 2025-12-31 with Orpheus as the named replacement — and nothing in the repo still
references them. Both Orpheus models are reachable today: `Settings.model` has no allowlist, so
`canopylabs/orpheus-arabic-saudi` needs only a model plus an Arabic voice. Orpheus's vocal
direction tags (`[cheerful]`, `[whisper]`) are inline text and already pass through unchanged.
The groq SDK pin is current.

## Verification

| model                        | class / path                   | ok | latency          | note |
| ---------------------------- | ------------------------------ | -- | ---------------- | ---- |
| canopylabs/orpheus-v1-english | GroqTTSService                 | ✅ | TTFB 652 / 809 ms | shipped default; audio frames produced (TTFA 1.17 / 1.32 s, 0.515 s leading silence) |
| canopylabs/orpheus-v1-english | GroqTTSService (branch, 24 kHz) | ✅ | TTFB 649 ms      | probe run with the worktree's source on `PYTHONPATH`; unchanged latency, audio produced |
| canopylabs/orpheus-v1-english | raw `/audio/speech`            | ✅ | —                | every response is a 24 kHz mono 16-bit WAV, whatever `sample_rate` asks for |
| canopylabs/orpheus-v1-english | raw, `sample_rate=8000`        | ⚠️ | —                | header says 8000, PCM md5 identical to the default: a relabel, so playback is 3× slow |
| canopylabs/orpheus-v1-english | raw, `speed=0.5` / `1.5`       | ⚠️ | —                | accepted, PCM md5 identical to the default |
| canopylabs/orpheus-v1-english | raw, `response_format=mulaw`   | ❌ | —                | `400 … response_format must be one of [wav]` |
| canopylabs/orpheus-v1-english | raw, 252-character input       | ✅ | —                | accepted, 15.1 s of audio, no error despite the documented 200-character limit |

`probe.py run` never prints its JSON for this service: `TTSService._maybe_pause_frame_processing`
holds frame processing until a `BotStoppedSpeakingFrame` the bare probe pipeline never emits, so
the run stalls at shutdown and is killed. Latencies above are read from `--verbose` logs. It is
the harness limitation the asyncai/tts report describes, shared by every TTS service with
`pause_frame_processing=True`, not a Groq defect. Ad-hoc scripts are in
`.pw-scratch/groq_tts_params.py`, `groq_tts_params2.py`, `groq_tts_chunks.py`,
`groq_tts_limit.py`.
