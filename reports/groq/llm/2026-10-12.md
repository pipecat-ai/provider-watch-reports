# Groq LLM — 2026-10-12

Nothing to do: `openai/gpt-oss-120b` is still Groq's only production chat flagship, the `reasoning_effort` field landed in pipecat-ai/pipecat#5748, and no string Pipecat ships names a retired model.

## What's new for Pipecat

### PRs
Nothing. pipecat-ai/pipecat#5748 (`reasoning_effort` on `GroqLLMSettings`) merged on 2026-09-14; that gap is closed and the field is in `src/pipecat/services/groq/llm.py`.

### To consider
- **Groq's reasoning default stands as shipped** (low, since 2026-09-01) — `openai/gpt-oss-120b` reasons on every turn; `reasoning_effort="low"` cut median TTFAT from 550 ms to 434 ms on a trivial prompt but was slower on a reasoning-triggering one (466 ms against 350 ms). The stronger half of last run's case has expired: `qwen/qwen3.6-27b` is shut down, and `qwen/qwen3.8-27b` answers both a trivial and a reasoning prompt with no `<think>` in the stream. — *Needs a call: ship `reasoning_effort="low"` for a modest, prompt-dependent latency gain on one model, or leave Groq's default alone?*
- **`reasoning_format` and `include_reasoning`** (low, since 2026-09-14) — Groq's own parameters, reachable only through `Settings.extra` today; a field pair would travel in `extra_body`. `openai/gpt-oss-120b` returns a 400 for `reasoning_format`, and no catalogue model now streams reasoning inline, so this buys little. — *Needs a call: Groq documents the two as mutually exclusive, so exposing both needs a stance on a user setting both.*
- **qwen/qwen3.8-27b** (low, since 2026-09-01) — still Groq *preview*, so it cannot be a default; its aiewf-eval rows (98.2% / 97.8%) come from Baseten and a local GPU, never from Groq. — *Needs a call: nothing to do until Groq promotes it and a Groq-hosted row appears.*

Groq retired `groq/compound` and `groq/compound-mini` (2026-09-21) and `qwen/qwen3.6-27b` (2026-09-14) since the last run — that is the whole difference in the catalogue. Pipecat names none of them in the service, its docstrings, or `examples/`, and `examples/voice/voice-groq.py` pins `openai/gpt-oss-120b`, which is current.

The API reference's `reasoning_effort` enum is wider than ours (`minimal`, `xhigh`, `max`), but those are not a gate we impose: `openai/gpt-oss-120b` answers `minimal` with a 400 naming `low`, `medium`, `high`, which is exactly what our `Literal` allows plus the Qwen values. `service_tier` (Groq's `flex`/`performance`) is already a base `Settings` field.
