# Groq LLM — 2026-11-23

Nothing to do: `openai/gpt-oss-120b` remains the only featured flagship on Groq's models page, it is absent from the deprecations page, and the `/models` catalogue is byte-identical to the last three runs.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Groq's reasoning default** (low, since 2026-09-01) — a fourth measurement, again favoring `reasoning_effort="low"` on both prompts: 249 ms TTFAT against 372 ms shipped on a trivial prompt (median of 5 each) and 376 ms against 497 ms on a reasoning-triggering one (median of 3 each, non-overlapping ranges). Over four runs `low` leads six of eight comparisons, with both exceptions in earlier runs. — *Needs a call: shipping `reasoning_effort="low"` changes what the service does by default, so it is a maintainer's decision, not an automatic bump.*
- **`reasoning_format` and `include_reasoning`** (low, since 2026-09-14) — Groq's own parameters, reachable only through `Settings.extra` today; a field pair would travel in `extra_body`. Groq still documents `reasoning_format` as unsupported on GPT-OSS and mutually exclusive with `include_reasoning`, and no catalogue model streams reasoning inline. — *Needs a call: Groq documents the two as mutually exclusive, so exposing both needs a stance on a user setting both.*
- **qwen/qwen3.8-27b** (low, since 2026-09-01) — still Groq *preview*, so it cannot be a default, and its two aiewf-eval rows (96.0% Baseten FP8, 95.1% local RTX 5090) are both off-Groq and unchanged. — *Needs a call: nothing to do until Groq promotes it and a Groq-hosted row appears.*
- **`xhigh` reasoning effort** (low, since 2026-10-28) — `meta-models/muse-spark-open` reasons always-on and defaults to `reasoning_effort="xhigh"`, a value our `Literal` does not list; the gate is typing and docstring only. — *Needs a call: the model is Enterprise-gated, so `xhigh` cannot be probed from this account.*

Groq's preview tier is unchanged from the last run (`meta-models/muse-spark-open`, `minimaxai/minimax-m2.7`, `openai/gpt-oss-safeguard-20b`, `qwen/qwen3.8-27b`), both Enterprise entries still absent from the `/models` response this account sees. The changelog dates MiniMax M2.7's arrival to 2026-08-10, so it is older than its first appearance in these reports suggested; it remains Enterprise preview and documents no `reasoning_effort` values, so it changes nothing here.

No string Pipecat ships names a retired model: `examples/voice/voice-groq.py` is the only Groq example pinning one (`openai/gpt-oss-120b`), `examples/function-calling/function-calling-groq.py` pins none, and the service's docstring default matches. The deprecations page has gained no entries since the 2026-09-21 compound shutdown, the changelog's newest entry is still 2026-09-21, and the OpenAI-compatibility page's unsupported list (`logprobs`, `logit_bias`, `top_logprobs`, `messages[].name`, `n != 1`) is unchanged. aiewf-eval still has no Groq-hosted row, so a future Groq default bump has no same-host baseline.
