# Groq LLM — 2026-10-28

Nothing to do: `openai/gpt-oss-120b` is unchanged as Groq's production flagship and is not on the deprecations page; the model catalogue is identical to the 2026-10-12 run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Groq's reasoning default stands as shipped** (low, since 2026-09-01) — this run's medians go the other way from last run's: with shipped defaults `openai/gpt-oss-120b` answered a trivial prompt at 270 ms TTFAT against 290 ms with `reasoning_effort="low"` (median of 5 each), while on a reasoning-triggering prompt `low` won, 262 ms against 400 ms. Last run measured the opposite on both. Two runs apart, the effect is prompt-dependent and inside the spread. — *Needs a call: ship `reasoning_effort="low"` on a latency case that does not replicate, or leave Groq's default alone?*
- **`reasoning_format` and `include_reasoning`** (low, since 2026-09-14) — Groq's own parameters, reachable only through `Settings.extra` today; a field pair would travel in `extra_body`. Groq still documents `reasoning_format` as unsupported on GPT-OSS, and no catalogue model streams reasoning inline. — *Needs a call: Groq documents the two as mutually exclusive, so exposing both needs a stance on a user setting both.*
- **qwen/qwen3.8-27b** (low, since 2026-09-01) — still Groq *preview*, so it cannot be a default. aiewf-eval rescored it down to 96.0% (Baseten FP8) / 95.1% (local RTX 5090), and both rows are off-Groq. — *Needs a call: nothing to do until Groq promotes it and a Groq-hosted row appears.*
- **`xhigh` reasoning effort** (low, since 2026-10-28) — Groq's new `meta-models/muse-spark-open` (Enterprise limited preview, 2026-10-15) reasons always-on and defaults to `reasoning_effort="xhigh"`, a value our `Literal` does not list. The gate is typing and docstring only: `GroqLLMSettings(reasoning_effort="xhigh")` constructs without error, and `Settings.extra` passes the value through anyway. — *Needs a call: the model is Enterprise-gated, so `xhigh` cannot be probed from this account; widening the `Literal` for an unverifiable model is the question.*

The leaderboard moved under us: aiewf-eval archived the `gpt-oss-120b (groq)` row that earlier reports quoted at 86.3% / 98 ms. No Groq-hosted row remains, so the next Groq default bump has no same-host baseline to compare against — worth knowing before a candidate appears.

Groq's deprecations page gained no entries since 2026-09-21, and the changelog's newest entry is still 2026-04-18. No string Pipecat ships names a retired model: `examples/voice/voice-groq.py` is the only example that pins one (`openai/gpt-oss-120b`), and the other five Groq examples set no model at all.
