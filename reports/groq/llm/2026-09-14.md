# Groq LLM — 2026-09-14

`openai/gpt-oss-120b` is still Groq's production recommendation and nothing in the catalogue, changelog or deprecation list moved since 2026-09-01; the branch adds the `reasoning_effort` field, and what is left to decide is the service's reasoning default.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5748 — Expose Groq's reasoning effort control

### To consider
- **Groq's reasoning defaults stand as shipped** (medium, since 2026-09-01) — the default model reasons at medium effort on every turn (TTFAT 574 ms, 158 ms of it thinking, against 248 ms / 42 ms at `reasoning_effort=low`), and on the Qwen models Groq's `reasoning_format` default of `raw` puts the whole chain of thought into the spoken text: `qwen/qwen3.6-27b` answered "Say hello in five words" with 964 `LLMTextFrame`s starting `\n<think>\n`. `reasoning_effort` fixes both, and the house pattern is to pick the low-latency value — `DeepSeekLLMService` defaults `thinking` to disabled, pipecat-ai/pipecat#5446 disabled thinking by default on Sonnet 5. — *Needs a call: should `GroqLLMService` ship `reasoning_effort="low"`? It is a behavior change, and "low" is the floor only for gpt-oss; the Qwen models spell the same idea `"none"`, so one shipped value cannot suit every model.*
- **`reasoning_format` and `include_reasoning`** (low, since 2026-09-14) — Groq's own parameters, so they travel in `extra_body` rather than as client kwargs. `reasoning_format=parsed|hidden` is the only way to keep reasoning on while keeping it out of the spoken text (Qwen and MiniMax only — `openai/gpt-oss-120b` returns a 400 for `raw` and puts reasoning in the separate `reasoning` field regardless). — *Needs a call: Groq documents `include_reasoning` and `reasoning_format` as mutually exclusive, so exposing both needs a stance on a user setting both, and `reasoning_effort` already covers the common case.*
- **Qwen 3.6/3.8-27B** (low, since 2026-09-01) — both are still Groq *preview* models, so neither can be a default; the aiewf-eval rows are unchanged (97.3% / 97.8% against gpt-oss-120b's 86.3%) and still come from Baseten and a local GPU, never from Groq. — *Needs a call: nothing to do until Groq promotes one to production and a Groq-hosted row appears on the leaderboard.*

Two claims in the 2026-09-01 report do not hold and are not carried forward: `openai/gpt-oss-120b` does not accept `reasoning_format` (Groq documents it as unsupported for GPT-OSS, and `raw` comes back as a 400), and the parameters Groq documents as mutually exclusive are `include_reasoning` and `reasoning_format`, not `reasoning_format` and `reasoning_effort`. The `<think>` leak therefore cannot reach the shipped default model, and its remedy needs no nested `extra_body`: `reasoning_effort` is an OpenAI SDK keyword, so it passes straight through.

`probe.py --setting reasoning_effort=none` cannot express Groq's `"none"`: `_parse_literal` turns the string into Python `None`. The value was probed through `extra` instead, which puts the same key on the wire.
