# Kokoro TTS — 2026-09-01

The service is current with kokoro-onnx 0.6.1 (our pin allows it) and nothing is broken; the branch adds the `speed` control users have to reach around the service for today.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5543 — Add a speed setting to KokoroTTSService

### To consider
- **Model downloads point at the superseded release** (medium, since 2026-09-01) — `KOKORO_MODEL_URL`/`KOKORO_VOICES_URL` fetch from `model-files-v1.0`, while kokoro-onnx 0.6.x and its README publish the same two file names under `model-files-v1.1`, re-exported with a duration output (`create_timed()` timestamps, `continuous=True` synthesis) and an embedded vocab config. 0.6.1 loads the old export fine — it falls back to the packaged vocabulary and reports no timings — so this costs capability, not correctness. — *Needs a call: the v1.1 files have the same names as the cached v1.0 ones, so bumping the URLs leaves every existing install on the old graph unless the cache key changes too.*
- **Model variants are hand-rolled** (low, since 2026-09-01) — `Settings.model` is unused; the fp16 (164 MB) and int8 (114 MB) exports and the Chinese/English `kokoro-v1.1-zh` model with its 103-voice pack are reachable only by downloading them and passing `model_path`/`voices_path`. — *Needs a call: whether a `model` value should map to a download URL pair, and how the zh model's separate voice pack fits that mapping.*
- **Pause and trim controls** (low, since 2026-09-01) — `create_stream()` takes `trim`, `sentence_pause` and `clause_pause`, which set the silence kokoro-onnx puts between synthesis batches. — *Needs a call: not a plain pass-through — pauses are only inserted when `trim` is on, so the three have to be exposed as a group with that interaction documented.*

## Verification

| model                     | class             | ok | latency      | note                                                    |
| ------------------------- | ----------------- | -- | ------------ | ------------------------------------------------------- |
| kokoro-v1.0 (default)     | KokoroTTSService  | ✅ | TTFB 1734 ms | `--setting voice=af_heart`, main checkout               |
| kokoro-v1.0, speed 1.25   | KokoroTTSService  | ✅ | TTFB 1585 ms | `--setting speed=1.25` on the branch worktree           |

Local CPU synthesis, so the TTFB figures track the runner, not a provider. Direct kokoro-onnx check on the same downloaded model that the speed value reaches the graph: the same sentence is 2.88 s at `speed=1.0` and 1.79 s at `speed=1.5`; the model declares a float `speed` input, so fractional values are not rounded.
