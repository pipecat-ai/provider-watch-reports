# Piper TTS — 2026-11-23

Current: PR 5551 merged on 2026-11-10, and the docs page now shows
`base_url="http://localhost:5000/synthesize"`, so the two highest items from
the last run are both closed. Three packaging/settings items carry over,
none of them a PR on its own.

Piper has no model dimension (`default_model` is `null` for both classes); the
catalogue axis is voices, now 183 across 58 languages in `voices.json` (180
last run), all accepted as-is — no allowlist, no per-voice table. The example
bot's `en_US-ryan-high` is still catalogued. Our `piper-tts>=1.3.0,<2` pin is
on the latest release, 1.8.0; there has been no release since 2026-09-04.

`/synthesize` takes the same body as before (`text`, `voice`, `speaker`,
`speaker_id`, `length_scale`, `noise_scale`, `noise_w_scale`), all of which our
HTTP class now sends bar `speaker` — the name form that `speaker_id`, which we
do send, overrides. `API_HTTP.md` documents one new endpoint, `POST /download`,
which neither class calls. Upstream's unreleased work (an empty-WAV fix,
Japanese phonemization and a multi-codepoint phoneme fix in `libpiper`, split
encoder/decoder streaming, the `http_server` settings panel) touches neither
the endpoint nor the request body our classes use, and the Lithuanian voices
still wait on the unreleased `lithuanian` phoneme type, which our pin already
admits.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Chinese, Japanese and Thai voices are unreachable** (medium, since 2026-09-01) — `voices.json` ships `zh_CN`, `ja_JP` and `th_TH` voices, but `pipecat-ai[piper]` installs plain `piper-tts`: in the current environment `unicode_rbnf`, `pyopenjtalk` and `tltk` are all absent, so `piper.phonemize_chinese` fails at import and `phonemize_japanese` / `phonemize_thai`, which import theirs lazily, fail at synthesis time. — *Needs a call: the `zh` extra pulls `transformers`, `g2pW` and `sentence-stream`, `ja` pulls `pyopenjtalk-plus`, and `th` pulls `tltk` and `pandas` — whether `pipecat-ai[piper]` carries them or the docs tell users to install them.*
- **`volume` and `normalize_audio`** (low, since 2026-09-01) — `SynthesisConfig` as installed takes `speaker_id, length_scale, noise_scale, noise_w_scale, normalize_audio, volume`; the last two have no equivalent in Piper's `/synthesize` body, so only `PiperTTSService` could expose them. — *Needs a call: exposing them would make the two Piper settings classes asymmetric.*
- **Vestigial `requests` pin** (low, since 2026-09-01) — the `piper` extra pins `requests>=2.32.5,<3`; `piper-tts` 1.8.0's PyPI metadata declares no `requests` dependency in any extra, nothing under `src/pipecat/services/piper/` imports it, and `download_voices` uses `urllib`. — *Needs a call: confirm nothing else in the Piper path needs `requests` before dropping the pin.*
