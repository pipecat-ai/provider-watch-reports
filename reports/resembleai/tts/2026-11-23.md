# Resemble AI TTS — 2026-11-23

Nothing moved this run: the provider exit is still the only thing worth a maintainer's time, and
the API it left behind is unchanged and serving.

## What's new for Pipecat

### PRs
Nothing. (PR #5563, "Expose Resemble AI custom pronunciations", merged on 2026-11-09;
`apply_custom_pronunciations` is now a `ResembleAITTSSettings` field, so that gap is closed.)

### To consider
- **Resemble has exited commercial voice AI** (high, since 2026-11-09) — unchanged from last run.
  `docs.resemble.ai/llms.txt` now reduces the whole voice platform to one index entry, the Voice
  AI Research Archive, which says the generative voice models "remain open and free to build on
  under Voice AI Research, but are no longer offered as commercial paid products" and that the
  API documentation "does not imply continued availability of commercial voice services". The
  archived pages still resolve, the changelog has carried nothing but Detect releases since
  August, no shutdown date is published, and our probe synthesizes normally on an existing key.
  So this is still not breakage: it is a provider a new Pipecat user can no longer sign up with.
  — *Needs a call: whether to deprecate `ResembleAITTSService`, note the closed signup in our
  docs and in `examples/voice/voice-resemble.py` /
  `examples/update-settings/tts/tts-resembleai.py`, or leave it as-is for existing customers.*
- **First-audio latency** (medium, since 2026-09-01) — `_jitter_buffer_bytes = 44100` holds back
  audio until roughly a second of it has accumulated, so median TTFB is 468 ms over five runs
  today (356-960 ms), consistent with earlier runs and far above the ~200 ms time-to-first-sound
  the WebSocket page advertised. — *Needs a call: whether the buffer can shrink without gaps in
  playback; the 300-450 ms burst gaps the code comments cite have not been re-measured.*
- **`voice_settings_preset_uuid`** (low, since 2026-09-14) — the WebSocket reference does not
  list the field, but the endpoint reads it, and without it prosody can only be reached by
  writing SSML into the text. — *Needs a call: a preset UUID in the probe account to confirm a
  valid one synthesizes, and a stance on presets silently overriding equivalent SSML in `data`.*
- **`project_uuid`** (low, since 2026-09-01) — `_build_msg` never sends `project_uuid`. The
  WebSocket page marks it required, the OpenAPI spec calls it optional, and synthesis succeeds
  without it, so this is a missing capability — users cannot pick the project clips are filed
  under — not a request heading for rejection. — *Needs a call: whether to expose the project at
  all, and a project UUID to probe with, since none is available in the probe environment.*
- **Non-PCM16 audio formats** (low, since 2026-09-01) — the constructor documents `precision`
  values PCM_32/PCM_24/MULAW and `output_format` `mp3`, but the receive path aligns chunks to
  2 bytes and hands them downstream as raw PCM at `self.sample_rate`. — *Needs a call: confirm
  what a MULAW or mp3 session produces, then either carry the format through to the frames or
  narrow the documented values.*

The live probe is the evidence that the hosted WebSocket is still serving despite the archived
documentation. `probe.py run --service ResembleAITTSService` still needs the voice passed
explicitly: `voice` is a settings param here and the harness fills settings only from
`--setting` and registry `param_defaults`, never from `RESEMBLE_VOICE_UUID`.

The two examples that use the service and the `evals/release/manifest.yaml` entry hard-code no
model or voice — all read `RESEMBLE_API_KEY` / `RESEMBLE_VOICE_UUID` — so there is no retired
string to refresh.

No PR branch this run: every open item needs a maintainer's decision, starting with the provider
exit.
