# Resemble AI TTS — 2026-11-09

Resemble has left the voice business: the TTS documentation is now an explicit historical
archive and the company is not accepting new voice customers, so the open question is what
Pipecat does with this service rather than which knob to add next. Nothing is broken today —
the WebSocket still synthesizes for an existing key and the request schema is unchanged.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5563 — Expose Resemble AI custom pronunciations (open since 2026-09-01)

### To consider
- **Resemble has exited commercial voice AI** (high, since 2026-11-09) — the 2026-08-13 post
  from Resemble's CEO says the voice models "are open and free to use, but we won't be
  producing new ones for commercial sale" and "We're supporting our existing customers but not
  taking new ones". The documentation followed: `docs.resemble.ai`'s index now lists only the
  Detect products, and every voice page — text-to-speech, the streaming WebSocket, model
  versions, voice settings presets — has moved under `/voice-archive`, "retained for historical
  reference", with the note that the API guides "describe the former hosted voice platform;
  they do not imply continued availability of commercial voice services". Voice Design was
  removed outright on 2026-09-28. The pages themselves still resolve, no shutdown date is
  published, and our probe synthesizes normally on an existing key — so this is not breakage,
  it is a provider a new Pipecat user can no longer sign up with. — *Needs a call: whether to
  deprecate `ResembleAITTSService`, note the closed signup in our docs and in
  `examples/voice/voice-resemble.py` / `examples/update-settings/tts/tts-resembleai.py`, or
  leave it as-is for existing customers.*
- **First-audio latency** (medium, since 2026-09-01) — `_jitter_buffer_bytes = 44100` holds back
  audio until roughly a second of it has accumulated, so median TTFB is 534 ms over five runs
  today (427-584 ms), consistent with the 551-687 ms of earlier runs and far above the ~200 ms
  time-to-first-sound the WebSocket page advertised. — *Needs a call: whether the buffer can
  shrink without gaps in playback; the 300-450 ms burst gaps the code comments cite have not
  been re-measured.*
- **`voice_settings_preset_uuid`** (low, since 2026-09-14) — unchanged as a capability: the
  WebSocket reference does not list the field, but the endpoint reads it (a well-formed UUID the
  account does not own comes back as `Unauthorized ... invalid voice settings preset`), and
  without it prosody can only be reached by writing SSML into the text. Dropped from medium
  because adding request knobs to a product the provider has stopped selling is hygiene now. —
  *Needs a call: a preset UUID in the probe account to confirm a valid one synthesizes, and a
  stance on presets silently overriding equivalent SSML in `data`.*
- **`project_uuid`** (low, since 2026-09-01) — `_build_msg` never sends `project_uuid`. The
  WebSocket page marks it required, but Resemble's OpenAPI spec calls it optional on both HTTP
  synthesis endpoints and synthesis succeeds without it, so this is a missing capability —
  users cannot pick the project clips are filed under — not a request heading for rejection. —
  *Needs a call: whether to expose the project at all, and a project UUID to probe with, since
  none is available in the probe environment.*
- **Non-PCM16 audio formats** (low, since 2026-09-01) — the constructor documents `precision`
  values PCM_32/PCM_24/MULAW and `output_format` `mp3`, but the receive path aligns chunks to
  2 bytes and hands them downstream as raw PCM at `self.sample_rate`. — *Needs a call: confirm
  what a MULAW or mp3 session produces, then either carry the format through to the frames or
  narrow the documented values.*

The live probe is the evidence that the hosted WebSocket is still serving despite the archived
documentation. `probe.py run --service ResembleAITTSService` still needs the voice passed
explicitly: `voice` is a settings param here and the harness fills settings only from
`--setting` and registry `param_defaults`, never from `RESEMBLE_VOICE_UUID`.

The two examples that use the service (`examples/voice/voice-resemble.py`,
`examples/update-settings/tts/tts-resembleai.py`) and the `evals/release/manifest.yaml` entry
hard-code no model or voice — all read `RESEMBLE_VOICE_UUID` — so there is no retired string to
refresh.

No PR branch this run: the one open question is the provider exit, which is a maintainer's call,
and the remaining items are unchanged from last run.
