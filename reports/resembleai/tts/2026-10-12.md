# Resemble AI TTS — 2026-10-12

Service is current — Resemble Ultra is still the only hosted model and it is selected by the
voice, so there is no default to bump, and the WebSocket request schema has not changed. The
pronunciations PR is still the only pending code.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5563 — Expose Resemble AI custom pronunciations (open since 2026-09-01)

### To consider
- **`voice_settings_preset_uuid`** (medium, since 2026-09-14) — Resemble's Voice Settings
  Presets save a `pace` / `pitch` / `temperature` / `exaggeration` / `useHd` / `description`
  combination and are applied per request. The WebSocket reference table does not list the
  field, but the endpoint reads it: a well-formed UUID the account does not own comes back as
  `Unauthorized ... invalid voice settings preset` rather than being ignored. Without it,
  prosody and expressiveness can only be reached by writing SSML into the text. — *Needs a call:
  a preset UUID in the probe account to confirm a valid one synthesizes, and a stance on presets
  silently overriding equivalent SSML in `data`.*
- **First-audio latency** (medium, since 2026-09-01) — `_jitter_buffer_bytes = 44100` holds back
  audio until roughly a second of it has accumulated, so measured TTFB is 578 ms today (551 ms
  and 561-687 ms on the two previous runs) while Resemble advertises ~200 ms time-to-first-sound
  for this WebSocket. — *Needs a call: whether the buffer can shrink without gaps in playback;
  the 300-450 ms burst gaps the code comments cite have not been re-measured.*
- **`project_uuid`** (low, since 2026-09-01) — `_build_msg` never sends `project_uuid`. The
  WebSocket page marks it required, but Resemble's OpenAPI spec calls it optional on both HTTP
  synthesis endpoints and synthesis succeeds without it, so this is a missing capability —
  users cannot pick the project clips are filed under — not a request heading for rejection.
  Dropped from medium for that reason. — *Needs a call: whether to expose the project at all,
  and a project UUID to probe with, since none is available in the probe environment.*
- **Non-PCM16 audio formats** (low, since 2026-09-01) — the constructor documents `precision`
  values PCM_32/PCM_24/MULAW and `output_format` `mp3`, but the receive path aligns chunks to
  2 bytes and hands them downstream as raw PCM at `self.sample_rate`. — *Needs a call: confirm
  what a MULAW or mp3 session produces, then either carry the format through to the frames or
  narrow the documented values.*

## Verification

| model | class                | ok | latency     | note                                                  |
| ----- | -------------------- | -- | ----------- | ----------------------------------------------------- |
| n/a   | ResembleAITTSService | ✅ | TTFB 578 ms | current `main`, `--setting voice=$RESEMBLE_VOICE_UUID` |

`probe.py run --service ResembleAITTSService` still needs the voice passed explicitly: `voice`
is a settings param here and the harness fills settings only from `--setting` and registry
`param_defaults`, never from `RESEMBLE_VOICE_UUID`. With `voice_uuid` null Resemble drops the
socket without an error message.

The two examples that use the service (`examples/voice/voice-resemble.py`,
`examples/update-settings/tts/tts-resembleai.py`) hard-code no model or voice — both read
`RESEMBLE_VOICE_UUID` — so there is nothing to refresh there.

## Sources
- https://docs.resemble.ai/getting-started/model-versions.md — unchanged: Resemble Ultra
  (`resemble-ultra`) is the current and only supported TTS model, chosen by `voice_uuid`, and the
  page says not to pass a `model` field. `tts-v4`/`tts-v4-turbo` (Chatterbox), `tts-v3`, `tts-v2`,
  `tts-v1` and `tts-legacy` remain end of life, with no dates given.
- https://docs.resemble.ai/voice-generation/text-to-speech/streaming-websocket.md — request schema
  unchanged since last run: `voice_uuid`, `project_uuid` (both marked required), `data`,
  `request_id`, `binary_response`, `output_format`, `sample_rate`, `precision`, `no_audio_header`,
  `apply_custom_pronunciations`. Business plan, 20 concurrent sessions per key, 3,000 characters.
- https://docs.resemble.ai/openapi.json — covers the REST endpoints only, no WebSocket. `/synthesize`
  and `/stream` both describe `project_uuid` as optional, which is what downgraded that gap; both
  also carry `use_hd` and a 48000 Hz sample rate the WebSocket does not offer.
- https://docs.resemble.ai/platform-management/voice-settings-presets.md — a preset's `settings`
  object holds `pace`, `temperature`, `pitch`, `useHd`, `exaggeration` and `description`, applied
  via `voice_settings_preset_uuid` on a synthesis request; the page warns a preset overrides
  equivalent SSML in `data` and does not say which endpoints accept the field.
- https://docs.resemble.ai/llms.txt — documentation index; still no changelog, release-notes or
  deprecations page, so Model Versions remains the retirement source. New since last run are
  Duets and Term Substitutions API sections, neither of which the WebSocket request schema can
  reach.
- probe.py list-models exits with "no model catalogue known"; probe.py sdk-versions reports nothing,
  as the `resembleai` extra has no dependencies and so no pin to track.
