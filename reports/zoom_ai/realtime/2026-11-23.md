# Zoom AI realtime — 2026-11-23

Current: `gemma-4` is still the only Zoom-hosted Voice Agent model, the ten voices are unchanged, and
every documented session field is reachable from `Settings`. One new question — the `session.type`
field in Zoom's own sample bodies — needs a live session to settle, and no credential is available.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`session.type` not sent** (medium, since 2026-11-23) — Zoom's `zoom/skills` voice-agent reference
  puts `"type": "realtime"` inside `session` for both the v1 and v2 bodies, and lists the refusal
  `first event must be a session.update carrying a realtime session`; the live-mode docs page, which
  is the normative schema, never mentions it, and `events.SessionProperties` has no `type` field.
  Adding `type: Literal["realtime"] = "realtime"` to `SessionProperties` would be a one-line change;
  today a user can get the same with `extra={"type": "realtime"}`. —
  *Needs a call: whether the server requires the field or defaults it cannot be settled from two
  Zoom sources that disagree, and the probe that would settle it needs ZOOM_AI_API_KEY.*
- **Reasoning on later session updates** (low, since 2026-11-09) — `_build_session` sends
  `think.reasoning` on every `session.update`, while Zoom's live-mode field table says to set the
  reasoning level in the first `session.update`; `provider` and `listen` are already gated on
  `first`. — *Needs a call: it is unknown whether the server rejects or ignores reasoning in a later
  update, and confirming that needs a live session.*

Dropped since the last report: the service's `docs_url`
(`https://docs.pipecat.ai/api-reference/server/services/s2s/zoom-ai`) now returns 200 and documents
the class, its `gemma-4` default and its settings, so the "no docs page" gap is closed.
