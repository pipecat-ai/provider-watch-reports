# Sarvam LLM — 2026-08-31

The default `sarvam-105b` thinks before every answer — TTFAT 10.2 s on "what is the capital of India" — and no `Settings` value can stop it; that decision, and whether the voice-agent variant should be the default, are the two calls to make.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Reasoning is always on for the default model** (high, since 2026-08-31) — Sarvam's `reasoning_effort` defaults to `medium`, so `sarvam-105b` spends a median 9301 ms thinking before its first answer token. Sarvam documents disabling it by sending `reasoning_effort: null`, and on `/v1` that works (805 ms vs 15.1 s for the same prompt); on `/v2`, where `SarvamLLMService` sends `sarvam-105b`, the null is ignored and the model still emits ~680 reasoning tokens. `SarvamLLMSettings.reasoning_effort=None` means "don't send the field", so the null can never be expressed. — *Needs a call: an explicit-null value needs a sentinel or a Sarvam-specific default, and it only bites on `/v1`, so honouring it also means routing Sarvam's own models to `/v1` — both change behavior for existing users.*
- **`sarvam-105b-conversations` as the default** (medium, since 2026-08-31) — the conversational variant answers in 888 ms median against 10219 ms for `sarvam-105b`, is GA, and is the model Sarvam describes for "real-time dialogue and voice-agent workloads". Sarvam still calls `sarvam-105b` its flagship, so this is a Pipecat-side judgement, not a provider succession. — *Needs a call: aiewf-eval's `aiwf_medium_context` leaderboard has no Sarvam rows at all, so the quality condition for a default bump cannot be checked.*
- **`deepseekv4-flash` is blocked by the allowlist** (medium, since 2026-08-31) — `GET /v2/models` lists it and a direct `/v2/chat/completions` call answered in 1120 ms with no reasoning pass, but `_SUPPORTED_MODELS` makes the constructor raise for it. Sarvam's changelog and model pages do not mention the model. — *Needs a call: whether to accept a model Sarvam has not announced, and which of the vision/reasoning/wiki-grounding sets it belongs in.*
- **Capability tables drifted from the docs** (medium, since 2026-08-31) — `_WIKI_GROUNDING_MODELS` and `_REASONING_MODELS` list `gemma4`, which Sarvam's open-source page marks as neither reasoning nor wiki-grounding capable, and omit `sarvam-105b-conversations`, for which `/v1` accepted both `reasoning_effort=low` and `wiki_grounding=true`. The user-visible effect is an error frame on the conversations model for parameters the API takes. — *Needs a call: HTTP 200 is not proof the parameters do anything there, so this needs a stance on validating against the docs or against what the API accepts.*
- **`sarvamai` pin behind PyPI** (low, since 2026-08-31) — `pyproject.toml` pins `sarvamai==0.1.28`, latest is 0.1.31 (2026-08-26). The LLM service talks to Sarvam through the `openai` SDK, so this only reaches it via the shared extra. — *Needs a call: the bump belongs with the Sarvam STT/TTS services that import the SDK.*
