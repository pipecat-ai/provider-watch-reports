# Sarvam LLM — 2026-11-09

`deepseekv4.1-flash` is a dead name: Sarvam renamed it `deepseekv4.1-flash-1017` at GA on
2026-10-30, two weeks after PR #6138 put the short form in the allowlist. Six models Sarvam
now serves on /v2 — two of them GA — are blocked by the same allowlist. No branch: the
account is out of credits, so nothing could be confirmed by request, and every one of these
changes needs a passing probe.

## What's new for Pipecat

### PRs

### To consider

- **`deepseekv4.1-flash` no longer exists** (high, since 2026-11-09) — gone from `GET /v2/models` and from the /v2 chat reference's model enum, which says an unknown or wrongly cased ID returns 404. `_SUPPORTED_MODELS`, `_REASONING_MODELS` and `tests/test_sarvam_llm.py` all still name it; the replacement is `deepseekv4.1-flash-1017`, GA since 2026-10-30 with a 1M context window, text and image input and `reasoning_effort` defaulting to `high`. — *Needs a call: the rename is documented but unconfirmed by request, because the account returns 402 on every completion; the swap wants one passing probe first.*
- **Reasoning runs at Sarvam's default on every model** (high, since 2026-08-31) — the service carries no reasoning-defaults table, so `glm5.3` and `kimi-k3.1-pro` reason at `max`, `glm5.3-flash` and the DeepSeek models at `high`, and `qwen38-27b` with thinking on. The /v2 reference now documents the lowest setting for each (`none` on `deepseekv4.1-flash-1017`, `deepseekv4-pro` and `qwen38-27b`; `low` elsewhere), which is what CONTRIBUTING asks an LLM service to send. For the default `sarvam-105b` the model page still gives `reasoning_effort=None` as the off-switch, and `None` means do-not-send in our code, so that null is unreachable; the measured cost on 2026-10-12 was 4053 ms TTFAT against 885 ms with thinking off. — *Needs a call: whether Sarvam gets a `_THINKING_DEFAULTS` table — the base `LLMService._apply_thinking_default` is already there — and how to express the explicit null.*
- **Six models the allowlist blocks** (medium, since 2026-11-09) — `glm5.3-flash` (GA 2026-10-22), `deepseekv4.1-flash-1017` (GA 2026-10-30), `deepseekv4.1-flash-1017-interactive` (over 200 tok/s against about 80, which is the kind of difference a voice agent feels), `deepseekv4-pro`, `kimi-k3.1-pro` and `qwen38-27b`. `kimi-k3` and the two MiMo models are still in the catalogue but were withdrawn on 2026-11-06 and are absent from the chat enum. — *Needs a call: each wants a probe and the account has no credits; the three Provisioned Throughput models may not answer on a serverless key at all.*
- **`reasoning_effort` allows the wrong values** (medium, since 2026-10-12) — `Literal["low", "medium", "high"]` against a documented union of `none`, `low`, `medium`, `high`, `max`, taken in per-model subsets: `low`/`high`/`max` on `glm5.3`, `glm5.3-flash` and `gemma4`, all five on the DeepSeek models and `qwen38-27b`, and `low`/`medium`/`high`/`max` on `kimi-k3.1-pro` where `medium` runs as `high`. So `medium` is accepted by the Literal and rejected by half the catalogue, while `none` and `max` are the reverse. — *Needs a call: widen the Literal to the union and validate per model, or split the values by model the way `_REASONING_MODELS` already splits support.*
- **`sarvam-105b-conversations` as the default** (medium, since 2026-08-31) — 775 ms median TTFAT against 4053 ms on 2026-10-12, GA, and the variant Sarvam describes for real-time dialogue and voice agents. It trades 128K of context for 32K and lives on /v1, and the model page still calls `sarvam-105b` the flagship. — *Needs a call: aiewf-eval's `aiwf_medium_context` leaderboard, re-read this run, still has no Sarvam rows, so the quality condition for a default bump cannot be checked.*
- **`wiki_grounding` is undocumented but still sent** (medium, since 2026-08-31) — the parameter appears in no current Sarvam page, yet `_WIKI_GROUNDING_MODELS` holds `gemma4` and `sarvam-105b` and the service merges it into `extra_body` for them. `sarvam-105b-conversations` is in neither capability set although /v1 takes both parameters, so users on it get an error frame. The `gemma4` reasoning half of this item has resolved itself: the /v2 reference now documents `reasoning_effort` as accepted there, matching `_REASONING_MODELS`. — *Needs a call: HTTP 200 is not proof a parameter does anything, and tightening the sets converts silently-ignored parameters into error frames.*

The /v2 reference documents it as valid with `stream: true`, required at top level, with `include_usage` also reporting `reasoning_tokens`. — *Needs a call: whether /v1, which serves `sarvam-105b-conversations`, accepts it too; the pop is unconditional and lifting it changes requests on both versions.*
