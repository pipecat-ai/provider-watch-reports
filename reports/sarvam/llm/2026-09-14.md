# Sarvam LLM — 2026-09-14

`deepseekv4-flash` moved from undocumented to a full Sarvam model page, and it answers
through `SarvamLLMService` once the allowlist lets it in — branch ready. Sarvam also
quietly cut what reasoning costs on `sarvam-105b` (median TTFAT 1921 ms, down from
10219 ms) and there is a working off-switch via `extra_body`, so that item drops from
high to medium. Two undocumented models, `glm5.3` and `glm5.3-flash`, are new in the
`/v2` catalogue.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5757 — Accept deepseekv4-flash on SarvamLLMService

### To consider

- **Reasoning cannot be turned off through Settings** (medium, since 2026-08-31) — the default `sarvam-105b` still thinks on every turn, but the cost has collapsed: median TTFAT 1921 ms with 1137 ms of thinking over 5 repeats, against 10219 ms on 2026-08-31. Sarvam's docs now disagree with themselves on the default (`low` on the model page, `medium` in the /v1 API reference). `extra_body.chat_template_kwargs.enable_thinking=false` — which Sarvam documents for the `/v2` open-source models, not for its own — does work on `sarvam-105b`: TTFAT 1010 ms, thinking 0. A user can already reach it as `Settings(extra={"extra_body": {...}})`. — *Needs a call: whether to give `enable_thinking` a field of its own when it contradicts `reasoning_effort` and is undocumented for Sarvam's models, or to leave users on the `extra` escape hatch.*
- **`sarvam-105b-conversations` as the default** (medium, since 2026-08-31) — 869 ms median TTFAT against 1921 ms, GA, and the variant Sarvam describes for "real-time dialogue, voice agents, customer-facing chat". The gap is much narrower than it was, and the conversations variant trades 128K of context for 32K. — *Needs a call: aiewf-eval's `aiwf_medium_context` leaderboard, re-read this run, still has no Sarvam rows, so the quality condition for a default bump cannot be checked.*
- **Capability tables drifted from the docs** (medium, since 2026-08-31) — `gemma4` sits in both `_REASONING_MODELS` and `_WIKI_GROUNDING_MODELS`, yet its page says `reasoning_effort` "is accepted but has no effect" and the open-source overview says wiki grounding is available on Sarvam models only. `sarvam-105b-conversations` is in neither set although `/v1` accepts both parameters, so users on it get an error frame. `sarvam-105b`'s own wiki-grounding status is unclear — retired in the March 2026 changelog, absent from the model page, still recommended for it by the open-source selection table, and accepted with HTTP 200 on `/v2`. — *Needs a call: HTTP 200 is not proof a parameter does anything, and tightening the sets converts silently-ignored parameters into error frames.*
- **`glm5.3` and `glm5.3-flash` are blocked by the allowlist** (medium, since 2026-09-14) — both are new in `GET /v2/models` this run. Sarvam documents neither: no changelog entry, `…/open-source/glm-5-3` 404s, and the open-source overview lists only `glm5.2`, `gemma4` and `deepseekv4-flash`. — *Needs a call: whether to accept models Sarvam has not announced, and which capability sets they belong in.*
- **`sarvamai` pin behind PyPI** (low, since 2026-08-31) — `pyproject.toml` pins `sarvamai==0.1.28`, latest is 0.1.33 (2026-09-09). The LLM service talks to Sarvam through the `openai` SDK, so this only reaches it via the shared extra. — *Needs a call: the bump belongs with the Sarvam STT/TTS services that import the SDK.*
