# Sarvam STT — 2026-09-01

Nothing to ship. Sarvam published no STT changes since the last run, `src/pipecat/services/sarvam/stt.py` is untouched, and both classes transcribe correctly on a fresh probe.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Registry still scaffolds the legacy endpoint** (medium, since 2026-08-31) — Sarvam's streaming-api page states that `saaras:v3-realtime` supersedes the legacy WebSocket for new voice-agent and live-transcription work, but `sarvam_stt` in `cli/registry/service_metadata.py` still lists `class_name=["SarvamSTTService"]`, which speaks the legacy endpoint. No sunset date is published. — *Needs a call: whether SarvamRealtimeSTTService should become, or join, the registry's Sarvam STT entry while Sarvam still labels realtime beta.*
- **sarvamai pin behind PyPI** (low, since 2026-08-31) — `pyproject.toml` still pins `sarvamai==0.1.28`; 0.1.31 (2026-08-26) remains the latest and no 0.1.32 shipped this week. The only STT-facing difference is the model `Literal`, which is `Any`-unioned and has no runtime effect. — *Needs a call: whether provider-watch bumps an exact SDK pin when nothing STT-relevant changed.*
- **Partial language maps** (low, since 2026-08-31) — both endpoints accept 24 codes; `LANGUAGE_MAP` has 12 and the realtime map 15. Unmapped values still reach Sarvam via `resolve_language(..., use_base_code=False)` with a "not verified" warning, and several missing codes (`ks-IN`, `sat-IN`, `mni-IN`, `brx-IN`, `doi-IN`, `ne-IN`) have no `Language` enum member. — *Needs a call: whether to add the missing `Language` members for Sarvam's smaller scheduled languages.*
