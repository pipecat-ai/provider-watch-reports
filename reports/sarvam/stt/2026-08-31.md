# Sarvam STT — 2026-08-31

Nothing to ship: `saaras:v4`, `saaras:v3` and `saaras:v3-realtime` all transcribe through our classes, and every documented request parameter on both endpoints is reachable from `Settings`.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Registry still scaffolds the legacy endpoint** (medium, since 2026-08-31) — Sarvam's streaming-api page states that `saaras:v3-realtime` "supersedes this endpoint for new voice-agent and live-transcription work", but `sarvam_stt` in `cli/registry/service_metadata.py` (and `_configs.py`/`_imports.py`) only offers `SarvamSTTService`, which speaks the legacy WebSocket. No sunset date is published. — *Needs a call: whether SarvamRealtimeSTTService should become, or join, the registry's Sarvam STT entry while Sarvam still labels realtime beta.*
- **sarvamai pin behind PyPI** (low, since 2026-08-31) — `pyproject.toml` pins `sarvamai==0.1.28`; 0.1.31 shipped 2026-08-26. Diffing the two wheels, `speech_to_text_streaming.connect()` has an identical signature; the only STT-facing change is the model Literal (`saarika:v2.5` out, `saaras:v4` in), which is `Any`-unioned and so has no runtime effect. The rest is Doc AI, dubbing and chat-completions surface. — *Needs a call: whether provider-watch bumps an exact SDK pin when nothing STT-relevant changed.*
- **Partial language maps** (low, since 2026-08-31) — both endpoints accept 24 codes (incl. `ur-IN`, `ne-IN`, `ks-IN`, `sa-IN`, `sat-IN`, `mni-IN`, `brx-IN`, `doi-IN`); `LANGUAGE_MAP` in `language_to_sarvam_language` has 12 and the realtime map 15. Unmapped values still reach Sarvam via `resolve_language(..., use_base_code=False)`, only with a "not verified" warning. Several of the missing codes have no `Language` enum member. — *Needs a call: whether to add the missing `Language` members for Sarvam's smaller scheduled languages.*
