# Sarvam STT — 2026-09-14

Sarvam's realtime endpoint gained a second model generation on 2026-09-03; `SarvamRealtimeSTTService` hard-rejects it, and the branch lifts that. The model string is `saaras:v4` — the `saaras:v4-realtime` that Sarvam's changelog, realtime docs and SDK all name is rejected by the live endpoint.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5758 — Accept saaras:v4 on Sarvam's realtime STT endpoint

`_validate_settings` allowed exactly `saaras:v3-realtime`, so the newer generation could not be reached at all. The branch replaces the single-value check with a two-value allowlist and leaves the default on `saaras:v3-realtime`, which is Sarvam's own default for the endpoint — the docs offer v4 as "the latest model to try" and make no successor claim, so the default is not a bump this run.

### To consider
- **Registry still scaffolds the legacy endpoint** (medium, since 2026-08-31) — Sarvam's streaming-api page still states that the realtime endpoint supersedes the legacy WebSocket for new voice-agent and live-transcription work, but `sarvam_stt` in `cli/registry/service_metadata.py` still lists `class_name=["SarvamSTTService"]`, which speaks the legacy endpoint. No sunset date is published. — *Needs a call: whether SarvamRealtimeSTTService should become, or join, the registry's Sarvam STT entry while Sarvam still labels realtime beta.*
- **sarvamai pin behind PyPI** (low, since 2026-08-31) — `pyproject.toml` pins `sarvamai==0.1.28`; 0.1.33 shipped 2026-09-09. Diffing the wheels, `speech_to_text_streaming.connect()` is unchanged and the only STT-facing differences are `Any`-unioned model Literals, so no request we build changes. — *Needs a call: whether provider-watch bumps an exact SDK pin when nothing STT-relevant changed.*
- **SDK now ships a realtime client** (low, since 2026-09-14) — 0.1.33 adds `sarvamai.speech_to_text_realtime_streaming` (client, raw client, socket client, typed events), covering the endpoint `SarvamRealtimeSTTService` implements over raw websockets. Its connect signature matches `_query_params()` field for field, so there is no capability behind it. — *Needs a call: whether the hand-rolled realtime websocket is worth replacing with the SDK client, which would also require moving the pin.*
- **Partial language maps** (low, since 2026-08-31) — both endpoints accept 24 codes. `_map_language_code_to_enum` grew to 17 on 2026-09-11, but the connect-side `LANGUAGE_MAP` still has 12 and the realtime map 15. Unmapped values still reach Sarvam via `resolve_language(..., use_base_code=False)`, and `ks-IN`, `sat-IN`, `mni-IN`, `brx-IN`, `doi-IN`, `ne-IN` have no `Language` enum member. — *Needs a call: whether to add the missing `Language` members for Sarvam's smaller scheduled languages.*
