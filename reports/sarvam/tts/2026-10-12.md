# Sarvam TTS — 2026-10-12

Nothing to fix: `bulbul:v3` is still Sarvam's stable model and its API default, `bulbul:v4-flash` was added in #5844 and synthesizes on both classes, and PR #5759 closed the last example gap. Five items remain for a maintainer's call.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — `dict_id` is documented on both the REST body and the WebSocket config for v3 and v4-flash and the endpoint reads it, but it has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: a successful probe requires creating a dictionary through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **v4-flash pitch/loudness ranges** (medium, since 2026-10-12) — the API caps pitch at ±0.5 and loudness at 0.1–2.5 and answers anything outside with a 400 and no audio; `TTSModelConfig` clamps pace only, the `Settings` docstrings quote no range, and the deprecated `InputParams` still validates against bulbul:v2's wider bounds, so `pitch=0.7` passes Pipecat and fails Sarvam. — *Needs a call: add `pitch_range`/`loudness_range` to `TTSModelConfig` and clamp as pace does, or only fix the docstrings and the stale `InputParams` bounds.*
- **Cloned voices** (medium, since 2026-10-12) — Sarvam's Voice Cloning API went GA on 2026-09-26 and gained streaming (including an incremental-text WebSocket) on 2026-10-01, but it synthesizes through `/voices/clone*` rather than `/text-to-speech`, so neither class can reach it. — *Needs a call: whether a saved `voice_id` doubles as a `speaker` on the standard endpoint (unverified, since checking it creates a voice on the account) and, if not, whether Pipecat wants a cloned-voice class.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API rejects, and omits 14 of the 37 voices its error message enumerates. `voice` is a free string, so the enum gates nothing, but it also backs the public `get_speakers_for_model()`. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; Pipecat still carries it as an enum member and a model-config entry, and the endpoint still serves it. — *Needs a call: deprecate the pre-GA tag or leave it working.*

Dropped from the previous report: the beta-gated language codes. #6010 added the missing `-IN` `Language` members, and `language_to_sarvam_language` falls back to the full code (`use_base_code=False`), so `ur-IN` and the other 11 unmapped codes already reach the API — which gates them itself ("Please request beta access to ur-IN"). Only a "not verified" log line remains.
