# Sarvam TTS — 2026-11-23

Sarvam's Bulbul page, REST reference and WebSocket AsyncAPI now agree that `pace`, `pitch`, `loudness` and `temperature` all apply to `bulbul:v3` and `bulbul:v4-flash` over the same ranges; Pipecat's per-model flags drop three of those combinations, and a branch fixes it. `bulbul:v3` is still the TTS API's own default, so the default does not move.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6976 — Send every Sarvam voice control on both Bulbul models

### To consider
- **Pitch and loudness ranges** (medium, since 2026-10-12) — `TTSModelConfig` has a range for pace only, and the deprecated `InputParams` on both classes still accepts pitch -0.75 to 0.75 and loudness 0.3 to 3.0, Bulbul v2's bounds. Sarvam caps pitch at ±0.5 and loudness at 0.1–2.5 on v3 and v4-flash and answers anything outside with a 400 and no audio, so `pitch=0.7` passes Pipecat and fails Sarvam. The branch widens this: v3 now sends both fields too. — *Needs a call: add `pitch_range`/`loudness_range` to `TTSModelConfig` and clamp as pace does, or only tighten the stale `InputParams` bounds.*
- **Pronunciation dictionaries** (medium, since 2026-08-31) — `dict_id` is on the REST body, the WebSocket config and the Bulbul page ("Supported on both models"), and the endpoint read it when last probed, but it has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: a successful probe requires creating a dictionary through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **Cloned voices** (medium, since 2026-10-12) — Sarvam's Voice Cloning API synthesizes through `/voices/clone*` rather than `/text-to-speech`, so neither class can reach it, and Sarvam keeps extending it: `POST /voices/watermark/detect` landed on 2026-11-09. Our `sarvamai` pin is 0.1.28 against 0.1.49 on PyPI, though the TTS classes import no SDK. — *Needs a call: whether a saved `voice_id` doubles as a `speaker` on the standard endpoint (unverified, since checking it creates a voice on the account) and, if not, whether Pipecat wants a cloned-voice class.*
- **Bulbul V3's platform-side end of life** (medium, since 2026-10-28) — the Voice Agents retirement slipped from 2026-11-10 to 2026-11-25, and the TTS API stays exempt: v3 is still what Sarvam serves when `model` is omitted. Two old blockers to a bump are gone — v4-flash now takes `ml-IN` and `od-IN` with any persona, and there is a published V3-to-V4 name mapping — but v4-flash still rejects v3's short speaker names, and v4-flash is no longer the faster of the two (560 ms vs 549 ms, medians of 5, against 550 ms vs 646 ms on 2026-10-28). — *Needs a call: whether Pipecat follows the voice-agent guidance to v4-flash while the TTS API keeps v3 as its default, and if so how `voice="shubh"` configs are migrated.*
- **Codec settings stranded on `InputParams`** (medium, since 2026-10-28) — `output_audio_codec` and `output_audio_bitrate` exist on `SarvamTTSService` only as deprecated `InputParams` fields, with no `SarvamTTSSettings` equivalent, and `InputParams` is slated for removal in 2.0.0. Sarvam now documents `opus` as working on both models at 8000, 16000, 24000 and 48000 Hz, where its references previously called it rejected on v3 and v4. — *Needs a call: the WebSocket receive path turns the payload straight into `TTSAudioRawFrame` as PCM, so any codec other than `linear16` needs decoding first — decide whether the fields are carried into `Settings` or dropped with `InputParams`.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API rejects, and omits 14 of the 37 voices the Bulbul page enumerates. `voice` is a free string, so the enum gates nothing, but it also backs the public `get_speakers_for_model()`. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; Pipecat still carries it as an enum member and a model-config entry, and the endpoint still served it on 2026-10-28. — *Needs a call: deprecate the pre-GA tag or leave it working.*
- **Sample-rate docstring blames the model, not the transport** (low, since 2026-11-23) — `SarvamHttpTTSService.__init__` documents 32000/44100/48000 as bulbul:v3-only, while Sarvam says the three high rates are REST-only and apply to every Bulbul model. — *Needs a call after a probe: one REST call at 48000 on v4-flash would confirm the docs before the line is reworded.*
