# Sarvam TTS — 2026-08-31

Both Sarvam TTS classes ship a default model the API refuses to serve; the branch moves them to `bulbul:v3` and fixes an unrelated sample-rate field name.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5517 — Default Sarvam TTS to bulbul:v3 and send the REST sample rate under the field Sarvam reads

The branch carries two commits:

- **Default Sarvam TTS to bulbul:v3.** `bulbul:v2` is answered with `400 Model 'bulbul:v2' has been deprecated. Please use 'bulbul:v3' instead.` on both transports, so today a user who constructs either class without naming a model gets no audio at all. The v3 defaults come with the bump (`shubh`, 24000 Hz), and the model tables, docstrings and examples lead with v3.
- **Send `speech_sample_rate` in the REST request.** `SarvamHttpTTSService` put the rate under `sample_rate`, a key Sarvam accepts and ignores: synthesis came back at the model default while `TTSAudioRawFrame` was tagged with the requested rate, so any non-default rate played at the wrong speed.

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — bulbul:v3's `dict_id` is documented on both the REST body and the WebSocket config but has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: probing it requires a dictionary created through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API no longer accepts, and omits 14 voices Sarvam now lists. `voice` is a free string, so the enum gates nothing; it is a discoverability surface only. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; the endpoint still synthesizes with it, and Pipecat still carries it as an enum member and a model-config entry. — *Needs a call: deprecate the pre-GA tag or leave it working.*
- **Beta-gated languages** (low, since 2026-08-31) — the API's own validation error lists 23 accepted codes; `language_to_sarvam_language` maps the 11 generally available ones. The other 12 answer "Please request beta access", and 5 have no `Language` member. — *Needs a call: whether to map codes that only work for accounts with beta access, and whether that justifies new `Language` members.*

| bulbul:v2     | SarvamTTSService      | ❌ | TTFB 251 ms to the error    | `400 Model 'bulbul:v2' has been deprecated. Please use 'bulbul:v3' instead.`; three reconnects, then the service marks itself unusable |

| bulbul:v3-beta| SarvamHttpTTSService  | ✅ | 1.3 s end-to-end            | the retired tag is still served |
| bulbul:v3     | SarvamHttpTTSService (branch) | ✅ | —                   | `speech_sample_rate` honoured: 61440 bytes at 24000 Hz, 24576 at 8000 Hz; before the fix an 8000 Hz request returned 24 kHz audio |

`probe.py run` never prints its summary line for `SarvamTTSService`: the class sets `pause_frame_processing=True`, and with no output transport in the probe pipeline no `BotStoppedSpeakingFrame` arrives to lift the pause, so `EndFrame` never reaches the sink. Latency above is read from the service's own TTFB metric in the verbose log. `SarvamHttpTTSService` needs an `aiohttp_session`, which `probe.py` cannot supply, so it was exercised by short scripts in `.pw-scratch/` that construct the real class.
