# Sarvam TTS — 2026-10-28

Nothing is broken: `bulbul:v3` still synthesizes on both classes and is still the Text-to-Speech API's default. The one new thing worth a maintainer's attention is that Sarvam ends Bulbul V3's life on its own Voice Agents platform on 2026-11-10 and points new integrations at `bulbul:v4-flash` — which the TTS API exempts, so this is a positioning question rather than a deadline.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — `dict_id` is documented on both the REST body and the WebSocket config for v3 and v4-flash and the endpoint reads it, but it has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: a successful probe requires creating a dictionary through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **v4-flash pitch/loudness ranges** (medium, since 2026-10-12) — the API caps pitch at ±0.5 and loudness at 0.1–2.5 and answers anything outside with a 400 and no audio; `TTSModelConfig` clamps pace only, the `Settings` docstrings quote no range, and the deprecated `InputParams` still validates against bulbul:v2's wider bounds, so `pitch=0.7` passes Pipecat and fails Sarvam. Sarvam's REST reference now claims pitch and loudness are bulbul:v2-only, contradicting its own v4-flash guide; the live endpoint accepts both on v4-flash, so Pipecat's model config is correct and the reference page is the stale one. — *Needs a call: add `pitch_range`/`loudness_range` to `TTSModelConfig` and clamp as pace does, or only fix the docstrings and the stale `InputParams` bounds.*
- **Cloned voices** (medium, since 2026-10-12) — Sarvam's Voice Cloning API synthesizes through `/voices/clone*` rather than `/text-to-speech`, so neither class can reach it; the `sarvamai` SDK picked up the full one-shot/HTTP-stream/WebSocket set on 2026-10-12 and the saved-voice limit rose to 50 on the Starter plan. — *Needs a call: whether a saved `voice_id` doubles as a `speaker` on the standard endpoint (unverified, since checking it creates a voice on the account) and, if not, whether Pipecat wants a cloned-voice class.*
- **Bulbul V3's platform-side end of life** (medium, since 2026-10-28) — Sarvam retires V3 on Voice Agents on 2026-11-10 and calls v4-flash "recommended for new integrations", and v4-flash measures faster through `SarvamTTSService` (TTFB 550 ms vs 646 ms, medians of 5). The TTS API is exempt: v3 stays "stable" and remains the API default when `model` is omitted. — *Needs a call: whether Pipecat follows the voice-agent guidance to v4-flash. It is not a one-value bump — v4-flash offers no Malayalam or Odia voices and rejects v3's short speaker names, so `voice="shubh"` configs and `ml-IN`/`od-IN` users would break.*
- **Codec settings stranded on `InputParams`** (medium, since 2026-10-28) — `output_audio_codec` and `output_audio_bitrate` exist on `SarvamTTSService` only as deprecated `InputParams` fields, with no `SarvamTTSSettings` equivalent, and `InputParams` is slated for removal in 2.0.0. — *Needs a call: the WebSocket receive path turns the payload straight into `TTSAudioRawFrame` as PCM, so any codec other than `linear16` needs decoding first — decide whether the fields are carried into `Settings` or dropped with `InputParams`.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API rejects, and omits 14 of the 37 voices its error message and the docs enumerate. `voice` is a free string, so the enum gates nothing, but it also backs the public `get_speakers_for_model()`. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; Pipecat still carries it as an enum member and a model-config entry, and the endpoint still serves it. — *Needs a call: deprecate the pre-GA tag or leave it working.*
