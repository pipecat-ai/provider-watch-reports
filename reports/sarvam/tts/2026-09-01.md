# Sarvam TTS — 2026-09-01

No change since yesterday: `bulbul:v2` is still the shipped default and Sarvam still refuses it, so the fix is entirely in the hands of PR #5517.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5517 — Default Sarvam TTS to bulbul:v3 and send the REST sample rate under the field Sarvam reads (open since last run)

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — bulbul:v3's `dict_id` is documented on both the REST body and the WebSocket config but has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: probing it requires a dictionary created through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API no longer accepts, and omits 14 voices Sarvam now lists. `voice` is a free string, so the enum gates nothing; it is a discoverability surface only. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; the endpoint still synthesizes with it, and Pipecat still carries it as an enum member and a model-config entry. — *Needs a call: deprecate the pre-GA tag or leave it working.*
- **Beta-gated languages** (low, since 2026-08-31) — the API's own validation error lists 23 accepted codes; `language_to_sarvam_language` maps the 11 generally available ones. The other 12 answer "Please request beta access", and 5 have no `Language` member. — *Needs a call: whether to map codes that only work for accounts with beta access, and whether that justifies new `Language` members.*
