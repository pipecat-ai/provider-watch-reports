# Sarvam TTS — 2026-11-09

Nothing on the Text-to-Speech API moved since the last run, and nothing could be verified live: the Sarvam account is out of credits, so every probe failed with "Credits exhausted". Sarvam's Voice-Agents-only retirement of Bulbul V3 takes effect tomorrow, 2026-11-10, and the docs still exempt the TTS API that both Pipecat classes call.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — `dict_id` is documented on both the REST body and the WebSocket config for v3 and v4-flash and the endpoint read it when last probed, but it has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: a successful probe requires creating a dictionary through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **v4-flash pitch/loudness ranges** (medium, since 2026-10-12) — the API caps pitch at ±0.5 and loudness at 0.1–2.5 and answers anything outside with a 400 and no audio; `TTSModelConfig` clamps pace only, the `Settings` docstrings quote no range, and the deprecated `InputParams` still validates against bulbul:v2's wider bounds, so `pitch=0.7` passes Pipecat and fails Sarvam. Sarvam's REST and WebSocket references still claim pitch and loudness are bulbul:v2-only, contradicting its own v4-flash guide; the live endpoint accepted both on v4-flash on 2026-10-28, so Pipecat's model config is correct and the reference pages are the stale ones. — *Needs a call: add `pitch_range`/`loudness_range` to `TTSModelConfig` and clamp as pace does, or only fix the docstrings and the stale `InputParams` bounds.*
- **Cloned voices** (medium, since 2026-10-12) — Sarvam's Voice Cloning API synthesizes through `/voices/clone*` rather than `/text-to-speech`, so neither class can reach it, and Sarvam keeps extending it: `language_code` became optional on all three cloning entry points on 2026-10-26, and `remove_background_noise` was documented across create/clone/stream/WebSocket on 2026-11-06 (sarvamai >= 0.1.45 for those fields; our pin is 0.1.28). — *Needs a call: whether a saved `voice_id` doubles as a `speaker` on the standard endpoint (unverified, since checking it creates a voice on the account) and, if not, whether Pipecat wants a cloned-voice class.*
- **Bulbul V3's platform-side end of life** (medium, since 2026-10-28) — the Voice Agents retirement lands tomorrow, 2026-11-10, and Sarvam calls v4-flash "recommended for new integrations"; v4-flash measured faster through `SarvamTTSService` on 2026-10-28 (TTFB 550 ms vs 646 ms, medians of 5). The TTS API both Pipecat classes call is exempt — v3 is still "stable" and still the API default when `model` is omitted — so no Pipecat user is affected by the date. — *Needs a call: whether Pipecat follows the voice-agent guidance to v4-flash. It is not a one-value bump — v4-flash offers no Malayalam or Odia voices and rejects v3's short speaker names, so `voice="shubh"` configs and `ml-IN`/`od-IN` users would break.*
- **Codec settings stranded on `InputParams`** (medium, since 2026-10-28) — `output_audio_codec` and `output_audio_bitrate` exist on `SarvamTTSService` only as deprecated `InputParams` fields, with no `SarvamTTSSettings` equivalent, and `InputParams` is slated for removal in 2.0.0. — *Needs a call: the WebSocket receive path turns the payload straight into `TTSAudioRawFrame` as PCM, so any codec other than `linear16` needs decoding first — decide whether the fields are carried into `Settings` or dropped with `InputParams`.*
- **`temperature` on v4-flash** (low, since 2026-11-09) — Pipecat's model table marks v4-flash as not supporting `temperature`, so setting it logs a warning and clears the value. Sarvam's REST and WebSocket references both list temperature for "v3 and v4-flash"; only the v4-flash migration guide calls it "silently ignored", which is what Pipecat follows. — *Needs a call after a probe: with credits restored, synthesize v4-flash at temperature 0.01 and 1.0 to see whether the output differs, then either flip the flag or say in the docstring why it stays off.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API rejects, and omits 14 of the 37 voices its error message and the docs enumerate. `voice` is a free string, so the enum gates nothing, but it also backs the public `get_speakers_for_model()`. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; Pipecat still carries it as an enum member and a model-config entry, and the endpoint still served it on 2026-10-28. — *Needs a call: deprecate the pre-GA tag or leave it working.*
