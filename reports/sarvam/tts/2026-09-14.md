# Sarvam TTS — 2026-09-14

PR #5517 merged on 2026-09-03, so the retired default and the ignored REST sample-rate field are both fixed; what is left is one example line naming a bulbul:v2 speaker, and a branch fixes it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5759 — Name a bulbul:v3 speaker in the voice-sarvam example

### To consider
- **Pronunciation dictionaries** (medium, since 2026-08-31) — bulbul:v3's `dict_id` is documented on both the REST body and the WebSocket config and the endpoint reads it, but it has no `Settings` field; a field plus a pass-through in `run_tts` and `_send_config` would do it. — *Needs a call: a successful probe requires creating a dictionary through the Pronunciation Dictionary API, so exposing the field means deciding whether Pipecat stops at the parameter or also helps manage dictionaries.*
- **Stale v3 voice enum** (low, since 2026-08-31) — `SarvamTTSSpeakerV3` names `amelia` and `sophia`, which the API rejects, and omits 14 voices Sarvam now serves. `voice` is a free string, so the enum gates nothing, but it also backs the public `get_speakers_for_model()`. — *Needs a call: dropping two members from a public `StrEnum` may want a deprecation cycle.*
- **`bulbul:v3-beta` tag** (low, since 2026-08-31) — Sarvam promoted the beta tag to `bulbul:v3` in February 2026 and dropped it from the docs; Pipecat still carries it as an enum member and a model-config entry, and the endpoint still serves it. — *Needs a call: deprecate the pre-GA tag or leave it working.*
- **Beta-gated languages** (low, since 2026-08-31) — the API's own validation error lists 23 accepted codes; `language_to_sarvam_language` maps the 11 that Sarvam's model page advertises. — *Needs a call: whether to map codes the docs do not advertise, and whether that justifies new `Language` members.*

`probe.py run` cannot drive either class: `SarvamHttpTTSService` needs an `aiohttp_session` it cannot supply, and `SarvamTTSService` sets `pause_frame_processing=True`, so with no output transport no `BotStoppedSpeakingFrame` lifts the pause and the run never ends (re-confirmed this run, 120 s timeout). The rows above come from a script in `.pw-scratch/` that reuses `probe.py`'s own `_run_pipeline` harness with the real classes, plus raw calls for values the `Settings` cannot express.
