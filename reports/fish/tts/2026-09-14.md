# Fish TTS — 2026-09-14

`s2.1-pro` remains Fish's recommended production model and the default; nothing is retiring. The
new finding is Fish's word-timestamp WebSocket endpoint, which the service does not use.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5534 — Expose Fish Audio's chunking and loudness request settings (open since last run)

### To consider
- **Word timestamps** (medium, since 2026-09-14) — Fish documented `wss://api.fish.audio/v1/tts/live/with-timestamp` on 2026-09-11. It takes the same start request as the endpoint we already use, and its `audio` events carry a cumulative `alignment.segments` snapshot (`text`, `start`, `end`) per `chunk_seq` plus a `chunk_audio_offset_sec` to place segments on the session timeline; a trailing event with empty audio can carry a final correction. `TTSService.add_word_timestamps` is the hook on our side. — *Needs a call: whether word timestamps justify a second endpoint and the cumulative-alignment bookkeeping, or whether the service should just move to the timestamped endpoint.*
- **Multi-speaker and inline references** (medium, since 2026-09-01) — the start request takes `references` (inline zero-shot cloning, MessagePack only) and an array of model IDs in `reference_id` for multi-speaker dialogue with `<|speaker:N|>` tags in the text; the S2 family and `drama-3-preview` support it, `s1` does not. `Settings.voice` is a single string and nothing sends `references`. — *Needs a call: whether `voice` may hold a list, and where reference audio bytes belong in Settings.*
- **`drama-3-preview`** (low, since 2026-09-14) — Fish added it to the model header enum on 2026-09-10 for the HTTP and timestamped-WebSocket endpoints, but the plain `/v1/tts/live` enum the service connects to still omits it, and an unrecognized model silently falls back to `s2.1-pro`. — *Needs a call: whether to chase a model Fish labels preview, with behavior and availability subject to change.*
- **`latency` values** (low, since 2026-09-01) — the API reference enumerates `low`, `normal`, `balanced`, while the `Settings` docstring names only the last two. The field is a plain `str`, so `low` already reaches the API. — *Needs a call: whether to recommend `low` when Fish's real-time streaming guide only documents normal and balanced.*
- **Generation knobs** (low, since 2026-09-01) — `max_new_tokens`, `repetition_penalty` and `early_stop_threshold` are documented start-request fields alongside the exposed `temperature` and `top_p`. — *Needs a call: whether they earn Settings surface area for a voice pipeline.*
- **Output bitrates** (low, since 2026-09-01) — `mp3_bitrate` and `opus_bitrate` apply only to non-pcm output, and `output_format` is an init-only constructor argument. — *Needs a call: whether non-pcm output is a use case worth widening the audio-format arguments for.*
- **`features` flags** (low, since 2026-09-14) — the HTTP `TTSRequest` schema carries `features: string[]`, documented with `["quality-guard"]`; the WebSocket start-event schema does not list it, although the page states the start request takes the same parameters as HTTP. — *Needs a call: establish by probe whether the WebSocket honors `features` before adding a Settings field for it.*

## Verification

| s2.1-pro | FishAudioTTSService | ✅ | TTFB 217 ms | single sample; TTFA 222 ms (5 ms leading silence) |

No default bump is on the table, so no repeat run was needed. As in the previous run, `probe.py
run` never prints its JSON for this service: Fish's WebSocket API has no per-utterance completion
event (`finish` is session-level), so the audio context stays open until the idle sweep, and with
`pause_frame_processing=True` and no output transport in the probe pipeline no
`BotStoppedSpeakingFrame` lifts the pause, leaving `EndFrame` queued until the probe is killed. The
latency above is the service's own TTFB metric from the verbose log.
