# Fish TTS — 2026-09-01

`s2.1-pro` is Fish's recommended production model and already the default; the branch adds four
documented request fields to `Settings`.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5534 — Expose Fish Audio's chunking and loudness request settings

### To consider
- **Multi-speaker and inline references** (medium, since 2026-09-01) — the start request takes `references` (inline zero-shot cloning) and an array of model IDs in `reference_id` for multi-speaker dialogue on `s2-pro` and the S2.1-Pro family; `Settings.voice` is a single string and nothing sends `references`. — *Needs a call: whether `voice` may hold a list, and where reference audio bytes belong in Settings.*
- **`latency` values** (low, since 2026-09-01) — the API reference enumerates `low`, `normal`, `balanced`, while the `Settings` docstring names only the last two. The field is a plain `str`, so `low` already reaches the API. — *Needs a call: whether to recommend `low` when Fish's real-time streaming guide only documents normal and balanced.*
- **Generation knobs** (low, since 2026-09-01) — `max_new_tokens`, `repetition_penalty` and `early_stop_threshold` are documented request fields alongside the exposed `temperature` and `top_p`. — *Needs a call: whether they earn Settings surface area for a voice pipeline.*
- **Output bitrates** (low, since 2026-09-01) — `mp3_bitrate` and `opus_bitrate` apply only to non-pcm output, and `output_format` is an init-only constructor argument. — *Needs a call: whether non-pcm output is a use case worth widening the audio-format arguments for.*

## Verification

| model                                | class              | ok | latency      | note                                                                                                    |
| ------------------------------------ | ------------------ | -- | ------------ | ------------------------------------------------------------------------------------------------------- |
| s2.1-pro (default, unchanged code)   | FishAudioTTSService | ✅ | TTFB 156 ms  | single sample                                                                                             |
| s2.1-pro (branch, new fields set)    | FishAudioTTSService | ✅ | TTFB 149 ms  | `chunk_length=200`, `min_chunk_length=20`, `condition_on_previous_chunks=false`, `prosody_normalize_loudness=false` |
| s2.1-pro (branch, `chunk_length=99999`) | FishAudioTTSService | ❌ | TTFB 3006 ms | out-of-range value yields "TTS context completed with no audio" — confirms Fish reads the new fields rather than ignoring them |

`probe.py run` never prints its JSON for this service: Fish's WebSocket API has no per-utterance
completion event (`finish` is session-level and closes the connection), so the audio context stays
open until the idle sweep, and with `pause_frame_processing=True` and no output transport in the
probe pipeline no `BotStoppedSpeakingFrame` arrives to lift the pause, leaving `EndFrame` queued.
Latencies above are the service's own TTFB metrics from the probe's verbose log.
