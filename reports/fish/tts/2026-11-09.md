# Fish TTS — 2026-11-09

`s2.1-pro` is still Fish's recommended production model and probes healthy; one branch carries
the new `language` field and removes the retiring `s1` from the docstring.

## What's new since the last run

- Fish added an optional BCP-47 `language` field to TTS requests on 2026-10-16, explicitly
  including the WebSocket start event. `Settings.language` exists (inherited, and documented on
  our docs page) but was never put in the request — the branch fixes that.
- `drama-3` went GA on 2026-10-13 and is now in the `model` header enum for the plain
  `/v1/tts/live` the service connects to, closing last run's `drama-3-preview` gap; a probe
  reached it through `FishAudioTTSService`. What it exposes instead is an expression gap: Fish
  directs it in plain-language brackets and seven paired tags, and our adapter selection gives it
  none.
- The `s1` retirement (2026-12-31) now does touch Pipecat: the class docstring recommends `s1` as
  an alternative model.
- Normalization gained Turkish, Tagalog and `pt-BR` rules on 2026-10-20 — no API surface.
- The docs page has caught up with PR 5534, so last run's "docs page lags the code" gap is gone.
- The public spec now documents the `/v1/pronunciation-dictionaries` endpoints, so the reference
  form's IDs are obtainable; the choice of form is still open.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6661 — Send Fish Audio's language field from Settings and stop suggesting the retiring s1 model

### To consider
- **An expression adapter for drama-3** (medium, since 2026-11-09) — `get_expression_adapter()`
  keys on `model.startswith("s2")`, so `drama-3` performs nothing. Fish directs drama-3 with
  bracketed plain-language directions, bracketed sounds and pauses, and seven paired tags
  (`<whisper>`, `<emphasis>`, `<soft>`, `<fast>`, `<slow>`, `<stress>`, `<forceful>`) that wrap
  only the words they shape — close to free-text delivery plus emphasis, but not S2's syntax. —
  *Needs a call: whether drama-3 earns a second Fish adapter with its own example and manifest
  entry.*
- **Pronunciation dictionaries** (medium, since 2026-10-12) — `TTSRequest.pronunciation_dictionary`
  applies up to 3 dictionaries, as either `{id, version}` references or inline
  `{items: [{key, value, case_sensitive?}]}` literals. Last run's open question about where
  reference IDs come from is answered: the spec documents `/v1/pronunciation-dictionaries` with
  versions. — *Needs a call: the two forms are mutually exclusive in one request, so Settings has
  to pick a form or model both.*
- **Word timestamps** (medium, since 2026-09-14) — `wss://api.fish.audio/v1/tts/live/with-timestamp`
  takes the same start request and adds `content`, `alignment`, `chunk_seq` and
  `chunk_audio_offset_sec` to each `audio` event, with absolute word time
  `chunk_audio_offset_sec + segment.start`. `TTSService.add_word_timestamps` is the hook. —
  *Needs a call: whether this justifies a second endpoint and the cumulative-alignment
  bookkeeping, or whether the service should just move to the timestamped endpoint.*
- **Multi-speaker and inline references** (medium, since 2026-09-01) — the start request takes
  `references` and an array of model IDs in `reference_id` with `<|speaker:N|>` tags in the text;
  `Settings.voice` is a single string. — *Needs a call: whether `voice` may hold a list, and where
  reference audio bytes belong in Settings.*
- **`features` flags** (low, since 2026-09-14) — the schema half is settled, the behavior half is
  not: the endpoint accepts `["quality-guard"]`, invented flag names and invented top-level keys
  alike, and `quality-guard` has no documented effect. — *Needs a call: whether to expose a
  backend-dependent flag list whose typos fail silently.*
- **Generation knobs** (low, since 2026-09-01) — `max_new_tokens`, `repetition_penalty` and
  `early_stop_threshold` sit alongside the exposed `temperature` and `top_p`;
  `early_stop_threshold` is documented as a batch-processing control. — *Needs a call: whether
  they earn Settings surface area for a voice pipeline.*
- **`latency` values** (low, since 2026-09-01) — the spec enumerates `low`, `normal`, `balanced`;
  the `Settings` docstring names only the last two, and the field is a plain `str` so `low`
  already reaches the API. — *Needs a call: whether to recommend `low` when Fish's real-time
  streaming guide only documents normal and balanced.*
- **Output bitrates** (low, since 2026-09-01) — `mp3_bitrate` and `opus_bitrate` apply only to
  non-pcm output, and `output_format` is an init-only constructor argument. — *Needs a call:
  whether non-pcm output is a use case worth widening the audio-format arguments for.*
- **`prosody_normalize_loudness` scope** (low, since 2026-11-09) — the spec scopes
  `normalize_loudness` to the S2 family and says nothing about drama-3, which our docstring
  claims. — *Needs a call: drop the mention, or confirm drama-3 honors it.*

## Verification

| model                        | class               | ok | latency     | note                                                    |
| ---------------------------- | ------------------- | -- | ----------- | ------------------------------------------------------- |
| s2.1-pro                     | FishAudioTTSService | ✅ | TTFB 171 ms | single sample; no default bump on the table              |
| drama-3                      | FishAudioTTSService | ✅ | TTFB 170 ms | reached through the plain `/v1/tts/live`                 |
| s2.1-pro, `language=es-MX`   | FishAudioTTSService | ✅ | TTFB 211 ms | from the branch, worktree sources on `PYTHONPATH`        |

Unlike previous runs, `probe.py run` now completes and prints its JSON for this service.

Two caveats on what the probes do and do not show. The WebSocket reports no model back, and an
unrecognized `model` header silently falls back to `s2.1-pro`, so the drama-3 row proves the
session was accepted, with the model enum on the endpoint's reference page as the evidence that
`drama-3` is honored. And an ad-hoc differential (`.pw-scratch/adhoc/fish_language_probe.py`, two
sessions against `/v1/tts/live/with-timestamp` with `language=en` and `language=de` on
`"I paid 1,234.50 on 3/4/2026."`) returned identical alignment text both times — the alignment
carries input tokens, not the normalized spoken form, so it cannot show normalization changing.
The `language` change rests on Fish documenting the field for the WebSocket start event plus the
request being accepted.
