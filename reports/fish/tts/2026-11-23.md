# Fish TTS — 2026-11-23

Nothing to review; the service is current on models, but the WebSocket has an `error` event
Pipecat does not handle, and a request Fish refuses currently reaches the user as silence.

## What's new since the last run

- PR 6661 merged on 2026-11-09, so `Settings.language` now reaches the start request and the
  docstring no longer suggests the retiring `s1`. Both of last run's gaps are closed.
- The spec grew a `TTSLiveErrorEvent`: a request-level `error` event with an `error` string and an
  optional `max_concurrency`. It is documented only for `/v1/tts/live/with-timestamp`, but an
  ad-hoc probe shows the plain `/v1/tts/live` the service connects to sends it too — see below.
  `TTSLiveFinishEvent` also gained a `message` field for `reason: "error"`.
- `s3-pro` appeared in the `model` header enum of all three spec'd TTS endpoints, with no docs
  page, changelog entry or announcement behind it.
- Changelog since 2026-11-09: only Swedish and Malay text normalization (2026-11-13). No API
  surface; Malay wants `language: ms` set, which the service can now do.
- The models overview no longer puts an end date on `s2.1-pro-free` (last run recorded free
  through 2026-11-30); it is now "free under fair-use limits". `s2.1-pro` is still the recommended
  production model, `s1` still retires 2026-12-31.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The `error` event is dropped** (high, since 2026-11-23) — a start request Fish refuses answers
  `{event: "error", error: "..."}`, confirmed against the plain `/v1/tts/live` with an unknown
  `reference_id` ("Reference not found"); the same event reports a concurrency refusal with
  `max_concurrency`. `_receive_messages` matches only `audio` and `finish`, so nothing is pushed
  upstream, no audio ever arrives, and once the socket closes `_receive_task_handler` reconnects
  with the same settings until retries are exhausted — the user sees silence, never the reason.
  The adjacent half is `finish`'s new `message` field, which the service replaces with a fixed
  "Fish Audio server error during synthesis". — *Needs a call: whether to surface the event with
  `push_error` and how — fatal or not, and whether reconnecting is right after a request the
  server has already refused.*
- **An expression adapter for drama-3** (medium, since 2026-11-09) — `get_expression_adapter()`
  keys on `model.startswith("s2")`, so `drama-3` performs nothing. Fish directs drama-3 with
  bracketed plain-language directions, bracketed sounds and pauses, and seven paired tags
  (`<whisper>`, `<emphasis>`, `<soft>`, `<fast>`, `<slow>`, `<stress>`, `<forceful>`) that wrap
  only the words they shape. — *Needs a call: whether drama-3 earns a second Fish adapter with its
  own example and manifest entry.*
- **Pronunciation dictionaries** (medium, since 2026-10-12) — `TTSRequest.pronunciation_dictionary`
  applies up to 3 dictionaries, as either `{id, version}` references or inline
  `{items: [{key, value, case_sensitive?}]}` literals, with `/v1/pronunciation-dictionaries` and
  its version endpoints minting the reference IDs. — *Needs a call: the two forms are mutually
  exclusive in one request, so Settings has to pick a form or model both.*
- **Word timestamps** (medium, since 2026-09-14) — `wss://api.fish.audio/v1/tts/live/with-timestamp`
  takes the same start request and adds `content`, `alignment`, `chunk_seq` and
  `chunk_audio_offset_sec` to each `audio` event, with absolute word time
  `chunk_audio_offset_sec + segment.start`. `TTSService.add_word_timestamps` is the hook. —
  *Needs a call: whether this justifies a second endpoint and the cumulative-alignment
  bookkeeping, or whether the service should just move to the timestamped endpoint.*
- **Multi-speaker and inline references** (medium, since 2026-09-01) — the start request takes
  `references` and an array of model IDs in `reference_id` with `<|speaker:N|>` tags in the text;
  `Settings.voice` is a single string. — *Needs a call: whether `voice` may hold a list, and where
  reference audio bytes belong in Settings.*
- **Undocumented `s3-pro`** (low, since 2026-11-23) — it is in the `model` enum of `POST /v1/tts`,
  `POST /v1/tts/stream/with-timestamp` and `/v1/tts/live/with-timestamp`, and nowhere else: no
  model page, no changelog entry, no announcement. `Settings.model` is a free string so it is
  already passable, and an unrecognized model falls back to `s2.1-pro` without a word, so a probe
  cannot prove it is served. — *Needs a call: nothing yet; re-check each run and weigh it as a
  default only once Fish documents it.*
- **`features` flags** (low, since 2026-09-14) — the schema half is settled, the behavior half is
  not: the endpoint accepts `["quality-guard"]`, invented flag names and invented top-level keys
  alike, and `quality-guard` has no documented effect. — *Needs a call: whether to expose a
  backend-dependent flag list whose typos fail silently.*
- **Generation knobs** (low, since 2026-09-01) — `max_new_tokens`, `repetition_penalty` and
  `early_stop_threshold` sit alongside the exposed `temperature` and `top_p`;
  `early_stop_threshold` is documented as a batch-processing control. — *Needs a call: whether
  they earn Settings surface area for a voice pipeline.*
- **`latency` values** (low, since 2026-09-01) — the spec enumerates `low`, `normal`, `balanced`;
  the `Settings` docstring names only the last two, and the field is a plain `str` so `low`
  already reaches the API. — *Needs a call: whether to recommend `low` when Fish's real-time
  streaming guide only documents normal and balanced.*
- **Output bitrates** (low, since 2026-09-01) — `mp3_bitrate` and `opus_bitrate` apply only to
  non-pcm output, and `output_format` is an init-only constructor argument. — *Needs a call:
  whether non-pcm output is a use case worth widening the audio-format arguments for.*
- **`prosody_normalize_loudness` scope** (low, since 2026-11-09) — the spec scopes
  `normalize_loudness` to the S2 family and says nothing about drama-3, which our docstring and
  the Pipecat docs page claim. — *Needs a call: drop the mention, or confirm drama-3 honors it.*

## Verification

| model    | class               | ok | latency     | note                                        |
| -------- | ------------------- | -- | ----------- | ------------------------------------------- |
| s2.1-pro | FishAudioTTSService | ✅ | TTFB 276 ms | single sample; no default bump on the table |
| drama-3  | FishAudioTTSService | ✅ | TTFB 243 ms | reached through the plain `/v1/tts/live`    |

The WebSocket reports no model back and an unrecognized `model` header silently falls back to
`s2.1-pro`, so the drama-3 row proves only that the session was accepted; the endpoint's model
enum is the evidence that `drama-3` is honored. The same caveat is why `s3-pro` was not probed.

Ad-hoc probe `.pw-scratch/adhoc/fish_error_event_probe.py` — one session against each of
`/v1/tts/live` and `/v1/tts/live/with-timestamp` with `reference_id` set to a voice ID that does
not exist. Both answered `{"event": "error", "error": "Reference not found"}` and then sent
nothing further, so the event the spec documents for the timestamped endpoint is sent by the plain
one the service uses.
