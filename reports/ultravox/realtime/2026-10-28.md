# Ultravox Realtime — 2026-10-28

Nothing actionable: Inworld's acquisition of Ultravox (announced 2026-09-30) left the call-creation schema, the WebSocket protocol and the deprecation list untouched, the service connects and answers on both the server default and `ultravox-v0.7`, and the five open gaps are unchanged.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Tool-result options** (medium, since 2026-09-01) — `client_tool_result` accepts `agentReaction` (`speaks` | `listens` | `speaks-once`) and `responseType` (hang-up, new-stage), as well as `errorType`/`errorMessage` and `updateCallState`; `_send_tool_result` sends only `invocationId` and `result`, so a handler cannot make the agent listen after a tool, end the call, or move to another call stage. — *Needs a call: how a function handler would carry these — a result-string convention, a new frame, or a service-level default.*
- **Text-injection urgency** (medium, since 2026-09-01) — `_send_user_text` can pass `urgency`, but only the async-tool progress path does (`soon`/`later`); `InputTextRawFrame` text and async-tool final results take Ultravox's documented default of `soon`, so injected text can never interrupt (`immediate`) and an application has no way to choose. `threadId` is omitted everywhere. — *Needs a call: urgency is per-message, so it needs a stance — a Settings default for all injected text, or a per-frame field.*
- **Unimplemented protocol messages** (low, since 2026-09-01) — `forced_agent_message`, `hang_up` and `spawn_thread` are never sent; `call_started` (with `callId`), `pong` and the thread messages only reach the debug log. — *Needs a call: which of these Pipecat should model at all; threads and forced messages have no frame-level equivalent today.*
- **Inert `Settings.model`** (low, since 2026-09-01) — the model is fixed by `OneShotInputParams`, so a model passed in `settings` at construction is dropped silently (runtime updates do warn); docs.pipecat.ai still lists `model` in the Settings table. — *Needs a call: whether to warn or reject an inert `Settings.model`; the docs page lives in the docs repo, outside this branch.*
- **No tier-2 probe** (low, since 2026-09-01) — the constructor takes a required `params` object rather than `api_key`/`model`, so `probe.py run` fails in `build_kwargs` and each run needs an ad-hoc connect script. — *Needs a call: this is a probe.py change (params-object support), not a service change.*

The acquisition is not a gap. Inworld's announcement upgrades Ultravox's built-in voices to Realtime TTS-2 with existing voice IDs intact and no code change required; TTS-2's pace/tone/emotion steering is inline natural-language instruction inside the agent's own text, not a request parameter, so there is nothing for `Settings` or the call body to expose.

The catalogue lost `ultravox-v0.6-gemma3-27b` since the last run — three models now, and the deprecation page never listed it. Nothing in Pipecat references it, and `ultravox-v0.7`, the one model string in the service (an `OneShotInputParams.model` docstring example), is still served. The service and all four Ultravox examples leave `model` unset and take Ultravox's server default, which the API reference still documents as `ultravox-v0.7`.

Call-creation parameters remain not-gaps: `AgentInputParams.extra` and `OneShotInputParams.extra` merge straight into the call-creation body, covering everything the API reference lists beyond our named fields (`vadSettings`, `backgroundAudio`, `dataConnection`, `retentionPolicy`, `admissionPreference`, `externalVoice`, …). Deprecated call fields are `firstSpeaker` (prefer `firstSpeakerSettings`), `transcriptOptional`, and the Cartesia voice-override `speed`/`emotion`/`emotions`; none appears in Pipecat. The `data_connection_tool_invocation` / `data_connection_tool_result` message pair is also unhandled, but it only arrives on calls configured with `dataConnection`, which this service never sets.

## Verification

Connect checks ran through the real class via an ad-hoc script in `scratch_dir` (`probe.py run` cannot build this constructor); each opened one one-shot call in text medium, took the agent's opening turn plus one injected text turn, and ended the call. Latency is not meaningful here — the class reports TTFB only off VAD-driven turns, which a text-only check never produces, and the agent's greeting arrives before the injected turn.
