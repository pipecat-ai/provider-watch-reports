# Ultravox Realtime — 2026-11-09

Nothing actionable: the service connects and answers on both the server default and `ultravox-v0.7`, Ultravox's one new deprecation cannot affect Pipecat, and the single new gap (query parameters unreachable through `extra`) has a documented workaround.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Tool-result options** (medium, since 2026-09-01) — `client_tool_result` accepts `agentReaction` (`speaks` | `listens` | `speaks-once`) and `responseType` (hang-up, new-stage), as well as `errorType`/`errorMessage` and `updateCallState`; `_send_tool_result` sends only `invocationId` and `result`, so a handler cannot make the agent listen after a tool, end the call, or move to another call stage. — *Needs a call: how a function handler would carry these — a result-string convention, a new frame, or a service-level default.*
- **Text-injection urgency** (medium, since 2026-09-01) — `_send_user_text` can pass `urgency`, but only the async-tool progress path does (`soon`/`later`); `InputTextRawFrame` text and async-tool final results take Ultravox's documented default of `soon`, so injected text can never interrupt (`immediate`) and an application has no way to choose. `threadId` is omitted everywhere. — *Needs a call: urgency is per-message, so it needs a stance — a Settings default for all injected text, or a per-frame field.*
- **Unimplemented protocol messages** (low, since 2026-09-01) — `forced_agent_message`, `hang_up` and `spawn_thread` are never sent; `call_started` (with `callId` and `mediumRestriction`), `pong` and the thread messages only reach the debug log. — *Needs a call: which of these Pipecat should model at all; threads and forced messages have no frame-level equivalent today.*
- **Query parameters unreachable** (low, since 2026-11-09) — `priorCallId`, `enableGreetingPrompt` and `throttle` are query parameters on the call-creation endpoints, not body fields, so `extra` — which merges into the JSON body — cannot express them: a user cannot continue a prior call's history, suppress the greeting prompt, or apply a throttle. Creating the call outside Pipecat and passing the join URL via `JoinUrlInputParams` covers all three. — *Needs a call: whether params should grow a query-parameter escape hatch (e.g. `extra_query`), or the `JoinUrlInputParams` workaround is the intended answer.*
- **Inert `Settings.model`** (low, since 2026-09-01) — the model is fixed by `OneShotInputParams`, so a model passed in `settings` at construction is dropped silently; runtime updates do warn, and docs.pipecat.ai now documents the field as "Not used". — *Needs a call: whether to warn or reject an inert `Settings.model`.*
- **No tier-2 probe** (low, since 2026-09-01) — the constructor takes a required `params` object rather than `api_key`/`model`, so `probe.py run` fails in `build_kwargs` and each run needs an ad-hoc connect script. — *Needs a call: this is a probe.py change (params-object support), not a service change.*

Ultravox's new deprecation, `priorCallId` inheriting call fields (deprecated 2026-11-03, removal 2026-12-07), is not a gap: after that date a call created with `?priorCallId=` stops inheriting `model`, `systemPrompt`, `voice`, `selectedTools`, `joinTimeout`, `maxDuration` and `recordingEnabled` from the prior call. Pipecat never sends the parameter — it posts to a bare endpoint URL — so every call it creates already sets its own fields. Only an application that creates calls itself and hands Pipecat a `JoinUrlInputParams` is exposed, and the fix lives in that application's own request.

Unchanged since the last run: the catalogue (the same three models), the WebSocket protocol, the call-creation body, and the model string. `ultravox-v0.7` — the one model name in Pipecat, an `OneShotInputParams.model` docstring example — is still served, and the API reference still documents it as the server default that the service and all three Ultravox examples take by leaving `model` unset. Body-level call parameters remain not-gaps: `extra` on both params classes merges into the request body, covering `vadSettings`, `firstSpeakerSettings`, `triggers`, `additionalModels`, `mediumRestriction`, `backgroundAudio`, `dataConnection`, `retentionPolicy`, `admissionPreference` and `externalVoice`. Deprecated body fields are `firstSpeaker`, `transcriptOptional` and the Cartesia voice-override `speed`/`emotion`/`emotions`; none appears in Pipecat.

## Verification

Connect checks ran through the real class via an ad-hoc script in `scratch_dir` (`probe.py run` cannot build this constructor); each opened one one-shot call in text medium, took the agent's opening turn plus one injected text turn, and ended the call. Latency is not meaningful here — the class reports TTFB only off VAD-driven turns, which a text-only check never produces, and the agent's greeting arrives before the injected turn.
