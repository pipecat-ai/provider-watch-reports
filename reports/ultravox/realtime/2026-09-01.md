# Ultravox Realtime — 2026-09-01

Nothing is broken or retiring: Ultravox's default (`ultravox-v0.7`, GLM 4.6) is what our unset `model` already gets, and the only retired string (`fixie-ai/ultravox-qwen3-32b-preview`) appears nowhere in Pipecat. One docstring fix is branched; the open items are WebSocket protocol options we don't expose.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5582 — Document the Ultravox one-shot model default accurately

### To consider
- **Tool-result options** (medium, since 2026-09-01) — `client_tool_result` accepts `agentReaction` (`speaks` | `listens` | `speaks-once`) and `responseType` (hang-up, new-stage); `_send_tool_result` sends only `invocationId` and `result`, so a handler cannot make the agent listen after a tool, end the call, or move to another call stage. — *Needs a call: how a function handler would carry these — a result-string convention, a new frame, or a service-level default.*
- **Text-injection urgency** (medium, since 2026-09-01) — `_send_user_text` omits `urgency`, so `InputTextRawFrame` text and async-tool final results always use `soon` and can never interrupt (`immediate`) or defer (`later`). — *Needs a call: urgency is per-message, so it needs a stance — a Settings default for all injected text, or a per-frame field.*
- **Unimplemented protocol messages** (low, since 2026-09-01) — `forced_agent_message`, `hang_up` and `spawn_thread` are never sent; `call_started` (with `callId`), `pong` and the thread messages are only debug-logged, so a session cannot be correlated with Ultravox call history or recordings. — *Needs a call: which of these Pipecat should model at all; threads and forced messages have no frame-level equivalent today.*
- **Inert `Settings.model`** (low, since 2026-09-01) — the model is fixed by `OneShotInputParams`, so a model passed in `settings` at construction is ignored silently (runtime updates do warn); docs.pipecat.ai still lists `model` in the Settings table and uses `fixie-ai/ultravox` in its one-shot example. — *Needs a call: whether to warn or reject an inert `Settings.model`; the docs page lives in the docs repo, outside this branch.*
- **No tier-2 probe** (low, since 2026-09-01) — the constructor takes a required `params` object rather than `api_key`/`model`, so `probe.py run` fails in `build_kwargs` and each run needs an ad-hoc connect script. — *Needs a call: this is a probe.py change (params-object support), not a service change.*

Call-creation parameters (`languageHint`, `vadSettings`, `firstSpeakerSettings`, `recordingEnabled`, `initialMessages`, `inactivityMessages`, `dataConnection`, `callbacks`, `experimentalSettings`, …) are not gaps: `AgentInputParams.extra` and `OneShotInputParams.extra` merge straight into the call-creation body.
