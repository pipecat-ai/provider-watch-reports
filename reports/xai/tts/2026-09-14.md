# xAI TTS — 2026-09-14

Both classes are current: no new voices, no model parameter, no deprecations since the last run, and the only substantive gap is already on open PR 5562.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5562 — Add a replace setting to XAIHttpTTSService (open since last run)

### To consider
- **HTTP language pass-through** (low, since 2026-09-01) — `XAIHttpTTSService.run_tts` sends `str(self._settings.language)` while `XAITTSService` maps through `language_to_xai_language`, so a region variant outside xAI's list (`en-US`, `fr-CA`) reaches the API verbatim from one class and as the base code from the other. `en-US` was accepted in a probe last run, so nothing fails today. — *Needs a call: is the verbatim pass-through deliberate, or should the HTTP class use the same map?*
- **`optimize_streaming_latency` range** (low, since 2026-09-01) — both Settings docstrings say 0, 1 or 2; xAI's REST reference documents only 0 and 1 (typed as strings), while the capability page describes all three levels. Integer 1 and 2 were both accepted. — *Needs a call: which xAI page is authoritative before we narrow the documented range.*

No provider-side change this run. The voice roster is unchanged at 26 built-in voices (5 original plus the 21 flagship voices from 2026-07-06) plus cloned voices from `GET /v1/custom-voices`, and neither class gates `voice`. There is still no model parameter on either endpoint. The REST reference's language list (`auto` plus 20 codes) is fully covered by `language_to_xai_language`. `speed`, `text_normalization`, `with_timestamps`, codecs and sample rates are all exposed; `replace` is documented for the HTTP endpoint only and is on the open PR; `bit_rate` applies only to MP3, which these classes do not emit as raw frames. Speech tags are inline in `text`, so they need no Settings field.
