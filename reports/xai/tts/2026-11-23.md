# xAI TTS — 2026-11-23

PR 5562 merged on 2026-11-09, which settles the question the last report raised: the WebSocket `replace` map lands on its own, and a branch does it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6981 — Add a replace setting to XAITTSService

### To consider
- **HTTP language pass-through** (low, since 2026-09-01) — `XAIHttpTTSService.run_tts` sends `str(self._settings.language)` while `XAITTSService` maps through `language_to_xai_language`, so a region variant outside xAI's list (`en-US`, `fr-CA`) reaches the API verbatim from one class and as the base code from the other. `en-US` was accepted in an earlier probe, so nothing fails today. — *Needs a call: is the verbatim pass-through deliberate, or should the HTTP class use the same map?*

The previous report's `optimize_streaming_latency` range item is dropped: the TTS capability page now documents the parameter as an integer with values `0`, `1` and `2` for `POST /v1/tts` as well as for the WebSocket, so both Settings docstrings are right and only xAI's REST reference page still shows the narrower `"0"`/`"1"` strings — nothing for Pipecat to change.

Nothing else moved. `GET /v1/tts/voices` returns the same 28 built-in voices as on 2026-11-09, neither class gates `voice`, and custom voices work on both endpoints. There is still no model parameter on either TTS endpoint; the voice model slugs (`grok-voice-3.0`, `grok-voice-latest`) belong to the Speech-to-Speech realtime API, and November's release notes cover only `grok-build-0.1` end of life and the `grok-imagine-image-quality` retirement. The language list (`auto` plus 20 codes) is still fully covered by `language_to_xai_language`. `speed`, `optimize_streaming_latency`, `text_normalization`, `with_timestamps`, codecs and sample rates are all exposed; `bit_rate` is MP3-only and these classes emit raw frames. Speech tags stay inline in `text` and need no Settings field.
