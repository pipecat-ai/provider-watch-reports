# xAI TTS — 2026-09-01

Nothing is retired or renamed; both classes work as shipped, and the one real gap — xAI's `replace` pronunciation map on the HTTP endpoint — is on a branch.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5562 — Add a replace setting to XAIHttpTTSService

### To consider
- **HTTP language pass-through** (low, since 2026-09-01) — `XAIHttpTTSService.run_tts` sends `str(self._settings.language)` while `XAITTSService` maps through `language_to_xai_language`, so a region variant outside xAI's list (`en-US`, `fr-CA`) reaches the API verbatim from one class and as the base code from the other. `en-US` was accepted in a probe, so nothing fails today. — *Needs a call: is the verbatim pass-through deliberate, or should the HTTP class use the same map?*
- **`optimize_streaming_latency` range** (low, since 2026-09-01) — both Settings docstrings say 0, 1 or 2; xAI's REST reference documents only 0 and 1 (the capability page still says 0-2). A probe with 2 was accepted. — *Needs a call: which xAI page is authoritative before we narrow the documented range.*

Everything else the API offers is already reachable: xAI's roster is now 26 built-in voices plus cloned voices from `GET /v1/custom-voices`, and since neither class gates `voice`, all of them pass straight through (`carina` probed fine). There is no model parameter on either endpoint. `speed`, `text_normalization`, `with_timestamps`, codecs and sample rates are all exposed; `bit_rate` applies only to MP3, which these classes do not emit as raw frames.

## Sources
- https://docs.x.ai/developers/rest-api-reference/inference/voice — request schema for `POST /v1/tts` and `wss://api.x.ai/v1/tts`: `replace` is documented for the HTTP endpoint only; `optimize_streaming_latency` listed as 0 or 1; 26 built-in voices; codecs mp3/wav/pcm/mulaw/alaw
- https://docs.x.ai/developers/model-capabilities/audio/text-to-speech — no model parameter; speed 0.7-1.5; inline speech tags; HTTP returns raw audio bytes unless `with_timestamps` is set
- https://docs.x.ai/developers/model-capabilities/audio/custom-voices — cloned voices are ordinary `voice_id` strings, listed by `GET /v1/custom-voices`
- https://docs.x.ai/developers/release-notes — 2026 voice entries are all Speech-to-Speech (`grok-voice-think-fast-2.0`, `grok-voice-latest` routing from 2026-08-05); no TTS deprecations
- https://docs.pipecat.ai/api-reference/server/services/tts/xai — matches the code: two classes, voice `eve`, speed/latency/normalization settings, `with_timestamps` on the WebSocket class
- probe.py list-models --provider xai — catalogue is LLM and image models only; no TTS entry
- probe.py sdk-versions --provider xai — openai 3.6.0 on PyPI (2026-08-28) is outside our `openai>=1.74.0,<3` pin, but that SDK backs only the xAI LLM classes; these TTS classes use aiohttp/websockets directly
- `GET https://api.x.ai/v1/custom-voices` — returns an empty list for this account; `GET /v1/voices` is 404, so the built-in roster comes from the docs
