# xAI Realtime — 2026-09-14

Nothing to do this run: `grok-voice-latest` is still xAI's recommended alias, the 22050 Hz fix merged as #5560, and the three open items are unchanged.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Binary audio transport** (medium, since 2026-09-01) — `AudioInput.transport` / `AudioOutput.transport` expose xAI's `"binary"` wire path, but the receive loop parses every message as JSON and `_send_user_audio` always base64-encodes into `input_audio_buffer.append`. Since assistant audio is emitted only on the configured `output.transport`, a user who sets `"binary"` gets warnings and no audio. — *Needs a call: implement binary framing, or drop `transport` from the settings so the field cannot be set to a value the service does not honor.*
- **SIP `call_id`** (medium, since 2026-09-01) — `_connect` always builds `?model=<model>`; joining an inbound SIP call requires `?call_id=<id>` (where `model` is ignored). The service already handles `input_audio_buffer.dtmf_event_received`, which xAI emits on SIP sessions only, so that path is unreachable today. — *Needs a call: `call_id` is per-call rather than per-service, so it needs a constructor or settings shape rather than a pass-through field.*
- **`audio/opus` codec** (low, since 2026-09-01) — xAI accepts `audio/opus` (24 kHz mono, one raw Opus packet per JSON delta or binary frame) for both directions; `events.py` models PCM, PCMU and PCMA only. — *Needs a call: Opus packets must be decoded before becoming `TTSAudioRawFrame`, so a new format class alone would not make it work.*

The previous run's sample-rate gap is closed: #5560 merged 2026-09-02 and `events.py` now lists `22050` in `SUPPORTED_SAMPLE_RATES`. Everything else in xAI's documented `session.update` schema — `instructions`, `voice`, `reasoning.effort`, all four `turn_detection` fields, `resumption.enabled`, `replace`, `audio.output.speed`, `audio.input.transcription.language_hint` / `keyterms`, per-response `instructions`, `force_message` items and all five tool types — is reachable from `SessionProperties`, and every server event xAI documents (including the MCP set) is in `_server_event_types`.
