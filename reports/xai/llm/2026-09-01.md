# xAI LLM — 2026-09-01

`grok-4.20-non-reasoning` is current and healthy as the default; the actionable gap is that
Grok's reasoning-effort knob — the difference between a 0.4 s and a 6 s first token — is only
reachable through `extra`.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5559 — Expose Grok's reasoning effort control

### To consider
- **openai SDK pin** (medium, since 2026-09-01) — `pyproject.toml` pins `openai>=1.74.0,<3` while openai 3.6.0 shipped 2026-08-28, so `GrokLLMService`'s client stays on the 2.x line. — *Needs a call: the cap is shared by every OpenAI-compatible service, so moving it is an openai-wide SDK migration rather than an xai decision.*
- **grok-4.6 as the default** (low, since 2026-09-01) — grok-4.6 is xAI's flagship (GA 2026-08-12) but reasons at `high` unless told otherwise and refuses `reasoning_effort=none`, measuring 2846 ms median TTFAT against 432 ms for the current default, and 6302 ms against 462 ms on a planning prompt; `low` effort only gets it to 1823 ms. xAI's own migration guidance still routes fast non-reasoning workloads to grok-4.20-non-reasoning. — *Needs a call: aiewf-eval's medium-context leaderboard carries no Grok row at all, so neither model has a benchmarked pass rate; the leaderboard gets re-read next run.*
