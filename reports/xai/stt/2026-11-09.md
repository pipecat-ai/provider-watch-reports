# xAI STT — 2026-11-09

`XAISTTService` fails end to end on the standard probe: every audio frame that arrives before xAI's `transcript.created` is thrown away, and with a burst-fed source that is all of them. Nothing on xAI's side regressed.

## What's new for Pipecat

### PRs
Nothing. No item can clear the probe bar until the pre-ready audio drop is fixed, so no branch this run. PR #5561 (last run's open PR) merged on 2026-11-07 and closed both of last run's `pr` items: `keyterm`, `filler_words`, `vad_threshold`, `smart_turn` and `smart_turn_timeout` are now Settings fields, and the endpointing/opus docstrings are correct.

### To consider
- **Pre-ready audio is discarded** (high, since 2026-11-09) — `run_stt` sends audio only while `_session_ready` is set, and drops it silently otherwise. The window is the ~250ms between the WebSocket handshake and `transcript.created`, and it reopens on every automatic reconnect. `probe.py run --service XAISTTService` now fails with "no TranscriptionFrame within 45s" and no `InterimTranscriptionFrame` at all; a raw socket fed the identical clip, paced or bursted *after* `transcript.created`, returns the correct `speech_final` transcript, and the same raw client reproduces the failure exactly when it drops pre-ready chunks the way `run_stt` does. Real-time transports are mostly unaffected at startup (setup connects long before speech), but any source that delivers audio faster than real time loses it, and a mid-call reconnect loses a quarter second of live speech. — *Needs a call: buffer the pre-ready audio and flush it on `transcript.created`, or hold the service's start until the session is ready. Either is a startup behavior change, not a value swap.*
- **`format` (inverse text normalization) is not exposed** (medium, since 2026-11-09) — xAI documents `format` as a boolean query parameter of the streaming endpoint; `XAISTTSettings` has no field for it and `_build_ws_url` never sends it. A live session with `format=true` connects and transcribes. The change is one optional field plus one entry in `optional_fields`, and the `language_to_xai_stt_language` docstring needs its stale "when set, the server applies Inverse Text Normalization" line corrected in the same edit. — *Needs a call: `probe.py run` cannot pass against this class at all while pre-ready audio is dropped, so a new Settings field cannot be verified the way a PR requires; this follows the drop fix.*
- **`finalize` is never sent** (medium, since 2026-09-01) — xAI accepts `{"type": "finalize"}` on the socket to finalize the current utterance immediately, confirmed live this run; `XAISTTService` only sends `audio.done` at disconnect, so every end-of-turn final waits out the `endpointing` silence timer. — *Needs a call: what triggers it. Wiring it to the user turn-stop path is a behavior change that interacts with the turn strategies and with server-side `smart_turn`.*
- **Language map lags the docs** (low, since 2026-09-01) — `language_to_xai_stt_language` verifies 16 codes against the 38 base codes and 7 regional variants xAI now publishes; the rest fall through to the base-code path and log a "not verified" warning each session. Last run's question is settled: `zh` is now in xAI's list and the live socket accepts `language=bn`, so both entries stay. — *Needs a call: whether the regional codes map through as-is, since `Language.ES_ES` sends `es` today and would start sending `es-ES`; plus the same probe blocker as `format`.*

`grok-voice-transcribe-2.0` is xAI's only STT model and its server-side default, which is what the service sends — no bump to make. `grok-voice-transcribe-1.0` reached end of life on 2026-10-02 and is referenced nowhere in the shipped code; only `tests/test_xai_stt.py` still uses the retired name as its "model override" example. The examples pass no model or version string.
