# xAI STT — 2026-09-14

Nothing changed on either side: xAI shipped no STT updates since 2026-09-01, `XAISTTService` is untouched, and PR #5561 still carries the parameter and docstring fixes.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5561 — Expose xAI STT's remaining streaming parameters and correct its documented defaults (open since last run)

### To consider
- **`finalize` is never sent** (medium, since 2026-09-01) — xAI accepts `{"type": "finalize"}` on the socket to finalize the current utterance immediately; `XAISTTService` only sends `audio.done` at disconnect, so every end-of-turn final waits out the `endpointing` silence timer. — *Needs a call: what triggers it. Wiring it to the user turn-stop path is a behavior change that interacts with the turn strategies and with server-side `smart_turn`.*
- **Language map lags the docs** (low, since 2026-09-01) — `language_to_xai_stt_language` verifies 16 codes against the 25 xAI documents; cs, da, fa, fil, mk, ms, nl, pl, ro, sv and th fall through to the base-code path and log a "not verified" warning each session. — *Needs a call: the map also carries BN and ZH, which xAI's language list still does not name, so it is unclear whether they should be dropped or the published list is simply incomplete.*

Once #5561 merges, the streaming query schema is fully covered: every documented parameter (`sample_rate`, `encoding`, `interim_results`, `endpointing`, `language`, `multichannel`, `channels`, `diarize`, `keyterm`, `filler_words`, `smart_turn`, `smart_turn_timeout`, `vad_threshold`) is reachable. `format` is batch-only and does not apply to the WebSocket endpoint. The examples pass no model or version string, so nothing there can go stale.
