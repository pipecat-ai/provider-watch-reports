# Perplexity LLM — 2026-09-14

The Sonar chat-completions endpoint retires on 2026-09-27, 13 days out; `PerplexityLLMService` calls nothing else, and the migration needs a maintainer decision this week.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Sonar chat completions retires 2026-09-27** (high, since 2026-09-01) — the date is unchanged and now restated directly by Perplexity staff in the forum on 2026-09-10: "The Sonar chat completions endpoint will retire on September 27. You will need to migrate to the Agent API responses endpoint before then." The docs banner on the models page still reads "Sonar Chat Completions is now Agent API. Sonar will be supported until September 27, 2026." `PerplexityLLMService` posts to `https://api.perplexity.ai` + `/chat/completions`, which still works today, so the break is a cliff rather than a degradation. The Agent API deliberately offers no chat-completions shim — the OpenAI-compatibility page documents only `POST /v1/agent` and its `/v1/responses` alias — so nothing mechanical (a base-URL change, a model rename) carries the class across. The escape hatch users have today is `OpenAIResponsesHttpLLMService` with `base_url=https://api.perplexity.ai/v1` and a Perplexity key, which streams `perplexity/sonar` fine. Users on `sonar-pro` have no slug to move to: the Agent API rejects `perplexity/sonar-pro` with HTTP 400, and Perplexity's migration notes map it to either the `low` preset or `perplexity/sonar` plus a `web_search` tool. — *Needs a call: reparenting the class onto the Responses/Agent surface changes the base class, the Settings shape (`messages`→`input`/`instructions`, `max_tokens`→`max_output_tokens`, unknown fields rejected with 400) and the model slugs, and probably retires `PerplexityLLMAdapter`'s message transforms; `examples/function-calling/function-calling-perplexity.py` and the "doesn't support tools" docstring change too, since the Agent API has tools. Deciding after 2026-09-27 means shipping a broken service.*
- **Search and reasoning controls unexposed** (low, since 2026-09-01) — the legacy endpoint accepts `search_mode`, `disable_search`, `search_domain_filter`, `search_language_filter`, `search_recency_filter`, `search_after_date_filter`, `web_search_options`, `return_images`, `return_related_questions` and `reasoning_effort`; `build_chat_completion_params` forwards only `frequency_penalty`, `presence_penalty`, `temperature`, `top_p` and `max_tokens`, so grounding is un-tunable. — *Needs a call: adding fields to an endpoint with under two weeks left is work thrown away; the same knobs live under `tools[web_search]` on the Agent API, so this should fold into the migration.*

The previous report's note that our `openai` pin (`>=1.74.0,<3`) sat behind PyPI no longer holds: the pin is now `openai>=1.74.0,<4` and the latest release, 3.13.0, is inside it.
