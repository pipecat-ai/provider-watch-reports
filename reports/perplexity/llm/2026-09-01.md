# Perplexity LLM — 2026-09-01

Perplexity retires the Sonar chat-completions API on 2026-09-27; `PerplexityLLMService` calls nothing else, so it needs a migration decision this month.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Sonar chat completions retires 2026-09-27** (high, since 2026-09-01) — the docs banner on both the models page and the OpenAI-compatibility page reads "Sonar Chat Completions is now Agent API. Sonar will be supported until September 27, 2026." `PerplexityLLMService` posts to `https://api.perplexity.ai` + `/chat/completions`, so the service and its `sonar` default stop working on that date. The successor is `POST /v1/agent`, exposed OpenAI-compatibly as `/v1/responses` with slugs like `perplexity/sonar`; `OpenAIResponsesHttpLLMService` pointed at `base_url=https://api.perplexity.ai/v1` already streams a real answer from it (table below), while the websocket `OpenAIResponsesLLMService` is rejected with HTTP 401 — Perplexity serves HTTP only. Perplexity's own migration notes say `sonar-pro` has no Agent slug (it maps to the `low` preset or to `perplexity/sonar` plus a `web_search` tool), that `messages` becomes `input`/`instructions`, `max_tokens` becomes `max_output_tokens`, and that the Agent API rejects any unknown field with HTTP 400. — *Needs a call: reparenting the class onto the Responses/Agent surface changes the base class, the Settings shape and the model slugs, and probably retires `PerplexityLLMAdapter`'s message transforms; the `function-calling/function-calling-perplexity.py` example and its "does NOT support function calling" docstring also change, since the Agent API has tools.*
- **Search and reasoning controls unexposed** (low, since 2026-09-01) — the endpoint accepts `search_mode`, `disable_search`, `search_domain_filter`, `search_language_filter`, `search_recency_filter`, `search_after_date_filter`, `web_search_options`, `return_images`, `return_related_questions` and `reasoning_effort`; `build_chat_completion_params` forwards only `frequency_penalty`, `presence_penalty`, `temperature`, `top_p` and `max_tokens`, so grounding is entirely un-tunable. — *Needs a call: adding fields to an endpoint that retires on 2026-09-27 buys four weeks, so this is probably work to fold into the Agent API migration, where the same knobs live under `tools[web_search].filters`.*
