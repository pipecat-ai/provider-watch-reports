# Perplexity LLM — 2026-10-12

The retirement passed and the service did not break: Perplexity reformulates Sonar chat-completions traffic into Agent API calls, so the migration is still owed but no longer on a clock.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Sonar Chat Completions is unsupported but still served** (high, since 2026-09-01) — the previous report expected `PerplexityLLMService` to stop working on 2026-09-27. It did not. Perplexity's chat-completions API reference now carries a different note: support ended on September 27, 2026, and synchronous and streaming requests keep working because they are being reformulated as Agent API requests, rolling out gradually by model. Only asynchronous Sonar requests were actually dropped, and Pipecat never used them. Today all three slugs a user might pass stream fine through the unchanged class — `sonar` (the default), `sonar-pro` and `sonar-reasoning-pro` — and the sampling parameters the service forwards are still accepted. So nothing is broken and nothing is dated; what remains is that the service's only endpoint is one the provider has declared unsupported, kept alive by a compatibility layer with no published lifetime, retired per-model at Perplexity's discretion. The migration target is unchanged from last run: `POST /v1/agent`, aliased `/v1/responses`, where the documented starting points are presets rather than slugs (`sonar`→`fast`, `sonar-pro`→`fast`, `sonar-reasoning-pro`→`low`, `sonar-deep-research`→`high`), `max_tokens` becomes `max_output_tokens`, and web search must be requested explicitly as a `web_search` tool. Last run's probe (not repeated today) found `OpenAIResponsesHttpLLMService` with `base_url=https://api.perplexity.ai/v1` streams `perplexity/sonar` as a user-side escape hatch, while `perplexity/sonar-pro` is rejected with HTTP 400. — *Needs a call: reparenting changes the base class, the Settings shape and the model slugs, and probably retires `PerplexityLLMAdapter`'s message transforms. The deadline that would have forced it is gone, so this is now a judgement about how long to sit on an endpoint the provider no longer supports.*
- **Search and reasoning controls unexposed** (low, since 2026-09-01) — `build_chat_completion_params` forwards only `frequency_penalty`, `presence_penalty`, `temperature`, `top_p` and `max_tokens`, leaving `search_mode`, `disable_search`, `search_domain_filter`, `search_recency_filter`, `web_search_options`, `return_related_questions` and `reasoning_effort` unreachable, so grounding is un-tunable. — *Needs a call: last run the blocker was that the endpoint had two weeks to live; now it is that reformulation may quietly discard these fields en route to the Agent API, where the same knobs live under the `web_search` tool. Establishing whether they still take effect is the prerequisite, and if they don't, this folds into the migration.*

`examples/function-calling/function-calling-perplexity.py` pins no model string and its "Perplexity's completions API doesn't support tool calling" note still holds for the endpoint the service calls, so there was nothing mechanical to fix. The `openai` pin (`>=1.74.0,<4`) still covers the latest release, 3.29.0.
