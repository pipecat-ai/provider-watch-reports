# Fal STT — 2026-10-12

No provider-side change since 2026-09-14; the news is ours — the Fal STT settings example raises a `TypeError` ten seconds into every call, and a branch fixes it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6134 — Update language in the Fal STT settings example

`examples/update-settings/stt/stt-fal.py` sends `STTUpdateSettingsFrame(delta=FalSTTService.Settings(worker="translate"))` from its `on_client_connected` handler. `FalSTTSettings` has only `model`, `extra` and `language`, so the construction raises `FalSTTSettings.__init__() got an unexpected keyword argument 'worker'` — confirmed by constructing it. The branch switches the demo to `language=Language.ES`, which is what the other twenty STT settings examples do and the only field Fal can usefully update; `_update_settings` converts the delta to the wire value `es`, and a probe with that value transcribes correctly.

### To consider
- **Language auto-detect errors out** (high, since 2026-09-01) — Wizper documents `language: null` as auto-detect and the request does succeed, but `Language(self._settings.language)` in `run_stt` raises `None is not a valid Language`; the handler turns the whole utterance into an ErrorFrame, so the user gets no transcript. Re-probed today, unchanged. — *Needs a call: what `TranscriptionFrame.language` should carry when fal auto-detects — the response returns a `languages` list rather than a single code.*
- **Leaked aiohttp session** (medium, since 2026-09-01) — the service creates its own `ClientSession` when none is passed and records `_owns_session`, but nothing reads that flag: no `stop`/`cancel`/`cleanup` closes it, and every probe run today still ended with `Unclosed client session`. `cartesia/tts.py` closes an owned session in both `stop` and `cancel`. — *Needs a call: which lifecycle hooks own the close; this is a behavior change rather than a value change.*
- **`task` is construction-only** (low, since 2026-10-12) — switching between transcription and translation means rebuilding the service: `task` lives in `self._task` from the constructor, not in `FalSTTSettings`, so no `STTUpdateSettingsFrame` can reach it. This is what the broken settings example was reaching for. — *Needs a call: whether `task` becomes a Settings field; it would have to win over the constructor argument, so it is not a pure pass-through.*
- **Language map never applied** (low, since 2026-09-14) — `run_stt` puts `self._settings.language` into the payload directly, bypassing `language_to_service_language`, so the 96-entry `LANGUAGE_MAP` and `resolve_language`'s base-code fallback are unreachable from the request path. Settings deltas are converted on the way in (`Settings(language=Language.ES)` stores `es`), so the common path is fine and this stays latent — but a raw string fal does not recognise reaches the API instead of degrading to its base code. — *Needs a call: whether to route the payload through `language_to_service_language`, which changes the wire value for regional codes fal currently tolerates.*
- **Wizper-only endpoint** (low, since 2026-09-01) — `https://fal.run/fal-ai/wizper` is hard-coded and `Settings(model=...)` is accepted but ignored, so fal's other transcription endpoints (Canary `fal-ai/speech-to-text` with its `/turbo`, `/stream` and `/turbo/stream` variants, ElevenLabs Scribe v2, Cohere Transcribe) are unreachable. — *Needs a call: keep Fal support Wizper-only, as the registry label `Fal (Wizper)` implies, or add model routing / a streaming class; the endpoints have different request schemas.*
- **`max_segment_len` / `merge_chunks` unexposed** (low, since 2026-09-01) — the only two Wizper request fields the service never sends; both only shape chunking of long audio (`max_segment_len` is bounded 10–29 s), while `SegmentedSTTService` posts one utterance at a time and reads only `text`. — *Needs a call: whether they earn Settings fields given segmented input.*

Checked and clear: the live Wizper schema is byte-identical to the last two runs — `version` still `const "3"`, `chunk_level` still `const "segment"`, `task` still the two-value enum, the language enum still 99 codes plus `null`, `max_segment_len` still 10–29. Wizper reports `deprecated: false` in fal's model index with no successor, and fal's STT catalogue holds the same eleven entries as on 2026-09-14 — no additions. The `fal` extra pulls no SDK (`fal = []` in `pyproject.toml`), so there is no pin to compare, and `src/pipecat/services/fal/stt.py` has not changed since 2026-06-13.
