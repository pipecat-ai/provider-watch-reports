# Fal STT — 2026-09-01

Wizper is current and the default path transcribes correctly; the findings are two bugs in our own code, both reproduced with `probe.py`.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Language auto-detect errors out** (high, since 2026-09-01) — Wizper documents `language: null` as auto-detect, and the request does succeed, but `Language(self._settings.language)` in `run_stt` raises `None is not a valid Language`; the exception handler turns the whole utterance into an ErrorFrame, so the user gets no transcript. Same shape for any settings language string outside the `Language` enum. — *Needs a call: what `TranscriptionFrame.language` should carry when fal auto-detects — the response returns a `languages` list rather than a single code.*
- **Leaked aiohttp session** (medium, since 2026-09-01) — the service creates its own `ClientSession` when none is passed and records `_owns_session`, but nothing ever reads that flag: there is no `stop`/`cancel`/`cleanup` that closes the session, and every probe run ends with `Unclosed client session`. `cartesia/tts.py` closes an owned session in both `stop` and `cancel`. — *Needs a call: which lifecycle hooks own the close; this is a behavior change rather than a value change.*
- **Wizper-only endpoint** (low, since 2026-09-01) — `https://fal.run/fal-ai/wizper` is hard-coded and `Settings(model=...)` is accepted but ignored, so fal's other transcription endpoints (Canary `fal-ai/speech-to-text` and its `/turbo` and `/stream` variants, ElevenLabs Scribe v2, Cohere Transcribe) are unreachable. — *Needs a call: keep Fal support Wizper-only, as the registry label `Fal (Wizper)` implies, or add model routing / a streaming class; the endpoints have different request schemas.*
- **`max_segment_len` / `merge_chunks` unexposed** (low, since 2026-09-01) — the only two Wizper request fields the service never sends; both only shape chunking of long audio, while `SegmentedSTTService` posts one utterance at a time and reads only `text`. — *Needs a call: whether they earn Settings fields given segmented input.*

Checked and clear: `version` is `const: "3"` in the live schema, so the hard-coded `"3"` is the only valid value; `task` and `chunk_level` match the schema's enums; the language map covers every code in Wizper's enum except `haw`, which `resolve_language`'s base-code fallback passes through unchanged. Wizper is not marked deprecated in fal's model index. The `fal` extra pulls no SDK (`fal = []` in `pyproject.toml`), so there is no pin to compare.
