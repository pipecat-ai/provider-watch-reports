# Fal image generation — 2026-10-12

Nothing to do: `fal-ai/fast-sdxl` is live, undeprecated and schema-identical to last run, the shipped defaults still generate an image, and the three open items are the same maintainer calls.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **SDXL-shaped payload on non-SDXL endpoints** (medium, since 2026-09-01) — `Settings.model` routes to any fal endpoint and fal ignores unknown fields, but `format`, `num_inference_steps` and `expand_prompt` only apply to fast-sdxl. Re-checked this run on fal's two newest endpoints: `fal-ai/nano-banana-2` and `fal-ai/gemini-3-pro-image-preview` accept `output_format` and have no `num_inference_steps`, `expand_prompt` or `format`; `fal-ai/gpt-image-1.5` and `fal-ai/flux-2-pro` likewise; `fal-ai/bytedance/seedream/v4.5/text-to-image` has no format field of any name. — *Needs a call: map the field per endpoint, add a parallel `output_format` setting (it would duplicate `format`'s meaning, so it is not a clean pass-through), or keep the settings SDXL-shaped and document that.*
- **Default model** (low, since 2026-09-01) — fal's line-up keeps growing (Gemini 3 Pro Image Preview and GPT-Image 1.5 joined since the last run), but fast-sdxl is still documented with no deprecation or legacy label and fal names no successor. — *Needs a call: choosing a different default is a cost/quality preference, not a provider migration.*
- **Unexposed request fields** (low, since 2026-09-01) — fast-sdxl's schema also offers `sync_mode`, `safety_checker_version`, `loras`, `embeddings` and `request_id`, none reachable from `Settings`; `sync_mode` is the only one fal's newer endpoints share. — *Needs a call: `sync_mode` requires `run_image_gen` to decode data URIs, `loras`/`embeddings` are lists of objects, and a fast-sdxl-only field like `safety_checker_version` prejudges the payload-shape question.*
