# Fal image generation — 2026-11-09

Nothing to do: `fal-ai/fast-sdxl` is undeprecated and still generates with the shipped defaults; the one schema change since last run is a field rename fal still accepts under the old name.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **SDXL-shaped payload on non-SDXL endpoints** (medium, since 2026-09-01) — `Settings.model` routes to any fal endpoint and fal ignores unknown fields, but `format`, `num_inference_steps` and `expand_prompt` only apply to fast-sdxl. Re-verified against live schemas this run: `fal-ai/nano-banana-2`, `fal-ai/z-image/turbo`, `fal-ai/gpt-image-1.5` and `fal-ai/flux/schnell` take `output_format`; `fal-ai/bytedance/seedream/v4.5/text-to-image` has no format field of any name. — *Needs a call: map the field per endpoint, add a parallel `output_format` setting (it would duplicate `format`'s meaning, so it is not a clean pass-through), or keep the settings SDXL-shaped and document that.*
- **Default model** (low, since 2026-09-01) — fal's documented line-up is unchanged since 2026-10-12 and still leads with Nano Banana 2, but fast-sdxl carries no deprecation or legacy label and fal names no successor. — *Needs a call: choosing a different default is a cost/quality preference, not a provider migration.*
- **Unexposed request fields** (low, since 2026-09-01) — fast-sdxl's schema also offers `sync_mode`, `safety_checker_version`, `loras`, `embeddings` and `request_id`, none reachable from `Settings`; `sync_mode` is the only one fal's newer endpoints share. — *Needs a call: `sync_mode` requires `run_image_gen` to decode data URIs, `loras`/`embeddings` are lists of objects, and a fast-sdxl-only field like `safety_checker_version` prejudges the payload-shape question.*
- **Prompt-expansion field renamed** (low, since 2026-11-09) — fast-sdxl's schema dropped `expand_prompt` and now documents `enable_prompt_expansion`, the name z-image/turbo already used. Probed both: each one expands the prompt, and a control call with neither leaves it verbatim, so the setting the service ships still works. — *Needs a call: sending the documented name would split the `expand_prompt` setting's name from the wire key, which is the same per-endpoint mapping question above; worth doing with that decision or when fal drops the alias.*
