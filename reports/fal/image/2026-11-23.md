# Fal image generation — 2026-11-23

Nothing to do: `fal-ai/fast-sdxl` is undeprecated and its request schema is byte-for-byte what it was on 2026-11-09; the open items are all the same per-endpoint payload-shape question as before.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **SDXL-shaped payload on non-SDXL endpoints** (medium, since 2026-09-01) — `Settings.model` routes to any fal endpoint and fal ignores unknown fields, but `format`, `num_inference_steps` and `expand_prompt` only apply to fast-sdxl. fal's two newest text-to-image endpoints widen the split: `microsoft/mai-image-2.7/text-to-image` takes `output_format` and has no `num_inference_steps`, `seed` or `negative_prompt`; `kling/v4/text-to-image` takes neither a format field nor `image_size`, `seed`, `num_inference_steps` or `enable_safety_checker` — six of the seven fields the service always sends are undefined there. — *Needs a call: map the field per endpoint, add a parallel `output_format` setting (it would duplicate `format`'s meaning, so it is not a clean pass-through), or keep the settings SDXL-shaped and document that.*
- **Default model** (low, since 2026-09-01) — fal shipped GPT Image 2.6 (2026-11-04), MAI-Image-2.7, Kling Image V4 and Ideogram 4.6 since the last run, and the docs quick start leads with `fal-ai/nano-banana-2`, but fast-sdxl carries no deprecation or legacy label and fal names no successor. — *Needs a call: choosing a different default is a cost/quality preference, not a provider migration.*
- **Unexposed request fields** (low, since 2026-09-01) — fast-sdxl's schema also offers `sync_mode`, `safety_checker_version`, `loras`, `embeddings` and `request_id`, none reachable from `Settings`; `sync_mode` is the only one fal's newer endpoints share, and it is on all of them including mai-image-2.7 and kling/v4. — *Needs a call: `sync_mode` requires `run_image_gen` to decode data URIs, `loras`/`embeddings` are lists of objects, and a fast-sdxl-only field like `safety_checker_version` prejudges the payload-shape question.*
- **Prompt-expansion field renamed** (low, since 2026-11-09) — fast-sdxl documents only `enable_prompt_expansion`, the name z-image/turbo already used, while the service sends `expand_prompt`. The 2026-11-09 probe showed fal honours both names; re-probing was not possible this run. — *Needs a call: sending the documented name would split the `expand_prompt` setting's name from the wire key, which is the same per-endpoint mapping question above; worth doing with that decision or when fal drops the alias.*
