# Fal image generation — 2026-09-01

`fal-ai/fast-sdxl` is still live and undeprecated, so the default stands; the branch adds the two
request fields users most often reach for, and the open question is how far the SDXL-shaped
payload should follow fal's newer image endpoints.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5556 — Expose Fal's negative_prompt and guidance_scale image settings

### To consider
- **SDXL-shaped payload on non-SDXL endpoints** (medium, since 2026-09-01) — `Settings.model` does route to any fal endpoint (fal ignores unknown fields, so the SDXL-only `expand_prompt`/`format` do not break the request), but `format` only applies to fast-sdxl: flux, qwen-image and nano-banana call it `output_format`, and a probe with `format=png` against `fal-ai/flux/schnell` came back `content_type=image/jpeg`. — *Needs a call: map the field per endpoint, or keep the settings SDXL-shaped and say so in the docstring.*
- **Default model** (low, since 2026-09-01) — `fal-ai/fast-sdxl` is fal's 2023 SDXL endpoint, still documented with no deprecation notice; fal's current text-to-image line-up (`fal-ai/flux/schnell`, `fal-ai/qwen-image`, `fal-ai/nano-banana`) is newer but fal names no successor, and fast-sdxl was the faster of the two endpoints probed. — *Needs a call: choosing a different default is a cost/quality preference, not a provider migration.*
- **Unexposed request fields** (low, since 2026-09-01) — `sync_mode`, `safety_checker_version`, `loras` and `embeddings` have no `Settings` fields; `sync_mode` is the interesting one, since it would remove the image download round-trip. — *Needs a call: `sync_mode` requires `run_image_gen` to decode data URIs instead of GETting a URL, and `loras`/`embeddings` are lists of objects.*

## Verification

`probe.py run` refuses image services (research-only, exit 3), so these are ad-hoc calls: the
first two through `FalImageGenService.run_image_gen`, the rest raw POSTs of the exact payload
`FalImageGenSettings.to_api_arguments()` builds. Latency is end-to-end (generation plus the
image download), one sample each.

| model               | class                                | ok | latency  | note                                                                                  |
| ------------------- | ------------------------------------ | -- | -------- | ------------------------------------------------------------------------------------- |
| fal-ai/fast-sdxl    | FalImageGenService                   | ✅ | 2220 ms  | shipped defaults; 1024×1024 PNG                                                        |
| fal-ai/fast-sdxl    | FalImageGenService (branch)          | ✅ | 2780 ms  | `negative_prompt="blurry, text"`, `guidance_scale=5.0` both sent and accepted          |
| fal-ai/fast-sdxl    | raw POST of the settings payload     | ✅ | 1800 ms  | generation only, no download                                                           |
| fal-ai/flux/schnell | raw POST of the settings payload     | ✅ | 2185 ms  | SDXL-only `expand_prompt`/`format` ignored, not rejected                               |
| fal-ai/flux/schnell | raw POST with `format=png`           | ✅ | —        | returned `content_type=image/jpeg`: the endpoint reads `output_format`                 |
