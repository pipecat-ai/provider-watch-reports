# AssemblyAI TTS — 2026-11-23

Current: AssemblyAI shipped no TTS change in the two weeks since the last report, `assemblyai-tts-1` is still the only model and still GA with no retirement date, and the five known gaps carry forward unchanged. No branch.

The changelog's only entries since 2026-10-28 are STT (AssemblyAI-STT-3.7 on 2026-11-18) and the MCP server; the TTS WebSocket reference still lists the same nine connect parameters, five client frames and seven server frames the last run catalogued, with nothing marked new, beta or deprecated. The emotion tags and pronunciation dictionaries AssemblyAI trailed at launch have not landed, so there is still no prosody, speed or expressive control anywhere in the API and no expression adapter to write. Pipecat's own code moved once in this window — `464481a06` now flushes a request before switching audio context — which closes no gap here.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Cloned-voice consent and idle timeout** (medium, since 2026-11-09) — `inactivity_timeout` (5–120 s, default 120) and `extend_biometric_consent` are documented connect params with no `Settings` fields. The idle timeout matters little while the service sends `KeepAlive` every 30 s, but consent does: `Begin.configuration` carries `voice_expires_at` and `resolved_voice.extend_due_at`, the service logs them only as part of the whole configuration dump, and a cloned voice whose consent lapses then fails with `3012 voice_expired`. — *Needs a call: `extend_biometric_consent` renews a consent on the account rather than shaping a request, and both apply at connect time only — a `Settings` field would have to join the `voice`/`language`/`model` reconnect set to mean anything — so whether they belong in `Settings` or as constructor arguments has to be decided.*
- **Error categories drop `error_type`** (low, since 2026-11-09) — `_handle_error` branches on `error_code` and retryability only. Every non-retryable `1008` becomes `AUTHENTICATION`, so an account out of balance (`insufficient_funds`) reports as a credential problem; non-retryable errors after `Begin` — `invalid_request`, `input_rate_exceeded`, `audio_backlog` — all become `UNKNOWN`, though the server names each in `error_type`. — *Needs a call: `QUOTA` is not permanent, so re-categorizing `insufficient_funds` would turn a dead stop into a reconnect loop; the fix is either a category change or a permanence change, and that is a maintainer's decision.*
- **Default voice as a UUID** (low, since 2026-11-09) — `_DEFAULT_VOICE_ID = "49c443a4-8a1d-5f7e-b70b-98bdbd9823c3"` (Audrey). AssemblyAI's voices page lists slugs only and names `aai-kyla` as the English default; a probe this run confirms `aai-kyla` works through the class unchanged. The literal is repeated in `examples/voice/voice-assemblyai*.py`, `examples/update-settings/tts/tts-assemblyai.py`, `src/pipecat/cli/registry/_configs.py` and `src/pipecat/cli/registry/service_metadata.py`. — *Needs a call: purely cosmetic churn across seven files plus the docs page, and the team may prefer AssemblyAI's own English default, `aai-kyla`.*
- **Unsupported sample rates fail hard** (low, since 2026-11-09) — `_build_websocket_url` forwards `self.sample_rate` as-is. The API takes 8000, 16000, 22050, 24000, 44100 and 48000; last run's probe at 32000 was refused before `Begin` with `3006 invalid_parameter`, which the service reports as `INVALID_REQUEST` — a permanent category, so the TTS is unusable for the rest of the call. — *Needs a call: whether to check client-side at construction or resample to a supported rate.*
- **No HTTP class** (low, since 2026-11-09) — AssemblyAI also exposes `POST /v1/speech`, `POST /v1/speech/events` (SSE carrying word timings) and OpenAI-compatible routes; Pipecat ships the WebSocket class alone. — *Needs a call: this is a new service class rather than a settings change, and the WebSocket session already covers the real-time path.*

One thing re-checked and still a non-issue: the service hard-codes `encoding=pcm_s16le` while the API also accepts `pcm_mulaw` and `pcm_alaw`, but Pipecat's telephony serializers do that conversion themselves, so nothing is lost.
