# AssemblyAI TTS — 2026-11-09

First report for this unit, and there is nothing to bump: AssemblyAI ships one TTS model, `assemblyai-tts-1`, launched 2026-10-28, and the service already speaks the full WebSocket protocol. No branch this run; the findings are small unexposed connect parameters and diagnostic polish.

The service leaves `model` unset, so the session runs the region's default for the language — which is `assemblyai-tts-1`, confirmed in `Begin.configuration.model`. Passing it explicitly works too. The six languages in `language_to_assemblyai_tts_language` are exactly the six the API accepts, and the API documents no prosody, speed or emotion controls at all (`speed` on the HTTP route is refused unless it equals `1`), so there is no expressive markup for an expression adapter to carry and no synthesis knob missing from `Settings`.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Cloned-voice consent and idle timeout** (medium, since 2026-11-09) — `inactivity_timeout` (5–120 s) and `extend_biometric_consent` are documented connect params with no `Settings` fields. The idle timeout matters little while the service sends `KeepAlive` every 30 s, but consent does: `Begin.configuration` carries `voice_expires_at` and `resolved_voice.extend_due_at`, the service logs them only as part of the whole configuration dump, and a cloned voice whose consent lapses then fails with `3012 voice_expired`. — *Needs a call: `extend_biometric_consent` renews a consent on the account rather than shaping a request, and applies at connect time only, so whether it belongs in `Settings` or as a constructor argument has to be decided.*
- **Error categories drop `error_type`** (low, since 2026-11-09) — `_handle_error` branches on `error_code` and retryability only. Every non-retryable `1008` becomes `AUTHENTICATION`, so an account out of balance (`insufficient_funds`) reports as a credential problem; non-retryable errors after `Begin` — `invalid_request`, `input_rate_exceeded`, `audio_backlog` — all become `UNKNOWN`, though the server names each in `error_type`. — *Needs a call: `QUOTA` is not permanent, so re-categorizing `insufficient_funds` would turn a dead stop into a reconnect loop; the fix is either a category change or a permanence change, and that is a maintainer's decision.*
- **Default voice as a UUID** (low, since 2026-11-09) — `_DEFAULT_VOICE_ID = "49c443a4-8a1d-5f7e-b70b-98bdbd9823c3"` (Audrey). AssemblyAI's voices page lists slugs only, and a probe showed `aai-audrey` resolving to that exact UUID, so the slug is the same voice in a readable form. The literal is repeated in `examples/voice/voice-assemblyai*.py`, `examples/update-settings/tts/tts-assemblyai.py` and the CLI registry config. — *Needs a call: purely cosmetic churn across six files plus the docs page, and the team may prefer AssemblyAI's own English default, `aai-kyla`, which its Pipecat page recommends.*
- **Unsupported sample rates fail hard** (low, since 2026-11-09) — `_build_websocket_url` forwards `self.sample_rate` as-is. The API takes 8000, 16000, 22050, 24000, 44100 and 48000; a probe at 32000 was refused before `Begin` with `3006 invalid_parameter` and a clear message, which the service reports as `INVALID_REQUEST` — a permanent category, so the TTS is unusable for the rest of the call. — *Needs a call: whether to check client-side at construction or resample to a supported rate.*
- **No HTTP class** (low, since 2026-11-09) — AssemblyAI also exposes `POST /v1/speech`, `POST /v1/speech/events` (SSE carrying word timings) and OpenAI-compatible routes; Pipecat ships the WebSocket class alone. — *Needs a call: this is a new service class rather than a settings change, and the WebSocket session already covers the real-time path.*

Two things checked and found to be non-issues: the docstring's example voices `aai-jane` and `987db62e-a2c2-569a-9c4d-82460cdea1bd` (Keegan) are absent from the published voices page but both resolve as public library voices, and the service's implicit handling of `Cancelled` (dropping audio by `flush_id` after a `Cancel`) matches what the spec asks for.
