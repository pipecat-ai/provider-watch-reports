# AssemblyAI STT — 2026-11-09

Current: `universal-3-6-pro` is still AssemblyAI's recommended streaming model and the session default when `speech_model` is omitted, both Pipecat classes ship it, and nothing in the service is deprecated or scheduled for removal. No branch this run.

## What's new for Pipecat

### PRs
Nothing. PR #5530 (`max_speakers` / `filter_profanity`) merged on 2026-11-07, closing that gap; both fields are in `AssemblyAISTTSettings` and on the connect URL.

### To consider
- **Server `Error` messages are swallowed** (medium, since 2026-08-31) — the errors page documents an `Error` frame (`type`, `error_code`, `error`) sent immediately before close, and says the close reason is *always* "See Error message for details.", so the close code alone tells the user nothing. `_parse_message` handles `Begin`, `Turn`, `SpeechStarted` and `Termination` and raises `ValueError` otherwise, which `_handle_message` turns into `push_error("Unknown error occurred: Unknown message type: Error")`. `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` go the same way. — *Needs a call: the `Error` path is a self-contained diagnostic fix, but `SpeakerRevision` corrects speaker labels on turns already pushed downstream, so whether the two land together has to be decided.*
- **Unrecognized values run silently** (medium, since 2026-10-28) — `Begin.configuration` is still described as "Always check that `model` matches the `speech_model` you requested — unrecognized or misspelled query parameters are ignored rather than rejected", and last run's probe confirmed it for both APIs. `BeginMessage` parses `id` and `expires_at` only, so the echo is discarded; `U3_PRO_MODEL_PREFIXES` and the deprecated `AssemblyAIConnectionParams.speech_model` Literal still advertise `u3-rt-pro`, which the models page marks "do not use". — *Needs a call: parsing `configuration` and warning on a mismatch is new behavior at connect time, and dropping retired IDs would start rejecting configurations that currently work.*
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` are connect params with no `Settings` fields, and `include_partial_turns` defaults to false once redaction is on. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `UpdateConfigurationPayload` carries eleven fields (`prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `vad_threshold`, `interruption_delay`, `agent_context`, `mode`, `end_of_turn_confidence_threshold`, `language_codes`, `session_heartbeat`); `HOT_UPDATABLE_SETTINGS` holds two, so changing any other setting disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns`, `session_heartbeat` and `speaker_labels_revision_interval_ms` have no `Settings` fields. Each changes session or frame behavior; `inactivity_timeout` drags in the client-side `KeepAlive` message the service never sends. — *Needs a call: `session_heartbeat` and `speaker_labels_revision_interval_ms` only pay off once `Heartbeat` and `SpeakerRevision` are parsed, and `include_partial_turns=false` would starve the pipeline of interim frames.*
- **Sync retries nothing** (medium, since 2026-09-14) — the Sync error-handling page classifies 429 and 503 as transient ("retry after the `Retry-After` header, or a short backoff when absent") and 500/504 as safe to retry once. `_transcribe` raises on any non-200 and `run_stt` converts it into an `ErrorFrame`, so a rate-limited or capacity-shed turn is lost. — *Needs a call: retrying inside `run_stt` holds up a live turn, so the retry budget — and whether to honor `Retry-After` verbatim or cap it — has to be decided.*
- **Sync chunked upload** (medium, since 2026-09-14) — `POST /v1/transcribe/live` takes a chunked multipart body whose `config` part precedes the `audio` part, so the upload happens while the speaker is still talking; `AssemblyAISyncSTTService` buffers each VAD segment and posts the complete WAV afterwards. — *Needs a design call: streaming the request body inverts `SegmentedSTTService`'s buffer-then-post flow.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — `continuous_partials`, `formatted_finals` and `word_finalization_max_wait_time` are absent from the spec and ignored on the wire, and continuous partials are documented as unconditional behavior, so the default-on field is a no-op. The spec's parameter list no longer carries `language_code` at all (only `language_codes`), and the deprecated `language_code` field still has no `.. deprecated::` marker. — *Needs a call: all four are public `Settings` fields, so retiring them means running a deprecation cycle.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages; it is also AssemblyAI's documented route to real-time translation. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **Streaming webhooks** (low, since 2026-11-09) — `webhook_url` (plus optional `webhook_auth_header_name` / `webhook_auth_header_value`) is a documented connect parameter that POSTs the session's finalized turns to an HTTP endpoint after termination. It appears on the webhooks page but not in the AsyncAPI spec's parameter list, and a Pipecat pipeline already holds every turn the webhook would deliver. — *Needs a call: `webhook_auth_header_value` would travel in the websocket URL's query string, so a secret-valued `Settings` field needs sign-off, as does whether post-session delivery is worth exposing at all.*
- **Diarization `speaker_confidence`** (low, since 2026-11-09) — the spec's `TurnPayload` and `Word` both carry an experimental `speaker_confidence` (0.0–1.0) when `speaker_labels` is enabled. Pipecat's `TurnMessage` and `Word` do not declare it, so pydantic drops it and it never reaches the `TranscriptionFrame`'s `result`. — *Needs a call: AssemblyAI calls the score experimental, uncalibrated and "not the probability that the label is correct", so confirm whether to surface it before its shape settles.*
- **Stale server default in a docstring** (low, since 2026-11-09) — `previous_context_n_turns` is documented in `AssemblyAISTTSettings` as "the server default, which is 3"; the spec now says "When unset, the server default applies (currently 5 turns)". Pipecat sends nothing when the field is unset, so only the documentation is wrong. — *Needs a call: AssemblyAI moves server-side defaults without notice, so confirm whether docstrings should quote them at all rather than just say "the server default".*
- **u3-rt-pro in the Inworld example** (low, since 2026-09-14) — `examples/realtime/realtime-inworld-locally-driven-turns.py` sets `stt_model = "assemblyai/u3-rt-pro"`. The string is Inworld's namespaced model ID inside its realtime session config, not a value Pipecat sends to AssemblyAI. — *Needs a call from the inworld/realtime unit: only Inworld can say which `assemblyai/*` IDs its realtime API accepts.*

Last run's `max_speakers`/`filter_profanity` gap is closed by the merge of #5530. The Sync API reference's `X-AAI-Model` enum, which listed `universal-3-5-pro` alone last run, now lists `universal-3-6-pro` as the recommended value — what both Pipecat classes already send.
