# AssemblyAI STT — 2026-10-28

Nothing to bump and nothing retiring: `universal-3-6-pro` is AssemblyAI's recommended streaming model, the session default when `speech_model` is omitted, and now the default of both Pipecat classes. No branch this run. What the probes turned up instead is about diagnosis — AssemblyAI ignores model IDs and parameters it does not recognize, and the service surfaces the server's own `Error` messages as "Unknown message type: Error".

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5530 — Expose AssemblyAI's max_speakers and filter_profanity settings (open since 2026-09-01)

### To consider
- **Server `Error` messages are swallowed** (medium, since 2026-08-31) — a connect the server rejects comes back as `{"type": "Error", "error_code": 3006, "error": "User Input Validation Error: ..."}`, observed this run. `_parse_message` knows only `Begin`, `Turn`, `SpeechStarted` and `Termination`, raises `ValueError` for anything else, and `_handle_message` turns that into `push_error("Unknown error occurred: Unknown message type: Error")` — the server's explanation never reaches the user. `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` go the same way. — *Needs a call: the `Error` path is a self-contained diagnostic fix, but `SpeakerRevision` corrects speaker labels on turns already pushed downstream, so whether the two land together has to be decided.*
- **Unrecognized values run silently** (medium, since 2026-10-28) — the streaming spec's `Begin.configuration` says "Always check that `model` matches the `speech_model` you requested — unrecognized or misspelled query parameters are ignored rather than rejected." A probe confirmed it: `speech_model=u3-rt-pro`, an ID AssemblyAI's models page now marks "do not use", opened a session running `universal-3-6-pro` with no warning, and the Sync API answered 200 to a made-up `X-AAI-Model`. `BeginMessage` parses `id` and `expires_at` only, so the echo Pipecat is told to check is discarded; meanwhile `U3_PRO_MODEL_PREFIXES` and the deprecated `AssemblyAIConnectionParams.speech_model` Literal still advertise `u3-rt-pro`. — *Needs a call: parsing `configuration` and warning on a mismatch is new behavior at connect time, and dropping retired IDs would start rejecting configurations that currently work.*
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` are connect params with no `Settings` fields. Redaction applies to final turns only, and the spec says `include_partial_turns` defaults to false when `redact_pii` is enabled. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `HOT_UPDATABLE_SETTINGS` holds `agent_context` and `language_codes`; `UpdateConfiguration` also accepts `prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `vad_threshold`, `interruption_delay`, `mode`, `end_of_turn_confidence_threshold` and `session_heartbeat`, and AssemblyAI now documents the set page by page with its per-model applicability. Changing any of those today disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision, not a mechanical widening of the set.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns`, `session_heartbeat` and `speaker_labels_revision_interval_ms` are documented optional scalars with no `Settings` fields. Unlike `max_speakers`/`filter_profanity` (on the open PR above), each changes session or frame behavior: `inactivity_timeout` drags in the client-side `KeepAlive` message the service never sends. — *Needs a call: `session_heartbeat` and `speaker_labels_revision_interval_ms` only pay off once `Heartbeat` and `SpeakerRevision` are parsed, and `include_partial_turns=false` would starve the pipeline of interim frames, so which subset to expose needs deciding.*
- **Sync retries nothing** (medium, since 2026-09-14) — AssemblyAI's Sync error-handling page classifies 429 and 503 as transient and tells clients to retry after `Retry-After`. `_transcribe` raises `ClientResponseError` on any non-200 and `run_stt` converts it into an `ErrorFrame`, so a rate-limited or capacity-shed turn is simply lost. — *Needs a call: retrying inside `run_stt` holds up a live turn, so the retry budget — and whether to honor `Retry-After` verbatim or cap it — has to be decided before any plumbing.*
- **Sync chunked upload** (medium, since 2026-09-14) — the Sync API exposes `POST /v1/transcribe/live` alongside `/v1/transcribe`: a chunked multipart body whose `config` part precedes the `audio` part, so the upload happens while the speaker is still talking. `AssemblyAISyncSTTService` buffers each VAD segment and posts the complete WAV afterwards. — *Needs a design call: streaming the request body during the segment inverts `SegmentedSTTService`'s buffer-then-post flow, so this is a restructure rather than a pass-through.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — `continuous_partials`, `formatted_finals` and `word_finalization_max_wait_time` are absent from the streaming spec and, per the `Begin` note above, ignored on the wire; the service still sends all three. Last run left open whether dropping `continuous_partials` changes the interim cadence: it does not — the turn-detection page now describes continuous partials as unconditional behavior ("emitted roughly every second during uninterrupted speech"), so the default-on field is a no-op. `language_code` was deprecated in favour of `language_codes` on 2026-07-03 and still carries no `.. deprecated::` marker. — *Needs a call: all three are public `Settings` fields, so retiring them means running a deprecation cycle; confirm the team wants to start one.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages; it is now also AssemblyAI's documented route to real-time translation. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **u3-rt-pro in the Inworld example** (low, since 2026-09-14) — `examples/realtime/realtime-inworld-locally-driven-turns.py` sets `stt_model = "assemblyai/u3-rt-pro"`. The string is Inworld's namespaced model ID inside its realtime session config, not a value Pipecat sends to AssemblyAI. — *Needs a call from the inworld/realtime unit: only Inworld can say which `assemblyai/*` IDs its realtime API accepts.*

The previous run's default-bump gap is closed: PR #5933 merged on 2026-09-28, and a separate commit (`6bc79c710`, from AssemblyAI) moved `AssemblyAISyncSTTService` to `universal-3-6-pro` on 2026-10-08.
