# AssemblyAI STT — 2026-08-31

`universal-3-5-pro` is still AssemblyAI's recommended streaming model, so the default stands; the branch retires the `u3-rt-pro` name from examples and service strings, and the streaming spec has grown six affordances `Settings` cannot express.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5507 — Name AssemblyAI's current U3 Pro streaming model in examples and docs

### To consider
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` shipped on 2026-05-15 for every streaming model and have no `Settings` fields. Redaction applies to final turns only, and the server flips `include_partial_turns` to false when it is on. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `HOT_UPDATABLE_SETTINGS` holds `agent_context` and `language_codes`; AssemblyAI's `UpdateConfiguration` also accepts `prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `continuous_partials`, `vad_threshold`, `interruption_delay`, `mode`, `end_of_turn_confidence_threshold` and `session_heartbeat`. Changing any of those today disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision, not a mechanical widening of the set.*
- **Unrecognized server messages** (medium, since 2026-08-31) — `_parse_message` raises `ValueError` for any message type it does not know and `_handle_message` converts that into `push_error`, so `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` all surface as errors. `SpeakerRevision` is sent at session end whenever `speaker_labels` is enabled, which the service already exposes. A short single-speaker probe with `speaker_labels=true` did not produce one, so the path is spec-derived rather than observed. — *Needs a call: `SpeakerRevision` corrects speaker labels on turns already pushed downstream; quietly ignoring it and acting on it are different features.*
- **Missing scalar connect params** (medium, since 2026-08-31) — `max_speakers` (1–10, pairs with the `speaker_labels` field we already have), `inactivity_timeout`, `filter_profanity`, `include_partial_turns` and `session_heartbeat` are documented optional scalars with no `Settings` fields; each would be a one-line pass-through in `_build_ws_url`. — *Needs a call: `session_heartbeat` is only useful once `Heartbeat` is parsed and `include_partial_turns=false` would starve the pipeline of interim frames, so which subset to expose needs deciding.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — `language_code` was deprecated in favour of `language_codes` on 2026-07-03 and the field docstring already says to prefer `language_codes`, but there is no `.. deprecated::` marker. `formatted_finals` and `word_finalization_max_wait_time` do not appear in the current AsyncAPI spec, yet `_build_ws_url` sends `formatted_finals` on every connect (probes still succeed, so the server tolerates it). — *Needs a call: confirm with AssemblyAI whether those two are still honoured before removing or documenting them.*
