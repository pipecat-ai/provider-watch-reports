# AssemblyAI STT — 2026-09-28

`universal-3-6-pro` is now AssemblyAI's documented flagship, its "Recommended" streaming model and the model a session gets when `speech_model` is omitted — the condition the last two runs set for the default bump. Branch ready; it is faster than `universal-3-5-pro` on our probe. The Sync service is untouched: `universal-3-5-pro` is still the only value the Sync API's `X-AAI-Model` enum accepts.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5933 — Default AssemblyAISTTService to universal-3-6-pro
- https://github.com/pipecat-ai/pipecat/pull/5530 — Expose AssemblyAI's max_speakers and filter_profanity settings (open since 2026-09-01)

### To consider
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` are connect params with no `Settings` fields. Redaction applies to final turns only, and the spec says `include_partial_turns` defaults to false when `redact_pii` is enabled. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `HOT_UPDATABLE_SETTINGS` holds `agent_context` and `language_codes`; `UpdateConfiguration` also accepts `prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `vad_threshold`, `interruption_delay`, `mode`, `end_of_turn_confidence_threshold` and `session_heartbeat`. Changing any of those today disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision, not a mechanical widening of the set.*
- **Unrecognized server messages** (medium, since 2026-08-31) — `_parse_message` raises `ValueError` for any message type it does not know and `_handle_message` converts that into `push_error`, so `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` all surface as errors. The spec sends `SpeakerRevision` at session end whenever `speaker_labels` is enabled, which the service already exposes, and `speaker_labels_revision_interval_ms` makes it periodic. The path is spec-derived rather than observed. — *Needs a call: `SpeakerRevision` corrects speaker labels on turns already pushed downstream; quietly ignoring it and acting on it are different features.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns`, `session_heartbeat` and `speaker_labels_revision_interval_ms` are documented optional scalars with no `Settings` fields. Unlike `max_speakers`/`filter_profanity` (on the open PR above), each changes session or frame behavior: `inactivity_timeout` drags in the client-side `KeepAlive` message the service never sends. — *Needs a call: `session_heartbeat` and `speaker_labels_revision_interval_ms` only pay off once `Heartbeat` and `SpeakerRevision` are parsed, and `include_partial_turns=false` would starve the pipeline of interim frames, so which subset to expose needs deciding.*
- **Fields AssemblyAI has moved on from** (medium, since 2026-08-31) — `continuous_partials` was in the AsyncAPI spec at the last run and is gone from it entirely now: not a connect parameter, not an `UpdateConfiguration` field, absent from the tuning docs. The service still sends it on every U3 Pro connect and defaults it to `True`. `formatted_finals` and `word_finalization_max_wait_time` are likewise absent and still sent. `language_code` was deprecated in favour of `language_codes` on 2026-07-03 and the field docstring already says to prefer `language_codes`, but there is no `.. deprecated::` marker. Probes still succeed, so the server tolerates all three. — *Needs a call: confirm with AssemblyAI whether `continuous_partials` is still honoured. If it is not, the service's default-on interim cadence is now whatever the server picks — a behavior change to document, not a docstring fix, which is why this is no longer hygiene.*
- **Sync retries nothing** (medium, since 2026-09-14) — AssemblyAI's Sync error-handling page classifies 429 and 503 as transient and tells clients to retry after `Retry-After`, and 500/504 as safe to retry once. `_transcribe` raises `ClientResponseError` on any non-200 and `run_stt` converts it into an `ErrorFrame`, so a rate-limited or capacity-shed turn is simply lost. — *Needs a call: retrying inside `run_stt` holds up a live turn, so the retry budget — and whether to honor `Retry-After` verbatim or cap it — has to be decided before any plumbing.*
- **Sync chunked upload** (medium, since 2026-09-14) — the Sync API exposes `POST /v1/transcribe/live` alongside `/v1/transcribe`: a chunked multipart body whose `config` part precedes the `audio` part, so the upload happens while the speaker is still talking. `AssemblyAISyncSTTService` buffers each VAD segment and posts the complete WAV afterwards. — *Needs a design call: streaming the request body during the segment inverts `SegmentedSTTService`'s buffer-then-post flow, so this is a restructure rather than a pass-through.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **u3-rt-pro in the Inworld example** (low, since 2026-09-14) — `examples/realtime/realtime-inworld-locally-driven-turns.py` sets `stt_model = "assemblyai/u3-rt-pro"`, a model AssemblyAI has dropped from its documented set. The string is Inworld's namespaced model ID inside its realtime session config, not a value Pipecat sends to AssemblyAI, which is why PR #5507 left it. — *Needs a call from the inworld/realtime unit: only Inworld can say which `assemblyai/*` IDs its realtime API accepts.*

The previous run's "universal-3-6-pro is undocumented" item is carried forward as the default-bump gap above — the re-check it asked for is what resolved it this run.
