# AssemblyAI STT — 2026-09-14

Nothing changed on AssemblyAI's side since the last run, and the default stays `universal-3-5-pro`; the new `AssemblyAISyncSTTService` covers the Sync API's whole request schema but adds two gaps of its own (no retry on documented-retryable statuses, no use of the chunked-upload endpoint). No branch this run — every open item needs a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5530 — Expose AssemblyAI's max_speakers and filter_profanity settings (open since last run)

PR #5507 (U3 Pro model strings in examples and docs) merged on 2026-09-03, so that gap is closed.

### To consider
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` are connect params with no `Settings` fields. Redaction applies to final turns only, and the spec says `include_partial_turns` defaults to false when `redact_pii` is enabled. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `HOT_UPDATABLE_SETTINGS` holds `agent_context` and `language_codes`; AssemblyAI's `UpdateConfiguration` also accepts `prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `continuous_partials`, `vad_threshold`, `interruption_delay`, `mode`, `end_of_turn_confidence_threshold` and `session_heartbeat`. Changing any of those today disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision, not a mechanical widening of the set.*
- **Unrecognized server messages** (medium, since 2026-08-31) — `_parse_message` raises `ValueError` for any message type it does not know and `_handle_message` converts that into `push_error`, so `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` all surface as errors. The spec sends `SpeakerRevision` at session end whenever `speaker_labels` is enabled, which the service already exposes; the path is spec-derived rather than observed. — *Needs a call: `SpeakerRevision` corrects speaker labels on turns already pushed downstream; quietly ignoring it and acting on it are different features.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns` and `session_heartbeat` are documented optional scalars with no `Settings` fields. Unlike `max_speakers`/`filter_profanity` (on the open PR above), each changes session or frame behavior: `inactivity_timeout` drags in the client-side `KeepAlive` message the service never sends. — *Needs a call: `session_heartbeat` is only useful once `Heartbeat` is parsed and `include_partial_turns=false` would starve the pipeline of interim frames, so which subset to expose needs deciding.*
- **Sync retries nothing** (medium, since 2026-09-14) — AssemblyAI's Sync error-handling page classifies 429 and 503 as transient and tells clients to retry after `Retry-After` (capacity 503s send `Retry-After: 1`), and 500/504 as safe to retry once. `_transcribe` raises `ClientResponseError` on any non-200 and `run_stt` converts it into an `ErrorFrame`, so a rate-limited or capacity-shed turn is simply lost. — *Needs a call: retrying inside `run_stt` holds up a live turn, so the retry budget — and whether to honor `Retry-After` verbatim or cap it — has to be decided before any plumbing.*
- **Sync chunked upload** (medium, since 2026-09-14) — the Sync API exposes `POST /v1/transcribe/live` alongside `/v1/transcribe`: a chunked multipart body whose `config` part precedes the `audio` part, so the upload and all but the final speech segment are processed while the speaker is still talking. `AssemblyAISyncSTTService` buffers each VAD segment and posts the complete WAV afterwards. — *Needs a design call: streaming the request body during the segment inverts `SegmentedSTTService`'s buffer-then-post flow, so this is a restructure rather than a pass-through.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — `language_code` was deprecated in favour of `language_codes` on 2026-07-03 and the field docstring already says to prefer `language_codes`, but there is no `.. deprecated::` marker. `formatted_finals` and `word_finalization_max_wait_time` do not appear in the current AsyncAPI spec, yet `_build_ws_url` sends `formatted_finals` on every connect (probes still succeed, so the server tolerates it). — *Needs a call: confirm with AssemblyAI whether those two are still honoured before removing or documenting them.*
- **universal-3-6-pro is undocumented** (low, since 2026-09-14) — the model was added to `U3_PRO_MODEL_PREFIXES` and the deprecated `speech_model` `Literal` on 2026-09-02 as "universal-3-5-pro upgraded", and a probe transcribes with it against `/v3/ws`. AssemblyAI's own surfaces do not know it: the AsyncAPI `speech_model` enum lists the three documented models, the model-selection page calls `universal-3-5-pro` the recommended default, and no changelog entry announces a 3.6. — *Needs a call: nothing to change today, but re-check each run — the default bump only becomes proposable once AssemblyAI documents the model and names it the successor.*
- **u3-rt-pro in the Inworld example** (low, since 2026-09-14) — `examples/realtime/realtime-inworld-locally-driven-turns.py` sets `stt_model = "assemblyai/u3-rt-pro"`, a model AssemblyAI has dropped from its documented set. The string is Inworld's namespaced model ID inside its realtime session config, not a value Pipecat sends to AssemblyAI, which is why PR #5507 left it. — *Needs a call from the inworld/realtime unit: only Inworld can say which `assemblyai/*` IDs its realtime API accepts.*
