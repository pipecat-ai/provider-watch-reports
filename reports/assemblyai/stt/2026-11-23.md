# AssemblyAI STT — 2026-11-23

The default is current — AssemblyAI shipped Universal-3.7 on 2026-11-17 and `assemblyai-stt-3-7-realtime-agent` landed as `AssemblyAISTTService`'s default before this run — but two things it brought need a maintainer: our probe makes the new default consistently slower to a final transcript than `universal-3-6-pro` under Pipecat's forced-endpoint mode, and `mode=manual` is now AssemblyAI's purpose-built path for exactly that mode. No branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Retired and retiring streaming model IDs** (high, since 2026-11-23) — the AsyncAPI spec's `speech_model` enum is now exactly `assemblyai-stt-3-7-realtime-agent`, `assemblyai-stt-3-7-realtime` and `universal-3-6-pro`. `U3_PRO_MODEL_PREFIXES` still carries `u3-rt-pro` and `universal-3-5-pro`, and the deprecated `AssemblyAIConnectionParams.speech_model` Literal offers those plus `u3-rt-pro-beta-1`, `universal-streaming-english` and `universal-streaming-multilingual`. Only one has a date: "Universal-3.5 Pro Realtime is retired on February 1, 2027", replacement `assemblyai-stt-3-7-realtime-agent`. The others are "not listed in the current API reference" or "replaced", with no date. — *Needs a call: removing values from a public Literal breaks users pinned to a model that still works today, so the choice is between a deprecation warning now and a removal timed to 2027-02-01.*
- **`mode="manual"`** (medium, since 2026-11-23) — AssemblyAI's turn-detection page now says to connect with `mode=manual` when the client runs external VAD, a semantic turn detector or push-to-talk, send `ForceEndpoint` when the detector fires, and keep `max_turn_silence` as a safety net (10000 ms by default in manual; `min_turn_silence` stops ending turns). That is `vad_force_turn_endpoint=True` described from the provider's side. Pipecat's `mode` Literal lists only `min_latency`/`balanced`/`max_accuracy`, and `_configure_pipecat_turn_mode` pins `min_turn_silence = max_turn_silence = 100`, which would end turns on silence before any `ForceEndpoint` arrived. Manual is `assemblyai-stt-3-7-realtime-agent`-only and falls back to the speaker-label defaults when `speaker_labels` is on. The server accepted `mode=manual` through the class in a probe. — *Needs a call: using manual as intended means Pipecat mode stops pinning `max_turn_silence`, which changes turn-taking on the default path.*
- **The new default finalizes later than the old one** (medium, since 2026-11-23) — five interleaved runs each: `assemblyai-stt-3-7-realtime-agent` median 811 ms from speech end to final transcript (784–930), `universal-3-6-pro` median 555 ms (288–678). AssemblyAI publishes the opposite for this pair — "Final transcript 86 ms after speech ends (vs 172 ms)" and Cekura time-to-final 47 ms against 91 ms — so the likely cause is Pipecat's forced `min_turn_silence = max_turn_silence = 100` rather than the model; the 3.7 model also emitted interim frames where 3.6 emitted none. — *Needs a call: the measurement contradicts the provider's benchmark, so someone has to decide whether to re-tune Pipecat mode (see manual mode above) or raise it with AssemblyAI.*
- **`assemblyai-stt-3-7-realtime` is gated out of its own features** (medium, since 2026-11-23) — the model is live and transcribes through the class, but `is_u3_pro_model()` returns False for it, so `prompt` raises `ValueError` at construction, `language_codes`, `agent_context`, `previous_context_n_turns` and `continuous_partials` are never sent, and `_configure_pipecat_turn_mode` gives it the legacy universal-streaming values (`end_of_turn_confidence_threshold=1.0`, `min_turn_silence=160`, under the model's documented 320 ms floor). AssemblyAI documents it with key terms, a 400-character prompt and context carryover, and recommends it for diarization — which `examples/features/features-speaker-diarization.py` drives with `vad_force_turn_endpoint=False`, a combination this class rejects for it. — *Needs a call: `voice_focus` and `interruption_delay` really don't apply to this model and its exclusion from the family was deliberate, so it needs a per-feature gate, not another prefix.*
- **Server `Error` messages are swallowed** (medium, since 2026-08-31) — the errors page still documents an `Error` frame (`type`, `error_code`, `error`) sent immediately before close, with the close reason always "See Error message for details". `_parse_message` now handles `SpeakerRevision` as well as Begin/Turn/SpeechStarted/Termination, so `Error`, `Heartbeat` and `LLMGatewayResponse` are what remain: each raises `ValueError` and surfaces as `push_error("Unknown error occurred: Unknown message type: ...")`. — *Needs a call: what an `Error` becomes downstream, in particular whether 1008 (authorization or account) should be fatal.*
- **Unrecognized values run silently** (medium, since 2026-10-28) — the spec still says "Always check that `model` matches the `speech_model` you requested — unrecognized or misspelled query parameters are ignored rather than rejected", and `Begin.configuration` now echoes `model`, `mode`, `api_version`, `speaker_labels`, `redact_pii`, `filter_profanity`, `domain` and `voice_focus`. `BeginMessage` parses `id` and `expires_at` only, so the echo is thrown away. — *Needs a call: comparing the echo against the request is new behavior at connect time; decide whether to log a mismatch and at what level.*
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` are connect params with no `Settings` fields, and `include_partial_turns` defaults to false once redaction is on. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `UpdateConfiguration` accepts ten fields (`prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `vad_threshold`, `interruption_delay`, `mode`, `language_codes`, `session_heartbeat`, `agent_context`); `HOT_UPDATABLE_SETTINGS` holds two, so changing any other setting disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns`, `session_heartbeat` and `speaker_labels_revision_interval_ms` have no `Settings` fields. `inactivity_timeout` drags in the client-side `KeepAlive` the service never sends, and the revision interval is documented only for `universal-3-6-pro` now that the 3.7 models label speakers finally at turn end. — *Needs a call: `session_heartbeat` only pays off once `Heartbeat` is parsed, and `include_partial_turns=false` would starve the pipeline of interim frames.*
- **Sync retries nothing** (medium, since 2026-09-14) — the Sync error-handling page classifies 429 and 503 as transient (retry after `Retry-After`, short backoff when absent) and 500/504 as safe to retry once. `_transcribe` raises on any non-200 and `run_stt` converts it into an `ErrorFrame`, so a rate-limited or capacity-shed turn is lost. — *Needs a call: retrying inside `run_stt` holds up a live turn, so the retry budget — and whether to honor `Retry-After` verbatim or cap it — has to be decided.*
- **Sync chunked upload** (medium, since 2026-09-14) — `POST /v1/transcribe/live` takes a chunked multipart body whose `config` part precedes the `audio` part, so the upload happens while the speaker is still talking; `AssemblyAISyncSTTService` buffers each VAD segment and posts the complete WAV afterwards. — *Needs a design call: streaming the request body inverts `SegmentedSTTService`'s buffer-then-post flow.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — the spec's parameter list no longer carries `continuous_partials`, `formatted_finals`, `word_finalization_max_wait_time`, `language_code`, `format_turns` or `end_of_turn_confidence_threshold`. Pipecat still sends the first two plus `format_turns=true` by default, and `end_of_turn_confidence_threshold=1.0` on every non-U3-Pro model; `turn_is_formatted` "always matches `end_of_turn`" now, so the formatting wait in `is_final_turn` never defers anything. The deprecated `language_code` field still has no `.. deprecated::` marker. — *Needs a call: all of these are public `Settings` fields, so retiring them means running a deprecation cycle.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages; it is also AssemblyAI's documented route to real-time translation. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **Streaming webhooks** (low, since 2026-11-09) — `webhook_url` (plus optional `webhook_auth_header_name` / `webhook_auth_header_value`) POSTs the session's finalized turns to an HTTP endpoint after termination. Still on the webhooks page, still absent from the spec's parameter list, and a Pipecat pipeline already holds every turn it would deliver. — *Needs a call: `webhook_auth_header_value` would travel in the websocket URL's query string, so a secret-valued `Settings` field needs sign-off, as does whether post-session delivery is worth exposing at all.*
- **Diarization `speaker_confidence`** (low, since 2026-11-09) — `TurnPayload` and `Word` both carry an experimental `speaker_confidence` (0.0–1.0) when `speaker_labels` is enabled. `TurnMessage` and `Word` do not declare it, so pydantic drops it and it never reaches the `TranscriptionFrame`'s `result`. — *Needs a call: AssemblyAI calls the score experimental, uncalibrated and "not the probability that the label is correct", so confirm whether to surface it before its shape settles.*
- **Stale server defaults and limits** (low, since 2026-11-09) — `previous_context_n_turns` is documented as "the server default, which is 3" where the spec says "currently 5 turns"; the deprecated `AssemblyAIConnectionParams` says `vad_threshold` defaults to 0.3 where the spec says 0.2 (0.5 with `speaker_labels`); and `MAX_AGENT_CONTEXT_CHARS` clips `agent_context` at 1500 characters where the spec allows 1750 per value, so carryover context is truncated earlier than it needs to be. — *Needs a call: AssemblyAI moves server-side defaults without notice, so confirm whether docstrings should quote them at all, and whether the documented 1750 per-value cap supersedes the rolling budget the 1500 clip came from.*
- **u3-rt-pro in the Inworld example** (low, since 2026-09-14) — `examples/realtime/realtime-inworld-locally-driven-turns.py` sets `stt_model = "assemblyai/u3-rt-pro"`. The string is Inworld's namespaced model ID inside its realtime session config, not a value Pipecat sends to AssemblyAI. — *Needs a call from the inworld/realtime unit: only Inworld can say which `assemblyai/*` IDs its realtime API accepts.*

Changes since the last run that close or move items: `SpeakerRevision` is parsed now, so last run's unparsed-message item is down to `Error`, `Heartbeat` and `LLMGatewayResponse`; the retired-model-ID half of the 2026-10-28 "unrecognized values" item is split out as its own item now that `universal-3-5-pro` has a date. `AssemblyAISyncSTTService` keeps `universal-3-6-pro`, which is still the Sync API's recommended `X-AAI-Model` value — Sync has no 3.7 model. AssemblyAI's own Pipecat page recommends `vad_force_turn_endpoint=False` with `min_turn_silence=128` / `max_turn_silence=640` for most voice agents, against Pipecat's `True` default; that is a documentation difference, not a code gap, but it is worth knowing when the latency item above is picked up.
