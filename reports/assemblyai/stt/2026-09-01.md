# AssemblyAI STT — 2026-09-01

AssemblyAI shipped nothing new for streaming since the last run — `universal-3-5-pro` is still the recommended model and the code's default. PR #5507 is still open, and a new branch takes the two clean pass-throughs (`max_speakers`, `filter_profanity`) out of the pending connect-param list.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5507 — Name AssemblyAI's current U3 Pro streaming model in examples and docs (open since last run)
- https://github.com/pipecat-ai/pipecat/pull/5530 — Expose AssemblyAI's max_speakers and filter_profanity settings

### To consider
- **Streaming PII redaction** (medium, since 2026-08-31) — `redact_pii`, `redact_pii_policies` and `redact_pii_sub` shipped on 2026-05-15 for every streaming model and have no `Settings` fields. Redaction applies to final turns only, and the spec says `include_partial_turns` defaults to false when `redact_pii` is enabled. — *Needs a call: with redaction enabled the service stops receiving partials, so exposing it means deciding what happens to `InterimTranscriptionFrame` output.*
- **Hot-updatable settings** (medium, since 2026-08-31) — `HOT_UPDATABLE_SETTINGS` holds `agent_context` and `language_codes`; AssemblyAI's `UpdateConfiguration` also accepts `prompt`, `keyterms_prompt`, `min_turn_silence`, `max_turn_silence`, `continuous_partials`, `vad_threshold`, `interruption_delay`, `mode`, `end_of_turn_confidence_threshold` and `session_heartbeat`. Changing any of those today disconnects and reconnects mid-call. — *Needs a call: `_configure_pipecat_turn_mode` rewrites `min_turn_silence`/`max_turn_silence` at construction, so which fields are safe to hot-update is a design decision, not a mechanical widening of the set.*
- **Unrecognized server messages** (medium, since 2026-08-31) — `_parse_message` raises `ValueError` for any message type it does not know and `_handle_message` converts that into `push_error`, so `SpeakerRevision`, `Heartbeat` and `LLMGatewayResponse` all surface as errors. The spec sends `SpeakerRevision` at session end whenever `speaker_labels` is enabled, which the service already exposes; the path is spec-derived rather than observed. — *Needs a call: `SpeakerRevision` corrects speaker labels on turns already pushed downstream; quietly ignoring it and acting on it are different features.*
- **Remaining scalar connect params** (medium, since 2026-08-31) — `inactivity_timeout`, `include_partial_turns` and `session_heartbeat` are documented optional scalars with no `Settings` fields. Unlike `max_speakers`/`filter_profanity` (on the branch above), each changes session or frame behavior: `inactivity_timeout` drags in the client-side `KeepAlive` message the service never sends. — *Needs a call: `session_heartbeat` is only useful once `Heartbeat` is parsed and `include_partial_turns=false` would starve the pipeline of interim frames, so which subset to expose needs deciding.*
- **LLM Gateway on streaming turns** (low, since 2026-08-31) — the `llm_gateway` connect param runs a chat-completions config over each finalized turn and returns `LLMGatewayResponse` messages. — *Needs a product call: an LLM inside the STT service overlaps with the pipeline's own LLM stage.*
- **Fields AssemblyAI has moved on from** (low, since 2026-08-31) — `language_code` was deprecated in favour of `language_codes` on 2026-07-03 and the field docstring already says to prefer `language_codes`, but there is no `.. deprecated::` marker. `formatted_finals` and `word_finalization_max_wait_time` do not appear in the current AsyncAPI spec, yet `_build_ws_url` sends `formatted_finals` on every connect (probes still succeed, so the server tolerates it). — *Needs a call: confirm with AssemblyAI whether those two are still honoured before removing or documenting them.*
