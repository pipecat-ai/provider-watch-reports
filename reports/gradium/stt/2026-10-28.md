# Gradium STT — 2026-10-28

Nothing to act on: `default` remains the model to ship, Gradium's October
release notes are entirely TTS, voices, Studio and compliance, and
`src/pipecat/services/gradium/stt.py` has not changed since the last run. The

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Keyword boosting** (medium, since 2026-09-01) — `json_config.keywords` is not reachable from `Settings`; a `keywords` field passed into the setup message would cover it. `{"words": [...], "boost": 3}`, boost valid from -6 to 6 and applied in log-probability space, 3 recommended and 4 for rare vocabulary, much above 4–5 risking the decoder repeating a keyword, negative values de-boosting. Up to 500 entries, each case/accent variant counting separately, multi-word names split into space-free tokens. Still no saved-dictionary or `keyword_boost_id` equivalent, so the words go inline on every connection. — *Needs a call: the field shape, raw dict vs a typed model carrying the documented boost range; probe blocked on GRADIUM_API_KEY.*
- **Translating model** (medium, since 2026-09-01) — `model="stt-translate"` transcribes into another language chosen with `target_language`, which `Settings` has no field for, and our `language` handling assumes it names the audio's language. Translation output is en/fr/de/es/pt only (no `any`). — *Needs a call: whether translated transcription belongs in an STT service, given the emitted `TranscriptionFrame` would carry the output language, not the audio's.*
- **Required language** (medium, since 2026-09-01) — `json_config.language` is mandatory ("Requests without it are rejected"); `Settings(language=None)` omits it and the setup is rejected. — *Needs a call: fall back to `"any"` or reject at construction time.*
- **`temp` and `padding_bonus`** (low, since 2026-09-01) — documented tuning knobs with no `Settings` fields (`padding_bonus` -4.0 to 4.0, negative pushing text out sooner; temperature listed as `temp` 0.0–1.5 on the settings guide and as `temperature` up to 1.0 defaulting to 0 on the endpoint reference). — *Needs a call: none beyond probe verification (blocked on GRADIUM_API_KEY) and picking which documented range and key name holds.*
- **Delay default, allowed values and flush_id type** (low, since 2026-09-01) — we default `delay_in_frames` to 12 where Gradium documents 10. A fourth provider page joined the disagreement this run: our docstring's ten values match the endpoint reference, the turn-taking recipe lists eleven (adding 32), the settings guide describes any int 0–80, and the WebSocket STT guide now says 7–55 with 16 suggested for stable interactive output. `_send_flush` sends `flush_id` as a string where the reference types it an integer. — *Needs a call: whether to move our default to Gradium's 10, and confirmation that a string flush_id stays accepted.*

Nothing from the 2026-10-12 report is unaccounted for: it carried no PRs, and
all five of its gaps still hold against unchanged code.
