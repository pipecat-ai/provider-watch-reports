# Gradium TTS — 2026-09-14

No action needed on models: we always take Gradium's `default` alias and the model behind it is still the one promoted on 2026-08-31. The six known gaps all stand; the only movement is Gradium raising the websocket session cap from 300 s to 3000 s, which takes the pressure off the reconnect item. No branch, because the one PR-shaped fix (`Settings.model` pass-through) needs a live probe and no API key was available.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`Settings.model` is dropped** (medium, since 2026-09-01) — `_build_setup_msg` builds `type`/`output_format`/`voice_id`/`close_ws_on_eos`/`client_req_id` and no `model_name`, so a user who sets `Settings(model="gradium-tts-beta")` gets the default model and no error. Our own default value (`default`) matches the server default, so adding the key is behavior-preserving. — *Needs a call: only in the sense that the fix needs a live probe first; GRADIUM_API_KEY was unset this run too.*
- **Voice tuning is constructor-only** (medium, since 2026-09-01) — `temp`, `cfg_coef`, `padding_bonus` and `rewrite_rules` live in Gradium's `json_config`, which we take as a JSON string at construction time and never as Settings; the deprecated `InputParams.temp` has no replacement field. Gradium's new Voice Design flow (2026-09-08) tells users to tune `temp`/`cfg_coef` per designed voice, so runtime access matters more than it did. — *Needs a call: typed per-knob Settings fields, or a single `json_config` dict field superseding the constructor argument.*
- **`pronunciation_id` not exposed** (medium, since 2026-09-01) — a session-wide pronunciation dictionary is a top-level setup field, and websocket-only. A Settings field would pass through in `_build_setup_msg`. — *Needs a call: verifying it needs a real dictionary created on the account, which a probe cannot do.*
- **Stale `_setup_context_ids` after `run_tts`'s inline reconnect** (low, since 2026-09-01) — correcting last run's reading: the `WebsocketService` reconnect path does clear the set, since `_reconnect_websocket` calls `_disconnect_websocket` first. Only `run_tts`'s own `state is State.CLOSED` branch reopens the socket via `_connect()` without clearing, so a context that was already set up on the dead socket gets `text` on a socket that never received its `setup`. With the cap now at 3000 s this needs a mid-context socket drop to hit. — *Needs a call: whether to handle it, or just clear the set in `_connect`.*
- **`Settings.language` is inert** (low, since 2026-09-01) — Gradium's TTS setup has no language field; language comes from the voice, and normalization from `rewrite_rules`. — *Needs a call: map it onto `rewrite_rules`, or document it as unsupported here.*
- **Telephony output formats unused** (low, since 2026-09-01) — always `pcm` at 48 kHz, though `ulaw_8000`, `alaw_8000`, lower PCM rates, `wav` and `opus` are available. — *Needs a call: whether server-side rate selection is worth diverging from the fixed 48 kHz the docs promise.*

Not a gap: Voice Design (2026-09-08) produces ordinary `voice_id` values through `/voices/from-embedding` that "work like any other `voice_id`", so `Settings.voice` already carries them. Our default voice `_6Aslh2DxfmnRLmP` (Russell) is still a listed flagship voice, and `examples/voice/voice-gradium.py` pins the same id.
