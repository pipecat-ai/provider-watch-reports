# Gradium TTS — 2026-09-01

Nothing urgent: Gradium's newest model became the `default` alias on 2026-08-31 and we always take the server default, so we are on it already — but `Settings.model` and `Settings.language` are both silently dropped, and the `json_config` and `pronunciation_id` knobs are out of reach. No branch: no API key was available to probe with.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`Settings.model` is dropped** (medium, since 2026-09-01) — `_build_setup_msg` builds `type`/`output_format`/`voice_id`/`close_ws_on_eos`/`client_req_id` and no `model_name`, so a user who sets `Settings(model="gradium-tts-beta")` gets the default model and no error. Our own default value (`default`) matches the server default, so adding the key is behavior-preserving. — *Needs a call: only in the sense that the fix needs a live probe first; GRADIUM_API_KEY was not set this run.*
- **Voice tuning is constructor-only** (medium, since 2026-09-01) — `temp`, `cfg_coef` (voice similarity), `padding_bonus` (speed) and `rewrite_rules` live in Gradium's `json_config`, which we take as a JSON string at construction time and never as Settings; the deprecated `InputParams.temp` has no replacement field. — *Needs a call: typed per-knob Settings fields, or a single `json_config` dict field superseding the constructor argument.*
- **`pronunciation_id` not exposed** (medium, since 2026-09-01) — a session-wide pronunciation dictionary is a top-level setup field; a Settings field would pass through in `_build_setup_msg`. — *Needs a call: verifying it needs a real dictionary created on the account, which a probe cannot do.*
- **300 s session cap vs. a call-long socket** (medium, since 2026-09-01) — Gradium caps a session at 300 seconds and tells clients to reconnect with a fresh `setup`; our reconnect paths do not clear `_setup_context_ids`, so a context carried across a reconnect would be sent `text` on a socket that never received its `setup`. — *Needs a call: confirm the cap's behavior on a live idle socket before changing reconnect handling.*
- **`Settings.language` is inert** (low, since 2026-09-01) — Gradium's TTS setup has no language field; language comes from the voice, and normalization from `rewrite_rules`. — *Needs a call: map it onto `rewrite_rules`, or document it as unsupported here.*
- **Telephony output formats unused** (low, since 2026-09-01) — always `pcm` at 48 kHz, though `ulaw_8000`, `alaw_8000` and lower PCM rates are available. — *Needs a call: whether server-side rate selection is worth diverging from the fixed 48 kHz the docs promise.*
