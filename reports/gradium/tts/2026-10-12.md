# Gradium TTS — 2026-10-12

Nothing to do on models: Gradium's 2026-09-30 model is served by the `default` alias, which is what we ship, so we picked the new model up without a change. The six known gaps stand; the only substantive movement is `cfg_coef` being deprecated for TTS, which shrinks the tuning item. No branch — the one PR-shaped fix (`Settings.model` pass-through) still needs a live probe and no API key was available.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`Settings.model` is dropped** (medium, since 2026-09-01) — `_build_setup_msg` builds `type`/`output_format`/`voice_id`/`close_ws_on_eos`/`client_req_id` and no `model_name`, so a user who sets `Settings(model="gradium-tts-beta")` silently gets the server default and no error. Our default value (`default`) matches the server default, so adding the key is behavior-preserving. — *Needs a call: only in the sense that the fix needs a live probe first; GRADIUM_API_KEY was unset this run too.*
- **Voice tuning is constructor-only** (medium, since 2026-09-01) — `temp`, `padding_bonus` and `rewrite_rules` live in Gradium's `json_config`, which we take as a JSON string at construction time and never as Settings; the deprecated `InputParams.temp` has no replacement field. `cfg_coef` is no longer part of this: the 2026-09-30 model ignores it and the docs tell users to remove it from TTS requests. — *Needs a call: typed per-knob Settings fields, or a single `json_config` dict field superseding the constructor argument.*
- **`pronunciation_id` not exposed** (medium, since 2026-09-01) — a session-wide pronunciation dictionary is a top-level setup field, and websocket-only. A Settings field would pass through in `_build_setup_msg`. — *Needs a call: verifying it needs a real dictionary created on the account, which a probe cannot do.*
- **Stale `_setup_context_ids` after `run_tts`'s inline reconnect** (low, since 2026-09-01) — only `run_tts`'s own `state is State.CLOSED` branch reopens the socket via `_connect()` without clearing the set, so a context already set up on the dead socket gets `text` on a socket that never received its `setup`. — *Needs a call: whether to handle it, or just clear the set in `_connect`.*
- **`Settings.language` is inert** (low, since 2026-09-01) — Gradium's TTS setup has no language field; language comes from the voice, normalization from `rewrite_rules`. — *Needs a call: map it onto `rewrite_rules`, or document it as unsupported here.*
- **Telephony output formats unused** (low, since 2026-09-01) — always `pcm` at 48 kHz, though `ulaw_8000`, `alaw_8000`, lower PCM rates, `wav` and `opus` are available. — *Needs a call: whether server-side rate selection is worth diverging from the fixed 48 kHz the docs promise.*

Not gaps: Voice Localization (2026-10-08) and Voice Enhance (GA 2026-10-08) are REST voice-management features whose output is an ordinary `voice_id`, which `Settings.voice` already carries; the `prompt` field deprecated on the candidate-listing response belongs to those endpoints, which this service never calls. Our default voice `_6Aslh2DxfmnRLmP` (Russell) is still a listed flagship voice, and `examples/voice/voice-gradium.py` pins the same id. The websocket setup/text/end_of_stream schema is unchanged.
