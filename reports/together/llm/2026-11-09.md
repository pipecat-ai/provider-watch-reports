# Together LLM — 2026-11-09

`zai-org/GLM-5.2` stays the default and nothing qualifies for a branch; the open question is still
whether the service should send GLM a reasoning-off default, and this run's numbers make it 10455 ms
against 268 ms.

## What's new for Pipecat

### PRs
Nothing. #6437 (`reasoning_effort`) merged on 2026-10-28, so `TogetherLLMSettings` now carries both
of Together's reasoning controls.

### To consider
- **Reasoning on by default** (high, since 2026-09-01) — re-measured with five repeats and worse
  than last run: as shipped, `zai-org/GLM-5.2` thinks 10227 ms before its first answer token on a
  plain scheduling request (TTFAT 10455 ms, spread 4157–19414 ms) and 2859 ms on a one-sentence
  question (TTFAT 3907 ms), against 268 ms with `reasoning={"enabled": false}`. That is dead air on
  every turn. `LLMService._apply_thinking_default` is the hook the Anthropic, Google, OpenAI
  Responses and Perplexity services use for exactly this, and `DeepSeekLLMService` ships `thinking`
  disabled outright. Both fields such a table would set are merged now, so it would read
  `zai-org/GLM-5.2` → `reasoning={"enabled": False}` and `zai-org/GLM-5.3` →
  `reasoning_effort="low"`. Also worth the decision: aiewf-eval's glm-5.2 row was measured with
  reasoning `none`, not the configuration Pipecat ships. — *Needs a call: whether
  `TogetherLLMService` should send GLM its reasoning-off default, as `DeepSeekLLMService` does for
  its V4 models and as #5446 did for Sonnet 5 and later.*
- **GLM-5.3 as the default** (low, since 2026-09-01) — the benchmark criterion holds (glm-5.3 low
  reasoning 97.7% / 2376 ms against glm-5.2 none 95.8% / 938 ms, leaderboard unchanged since the
  October judge refresh) and Together names GLM-5.3 and GLM-5.3 Flash as its only GLMs. Latency as
  shipped is split this run: GLM-5.3 is faster on the trivial prompt (TTFAT 1546 ms against 3907 ms,
  medians of 5 — reversing last run's reading) and clearly slower on the scheduling one (13510 ms
  against 10455 ms). Both models' reasoning passes are long and variable at Together's defaults, so
  the comparison only settles once the service sends a reasoning default: with
  `reasoning_effort="low"` GLM-5.3 answers the scheduling prompt in 910 ms. — *Needs a call: whether
  a GLM-5.3 default is worth having only once the service sends a reasoning default with it.*
- **Together's sampling extensions** (low, since 2026-09-28) — `top_k`, `min_p` and
  `repetition_penalty` are documented on the endpoint but are not OpenAI SDK keyword arguments, so
  `BaseOpenAILLMService`'s `params.update(self._settings.extra)` splat rejects them and users must
  nest them under `extra={"extra_body": {...}}`. — *Needs a call: whether these knobs are worth
  first-class fields for voice pipelines, or the `extra_body` idiom is enough.*
- **The `.xyz` base URL** (low, since 2026-10-28) — the service defaults to
  `https://api.together.xyz/v1`, while Together's OpenAI-compatibility page documents
  `https://api.together.ai/v1` and mentions no `.xyz` host. Nothing is deprecated and every probe
  this run went through the `.xyz` default, so this is hygiene against an undocumented host. —
  *Needs a call: whether to move a working default host, given users may have the current one in
  allowlists.*
- **Kimi K3.1 Pro** (low, since 2026-11-09) — Together's recommended-models page now leads with
  `moonshotai/Kimi-K3.1-Pro` for chat and reasoning, moving GLM-5.3 to an alternative. It is
  serverless since 2026-11-05 and works through our class (TTFAT 1767 ms, median of 3, trivial
  prompt, reasoning on by default). aiewf-eval has not benchmarked it — the leaderboard's newest
  Kimi row is kimi-k2.6 — so the third bump criterion cannot be checked yet. — *Needs a call:
  nothing yet; re-read the leaderboard next run.*
