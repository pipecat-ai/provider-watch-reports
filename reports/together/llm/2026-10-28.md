# Together LLM — 2026-10-28

`zai-org/GLM-5.2` stays the default; the branch adds `reasoning_effort`, which is the only reasoning
control `zai-org/GLM-5.3` honors, and the two-month-old question of whether the default should ship
with reasoning off is still open.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6437 — Add Together's reasoning_effort to TogetherLLMSettings

`TogetherLLMSettings.reasoning` turned out not to reach every model. On `zai-org/GLM-5.3`,
`reasoning={"enabled": false}` is ignored: the model still thought for 10459 ms before its first
answer token (TTFAT 11000 ms, median of 5). Together documents `reasoning_effort` ("low", "medium",
"high") beside `reasoning` on the same endpoint, and it does work — GLM-5.3 answered the same prompt
in 653 ms (median of 3) from the branch. The field follows `GrokLLMSettings.reasoning_effort`:
optional, unset by default, passed straight through with `params.setdefault`.

### To consider
- **Reasoning on by default** (high, since 2026-09-01) — unchanged and re-measured with five
  repeats: as shipped, `zai-org/GLM-5.2` thinks 2782 ms before its first answer token on a plain
  scheduling request (TTFAT 3056 ms) and 4474 ms on a one-sentence weather question (TTFAT 4771 ms),
  against 244 ms with `reasoning={"enabled": false}`. That is dead air on every turn. The framework
  already has the hook: `LLMService._apply_thinking_default` sends a model its lowest thinking
  setting unless `use_provider_thinking_default` is set, and the Anthropic, Google, OpenAI Responses
  and Perplexity services use it; `DeepSeekLLMService` goes further and ships `thinking` disabled.
  With the branch's field, a Together table would read `zai-org/GLM-5.2` →
  `reasoning={"enabled": False}` and `zai-org/GLM-5.3` → `reasoning_effort="low"`. Also worth the
  decision: aiewf-eval's glm-5.2 row was measured with reasoning `none`, not the configuration
  Pipecat ships. — *Needs a call: whether `TogetherLLMService` should send GLM its reasoning-off
  default, as `DeepSeekLLMService` does for its V4 models and as #5446 did for Sonnet 5 and later.*
- **GLM-5.3 as the default** (low, since 2026-09-01) — the benchmark blocker is gone. The Oct 17-19
  judge refresh rescored both GLM rows and reversed their order: glm-5.3 (low reasoning) 97.7% /
  2376 ms at rank 13, glm-5.2 (none) 95.8% / 938 ms at rank 22. Together's recommended-models page
  now names GLM-5.3 and GLM-5.3 Flash and names no other GLM. What blocks the bump is latency at
  the settings Pipecat ships: GLM-5.3 reasons longer than GLM-5.2 on every prompt probed (TTFAT
  6893 ms against 4771 ms trivial, 12674 ms against 3056 ms scheduling, medians of 5). Last run's
  trivial-prompt reading had GLM-5.3 ahead (3907 ms against 4988 ms, medians of 3); this run's five
  repeats reverse it, and the gap on the harder prompt is not close. GLM-5.3 only becomes fast
  through `reasoning_effort="low"` (653 ms), which is the item above. — *Needs a call: whether a
  GLM-5.3 default is worth having only once the service sends a reasoning default with it.*
- **Together's sampling extensions** (low, since 2026-09-28) — `top_k`, `min_p` and
  `repetition_penalty` are documented on the endpoint but are not OpenAI SDK keyword arguments, so
  `BaseOpenAILLMService`'s `params.update(self._settings.extra)` splat rejects them and users must
  nest them under `extra={"extra_body": {...}}`. — *Needs a call: whether these knobs are worth
  first-class fields for voice pipelines, or the `extra_body` idiom is enough.*
- **The `.xyz` base URL** (low, since 2026-10-28) — the service defaults to
  `https://api.together.xyz/v1`, while Together's OpenAI-compatibility page documents
  `https://api.together.ai/v1` and mentions no `.xyz` host anywhere. Nothing is deprecated and both
  answered a probe through our class, so this is hygiene against a host that is no longer
  documented. — *Needs a call: whether to move a working default host, given users may have the
  current one in allowlists.*
