# Together LLM — 2026-11-23

`zai-org/GLM-5.2` stays the default and nothing qualifies for a branch; the open question is still
whether the service should send GLM a reasoning-off default.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Reasoning on by default** (high, since 2026-09-01) — as shipped, `zai-org/GLM-5.2` thinks
  2370 ms before its first answer token on a plain scheduling request (TTFAT 2626 ms, median of 3,
  spread 2039–6832 ms), against 186 ms with `reasoning={"enabled": false}`. Milder than the
  10455 ms this run's predecessor measured, but the same dead air on every turn, and the spread
  shows how variable Together's reasoning pass is.
  `LLMService._apply_thinking_default` is the hook the Anthropic, Google, OpenAI Responses and
  Perplexity services use for exactly this, and `DeepSeekLLMService` ships `thinking` disabled
  outright. Both fields such a table would set already ship, so it would read `zai-org/GLM-5.2` →
  `reasoning={"enabled": False}` and `zai-org/GLM-5.3` → `reasoning_effort="low"`. Also worth the
  decision: aiewf-eval's glm-5.2 row was measured with reasoning `none`, not the configuration
  Pipecat ships. — *Needs a call: whether `TogetherLLMService` should send GLM its reasoning-off
  default, as `DeepSeekLLMService` does for its V4 models and as #5446 did for Sonnet 5 and later.*
- **GLM-5.3 as the default** (low, since 2026-09-01) — the benchmark criterion holds (glm-5.3 low
  reasoning 97.7% / 2376 ms against glm-5.2 none 95.8% / 938 ms, leaderboard unchanged since the
  October refresh) and Together names GLM-5.3 and GLM-5.3 Flash as its only GLMs. Latency at the
  settings Pipecat ships still argues the other way: on the scheduling prompt GLM-5.3 took TTFAT
  10890 ms (median of 3, thinking 10460 ms) against GLM-5.2's 2626 ms. The comparison only settles
  once the service sends a reasoning default — last run `reasoning_effort="low"` brought GLM-5.3 to
  910 ms on the same prompt. — *Needs a call: whether a GLM-5.3 default is worth having only once
  the service sends a reasoning default with it.*
- **Together's sampling extensions** (low, since 2026-09-28) — `top_k`, `min_p` and
  `repetition_penalty` are documented on the endpoint but are not OpenAI SDK keyword arguments, so
  `BaseOpenAILLMService`'s `params.update(self._settings.extra)` splat rejects them and users must
  nest them under `extra={"extra_body": {...}}`. — *Needs a call: whether these knobs are worth
  first-class fields for voice pipelines, or the `extra_body` idiom is enough.*
- **The `.xyz` base URL** (low, since 2026-10-28) — the service defaults to
  `https://api.together.xyz/v1`, while Together's OpenAI-compatibility page documents
  `https://api.together.ai/v1` and mentions no `.xyz` host. Nothing is deprecated and every probe
  this run went through the `.xyz` default, so this is hygiene against an undocumented host. —
  *Needs a call: whether to move a working default host, given users may have the current one in
  allowlists.*
- **Kimi K3.1 Pro** (low, since 2026-11-09) — Together's recommended-models page still leads with
  `moonshotai/Kimi-K3.1-Pro` for chat and reasoning. aiewf-eval has not benchmarked it — the
  leaderboard's newest Kimi row is kimi-k2.6 and the file is unchanged since October — so the third
  bump criterion still cannot be checked. — *Needs a call: nothing yet; re-read the leaderboard next
  run.*
