# Together LLM — 2026-10-12

`zai-org/GLM-5.2` is still Together's current, non-deprecated serverless GLM and stays the default;
nothing needs a branch this run, and the one open call is whether that default should ship with
reasoning turned off.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Reasoning on by default** (high, since 2026-09-01) — #5939 merged, so `reasoning` is now a
  `TogetherLLMSettings` field and a probe confirms it works on main. What it did not decide is the
  default. Out of the box `zai-org/GLM-5.2` thought for 2808 ms before its first answer token on a
  plain scheduling request (TTFAT 3009 ms, median of 3) and for 4721 ms on a one-sentence weather
  question (TTFAT 4988 ms) — dead air on every turn of a voice pipeline. The same scheduling prompt
  with `reasoning={"enabled": false}` answered in 191 ms. Worth noting for the decision:
  aiewf-eval's 99.7% / 936 ms row for glm-5.2 was measured with reasoning `none`, which is not the
  configuration Pipecat ships. — *Needs a call: whether `TogetherLLMService` should default
  `reasoning` to off, as `DeepSeekLLMService` does for its V4 models and as #5446 did for Sonnet 5
  and later.*
- **GLM-5.3 as the default** (low, since 2026-09-01) — aiewf-eval's `aiwf_medium_context` is
  unchanged: glm-5.3 (low reasoning) 98.7% / 2376 ms against glm-5.2 (none) 99.7% / 936 ms, with
  still no GLM-5.3-Flash row. The latency case has weakened too: last run GLM-5.3 answered a
  trivial prompt in 344 ms against GLM-5.2's 1515 ms, and this run both reason by default and land
  within the same seconds-long band (3907 ms against 4988 ms, medians of 3). — *Needs a call: a
  released model's row is final, so GLM-5.3 only becomes the Together default if a maintainer
  overrides the benchmark condition (#5447) or the leaderboard gains a better row.*
- **Together's sampling extensions** (low, since 2026-09-28) — `top_k`, `min_p` and
  `repetition_penalty` are documented on the endpoint but are not OpenAI SDK keyword arguments, so
  `BaseOpenAILLMService`'s `params.update(self._settings.extra)` splat rejects them and users must
  nest them under `extra={"extra_body": {...}}`. The merged `reasoning` field is the shape they
  would follow. — *Needs a call: whether these knobs are worth first-class fields for voice
  pipelines, or the `extra_body` idiom is enough.*

The previous report's gap "Together's documented `reasoning` toggle is not reachable from Settings"
is closed: #5939 merged on 2026-09-28 and `TogetherLLMSettings.reasoning` is on main.
