# Together TTS — 2026-10-12

The unit is healthy again: PRs 5581 and 5940 merged on 2026-09-28, and `main` now synthesizes audio end to end. One branch is ready, adding Together's `extra_params`.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6145 — Pass Together TTS extra_params through to the session

Three gaps closed since last run. PR 5581 (merged 2026-09-28) sends the `language` query parameter, and `9cbb31394` resolves it through a verified code map; PR 5940 (merged 2026-09-28) escapes the voice so Kokoro's blended names reach the server. The odd-length audio crash was fixed in the shared layer rather than in this service: `b70dfa3be` holds a split sample back per audio context in `TTSService` and makes `detect_speech_onset` ignore a trailing partial sample (`src/pipecat/audio/utils.py:388`), after which `567e03a3e` removed Together's own alignment code. That also closes the "shared onset scanner tolerance" item carried since 2026-09-01 — any provider that chunks PCM mid-sample is now covered.

The branch is the `extra_params` item, open since 2026-09-01. `TogetherTTSSettings` gains `extra_params: dict[str, Any] | None`, and `_connect_websocket` puts it in the `tts_session.updated` session next to the voice. The opaque dict is how Together documents the field — model-specific, with `pronunciation_dict` as the one documented key today — so there is nothing to validate or convert on our side, and behavior is unchanged unless a user sets it.

`Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice` is new in the catalogue (dedicated-endpoint availability announced 2026-10-01; the TTS docs price it serverless at $4/1M characters, nine preset voices, ten languages). It needs no Pipecat change: the service has no model allowlist, and a probe with `voice=vivian` streamed audio from the serverless WebSocket endpoint — even though the WebSocket reference still names only `hexgrad/Kokoro-82M` and `cartesia/sonic-english` under `model`.

### To consider
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Reconnect on every settings change** (low, since 2026-10-12) — `_update_settings` disconnects and reconnects whenever anything changes, but Together applies `voice`, `model` and `language` in-session through `tts_session.updated`, so a mid-call voice switch pays a full reconnect (~0.7 s on this run's cold connect) for what is one message. — *Needs a call: special-case the in-session fields, or keep one reconnect path for every setting.*

Default model: `hexgrad/Kokoro-82M` stays. It is still the WebSocket endpoint's documented default, Together designates no successor, and the deprecations page lists no audio model at all.

The REST-only parameters (`alignment` word timestamps, `segment`, `response_format`, `sample_rate`, `bit_rate`) are still absent from the WebSocket endpoint's surface, so they remain out of scope for this class.
