# Together TTS — 2026-09-01

`TogetherTTSService` currently produces no audio at all when pipeline metrics are enabled, and silently drops the `language` setting; the branch fixes both, verified against the live WebSocket API.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5581 — Fix TogetherTTSService's odd-length audio frames and send its language setting

Commit 1 (sample alignment): Together's `conversation.item.audio_output.delta` payloads are not sample-aligned — one probe saw a first delta of 65529 bytes — and the service passed the decoded bytes straight into a `TTSAudioRawFrame`. The TTFA speech-onset scan reads that frame as `int16` and raises `buffer size must be a multiple of element size`, which kills `TogetherTTSService#0::_audio_context_task_handler`: no audio and no `TTSStoppedFrame` reach the pipeline. The service now holds a trailing odd byte until its sample completes.

Commit 2 (language): `_build_websocket_url` sent only `model`, `voice` and `max_partial_length`, and `language_to_service_language` was dead code. Together documents `language` as a connect-time query parameter (ISO 639-1 plus lowercase locale codes), and docs.pipecat.ai advertises the setting, so the setting is now sent, lowercased.

### To consider
- **`extra_params` / pronunciation dictionary** (medium, since 2026-09-01) — `tts_session.updated` accepts `session.extra_params` (documented example: `pronunciation_dict` entries of the form `"omg/oh my god"`); the service only ever sends `session.voice`, so users cannot correct pronunciation. — *Needs a call: `extra_params` is model-specific, so it is either an opaque dict field or a typed `pronunciation_dict` list.*
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Shared onset scanner tolerance** (low, since 2026-09-01) — `detect_speech_onset` (`src/pipecat/audio/utils.py:370`) raises on an odd-length buffer, so the same crash awaits any other service that emits a half-sample frame; the branch only fixes Together. — *Needs a call: harden the shared scanner, or keep alignment a service responsibility (as `TTSService.stream_frames_from_iterator` already assumes).*

Default model: `hexgrad/Kokoro-82M` stays. It is still the WebSocket endpoint's own documented default, and Together designates no successor — the newer TTS models in the catalogue (`minimax/speech-2.8-turbo`, `rime-labs/rime-arcana-v3`, `cartesia/sonic-3.5`) are additions, and the WebSocket reference documents only Kokoro and `cartesia/sonic-english`. The class has no model allowlist, so users can pass any of them.

## Verification

| model             | class              | ok | latency                          | note |
| ----------------- | ------------------ | -- | -------------------------------- | ---- |
| hexgrad/Kokoro-82M | TogetherTTSService (main) | ❌ | TTFB 280 ms, then no audio | audio-context task died: `buffer size must be a multiple of element size`; instrumented run shows the offending buffer at 65529 bytes |
| hexgrad/Kokoro-82M | TogetherTTSService (branch) | ✅ | TTFB 303 ms, TTFA 370 ms | audio flows; 67 ms leading silence |
| hexgrad/Kokoro-82M, `language=fr`, `voice=ff_siwis` | TogetherTTSService (branch) | ✅ | TTFB 350 ms, TTFA 399 ms | connect URL carries `&language=fr`; French audio returned |

Both branch probes then sit until the harness timeout: `probe.py` has no output transport, so the `BotStoppedSpeakingFrame` that lifts this class's `pause_frame_processing=True` never arrives and the `EndFrame` cannot drain. That is a harness limit, not a provider issue — latencies above are the service's own metrics, read from the probe's debug output.

Ad-hoc WebSocket checks (`.pw-scratch/together_delta_sizes.py`, `.pw-scratch/together_language_param.py`, one call each) confirmed delta sizes vary in parity and that `language=fr` is accepted with audio returned.
