# Together TTS — 2026-10-28

Nothing to do: the service is current, and the two open items are the same low-priority ones as last run.

## What's new for Pipecat

### PRs
Nothing.

PR 6145 merged on 2026-10-12, so `TogetherTTSSettings.extra_params` is on `main` and that gap — open since 2026-09-01 — is closed. A probe with `extra_params={"pronunciation_dict": [...]}` synthesizes cleanly against the live session.

Together shipped no TTS change this cycle. The catalogue's TTS set is byte-identical to last run's 16 models (the overall catalogue grew from 265 to 269, all text/image/video/STT). The changelog's only audio entries since 2026-10-12 are the 2026-10-13 speech-to-text endpoints (`nvidia/parakeet-tdt-0.6b-v3`, `openai/whisper-large-v3`), which belong to the STT unit. The WebSocket reference is unchanged — same four query parameters, same client and server events, same fixed 24 kHz s16le mono, Kokoro still its documented default. The deprecations page still lists no audio model; the newest removals (2026-10-22, `meta-llama/Llama-3.3-70B-Instruct-Turbo` and `deepseek-ai/DeepSeek-V4-Flash-0731`) are text models.

Default model: `hexgrad/Kokoro-82M` stays. Together designates no successor and nothing schedules it for removal.

The 2026-10-22 Together Python SDK 3.0 release carries breaking changes, but it does not reach this unit: the `together` extra is empty and the class talks to the WebSocket endpoint directly.

The REST-only parameters (`alignment`, `segment`, `response_format`, `sample_rate`, `bit_rate`) are still absent from the WebSocket surface and remain out of scope for this class.

### To consider
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Reconnect on every settings change** (low, since 2026-10-12) — `_update_settings` disconnects and reconnects whenever anything changes, but Together applies `voice`, `model` and `language` in-session through `tts_session.updated`, so a mid-call voice switch pays a full reconnect for what is one message. — *Needs a call: special-case the in-session fields, or keep one reconnect path for every setting.*
