# Together TTS — 2026-11-23

Qwen3-TTS is now serverless under a new name and needs no code change; one branch adds the three language codes it brings.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6980 — Map German, Korean and Russian to Together TTS language codes

Together renamed its Qwen TTS model: `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice` is gone from the catalogue and `Qwen/Qwen3-TTS-12Hz-1.7B` took its place (serverless 2026-11-12, dedicated endpoints 2026-11-13, $20/1M characters). The old string now fails with `model_not_available`; nothing in Pipecat references it, and the new one streams audio through the class as-is, since the service sends `model` through verbatim with no allowlist. The rest of the TTS catalogue is unchanged — the same 15 other entries as the last three runs, out of 274 models total.

Qwen3-TTS documents ten languages, and three of them — German, Korean, Russian — were absent from `language_to_together_language`'s verified map, so a pipeline configured for them resolved through the unverified fallback and logged a warning on every connect. Together accepts all three (probed, audio returned), so the branch names them.

Default model: `hexgrad/Kokoro-82M` stays. It is still the WebSocket endpoint's own documented default, Together designates no successor, and the deprecations page lists no audio, speech or TTS model at all (the pending removals, `Qwen/Qwen3.8-2.4T-A95B` and the two from 2026-11-06, are text models).

The WebSocket surface is otherwise what we already handle: four query parameters (`model`, `voice`, `max_partial_length`, `language`), the same client and server events, fixed 24 kHz s16le mono, optional `context_id` with `context.cancel`/`context.cancelled`. Its `model` enum is still the stale pair (`hexgrad/Kokoro-82M`, `cartesia/sonic-english`) against a 16-model catalogue. Qwen3-TTS's 8 kHz option and its `response_format` restriction are REST-side only and out of scope for this class.

The SDK pin is untouched: the `together` extra is empty and this class speaks the WebSocket protocol directly, so Together's SDK 3.1–3.3 releases this cycle do not reach it. Only the base `openai` pin (`>=1.74.0,<4`, latest 3.58.0 of 2026-11-23) is reported, and it is unused here.

### To consider
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Reconnect on every settings change** (low, since 2026-10-12) — `_update_settings` disconnects and reconnects whenever anything changes, but the reference marks `model`, `voice` and `language` as settable via `tts_session.updated`, so a mid-call voice switch pays a full reconnect for what is one message. — *Needs a call: special-case the in-session fields, or keep one reconnect path for every setting.*
- **Undocumented `extra_params` keys** (low, since 2026-11-23) — Together's TTS page now documents `seed` (int) and `instructions` (≤500 characters of emotion, tone or pace, Qwen3-TTS only) alongside `pronunciation_dict`; both already reach the provider through the existing dict, verified by probe, but the `TogetherTTSSettings` docstring and the docs.pipecat.ai page name only `pronunciation_dict`. — *Needs a call: whether to enumerate provider keys in the docstring at all, given they are model-specific and Together adds them without notice.*
