# Together TTS — 2026-09-14

No provider-side change since the last run; the blocker is on our side — PR 5581 is still open and `TogetherTTSService` on `main` still produces no audio at all.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5581 — Fix TogetherTTSService's odd-length audio frames and send its language setting (open since 2026-09-01)

A probe against `main` today reproduces the failure unchanged: TTFB 162 ms, then `TogetherTTSService#0::_audio_context_task_handler unexpected exception (src/pipecat/audio/utils.py:370): buffer size must be a multiple of element size`, and no audio or `TTSStoppedFrame` reaches the pipeline. Getting this PR reviewed is the only action this unit needs.

### To consider
- **`extra_params` / pronunciation dictionary** (medium, since 2026-09-01) — `tts_session.updated` accepts `session.extra_params` (documented example: `pronunciation_dict` entries of the form `"omg/oh my god"`); the service only ever sends `session.voice`, so users cannot correct pronunciation. — *Needs a call: `extra_params` is model-specific, so it is either an opaque dict field or a typed `pronunciation_dict` list.*
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Shared onset scanner tolerance** (low, since 2026-09-01) — `detect_speech_onset` (`src/pipecat/audio/utils.py:370`) raises on an odd-length buffer, so the same crash awaits any other service that emits a half-sample frame; PR 5581 only fixes Together. — *Needs a call: harden the shared scanner, or keep alignment a service responsibility (as `TTSService.stream_frames_from_iterator` already assumes).*

Default model: `hexgrad/Kokoro-82M` stays. It is still the WebSocket endpoint's own documented default, Together designates no successor, and the WebSocket reference still documents only Kokoro and `cartesia/sonic-english`.

Catalogue change since 2026-09-01: `deepgram/aura-2` (Deepgram's enterprise TTS, part of the Deepgram-on-Together partnership) now appears in `/v1/models`. It is not reachable from this service and needs no code change — Together serves it from dedicated inference only, and the WebSocket endpoint rejects it outright (see Verification). No allowlist in the class blocks it; the rejection is Together's.
