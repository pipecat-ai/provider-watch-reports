# Together TTS — 2026-11-09

Nothing to do: the service is current, and the two open items are the same low-priority ones as the last two runs.

## What's new for Pipecat

### PRs
Nothing.

Together shipped no TTS change this cycle. The catalogue is unchanged — 269 models, with the same 16 TTS entries as 2026-10-12 and 2026-10-28. The changelog's newest audio entry is still 2026-10-13 (the `nvidia/parakeet-tdt-0.6b-v3` and `openai/whisper-large-v3` speech-to-text endpoints, which belong to the STT unit); everything since — Kimi K3.1 Pro, the Anthropic Messages and OpenAI Responses APIs, SDK/CLI 3.1.0 on 2026-11-03 — is text-side.

The WebSocket reference (last modified 2026-10-21) is byte-for-byte the surface we already handle: four query parameters (`model`, `voice`, `max_partial_length`, `language`), the same client and server events, fixed 24 kHz s16le mono, optional `context_id` with `context.cancel`/`context.cancelled`, and `session.extra_params` whose one documented key is `pronunciation_dict`. Its `model` enum is still the stale pair (`hexgrad/Kokoro-82M`, `cartesia/sonic-english`) against a 16-model catalogue, and the service sends `model` through verbatim, so no allowlist blocks a user.

Default model: `hexgrad/Kokoro-82M` stays. It is the endpoint's own documented default, Together designates no successor, and the deprecations page still lists no audio, speech or TTS model (next scheduled removals, 2026-11-04 and 2026-11-06, are text models).

The REST-only parameters (`response_format`, `sample_rate`, `bit_rate`, `alignment`, `segment`) remain absent from the WebSocket surface and out of scope for this class.

The SDK pin is untouched: the `together` extra is empty and this class speaks the WebSocket protocol directly, so Together's Python SDK 3.x releases do not reach it. Only the base `openai` pin (`>=1.74.0,<4`, latest 3.48.0 of 2026-11-09) is reported, and it is unused here.

### To consider
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Reconnect on every settings change** (low, since 2026-10-12) — `_update_settings` disconnects and reconnects whenever anything changes, but the reference marks `model`, `voice` and `language` as settable via `tts_session.updated`, so a mid-call voice switch pays a full reconnect for what is one message. — *Needs a call: special-case the in-session fields, or keep one reconnect path for every setting.*
