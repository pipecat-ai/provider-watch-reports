# Together TTS — 2026-09-28

No provider-side change in three runs; both open items are ours. PR 5581 (no audio at all) is still unreviewed, and a new branch makes Kokoro's blended voices reachable.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5581 — Fix TogetherTTSService's odd-length audio frames and send its language setting (open since 2026-09-01, no human review; only a codecov comment)
- https://github.com/pipecat-ai/pipecat/pull/5940 — Escape the voice in TogetherTTSService's WebSocket URL

`main` still produces no audio for any turn: TTFB 293 ms, then `TogetherTTSService#0::_audio_context_task_handler unexpected exception (src/pipecat/audio/utils.py:371): buffer size must be a multiple of element size`, and nothing reaches the pipeline. Unchanged since 2026-09-01; getting PR 5581 reviewed is still this unit's most valuable action. The two commits that touched `audio/utils.py` on 2026-09-23/24 (`pcm_to_wav` memoryviews, int16 silence classification) did not change the `np.frombuffer` call that raises.

The new branch is a one-line fix found this run. `_build_websocket_url` interpolates `voice` into the query string raw, and Together decodes the query with a form decoder, so a `+` arrives as a space. Kokoro's blended voice syntax (`af_bella(2)+af_heart(1)`, documented as the only way Together exposes voice mixing, and Kokoro-only) therefore comes back as `Voice 'af_bella(2) af_heart(1)' is not available`, after which the service reconnects three times and gives up. Percent-encoding the value makes Together accept the blend; the `tts_session.updated` message keeps sending the name verbatim as JSON, which is what the server wants there. The branch conflicts textually with PR 5581, which adds a `&language=` line to the same function — whichever lands second needs a trivial rebase.

### To consider
- **`extra_params` / pronunciation dictionary** (medium, since 2026-09-01) — `tts_session.updated` accepts `session.extra_params` (documented example: `pronunciation_dict` entries of the form `"omg/oh my god"`); the service only ever sends `session.voice`, so users cannot correct pronunciation. — *Needs a call: `extra_params` is model-specific, so it is either an opaque dict field or a typed `pronunciation_dict` list.*
- **Per-context messaging** (low, since 2026-09-01) — every client message rides Together's `default` context, and interruption sends `input_text_buffer.clear`; Together accepts a `context_id` on each message plus `context.cancel`, which maps onto Pipecat's audio contexts. — *Needs a call: whether that mapping is worth it while the service only ever has one context open.*
- **Shared onset scanner tolerance** (low, since 2026-09-01) — `detect_speech_onset` (`src/pipecat/audio/utils.py:371`) raises on an odd-length buffer, so the same crash awaits any other service that emits a half-sample frame; PR 5581 only fixes Together. — *Needs a call: harden the shared scanner, or keep alignment a service responsibility (as `TTSService.stream_frames_from_iterator` already assumes).*

Default model: `hexgrad/Kokoro-82M` stays. It is still the WebSocket endpoint's documented default, Together designates no successor, and no audio model appears on Together's deprecations page (which lists only inference and fine-tuning models, most recent sunset batch 2026-09-14).

Catalogue: the 15 TTS entries are unchanged from 2026-09-14. What is new in `/v1/models` is STT and non-audio (`deepgram/flux`, `deepgram/nova-3-en`, `deepgram/nova-3-multi`, `nvidia/nemotron-3.5-asr-streaming-0.6b`, `nvidia/parakeet-tdt-0.6b-v3`, plus LLM and video models) — nothing this unit can reach. `deepgram/aura-2` remains dedicated-inference only, as last run's probe showed; not re-probed.

The REST-only parameters (`alignment` word timestamps, `segment`, `response_format`, `sample_rate`) are still absent from the WebSocket endpoint's surface, so they are not gaps for this class.
