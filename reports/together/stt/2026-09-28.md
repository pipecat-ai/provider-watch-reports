# Together STT — 2026-09-28

Nothing changed on Together's side this cycle; the new finding is ours: the delta handler reads a field the endpoint never sends, so the interim results docs.pipecat.ai advertises cannot be produced.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **`language` is dropped** (high, since 2026-09-01) — `_connect_websocket` builds the URL from `model`, `turn_detection` and `input_audio_format` only, so the `language` field that the class docstring and docs.pipecat.ai both advertise (default `Language.EN`) has no effect. The endpoint documents and accepts the parameter. — *Needs a call: wiring the field up as-is turns today's autodetect into forced English; the alternative is defaulting the field to `None` and sending it only when set.*
- **Interim transcriptions are unreachable** (medium, since 2026-09-28) — `_handle_transcription_delta` reads `evt.get("transcript", "")`, but a raw-socket probe shows the delta event carries the text under `delta` and has no `transcript` key at all, so the `InterimTranscriptionFrame` push never happens. It is unreachable a second way too: the class hard-codes `turn_detection=none`, and under that setting the endpoint sends only one `completed` event — parakeet produced 13 deltas with server VAD on and zero with it off. Our docs page nonetheless says the service supports interim results. — *Needs a call: `turn_detection=none` is deliberate, since the class commits on `VADUserStoppedSpeakingFrame`, so correcting the key on its own changes no behavior. Someone has to decide whether interim results are a feature to make work or the handler is dead code to remove along with the docs claim.*
- **Streaming ASR models** (medium, since 2026-09-01) — `nvidia/parakeet-tdt-0.6b-v3` and `nvidia/nemotron-3.5-asr-streaming-0.6b` are serverless on Together and work through the class unchanged. Parakeet was the fastest of the three on this run's single sample; nemotron truncated the clip to its first sentence, which it also did on 2026-09-01 but not on 2026-09-14, so the truncation is intermittent. — *Needs a call: Together still doesn't position either as Whisper's successor, so there is nothing to bump the default to; revisit if Together designates one.*
- **`prompt` biasing** (low, since 2026-09-01) — a documented query parameter with no `Settings` field. Together's model page says prompts apply to Whisper-family models only, yet earlier runs' raw-socket probes on Whisper left the transcript unchanged. — *Needs a call: confirm the realtime endpoint applies the hint at all before adding a field for it.*
- **Hard-coded 16 kHz declaration** (low, since 2026-09-01) — `input_audio_format=pcm_s16le_16000` is fixed while audio is sent at whatever rate the pipeline delivers. Latent rather than broken. — *Needs a call: the fix is either a resample to 16 kHz or a format string derived from `self.sample_rate`, depending on which other rates the endpoint accepts.*

## Verification

| model                                  | class              | ok | latency      | note                                                       |
| -------------------------------------- | ------------------ | -- | ------------ | ---------------------------------------------------------- |
| openai/whisper-large-v3                | TogetherSTTService | ✅ | TTFB 845 ms  | full transcript; no `InterimTranscriptionFrame` emitted    |
| nvidia/parakeet-tdt-0.6b-v3            | TogetherSTTService | ✅ | TTFB 367 ms  | full transcript; no `InterimTranscriptionFrame` emitted    |
| nvidia/nemotron-3.5-asr-streaming-0.6b | TogetherSTTService | ✅ | TTFB 1333 ms | truncated to the first sentence, as on 2026-09-01          |

Single samples: no comparison here decided a default. Whisper's 845 ms against last run's 235 ms is within what one sample can say.

Raw-socket probe (`.pw-scratch/together_delta_shape.py`, parakeet): with the class's `turn_detection=none`, the only events are `session.created` and one `...transcription.completed` (keys include `transcript`). Dropping `turn_detection=none` yields 13 `...transcription.delta` events whose keys are `audio_end_ms, audio_start_ms, delta, duration, item_id, start, type`, then the same `completed`.
