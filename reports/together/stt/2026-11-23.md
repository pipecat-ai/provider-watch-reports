# Together STT — 2026-11-23

Together's side is unchanged, but Pipecat's STT base class gained `send_sample_rate` resampling since the last run, which turns the long-standing 16 kHz item into a one-property fix: branch ready, backed by a before/after probe at a 48 kHz pipeline rate.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6979 — Send Together STT audio at the 16 kHz the endpoint takes

### To consider

- **`language` is dropped** (medium, since 2026-09-01) — `_connect_websocket` builds the URL from `model`, `turn_detection` and `input_audio_format` only, so the `language` field (default `Language.EN`) never reaches the endpoint. docs.pipecat.ai says so outright, so what's left is that non-English users have no way to force a language. Open for six runs. — *Needs a call: wiring the field up as-is turns today's autodetect into forced English; the alternative is defaulting the field to `None` and sending it only when set.*
- **Interim transcriptions are unreachable** (medium, since 2026-09-28) — `_handle_transcription_delta` reads `evt.get("transcript", "")`, but Together's streaming page documents the delta event's text as `delta` and the completed event's as `transcript`, so the `InterimTranscriptionFrame` push never happens; none of this run's seven probe runs produced one. It is unreachable a second way: with the class's hard-coded `turn_detection=none` the endpoint sends only one `completed` event. Our docs page still says the service supports interim results. — *Needs a call: `turn_detection=none` is deliberate, since the class commits on `VADUserStoppedSpeakingFrame`, so correcting the key on its own changes no behavior. Someone has to decide whether interim results are a feature to make work or the handler is dead code to remove along with the docs claim.*
- **Streaming ASR models** (medium, since 2026-09-01) — `nvidia/parakeet-tdt-0.6b-v3` and the two Nemotron ASR streaming models are serverless on Together and work through the class unchanged. Parakeet was again the faster on a single sample, with an equivalent transcript. — *Needs a call: Together's STT page names no recommended model and no successor to Whisper, so there is nothing to bump the default to; revisit if Together designates one.*
- **`prompt` biasing** (low, since 2026-09-01) — a documented transcription parameter with no `Settings` field. Together's STT page says prompts apply to Whisper-family models only and that other models ignore the field, yet earlier runs' raw-socket probes on Whisper left the transcript unchanged. — *Needs a call: confirm the realtime endpoint applies the hint at all before adding a field for it.*

| openai/whisper-large-v3     | branch, `sample_rate=48000`       | ✅ | TTFB 536 ms | full transcript                                                        |
| openai/whisper-large-v3     | branch, `sample_rate=24000`       | ✅ | TTFB 508 ms | full transcript                                                        |
| openai/whisper-large-v3     | branch, pipeline 16 kHz           | ✅ | TTFB 801 ms | full transcript; unchanged path                                        |

Single samples; no comparison here decided a default. Whisper's TTFB has swung between 250 ms and 886 ms across runs, so these are within the usual spread. A local check with the socket stubbed (no provider call) confirms the branch sends the clip's 161,998 bytes unchanged at a 48 kHz pipeline rate, where main sends 485,994 resampled bytes under the same `pcm_s16le_16000` label.
