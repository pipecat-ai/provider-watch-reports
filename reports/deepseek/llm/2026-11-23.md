# DeepSeek LLM — 2026-11-23

Nothing urgent. The default `deepseek-flash` is still DeepSeek's only flash model and probes are notably faster than last run (TTFAT 515 ms vs 884 ms median); the 2026-11-13 "full app experience" release brings server-side web tools and a `safety_check` parameter that this service can only reach through escape hatches.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Server-side web tools** (medium, since 2026-11-23) — `deepseek_web_search` and `deepseek_read_url` became declarable tool types on Chat Completions for `deepseek-flash` on 2026-11-13. They pass through today only as provider-specific custom tools (`ToolsSchema(custom_tools={AdapterType.OPENAI: [{"type": "deepseek_web_search"}]})`); a probe sending that tool was accepted and streamed an answer (TTFAT 2089 ms, thinking 1711 ms). What the response adds — `server_tool_calls` and `annotations` with url citations — is dropped, since the inherited OpenAI streaming path reads neither, so a user gets a web-grounded answer with no sources. `tool_choice: required` is a 400 with these tools, and with thinking enabled search becomes a multi-step deep search of up to ~20 tool calls. — *Needs a call: whether Pipecat should name these tools (an `AdapterType.DEEPSEEK` entry or a documented recipe) and whether citations should surface as frames.*
- **`reasoning_effort` has no field** (medium, since 2026-09-01) — accepted values are `none`/`low`/`high`/`max`, default `high`; `minimal` maps to `low`, `medium`/`xhigh` to `high`. It reaches the API today only via `extra={"reasoning_effort": "low"}`. A typed field is not a clean pass-through here: the API reference states `thinking` takes precedence over `reasoning_effort`, and the service ships `thinking={"type":"disabled"}`, so the field would appear to do nothing. — *Needs a call: whether a typed field is worth adding when it only bites once `thinking` is enabled or cleared, or whether `extra` remains the answer.*
- **`use_provider_thinking_default` is ignored here** (medium, since 2026-11-09) — DeepSeek applies its low-latency thinking choice as a constructor default rather than through `LLMService._apply_thinking_default`, the hook Google, OpenAI Responses and Perplexity route through, so the flag never reaches a request and `deepseek-flash` keeps thinking disabled where a `BackendLLMWorker` asked for DeepSeek's own default. The one-log-line-per-model behavior is missing too. — *Needs a call: whether to move the disabled default into a `_maybe_apply_thinking_default` hook, which changes what `service.settings.thinking` reads back as and what an explicit `thinking=None` means.*
- **Dead penalty parameters** (low, since 2026-09-01) — `build_chat_completion_params` always sends `frequency_penalty` and `presence_penalty`, which DeepSeek still documents as deprecated and ignored; the docstring names only `seed` and `max_completion_tokens`. `top_p` is adjacent: for `deepseek-flash` in non-thinking mode, the mode the service ships, DeepSeek fixes it at 1.0 and ignores the value sent. — *Needs a call: whether to drop them from the request or keep sending them for OpenAI-compatible symmetry.*
- **Vision is untested here** (low, since 2026-09-14) — the vision guide takes base64 data URLs and http(s) links in `image_url`, which is what the inherited OpenAI path sends, and the retired `deepseek-v4-flash-vision-exp` name is now served by Flash; no probe here used an image and the class says nothing about it. Documents (PDF, Office) are a different path — Files API upload plus a `file` block with `file_id` — that the adapter does not implement. — *Needs a call: whether to verify image input through the inherited path and document it on the class.*
- **`safety_check` is awkward to reach** (low, since 2026-11-23) — the new `safety_check.level` (`low`/`high`) enables input/output risk review. `extra={"safety_check": ...}` fails before the request leaves the process, because the OpenAI SDK rejects unknown top-level keyword arguments; only `extra={"extra_body": {"safety_check": {"level": "high"}}}` works (probed, accepted). A typed field passed through `_merge_extra_body`, as `thinking` already is, would be a one-field change. — *Needs a call: what the pipeline should do with the refusal marker a tripped check returns, since it arrives as ordinary assistant text.*

The rest of the 2026-11-13 release is outside this unit: DeepSeek now also serves an Anthropic-style Messages API and an OpenAI-style Responses API for `deepseek-flash`, and standalone Search/Fetch, OCR, ASR and TTS endpoints. A DeepSeek Responses variant or DeepSeek STT/TTS services would each be a new integration, not a gap in `DeepSeekLLMService`.

No default bump is in play: the catalogue still holds only `deepseek-flash` (updated in place) and the higher-cost `deepseek-v4-pro`. The aiewf-eval medium-context leaderboard still carries only V4 rows, so there is nothing new to compare.
