# DeepSeek LLM — 2026-10-12

Nothing to do. DeepSeek has published no release note since 2026-09-10, the catalogue is unchanged, our default `deepseek-flash` is the current name, and the high-priority finding the last run opened turns out not to hold.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`reasoning_effort` has no field** (medium, since 2026-09-01) — accepted values are `none`/`low`/`high`/`max`, default `high`; `minimal` maps to `low`, `medium`/`xhigh` to `high`. It reaches the API today only via `extra={"reasoning_effort": "low"}`. Adding a typed field is not a clean pass-through here: with the service's shipped `thinking={"type":"disabled"}`, a direct API call sending `reasoning_effort="high"` alongside it returned 0 reasoning tokens, so `thinking` wins and the field would appear to do nothing. — *Needs a call: whether a typed field is worth adding when it only bites once `thinking` is enabled or cleared, or whether `extra` remains the answer.*
- **Dead penalty parameters** (low, since 2026-09-01) — `build_chat_completion_params` always sends `frequency_penalty` and `presence_penalty`, which DeepSeek documents as deprecated and silently ignores; the docstring still names only `seed` and `max_completion_tokens`. `top_p` is adjacent: DeepSeek fixes it at 1.0 and ignores it in non-thinking mode, which is the mode the service ships. — *Needs a call: whether to drop them from the request or keep sending them for OpenAI-compatible symmetry.*
- **Vision is untested here** (low, since 2026-09-14) — V4.1 Flash has native image understanding and the experimental `-vision-exp` model it replaced is retired. The inherited `OpenAILLMService` image path should carry it, but no probe here used an image. — *Needs a call: whether to verify image input through the inherited path and document it on the class.*

### Resolved since last run
- **Default model name** — PR #5746 merged on 2026-09-14; the service ships `deepseek-flash` and no example, test or docstring still names a retired model.
- **"The thinking default is inert on `deepseek-flash`" (was high)** — dropped, it does not reproduce. A direct streaming call counting `reasoning_content` shows the shipped `thinking={"type":"disabled"}` produces 0 reasoning characters and 0 reasoning tokens, while `thinking={"type":"enabled"}` produces 73 characters / 17 reasoning tokens on the same prompt. `reasoning_effort="none"` is equivalent to `disabled`, not better. The September reading rested on the probe's `thinking_ms`, which on DeepSeek measures the gap between the first chunk carrying `choices` (a role-only delta) and the first answer token — stream jitter, not reasoning. Latency figures below are also uniformly ~2x faster than September's across every configuration, so that run looks to have caught DeepSeek under load.

No aiewf-eval row exists for V4.1 Flash; the leaderboard still carries only the V4 `-0731`/`-0813` rows. That blocks nothing this run, since the catalogue offers no successor to evaluate — `deepseek-v4-pro` is the higher-cost tier, not flash's replacement.
