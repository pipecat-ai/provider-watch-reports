# DeepSeek LLM — 2026-11-09

Nothing to do. DeepSeek's one release since the last run (2026-10-17) upgraded `deepseek-flash` to V4.1-Flash-1017 in place and added a standalone Search API; no model name, request parameter or default changed, and the probes pass with latency in line with last run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`reasoning_effort` has no field** (medium, since 2026-09-01) — accepted values are `none`/`low`/`high`/`max`, default `high`; `minimal` maps to `low`, `medium`/`xhigh` to `high`. It reaches the API today only via `extra={"reasoning_effort": "low"}`. Adding a typed field is not a clean pass-through here: the API reference states `thinking` takes precedence over `reasoning_effort`, and the service ships `thinking={"type":"disabled"}`, so the field would appear to do nothing. — *Needs a call: whether a typed field is worth adding when it only bites once `thinking` is enabled or cleared, or whether `extra` remains the answer.*
- **`use_provider_thinking_default` is ignored here** (medium, since 2026-11-09) — the setting landed on 2026-10-14 (`9a1bd2104`) for services that send each model their lowest thinking setting, and `BackendLLMWorker` sets it. DeepSeek is such a service, but it applies its low-latency choice as a constructor default rather than through `LLMService._apply_thinking_default`, the hook Anthropic, Google, OpenAI Responses and Perplexity route through, so the flag never reaches a request and `deepseek-flash` keeps thinking disabled where the worker asked for DeepSeek's own default. The one-log-line-per-model behavior is missing too. — *Needs a call: whether to move the disabled default into a `_maybe_apply_thinking_default` hook, which changes what `service.settings.thinking` reads back as and what an explicit `thinking=None` means.*
- **Dead penalty parameters** (low, since 2026-09-01) — `build_chat_completion_params` always sends `frequency_penalty` and `presence_penalty`, which DeepSeek still documents as deprecated and ineffective; the docstring names only `seed` and `max_completion_tokens`. `top_p` is adjacent: for `deepseek-flash` in non-thinking mode, the mode the service ships, DeepSeek fixes it at 1.0 and ignores the value sent. — *Needs a call: whether to drop them from the request or keep sending them for OpenAI-compatible symmetry.*
- **Vision is untested here** (low, since 2026-09-14) — V4.1 Flash has native image understanding and the experimental `-vision-exp` model it replaced is retired. The inherited `OpenAILLMService` image path should carry it, but no probe here used an image. — *Needs a call: whether to verify image input through the inherited path and document it on the class.*

The 2026-10-17 Search API (`POST /v1/tools/search`, plus Fetch) is a standalone JSON endpoint, not a chat-completion parameter or built-in tool, so it is nothing this LLM service can expose; it would be a new integration rather than a gap in this unit.

No aiewf-eval row exists for V4.1 Flash — the leaderboard still carries only V4 rows — but nothing hinges on it this run: the catalogue offers no successor to `deepseek-flash` (it is updated in place), and `deepseek-v4-pro` is the higher-cost tier rather than flash's replacement.
