# DeepSeek LLM — 2026-09-14

DeepSeek retired the V4 Flash models on 2026-09-10 and serves V4.1 Flash as `deepseek-flash`; our default still uses the retired name, and the branch fixes it. The more consequential finding is that `thinking={"type":"disabled"}` — what the service ships to keep voice latency down — has no measurable effect on the new model.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5746 — Default DeepSeekLLMService to deepseek-flash

This is a rename, not a model bump: DeepSeek routes `deepseek-v4-flash` to V4.1 Flash already, so both strings reach the same weights today and the aiewf-eval condition has nothing to compare (the leaderboard still carries only the `-0731`/`-0813` V4 rows). The routing is documented as temporary, which is what makes the fix worth shipping now.

### To consider
- **The thinking default is inert on `deepseek-flash`** (high, since 2026-09-14) — with settings as shipped (`thinking` disabled), the model still streams 1.1 s of reasoning and reaches the first answer token at 1531 ms (median of 5); explicitly *enabling* thinking measures the same 1531 ms. `reasoning_effort="none"` — a value DeepSeek added with V4.1 — brings it to 964 ms with `thinking` disabled and 974 ms without it, so `reasoning_effort` is the lever and `thinking.type` no longer moves anything. DeepSeek's guide still documents both, so this is behavior, not documentation. — *Needs a call: whether the service's "no thinking" default should send `reasoning_effort="none"` instead of `thinking`, since that changes what every existing bot's requests carry.*
- **`reasoning_effort` has no field** (medium, since 2026-09-01) — the accepted values are now `none`/`low`/`high`/`max` (`minimal` maps to `low`, `medium`/`xhigh` to `high`), default `high`. It reaches the API today only via `extra={"reasoning_effort": "none"}`. — *Needs a call: whether a typed field beside `thinking` is worth it, or `extra` remains the answer for a parameter the OpenAI client forwards unchanged.*
- **Dead penalty parameters** (low, since 2026-09-01) — `_build_chat_completion_params` always sends `frequency_penalty` and `presence_penalty`, which DeepSeek documents as no longer supported and silently ignores; the method docstring still names only `seed` and `max_completion_tokens`. — *Needs a call: whether to drop them from the request or keep sending them for OpenAI-compatible symmetry.*
- **Vision is untested here** (low, since 2026-09-14) — V4.1 Flash has native multimodal image understanding, and the experimental `-vision-exp` model it replaces is retired. The inherited `OpenAILLMService` image path should carry it, but no probe here used an image. — *Needs a call: whether to verify image input through the inherited path and document it on the class.*

`deepseek-v4-pro` remains in the catalogue and in DeepSeek's pricing table; the docs state API service for it continues past 2026-09-14 with billing unchanged (third-party posts claiming it is routed to Flash are not what DeepSeek's own pages say). It is the higher-cost tier rather than flash's successor, so no default question there.

Both items the previous report carried about thinking are closed in code: PR #5528 merged on 2026-09-03 (the `thinking` Settings field), and commit bba868b80 made `disabled` the shipped default. The gap above is what became of the second one on DeepSeek's new model.

## Verification

| model             | class              | ok | latency                                       | note |
| ----------------- | ------------------ | -- | --------------------------------------------- | ---- |
| deepseek-v4-flash | DeepSeekLLMService | ✅ | TTFAT 1788 ms (median of 5), thinking 1166 ms | retired name, settings as shipped; spread 1301-2099 ms |
| deepseek-flash    | DeepSeekLLMService | ✅ | TTFAT 1531 ms (median of 5), thinking 1107 ms | same call, settings as shipped; spread 1183-2029 ms |
| deepseek-flash    | DeepSeekLLMService | ✅ | TTFAT 1531 ms (median of 5), thinking 782 ms  | `thinking={"type":"enabled"}` - indistinguishable from disabled |
| deepseek-flash    | DeepSeekLLMService | ✅ | TTFAT 964 ms (median of 5), thinking 548 ms   | shipped `thinking` disabled plus `extra={"reasoning_effort":"none"}` |
| deepseek-flash    | DeepSeekLLMService | ✅ | TTFAT 974 ms (median of 5), thinking 493 ms   | `thinking=None` plus `extra={"reasoning_effort":"none"}` - `reasoning_effort` alone accounts for the gain |
| (branch default)  | DeepSeekLLMService | ✅ | TTFAT 1786 ms, thinking 1144 ms               | branch build, no `--model`; single sample, inside the spread above |

All probes used the trivial default prompt; the enabled/disabled pair is measured on the same prompt, so the null result is a like-for-like comparison rather than a prompt effect.
