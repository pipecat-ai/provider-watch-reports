### To consider

- **Moondream 3 is not reachable** (medium, since 2026-09-01) — `moondream/moondream3.1-9B-A2B` is unchanged since 2026-07-08 and its Hugging Face repo still holds only `config.json` and `model.safetensors` with no `auto_map`, so `AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True)` cannot load it; Moondream ships it for the Photon runtime. `moondream/moondream3-preview` does carry remote code and would drop into the current call path, but moondream.ai/models still labels it preview (recommended for new projects) against moondream2 "stable". — *Needs a call: add a Photon-based backend, or wait for a transformers-loadable Moondream 3 release.*
- **`revision` is moondream2-specific** (medium, since 2026-09-01) — the constructor's `revision="2025-06-21"` default is applied to whatever repo `Settings(model=...)` names, and that tag exists only in `vikhyatk/moondream2`; pointing the service at `moondream/moondream3-preview` fails to resolve unless the caller also passes `revision=None`. — *Needs a call: move `revision` into `Settings`, or default it to `None` when the model is not moondream2.*
- **transformers floor is below what the code needs** (medium, since 2026-09-01) — `vision.py` calls `from_pretrained(..., dtype=dtype)`, but `from_pretrained` only started popping `dtype` in transformers 4.56.0; the `moondream` extra still pins `transformers>=4.48.0,<6`. Resolving anywhere in 4.48–4.55 silently discards the device-appropriate dtype `detect_device()` picked. A fresh `uv sync` lands on 5.x, so only environments constrained by other packages are affected. — *Needs a call: raise the floor to `>=4.56`, or pass `torch_dtype` as well for backwards compatibility.*
- **`query` knobs are not exposed** (medium, since 2026-09-01) — moondream2's `query(image, question, reasoning=False, spatial_refs=None, stream=False, settings=None)` offers grounded reasoning, streaming and `TextSamplingSettings`; `MoondreamSettings` inherits only `model`, and `run_vision` calls `query(image_embeds, text)` positionally, then yields a single `VisionTextFrame` once the whole answer is generated. On moondream3-preview `reasoning` defaults to `True`, so the flag becomes load-bearing if that model is ever supported. — *Needs a call: whether reasoning and sampling belong in `Settings`, and whether streaming should change the emitted frame shape.*
- **Dependency caps a minor behind** (low, since 2026-09-01) — `accelerate~=1.10.0` now excludes 1.15.0 (released 2026-09-09) and `pyvips[binary]~=3.0.0` excludes 3.2.0. Nothing in the model's own code needs the older minors. — *Needs a call: whether the compatible-release caps are deliberate or stale.*
