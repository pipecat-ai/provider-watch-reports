# Moondream Vision — 2026-11-09

No change needed: `vikhyatk/moondream2` at revision `2025-06-21` is still the newest tag and Moondream's "stable" model, and the two dependency gaps the last run raised have both been fixed in `pyproject.toml`.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Moondream 3 is not reachable** (medium, since 2026-09-01) — `moondream/moondream3.1-9B-A2B` is still unchanged since 2026-07-08 and its Hugging Face repo holds only `config.json` and `model.safetensors` with no `auto_map`, so `trust_remote_code` loading cannot reach it; it targets the Photon runtime. `moondream/moondream3-preview` does carry `hf_moondream.HfMoondream`, but it is now blocked twice over: moondream.ai/models still labels it "preview" against moondream2 "stable", and `load_model`'s `Transformers5Moondream` subclass is written to moondream2's layout — it copies a 2-D `tril(max_context, max_context)` into `module.attn_mask`, where moondream3 registers a 4-D mask and keeps `freqs_cis` on the text module. — *Needs a call: add a Photon-based backend, or wait for a transformers-loadable Moondream 3 release.*
- **`revision` is moondream2-specific** (medium, since 2026-09-01) — the constructor's `revision="2025-06-21"` default is applied to whatever repo `Settings(model=...)` names, and that tag exists only in `vikhyatk/moondream2`; pointing the service at any `moondream/*` repo fails to resolve unless the caller also passes `revision=None`. — *Needs a call: move `revision` into `Settings`, or default it to `None` when the model is not moondream2.*
- **`query` knobs are not exposed** (medium, since 2026-09-01) — at the pinned revision, `query(image, question, reasoning=False, spatial_refs=None, stream=False, settings=None)` offers grounded reasoning, streaming and `TextSamplingSettings`; `MoondreamSettings` inherits only `model`, and `run_vision` calls `query(image_embeds, text)` positionally, then yields a single `VisionTextFrame` once the whole answer is generated. On moondream3-preview `reasoning` defaults to `True`, so the flag becomes load-bearing if that model is ever supported. — *Needs a call: whether reasoning and sampling belong in `Settings`, and whether streaming should change the emitted frame shape.*

Closed since 2026-09-14: the `moondream` extra now pins `transformers>=5.10.0,<6`, above the 4.56.0 floor where `from_pretrained` started accepting `dtype=`, and the `accelerate` / `pyvips` compatible-release caps were widened to `<2` and `<4`, so both admit the current releases. Neither is a gap any more.

Context, no action: Moondream announced on 2026-10-14 that it is joining Prime Intellect and is shutting down Moondream Cloud (inference and Lens) on 2026-11-13. `MoondreamService` runs the model locally through transformers and no Pipecat code or example touches a Moondream cloud endpoint, so the shutdown does not reach us; the announcement says the models stay open. Separately, upstream merged "Support transformers 5" into `vikhyatk/moondream2`'s `main` on 2026-09-23 — the same fix `load_model`'s subclass applies locally — but no tag carries it, so the shim stays needed while `revision` is pinned to `2025-06-21`.
