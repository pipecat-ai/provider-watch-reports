# Moondream Vision — 2026-09-01

`vikhyatk/moondream2` at revision `2025-06-21` is still Moondream's production-stable model and the latest tag in that repo, so the default stays; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Moondream 3 is not reachable** (medium, since 2026-09-01) — `moondream/moondream3.1-9B-A2B` (published 2026-07-08) is Moondream's current flagship, but its Hugging Face repo holds only `config.json` and `model.safetensors`, with no `auto_map`, so `AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True)` cannot load it; Moondream ships it for the Photon runtime (`pip install moondream`). `moondream/moondream3-preview` does carry remote code (`auto_map` → `hf_moondream.HfMoondream`, with `encode_image` and `query` present), so it would drop into the current call path, but it is a preview. — *Needs a call: add a Photon-based backend, or wait for a transformers-loadable Moondream 3 release.*
- **`revision` is moondream2-specific** (medium, since 2026-09-01) — the constructor's `revision="2025-06-21"` default is applied to whatever repo `Settings(model=...)` names, and that tag exists only in `vikhyatk/moondream2`; pointing the service at `moondream/moondream3-preview` therefore fails to resolve unless the caller also passes `revision=None`. — *Needs a call: move `revision` into `Settings`, or default it to `None` when the model is not moondream2.*
- **transformers floor is below what the code needs** (medium, since 2026-09-01) — `vision.py` calls `from_pretrained(..., dtype=dtype)`, but `from_pretrained` only started popping `dtype` in transformers 4.56.0 (4.55 pops `torch_dtype` only); the `moondream` extra pins `transformers>=4.48.0,<6`. Resolving anywhere in 4.48–4.55 silently discards the device-appropriate dtype `detect_device()` picked. A fresh `uv sync` lands on 4.57+, so only environments constrained by other packages are affected. — *Needs a call: raise the floor to `>=4.56`, or pass `torch_dtype` as well for backwards compatibility.*
- **`query` knobs are not exposed** (medium, since 2026-09-01) — moondream2's `query(image, question, reasoning=False, spatial_refs=None, stream=False, settings=None)` offers grounded reasoning, streaming and `TextSamplingSettings` (max tokens, temperature, top-p); `MoondreamSettings` inherits only `model` and `run_vision` calls `query(image_embeds, text)` positionally, then yields a single `VisionTextFrame` once the whole answer is generated. On moondream3-preview `reasoning` even defaults to `True`, so the flag becomes load-bearing if that model is ever supported. — *Needs a call: whether reasoning and sampling belong in `Settings`, and whether streaming should change the emitted frame shape.*
- **Dependency caps a minor behind** (low, since 2026-09-01) — `accelerate~=1.10.0` excludes 1.14.0 and `pyvips[binary]~=3.0.0` excludes 3.2.0. Nothing in the model's own code needs the older minors (moondream2's `image_crops.py` uses only `pyvips.Image.new_from_array`, `.resize` and `.numpy`). — *Needs a call: whether the compatible-release caps are deliberate or stale.*
