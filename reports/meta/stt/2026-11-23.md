# Meta STT — 2026-11-23

Nothing to change automatically: `muse-voice-transcribe-1.0` is still Meta's only ASR model. The one new finding is that `zdrOverride` has vanished from Meta's documented handshake schema while `MetaSTTSettings.zdr_override` still sends it.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`zdr_override` is no longer a documented handshake field** (medium, since 2026-11-23) — the voice schemas page's `RealtimeHandshakeRequest` now lists only `authorization`, `audioEncoding`, `model`, `mode`, `partialMode`, `emitAudioProgress`, `keywords` and `languageBias`; "zdr", "ZDR" and "retention" appear nowhere on it, though the last two reports read `zdrOverride` there. Meta's ZDR help page describes ZDR as organization-level only, enabled by Meta after review and not switchable per request. `_build_handshake` adds `zdrOverride` whenever the setting is not None, so a user who sets it sends a field the API reference no longer defines; the default None leaves everyone else unaffected. — *Needs a call: deprecate and remove the field, or keep it as an undocumented passthrough? Whether the server still accepts it or closes the session with 1008 can only be settled by a live handshake, and no credential was available.*
- **Duplicate finals in DIARIZATION** (medium, since 2026-09-14) — the schemas page now states outright that `final: true` marks stream completion in PUSH_TO_TALK and that ENDPOINTING and DIARIZATION use `speechComplete` for turn completion, and the speech-to-text page's per-mode table says the same. `_handle_transcript` finalizes any final-flagged transcript when `mode != "ENDPOINTING"`, which includes DIARIZATION, while `speechComplete` pushes its own final — two `TranscriptionFrame`s for one turn. The condition would become `mode == "PUSH_TO_TALK"`. The DIARIZATION tests added with speaker labels (`_diarized_turn`) send `final: false`, so the path is still uncovered. — *Needs a call: confirm against a live DIARIZATION session whether the server emits final-flagged transcripts there; no credential was available to check.*
- **No batch transcription service** (low, since 2026-09-14) — `POST /v1/asr/transcribe` takes a multipart `request` JSON plus a WAV `audio` part (10 min, 32 MB) and shares models, modes, `languageBias` and `keywords` with the socket. — *Needs a call: whether a `SegmentedSTTService` subclass is wanted, since it is a new class rather than a settings change.*

Closed since the last run: **diarization speaker labels** (open since 2026-09-14) now reach the pipeline — commit e455812a2 added `TranscriptionFrame.speaker` from Meta's per-turn `speaker` events plus the local `speaker_format` setting, and docs.pipecat.ai documents it. The rest of the handshake stays fully reachable: `model`, `mode`, `audioEncoding`, `languageBias`, `keywords` and `emitAudioProgress` all map to `MetaSTTSettings`, and `partialMode` stays pinned to `CUMULATIVE` for the interim-replacement behavior. The 25 documented languages still match `_LANGUAGE_MAP` exactly, and the limits (256 concurrent streams, 16,000 per hour, 60-minute sessions, close codes 1000/1008/1011/1013) are unchanged.
