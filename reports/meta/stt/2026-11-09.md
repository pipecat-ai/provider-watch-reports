# Meta STT — 2026-11-09

Nothing to change: `muse-voice-transcribe-1.0` is still the only ASR model Meta ships and the handshake schema is unchanged since the last run. The three open items are the same DIARIZATION and batch-endpoint items, and none could be probed — `META_API_KEY` is not set in this environment.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Duplicate finals in DIARIZATION** (medium, since 2026-09-14) — the schemas page states `final: true` marks stream completion *in PUSH_TO_TALK*, and the speech-to-text page's per-mode table gives `speechComplete` as the completion signal for both ENDPOINTING and DIARIZATION. `_handle_transcript` treats any final-flagged transcript as final when `mode != "ENDPOINTING"`, which includes DIARIZATION, while `speechComplete` pushes its own final — two `TranscriptionFrame`s for one turn. The condition would become `mode == "PUSH_TO_TALK"`; `tests/test_meta_stt.py` still covers ENDPOINTING and PUSH_TO_TALK only. — *Needs a call: confirm against a live DIARIZATION session whether the server emits final-flagged transcripts there; no credential was available to check.*
- **Speaker labels do not leave the service** (medium, since 2026-09-14) — `speaker` events carry a session-scoped `label`, but `_handle_message` only trace-logs them and the `speechComplete` that becomes the final frame has no label, so diarized output is unattributed downstream. Meta's batch endpoint renders the same information as `A:Hello`, with `unknown:<transcript>` for unattributed turns. — *Needs a call: which surface to use — Speechmatics formats the speaker into the transcript text, Soniox annotates tokens, and Meta's own `text/plain` uses a `label:` prefix; picking one is a design decision, not a pass-through.*
- **No batch transcription service** (low, since 2026-09-14) — `POST /v1/asr/transcribe` takes a multipart `request` JSON plus a WAV `audio` part (10 min, 32 MB) and shares models, modes, `languageBias` and `keywords` with the socket. — *Needs a call: whether a `SegmentedSTTService` subclass is wanted, since it is a new class rather than a settings change.*

Everything else in the handshake is still reachable: `model`, `mode`, `audioEncoding`, `languageBias`, `keywords`, `emitAudioProgress` and `zdrOverride` all map to `MetaSTTSettings`, and `partialMode` stays pinned to `CUMULATIVE` for the interim-replacement behavior. The 25 documented languages still match `_LANGUAGE_MAP` exactly. Two doc details moved without affecting the code: the tenant limit is now 256 concurrent streams and 16,000 streams per hour (was 128 concurrent), and the realtime page documents close codes 1000/1008/1011/1013, which `WebsocketService`'s exponential backoff and quick-failure tracking already cover generically.
