# Async TTS — 2026-09-01

Nothing moved at Async — same three models, same request schema, latest announcement still 2026-06-02 — and both classes were verified end-to-end this run; the open item is still the websocket receive loop discarding error frames.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5464 — Apply model, voice and language changes by opening a new session (still open). It matters for the shipped example `examples/update-settings/tts/tts-asyncai.py`, which sends a `TTSUpdateSettingsFrame(language=ES)` that the websocket class today only warns about; the HTTP class rebuilds its payload from `_settings` per request, so it is unaffected.

### To consider
- **Server error frames are dropped** (high, since 2026-08-31) — `_receive_messages` understands only `final` and `audio`. Async's documented `error` frame (`error_code`, `message`, `extra`) carries no `context_id`, so it takes the "unavailable context" branch, logs `Ignoring message from unavailable context: None` and continues: no `ErrorFrame`, no audio, silent failure. The same branch swallows the undocumented `init_ack` the server sends right after init; this run a healthy websocket turn through the real class logged `Ignoring message from unavailable context: <server uuid>` on connect, confirming it. — *Needs a call: whether an `error_code` frame should push an ErrorFrame and close the context, or only be logged.*
- **`speed_control` and `stability` not exposed** (low, since 2026-08-31) — both are documented HTTP request fields and `AsyncAITTSSettings` adds no fields over `TTSSettings`. Async's model page still restricts them to `async_flash_v1.0`, so on the default they are accepted and ignored. — *Needs a call: a stance on exposing settings that the default model accepts but does not honor.*
- **Language map is wider than the default model** (low, since 2026-08-31) — `language_to_async_language` maps 16 `Language` values; the model page gives `async_flash_v1.5` six (en, es, fr, de, it, pt) and the other nine to `async_flash_v1.0` only, and `nl` appears in neither the model page nor the HTTP reference's 15-code list. — *Needs a call: whether to warn per model, document the split, or leave the map model-agnostic.*

`async_flash_v1.5` is still Async's recommendation for voice agents, so the default stands. `async_pro_v1.0` remains English-only and quality-tier, not a real-time default candidate, and `Settings.model` is a free-form string with no allowlist, so all three are already selectable. No example pins a model string.

`probe.py` cannot drive either class: `AsyncAIHttpTTSService` requires an `aiohttp_session` constructor argument, and `AsyncAITTSService` stalls because `TTSService._maybe_pause_frame_processing` holds frame processing until a `BotStoppedSpeakingFrame` the bare probe pipeline never emits. Both were probed instead through `run_test` (scripts in `.pw-scratch/asyncai_*_probe.py`), the websocket one sending the `BotStoppedSpeakingFrame` by hand. The stall is a harness limitation shared by every websocket TTS service with `pause_frame_processing=True`, not an Async defect.
