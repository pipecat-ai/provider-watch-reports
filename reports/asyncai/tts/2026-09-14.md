# Async TTS — 2026-09-14

Nothing moved at Async — same three models, same request schema, latest announcement still 2026-06-02 — and both classes synthesized end-to-end this run; the runtime-settings fix merged, leaving the silent-failure path as the only item needing a decision.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5464 — Apply model, voice and language changes by opening a new session (merged 2026-09-03). `_update_settings` now reconnects when `model`, `voice` or `language` changes, so the shipped `examples/update-settings/tts/tts-asyncai.py` takes effect; that gap is closed and is no longer listed.

### To consider
- **Server error frames are dropped** (high, since 2026-08-31) — driving the real class with an unknown model id produced no audio and no `ErrorFrame` at all, while a tap on the same socket showed Async sending `error_code: BAD_REQUEST` four times. The frames carry `message`, `extra` and `request_id` but no `context_id`, so they take `_receive_messages`' "unavailable context" branch and are discarded. A rejected request is therefore indistinguishable from a slow one: the turn goes silent and the application is never told. The same branch swallows the undocumented `init_ack` on every healthy connect. — *Needs a call: whether an `error_code` frame should push an ErrorFrame and close the context, or only be logged.*
- **`speed_control` and `stability` not exposed** (low, since 2026-08-31) — both are documented HTTP request fields and `AsyncAITTSSettings` adds no fields over `TTSSettings`. Async's model page still restricts them to `async_flash_v1.0`, so on the default they are accepted and ignored, and the websocket init message has no slot for them. — *Needs a call: a stance on exposing settings that the default model accepts but does not honor, and that the websocket class cannot send.*
- **Language map is wider than the default model** (low, since 2026-08-31) — `language_to_async_language` maps 16 `Language` values; the model page gives `async_flash_v1.5` six (en, es, fr, de, it, pt) and the other nine to `async_flash_v1.0` only, and `nl` appears in neither the model page nor the HTTP reference's 15-code list. — *Needs a call: whether to warn per model, document the split, or leave the map model-agnostic.*

`async_flash_v1.5` is still Async's recommendation for voice agents, so the default stands. `async_pro_v1.0` remains English-only and quality-tier, not a real-time default candidate, and `Settings.model` is a free-form string with no allowlist, so all three are already selectable. No example or docstring pins a model string other than the default.

`probe.py` still cannot drive either class: `AsyncAIHttpTTSService` requires an `aiohttp_session` constructor argument, and `AsyncAITTSService` stalls because `TTSService._maybe_pause_frame_processing` holds frame processing until a `BotStoppedSpeakingFrame` the bare probe pipeline never emits. Both were probed instead through `run_test` (scripts in `.pw-scratch/asyncai_*_probe.py`), the websocket one sending the `BotStoppedSpeakingFrame` by hand. The stall is a harness limitation shared by every websocket TTS service with `pause_frame_processing=True`, not an Async defect.
