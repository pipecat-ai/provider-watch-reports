Findings that did not need a probe:

- **Catalogue shrank from 19 to 13 models.** Crusoe retired `zai/GLM-5.1`, `zai/GLM-5.2`, `deepseek-ai/DeepSeek-V3-0324`, `qwen/Qwen3-235B-A22B-Instruct-2507` and `meta-llama/Llama-3.3-70B-Instruct` on 2026-09-12 and `moonshotai/Kimi-K2.6` on 2026-10-02. `nvidia/Nemotron-3-Ultra-550B` is simply gone — absent from both the current table and the deprecation list. `deepseek-ai/DeepSeek-V4.1-Flash` (1M) is new and has no leaderboard row (the leaderboard's DeepSeek Flash row is the 0731 build).
- **Nothing in Pipecat references a retired model.** The default `openai/gpt-oss-120b` is still listed and carries no deprecation notice; `examples/function-calling/function-calling-crusoe.py` sets only `system_instruction`, so no model string can go stale there, and the service has no allowlist, model table or `Literal` — all 13 IDs work through `settings=CrusoeLLMService.Settings(model=...)`.
- **No `Settings` gap.** `BaseOpenAILLMService.Settings.extra` passes arbitrary provider parameters (GLM/Nemotron thinking controls, `reasoning_effort`) straight into the request, and Crusoe documents no parameter outside the OpenAI chat-completions schema.
- **Base URL and roles unchanged.** `api.inference.crusoecloud.com/v1` is still the documented endpoint, and `supports_developer_role = False` stays consistent with docs that show only `system`/`user`/`assistant`.
- **docs.pipecat.ai is in sync** — it documents `openai/gpt-oss-120b` and the standard OpenAI settings, matching the code.
