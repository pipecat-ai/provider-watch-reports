# Crusoe LLM — 2026-09-14

The default changed since the last run — `zai/GLM-5.2` → `openai/gpt-oss-120b` (#5656, merged 2026-09-09) — and the new default is the weakest voice-benchmark model on Crusoe's catalogue; a maintainer should pick a replacement from the three that now score at parity.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model quality** (high, since 2026-09-14) — `openai/gpt-oss-120b` passes 86.3% of aiewf-eval `aiwf_medium_context` (9.3% tool error, 13.0% instruction error). Crusoe's catalogue grew this fortnight and now includes three models at parity or better: `nvidia/Nemotron-3-Ultra-550B` (100.0% / 541 ms), `zai/GLM-5.3` (98.7% / 2376 ms) and `qwen/Qwen3.8-27B` (98.2% / 649 ms). #5656 switched the default off the deprecated `zai/GLM-5.2` (99.7% / 936 ms) without a benchmark row for the replacement, which #5447 made a condition of LLM default bumps. — *Needs a call: which of the three becomes the default — Nemotron-3-Ultra tops the leaderboard but is a 550B model, Qwen3.8-27B is the cheap fast option, GLM-5.3 continues the GLM lineage at 2.4 s TTFAT — and a working `CRUSOE_API_KEY`, since the benchmark rows were measured on other hosts and nothing can be probed on Crusoe today.*

`list-models` failed the same way (401 from `/v1/models`), for the second run in a row, so the catalogue above comes from Crusoe's docs. The 401 is a credential problem on our side, not a service defect — the request shape and `base_url` match the documented OpenAI-compatible endpoint.

Findings that did not need a probe:

- **Catalogue grew from 16 to 19 models**: `qwen/Qwen3.8-27B`, `zai/GLM-5.3` and `zai/GLM-5.3-Flash` are new (GLM-5.3 at 1M context). The last run recorded GLM-5.3 as upstream-only; Crusoe hosts it now. Nothing on the page is marked deprecated, retiring or preview — including `zai/GLM-5.2`, which #5656's description calls deprecated and which remains listed both here and in Z.AI's own lineup.
- **No allowlist to update.** The class is a thin `OpenAILLMService` subclass with no model table or `Literal`, so all 19 IDs are already usable via `settings=CrusoeLLMService.Settings(model=...)`.
- **No `Settings` gap.** `BaseOpenAILLMService.Settings.extra` passes arbitrary provider parameters (GLM/Nemotron thinking controls, `reasoning_effort`) straight into the request.
- **Base URL matches** the documented endpoint `api.inference.crusoecloud.com/v1`, and `supports_developer_role = False` stays consistent with the docs, which show only `system`/`user`/`assistant`.
- **Rate limits** are documented as HTTP 429 with a request-an-increase path; nothing the service needs to encode.
- **The example** `examples/function-calling/function-calling-crusoe.py` pins no model string, so nothing there can go stale.
- **docs.pipecat.ai is in sync**: it documents `openai/gpt-oss-120b` and the standard OpenAI settings, matching the code.
