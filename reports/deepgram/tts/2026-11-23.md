# Deepgram TTS — 2026-11-23

Current: `aura-2-helena-en` is served and unchanged, Deepgram shipped nothing for Aura on `/v1/speak` this window, and there is nothing to branch.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **SageMaker SDK pin is five releases behind** (medium, since 2026-10-12) — `pyproject.toml` pins `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` and PyPI has moved on to 0.13.1 (2026-11-18), with 0.10.0, 0.11.0, 0.12.0 and 0.13.0 in between; two of those landed this window. The package describes itself as experimental with breaking changes expected before 1.0.0, so the ceiling looks intentional rather than stale; the cost is that anyone who needs a newer SageMaker runtime for other reasons cannot also install `pipecat-ai[sagemaker]`. — *Needs a call: raising the ceiling needs a deployed endpoint to verify against, and the pin is shared with the Flux SageMaker classes, so it may want one owner rather than three units proposing it.*
- **`tag` is Flux-only** (medium, since 2026-09-01) — the REST `/v1/speak` reference still documents `tag` for labelling requests in usage reporting, and `DeepgramFluxTTSService` plus both Flux STT services already take `tag: list[str]`. Users who split Deepgram spend by workload can do it for Flux and for STT but not for Aura. The WebSocket reference lists only `model`, `encoding`, `sample_rate`, `speed` and `mip_opt_out`; an earlier ad-hoc connect with `tag=` synthesized normally, but so did one with an invented parameter name, so tolerance is not support. — *Needs a call: it means a new constructor argument, and whether a WebSocket `tag` is recorded can only be settled from the usage report.*
- **`extra` is dropped** (medium, since 2026-09-01) — `DeepgramTTSSettings` inherits `extra`, but `_connect_websocket` and the HTTP `run_tts` assemble their query from named fields only. `Settings(extra={"tag": "prod"})` is accepted, stored, and never sent, so there is no escape hatch for a parameter Pipecat has no field for — `tag`, `callback`, `callback_method` and `bit_rate` are all in the REST reference with no field here. — *Needs a call: forward undeclared keys to the query string unvalidated, or reject them at construction rather than dropping them silently.*
- **Settings `model` does nothing** (low, since 2026-09-01) — Deepgram's request parameter is `model` but these classes read it from `voice`; `_update_settings` syncs `model` from `voice` and not the reverse. A user who sets `model` gets a reconnect and the old voice, with no warning. — *Needs a call: alias `model` to `voice` the way `voice_id` already is, reject it, or document it as derived.*
- **SageMaker class is behind** (low, since 2026-09-01) — the cloud classes carry `speed` and `DeepgramSageMakerTTSSettings` is still `pass`; its `_update_settings` warns rather than reconnecting, so any setting would be construction-time only, and Deepgram's self-hosted notes require an April 2026 or later Aura-2 voice pack for `speed` (older packs return 400). — *Needs a call: a deployed endpoint to verify against, and whether the class should reconnect on settings changes first.*

The catalogue is unchanged from 2026-11-09: 103 entries (91 Aura-2, 12 Aura-1), architectures `aura` and `aura-2` only, with no additions or removals. Aura-2 is still the newest generation on `/v1/speak`, the docs carry no deprecation or retirement notice for either generation, and no example or test in this repo pins a voice string. The Aura WebSocket surface is also unchanged — the same five query parameters and the same Speak/Flush/Clear/Close client messages, still no `Configure` and still no pause or volume controls. Nothing in `src/pipecat/services/deepgram/tts.py` or the SageMaker TTS module changed since the last report.

Of the five changelog entries since 2026-10-27, the one that touches Aura is the 2026-11-23 GA of the US endpoint `api.us.deepgram.com`, which covers `/v1/speak`. It needs no code: both cloud classes already take `base_url`, and a probe through `wss://api.us.deepgram.com` synthesized normally on the first try (92 ms TTFB). `api.deepgram.com` is not deprecated, but after 2027-01-31 Deepgram may serve it from outside the US, so a deployment with a US data-residency requirement has to pass the regional `base_url` by then — which it can today. The rest are not Aura: 2026-11-20 adds per-request AWS Marketplace purchasing (Aura-2 included, but via x402/Bedrock rather than our API path), 2026-11-10 self-hosted 261110 covers Flux TTS shutdown and half-precision preloaded models, 2026-11-08 makes `normalize_volume` default on for Flux `/v2/speak` only, and the 2026-11-13 CLI release is `dg speak` flags. The voice-controls page still shows Aura-2 with `speed` (0.7–1.5) and GA pronunciation, and keeps pauses, mid-stream `Configure` speed and volume normalization on the Flux side.
