# Deepgram TTS — 2026-11-09

Current: `aura-2-helena-en` is served and unchanged, Deepgram published nothing for Aura on `/v1/speak` this window, and there is nothing to branch.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **SageMaker SDK pin is three releases behind** (medium, since 2026-10-12) — `pyproject.toml` pins `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` and PyPI is still at 0.12.0 (2026-10-08), with 0.10.0 and 0.11.0 in between; no new release this window. The package describes itself as experimental with breaking changes expected before 1.0.0, so the ceiling looks intentional rather than stale; the cost is that anyone who needs a newer SageMaker runtime for other reasons cannot also install `pipecat-ai[sagemaker]`. — *Needs a call: raising the ceiling needs a deployed endpoint to verify 0.12.0 against, and the pin is shared with the Flux SageMaker classes, so it may want one owner rather than three units proposing it.*
- **`tag` is Flux-only** (medium, since 2026-09-01) — the REST `/v1/speak` reference documents `tag` for labelling requests in usage reporting, and `DeepgramFluxTTSService` plus both Flux STT services already take `tag: list[str]`. Users who split Deepgram spend by workload can do it for Flux and for STT but not for Aura. The WebSocket reference still lists only `model`, `encoding`, `sample_rate`, `speed` and `mip_opt_out`; an earlier ad-hoc connect with `tag=` synthesized normally, but so did one with an invented parameter name, so tolerance is not support. — *Needs a call: it means a new constructor argument, and whether a WebSocket `tag` is recorded can only be settled from the usage report.*
- **`extra` is dropped** (medium, since 2026-09-01) — `DeepgramTTSSettings` inherits `extra`, but `_connect_websocket` and the HTTP `run_tts` assemble their query from named fields only. `Settings(extra={"tag": "prod"})` is accepted, stored, and never sent, so there is no escape hatch for a parameter Pipecat has no field for — including `callback`, whose verification scheme Deepgram changed on 2026-10-27. The STT service has the mirror-image problem: it forwards `extra` into an SDK call that raises on undeclared keys. — *Needs a call: forward undeclared keys to the query string unvalidated, or reject them at construction rather than dropping them silently.*
- **Settings `model` does nothing** (low, since 2026-09-01) — Deepgram's request parameter is `model` but these classes read it from `voice`; `_update_settings` syncs `model` from `voice` and not the reverse. A user who sets `model` gets a reconnect and the old voice, with no warning. — *Needs a call: alias `model` to `voice` the way `voice_id` already is, reject it, or document it as derived.*
- **SageMaker class is behind** (low, since 2026-09-01) — the cloud classes carry `speed` and `DeepgramSageMakerTTSSettings` is still `pass`; its `_update_settings` warns rather than reconnecting, so any setting would be construction-time only, and Deepgram's self-hosted notes require an April 2026 or later Aura-2 voice pack for `speed` (older packs return 400). — *Needs a call: a deployed endpoint to verify against, and whether the class should reconnect on settings changes first.*

The catalogue is 103 entries (91 Aura-2, 12 Aura-1), architectures `aura` and `aura-2` only — one more than the 2026-10-12 list. The addition is `aura-2-valentina-es`, which appears in `/v1/models` but not yet in the voice tables or the changelog; a probe synthesized with it unchanged, since our classes pass the voice string through with no allowlist. Aura-2 is still the newest generation on `/v1/speak`, with no deprecation or retirement notice for either generation, and no example or test in this repo pins a voice string.

Four changelog entries landed since 2026-10-12 and none needs code here. The 2026-10-27 callback change drops the `dg-token` header in favour of Basic Auth in the callback URL; it only affects `/v1/speak` requests that set `callback`, which Pipecat never does (and could not, per the `extra` gap). The 2026-10-20 self-hosted release improves Aura-2 Dutch and Portuguese reading and 8 kHz output server-side. The 2026-10-19 SDK/CLI round-up is Flux TTS, Voice Agent and Nova-3; the two 2026-10-23 entries are Nova-3 only. The Aura WebSocket surface is unchanged: the same five query parameters and the same Speak/Flush/Clear/Close client messages, still no `Configure` and still no pause markers.

Method, for the next researcher: `probe.py run --service DeepgramTTSService` now completes normally — the hang the 2026-10-12 report described (no `BotStoppedSpeakingFrame`, so `pause_frame_processing=True` latched and the `EndFrame` never drained) no longer reproduces, so no `timeout` wrapper or `--verbose` log scraping is needed. `DeepgramHttpTTSService` still takes a required `aiohttp_session` that `probe.py` cannot supply, so exercising it needs an ad-hoc `run_test` script; `probe.py list-models --provider deepgram` still returns only STT names, so the TTS catalogue came from a one-call scratch script against `/v1/models`.
