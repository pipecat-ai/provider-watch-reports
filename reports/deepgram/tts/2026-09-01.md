# Deepgram TTS — 2026-09-01

`aura-2-helena-en` is current — Aura-2 remains Deepgram's recommended Aura generation and the Flux TTS launch left `/v1/speak` alone — and the one shippable change is a `speed` setting, on a branch.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5552 — Add a speed setting to the Deepgram Aura TTS services

Deepgram shipped Aura-2 speed control in April 2026 and documents it on both `/v1/speak` transports: a multiplier from 0.7 to 1.5 (0.9 and up recommended for Spanish), billed the same. It was unreachable from Pipecat — the Aura classes have no field for it and never read `extra` — while the Flux TTS services have carried their own `speed` since they landed. The field is optional and unset by default, so a request is unchanged unless a user sets it, and Deepgram validates the range (probed below).

### To consider

- **`tag` is Flux-only** (medium, since 2026-09-01) — the REST `/v1/speak` reference documents `tag` for labelling requests in usage reporting, and `DeepgramFluxTTSService` plus both Flux STT services already take `tag: list[str]` and append one `tag=` per value. Users who split Deepgram spend by workload can do it for Flux and for STT but not for Aura. — *Needs a call: it means a new constructor argument, and the Aura WebSocket reference does not list `tag`, so WebSocket support has to be confirmed first.*
- **`extra` is dropped** (medium, since 2026-09-01) — `DeepgramTTSSettings` inherits `extra`, but `_connect_websocket` and the HTTP `run_tts` assemble their query from named fields only. `Settings(extra={"tag": "prod"})` is accepted, stored, and never sent, so there is no escape hatch for a parameter Pipecat has no field for. The STT service has the mirror-image problem: it forwards `extra` into an SDK call that raises on undeclared keys. — *Needs a call: forward undeclared keys to the query string unvalidated, or reject them at construction rather than dropping them silently.*
- **Settings `model` does nothing** (low, since 2026-09-01) — Deepgram's request parameter is `model` but these classes read it from `voice`; `_update_settings` syncs `model` from `voice` and not the reverse. A user who sets `model` gets a reconnect and the old voice, with no warning. — *Needs a call: alias `model` to `voice` the way `voice_id` already is, reject it, or document it as derived.*
- **SageMaker class is behind** (low, since 2026-09-01) — `DeepgramSageMakerTTSService` builds the same query string and would take `speed` the same way, but its `_update_settings` warns rather than reconnecting, so any setting is construction-time only, and Deepgram's self-hosted notes require an April 2026 or later Aura-2 voice pack for `speed` (older packs return 400). — *Needs a call: a deployed endpoint to verify against, and whether the class should reconnect on settings changes first.*

Flux TTS went GA on the new `/v2/speak` endpoint (36 English voices, `flux-{voice}-en`) and is now the Voice Agent API default; `DeepgramFluxTTSService` already covers it, and Deepgram states existing Aura `/v1/speak` code keeps working. Aura-1 voices (`aura-*-en`) are still served with no deprecation notice, and the catalogue's newest additions are Aura-2 voices in French, Italian, Dutch, German, Spanish and Japanese, all reachable today since neither class gates the voice string. Pause controls are still listed as "coming soon"; pronunciation overrides are inline text markup, not a request parameter.

| aura-2-helena-en, `speed=2.5`  | DeepgramHttpTTSService (branch)| ❌ | —           | HTTP 400 `'speed' must be within documented range.`, surfaced as an `ErrorFrame`           |

Method, for the next researcher: `probe.py run --service DeepgramTTSService` never returns on a *successful* WebSocket synthesis — with no output transport there is no `BotStoppedSpeakingFrame`, so the service's `pause_frame_processing=True` latches and the `EndFrame` never drains — so the WebSocket rows are read from the run's own metrics under a shell `timeout` (a failing connect returns normally, as the `speed=2.5` row shows). `DeepgramHttpTTSService` takes a required `aiohttp_session`, which `probe.py` cannot supply, so its rows come from an ad-hoc `run_test` script in the scratch dir. Branch rows were probed from the worktree so its sources win.
