# Deepgram TTS — 2026-10-12

Current: `aura-2-helena-en` is served and unchanged, Deepgram shipped nothing for Aura on `/v1/speak` this window, and there is nothing to branch.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **SageMaker SDK pin is three releases behind** (medium, since 2026-10-12) — `pyproject.toml` pins `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` and PyPI is at 0.12.0 (2026-10-08), with 0.10.0 and 0.11.0 in between. The package describes itself as experimental with breaking changes expected before 1.0.0, so the ceiling looks intentional rather than stale; the cost is that anyone who needs a newer SageMaker runtime for other reasons cannot also install `pipecat-ai[sagemaker]`. — *Needs a call: raising the ceiling needs a deployed endpoint to verify 0.12.0 against, and the pin is shared with the Flux SageMaker classes, so it may want one owner rather than three units proposing it.*
- **`tag` is Flux-only** (medium, since 2026-09-01) — the REST `/v1/speak` reference documents `tag` for labelling requests in usage reporting, and `DeepgramFluxTTSService` plus both Flux STT services already take `tag: list[str]`. Users who split Deepgram spend by workload can do it for Flux and for STT but not for Aura. An ad-hoc WebSocket connect with `tag=` synthesized normally — but so did one with an invented parameter name, so the Aura WebSocket simply ignores query keys it does not know, and tolerance is not support. — *Needs a call: it means a new constructor argument, and whether a WebSocket `tag` is recorded can only be settled from the usage report.*
- **`extra` is dropped** (medium, since 2026-09-01) — `DeepgramTTSSettings` inherits `extra`, but `_connect_websocket` and the HTTP `run_tts` assemble their query from named fields only. `Settings(extra={"tag": "prod"})` is accepted, stored, and never sent, so there is no escape hatch for a parameter Pipecat has no field for. The STT service has the mirror-image problem: it forwards `extra` into an SDK call that raises on undeclared keys. — *Needs a call: forward undeclared keys to the query string unvalidated, or reject them at construction rather than dropping them silently.*
- **Settings `model` does nothing** (low, since 2026-09-01) — Deepgram's request parameter is `model` but these classes read it from `voice`; `_update_settings` syncs `model` from `voice` and not the reverse. A user who sets `model` gets a reconnect and the old voice, with no warning. — *Needs a call: alias `model` to `voice` the way `voice_id` already is, reject it, or document it as derived.*
- **SageMaker class is behind** (low, since 2026-09-01) — the cloud classes carry `speed` and `DeepgramSageMakerTTSSettings` is still `pass`; its `_update_settings` warns rather than reconnecting, so any setting would be construction-time only, and Deepgram's self-hosted notes require an April 2026 or later Aura-2 voice pack for `speed` (older packs return 400). — *Needs a call: a deployed endpoint to verify against, and whether the class should reconnect on settings changes first.*

The catalogue is byte-for-byte the 2026-09-14 list — 102 entries, 90 Aura-2 and 12 Aura-1, architectures `aura` and `aura-2` only — and none of it is gated by our classes, which pass the voice string through. Aura-2 is still the newest generation on `/v1/speak` with no retirement notice for either generation.

Three changelog entries touched TTS in this window and none needs code here. Aura-2 pronunciation went from Early Access to generally available with published limits (500 overrides per request, 128-character IPA, 2000-character input); `format_deepgram_pronunciation` already enforces the 128-character cap, and the stress-before-vowel rule it implements is still what Deepgram documents. The 2026-09-15 India endpoint (`api.in.deepgram.com`, GA, `/v1/speak` included) is reachable today by passing `base_url`, so it needs nothing. The 2026-10-01 self-hosted release improves Aura-2 German and Japanese number and date reading server-side, and its Flux watermarker requirement is operator-side configuration for `/v2/speak`. The 2026-09-30 pause markers and the 2026-09-14 SDK expressivity control are both Flux (`/v2/speak`) and belong to the Flux classes; the same SDK release dropped `aura-2-perseo-it`, which never appeared in this repo. Aura-2 still has no pause markers and no mid-stream `Configure`.

Method, for the next researcher: `probe.py run --service DeepgramTTSService` never returns on a *successful* WebSocket synthesis — with no output transport there is no `BotStoppedSpeakingFrame`, so the service's `pause_frame_processing=True` latches and the `EndFrame` never drains. Run it under a shell `timeout` **with `--verbose`**, redirect to a file (a pipe into `tail` loses the buffer when the timeout kills it), and read TTFB/TTFA from the service's own log lines. `DeepgramHttpTTSService` takes a required `aiohttp_session`, which `probe.py` cannot supply, so it needs an ad-hoc `run_test` script; `run_test` asserts the received frame count against `expected_down_frames`, so either enumerate them or read the `received DOWN frames = [...]` line it logs before the assertion, and note it leaves metrics off so there is no TTFB.
