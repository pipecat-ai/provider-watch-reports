# Deepgram STT — 2026-10-12

`nova-3-general` is still Deepgram's general-purpose model, but `diarize` is now deprecated in Deepgram's own reference and Pipecat sends it on every connection, which makes the replacement unusable.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **`diarize` is deprecated and blocks `diarize_model`** (high, since 2026-08-25) — Deepgram's `/v1/listen` reference now marks `diarize` "deprecated in favor of `diarize_model`", and the diarization docs say setting both parameters in one request is rejected. Both Pipecat classes hardcode `diarize=False` into their default settings, so `diarize=false` goes out on every connection: a user who reaches for the replacement through the documented escape hatch, `extra={"diarize_model": "latest"}`, gets a 400 at the handshake, which `_connection_handler` treats as permanent and retires the service. `diarize_model=latest` on its own connects fine. `Settings(diarize=None, extra={"diarize_model": "latest"})` also works, but `None` is outside the field's declared `bool | NotGiven` type. On self-hosted deployments from `release-260514` only the v2 diarizer ships, so `diarize=true` there returns no speaker labels. — *Needs a call: drop `diarize` from the default request and add a `diarize_model` field, or map `diarize=True` onto `diarize_model="v1"` and deprecate the field outright.*
- **`extra`/`addons` passthrough is broken for undeclared params** (high, since 2026-08-25) — `_build_connect_kwargs` spreads `extra` and `addons` into `client.listen.v1.connect(**kwargs)`, whose signature is exactly the AsyncAPI query-param list. `Settings(extra={"filler_words": "true"})` raises `AsyncV1Client.connect() got an unexpected keyword argument 'filler_words'`, is retried three times and then permanently retires the service. Deepgram documents `filler_words` and `measurements` for streaming Nova, so both are unreachable from this class; the SageMaker class, which builds its own query string, accepts them. The SDK spreads `request_options["additional_query_parameters"]` into the WebSocket URL, so undeclared keys could be routed there. — *Needs a call: forward undeclared keys to Deepgram unvalidated, or reject them at construction rather than failing mid-run.*
- **Deepgram's endpointing events are dropped** (medium, since 2026-09-01) — `_on_message` handles only `ListenV1Results`, while the `/v1/listen` AsyncAPI spec also publishes `ListenV1UtteranceEnd`, `ListenV1SpeechStarted` and `ListenV1Metadata`. `utterance_end_ms` is a documented Settings field, so a user can set it, see it in the request, and get nothing back: Pipecat ends turns from VAD plus a `Finalize` message instead. — *Needs a call: whether Deepgram's own endpointing signals should feed turn-taking, or whether the setting should be documented as inert.*
- **Keyterm updates still reconnect** (medium, since 2026-10-12) — Deepgram's 2026-10-02 release added a `Configure` client message to `/v1/listen` that swaps the Nova-3 keyterm list mid-stream. `_update_settings` reconnects on any settings change, so a keyterm swap costs a full WebSocket round trip and the audio buffered across it. deepgram-sdk 7.12.0 still generates `Configure` for Listen v2 only, so v1 would need a hand-written JSON frame; the feature is also limited to `api.deepgram.com` today. — *Needs a call: hand-roll the v1 frame now or wait for the SDK, given the regional limitation.*
- **`vad_events` undeclared in Settings** (low, since 2026-08-25) — accepted by `connect()` and reachable through `extra`, so this is discoverability only, and the `SpeechStarted` messages it produces are the ones the item above says are dropped. — *Needs a call: whether `vad_events` is worth a field before its event is handled.*

`nova-3-pharma` (2026-09-17) is the one new model in the catalogue; `model` is a free-form string with no allowlist, so it works today — probed below. Nova-3 Medical gained `language=multi` on 2026-10-06; `STTSettings.language` is typed `Language | str | None`, so `language="multi"` passes straight through even though there is no `Language` member for it. The India endpoint (`api.in.deepgram.com`) went GA on 2026-09-15 and is reachable through `base_url`. Everything else since the last run is Flux or Voice Agent work, which belongs to other units. The previous report's third gap has been split: its `diarize_model` half is the high item above, its `vad_events` half the low one.
