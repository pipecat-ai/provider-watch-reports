# Deepgram STT — 2026-09-01

`nova-3-general` is still Deepgram's recommended general model; the one change worth shipping is a `version` field so users can pin a model build, and the `extra` passthrough is still broken for anything the SDK doesn't declare.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5527 — Add a `version` Settings field to the Deepgram STT services

Deepgram refreshes models in place: on 2026-08-28 it shipped improved Nova-3 monolingual models for ten languages with "you do not need to change your API requests to access these improvements." `version` is the documented way to hold a build steady, and it was reachable only through `extra`. The field is optional and unset by default, and both classes build their query from the settings fields, so it also reaches the SageMaker endpoint.

### To consider

- **`extra`/`addons` passthrough is broken for undeclared params** (high, since 2026-08-25) — `_build_connect_kwargs` spreads `extra` and `addons` into `client.listen.v1.connect(**kwargs)`, whose signature is exactly the AsyncAPI query-param list. `Settings(extra={"filler_words": "true"})` raises `AsyncV1Client.connect() got an unexpected keyword argument 'filler_words'`, is retried three times and then permanently retires the service (re-probed below). Deepgram documents `filler_words` and `measurements` for streaming Nova, so both are unreachable from this class; the SageMaker class, which builds its own query string, accepts them. The SDK spreads `request_options["additional_query_parameters"]` into the WebSocket URL, so undeclared keys could be routed there. — *Needs a call: forward undeclared keys to Deepgram unvalidated, or reject them at construction rather than failing mid-run.*
- **Deepgram's endpointing events are dropped** (medium, since 2026-09-01) — `_on_message` handles only `ListenV1Results`, while the `/v1/listen` AsyncAPI spec also publishes `ListenV1UtteranceEnd` and `ListenV1SpeechStarted`. `utterance_end_ms` is a documented Settings field, so a user can set it, see it in the request, and get nothing back: Pipecat ends turns from VAD plus a `Finalize` message instead. — *Needs a call: whether Deepgram's own endpointing signals should feed turn-taking, or whether the setting should be documented as inert.*
- **`diarize_model` and `vad_events` undeclared in Settings** (low, since 2026-08-25) — both are accepted by `connect()` and reach Deepgram through `extra` today, so this is discoverability only. `diarize_model` picks the streaming diarizer and enables diarization on its own; `vad_events` only produces the `SpeechStarted` messages the item above says are dropped. — *Needs a call: how `diarize_model` should combine with `diarize`, and whether `vad_events` is worth a field before its event is handled.*

Deepgram's Flux models are served by `DeepgramFluxSTTService` (a separate unit); the 2026-08-28 Flux turn-taking release (`ForceEndTurn`, `eot_threshold=1.0`) belongs to that unit. `DeepgramSageMakerSTTService` was not probed: it needs a deployed SageMaker endpoint.
