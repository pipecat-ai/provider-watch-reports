# Deepgram STT — 2026-11-09

`nova-3-general` is still Deepgram's general-purpose recommendation; the one new request parameter since the last run, `language_hint`, is on a branch, and the `diarize` deprecation that blocks `diarize_model` is unchanged.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6665 — Add a language_hint Settings field to the Deepgram STT services

### To consider

- **`diarize` is deprecated and blocks `diarize_model`** (high, since 2026-08-25) — the `/v1/listen` reference still marks `diarize` "Deprecated. Use `diarize_model` instead.", and setting both parameters in one request is rejected. Both Pipecat classes hardcode `diarize=False` into their default settings, so `diarize=false` goes out on every connection: a user who reaches for the replacement through `extra={"diarize_model": "latest"}` gets a 400 at the handshake, which `_connection_handler` treats as permanent and retires the service. Re-probed on deepgram-sdk 7.17.0, which declares `diarize_model` in `connect()` — the failure is Deepgram's, not the SDK's. — *Needs a call: drop `diarize` from the default request and add a `diarize_model` field, or map `diarize=True` onto `diarize_model="v1"` and deprecate the field outright.*
- **`extra`/`addons` passthrough is broken for undeclared params** (high, since 2026-08-25) — `_build_connect_kwargs` spreads `extra` and `addons` into `client.listen.v1.connect(**kwargs)`, whose signature is exactly the AsyncAPI query-param list; an undeclared key raises TypeError, is retried three times and then permanently retires the service. On 7.17.0 that list has gained `diarize_model` and `language_hint` but still lacks `filler_words`, `measurements`, `keyterms` and the new `redact_usage`, so all four are unreachable from this class while the SageMaker class accepts them. The SDK spreads `request_options["additional_query_parameters"]` into the WebSocket URL, so undeclared keys could be routed there. — *Needs a call: forward undeclared keys to Deepgram unvalidated, or reject them at construction rather than failing mid-run.*
- **Keyterm updates still reconnect** (medium, since 2026-10-12) — both reasons this sat still last run have gone away: deepgram-sdk 7.13.0 put `send_configure` on the Listen v1 socket client (7.14.0 added the typed `ConfigureSuccess`/`ConfigureFailure` replies), and Deepgram extended mid-stream keyterm updates to the EU, AU and IN endpoints on 2026-10-19. `_update_settings` still reconnects on any settings change, so a keyterm swap costs a full WebSocket round trip and the audio buffered across it; `features` would also toggle `numerals` in place. This is a change to how `_update_settings` dispatches, not a pass-through, so it stays a maintainer's call. — *Needs a call: route keyterm and numerals through `Configure` and reconnect only for the rest, and decide what a `ConfigureFailure` should do.*
- **Deepgram's endpointing and Configure events are dropped** (medium, since 2026-09-01) — `_on_message` handles only `ListenV1Results`, while the SDK exports `ListenV1UtteranceEnd`, `ListenV1SpeechStarted`, `ListenV1Metadata`, `ListenV1Error` and the two Configure replies. `utterance_end_ms` is a documented Settings field, so a user can set it, see it in the request, and get nothing back. The item above also depends on reading a reply message. — *Needs a call: whether Deepgram's own endpointing signals should feed turn-taking, or whether the setting should be documented as inert.*
- **`vad_events` undeclared in Settings** (low, since 2026-08-25) — accepted by `connect()` and reachable through `extra`, so this is discoverability only, and the `SpeechStarted` messages it produces are the ones the item above says are dropped. — *Needs a call: whether `vad_events` is worth a field before its event is handled.*

The STT catalogue is unchanged since 2026-10-12. Nova-3 multilingual went from 10 to 55 languages on 2026-10-23 (`language="multi"` already passes through; the 10-language model can be pinned with the existing `version` field), and `numerals` gained Japanese the same day. Deepgram dropped `dg-token` callback verification on 2026-10-27, which Pipecat never sent. Self-hosted `release-261001` removes Whisper, but the hosted `whisper-*` models are still in the catalogue and carry no retirement date. Everything else is Flux or Voice Agent work, which belongs to other units.

The branch's field needs deepgram-sdk 7.15.0 or later, where `connect()` declares `language_hint`; our pin is `>=6.1.1,<8`, so the field's docstring states the requirement rather than raising the floor. It is unset by default, so nothing changes for a user who does not set it.
