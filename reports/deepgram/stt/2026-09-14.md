# Deepgram STT — 2026-09-14

Nothing to review: `nova-3-general` is still Deepgram's recommended general model, PR #5527 merged, and the three carried-forward items all still need a maintainer's call.

## What's new for Pipecat

### PRs

Nothing.

PR #5527 (the `version` Settings field) merged on 2026-09-03; `version` is now a declared field on both classes and the gap is closed.

### To consider

- **`extra`/`addons` passthrough is broken for undeclared params** (high, since 2026-08-25) — `_build_connect_kwargs` spreads `extra` and `addons` into `client.listen.v1.connect(**kwargs)`, whose signature is exactly the AsyncAPI query-param list. `Settings(extra={"filler_words": "true"})` raises `AsyncV1Client.connect() got an unexpected keyword argument 'filler_words'`, is retried three times and then permanently retires the service. Deepgram documents `filler_words` and `measurements` for streaming Nova, so both are unreachable from this class; the SageMaker class, which builds its own query string, accepts them. The SDK spreads `request_options["additional_query_parameters"]` into the WebSocket URL, so undeclared keys could be routed there. — *Needs a call: forward undeclared keys to Deepgram unvalidated, or reject them at construction rather than failing mid-run.*
- **Deepgram's endpointing events are dropped** (medium, since 2026-09-01) — `_on_message` handles only `ListenV1Results`, while the `/v1/listen` AsyncAPI spec also publishes `ListenV1UtteranceEnd`, `ListenV1SpeechStarted` and `ListenV1Metadata`. `utterance_end_ms` is a documented Settings field, so a user can set it, see it in the request, and get nothing back: Pipecat ends turns from VAD plus a `Finalize` message instead. — *Needs a call: whether Deepgram's own endpointing signals should feed turn-taking, or whether the setting should be documented as inert.*
- **`diarize_model` and `vad_events` undeclared in Settings** (low, since 2026-08-25) — both are accepted by `connect()` and reach Deepgram through `extra` today, so this is discoverability only. `diarize_model` picks the streaming diarizer and enables diarization on its own; `vad_events` only produces the `SpeechStarted` messages the item above says are dropped. — *Needs a call: how `diarize_model` should combine with `diarize`, and whether `vad_events` is worth a field before its event is handled.*

Deepgram's 2026-09-03 release added Kazakh to Nova-3 and improved eight more languages; no request change is needed and `Language.KK` already resolves to `kk`, which `_build_connect_kwargs` passes straight through. The 2026-09-08 release is Voice Agent API only (`defer_until_eot`, `FunctionCallCancelled`) and does not touch `/v1/listen`. Deepgram's Flux models are served by `DeepgramFluxSTTService` (a separate unit). `DeepgramSageMakerSTTService` was not probed: it needs a deployed SageMaker endpoint.
