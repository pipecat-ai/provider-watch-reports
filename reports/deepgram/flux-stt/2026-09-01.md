# Deepgram Flux STT — 2026-09-01

`flux-general-en` remains Deepgram's English Flux model and stays the default; the branch adds the two documented formatting parameters the service cannot express, and Deepgram's 2026-08-28 turn-control release is the one item needing a decision.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5523 — Expose Flux's profanity_filter and redact settings

### To consider

- **`ForceEndTurn` has no entry point** (medium, since 2026-09-01) — Deepgram shipped manual turn control on 2026-08-28: `{"type": "ForceEndTurn"}` ends the active turn immediately, `eot_threshold=1.0` suppresses native detection entirely, and the two combine into "bring your own turn detection". Pipecat can already set `eot_threshold` to 1.0 and both transports have `_transport_send_json`, but nothing sends the message, so the mode is unreachable. `EndOfTurn` now also carries `trigger` (`model` / `manual` / `timeout`), reachable only by digging into `TranscriptionFrame.result`. — *Needs a call: whether this becomes a public service method, a new frame, or an integration with the user-turn strategies — that choice decides how an external turn detector drives Flux.*
- **Stale constructor docstrings** (low, since 2026-09-01) — `DeepgramFluxSTTService.__init__` documents `url` as "the preview endpoint" although `wss://api.deepgram.com/v2/listen` is Flux's GA endpoint, and both `flux_encoding` docstrings say the encoding "Must be `linear16`" while Flux documents linear16, linear32, mulaw, alaw, opus and ogg-opus. — *Needs a call: whether Flux should accept the other encodings at all, given Pipecat transports always hand the service linear16 PCM.*

`DeepgramFluxSageMakerSTTService` was not probed: it needs a deployed SageMaker endpoint. It shares `DeepgramFluxSTTBase._build_query_string`, so the branch covers it too. Deepgram's model catalogue endpoint still omits Flux entirely, so `models_seen` comes from the docs.

TTFB here is dominated by the fixture's leading silence — Flux reports a turn only at `EndOfTurn` — so it is a liveness signal, not a latency comparison. Flux confirms a connection with a `Connected` message and stays silent when it rejects a query parameter, so a successful connect is evidence the new parameters were accepted.
