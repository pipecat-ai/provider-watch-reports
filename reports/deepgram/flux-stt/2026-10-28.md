# Deepgram Flux STT — 2026-10-28

Nothing in Flux's October changes needs Pipecat code; `flux-general-en` stays the default and both models probe clean.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5584 — Add manual turn finalization to Deepgram Flux STT (open since 2026-09-01; adds a `turn_detection` mode and a public `force_end_turn()`, which is what the `ForceEndTurn` gap asks for). Deepgram's 2026-10-20 self-hosted release makes `ForceEndTurn` work on every `/v2/listen` stream with no feature flag, so the PR now applies to self-hosted deployments too.

### To consider

- **SageMaker SDK pin is behind** (medium, since 2026-10-12) — `pyproject.toml` still pins `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` while PyPI is at 0.12.0 (2026-10-08, unchanged since last run), so an application already on 0.10+ cannot resolve `pipecat-ai[deepgram,sagemaker]`. AWS ships no release notes for the package; separately, `pipecat.services.aws.sagemaker.bidi_client` imports the deprecated `SageMakerRuntimeHTTP2Client` alias, which the SDK says to replace with `AsyncSageMakerRuntimeHTTP2Client`. — *Needs a call: the pin covers every SageMaker service, and with no changelog for a 0.x preview, widening it means running the AWS BiDi services against 0.12.0 first.*
- **`flux_encoding` overstates Flux's constraint** (low, since 2026-09-01) — both constructors document the encoding as "Must be `linear16`", while the `/v2/listen` reference accepts linear16, linear32, mulaw, alaw, opus and ogg-opus. The default is still the only workable value in Pipecat, since transports deliver linear16 PCM. — *Needs a call: whether Flux should accept the other encodings at all; if not, the wording should attribute the constraint to Pipecat rather than to Flux.*

PR 6124 merged on 2026-10-12, closing the numerals-via-Configure gap; `numerals` is in `_CONFIGURE_FIELDS` and `_send_configure` on this commit. Deepgram's only Flux STT entry since then is 2026-10-23, which extends `numerals` formatting to Japanese on `flux-general-multi` — a server-side change that needs nothing from Pipecat, and no Pipecat docstring claims otherwise. The `/v2/listen` query parameters, the Configure field set and the two model names are all unchanged from last run and all reachable from `Settings` or the constructor; `language_to_deepgram_flux_language` still covers exactly the ten languages `flux-general-multi` lists. October's other Deepgram entries — Nova-3 Multilingual at 55 languages, Nova-3 Medical models, mid-stream keyterms and the 10-08 over-limit-keyterm correction — are all `/v1/listen` and belong to the Nova unit; the 10-01 self-hosted entry is Flux TTS. `DeepgramFluxSageMakerSTTService` was not probed: it needs a deployed SageMaker endpoint. No decisions file exists for this unit, and the digest comments name no Deepgram item.
