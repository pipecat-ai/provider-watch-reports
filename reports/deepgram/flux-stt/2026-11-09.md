# Deepgram Flux STT — 2026-11-09

Deepgram shipped nothing new for Flux STT this cycle; the one finding is a long-standing omission — `redact_usage`, which Flux takes both on the connection and in a Configure message, has no `Settings` field. Branch ready.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6668 — Expose Deepgram Flux's redact_usage setting
- https://github.com/pipecat-ai/pipecat/pull/5584 — Add manual turn finalization to Deepgram Flux STT (open since 2026-09-01; adds a `turn_detection` mode and a public `force_end_turn()`, which is what the `ForceEndTurn` gap asks for)

### To consider

- **SageMaker SDK pin is behind** (medium, since 2026-10-12) — `pyproject.toml` still pins `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` while PyPI is at 0.12.0 (2026-10-08, unchanged since last run), so an application already on 0.10+ cannot resolve `pipecat-ai[deepgram,sagemaker]`. AWS ships no release notes for the package; separately, `pipecat.services.aws.sagemaker.bidi_client` imports the deprecated `SageMakerRuntimeHTTP2Client` alias. — *Needs a call: the pin covers every SageMaker service, and with no changelog for a 0.x preview, widening it means running the AWS BiDi services against 0.12.0 first.*
- **`flux_encoding` overstates Flux's constraint** (low, since 2026-09-01) — both constructors document the encoding as "Must be `linear16`", while the `/v2/listen` reference accepts linear16, linear32, mulaw, alaw, opus and ogg-opus. The default is still the only workable value in Pipecat, since transports deliver linear16 PCM. — *Needs a call: whether Flux should accept the other encodings at all; if not, the wording should attribute the constraint to Pipecat rather than to Flux.*

Deepgram's changelog has no entry newer than 2026-10-27, and that one (callback verification moving off the `dg-token` header to Basic Auth) is about callback servers, which Flux STT's streaming service does not use. The 2026-10-20 self-hosted release and the 2026-10-23 Japanese-numerals entry were both covered last run and still need no code. The `/v2/listen` reference, the Configure field set and the two model names are unchanged; `language_to_deepgram_flux_language` still covers exactly the ten languages `flux-general-multi` lists, and neither model is deprecated or singled out as the successor to the other. `redact_usage` is the one parameter in that reference Pipecat never exposed — earlier reports saw it only in the `ConfigureSuccess` echo and read it as read-only, but the reference lists it as a query parameter and the Configure page lists it as a settable field. `DeepgramFluxSageMakerSTTService` was not probed: it needs a deployed SageMaker endpoint. No decisions file exists for this unit, and the digest comments name no Deepgram item.

TTFB is dominated by the fixture's leading silence — Flux reports a turn only at `EndOfTurn` — so it is a liveness signal, not a latency measurement.

An ad-hoc WebSocket check (`.pw-scratch/adhoc/flux_configure_redact_usage.py`, one connection) sent `{"type": "Configure", "redact_usage": true}` to `/v2/listen?model=flux-general-en`: Flux answered `ConfigureSuccess` with `redact_usage: true` in the active configuration, confirming the mid-stream half of the branch. `probe.py` cannot drive a settings update mid-stream, hence the script.
