# Deepgram Flux TTS — 2026-10-12

Deepgram gave Flux inline IPA pronunciation on 2026-09-30; our docstring still says Flux has no pronunciation markup (branch ready), and actually emitting the markup is the one new decision for a maintainer. Everything else carries over.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6125 — Document Flux TTS's pronunciation markup and its speed constraint

### To consider

- **Pronunciation hints are still spoken as written** (medium, since 2026-10-12) — Flux streaming now applies the same escaped `\{"word": …, "pronounce": …\}` object Aura-2 takes; a live turn with the markup `format_deepgram_pronunciation` builds came back `controls_applied: {pronunciations_applied: 1, breaks_applied: 0, pronunciation_warnings: 0}`, so Aura-2's IPA normalization passes Flux's validator unchanged. Support would be the Aura-2 `format_pronunciation` override plus a `supports_pronunciations` gate, since the control is incompatible with `speed`. — *Needs a call: whether to emit an Early-Access control whose misuse is fatal — the same text on a `speed=1.1` connection ends the session with `Error DATA-0002`, and a `Configure` speed over a queued pronunciation turn is `CONTROL_COMBINATION_INVALID`.*
- **`Interrupt` carries no `playback_offset`** (medium, since 2026-09-01) — Deepgram's barge-in pattern is: stop playback locally, then send `{"type": "Interrupt", "playback_offset": {"type": "time_ms", "value": <session ms played>}}`, and Flux answers with `text_spoken` / `text_remaining` so the LLM context matches what the user actually heard. `on_audio_context_interrupted` sends a bare `Interrupt`, so the server omits both fields and `audio_played_ms` degrades to its own generated-audio total. The offset is cumulative from the start of the *session* and each one must advance past the previous, or Flux rejects it with `INVALID_INTERRUPT_OFFSET`. — *Needs a call: whether Pipecat can give the service a session-cumulative played-ms counter, and whether Flux's `text_spoken` should override the assistant aggregator's own account of what was spoken.*
- **SageMaker SDK pin and deprecated client alias** (medium, since 2026-10-12) — `aws_sdk_sagemaker_runtime_http2` is pinned `>=0.6.0,<0.10` while PyPI is at 0.12.0 (2026-10-08), and the 0.9.0 we resolve warns that `SageMakerRuntimeHTTP2Client`, the name `src/pipecat/services/aws/sagemaker/bidi_client.py` imports, is a deprecated alias for `AsyncSageMakerRuntimeHTTP2Client` that will be removed. The SDK is pre-1.0 and warns of breaking changes, so the ceiling is deliberate. — *Needs a call: someone with a deployed SageMaker endpoint to verify the BiDi client against 0.12 before the pin widens and the import changes; the item is shared with Flux STT and the Aura SageMaker services.*
- **Ignored-`Interrupt` warning is noisy** (low, since 2026-09-01) — the quiet path in `_handle_message` is keyed on `NO_ACTIVE_SPEECH` alone; an `Interrupt` with nothing to interrupt — a barge-in in the first moments of a turn — is `NO_AUDIO_GENERATED` and reaches `logger.warning`. The code list has grown again with the inline-control warnings, which take the same path, so a decision here should cover the code-by-code levels rather than one code. — *Needs a call: whether an ignored `Interrupt` should be quiet at all, since `INTERRUPT_IN_PROGRESS` is also an ignored barge-in and there a warning is arguably the right level.*
- **No batch REST path** (low, since 2026-09-01) — the same Flux voices are served by `POST /v2/speak` with mp3/opus/flac/aac output, and batch is the only transport that takes inline pause markers (`\{pause:1s\}`, 500–3000 ms). `DeepgramHttpTTSService` speaks `/v1/speak` only, which rejects `flux-*` model strings. — *Needs a call: whether a batch Flux path is wanted at all, given the streaming class already covers the live-agent case.*

Checked and clean: the streaming query-parameter set is unchanged (`model`, `encoding`, `sample_rate`, `speed`, `expressivity`, `mip_opt_out`, `tag`), all seven reachable; `speed` is still 0.5–1.5 and still the only `Configure`-settable field, matching `_CONFIGURE_FIELDS`; `expressivity` is still −2…2, beta, fixed for the connection; `SUPPORTED_SAMPLE_RATES` still matches the `linear16` list; the catalogue is the same 36 `flux-*-en` voices, English only. Inline pause is batch-only and fails the streaming connection, so there is nothing to add there. Deepgram's self-hosted 261001 release adds a Flux TTS watermarker model file, which is a deployment requirement for self-hosted/SageMaker images, not a Pipecat code change. `DeepgramFluxSageMakerTTSService` was not probed — it needs a deployed endpoint — but it shares `_build_query_string` and all message handling with the WebSocket class. The previous run's only PR, #5740, merged on 2026-09-14, so the speed-range gap is closed.
