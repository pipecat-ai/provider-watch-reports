# Deepgram Flux TTS — 2026-11-09

Flux's `/v2/speak` documents a `normalize_volume` parameter that `Settings` could not reach; the branch adds it, and nothing else about Flux moved since the last run.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6669 — Expose Flux TTS's normalize_volume setting

### To consider

- **Pronunciation hints are still spoken as written** (medium, since 2026-10-12) — Flux streaming applies the same escaped `\{"word": …, "pronounce": …\}` object Aura-2 takes, but `format_pronunciation` is left at the base implementation, so `pronunciation_transform_ipa` speaks the words as written. Support would be the Aura-2 override plus a `supports_pronunciations` gate, since the control is incompatible with `speed`. The control matrix still scopes Flux's controls to English, so a gate has to decide what happens on the 41 non-English languages. — *Needs a call: whether to emit an Early-Access control whose misuse is fatal — the same text on a `speed=1.1` connection ends the session with `Error DATA-0002`, and a `Configure` speed over a queued pronunciation turn is `CONTROL_COMBINATION_INVALID`.*
- **`Interrupt` carries no `playback_offset`** (medium, since 2026-09-01) — Deepgram's barge-in pattern is: stop playback locally, then send `{"type": "Interrupt", "playback_offset": {"type": "time_ms", "value": <session ms played>}}`, and Flux answers with `text_spoken` / `text_remaining` so the LLM context matches what the user actually heard. `on_audio_context_interrupted` sends a bare `Interrupt`, so the server omits both fields and `audio_played_ms` degrades to its own generated-audio total. The offset is cumulative from the start of the *session* and each one must advance past the previous, or Flux rejects it with `INVALID_INTERRUPT_OFFSET`. — *Needs a call: whether Pipecat can give the service a session-cumulative played-ms counter, and whether Flux's `text_spoken` should override the assistant aggregator's own account of what was spoken.*
- **SageMaker SDK pin and deprecated client alias** (medium, since 2026-10-12) — `aws_sdk_sagemaker_runtime_http2` is pinned `>=0.6.0,<0.10` while PyPI is at 0.12.0 (2026-10-08), and the 0.9.0 we resolve warns that `SageMakerRuntimeHTTP2Client`, the name `src/pipecat/services/aws/sagemaker/bidi_client.py` imports, is a deprecated alias for `AsyncSageMakerRuntimeHTTP2Client`. The SDK is pre-1.0 and warns of breaking changes, so the ceiling is deliberate. — *Needs a call: someone with a deployed SageMaker endpoint to verify the BiDi client against 0.12 before the pin widens and the import changes; the item is shared with Flux STT and the Aura SageMaker services.*
- **Ignored-`Interrupt` warning is noisy** (low, since 2026-09-01) — the quiet path in `_handle_message` is keyed on `NO_ACTIVE_SPEECH`, which the server-message reference documents as the code for an ignored *Flush*. An `Interrupt` with nothing to interrupt — a barge-in in the first moments of a turn — is `NO_AUDIO_GENERATED` and reaches `logger.warning`, alongside the two other interrupt-scoped codes and the six inline-control warnings. — *Needs a call: whether an ignored `Interrupt` should be quiet at all, since `INTERRUPT_IN_PROGRESS` is also an ignored barge-in and there a warning is arguably the right level; a fix is really a level per code.*
- **No batch REST path** (low, since 2026-09-01) — the same Flux voices are served by `POST /v2/speak` with mp3/opus/flac/aac output, and batch is the only transport that takes inline pause markers (500–3000 ms, up to 8, speed capped at 1.15 when combined). `DeepgramHttpTTSService` speaks `/v1/speak` only, which is Aura-only. — *Needs a call: whether a batch Flux path is wanted at all, given the streaming class already covers the live-agent case.*

Checked and clean: the voice catalogue is unchanged at 266 — the same 36 English voices, 9 generally-available non-English languages and 32 in Early Access — and `voice` is still a free string passed straight through as Flux's `model` query parameter, so nothing gates it. The streaming query-parameter set grew by one, to `model`, `encoding`, `sample_rate`, `speed`, `expressivity`, `normalize_volume`, `mip_opt_out` and `tag`; the branch covers the new one and the other seven are reachable. `speed` is still 0.5–1.5 and still the only `Configure`-settable field, matching `_CONFIGURE_FIELDS`; `expressivity` is still −2…2, beta, fixed for the connection; `SUPPORTED_SAMPLE_RATES` still matches the `linear16` list, and `encoding=linear16` stays hard-coded on purpose since Pipecat pipelines carry raw PCM. The client and server message sets, the warning and error codes, and the control matrix are all unchanged since the last run, and Deepgram published no changelog entry after 2026-10-27. `DeepgramFluxSageMakerTTSService` was not probed — it needs a deployed endpoint — but it shares `_build_query_string` and all message handling with the WebSocket class, so the new setting reaches it unchanged.
