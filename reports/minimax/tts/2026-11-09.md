# MiniMax TTS — 2026-11-09

`speech-2.8-turbo` is still MiniMax's latest turbo model; the one new finding is that
`voice_setting.text_normalization` is now deprecated in the T2A reference, and the branch adds
the top-level `text_normalization_mode` that replaces it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6655 — Send MiniMax's text_normalization_mode
- https://github.com/pipecat-ai/pipecat/pull/5545 — Expose MiniMax's pronunciation dictionary and accept its calm and whisper emotions (open since 2026-09-01)

PR 5545's second half has since landed on main independently (`7599b05c4`, 2026-10-21), so only
its `pronunciation_dict` commit is still needed; the emotion gap is dropped from this report.

### To consider
- **Aggregated audio is downloaded twice** (medium, since 2026-09-01) — `stream_options.exclude_aggregated_audio` is never sent, so MiniMax's final SSE block carries the complete audio a second time; `run_tts` throws it away by skipping blocks with `extra_info`. The deprecated `InputParams.exclude_aggregated_audio` documents the option, but no code reads it. — *Needs a call: `stream_options` is only valid when `stream=True`, so exposing it means deciding whether to gate on `self._stream` or simply always exclude the aggregate.*
- **`voice_modify` controls** (medium, since 2026-09-01) — `pitch`, `intensity` and `timbre` on -100..100 plus a `sound_effects` enum, none of it reachable from `Settings`. — *Needs a call: whether to model it as a nested settings dataclass or a pass-through dict, and whether its `pitch` overlaps confusingly with the existing top-level `pitch`.*
- **No WebSocket T2A service** (medium, since 2026-09-01) — `wss://api.minimax.io/ws/v1/t2a_v2` holds one connection across turns and accepts incremental text via `task_continue`; `MiniMaxHttpTTSService` opens a fresh POST per utterance (median TTFB 383 ms). — *Needs a call: a new service class is out of scope for an automatic PR, so a maintainer has to decide whether MiniMax warrants a WebSocket implementation.*
- **`timbre_weights` voice mixing** (low, since 2026-09-01) — up to four `voice_id`/`weight` pairs blended into a single timbre; not exposed, and the T2A reference now labels the field legacy. — *Needs a call: a nested list-of-objects field on a parameter MiniMax calls legacy, so whether to expose it at all is the question.*
- **Fixed audio encoding** (low, since 2026-09-01) — `_audio_bitrate` (128000), `_audio_format` ("pcm") and `_audio_channel` are private init-only attributes, and the API's `force_cbr` and `output_format` are not sent. — *Needs a call: pcm is what the pipeline consumes, so exposing format at all needs a reason beyond parity with the API.*

The API's `subtitle_enable` / `subtitle_type` produce a downloadable subtitle file and have no use
in a streaming pipeline, so they are not counted as a gap. The service keeps sending
`voice_setting.text_normalization` when a caller sets the existing `text_normalization` field;
MiniMax still honours it (`true` ≡ `text_normalization_mode=basic`) and gives no removal date, so
deprecating our own field is left alone.
