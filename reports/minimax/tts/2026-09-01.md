# MiniMax TTS — 2026-09-01

The `speech-2.8-turbo` default is current; the branch adds a `pronunciation_dict` setting and
unblocks two documented emotions, and five request affordances are still unexposed.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5545 — Expose MiniMax's pronunciation dictionary and accept its calm and whisper emotions

### To consider
- **Aggregated audio is downloaded twice** (medium, since 2026-09-01) — `stream_options.exclude_aggregated_audio` is never sent, so MiniMax's final SSE block carries the complete audio a second time; `run_tts` throws it away by skipping blocks with `extra_info`. The deprecated `InputParams.exclude_aggregated_audio` documents the option, but no code reads it. — *Needs a call: `stream_options` is only valid when `stream=True`, so exposing it means deciding whether to gate on `self._stream` or simply always exclude the aggregate.*
- **`voice_modify` controls** (medium, since 2026-09-01) — MiniMax added `voice_modify` to T2A in 2026: `pitch`, `intensity` and `timbre` on -100..100 plus a `sound_effects` enum. None of it is reachable from `Settings`. — *Needs a call: whether to model it as a nested settings dataclass or a pass-through dict, and whether its `pitch` overlaps confusingly with the existing top-level `pitch`.*
- **No WebSocket T2A service** (medium, since 2026-09-01) — `wss://api.minimax.io/ws/v1/t2a_v2` holds one connection across turns and accepts incremental text via `task_continue`; `MiniMaxHttpTTSService` opens a fresh POST per utterance (measured TTFB 431 ms). — *Needs a call: a new service class is out of scope for an automatic PR, so a maintainer has to decide whether MiniMax warrants a WebSocket implementation.*
- **`timbre_weights` voice mixing** (low, since 2026-09-01) — up to four `voice_id`/`weight` pairs can be blended into a single timbre; not exposed. — *Needs a call: a nested list-of-objects field, so it needs the same modelling decision as `voice_modify`.*
- **Fixed audio encoding** (low, since 2026-09-01) — `_audio_bitrate` (128000), `_audio_format` ("pcm") and `_audio_channel` are private init-only attributes, and the API's `force_cbr` and `output_format` are not sent. — *Needs a call: pcm is what the pipeline consumes, so exposing format at all needs a reason beyond parity with the API.*

`aiohttp_session` the probe does not supply, so it fails at the constructor. Probes below ran
through an ad-hoc script in `scratch_dir` that drives the real class's `run_tts`.
