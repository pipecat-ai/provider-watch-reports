# MiniMax TTS — 2026-11-23

Current. `speech-2.8-turbo` is still MiniMax's "Latest Turbo model", both PRs from the last run
merged, and MiniMax has shipped nothing new since; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

Last run's two PRs merged and their gaps are closed: #6655 (`text_normalization_mode`, merged
2026-11-09) and #5545 (`pronunciation_dict`, merged 2026-11-10). Both ship on `main` today and
both were probed live below.

### To consider
- **Aggregated audio is downloaded twice** (medium, since 2026-09-01) — `stream_options.exclude_aggregated_audio` is never sent, so MiniMax's final SSE block carries the complete audio a second time; `run_tts` throws it away by skipping blocks with `extra_info`. The deprecated `InputParams.exclude_aggregated_audio` documents the option, but no code reads it. — *Needs a call: `stream_options` is only valid when `stream=True`, so exposing it means deciding whether to gate on `self._stream` or simply always exclude the aggregate.*
- **`voice_modify` controls** (medium, since 2026-09-01) — `pitch`, `intensity` and `timbre` on -100..100 plus a `sound_effects` enum (`spacious_echo`, `auditorium_echo`, `lofi_telephone`, `robotic`), none of it reachable from `Settings`. The reference also limits `voice_modify` to mp3 on streaming requests, which our pcm path would conflict with. — *Needs a call: whether to model it as a nested settings dataclass or a pass-through dict, and whether its `pitch` overlaps confusingly with the existing top-level `pitch`.*
- **No WebSocket T2A service** (medium, since 2026-09-01) — `wss://api.minimax.io/ws/v1/t2a_v2` holds one connection across turns and accepts incremental text via `task_continue`; `MiniMaxHttpTTSService` opens a fresh POST per utterance (median TTFB 312 ms this run). — *Needs a call: a new service class is out of scope for an automatic PR, so a maintainer has to decide whether MiniMax warrants a WebSocket implementation.*
- **`timbre_weights` voice mixing** (low, since 2026-09-01) — up to four `voice_id`/`weight` (1–100) pairs blended into a single timbre; not exposed, and the T2A reference labels the field legacy. — *Needs a call: a nested list-of-objects field on a parameter MiniMax calls legacy, so whether to expose it at all is the question.*
- **Fixed audio output format** (low, since 2026-09-01) — `_audio_bitrate`, `_audio_format` and `_audio_channel` are private init-only attributes, so `mp3`, `flac`, `wav`, `opus` and the telephony-friendly `pcmu_raw` are unreachable. `force_cbr` (streamed mp3 only) and `output_format` (non-streaming only) do not apply to our streaming pcm requests, so the gap is narrower than previously recorded. — *Needs a call: pcm is what the pipeline consumes, so exposing format at all needs a reason beyond parity with the API.*

The API's `subtitle_enable` / `subtitle_type` produce a downloadable subtitle file and have no use
in a streaming pipeline, so they are not counted as a gap. The service still sends
`voice_setting.text_normalization` when a caller sets the now-deprecated `text_normalization`
field; MiniMax honours it and gives no removal date, and our own field already warns, so nothing
further is needed there. The adapter's emotion list excludes `fluent`/`whisper` for speech-2.8,
matching the reference.
