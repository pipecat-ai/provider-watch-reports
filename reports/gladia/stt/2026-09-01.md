# Gladia STT — 2026-09-01

Current: Gladia's live API still accepts only `solaria-1`, which is our default. The one thing worth a maintainer's time is that the inherited `language` setting is silently ignored.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`language` is silently dropped** (high, since 2026-09-01) — `_prepare_settings` builds the `/v2/live` body from `language_config` alone, so `GladiaSTTService.Settings(language=Language.FR)` has no effect; the base class converts it to `"fr"` and nothing reads it. A probe with `language=fr` against the English clip returned the English transcript unchanged, and docs.pipecat.ai lists `language` as a supported way to set the language. — *Needs a call: whether `language` should populate `language_config.languages`, and what wins when both are set.*
- **`post_processing` not exposed** (low, since 2026-09-01) — `/v2/live` accepts `post_processing.summarization` / `.chapterization` (a live init with summarization on returned 201) and `messages_config.receive_post_processing_events` is already a Settings field, but nothing can turn the processing on and `_receive_messages` drops those message types. — *Needs a call: whether end-of-session summaries belong in a real-time pipeline, and what frame would carry them.*
- **Oversized buffered resend** (low, since 2026-09-01) — after a reconnect `_send_buffered_audio` sends the entire buffer (20 MB by default) as one base64 `audio_chunk`; Gladia's websocket guidance is 20-50 ms chunks. — *Needs a call: confirm Gladia actually rejects or truncates such a frame before reworking the reconnect path.*

Notes that are not gaps: `solaria-3` (2026-06-10) and `solaria-fusion` are pre-recorded-only models — the live enum rejects them (probe below). The `gladia` extra pulls no SDK, so there is no pin to compare against Gladia's Python SDK 1.0.3.
