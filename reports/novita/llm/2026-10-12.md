# Novita LLM — 2026-10-12

Nothing to merge: `moonshotai/kimi-k2.5` is still end-of-life at Moonshot, still served by Novita, and still the fastest Kimi there, so the two open items carry over unchanged.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default kimi-k2.5 is retired upstream** (high, since 2026-09-01) — Moonshot's model page still lists `kimi-k2.5` as discontinued on 2026-08-31 and names `kimi-k3` the replacement; Novita's model page still carries no retirement notice, and Novita's only October notice retires `deepseek/deepseek-v4-flash`, not any Kimi. Our probe answers normally and is now *faster* than last run (TTFAT 820 ms, median of 5, against 1718 ms on 2026-09-14), while `kimi-k3` medians 4333 ms with thinking on by default and still 2573 ms with thinking off, and `kimi-k2.6` 3881 ms / 1383 ms. aiewf-eval's `aiwf_medium_context` leaderboard is unchanged for Kimi — `kimi-k2.6` at 98.3% (thinking on) / 93.9% (thinking off), no row for `kimi-k2.5` or `kimi-k3` — so the pass-rate comparison a default bump requires still cannot be made. — *Needs a call: which successor to adopt given that every candidate is 1.7–5x slower to first answer token, and whether to ship it with thinking disabled, which is a behavior change rather than a value change.*
- **Thinking control is undiscoverable** (low, since 2026-09-01) — Novita's reasoning models accept `chat_template_kwargs: {"thinking": false}`, but `Settings.extra` keys are merged straight into the OpenAI SDK call as top-level kwargs (`base_llm.py`, `params.update(self._settings.extra)`), so users must write `extra={"extra_body": {"chat_template_kwargs": {"thinking": False}}}`. That idiom probes green and roughly halves TTFAT on both `kimi-k2.6` and `kimi-k3`, but neither the class docstring nor docs.pipecat.ai mentions it. — *Needs a call: whether this belongs in the class docstring here or only in the docs repo.*

`moonshotai/kimi-k3-p` is new in the catalogue since last run; Moonshot documents no such id, and Novita's `-p` suffix elsewhere (`deepseek-v4-pro-0813-p`, `glm-5.3-p`) marks a serving tier rather than a different model, so it is not a bump candidate.
