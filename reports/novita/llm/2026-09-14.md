# Novita LLM — 2026-09-14

Nothing changed for this unit in the last two weeks: `moonshotai/kimi-k2.5` is still end-of-life at Moonshot and still served by Novita, and `kimi-k3` is still too slow and unbenchmarked to propose as the default.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default kimi-k2.5 is retired upstream** (high, since 2026-09-01) — Moonshot retired `kimi-k2.5` on 2026-08-31 and points users at `kimi-k3`; Novita's model page still carries no retirement notice and our probe answers normally at TTFAT 1718 ms (median of 3). `kimi-k3` on Novita medians 5783 ms with thinking on by default (1443 ms of it reasoning), and aiewf-eval's `aiwf_medium_context` leaderboard is unchanged from last run: `kimi-k2.6` at 98.3% (thinking on) / 93.9% (thinking off), no row for `kimi-k2.5` or `kimi-k3`, so the pass-rate comparison a default bump requires still cannot be made. — *Needs a call: which successor to adopt, and whether to ship it with thinking disabled — the only variant that is fast enough is a behavior change, not a value change.*
- **Thinking control is undiscoverable** (low, since 2026-09-01) — Novita's reasoning models accept `chat_template_kwargs: {"thinking": false}`, but `Settings.extra` keys are merged straight into the OpenAI SDK call as top-level kwargs (`base_llm.py`, `params.update(self._settings.extra)`), so users must write `extra={"extra_body": {"chat_template_kwargs": {"thinking": False}}}`. That idiom probes green and takes `kimi-k2.6` to 1494 ms with no thinking time, but neither the class docstring nor docs.pipecat.ai mentions it. — *Needs a call: whether this belongs in the class docstring here or only in the docs repo.*

Previously noted and now moot: the `openai` SDK pin. Our pin is `openai>=1.74.0,<4` and the latest release is 3.13.0, so nothing is out of range.
