# Cartesia STT — 2026-10-28

Current; no branch. Cartesia published nothing for STT since the September ink-2 multilingual entry, and the service is unchanged.

## What's new for Pipecat

Nothing. The changelog has no October entries; the STT models page still dates `ink-2` (Stable) and `ink-preview` (Preview) to 2026-09-17 with the same five languages, and `ink-whisper` is still Stable on the older-models page with no sunset date. The `/stt/websocket` query schema is byte-for-byte what last run recorded — same parameters, same per-model scoping, `2026-08-14` still the only documented `cartesia_version`. The `cartesia` extra declares no SDK dependency, so there is no pin to move.

Both open questions carry forward unchanged, and PR #5531 is still open and unreviewed.

### To consider
- **ink-whisper is the older model** (medium, since 2026-08-31) — Cartesia's flagship is `ink-2`, with `ink-whisper` filed under older models. The latency gap has not moved in four runs: TTFS 740 ms against 195 ms this run, after medians of 523/239, 516/250 and 506/205. Cartesia's own answer for ink-2 is the auto-finalizing `/stt/turns/websocket`, already shipped as `CartesiaTurnsSTTService`, and ink-whisper still covers 100+ languages with no announced sunset. — *Needs a call: whether this service should follow ink-2 and accept a 2-3x TTFS regression, or stay on ink-whisper and leave ink-2 to `CartesiaTurnsSTTService`.*
- **API version pin** (low, since 2026-08-31) — the service sends `Cartesia-Version: 2026-03-01`; the reference documents `2026-08-14` as the only value. Both transcribed on both models last run, and the changelog promises earlier pins keep working. — *Needs a call: what 2026-08-14 changes for STT; the API-versioning page still redirects to a login, so the diff could not be read.*
