# Cartesia TTS — 2026-08-25

sonic-3.5 is still Cartesia's recommended stable model, so the default is right; the one clear-cut change is a `normalization` setting, on a branch.

## What's new for Pipecat

Cartesia announced Sonic 3.6 on 2026-08-17, but it ships only as the `sonic-preview` beta channel — the model ID `sonic-3.6` returns 404 and the docs still name `sonic-3.5` as the stable ID to use. No default bump. Nothing the services or examples hard-code is retired: the June 2026 retirements covered `sonic`, `sonic-english`, `sonic-multilingual`, `sonic-2` and `sonic-turbo`, none of which appear in the repo, and the pinned `Cartesia-Version: 2026-03-01` is the current API version. The `cartesia` extra has no SDK dependency, so there is no pin to move.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5430 — Add a normalization setting to the Cartesia TTS services

### To consider
- **`locale`** (medium, since 2026-08-25) — Cartesia's `locale` field selects a regional accent (`en-GB`) and is documented as mutually exclusive with `language`, which both services always send when the setting is set; it also requires Sonic 3.6+. — *Needs a call: how a `locale` setting should suppress the `language` field, and whether to ship it before Sonic 3.6 is GA.*
- **Sonic 3.6** (low, since 2026-08-25) — reachable only as `sonic-preview`, which works through `CartesiaTTSService` at TTFB 140 ms against 144 ms for sonic-3.5; `sonic-3.6` is 404. — *Needs a call: nothing until Cartesia ships a GA model ID; re-check next run.*
- **Odia and Urdu** (low, since 2026-08-25) — Sonic 3.6 takes the language list to 44 by adding `or` and `ur`, which `language_to_cartesia_language` does not map; `resolve_language` falls back to the base code, so they synthesize but log a warning. — *Needs a call: whether to map languages only a preview model supports.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
