# Cartesia TTS — 2026-09-14

Cartesia published nothing in September, so `sonic-3.6` stays current and no branch was left; the new finding is a Pipecat-side crash when `generation_config` is updated through the dict form of `TTSUpdateSettingsFrame`.

## What's new for Pipecat

Nothing from the provider. The changelog's newest entry is still Sonic 3.6 GA (2026-08-27), the model page still lists `sonic-3.6` (rolling), `sonic-3.6-2026-08-27` (snapshot) and `sonic-preview` (beta), and there are no new deprecations — the `sonic-2` / `sonic-turbo` / `sonic-3-2025-10-27` sunset after 2026-10-20 touches nothing in the repo or the examples. The pinned `Cartesia-Version: 2026-03-01` is unchanged (the versioning page is behind Cartesia's docs login) and the `cartesia` extra declares no SDK dependency, so there is no pin to move.

The Odia/Urdu gap is closed: PR #5532 merged on 2026-09-02 and `Language.OR` / `Language.UR` are in the language map on this commit.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5430 — Add a normalization setting to the Cartesia TTS services (open since last run)

### To consider
- **Dict-valued `generation_config` breaks a turn** (medium, since 2026-09-14) — `TTSUpdateSettingsFrame(settings={"generation_config": {...}})` goes through `CartesiaTTSSettings.from_mapping`, which stores the nested value as a plain `dict`; `_build_msg` (WebSocket) and `run_tts` (HTTP) then call `.model_dump()` on it and raise `AttributeError`, so the turn pushes an error and produces no audio. Several services (`fish`, `inworld`, `google`, `anthropic`) already override `from_mapping` to destructure nested values; Cartesia does not. — *Needs a call: whether the dict path should coerce into `GenerationConfig` — and what happens to unknown keys — or reject nested values outright.*
- **`locale`** (medium, since 2026-08-25) — `locale` picks a regional accent (`en-GB`) and needs Sonic 3.6+, which is now the default, so only the API rule blocks it: a request may set `language` or `locale`, never both, and both services always send `language` when the setting is set. — *Needs a call: how a `locale` setting should suppress the `language` field.*
- **`accent`** (medium, since 2026-08-31) — both the WebSocket and HTTP schemas take an `accent` field for sonic-3 and newer, setting how a multilingual voice sounds while speaking the language; neither service can send it. — *Needs a call: the valid accent values live in Cartesia's authenticated capability guide, still unreadable this run, so the value set has to be established before a pass-through field can be probed.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
