# Cartesia TTS — 2026-08-31

Sonic 3.6 went GA on 2026-08-27 and Pipecat already defaults to it; the remaining follow-on is the two languages it added, on a branch.

## What's new for Pipecat

Sonic 3.6 is generally available as `sonic-3.6` (snapshot `sonic-3.6-2026-08-27`), and commit `182c7f187` moved both services onto it — the previous report's preview-only gap is closed, and `sonic-3.6` probes fine through both classes. Cartesia asks Sonic 3.5 users to redirect traffic themselves, so the bump was needed rather than automatic. GA also settles the question the last run left open about the two new languages: Odia and Urdu are now supported by the default model, so the language map should carry them.

Retirements do not touch us: `sonic-2`, `sonic-turbo` and `sonic-3-2025-10-27` sunset after 2026-10-20, and none appear in the repo or the examples. `sonic-3.5` has no announced retirement. The pinned `Cartesia-Version: 2026-03-01` is still current, and the `cartesia` extra declares no SDK dependency, so there is no pin to move.

### PRs
- `provider-watch/cartesia-tts-odia-urdu` — review: `git show provider-watch/cartesia-tts-odia-urdu` — Map Odia and Urdu for the Cartesia TTS services
- https://github.com/pipecat-ai/pipecat/pull/5430 — Add a normalization setting to the Cartesia TTS services (open since last run)

### To consider
- **`locale`** (medium, since 2026-08-25) — `locale` picks a regional accent (`en-GB`) and needs Sonic 3.6+, which is now the default, so only the API rule blocks it: a request may set `language` or `locale`, never both, and both services always send `language` when the setting is set. — *Needs a call: how a `locale` setting should suppress the `language` field.*
- **`accent`** (medium, since 2026-08-31) — both the WebSocket and HTTP schemas take an `accent` field for sonic-3 and newer, setting how a multilingual voice sounds while speaking the language; neither service can send it. — *Needs a call: the valid accent values live in Cartesia's authenticated capability guide and each must match the voice's capabilities, so the value set has to be established before a pass-through field can be probed.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
