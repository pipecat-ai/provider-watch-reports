# Cartesia TTS — 2026-11-23

Quiet run: no new Cartesia model or request parameter, `sonic-3.6` stays the default, and the `normalization` PR merged — one open design question remains.

## What's new for Pipecat

Cartesia's changelog now carries an October section (an inaudible AI watermark on all Sonic 3.6 audio, 13 new accent IDs such as `bulgarian`, `danish` and `odia`, 31 new voices) and no November entries. None of it needs code: the watermark is applied server-side with no request field, `accent` is already a free-form pass-through setting on both classes, and `voice` is a free-form ID. Everything else in October is Voice Agents, which these classes don't use.

The model page is unchanged: `sonic-3.6` GA and recommended, `sonic-3.6-2026-08-27` the stable snapshot, `sonic-preview` the only beta. `sonic-3.5-2026-05-04` and `sonic-3-2026-01-12` remain stable with no sunset. The October 20 sunsets of the `sonic-2` / `sonic-turbo` / `sonic-3-2025-10-27` families are past; the only retiring string left in the repo is the `sonic-2` fallback in `src/pipecat/evals/services.py`, which is a recorded decision, not a gap. The deprecated `sonic-latest` / `sonic-3-latest` / `sonic-3-preview` aliases appear nowhere in the repo.

The `normalization` gap is closed: PR #5430 merged on 2026-11-10, and a probe with `normalization=en-GB` synthesizes clean on main.

The WebSocket request schema is unchanged. Against it the services now send everything except `add_phoneme_timestamps`, `flush` (the WebSocket service finalizes a context with an empty `continue: false` transcript instead) and `locale` (a documented synonym of `language`, mutually exclusive with it). The pinned `Cartesia-Version: 2026-03-01` still carries no end-of-support date — the versioning page remains behind Cartesia's docs login, so the pin could not be re-confirmed against a published list, but both classes probe clean with it. The `cartesia` extra declares no SDK dependency, so there is nothing to compare against PyPI.

### To consider
- **Dict-valued `generation_config` breaks a turn** (medium, since 2026-09-14) — any dict-shaped settings path — `TTSUpdateSettingsFrame(settings={"generation_config": {...}})`, or `probe.py --setting`, which hit it again this run on the WebSocket class — goes through `CartesiaTTSSettings.from_mapping`, which stores the nested value as a plain `dict`; `_generation_config` then calls `.model_dump()` on it and raises `AttributeError`, so the turn pushes an error and produces no audio. The typed path (`GenerationConfig(...)`) is unaffected. `fish`, `inworld`, `google` and `anthropic` override `from_mapping` for exactly this. — *Needs a call: whether the dict path should coerce into `GenerationConfig` — and what happens to unknown keys — or reject nested values outright.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
