# Cartesia TTS — 2026-10-12

Cartesia shipped no new TTS model, so `sonic-3.6` stays the right default — but `sonic-2` stops being served after 2026-10-20 and the eval harness still falls back to it, which the branch fixes.

## What's new for Pipecat

The sunset Cartesia announced in July lands in eight days: `sonic-2`, every `sonic-2-*` snapshot, `sonic-turbo-*` and `sonic-3-2025-10-27` stop working after 2026-10-20, with Sonic 3.6 named as the migration target. Both TTS services already default to `sonic-3.6`, but `_cartesia_service` in `src/pipecat/evals/services.py` builds the harness's user-audio voice with `voice_cfg.get("model") or "sonic-2"`, so any `user.speech` config that names a Cartesia voice without a model breaks on that date. The shipped release scenarios use Kokoro, so nothing in `evals/release/` hits it today; a scenario of one's own does.

September's provider changes are behavioral, not API-shaped: Sonic 3.6 pronunciation dictionaries now match case-insensitively by default (case sensitivity is set per entry when the dictionary is created, which Pipecat does not do — it only passes `pronunciation_dict_id`), and Latin-script words inside Japanese and Chinese text are handled better. The WebSocket request schema is unchanged, the pinned `Cartesia-Version: 2026-03-01` is unchanged, and the `cartesia` extra still declares no SDK dependency.

### To consider
- **Dict-valued `generation_config` breaks a turn** (medium, since 2026-09-14) — `TTSUpdateSettingsFrame(settings={"generation_config": {...}})` goes through `CartesiaTTSSettings.from_mapping`, which stores the nested value as a plain `dict`; `_build_msg` (WebSocket) and `run_tts` (HTTP) then call `.model_dump()` on it and raise `AttributeError`, so the turn pushes an error and produces no audio. `fish`, `inworld`, `google` and `anthropic` override `from_mapping` for exactly this. — *Needs a call: whether the dict path should coerce into `GenerationConfig` — and what happens to unknown keys — or reject nested values outright.*
- **`locale`** (medium, since 2026-08-25) — `locale` picks a regional accent (`en-GB`) and is available on sonic-3.6, so only the API rule blocks it: a request may set `language` or `locale`, never both, and both services always send `language` when the setting is set. — *Needs a call: how a `locale` setting should suppress the `language` field.*
- **`accent`** (medium, since 2026-08-31) — both schemas take an `accent` field that forces how a multilingual voice sounds; neither service can send it, and the API requires the value to come from the voice's own `accents` list. — *Needs a call: the accent value set lives in Cartesia's authenticated capability guide, still unreadable this run, so it has to be established before a pass-through field can be probed.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
