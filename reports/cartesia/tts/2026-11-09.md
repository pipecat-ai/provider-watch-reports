# Cartesia TTS — 2026-11-09

Quiet run: no new Cartesia model or request parameter, `sonic-3.6` stays the default, and the only open work is the `normalization` PR that has been waiting since August.

## What's new for Pipecat

Cartesia's changelog still ends at September — no October or November entries — and the model page is unchanged: `sonic-3.6` GA and recommended, `sonic-3.6-2026-08-27` the stable snapshot, `sonic-preview` the only beta. The October 20 sunset of the `sonic-2` / `sonic-turbo` / `sonic-3-2025-10-27` families has passed; the only retiring string left in the repo is the `sonic-2` fallback in `src/pipecat/evals/services.py`, which is a recorded decision, not a gap. `sonic-3.5` (used as a test fixture) and `sonic-3` have no announced sunset. The deprecated `sonic-latest` / `sonic-3-latest` / `sonic-3-preview` aliases appear nowhere in the repo.

The WebSocket and HTTP request schemas are unchanged. Against them the services now send everything except `normalization` (PR #5430), `add_phoneme_timestamps`, `flush` (the WebSocket service finalizes a context with an empty `continue: false` transcript instead) and `locale` (a documented synonym of `language`, mutually exclusive with it). The pinned `Cartesia-Version: 2026-03-01` still carries no end-of-support date — the versioning page remains behind Cartesia's docs login, but the header is accepted and both classes probe clean. The `cartesia` extra declares no SDK dependency, so there is nothing to compare against PyPI.

The `accent` gap is closed: PR #6429 merged on 2026-10-28 and `accent` is a pass-through setting on both classes in main.

September's voice additions (85 public voices across 24 languages, 58 multilingual voices) need no code change — `voice` is a free-form ID and the language map already covers Sonic 3.6's locales including Odia and Urdu.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5430 — Add a normalization setting to the Cartesia TTS services (open since 2026-08-25)

### To consider
- **Dict-valued `generation_config` breaks a turn** (medium, since 2026-09-14) — any dict-shaped settings path — `TTSUpdateSettingsFrame(settings={"generation_config": {...}})`, or `probe.py --setting`, which hit it again this run — goes through `CartesiaTTSSettings.from_mapping`, which stores the nested value as a plain `dict`; `_generation_config` then calls `.model_dump()` on it and raises `AttributeError`, so the turn pushes an error and produces no audio. `fish`, `inworld`, `google` and `anthropic` override `from_mapping` for exactly this. — *Needs a call: whether the dict path should coerce into `GenerationConfig` — and what happens to unknown keys — or reject nested values outright.*
- **`add_phoneme_timestamps`** (low, since 2026-08-25) — Cartesia can return phoneme-level timestamps alongside the word timestamps the WebSocket service already consumes. — *Needs a call: a consumer for phoneme timestamps in the pipeline before adding a setting nothing reads.*
