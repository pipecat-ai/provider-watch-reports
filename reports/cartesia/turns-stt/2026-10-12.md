# Cartesia Turns STT — 2026-10-12

Ink-2 — the default and the only model this endpoint is documented for — became multilingual on 2026-09-17, which turns last run's preview-only labeling item into one about the default; the same release moved two turn detection values the Settings docstring quotes, and that correction is on a branch.

## What's new for Pipecat

Cartesia's September changelog entry "Ink-2 is now multilingual" adds Spanish, French, Hindi and Japanese to `ink-2`, with semantic endpointing, and the model page now lists `ink-2` as Stable across all five languages (release date restated as September 17, 2026). The endpoint comparison page spells out the consequence for this service: the turns endpoint runs `ink-2`, so it "can work multilingually across those five languages without you specifying which one is spoken". Nothing in the class blocks that — the probe below transcribes normally — but the constructor fixes `self._language = Language.EN`, `_update_settings` reports a `language` change as unhandled, and both docstrings plus our docs page still say the family is English-only. Non-English turns therefore reach the LLM tagged English. The turn events still carry no detected language, which is what keeps this out of a PR.

The same release retuned turn detection: Cartesia now documents `turn_eager_end_threshold` as 0.3–0.8 defaulting to 0.6 (was 0.3–0.6 defaulting to 0.4) and `turn_end_threshold` as defaulting to 0.3 (was 0.2), states the ordering requirement start > eager_end > end, and lists Responsive as 0.7 / 0.6 / 0.4 / 4500 ms. `CartesiaTurnsSTTSettings` quotes the superseded numbers, and our docs page renders them. The server accepts an eager-end threshold of 0.7 — above the maximum our docstring states — so the widened range is live, not a documentation edit. The branch brings the docstring to the published values; the service passes the fields through unvalidated, so nothing else changes.

Otherwise the unit is current. `ink-2` is Stable and undeprecated with no successor (`ink-preview` is still Preview, so not a default candidate), the spec's model enum (`ink-2`, `ink-preview`) is not gated anywhere in the class, the event set the service handles still matches the spec exactly, and the `cartesia` extra declares no SDK dependency, so there is no pin to move. No decisions are on file for this unit and no digest comment names it.

### To consider
- **`ink-2` language labeling** (medium, since 2026-09-14) — Cartesia's September 17 release made the default model multilingual (en, fr, hi, ja, es, auto-detected), and the class transcribes all of it unchanged, but `self._language = Language.EN` is fixed and a `language` update is refused, so non-English turns go downstream tagged English; the class and Settings docstrings and our docs page still describe the family as English-only. — *Needs a call: the server reports no detected language on any event, so either the user declares one or frames go out unlabeled.*
- **Mid-session `config` command** (low, since 2026-08-31) — the endpoint takes `{"type": "config", "turn": {...}}` as a text message to retune turn detection on a live socket; the merged threshold support applies a change by reconnecting, mirroring how a changed keyterm list is handled. — *Needs a call: whether retuning mid-call justifies a second update path, and a probe that the config command is honored under the API version the service pins.*
- **API version** (low, since 2026-08-31) — the AsyncAPI spec makes `cartesia_version` a required query parameter whose only listed value is `2026-08-14`, while the service pins `Cartesia-Version: 2026-03-01` as a header and transcribes normally. The changelog describes 2026-08-14 as a multilingual-voice cleanup that also drops already-deprecated fields, and says pinned integrations keep running unchanged. — *Needs a call: whether that cleanup touches STT at all, since the same header is pinned by the other Cartesia STT and TTS services.*
