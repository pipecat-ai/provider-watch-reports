# Cartesia Turns STT — 2026-08-31

`ink-2` is the only model `/stt/turns/websocket` accepts, so the default is right; the actionable gap is the turn detection thresholds Cartesia shipped in June 2026, on a branch.

## What's new for Pipecat

Cartesia's June 2026 release added four connection parameters that tune turn detection — `turn_start_threshold`, `turn_eager_end_threshold`, `turn_end_threshold`, `turn_end_timeout_ms` — and `CartesiaTurnsSTTSettings` carries only `keyterm`, so a user cannot reach them. Nothing else is stale: `ink-2` is the sole supported model for this endpoint and is documented as Stable, it remains English-only, the turn event set the service handles matches the spec exactly (`connected`, `turn.start`, `turn.update`, `turn.eager_end`, `turn.resume`, `turn.end`, `error`), and no STT deprecation is scheduled (July's sunset notice covers Sonic TTS snapshots only). The `cartesia` extra declares no SDK dependency, so there is no pin to move.

### To consider
- **Mid-session `config` command** (low, since 2026-08-31) — the endpoint takes `{"type": "config", "turn": {...}}` as a text message to retune turn detection on a live socket; the branch applies a threshold change by reconnecting, mirroring how a changed keyterm list is handled. — *Needs a call: whether retuning mid-call justifies a second update path, and a probe that the config command is honored under the API version the service pins.*
- **API version** (low, since 2026-08-31) — the endpoint's AsyncAPI spec makes `cartesia_version` a required query parameter whose only listed value is `2026-08-14`, while the service pins `Cartesia-Version: 2026-03-01` as a header; probing with either version transcribes identically, and no changelog entry says what 2026-08-14 changes. — *Needs a call: what the newer version changes for STT, since the same header is pinned by the other Cartesia STT and TTS services.*
- **`turn.eager_end`** (low, since 2026-08-31) — Cartesia positions eager end as Ink 2's latency win: generate a reply when it fires, drop the work on `turn.resume`, play it on `turn.end`. Pipecat raises the event and stops there, as it does for Deepgram Flux's equivalent. — *Needs a call: a framework design for speculative LLM turns and their cancellation; no service change helps until one exists.*
