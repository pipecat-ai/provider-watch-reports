# Cartesia Turns STT — 2026-11-09

Nothing moved on either side this cycle; the three open items are unchanged and no branch is warranted.

## What's new for Pipecat

Cartesia's changelog still ends at September 2026 — no October or November entry, and the last STT item remains "Ink-2 is now multilingual". The STT model page lists the same two models (`ink-2` Stable, `ink-preview` Preview, both dated September 17, 2026, both en/fr/hi/ja/es), neither deprecated and no successor named. The turns AsyncAPI spec is unchanged in everything the service touches: the `model` enum, the `encoding` enum, the four `turn_*` ranges and defaults, the `close` and `config` commands, the event set with no language field, and `cartesia_version` with `2026-08-14` as its only value. The `cartesia` extra declares no SDK dependency, so there is no pin to move, and no Cartesia turns code or example changed in Pipecat since the last run.

PR #6123 (threshold docstring ranges) merged on 2026-10-12 and was already recorded as closing that gap last run, so it is not carried forward.

The TTFB that jumped to 2618 ms on 2026-10-28 reproduced at 2640 ms, again tight across interleaved runs, with a correct transcript. Two consecutive runs at the same level against unchanged code and an unchanged API make this the endpoint's current behavior rather than a one-off; it is recorded, not acted on, since nothing in the service can shorten it.

### PRs
Nothing.

### To consider
- **`ink-2` language labeling** (medium, since 2026-09-14) — the default model transcribes en/fr/hi/ja/es with auto-detection and the class handles all of it unchanged, but `self._language = Language.EN` is fixed and a `language` update is refused, so non-English turns go downstream tagged English; the class and Settings docstrings and our docs page still describe the family as English-only at launch. — *Needs a call: the server reports no detected language on any event, so either the user declares one or frames go out unlabeled.*
- **Mid-session `config` command** (low, since 2026-08-31) — the endpoint takes `{"type": "config", "turn": {...}}` as a text message to retune turn detection on a live socket; the merged threshold support applies a change by reconnecting, mirroring how a changed keyterm list is handled. — *Needs a call: whether retuning mid-call justifies a second update path, and a probe that the config command is honored under the API version the service pins.*
- **API version** (low, since 2026-08-31) — the spec makes `cartesia_version` a required query parameter whose only listed value is `2026-08-14`, while the service pins `Cartesia-Version: 2026-03-01` as a header and transcribes normally. The changelog describes 2026-08-14 as a multilingual-voice cleanup that also drops already-deprecated fields, and says pinned integrations keep running unchanged. — *Needs a call: whether that cleanup touches STT at all, since the same header is pinned by the other Cartesia STT and TTS services.*
