# Cartesia Turns STT — 2026-09-01

Nothing moved on Cartesia's side since 2026-08-31; the one actionable item is still the turn detection thresholds, whose branch is rebuilt on current main and probed against the live endpoint.

## What's new for Pipecat

Nothing new from the provider. The only 2026 changelog entry since the last run is Sonic 3.6 TTS (GA 2026-08-27), which does not touch STT. `ink-2` remains the sole model `/stt/turns/websocket` accepts, is documented as Stable and English-only, and carries no deprecation; the turn event set the service handles still matches the spec exactly. The `cartesia` extra declares no SDK dependency, so there is no pin to move.

`CartesiaTurnsSTTSettings` still carries only `keyterm`, so the four connection parameters Cartesia added in June 2026 — `turn_start_threshold`, `turn_eager_end_threshold`, `turn_end_threshold`, `turn_end_timeout_ms` — remain unreachable. The branch the previous run left was never published and is not in the repo, so it is rebuilt here on current main, with unit tests for the URL construction.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5533 — Expose Cartesia Ink 2 turn detection thresholds

### To consider
- **Mid-session `config` command** (low, since 2026-08-31) — the endpoint takes `{"type": "config", "turn": {...}}` as a text message to retune turn detection on a live socket; the branch applies a threshold change by reconnecting, mirroring how a changed keyterm list is handled. — *Needs a call: whether retuning mid-call justifies a second update path, and a probe that the config command is honored under the API version the service pins.*
- **API version** (low, since 2026-08-31) — the endpoint's AsyncAPI spec makes `cartesia_version` a required query parameter whose only listed value is `2026-08-14`, while the service pins `Cartesia-Version: 2026-03-01` as a header; the 2026-08-31 probe transcribed identically under either version, and no changelog entry says what 2026-08-14 changes. — *Needs a call: what the newer version changes for STT, since the same header is pinned by the other Cartesia STT and TTS services.*
- **`turn.eager_end`** (low, since 2026-08-31) — Cartesia positions eager end as Ink 2's latency win: generate a reply when it fires, drop the work on `turn.resume`, play it on `turn.end`. Pipecat raises the event and stops there, as it does for Deepgram Flux's equivalent. — *Needs a call: a framework design for speculative LLM turns and their cancellation; no service change helps until one exists.*
