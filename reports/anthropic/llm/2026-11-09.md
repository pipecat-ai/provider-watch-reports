# Anthropic LLM — 2026-11-09

Claude Fable 5.2 shipped today and is the only code change this run: it has no
reasoning-defaults entry, so Pipecat runs it at Anthropic's `high` effort with
thinking it cannot turn off. Branch ready. Everything else is carried forward.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6666 — Send Claude Fable 5.2 low effort by default
- https://github.com/pipecat-ai/pipecat/pull/5529 — Add an output_config setting to AnthropicLLMService (open since 2026-09-01, superseded: `AnthropicLLMSettings.effort` is on main; worth closing)

### To consider
- **Sonnet 5.5 as the default** (medium, since 2026-10-28) — unchanged this run. `claude-sonnet-5-5` is Active to at least 2027-09-28 and is the replacement Anthropic names for the Sonnet 4.5 retiring on 2026-11-30, and on 2026-10-28 it beat our default through our class on both prompts (TTFAT 462 ms against 777 ms trivial, 466 ms against 921 ms on a scheduling prompt, medians of 5). The blocker is still the benchmark rule: `leaderboard-medium-context.md` carries `claude-sonnet-5-5 (low)` at 99.9% / 838 ms and no live `claude-sonnet-4-6` row, only the archived 100.0% / 850 ms that was copied over without rescoring under the refreshed judge. Neither published Sonnet 5.5 row is the configuration Pipecat sends either: `_THINKING_DEFAULTS` gives it `between_tools` with no effort, so it runs at `high`, while the rows are adaptive at `low` (838 ms) and `between_tools` at `low` (1180 ms). — *Needs a call: whether 99.9% against an archived, differently-judged 100.0% counts as parity, and whether the bump should also set an effort level so the shipped configuration matches a measured one.*
- **Preserved thinking's prefix check** (medium, since 2026-09-14) — Fable 5.2 and Mythos 5.2 tighten this: on them the check is enforced for **every** account, where on Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5 it binds only accounts created on or after 2026-08-31. Pipecat replays thinking blocks and its history is not append-only — `LLMContextSummarizer._apply_summary` replaces the message list with `set_messages`, and `_should_inject_trailing_user_message` injects a `"."` user turn that is never stored — so an edited earlier turn plus a replayed block is a 400. The escape hatch needs the `thinking-binding-controls-2026-08-01` beta plus `thinking.block_binding`, unreachable except by overriding `thinking` and the hard-coded `betas` list wholesale through `extra`. Still not `high`: the default model does not run the check. — *Needs a call: whether Pipecat should opt into `drop_block` for Anthropic by default, expose `block_binding` as a Settings field, or make the summarizer and the trailing-user injection thinking-aware.*
- **The SDK pin excludes anthropic 2.x** (medium, since 2026-10-28) — our extra pins `anthropic>=0.49.0,<2`; the latest release is now 2.7.0 (2026-11-09), four minors past last run's 2.3.0. Raising the ceiling is not only a number: SDK 2.0.0 sends API version `2026-10-21`, which removes `temperature`, `top_p` and `top_k` for every model and returns a 400 even at their default values. `_apply_sampling_settings` puts them in `extra_body`, which the SDK passes through untyped, so under 2.x they would fail every request that sets them rather than only those on Opus 4.7 and later. The same version errors on `document` blocks in assistant messages and on `citations` in user messages. — *Needs a call: whether to raise the ceiling and make the sampling settings version-aware, or hold the pin until the sampling item below is settled.*
- **A default effort level on Sonnet 4.6** (medium, since 2026-08-25) — `_THINKING_DEFAULTS` disables thinking on Sonnet 4.6, but effort applies to every output token, thinking or not, and the request omits it, so Sonnet 4.6 runs at `high`. The effort page is unchanged — "Explicitly set effort when using Sonnet 4.6 to avoid unexpected latency", `medium` recommended, `low` for latency-sensitive work. Moot if the default moves to Sonnet 5.5. — *Needs a call: whether the service should choose an effort level the way `_THINKING_DEFAULTS` already chooses a thinking mode, which trades output quality for latency rather than only latency.*
- **Fast mode has no typed setting** (low, since 2026-11-09) — `speed: "fast"` is GA without a beta header on Opus 5.5 since 2026-10-15 and ships that way on Fable 5.2, giving up to 2.5x output speed at double the token price — the kind of knob a voice agent wants. It is already reachable, since `params.update(self._settings.extra)` carries anything in `extra` into the request; what is missing is a named field. It is not a clean pass-through, though: Opus 5 and Opus 4.8 still need the `fast-mode-2026-02-01` header that the hard-coded `betas` list does not send, fast mode on Opus 4.8 is removed on 2026-11-30, and every other model 400s on `speed`. — *Needs a call: whether a parameter only three models accept, and that `extra` already reaches, earns a typed field.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` at `llm.py:517` (one-shot) and `llm.py:606` (streaming). `AnthropicLLMSettings` still has no `__post_init__` on 24761a4c6. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — the parameter table still gives a 400 for `temperature`, `top_p` and `top_k` on Claude Opus 4.7 and later when set to a non-default value, and Fable 5.2 joins Haiku 5.5 on that list. `_apply_sampling_settings` moves them into `extra_body`, so they no longer raise client-side, but they still reach the API and still fail the turn. Decided together with the SDK pin, which widens the rejection to every model. — *Needs a call: warn, drop, or leave it to the provider's error.*

Claude Fable 5.2 (`claude-fable-5-2`, 2026-11-09) is the only new catalogue
entry. Adaptive thinking is always on and cannot be turned off, effort is the
only thinking control, and the API default is `high` — so its lowest documented
setting is `output_config.effort: "low"`, the same entry Fable 5 and Fable 5.1
carry. The probe shows what the missing entry costs: on `main` the model thinks
for 264 ms before answering, and with the entry `thinking_ms` is 0. Claude
Mythos 5.2 shipped the same day but is limited to organizations in Anthropic's
verification programs and is not in our catalogue, so it gets no entry, matching
how the table already omits the other Mythos models. With Fable 5.2 added the
table covers all fifteen catalogue models.

Fable 5.2's other breaking changes miss us: `tool_choice: any|tool` is a 400 and
the Anthropic adapter never sends `tool_choice`; `computer_20251124` is a 400
off Bedrock and Pipecat declares no computer-use toolset; the advisor-tool
restriction is beta-only. `claude-sonnet-4-5-20250929` retires on 2026-11-30 and
no Pipecat code names it as a model — `_THINKING_DEFAULTS` and
`_PREFILL_SUPPORTED_PATTERNS` key on `claude-sonnet-4-5`, which `_model_name`
also resolves for Bedrock and Vertex ids, and those platforms keep their own
schedules, so the entries stay. No new digest-issue comments for this unit and
#5529 is still open, so `decisions.md` is unchanged.
