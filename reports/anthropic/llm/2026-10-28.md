# Anthropic LLM — 2026-10-28

Claude Sonnet 5.5 and Claude Haiku 5.5 both work through `AnthropicLLMService`
with no code change, and Sonnet 5.5 is roughly half the TTFAT of our default —
but aiewf-eval puts it at 99.9% against Sonnet 4.6's archived 100.0%, so the
default bump is a maintainer's call, not a branch. No branch this run.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5529 — Add an output_config setting to AnthropicLLMService (open since last run, now superseded: `AnthropicLLMSettings.effort` landed on main in 6c6c53f94, and the PR's own commit is not an ancestor of 9d03e5b42)

### To consider
- **Sonnet 5.5 as the default** (medium, since 2026-10-28) — `claude-sonnet-5-5` went GA on 2026-09-28, is Anthropic's recommended replacement for the Sonnet 4.5 that retires on 2026-11-30, and is Active to at least 2027-09-28. Through our class it beats the current default on both prompts: TTFAT 462 ms (404–523) against 777 ms (672–1357) trivial, and 466 ms (416–641) against 921 ms (747–1932) on a scheduling prompt, medians of 5 interleaved runs, with `thinking_ms` 0 on both models. What blocks the bump is the benchmark rule: `claude-sonnet-5-5 (low)` scores 99.9% / 838 ms TTFAT P50, while `claude-sonnet-4-6` scored 100.0% / 850 ms — a hundredth of a point higher, from a row the maintainer archived on 2026-10-17 and never rescored under the refreshed Opus 5.5 judge, so the two numbers are not from one grading campaign. A further mismatch: neither published Sonnet 5.5 row is the configuration Pipecat would send. `_THINKING_DEFAULTS` gives `claude-sonnet-5-5` `thinking: {"type": "between_tools"}` and no effort, so it runs at the default `high`; the leaderboard rows are adaptive at `low` (838 ms) and `between_tools` at `low` (1180 ms). — *Needs a call: whether 99.9% against an archived, differently-judged 100.0% counts as parity, and whether the bump should also set an effort level so the shipped configuration matches a measured one.*
- **Preserved thinking's prefix check** (medium, since 2026-09-14) — the check now runs on four models, Claude Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5: every replayed `thinking`/`redacted_thinking` signature is validated against the `system` prompt, `tools` and preceding messages it was produced with, and a mismatch is a 400 by default on accounts created on or after 2026-08-31. Pipecat replays these blocks and its history is not append-only: `LLMContextSummarizer._apply_summary` replaces the message list with `set_messages`, and `_should_inject_trailing_user_message` injects a `"."` user turn into the request that is never stored. The escape hatch needs the `thinking-binding-controls-2026-08-01` beta plus `thinking.block_binding`, unreachable except by overriding `thinking` and the hard-coded `betas` list wholesale through `extra` — and on Sonnet 5.5 `block_binding` is accepted only with adaptive thinking, so it is unavailable in exactly the configuration Pipecat sends to that model. Still not `high`: the default model does not run the check. It becomes `high` if the default moves to Sonnet 5.5 or a model enforces for every account. — *Needs a call: whether Pipecat should opt into `drop_block` for Anthropic by default, expose `block_binding` as a Settings field, or make the summarizer and the trailing-user injection thinking-aware.*
- **The SDK pin excludes anthropic 2.x** (medium, since 2026-10-28) — our extra pins `anthropic>=0.49.0,<2` and the latest release is 2.3.0 (2026-10-23), so a user who wants the current SDK cannot have it alongside the pin. The ceiling is not only a number: SDK 2.0.0 sends API version `2026-10-21`, which removes `temperature`, `top_p` and `top_k` for every model, returning a 400 even at their default values. `_apply_sampling_settings` puts them in `extra_body`, which the SDK passes through untyped, so under 2.x those settings would fail every request that uses them instead of only those on Opus 4.7 and later. The same version errors on `document` blocks in assistant messages and on `citations` in user messages. — *Needs a call: whether to raise the ceiling and make the sampling settings version-aware, or hold the pin until the sampling item below is settled.*
- **A default effort level on Sonnet 4.6** (medium, since 2026-08-25) — `_THINKING_DEFAULTS` now sends `thinking: {"type": "disabled"}` on Sonnet 4.6, which closes the thinking half of this item but not the effort half: effort applies to every output token, thinking or not, and the request omits it, so Sonnet 4.6 runs at `high`. The effort page is unchanged — "Explicitly set effort when using Sonnet 4.6 to avoid unexpected latency", `medium` recommended, `low` for latency-sensitive work. Moot if the default moves to Sonnet 5.5. — *Needs a call: whether the service should choose an effort level the way `_THINKING_DEFAULTS` already chooses a thinking mode, which trades output quality for latency rather than only latency.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` at `llm.py:517` (one-shot) and `llm.py:606` (streaming). Confirmed by reading the current source: `AnthropicLLMSettings` still has no `__post_init__`. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — the parameter table still gives a 400 for `temperature`, `top_p` and `top_k` on Claude Opus 4.7 and later when set to a non-default value, and Haiku 5.5 joins that list. `_apply_sampling_settings` moves them into `extra_body`, so they no longer raise client-side, but they still reach the API and still fail the turn. Decided together with the SDK pin, which widens the rejection to every model. — *Needs a call: warn, drop, or leave it to the provider's error.*

Dropped since the last run: **`output_config.effort` is not reachable from Settings** (was `action: pr` behind #5529). `AnthropicLLMSettings.effort` and `_output_config` are on main as of 6c6c53f94, so the gap is closed by other work while the PR itself remains open and unmerged — worth closing or rebasing.

Two models are new since 2026-09-28 and neither needs code. `claude-sonnet-5-5` (2026-09-28) and `claude-haiku-5-5` (2026-10-07) both already have `_THINKING_DEFAULTS` entries, and both are the lowest setting Anthropic documents: `between_tools` is named "the lowest thinking setting on Claude Sonnet 5.5", and Haiku 5.5 accepts `thinking: {"type": "disabled"}` at `high` effort or below, which its `medium` default satisfies. The probes confirm the provider accepts both, with `thinking_ms` 0 on each. Their breaking changes miss us: `tool_choice: any|tool` is rejected on both and the Anthropic adapter never sends `tool_choice`; Haiku 5.5 rejects assistant prefill and `_PREFILL_SUPPORTED_PATTERNS` does not match it, so the trailing-user injection is already on; the computer-use toolset changes are out of scope. The reasoning-defaults table covers all fourteen catalogue models, with no entry for a model Anthropic has shut down.

`claude-sonnet-4-5-20250929` was deprecated on 2026-09-30 and retires on 2026-11-30, but no Pipecat code names it — the service, its docstrings and every example under `examples/` use live ids (`claude-sonnet-4-6`, and `us.anthropic.claude-haiku-4-5-20251001-v1:0` on Bedrock, which keeps its own schedule). The `claude-sonnet-5` default bump stays out of the report per `decisions.md`; that decision is about Sonnet 5 specifically and says the next Sonnet gets evaluated when it ships, which is the first item above. No new digest-issue comments for this unit, so `decisions.md` is unchanged.
