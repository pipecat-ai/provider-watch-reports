# Anthropic LLM — 2026-09-01

The provider stood still — same ten-model catalogue, same deprecation table, same
SDK 1.2.0 — so the run's one piece of work is the branch that turns the
long-standing effort gap into a plain `Settings` field.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5529 — Add an output_config setting to AnthropicLLMService

`Settings.output_config` takes `AnthropicLLMService.OutputConfig(effort=...)` or the
documented dict, defaults to unset, and is copied into the request; `extra` still wins
if a user already sets `output_config` there. Effort needs no beta header and is
supported on our default model.

### To consider
- **A default effort level on Sonnet 4.6** (medium, since 2026-08-25) — with the setting in place the open half of the old item is policy: Anthropic's effort page tells Sonnet 4.6 users to set effort explicitly "to avoid unexpected latency", recommending `medium` for most applications and `low` for latency-sensitive work, and Pipecat's default model is Sonnet 4.6 with the field left unset. Last run's median-of-5 on a scheduling prompt — TTFAT 1746 ms (1199–2184) at the provider default against 1312 ms (1004–1887) at `low` — is the standing evidence; not re-measured this run. — *Needs a call: whether the service should choose an effort level on Sonnet 4.6 the way `_maybe_disable_thinking` already chooses a thinking mode on Sonnet 5, which trades output quality for latency rather than only latency.*
- **SDK pin behind the current major** (medium, since 2026-08-25) — `pyproject.toml` pins `anthropic>=0.49.0,<1`; the SDK is still at 1.2.0 (2026-08-27), with 1.0.0 on 2026-08-20. Anthropic's deprecation page states the Python SDK 1.x removes `temperature`, `top_p` and `top_k` outright so passing them raises `TypeError`, and `_process_context` puts all three in every request, sentinel or not; 1.0 also moves the client to httpx2 and 1.1 removed the legacy response API. — *Needs a call: dropping the sampling parameters from the Anthropic request path, which changes what `Settings.temperature`, `top_k` and `top_p` do.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` at `llm.py:481`. Reproduced again this run. The new `output_config` pass-through takes the dict form directly and so is unaffected. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — Anthropic returns a 400 for a non-default `temperature`, `top_p` or `top_k` on Claude Opus 4.7 and later, including `claude-sonnet-5`; the service forwards whatever the user set, so carrying settings across a model switch fails the turn. — *Needs a call: warn, drop, or leave it to the provider's error.*

`claude-sonnet-4-6` is Active with retirement not sooner than 2027-02-17, and every
hard-coded model string in the service and its examples is either the current default
or a member of the deliberately frozen `_PREFILL_SUPPORTED_PATTERNS` legacy set. The
`claude-sonnet-5` default bump stays out of the report: the team decided against it on
aiewf-eval grounds (`decisions.md`), and the leaderboard rows are unchanged this run.
