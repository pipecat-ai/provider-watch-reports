# Anthropic LLM — 2026-09-28

## What's new for Pipecat

### PRs

### To consider
- **Preserved thinking's prefix check** (medium, since 2026-09-14) — the check now runs on Claude Opus 5.5 as well as Claude Fable 5.1: every replayed `thinking`/`redacted_thinking` signature is validated against the `system` prompt, `tools` and preceding messages it was produced with, and a mismatch is a 400 `invalid_request_error` by default on accounts created on or after 2026-08-31. Pipecat replays these blocks (`anthropic_adapter._from_anthropic_specific_message` rebuilds them from stored signatures) and its history is not append-only: `LLMContextSummarizer._apply_summary` replaces the message list with `set_messages`, and `_should_inject_trailing_user_message` injects a `"."` user turn into the request that is never stored, so the next request differs at that position. The escape hatch, `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` plus the `thinking-binding-controls-2026-08-01` beta, is unreachable except by overriding `thinking` and the hard-coded `betas` list wholesale through `extra`. Still not `high`: it bites only Fable 5.1 and Opus 5.5 users on new accounts, and the default model has thinking off. It becomes `high` the moment a model enforces for every account. — *Needs a call: whether Pipecat should opt into `drop_block` for Anthropic by default, expose `block_binding` as a Settings field, or make the summarizer and the trailing-user injection thinking-aware.*
- **A default effort level on Sonnet 4.6** (medium, since 2026-08-25) — the effort page is unchanged for Sonnet 4.6: defaults to `high`, "explicitly set effort when using Sonnet 4.6 to avoid unexpected latency", `medium` recommended, `low` for latency-sensitive work. Pipecat's default model is Sonnet 4.6 with the field unset. The 2026-08-31 median-of-5 on a scheduling prompt — TTFAT 1746 ms (1199–2184) at the provider default against 1312 ms (1004–1887) at `low` — is the standing evidence; not re-measured this run. — *Needs a call: whether the service should choose an effort level on Sonnet 4.6 the way `_maybe_disable_thinking` already chooses a thinking mode on Sonnet 5, which trades output quality for latency rather than only latency.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` at `llm.py:454` (one-shot) and `llm.py:543` (streaming). Confirmed by reading the current source: `AnthropicLLMSettings` still has no `__post_init__`. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — the parameter-deprecation table is unchanged: `temperature`, `top_p` and `top_k` return a 400 on Claude Opus 4.7 and later when set to a non-default value. `_apply_sampling_settings` moves them into `extra_body`, so they no longer raise client-side, but they still reach the API and still fail the turn. — *Needs a call: warn, drop, or leave it to the provider's error.*

`claude-opus-5-5` shipped 2026-09-22 and works through the service unchanged
(probed below, with its always-on adaptive thinking visible as 114 ms). Its
breaking changes miss us: `thinking: {"type": "disabled"}` and `{"type": "enabled"}`
return a 400, but `_maybe_disable_thinking` only injects `disabled` for the Sonnet
line; `tool_choice: any|tool` is rejected and the Anthropic adapter never sends
`tool_choice`; the computer-use toolset change is out of scope. `model_supports_response_schema`
reads it as (5, 5) and allows structured outputs. Opus 5.5 does raise the stakes
on the open `output_config.effort` PR: thinking cannot be disabled on it at any
level, so effort is the only reasoning control it has.

The `claude-sonnet-5` default bump stays out of the report per `decisions.md`. The
aiewf-eval `aiwf_medium_context` leaderboard is unchanged — no Fable 5.1 or Opus 5.5
row — so `claude-sonnet-4-6` (100% / 850 ms) remains the default. Three new betas
landed in September (`inline-tools-2026-09-15` mid-conversation tool definitions,
`mcp-client-2026-09-15`, per-message effort) and fast mode is a research preview;
none is a simple pass-through, and they are not listed as gaps.
