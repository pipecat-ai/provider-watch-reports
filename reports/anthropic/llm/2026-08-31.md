# Anthropic LLM — 2026-08-31

Anthropic shipped nothing this week — same ten-model catalogue, same deprecation
table, same SDK 1.2.0 — so the report is a re-measurement: effort is worth about
434 ms of TTFAT on our default model, not the 2.7 s an earlier single sample
implied.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Effort control on the default model** (medium, since 2026-08-25) — `output_config.effort` (`low`…`max`, no beta header) has no `Settings` field. Anthropic's effort page still tells Sonnet 4.6 users to "explicitly set effort when using Sonnet 4.6 to avoid unexpected latency", recommending `medium` as the everyday default and `low` for latency-sensitive work — and Sonnet 4.6 is our default model. Re-probed with `--repeat 5` on a scheduling prompt: TTFAT 1746 ms median (1199–2184) at the provider default against 1312 ms median (1004–1887) with `extra={"output_config": {"effort": "low"}}`. That is a real but modest win, so the item drops from high to medium; the 4002 ms vs 1264 ms pair in the earlier report was a single sample on each side and the spread above covers it. `extra` remains the only route. — *Needs a call: whether to expose Anthropic's nested `output_config` or a flat `effort` field, and whether Pipecat should pick a low-latency level on Sonnet 4.6 the way `_maybe_disable_thinking` already does for Sonnet 5.*
- **SDK pin behind the current major** (medium, since 2026-08-25) — `pyproject.toml` pins `anthropic>=0.49.0,<1`; the SDK is at 1.2.0 (1.0.0 on 2026-08-20), unchanged since the last run. Anthropic's deprecation page states the Python SDK 1.x removes `temperature`, `top_p` and `top_k` outright so passing them raises `TypeError`, and `_process_context` puts all three in every request, sentinel or not; 1.0 also moves the client to httpx2 and 1.1 removed the legacy response API. — *Needs a call: dropping the sampling parameters from the Anthropic request path, which changes what `Settings.temperature`, `top_k` and `top_p` do.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` at `llm.py:481`. Reproduced again this run. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — Anthropic returns a 400 for a non-default `temperature`, `top_p` or `top_k` on Claude Opus 4.7 and later, including `claude-sonnet-5`; the service forwards whatever the user set, so carrying settings across a model switch fails the turn. — *Needs a call: warn, drop, or leave it to the provider's error.*

`claude-sonnet-4-6` is Active with retirement not sooner than 2027-02-17, and every
hard-coded model string in the service and its examples is either the current default
or a member of the deliberately frozen `_PREFILL_SUPPORTED_PATTERNS` legacy set. The
`claude-sonnet-5` default bump stays out of the report: the team decided against it on
aiewf-eval grounds (`decisions.md`), and the leaderboard rows are unchanged this run.
