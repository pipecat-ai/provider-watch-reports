# Anthropic LLM — 2026-09-14

Pipecat caught up with the Anthropic 1.x SDK in-tree, closing the pin gap; the new
provider-side item is the preserved-thinking prefix check that landed with Claude
Fable 5.1, which Pipecat's history rewriting can trip.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5529 — Add an output_config setting to AnthropicLLMService (open since last run)
- https://github.com/pipecat-ai/pipecat/pull/5742 — Name a live Claude model in the Mem0 RAG example

`examples/rag/rag-mem0.py` invites the reader to uncomment a Mem0 local configuration
that names `claude-3-5-sonnet-20240620`, retired on 2025-10-28. The branch moves it to
`claude-sonnet-4-6`, Anthropic's listed replacement.

### To consider
- **Preserved thinking's prefix check** (medium, new) — since Claude Fable 5.1 (2026-09-01) the API checks every replayed `thinking`/`redacted_thinking` signature against the `system` prompt, `tools` and messages that preceded it; a mismatch is a 400 `invalid_request_error` by default on accounts created on or after 2026-08-31, and Anthropic says "later models will enforce the prefix check for all accounts". Pipecat replays these blocks — `anthropic_adapter._from_anthropic_specific_message` rebuilds them from stored signatures — and its history is not append-only: `LLMContextSummarizer._apply_summary` replaces the message list with `set_messages`, and `_should_inject_trailing_user_message` injects a `"."` user turn into the request that is never stored, so the next request differs at that position. The escape hatch, `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` plus the `thinking-binding-controls-2026-08-01` beta, is unreachable except by overriding `thinking` and the hard-coded `betas` list wholesale through `extra`. Today this bites only Fable 5.1 users on new accounts (the default model has thinking off), which is why it is not `high` — it becomes `high` the moment a model enforces for every account. — *Needs a call: whether Pipecat should opt into `drop_block` for Anthropic by default, expose `block_binding` as a Settings field, or make the summarizer and the trailing-user injection thinking-aware.*
- **A default effort level on Sonnet 4.6** (medium, since 2026-08-25) — the effort page is unchanged: Sonnet 4.6 defaults to `high`, users are told to "explicitly set effort when using Sonnet 4.6 to avoid unexpected latency", `medium` is the recommended default and `low` the latency-sensitive one. Pipecat's default model is Sonnet 4.6 with the field unset. The 2026-08-31 median-of-5 on a scheduling prompt — TTFAT 1746 ms (1199–2184) at the provider default against 1312 ms (1004–1887) at `low` — is the standing evidence; not re-measured this run. — *Needs a call: whether the service should choose an effort level on Sonnet 4.6 the way `_maybe_disable_thinking` already chooses a thinking mode on Sonnet 5, which trades output quality for latency rather than only latency.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'`, now at `llm.py:505`. Reproduced again this run. — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — confirmed live: `claude-opus-4-7` with `temperature=0.5` returns 400 ``temperature` is deprecated for this model.` The SDK-1.x work moved these three into `extra_body`, so they no longer raise a `TypeError` client-side, but they still reach the API and still fail the turn on models that reject them. — *Needs a call: warn, drop, or leave it to the provider's error.*

Closed since the last run: the `anthropic>=0.49.0,<1` pin gap. `pyproject.toml` now pins
`anthropic>=0.49.0,<2` (PR #5623), the installed 1.3.0 is inside it and the latest 1.5.0
would be too, and `_apply_sampling_settings` carries `temperature`/`top_k`/`top_p` through
`extra_body` instead of the removed typed parameters.

`claude-fable-5-1` and `claude-mythos-5-1` shipped 2026-09-01; the service has no
allowlist, so Fable 5.1 works unchanged (probed below). Their restriction on
`tool_choice: any|tool` is a non-issue — the Anthropic adapter never sends `tool_choice`.
`claude-sonnet-4-6` is Active with retirement not sooner than 2027-02-17, and no other
hard-coded model string in the service or its examples is deprecated. The
`claude-sonnet-5` default bump stays out of the report per `decisions.md`; the
leaderboard rows are unchanged and no new Anthropic model has been benchmarked.
