# Anthropic LLM — 2026-08-25

`ThinkingConfig` is out of date with Anthropic's thinking API (branch ready); the
`claude-sonnet-5` default bump is a real option but not a free one — adaptive thinking is on by
default there and cost us ~700 ms of TTFAT on a reasoning prompt.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5429 — Accept adaptive thinking in AnthropicThinkingConfig

### To consider
- **claude-sonnet-5 as the default** (medium, since 2026-08-25) — GA 2026-06-30, documented as a drop-in replacement for `claude-sonnet-4-6` at $2/$10 per MTok instead of $3/$15, with `claude-sonnet-4-6` moved to "legacy" (retirement not sooner than 2027-02-17, so nothing is breaking). The catch is latency: Sonnet 5 turns on adaptive thinking unless asked not to, and it probed at 1632 ms TTFAT against 910 ms for the current default on a scheduling question, level with it on a trivial one. Neither `thinking: {"type": "disabled"}` nor low effort is our default today. — *Needs a call: whether the bump ships with a thinking-off (or low-effort) default the way `GoogleLLMService` pins low-latency thinking defaults per model.*
- **Effort control** (medium, since 2026-08-25) — `output_config.effort` (`low`…`max`) is the control Anthropic now points at for trading capability against latency, is supported on our current default as well as every 5-generation model, and has no `Settings` field; `extra={"output_config": {"effort": "low"}}` is the only way through today and probed fine. — *Needs a call: whether to model the provider's nested `output_config` (which also carries structured-output `format`) or expose a flat `effort` field.*
- **SDK pin behind the current major** (medium, since 2026-08-25) — `pyproject.toml` pins `anthropic>=0.49.0,<1`; 1.0.0 shipped 2026-08-20. Anthropic's docs state the 1.x request types drop `temperature`, `top_p` and `top_k` (passing them raises `TypeError`), and `_process_context` puts all three in every request, sentinel or not; 1.0 also moves the client to httpx2. — *Needs a call: dropping the sampling parameters from the Anthropic request path, which changes what `Settings.temperature`, `top_k` and `top_p` do.*
- **Thinking dicts crash at request time** (low, since 2026-08-25) — `Settings.from_mapping` coerces a `thinking` dict into a `ThinkingConfig`, but `Settings(thinking={...})` keeps the dict and the turn fails with `'dict' object has no attribute 'model_dump'` (hit by `probe.py --setting thinking=...`). — *Needs a call: whether the coercion belongs in `__post_init__` so every path accepts the dict form.*
- **Sampling parameters on 4.7-and-later models** (low, since 2026-08-25) — Anthropic returns a 400 for a non-default `temperature`, `top_p` or `top_k` on Claude Opus 4.7 and later, including `claude-sonnet-5`; the service forwards whatever the user set, so carrying settings across a model switch fails the turn. — *Needs a call: warn, drop, or leave it to the provider's error.*
