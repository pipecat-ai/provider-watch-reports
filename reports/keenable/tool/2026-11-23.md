# Keenable tool — 2026-11-23

Nothing is broken for keyless agents, but Keenable stopped being a web-search-only
server on 18 November: with a key it also lists four Monitors tools, and
`KeenableWebSearch` advertises everything the server lists.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Monitors tools reach a keyed agent's LLM** (high, since 2026-11-23) — Keenable's
  Monitors launch added `create_monitor`, `list_monitors`, `get_monitor_results` and
  `delete_monitor`, listed only when the request carries `X-API-Key` or an OAuth
  sign-in. `KeenableWebSearch` passes no `tools_filter`, so `tools()` returns all six
  schemas with handlers attached, and the feature example passes `KEENABLE_API_KEY`
  whenever it is set — a voice LLM asked to "stop watching that page" can call
  `delete_monitor`, which removes a monitor and its results with no undo.
  `MCPClient` still takes `tools_filter`, so the change is one argument naming
  `search_web_pages` and `fetch_page_content`; it reverses commit e412d5481, which
  dropped the filter on the reasoning that anything Keenable added would still serve
  the web-search mission. The keyless listing (probed) is unaffected: two tools. —
  *Needs a call: go back to a fixed two-tool allowlist, or expose Monitors
  deliberately?*
- **No way to pin the search knobs** (medium, since 2026-09-01) — `max_results`,
  `snippet_max_length`, `disable_cards` and November's `objective` and
  `exclude_domains` are model-visible in the live schema, so only the model sets them;
  `safety_mode` is accepted by the server but absent from the schema, so pinning is the
  only way to reach it at all. A keyless probe pinned `mode=pro, max_results=2,
  disable_cards=true, objective=...` through `tools_arguments` and got 2 791 characters
  of tool output against 21 951 unbounded — that difference lands in the LLM context on
  every search turn. The constructor pins only `mode`. — *Needs a call: whether to grow
  the constructor past `mode`, and whether the shape is named arguments or a
  pinned-arguments passthrough to `MCPClient(tools_arguments=...)`.*
- **`session_id` is never sent** (low, since 2026-11-09) — Keenable asks for the same
  value on every call of one agent session so its requests group together; left in the
  model's hands it varies call to call or is omitted. — *Needs a call: whether the
  wrapper should mint and pin a session id by default, which changes what every call
  sends.*
- **Operator overrides `_meta` unreachable** (low, since 2026-09-01) — `skip_cache` has
  no path: `_call_tool_text` never passes `meta=` to `session.call_tool`, though mcp
  2.3.0's signature still takes one. Pinning `mode` as a tool argument still works. —
  *Needs a call: whether `skip_cache` earns a request-`_meta` hook in `MCPClient`.*

Accounted for from 2026-11-09: all three carried gaps still hold and keep their
`first_seen`. November's stricter parameter checking (`unknown_parameter`, `400`) does
not touch the wrapper — `mode` is on the server's supported list, confirmed live — and
`fetch_page_content`'s default `max_chars` dropping 50 000 → 20 000 only shrinks what
reaches the context. No deprecation notice touches the two web tools; the `mcp` extra
is still `mcp[cli]>=2.1.1,<3` with the lock on 2.3.0, PyPI's latest.
