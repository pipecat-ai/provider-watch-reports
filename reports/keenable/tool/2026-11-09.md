# Keenable tool — 2026-11-09

`KeenableWebSearch` is current: keyless connect works, both tools are advertised, the
pinned `mode` argument is still accepted and hidden from the model. Keenable's November
release added three search parameters; all three reach the model through the live schema,
and none can be pinned by the operator — the standing constructor-shape question.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **No way to pin the search knobs** (medium, since 2026-09-01) — `max_results` (1–50,
  default 10), `snippet_max_length` (180–10000) and November's `disable_cards` are all in
  the live `search_web_pages` schema, so only the model sets them. A keyless probe pinned
  `mode=pro, disable_cards=true, max_results=2` through `MCPClient`'s `tools_arguments`
  path and got 997 characters of tool output, against 21 951 unbounded last run — that
  difference lands in the LLM context on every search turn. The constructor pins only
  `mode`. — *Needs a call: whether to grow the constructor past `mode`, and whether the
  shape is named arguments or a pinned-arguments passthrough to
  `MCPClient(tools_arguments=...)`.*
- **`session_id` is never sent** (low, since 2026-11-09) — November added `session_id`
  (≤128 chars) to both tools, with Keenable asking for the same value on every call of one
  agent session so its requests group together. That is a per-session identifier the
  wrapper could mint once and pin, not a knob a user tunes; left in the model's hands it
  varies call to call or is omitted, and grouping never happens. — *Needs a call: whether
  the wrapper should mint and pin a session id by default, which changes what every call
  sends.*
- **Operator overrides `_meta` unreachable** (low, since 2026-09-01) — Keenable documents
  `_meta["keenable/overrides"]` on `tools/call` as the integrator channel for `mode` and
  `skip_cache`. The wrapper pins `mode` through tool arguments, which the live schema still
  accepts, so nothing is broken — but `skip_cache` has no path: `_call_tool_text` never
  passes `meta=` to `session.call_tool`, though mcp 2.3.0's signature still takes one. —
  *Needs a call: whether `skip_cache` earns a request-`_meta` hook in `MCPClient`.*

Accounted for from 2026-09-14: both carried gaps still hold and keep their `first_seen`;
the fetch tool's `published_at` moved from Unix seconds to an ISO 8601 string in November,
which the wrapper does not parse (the text goes straight to the LLM), so it is not a gap.
The `mcp` extra is now `mcp[cli]>=2.1.1,<3` and the lock resolves 2.3.0, PyPI's latest.
