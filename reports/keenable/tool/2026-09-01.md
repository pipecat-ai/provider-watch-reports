# Keenable tool — 2026-09-01

`KeenableWebSearch` matches the server as it stands today: keyless connect works, both
tools are advertised, and the pinned `mode` argument is still accepted. Nothing to fix;
three items for a maintainer to weigh.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **`mcp[cli]` pinned below 2.x** (medium, since 2026-09-01) — the `keenable` extra is
  `pipecat-ai[mcp]`, whose pin is `mcp[cli]>=1.11.0,<2`; the SDK is on 2.1.1 (2026-08-25),
  with 2.0.0 (2026-07-28) replacing the transport + `ClientSession` + `initialize()` pattern
  `MCPClient` is built on with a unified `Client`. — *Needs a call: the pin is shared by
  every MCPClient user, so moving it means migrating `MCPClient` and deciding the 1.x floor,
  not a keenable-only bump.*
- **No way to pin `max_results` / `snippet_max_length`** (medium, since 2026-09-01) — both
  landed in Keenable's August 2026 update and are in the live `search_web_pages` schema, so
  today only the model can set them. Keyless probe: an unbounded search returned 21 066
  characters of tool output, the same query with `max_results=2` returned 4 803 — that
  difference lands in the LLM context on every search turn. The constructor pins only
  `mode`. — *Needs a call: whether to grow the constructor past `mode`, and whether the shape
  is named arguments or a pinned-arguments passthrough to `MCPClient(tools_arguments=...)`.*
- **Operator overrides `_meta` unreachable** (low, since 2026-09-01) — Keenable documents
  `_meta["keenable/overrides"]` on `tools/call` as the integrator channel for `mode` and
  `skip_cache`; the wrapper pins `mode` through tool arguments, which the live schema still
  accepts and `MCPClient` strips from the model-visible schema, so nothing is broken — but
  `skip_cache` has no path. — *Needs a call: whether `skip_cache` earns a request-`_meta`
  hook in `MCPClient`.*

ad-hoc probes in `.pw-scratch/`, keyless — `KEENABLE_API_KEY` is not set in this
environment, so the keyed `realtime` mode was not exercised.
