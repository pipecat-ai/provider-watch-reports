# Keenable tool — 2026-09-14

`KeenableWebSearch` is current: keyless connect works, both tools are advertised, and
the pinned `mode` argument is still accepted. Last run's `mcp[cli]` pin gap is closed
in-tree; two items remain for a maintainer to weigh.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **No way to pin `max_results` / `snippet_max_length`** (medium, since 2026-09-01) — both
  are in the live `search_web_pages` schema (`max_results` 1–50, default 10;
  `snippet_max_length` 180–10000), so today only the model can set them. Keyless probe: an
  unbounded search returned 21 951 characters of tool output, the same query with
  `max_results=2` returned 4 763 — that difference lands in the LLM context on every search
  turn. The constructor pins only `mode`. — *Needs a call: whether to grow the constructor
  past `mode`, and whether the shape is named arguments or a pinned-arguments passthrough to
  `MCPClient(tools_arguments=...)`.*
- **Operator overrides `_meta` unreachable** (low, since 2026-09-01) — Keenable documents
  `_meta["keenable/overrides"]` on `tools/call` as the integrator channel for `mode` and
  `skip_cache`. The wrapper pins `mode` through tool arguments, which the live schema still
  accepts and `MCPClient` strips from the model-visible schema, so nothing is broken — but
  `skip_cache` has no path: `MCPClient._call_tool_text` never passes `meta=` to
  `session.call_tool`, though the SDK's signature accepts it. A keyless probe confirmed the
  server accepts the `_meta` channel. — *Needs a call: whether `skip_cache` earns a
  request-`_meta` hook in `MCPClient`.*

Accounted for from 2026-09-01: the `mcp[cli]>=1.11.0,<2` pin gap is closed — #5624 ("Support
the MCP SDK's 2.x line", commit 04b468463) moved the `mcp` extra to `mcp[cli]>=1.24.0,<3`,
which covers the current 2.2.0 release, so it is no longer a gap.
