# Rime STT — 2026-11-23

`RimeSTTService` is current and has no open gaps: Rime's STT API has not changed
since its 2026-10-20 launch, and both items the 2026-11-09 report raised have
since been resolved in the repo.

Rime STT still takes no model (`RimeSTTSettings.model` must be `None`), so there
is no default to bump and no catalogue. The `start` message still accepts
exactly `outputContract`, `language` (`en`/`es`, no detection), `mode` and
`contextTerms`, which map one-to-one onto `RimeSTTSettings`. Nothing in the
changelog since 2026-10-20 touches STT — every entry is Prism or on-prem TTS.

Both previous gaps are closed:

- **Prism has no Pipecat service** — `RimeRealtimeLLMService` now ships in
  `src/pipecat/services/rime/realtime/llm.py`, with three examples under
  `examples/realtime/`. Prism is a separate unit's concern now.
- **No docs.pipecat.ai page** — `/api-reference/server/services/stt/rime`
  resolves and documents the constructor and all four settings.

The SDK pin `rimelabs-sdk==0.1.0a31` is one alpha behind `0.1.0a32`
(2026-11-17), but a32 differs from a31 only in `rimelabs_sdk/realtime/`
(`_protocol.py`, `_types.py`) — the `stt/` and `tts/` packages are byte-identical,
so the pin costs this unit nothing. The a32 Prism changes (`eagerness` auto
silence ramp, `end_of_turn_min_silence_ms` on `speech_stopped`,
`prism_request_event_id`) are a `rime/realtime` matter. `rime-api~=0.4.0` is
still a minor behind 0.5.0, still pinned there by `rimelabs-sdk`'s
`rime-api==0.4.0` requirement, and still a `rime/tts` matter.

The SDK's `stt.stream()` takes a client-side `timeout` the service does not set;
Rime's own 120 s stream cap and 15 s silence cap apply regardless, so there is
nothing a user can reach that the service blocks.
