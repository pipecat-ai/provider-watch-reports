# Rime STT — 2026-11-09

`RimeSTTService` (merged 2026-11-07, PR #6602) is current: Rime's STT API has not
changed since its 2026-10-20 launch, and the service's `Settings` already cover
every field of Rime's `start` message. No PR this run.

Rime STT has no model selection — `RimeSTTSettings.model` must be `None` and the
service rejects anything else — so there is no default model to bump and no
catalogue to track. Languages are `en` and `es`; the service passes the tag
through unchanged.

The four `start` parameters Rime documents (`language`, `mode`, `contextTerms`,
`outputContract`) map one-to-one onto `RimeSTTSettings`, including the 1,024-byte
limit on joined context terms. All three were probed live and accepted (below).

The SDK pin is current: `rimelabs-sdk==0.1.0a29` is the latest release
(2026-11-03), and the exact pin matches Rime's own advice to pin the alpha
version you tested against. `rime-api` is behind (`~=0.4.0`, latest 0.5.0) but
that package belongs to `RimeNonJsonTTSService`, and `rimelabs-sdk` requires
`rime-api==0.4.0`, so bumping it is blocked by this unit's SDK — a `rime/tts`
matter, noted here because the two share the extra.

Rime's 8 kHz telephony path is safe on every Python we support: the service
sends the pipeline rate when Rime takes it, and the SDK resamples to 16 kHz with
`audioop`, pulling in `audioop-lts` on Python 3.13+.
