# Rime TTS — 2026-10-12

`coda` is still Rime's flagship and stays the default; the cloud API has not changed since 2026-08-25. No PR this run.

PR #5756 (send `noTextNormalization` on HTTP requests) merged on 2026-09-14, so that gap is closed — `RimeHttpTTSService.run_tts` now puts the field in the payload for mist models.

Rime's two changelog entries since the last run (2026-09-12, 2026-09-25) are on-prem releases only: a Coda 1.0.5 checkpoint with new voices and corrected duration limits, and newer container image tags. Neither touches the cloud API our classes call.

The community PR https://github.com/pipecat-ai/pipecat/pull/5629 (protobuf "WebSocket v1" plus a `rime-api` dependency) is still open. Rime's websocket docs still name `/ws3` — what `RimeTTSService` speaks — the recommended endpoint and document no protobuf protocol, so provider-watch tracks no gap for it.

The previous run's `models_seen` listed `mistv1`; Rime's models page names that legacy April-2023 model `mist`, which is the same thing.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **US East endpoint for the HTTP service** (medium, since 2026-09-01) — `RimeHttpTTSService.__init__` pins `https://users.rime.ai/v1/rime-tts`, so a bot deployed in `us-east-1` pays Rime's documented 60-85 ms coast-to-coast hop; `RimeTTSService` already accepts `url=` and can point at `wss://users-east-ws.rime.ai/ws3`. — *Needs a call: exposing it means a new constructor parameter (`base_url=`), which is a public-API decision.*
- **`segment=never` is unusable with a per-turn flush** (medium, since 2026-09-14) — Rime's segmentation page still marks `segment=never` the recommended setting for production voice agents: the server buffers every token and synthesizes only on `flush`. `TTSService` sends `flush_audio` once, when the bot turn ends, so setting `segment="never"` (the field is exposed) withholds all audio until the turn is complete. The services leave `segment` unset today, taking Rime's `bySentence` default, which matches Pipecat's sentence aggregation. — *Needs a call: following Rime's recommendation means flushing per aggregated utterance rather than per turn — a change in synthesis cadence, not a settings pass-through.*
- **Mist-era field labels no longer match Rime's docs** (low, since 2026-10-12) — `RimeTTSSettings` documents `speedAlpha`, `phonemizeBetweenBrackets`, `noTextNormalization` and friends as "(mistv2 only)", but both services send them for every non-coda model and `speedAlpha` for every model including Coda, which accepts it (probe below). Rime's Mist v2 reference now says Coda and Mist v3 read `speedAlpha` the other way round (higher is faster), and its custom-pronunciation page extends `phonemizeBetweenBrackets` to English Mist v3 while the models page denies Mist v3 any inline pronunciation control. — *Needs a call: Rime's pages contradict each other on model applicability, and Coda's documented speed control is `timeScaleFactor`, so fixing the labels needs a stance on what the service should send to Coda.*
