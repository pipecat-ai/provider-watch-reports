# Rime TTS — 2026-11-09

`coda` is still Rime's flagship and stays the default. Nothing Pipecat sends is retired, but Rime
reorganized its endpoints onto per-model hosts and Coda's documented pronunciation control
(`customLexicon`) is reachable from none of our classes. No PR this run: every item needs a call.

Since the last run Rime shipped two products outside this unit — speech-to-text (2026-10-20), which
Pipecat now wraps as `RimeSTTService`, and **Prism** (2026-10-28), an English speech-to-speech model
at `wss://prism.api.rime.ai/v1/realtime` using OpenAI Realtime beta event names, which Pipecat has no
service for.

`RimeV1TTSService` landed in #6208 (merged 2026-10-16); the community PR #5629 the last report tracked
was closed in its favor. The class is invisible to provider-watch (gap above) and was probed by hand.

Coda v2 exists only as an on-prem image so far (changelog 2026-10-28/11-04: faster first bytes, a
WebSocket `stop` message, Rime no longer publishing Coda v1 tags). The cloud models page still lists
only `coda`, `mistv3`, `mistv2` and legacy `mist`, so there is no cloud model string to adopt yet —
re-check next run.

`rime-api` 0.5.0 is out, ahead of our `~=0.4.0` pin, but the pin must stay: `rimelabs-sdk==0.1.0a29`
(the STT dependency) requires `rime-api==0.4.0`, and 0.5.0 adds only gRPC stubs — its
`text_to_speech.proto` is byte-identical to 0.4.0's.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Coda custom pronunciation is unreachable** (medium, since 2026-11-09) — Rime documents `customLexicon` (array of `{spelling, pronunciation}` in X-SAMPA, up to 500 entries, en/de/es/fr/it/pt) as the way to fix pronunciation on Coda; a probe POST carrying it returns 200 and WebSocket v1 accepts the equivalent `custom_lexicon`. No Rime `Settings` class has a field for it, and `RimeTTSService.PRONOUNCE()` — which sets `phonemizeBetweenBrackets` — is accepted and ignored by Coda, so on the default model it silently does nothing. — *Needs a call: `RimeTTSSettings` is shared by the websocket and HTTP classes and the websocket class pastes settings into the URL query string unencoded, so a shared field needs a stance on how (or whether) the websocket class sends a JSON array.*
- **Mist v3 now 400s on `phonemizeBetweenBrackets` for de/es/fr** (medium, since 2026-11-09) — confirmed against the cloud: `lang=de` with the field returns `400 invalid_input` ("phonemizeBetweenBrackets is not supported for language \"de\""), without it 200, and `lang=en` with it 200. Both the websocket and HTTP classes pass the setting through for any non-coda model and any language, and `PRONOUNCE()` sets it implicitly, so a German or French Mist v3 bot loses the turn. — *Needs a call: whether the services should drop or warn about model- and language-specific fields rather than pass the user's setting through.*
- **HTTP class pins a legacy path with no override** (medium, since 2026-09-01) — `RimeHttpTTSService.__init__` hard-codes `https://users.rime.ai/v1/rime-tts`. Rime's cheat sheet now documents per-model hosts (`https://coda.api.rime.ai/`, `https://mist.api.rime.ai/`) as where HTTP TTS requests must go, documents neither the pinned path nor the `users-east` regional hosts the earlier form of this gap was about (`/docs/regional-endpoints` redirects to the cheat sheet), and the pinned path still answers 200. The same payload works against both hosts. — *Needs a call: exposing the host means a new constructor parameter (`base_url=`), and moving the default to the per-model hosts is a behavior change; both are public-API decisions.*
- **`segment=never` is unusable with a per-turn flush** (medium, since 2026-09-14) — Rime still marks `segment=never` the recommended setting for production voice agents, with synthesis only on `flush`; `TTSService` flushes once, at end of turn, so the setting withholds all audio until the turn is complete. The services leave `segment` unset and take Rime's `bySentence` default. WebSocket v1 avoids this: `RimeV1TTSService` maps token streaming onto `SPLIT_STRATEGY_ACCUMULATE_SENTENCE`. — *Needs a call: following Rime's recommendation means flushing per aggregated utterance rather than per turn — a change in synthesis cadence, not a settings pass-through.*
- **WebSocket v1 word timestamps are left off** (medium, since 2026-11-09) — `RimeV1TTSService` never sets `timestamps.enable` and its docstring states "WebSocket v1 does not report word timestamps"; a probe that enabled it got five aligned spans back in `done`, and Rime documents the feature for Coda in de/en/es/fr/it/pt and Mist v3 in en. Moving from `/ws3` to v1 therefore drops word timestamps. — *Needs a call: v1 delivers every span in the terminal `done` event, after the context's audio, so turning them on means deciding how late timestamps should feed word tracking.*
- **RimeV1TTSService is outside provider-watch** (medium, since 2026-11-09) — `inventory.py` derives a unit's type from the module stem, so `src/pipecat/services/rime/tts_v1.py` belongs to no unit: no report covers the class and `probe.py run --service RimeV1TTSService` answers "unknown service class". — *Needs a call: whether `tts_v1` folds into the `rime/tts` unit or becomes its own variant unit.*
- **Dutch missing from the language maps** (low, since 2026-11-09) — Rime lists `nl` among Coda's ten languages (one Dutch voice); neither `language_to_rime_language` nor `language_to_rime_v1_language` has a `Language.NL` entry, so Dutch goes through the unverified base-code fallback and logs a warning. — *Needs a call: the legacy map holds ISO 639-2 codes while Rime's canonical form is now BCP-47, so adding Dutch needs a choice of code form.*
- **Mist-era field labels no longer match Rime's docs** (low, since 2026-10-12) — `RimeTTSSettings` documents `speedAlpha`, `phonemizeBetweenBrackets` and friends as "(mistv2 only)", but both services send them for every non-coda model and `speedAlpha` for every model including Coda, which accepts it. Rime says Coda and Mist v3 invert the `speedAlpha` direction, and scopes `phonemizeBetweenBrackets` to English Mist v3. — *Needs a call: Rime's pages contradict each other on model applicability and Coda's documented speed control is `timeScaleFactor`, so fixing the labels needs a stance on what the service should send to Coda.*
