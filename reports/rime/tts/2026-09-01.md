# Rime TTS — 2026-09-01

`coda` is Rime's flagship and stays the default; the actionable finding is the language map — `Language.EN_US` and every other region-qualified value makes Rime drop the websocket without synthesizing. Branch ready.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5564 — Map Rime's Coda languages and fall back to base language codes

### To consider
- **US East endpoint for the HTTP service** (medium, since 2026-09-01) — `RimeHttpTTSService.__init__` pins `https://users.rime.ai/v1/rime-tts`, so a bot deployed in `us-east-1` pays Rime's documented ~60 ms coast-to-coast hop; `RimeTTSService` already accepts `url=` and can point at `wss://users-east-ws.rime.ai/ws3`. — *Needs a call: exposing it means a new constructor parameter (`base_url=`), which is a public-API decision.*
- **`noTextNormalization` never reaches the HTTP request** (medium, since 2026-09-01) — the field is on `RimeTTSSettings` and documented on Rime's HTTP endpoint, and `RimeTTSService` sends it, but `RimeHttpTTSService.run_tts` builds its mist payload with only `pauseBetweenBrackets` and `phonemizeBetweenBrackets`, so setting it silently does nothing. `saveOovs` is dropped at the same site and is deprecated upstream, so it is better left unsent. — *Needs a call: probe.py cannot construct `RimeHttpTTSService` (it requires `aiohttp_session`), so the pass-through is unverified against the live API.*

## Verification

| model  | class          | ok | latency     | note                                                                |
| ------ | -------------- | -- | ----------- | ------------------------------------------------------------------- |
| coda   | RimeTTSService | ✅ | TTFB 146 ms | `voice=luna`, no `lang`                                              |
| coda   | RimeTTSService | ✅ | TTFB 127 ms | `voice=luna`, `lang=en` — ISO 639-1 accepted                         |
| coda   | RimeTTSService | ❌ | TTFB 28 ms  | `voice=luna`, `lang=en-US` — websocket closed, no audio, reconnect loop |
| coda   | RimeTTSService | ✅ | TTFB 123 ms | `voice=akari`, `lang=jpn` — Japanese synthesis                       |
| mistv3 | RimeTTSService | ✅ | TTFB 63 ms  | `voice=astra`, `lang=en` — base codes work on mist too               |
| coda   | RimeHttpTTSService | ❌ | —       | probe harness cannot pass `aiohttp_session` to the constructor       |

Every websocket probe reaches first audio and then stalls: with no transport in the probe pipeline nothing emits `BotStoppedSpeakingFrame`, so `pause_frame_processing=True` holds the `EndFrame`. Latencies above are read from the service's own TTFB metric in the probe log.
