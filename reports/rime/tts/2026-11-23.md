# Rime TTS — 2026-11-23

`coda` remains Rime's flagship and the right default. One branch is ready: `timeScaleFactor` is
gated to Coda in both the websocket and HTTP classes, so Mist v3 users cannot reach the speed
control Rime's own migration guide tells them to use.

**Mist v1 (`mist`) and Mist v2 (`mistv2`) retire on 2026-12-03.** Nothing Pipecat ships names
either as a model — every class defaults to `coda` and no example sets a Mist model — so no code
breaks on that date. Two consequences land on this unit anyway: the non-Coda request branch is
written for Mist v2's parameter set, which Mist v3 only partly keeps (gap above), and Rime's
documented websocket migration path for Mist users is "connect to `wss://users-ws.rime.ai/ws3`
with `modelId=mistv3`" — exactly what `RimeTTSService` does, probed working this run.

Coda v2 is still on-prem only (changelog through 2026-11-23: new voices, speaker metadata,
pronunciation-error detail). The cloud catalogue is unchanged at `coda`, `mistv3` and the two
retiring Mist models, so there is no new cloud model string to adopt.

`rime-api` 0.5.0 remains ahead of our `~=0.4.0` pin, and the pin must stay: `rimelabs-sdk`
0.1.0a31 still requires `rime-api==0.4.0`.

### To consider
- **Mist v3 400s on `phonemizeBetweenBrackets` for de/es/fr** (high, since 2026-11-09) — confirmed against the cloud: `lang=de` with the field returns `400 invalid_input`, without it 200, and `lang=en` with it 200. Both the websocket and HTTP classes pass the setting through for any non-coda model and any language, and `PRONOUNCE()` sets it implicitly, so a German or French Mist v3 bot loses the turn. Mist v1/v2 retiring on 2026-12-03 moves the remaining Mist traffic onto v3. — *Needs a call: whether the services should drop or warn about model- and language-specific fields rather than pass the user's setting through.*
- **Coda custom pronunciation is unreachable** (medium, since 2026-11-09) — Rime documents `customLexicon` (array of `{spelling, pronunciation}` in X-SAMPA, ≤500 entries, en/de/es/fr/it/pt) as the way to fix pronunciation on Coda; no Rime `Settings` class has a field for it, and `PRONOUNCE()` — which sets `phonemizeBetweenBrackets` — is accepted and ignored by Coda. — *Needs a call: `RimeTTSSettings` is shared by the websocket and HTTP classes and the websocket class pastes settings into the URL query string unencoded, so a shared field needs a stance on how (or whether) the websocket class sends a JSON array.*
- **HTTP class pins a legacy path with no override** (medium, since 2026-09-01) — `RimeHttpTTSService.__init__` hard-codes `https://users.rime.ai/v1/rime-tts`, which Rime's cheat sheet no longer documents (it names `coda.api.rime.ai` and `mist.api.rime.ai`); the pinned path still answers 200. — *Needs a call: exposing the host means a new constructor parameter (`base_url=`), and moving the default to the per-model hosts is a behavior change; both are public-API decisions.*
- **`segment=never` is unusable with a per-turn flush** (medium, since 2026-09-14) — Rime marks `segment=never` the recommended setting for production voice agents, with synthesis only on `flush`; `TTSService` flushes once, at end of turn, so the setting withholds all audio until the turn is complete. — *Needs a call: following Rime's recommendation means flushing per aggregated utterance rather than per turn — a change in synthesis cadence, not a settings pass-through.*
- **WebSocket v1 word timestamps are left off** (medium, since 2026-11-09) — `RimeV1TTSService` never sets `timestamps.enable` and its docstring states v1 reports no word timestamps; a probe that enabled it got aligned spans back in `done`. Moving from `/ws3` to v1 therefore drops word timestamps. — *Needs a call: v1 delivers every span in the terminal `done` event, after the context's audio, so turning them on means deciding how late timestamps should feed word tracking.*
- **RimeV1TTSService is outside provider-watch** (medium, since 2026-11-09) — inventory now lists `rime/tts`, `rime/stt` and `rime/realtime`; `src/pipecat/services/rime/tts_v1.py` belongs to none of them, and `probe.py run --service RimeV1TTSService` answers "unknown service class". — *Needs a call: whether `tts_v1` folds into the `rime/tts` unit or becomes its own variant unit.*
- **Mist-era fields outlive the model they are labelled for** (medium, since 2026-10-12) — `RimeTTSSettings` documents `speedAlpha`, `reduceLatency`, `phonemizeBetweenBrackets`, `noTextNormalization` and `saveOovs` as "(mistv2 only)", and the non-coda branch sends them; after 2026-12-03 that branch reaches only Mist v3, where Rime says `speedAlpha` runs in the opposite direction, `noTextNormalization` does nothing, and `phonemizeBetweenBrackets` is English-only. — *Needs a call: Rime documents no replacement for `reduceLatency` and `saveOovs` on Mist v3, so relabelling or dropping them needs a ruling on what the service should still send.*
- **Dutch missing from the language maps** (low, since 2026-11-09) — Rime lists `nl` among Coda's ten languages; neither `language_to_rime_language` nor `language_to_rime_v1_language` has a `Language.NL` entry, so Dutch goes through the unverified base-code fallback and logs a warning. — *Needs a call: the legacy map holds ISO 639-2 codes while Rime's canonical form is now BCP-47, so adding Dutch needs a choice of code form.*
- **An unset voice fails opaquely** (low, since 2026-11-23) — `RimeTTSService()` with no `voice` sends `speaker=None` in the `/ws3` query string and the connection is closed with `Invalid speaker: none`; the user sees "server rejected WebSocket connection: HTTP 400". Omitting the parameter 400s too, so the legacy endpoints have no random-voice default. — *Needs a call: whether an unset voice should raise at construction or pick a documented default voice.*
