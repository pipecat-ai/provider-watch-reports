# Rime TTS — 2026-09-14

`coda` is still Rime's flagship and stays the default; nothing retired or renamed since the last run. The one actionable change is on a branch: `RimeHttpTTSService` now sends `noTextNormalization`, verified against the live API with an ad-hoc probe of the patched class.

PR #5564 (language map) merged on 2026-09-02 and a probe confirms the fix: `language=en-US` now reaches Rime as `eng` and synthesizes, where it used to drop the websocket.

An unrelated community PR, https://github.com/pipecat-ai/pipecat/pull/5629, proposes a protobuf "WebSocket v1" interface plus a `rime-api` dependency (Rime published that package to PyPI on 2026-09-07). Rime's public docs still name `/ws3` — what `RimeTTSService` already speaks — the recommended endpoint and describe no protobuf protocol, so provider-watch tracks no gap for it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5756 — Send noTextNormalization on Rime HTTP requests

### To consider
- **US East endpoint for the HTTP service** (medium, since 2026-09-01) — `RimeHttpTTSService.__init__` pins `https://users.rime.ai/v1/rime-tts`, so a bot deployed in `us-east-1` pays Rime's documented ~60 ms coast-to-coast hop; `RimeTTSService` already accepts `url=` and can point at `wss://users-east-ws.rime.ai/ws3`. — *Needs a call: exposing it means a new constructor parameter (`base_url=`), which is a public-API decision.*
- **`segment=never` is unusable with a per-turn flush** (medium, since 2026-09-14) — Rime's segmentation page marks `segment=never` "recommended for production voice agents": the server buffers every token and synthesizes only on `flush`. `TTSService` sends `flush_audio` once, when the bot turn ends, so setting `segment="never"` (the field is exposed) withholds all audio until the turn is complete. Today the services leave `segment` unset, taking Rime's `bySentence` default, which matches Pipecat's sentence aggregation. — *Needs a call: following Rime's recommendation means flushing per aggregated utterance rather than per turn — a change in synthesis cadence, not a settings pass-through.*

`probe.py run` cannot construct `RimeHttpTTSService` (it requires an `aiohttp_session`), so the HTTP rows come from an ad-hoc script in the scratch dir that builds the class with a session and drives it through `probe.py`'s own pipeline helper against the branch worktree's sources. Websocket probes reach first audio and then stall — with no transport in the probe pipeline nothing emits `BotStoppedSpeakingFrame`, so `pause_frame_processing=True` holds the `EndFrame`; latencies are read from the service's own TTFB metric.
