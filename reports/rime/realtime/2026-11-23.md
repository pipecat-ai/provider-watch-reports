# Rime Realtime — 2026-11-23

`RimeRealtimeLLMService` (Prism, merged over 2026-10-24…11-19) is current: of Prism's documented
session settings only reply review is unreachable, and the probe connects cleanly. No PR this run.

Prism takes one model string, `prism`, so there is no default to bump and no catalogue. Rime refreshed
the model behind it on 2026-11-17 — it now speaks the Coda voices (all but `marielle`) plus `aurora`
and `brando`, still English only — and `RimeRealtimeSettings.voice` is a free string, so every new
voice already passes through. Unset, it takes Prism's server default, `astra`.

The same 2026-11-17 release changed turn timing: with the default `eagerness="auto"`, Prism now adapts
the end-of-turn silence between 0 and 900 ms, so replies can arrive up to 0.9 s later than at launch.
Pipecat bots get that default, and the documented opt-out (`end_of_turn_min_silence_ms=0` or
`eagerness="medium"`) is reachable today through the constructor's
`turn_detection=rimelabs_sdk.realtime.TurnDetection(...)` — no code change needed, but it is worth
knowing when a bot feels slower than it did in October.

Everything else Prism documents as settable is covered: `voice`, `speed`, `instructions`, `tools` with
`prism_filler`, the four `turn_detection` interruption rules, `truncation`, `prism_response_metadata`,
and the connect-time `eagerness` / `prism_end_of_turn_timeout_ms` / `end_of_turn_min_silence_ms`.
`modalities`, `tool_choice` and `input_audio_format` are fixed by Prism and the service sends what it
requires. Nothing the service sends is deprecated; Rime's realtime reference announces no removals.

This unit's existence closes the "Prism has no Pipecat service" item the 2026-11-09 `rime/stt` report
carried.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Reply review is unreachable** (medium, since 2026-11-23) — Prism can hand each chunk of a reply to the backend before speaking it, answering with allow / replace / stop, with a 100–5000 ms `timeout_ms` and an `on_timeout` of `stop`, `speak` or `say`; it is fixed at the first session update and cannot be turned on later. `rimelabs_sdk.realtime` exports `Review`, `ReviewRequest`, `ReviewDecision`, `Allow`, `Replace`, `Stop`, `Speak`, `Say` and `Realtime.connect(review=...)`, and `_settings.review_settings` encodes it, but `RimeRealtimeLLMService` never passes `review` into `connect` and takes no argument for it. — *Needs a call: review is a callback that must return a decision inside the deadline, so it means a new constructor parameter plus a Pipecat-level decision API rather than a settings field.*
- **Push-to-talk mode cannot be selected** (low, since 2026-11-23) — Rime documents `turn_detection: null` with client-side `prism.input_audio_buffer.start` / `input_audio_buffer.commit` as the way to drive turns yourself. `Realtime.connect` unconditionally builds `turn_detection` as an object and `RealtimeSession` exposes no commit, so the SDK cannot send it; the service additionally raises unless turn detection is an SDK `TurnDetection` and reports `ExternalUserTurnStrategies`. — *Needs a call: the blocker is upstream in `rimelabs-sdk`, so Pipecat can only follow once the SDK can express it.*
- **Truncation is not surfaced** (low, since 2026-11-23) — with Prism's default `truncation="auto"` the server trims history to 80% of the window and reports the cut in `response.done` as `ResponseTruncation(items_left_out, first_kept_item_id)`. The service reads `usage` from that event and ignores `truncation`, so on a long call the local `LLMContext` keeps turns Prism has dropped and nothing tells the application. — *Needs a call: whether dropped turns should reach the application and whether the local context should follow Prism's window.*
- **SDK pin one alpha behind** (low, since 2026-11-23) — `rimelabs-sdk==0.1.0a31` against 0.1.0a32 (2026-11-17). Diffing the two sdists, the only realtime change is `SpeechStopped.end_of_turn_min_silence_ms`, which the service does not read; `on_rime_event` still forwards raw SDK events, so an application that wants the field needs the newer SDK. — *Needs a call: the exact pin is shared with `rime/tts` and `rime/stt`, and Rime advises pinning the alpha you tested, so a bump means re-probing all three.*
