# SambaNova LLM — 2026-11-23

Pipecat's default model is gone: SambaNova retired `Meta-Llama-3.3-70B-Instruct` on 11/17/2026, `/v1/models/Meta-Llama-3.3-70B-Instruct` now returns 404, and the credential needed to verify a replacement is still rejected — so this needs a maintainer, not a branch.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default model retired** (high, since 2026-11-23) — SambaNova's deprecations page added a November 17, 2026 entry: `Meta-Llama-3.3-70B-Instruct`, removal date 11/17/2026, recommended replacement `MiniMax-M3.1-Flash`, "deprecated and moved to SambaStack and SambaManaged only". The live API agrees: the model is absent from `/v1/models` and `GET /v1/models/Meta-Llama-3.3-70B-Instruct` answers 404 "Model not found" (unauthenticated, so the 401 on chat does not explain it). `src/pipecat/services/sambanova/llm.py` still ships `self.Settings(model="Meta-Llama-3.3-70B-Instruct")`, so every user who does not pass a model hits a retired model. Nothing else in the repo pins the string — `examples/function-calling/function-calling-sambanova.py`, `examples/update-settings/llm/llm-sambanova.py` and `tests/test_sambanova_llm.py` all follow the default — so the change is the constructor literal and the `Defaults to ...` docstring. The docs page at docs.pipecat.ai also documents the retired string, but that lives in another repo. — *Needs a call: the bump could not be probed (`SAMBANOVA_API_KEY` returns 401 "Incorrect API key provided" on `/chat/completions`, third run running), aiewf-eval's medium-context leaderboard has no row for `MiniMax-M3.1-Flash` or for the outgoing default so no parity can be shown, and SambaNova now labels **every** SambaCloud model Preview — including the replacement it designates — so there is no non-preview choice to bump to.*
- **SambaNova-only body parameters unreachable** (medium, since 2026-09-14) — `top_k`, `repetition_penalty` and `chat_template_kwargs` are in SambaNova's `/chat/completions` schema but not in the openai SDK's signature. Code and spec are both unchanged from last run: `build_chat_completion_params` never sends `top_k`, and `params.update(self._settings.extra)` is splatted into `chat.completions.create(**params)`, so `extra={"top_k": 40}` raises a TypeError and only `extra={"extra_body": {"top_k": 40}}` works. `repetition_penalty` is now documented as supported only on MiniMax and gpt-oss models and silently ignored elsewhere. — *Needs a call: `base_llm.py` states that `top_k` is ignored for openai-client services, so wiring it here deviates from the base class, and a service-built `extra_body` would have to merge with a user's own `extra["extra_body"]` rather than be overwritten by it.*

Carried forward from the previous report, now resolved or reframed:

- The 2026-11-09 gap "Default is the oldest model in SambaNova's catalogue and caps completions at 3072 tokens" (first seen 2026-09-01) is superseded by the retirement above and is not listed separately.
- The whole SambaCloud catalogue is now four models, all Preview, and the models page says plainly that none should be used in production. `reasoning_effort` is a documented `/chat/completions` parameter (`low`/`medium`/`high`) and reaches the API today through `extra`, so it is not a gap; note that `GLM-5.3` defaults to `max` reasoning and serves `medium` as `max`, which would matter if it were ever chosen as the default.
- `service_tier` is still absent from `/chat/completions` (it exists only on the Responses and Messages compatibility schemas), so the service's docstring note stays accurate. `frequency_penalty` and `presence_penalty` remain "accepted for API compatibility" with no effect.
