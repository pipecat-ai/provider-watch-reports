# SambaNova LLM — 2026-11-09

`Meta-Llama-3.3-70B-Instruct` is still correct as the default and nothing in the service is retired; the credential is the thing needing attention — `SAMBANOVA_API_KEY` has now been rejected with 401 on two consecutive runs.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **SambaNova-only body parameters unreachable** (medium, since 2026-09-14) — `top_k`, `repetition_penalty` and `chat_template_kwargs` are in SambaNova's `/chat/completions` schema but not in the openai SDK's signature. `src/pipecat/services/sambanova/llm.py` is unchanged: `build_chat_completion_params` never sends `top_k`, and `params.update(self._settings.extra)` is splatted into `chat.completions.create(**params)`, so `extra={"top_k": 40}` raises a TypeError and only `extra={"extra_body": {"top_k": 40}}` works. `do_sample` has since dropped out of SambaNova's spec, so the parameter list is one shorter than last run. — *Needs a call: `base_llm.py` states that `top_k` is ignored for openai-client services, so wiring it here deviates from the base class, and a service-built `extra_body` would have to merge with a user's own `extra["extra_body"]` rather than be overwritten by it.*
- **Default model age and output cap** (low, since 2026-09-01) — `Meta-Llama-3.3-70B-Instruct` remains Production and undeprecated, named on the deprecations page only as a replacement target. It is now the only catalogued model with a small output budget: `/v1/models` gives it `max_completion_tokens` 3072, against 131072 for `gpt-oss-120b` and `gemma-4-31B-it` and 1048576 for `GLM-5.3` and `MiniMax-M3.1-Flash`. For voice replies 3072 tokens is ample, so this is a characterisation, not a defect. — *Needs a call: SambaNova designates no successor, and aiewf-eval's medium-context leaderboard has no row for the current default, so no candidate can be shown at parity. `GLM-5.3` is the only catalogued model with a row (97.7% pass / 2376 ms TTFAT P50, low reasoning) but that row is Z.AI-hosted, and SambaNova neither documents nor announced GLM-5.3 at all.*

Three observations that are not gaps for Pipecat:

- SambaNova's live catalogue and its docs have drifted apart. `/v1/models` now serves `GLM-5.3` (priced, but absent from the models page, the release notes and any announcement) and `MiniMax-M3.1-Flash`, while `DeepSeek-V3.1` — which the models page still calls Production — and `DeepSeek-V3.2` are gone, as is last run's `MiniMax-M3`. Pipecat hardcodes none of these, so nothing needs changing; treat the live endpoint, not the docs, as the catalogue of record.
- Last run's open question about `MiniMax-M2.7` is answered: the deprecations page now lists it with removal date 10/1/2026, replaced by `MiniMax-M3`. It was a real retirement, announced late.
- `service_tier` has appeared in SambaNova's spec since last run, but only on the Responses and Anthropic-Messages compatibility schemas, where it is "accepted for API compatibility" with "no effect on server behavior". `/chat/completions` still has no `service_tier`, so the service's docstring note that SambaNova doesn't support it stays accurate.
