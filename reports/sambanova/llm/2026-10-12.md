# SambaNova LLM — 2026-10-12

Nothing changed at SambaNova since 2026-09-14 and `Meta-Llama-3.3-70B-Instruct` remains current; the credential is the only thing needing attention — `SAMBANOVA_API_KEY` now gets 401 `invalid_api_key` from `/chat/completions`.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **SambaNova-only body parameters unreachable** (medium, since 2026-09-14) — `top_k`, `do_sample` and `chat_template_kwargs` are in SambaNova's schema but not in the openai SDK's signature. `src/pipecat/services/sambanova/llm.py` is unchanged since the last run: `build_chat_completion_params` never sends `top_k`, and `params.update(self._settings.extra)` is splatted into `chat.completions.create(**params)`, so `extra={"top_k": 40}` raises a TypeError and only `extra={"extra_body": {"top_k": 40}}` works. — *Needs a call: `base_llm.py` states that `top_k` is ignored for openai-client services, so wiring it here deviates from the base class, and a service-built `extra_body` would have to merge with a user's own `extra["extra_body"]` rather than be overwritten by it.*
- **Default model age** (low, since 2026-09-01) — `Meta-Llama-3.3-70B-Instruct` is the oldest of SambaNova's production models and the deprecations page still lists it only as a replacement target, never as deprecated; the three preview models are not default candidates. — *Needs a call: SambaNova designates no successor, and the aiewf-eval medium-context leaderboard still carries no Llama row and no SambaNova-hosted row (`gpt-oss-120b` appears only via Groq at 86.3%), so there is no comparable benchmark to justify a bump.*

Two observations that are not gaps for Pipecat:

- `MiniMax-M2.7` has disappeared from the live `/v1/models` catalogue while both docs mirrors still list it as Production and the deprecations page does not mention it. Pipecat hardcodes no MiniMax model for SambaNova, so nothing here needs changing; re-check next run in case it is an unannounced retirement.
- SambaNova's spec annotates `frequency_penalty` and `presence_penalty` as "not currently implemented". Pipecat sends both (via #5565); they are accepted and ignored, so setting them has no effect on SambaNova today. No code change is warranted — removing them would regress the day SambaNova implements them.
