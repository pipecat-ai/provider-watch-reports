# ElevenLabs Dialogue TTS — 2026-09-01

`eleven_v3_conversational` remains the model ElevenLabs recommends for realtime
v3 synthesis, and nothing on the endpoint is deprecated. One branch adds the one
documented query parameter the service never sends.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5554 — Expose apply_text_normalization on ElevenLabsDialogueTTSService

### To consider
- **Pronunciation dictionaries** (medium, since 2026-09-01) — the multi-stream Text-to-Dialogue endpoint accepts `pronunciation_dictionary_locators` on a context's first message, alongside the `voices` and `voice_settings` the service already sends; `ElevenLabsTTSService` takes the same locators as a constructor argument, this class has no way to pass them. — *Needs a call: it means a new constructor argument, and Text-to-Dialogue documents `normalized_alignment` as "reserved for future use, currently unused", so with a dictionary in play the word timestamps built from the raw alignment would no longer match the spoken text.*
- **Multi-speaker contexts** (low, since 2026-09-01) — `eleven_v3` registers up to 10 voices per context and each input names the `voice_id` that speaks it; the service registers only `settings.voice` and tags every input with it, so the dialogue the endpoint is named for cannot be produced. `eleven_v3_conversational`, the default, is capped at one voice per context anyway. — *Needs a call: whether a Pipecat TTS service should express per-utterance speakers, and through what API.*
- **Missing voice** (low, since 2026-09-01) — constructing the service without a `voice` leaves `_send_context_init` sending `voices: [null]`; ElevenLabs replies `Could not validate message: voices.0: Input should be a valid string`, closes the connection, and the turn ends with no audio. `_register_keepalive_context` already handles the unset case with a debug line. — *Needs a call: refuse a missing voice at construction, as a required setting, or keep logging and let the server answer.*

Probe commands: `probe.py run --service ElevenLabsDialogueTTSService --model
eleven_v3_conversational --setting voice=$ELEVENLABS_VOICE_ID`. `probe.py` never
prints its JSON for this class — the service is constructed with
`pause_frame_processing=True` and the probe pipeline has no output transport, so
the `EndFrame` never drains and the process has to be killed; latencies above are
the service's own TTFB/TTFA metric lines. To probe the branch, run the
*worktree's* copy of `probe.py`: `inventory.py` puts its own `REPO_ROOT/src` at
the front of `sys.path`, so `PYTHONPATH` alone does not make a worktree's sources
win.
