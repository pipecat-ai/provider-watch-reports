# ElevenLabs Dialogue TTS — 2026-10-12

The default moved to `eleven_v4_turbo` upstream (#5959) and that is the model
ElevenLabs now recommends for realtime Text-to-Dialogue, so nothing is owed on
the default. One branch is ready: `eleven_v4`, the sibling model the class
explicitly accepts, has no entry in the language table, so any `language` a user
sets on it is dropped with a warning.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6133 — Accept a language code for eleven_v4
- https://github.com/pipecat-ai/pipecat/pull/5554 — Expose apply_text_normalization on ElevenLabsDialogueTTSService (open since 2026-09-01)

### To consider
- **Pronunciation dictionaries** (medium, since 2026-09-01) — the multi-stream Text-to-Dialogue endpoint accepts `pronunciation_dictionary_locators` on a context's first message, alongside the `voices` and `voice_settings` the service already sends; `ElevenLabsTTSService` takes the same locators as a constructor argument, this class has no way to pass them. — *Needs a call: it means a new constructor argument, and Text-to-Dialogue documents `normalized_alignment` as reserved and currently unused, so with a dictionary in play the word timestamps built from the raw alignment would no longer match the spoken text.*
- **Multi-speaker contexts** (medium, since 2026-09-01) — each input names the `voice_id` that speaks it, and a context can register several voices; the service registers only `settings.voice` and tags every input with it, so the dialogue the endpoint is named for cannot be produced. This was low while the default was `eleven_v3_conversational`, which takes exactly one voice per context; `eleven_v4_turbo` accepted a two-voice context in this run's probe, so the default model can now do what the service cannot express. — *Needs a call: whether a Pipecat TTS service should express per-utterance speakers, and through what API.*
- **Missing voice** (low, since 2026-09-01) — `_send_context_init` reads the voice through `assert_given`, which only rejects `NOT_GIVEN`, so an unset voice reaches the wire as `voices: [null]`; ElevenLabs answers `Could not validate message: voices.0: Input should be a valid string` and the turn ends with no audio. Reproduced this run by probing without a voice. — *Needs a call: refuse a missing voice at construction, as a required setting, or keep logging and let the server answer.*
- **New Text-to-Dialogue request options** (low, since 2026-10-12) — ElevenLabs added `settings.similarity` (0–1, default 0.75), `use_pvc_as_ivc`, and `previous_text`/`future_text` with `previous_request_ids`/`next_request_ids` on 2026-09-28. They are documented for the HTTP Text-to-Dialogue endpoints only; the multi-stream websocket reference still lists `stability` as the one supported voice setting. The websocket accepted `similarity`, `similarity_boost`, `speed` and `use_speaker_boost` in `voice_settings` without an error, but it accepts unknown keys silently, so that is not evidence they take effect. — *Needs a call: confirmation that the websocket honours these before adding Settings fields whose effect we cannot demonstrate.*

Ad-hoc websocket probes (`.pw-scratch/ttd_language_probe.py`,
`ttd_multivoice_probe.py`, `ttd_voice_settings_probe.py`), one short connection
per case:

- `eleven_v4` with `language_code` `de`, `yue`, `ast`, `mi`, `uz` — all synthesise; `zz` is rejected with `Model 'eleven_v4' does not support language 'zz'`. The endpoint validates the code, and `eleven_v4` takes the same set as `eleven_v4_turbo`.
- `eleven_v4_turbo` with two `voices` registered on one context and an input per voice — synthesises.
- `eleven_v4_turbo` `voice_settings` with `similarity`, `similarity_boost`, `speed`, `use_speaker_boost` — all accepted without an error, which only shows the server ignores unknown keys.

`probe.py run` reaches and reports the measurement for this class now, but still
does not shut down once audio flows: the service is constructed with
`pause_frame_processing=True` and the probe pipeline has no output transport, so
the `EndFrame` never drains and the process has to be killed. Probing a branch
needs the probe run from inside the worktree — `inventory.py` inserts its own
`REPO_ROOT/src` at `sys.path[0]`, so `PYTHONPATH` cannot redirect it.
