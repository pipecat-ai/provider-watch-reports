### To consider
- **Pronunciation dictionaries** (medium, since 2026-09-01) — the multi-stream Text-to-Dialogue endpoint accepts `pronunciation_dictionary_locators` on a context's first message, alongside the `voices` and `voice_settings` the service already sends; `ElevenLabsTTSService` takes the same locators as a constructor argument, this class has no way to pass them. ElevenLabs capped dictionary expansion at 50× the input plus 10,000 characters on 2026-11-02, which an implementation would have to stay under. — *Needs a call: it means a new constructor argument, and Text-to-Dialogue documents `normalized_alignment` as reserved and currently unused, so with a dictionary in play the word timestamps built from the raw alignment would no longer match the spoken text.*
- **Multi-speaker contexts** (medium, since 2026-09-01) — each input names the `voice_id` that speaks it and a context can register several voices; the service registers only `settings.voice` and tags every input with it. The websocket reference now documents the per-model limits it previously omitted: `eleven_v3` takes up to 10 voices per context, `eleven_v3_conversational` and `eleven_v4` exactly one. The default `eleven_v4_turbo` is not named in that table, and the previous run's probe had it accept a two-voice context, so the ceiling for the default model is unsettled. — *Needs a call: whether a Pipecat TTS service should express per-utterance speakers, and through what API.*
- **Missing voice** (low, since 2026-09-01) — `_send_context_init` reads the voice through `assert_given`, which only rejects `NOT_GIVEN`, so an unset voice reaches the wire as `voices: [null]`; ElevenLabs answers with a validation error and the turn ends with no audio. Unchanged in the code this run; not re-probed. — *Needs a call: refuse a missing voice at construction, as a required setting, or keep logging and let the server answer.*

Closed since the last run:

- `eleven_v4`'s missing entry in `ELEVENLABS_MODEL_LANGUAGES` — #6133 merged 2026-10-12; `tts_base.py` now maps both `eleven_v4` and `eleven_v4_turbo` to `ELEVENLABS_V4_LANGUAGES`.
- The 2026-09-28 Text-to-Dialogue options (`similarity`, `use_pvc_as_ivc`, `previous_text`/`future_text`). The websocket reference now enumerates its `voice_settings` sub-fields as exactly `stability` and `clone_strength`, and the service sends both (`clone_strength` landed in 352a543ad); the rest are HTTP-only. ElevenLabs deprecated `use_pvc_as_ivc` on 2026-10-26 in favour of `clone_strength`.
- `audio_effects`, added 2026-10-12, is not a gap here: it is documented for the HTTP Text-to-Dialogue endpoints only, and its reverb and panning options are rejected outright for `pcm_*` output, which is what this service requests.
