## What's new for Pipecat

### PRs

### To consider
- **Pronunciation dictionaries** (medium, since 2026-09-01) — the multi-stream Text-to-Dialogue endpoint accepts `pronunciation_dictionary_locators` on a context's first message, alongside the `voices` and `voice_settings` the service already sends; `ElevenLabsTTSService` takes the same locators as a constructor argument, this class has no way to pass them. Expansion is capped at 50× the input plus 10,000 characters since 2026-11-02, which an implementation would have to stay under. — *Needs a call: it means a new constructor argument, and Text-to-Dialogue documents `normalized_alignment` as reserved and unused, so with a dictionary in play the word timestamps built from the raw alignment would no longer match the spoken text.*
- **Multi-speaker contexts** (medium, since 2026-09-01) — each input names the `voice_id` that speaks it and a context can register several voices; the service registers only `settings.voice` and tags every input with it. The per-model ceilings are still contradictory: the websocket reference gives `eleven_v3` 10 voices per context, `eleven_v3_conversational` and `eleven_v4` exactly one, and omits the default `eleven_v4_turbo`, while ElevenLabs' `elevenlabs/skills` streaming reference gives `eleven_v4_turbo` one and `eleven_v4` ten, and the 2026-10-12 probe had `eleven_v4_turbo` accept a two-voice context. — *Needs a call: whether a Pipecat TTS service should express per-utterance speakers, and through what API.*
- **Missing voice** (low, since 2026-09-01) — `_send_context_init` reads the voice through `assert_given`, which only rejects `NOT_GIVEN`, so an unset voice reaches the wire as `voices: [null]`; ElevenLabs answers with a validation error and the turn ends with no audio. Unchanged in the code this run; not re-probed. — *Needs a call: refuse a missing voice at construction, as a required setting, or keep logging and let the server answer.*

Closed since the last run:

- `apply_text_normalization` — #5554 merged 2026-11-10. The setting is a `Literal["auto", "on", "off"]` field in `URL_FIELDS`, so a change reconnects and the query parameter carries it.

Considered and not a gap:

- 2026-11-17 deprecated `apply_language_text_normalization` on the Text-to-Speech endpoints. Text-to-Dialogue never accepted it and no Pipecat service sends it.
- 2026-11-17 changed the multi-stream close code for an unknown `model_id` from 1011 to 1008. Both surface as `ConnectionClosedError`, so the bounded reconnect in `websocket_service.py` behaves the same; the constructor already warns for a model outside the v3/v4 families.
