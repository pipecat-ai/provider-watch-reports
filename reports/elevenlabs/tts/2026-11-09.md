# ElevenLabs TTS — 2026-11-09

Nothing urgent. Both of last run's top items landed in main, and `eleven_flash_v2_5`
stays the default; the remaining five items are pass-through parameters, each
needing a call. No branch, and no probe either: the API key in the environment
is invalid.

Closed since 2026-10-12:

- **Eleven v3/v4 on the WebSocket service** (was high) — commit `95ca0f9eb`
  warns at construction when `ElevenLabsTTSService` is given an `eleven_v3*` or
  `eleven_v4*` model, pointing at `ElevenLabsDialogueTTSService` and
  `ElevenLabsHttpTTSService`. That is one of the three options the gap put to a
  maintainer, so the item is settled.
- **`eleven_v4` language codes** (was medium) — PR
  [#6133](https://github.com/pipecat-ai/pipecat/pull/6133) (merged 2026-10-12)
  added `eleven_v4` to `ELEVENLABS_MODEL_LANGUAGES` against
  `ELEVENLABS_V4_LANGUAGES`.

`eleven_flash_v2_5` remains the right default: the models page still lists it as
active, ~100 ms, cheapest per character, with no successor named. `eleven_v4_turbo`
is ElevenLabs' low-latency recommendation but is served only by the Text-to-Dialogue
API, which is a different Pipecat class. The page's only deprecated TTS models are
`eleven_turbo_v2` and `eleven_turbo_v2_5`, which no default, docstring or example
pins; `ELEVENLABS_PHONEME_MODELS` and `ELEVENLABS_MODEL_LANGUAGES` mention
`eleven_turbo_v2*` deliberately, to describe models a user may still pass.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`clone_strength`** (medium, since 2026-11-09) — added to TTS `voice_settings` on 2026-10-26 (0-1, how closely a v4 Professional Voice Clone follows its samples; ElevenLabs recommends 0 for most uses), and on 2026-11-02 v4 PVC fine-tuning opened to all workspaces, so the audience is no longer enterprise-only. `ElevenLabsDialogueTTSService` already exposes it as a Settings field that warns on non-v4 models; neither class here does, and both build their `voice_settings` from one hard-coded key list in `build_elevenlabs_voice_settings`. — *Needs a call: the parameter is v4-only, and the WebSocket endpoint serves no v4 model and does not document `clone_strength` among its RealtimeVoiceSettings — so either the field goes on `ElevenLabsHttpTTSSettings` alone, or the shared builder learns which class and model it is building for.*
- **`audio_effects`** (low, since 2026-11-09) — new on 2026-10-12 on create/stream speech including the with-timestamps endpoint `ElevenLabsHttpTTSService` posts to: a nested object with `filter_preset_id` (e.g. `phone`), `distance`, `environment_id`, `background_noise_id`, `send_level` and `pan`, with valid ids from `GET /v1/audio-effects/catalog`. Not in `ElevenLabsHttpTTSSettings`; the WebSocket endpoint has no equivalent. — *Needs a call: reverb and a non-zero pan return stereo audio and are rejected with 400 for `pcm_*`, `ulaw_*` and `alaw_*`, which are the formats a Pipecat pipeline requests, so exposing the object means exposing fields that will always fail here.*
- **`seed`** (low, since 2026-08-25) — still documented on the multi-stream WebSocket (query parameter) and in the HTTP body; neither `Settings` class has it. `ElevenLabsDialogueTTSService` accepts it, but as a constructor argument appended to its URL. The 2026-10-12 `seed` deprecation applies to the Agents Platform's TTS `effects` block, not to these endpoints. — *Needs a call: Settings field or constructor argument to match the dialogue service, and on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`apply_language_text_normalization`** (low, since 2026-08-25) — an HTTP-body boolean (default `false`), documented as Japanese-only and as significantly increasing latency; not in `ElevenLabsHttpTTSSettings`, and the WebSocket endpoint has no equivalent. — *Needs a call: whether to add a field that only one of the two classes can honor and that costs latency.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — still the one parameter marked deprecated on the stream-with-timestamps reference; `ElevenLabsHttpTTSSettings` still offers it undecorated. No removal date, requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*
