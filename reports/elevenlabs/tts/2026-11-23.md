# ElevenLabs TTS — 2026-11-23

Nothing urgent, no branch. `eleven_flash_v2_5` stays the default, one open item
closed itself when ElevenLabs deprecated the parameter behind it, and the four
that remain are pass-through parameters that each need a maintainer's call. The
API key in the environment is still invalid, so again nothing was measured live.

Closed since 2026-11-09:

- **`apply_language_text_normalization`** (was low, open since 2026-08-25) — the
  2026-11-17 changelog deprecates the parameter on the convert, stream,
  with-timestamps and stream-with-timestamps endpoints, and the
  stream-with-timestamps reference now marks it deprecated with no replacement.
  Adding a Settings field for a parameter the provider is retiring is no longer
  worth doing, so the item is dropped rather than carried.

`eleven_flash_v2_5` remains the right default: the models page still lists it as
active, ~100 ms, 40,000 characters, with no successor named. `eleven_v4_turbo` is
ElevenLabs' low-latency recommendation, but the models page states it is served
by the Text-to-Dialogue WebSocket (and `eleven_v4` by the Text-to-Dialogue API),
which is a different Pipecat class; `ElevenLabsTTSService` already warns when
given a v3/v4 id. The only deprecated TTS models are `eleven_turbo_v2` and
`eleven_turbo_v2_5`, still with no removal dates, and no default, docstring or
example pins either.

One wire-level change on 2026-11-17 needs nothing from us: the `stream-input` and
`multi-stream-input` WebSockets now close with `1008 model_not_found` for an
unknown `model_id` instead of `1011`. Pipecat's receive loop treats any server
close the same way, so the only difference a user sees is the code in the log.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`clone_strength`** (medium, since 2026-11-09) — ElevenLabs added it to TTS `voice_settings` on 2026-10-26 (0-1, how closely a v4 Professional Voice Clone follows its samples). The audience keeps widening: 2026-11-02 opened v4 PVC fine-tuning to all workspaces and made the clone's saved value the fallback when a request sets neither `clone_strength` nor `use_pvc_as_ivc`, and 2026-11-09 added the setting to the Agents Platform TTS config. `ElevenLabsDialogueTTSService` already exposes it as a Settings field that warns on non-v4 models; neither class here does, and both build their `voice_settings` from one hard-coded key list in `build_elevenlabs_voice_settings`. — *Needs a call: the parameter is v4-only, and the WebSocket endpoint serves no v4 model and does not document `clone_strength` among its RealtimeVoiceSettings — so either the field goes on `ElevenLabsHttpTTSSettings` alone, or the shared builder learns which class and model it is building for.*
- **`audio_effects`** (low, since 2026-11-09) — a nested object on create/stream speech including the with-timestamps endpoint `ElevenLabsHttpTTSService` posts to: `filter_preset_id` (e.g. `phone`), `distance`, `environment_id`, `background_noise_id`, `send_level` and `pan`, with valid ids from `GET /v1/audio-effects/catalog`. Not in `ElevenLabsHttpTTSSettings`; the WebSocket endpoint has no equivalent. — *Needs a call: reverb and a non-zero pan return stereo audio and are rejected with 400 for `pcm_*`, `ulaw_*` and `alaw_*`, which are the formats a Pipecat pipeline requests, so exposing the object means exposing fields that will always fail here.*
- **`seed`** (low, since 2026-08-25) — still documented on the multi-stream WebSocket (query parameter) and in the HTTP body, neither of them deprecated; neither `Settings` class has it. `ElevenLabsDialogueTTSService` accepts it, but as a constructor argument appended to its URL. — *Needs a call: Settings field or constructor argument to match the dialogue service, and on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — marked deprecated on the stream-with-timestamps reference with no replacement named; `ElevenLabsHttpTTSSettings` still offers it undecorated. No removal date, requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*
