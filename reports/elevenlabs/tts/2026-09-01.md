# ElevenLabs TTS — 2026-09-01

Current. `eleven_flash_v2_5` remains ElevenLabs' recommended real-time model
(~75 ms documented, 164 ms TTFB measured today) and the catalogue is unchanged
from last week. Last week's branch landed as
[#5431](https://github.com/pipecat-ai/pipecat/pull/5431), closing the
`previous_text` gap. The four remaining items each need a maintainer's call, so
there is no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Eleven v3 on the WebSocket service** (medium, since 2026-08-25) — `ElevenLabsTTSService` with `model="eleven_v3_conversational"` still gets HTTP 403 from `/v1/text-to-speech/{voice}/multi-stream-input`, then `PipelineWorker: ElevenLabsTTSService#0 can no longer do its job`. The v3 models are served only by Text-to-Dialogue, which `ElevenLabsDialogueTTSService` wraps; `ElevenLabsTTSService` gives no hint of that. — *Needs a call: refuse a v3 model id at construction, warn and point at the dialogue service, or leave it to the docs.*
- **`seed`** (low, since 2026-08-25) — ElevenLabs documents `seed` on both the multi-stream WebSocket (query parameter) and the HTTP body; neither `Settings` class has it. `ElevenLabsDialogueTTSService` does accept it, but as a constructor argument appended to its URL. — *Needs a call: Settings field or constructor argument to match the dialogue service, and on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`apply_language_text_normalization`** (low, since 2026-08-25) — an HTTP-body boolean that improves pronunciation, documented as Japanese-only and as heavily increasing latency; not in `ElevenLabsHttpTTSSettings`, and the WebSocket endpoint has no equivalent. — *Needs a call: whether to add a field that only one of the two classes can honor and that costs latency.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — ElevenLabs marks this query parameter deprecated in the API reference; `ElevenLabsHttpTTSSettings` still offers it with no deprecation marker. No removal date is published and requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*

## Verification

| model                    | class                | ok | latency     | note                                                                       |
| ------------------------ | -------------------- | -- | ----------- | -------------------------------------------------------------------------- |
| eleven_flash_v2_5        | ElevenLabsTTSService | ✅ | TTFB 164 ms | audio and alignment received, context closed cleanly (in line with 159 ms last week) |
| eleven_v3_conversational | ElevenLabsTTSService | ❌ | —           | `server rejected WebSocket connection: HTTP 403`, then the processor is marked unusable |

Probe: `probe.py run --service ElevenLabsTTSService --model <id> --setting voice=$ELEVENLABS_VOICE_ID --verbose`, one model per invocation. On the success path the probe never prints its JSON: `TTSService._maybe_pause_frame_processing` holds the `EndFrame` waiting for a `BotStoppedSpeakingFrame`, which only an output transport emits, so the probe pipeline hangs at shutdown and has to be killed. TTFB is read from the service's own metrics line. This is harness-only — the same artifact the previous report saw as `ok:false` — and not a defect in the service. Because of it, repeated/interleaved runs are not available; the single sample matches last week's, and no comparison this run turns on latency. The HTTP class still cannot be driven by `probe.py` (required `aiohttp_session`) and was not re-probed: no code or API change since #5431 landed.
