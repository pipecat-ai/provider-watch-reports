# ElevenLabs TTS — 2026-09-14

Current. `eleven_flash_v2_5` stays the default — ElevenLabs still names no
successor — and the catalogue, the WebSocket schema and the HTTP schema are all
unchanged since 2026-09-01. The four open items are the same four, each still
waiting on a maintainer's call, so there is no branch.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Eleven v3 on the WebSocket service** (medium, since 2026-08-25) — `ElevenLabsTTSService` with `model="eleven_v3_conversational"` gets HTTP 403 from `/v1/text-to-speech/{voice}/multi-stream-input`, then `PipelineWorker#0: ElevenLabsTTSService#0 can no longer do its job`. The v3 models are served only by Text-to-Dialogue, which `ElevenLabsDialogueTTSService` wraps; `ElevenLabsTTSService` gives no hint of that. — *Needs a call: refuse a v3 model id at construction, warn and point at the dialogue service, or leave it to the docs.*
- **`seed`** (low, since 2026-08-25) — ElevenLabs documents `seed` on both the multi-stream WebSocket (query parameter) and the HTTP body; neither `Settings` class has it. `ElevenLabsDialogueTTSService` does accept it, but as a constructor argument appended to its URL. — *Needs a call: Settings field or constructor argument to match the dialogue service, and on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`apply_language_text_normalization`** (low, since 2026-08-25) — an HTTP-body boolean (default `false`) that improves pronunciation, documented as Japanese-only and as heavily increasing latency; not in `ElevenLabsHttpTTSSettings`, and the WebSocket endpoint has no equivalent. — *Needs a call: whether to add a field that only one of the two classes can honor and that costs latency.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — ElevenLabs marks this query parameter deprecated in the API reference; `ElevenLabsHttpTTSSettings` still offers it with no deprecation marker. No removal date is published and requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*

Probe: `probe.py run --service ElevenLabsTTSService --model <id> --setting voice=$ELEVENLABS_VOICE_ID --verbose`, one model per invocation. On the success path the probe still never prints its JSON — `TTSService._maybe_pause_frame_processing` holds the `EndFrame` waiting for a `BotStoppedSpeakingFrame`, which only an output transport emits — so the pipeline hangs at shutdown and has to be killed, and `--repeat` is unusable. The four samples above are therefore separate invocations with TTFB read from the service's own metrics line. Nothing this run turns on latency. The HTTP class still cannot be constructed by `probe.py` at all, which is what keeps the two HTTP-only `Settings` items below the PR bar rather than any doubt about the parameters themselves.
