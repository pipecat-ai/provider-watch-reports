# ElevenLabs TTS — 2026-10-12

Eleven v4 and Eleven v4 Turbo landed on 2026-09-28 and changed the picture for
this unit: `ElevenLabsHttpTTSService` can use both today, while
`ElevenLabsTTSService` — the class the registry exposes as `elevenlabs_tts` —
rejects every v4 id at the WebSocket handshake. No branch: the fix is a design
call, not a value change.

`eleven_flash_v2_5` stays the default. ElevenLabs does not call v4 Turbo its
successor (Flash v2.5 is still listed, still GA, still the cheapest and the
lowest-latency option), the WebSocket class cannot run v4 at all, and on the
HTTP endpoint v4 Turbo measured slower than Flash (300 ms vs 259 ms TTFB), so
the bump fails the latency test as well.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Eleven v3 and v4 on the WebSocket service** (high, since 2026-08-25) — `ElevenLabsTTSService` with any `eleven_v3*` or `eleven_v4*` model gets a 400 from `/v1/text-to-speech/{voice}/multi-stream-input`, then `PipelineWorker#0: ElevenLabsTTSService#0 can no longer do its job`. The endpoint serves neither family. Raised to high because `eleven_v4_turbo` is now the model ElevenLabs recommends for real-time agents and the ElevenAgents default, so this is the id users will reach for. Both work on `ElevenLabsHttpTTSService` and on `ElevenLabsDialogueTTSService`; neither class nor docstring says so. — *Needs a call: refuse a v3/v4 id at construction, warn and point at the HTTP or dialogue class, or leave it to the docs.*
- **`eleven_v4` language codes** (medium, since 2026-10-12) — `ELEVENLABS_MODEL_LANGUAGES` gained `eleven_v4_turbo` but not `eleven_v4`, so `elevenlabs_language_code` logs "Language code not applied" and drops it, leaving the model to auto-detect. The HTTP endpoint accepted `en` and `yue` for `eleven_v4`, which suggests it shares `ELEVENLABS_V4_LANGUAGES`. — *Needs a call: confirming the set means probing all 84 codes as was done for Turbo; on two samples a one-line table entry is a guess, and a code the model doesn't take is a 400.*
- **`seed`** (low, since 2026-08-25) — documented on both the multi-stream WebSocket (query parameter) and the HTTP body; neither `Settings` class has it. `ElevenLabsDialogueTTSService` does accept it, but as a constructor argument appended to its URL. — *Needs a call: Settings field or constructor argument to match the dialogue service, and on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`apply_language_text_normalization`** (low, since 2026-08-25) — an HTTP-body boolean (default `false`), documented as Japanese-only and as significantly increasing latency; not in `ElevenLabsHttpTTSSettings`, and the WebSocket endpoint has no equivalent. — *Needs a call: whether to add a field that only one of the two classes can honor and that costs latency.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — still marked deprecated on the stream-with-timestamps reference; `ElevenLabsHttpTTSSettings` still offers it with no deprecation marker. No removal date, requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*

`probe.py run` still hangs after a successful TTS turn — `TTSService._maybe_pause_frame_processing` holds the `EndFrame` waiting for a `BotStoppedSpeakingFrame` that only an output transport emits — so each model is a separate invocation killed at the timeout, with TTFB read from the service's own metrics line, and `--repeat` is unusable. Nothing this run turns on a median.

Because `probe.py` cannot construct the HTTP class, the v4 question on it was answered with an ad-hoc script that posts the payload that class builds to `/v1/text-to-speech/{voice}/stream/with-timestamps` (`.pw-scratch/probe_v4b.py`, 5 short requests):

| --------------- | ----------------------------- | ---------------------------------------- |
| eleven_v4_turbo | no language_code              | 200, alignment present, first line 300 ms |
| eleven_v4_turbo | `language_code=en`            | 200, alignment present, 303 ms            |
| eleven_v4       | `language_code=en`            | 200, alignment present, 715 ms            |
