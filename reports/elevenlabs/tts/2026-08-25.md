# ElevenLabs TTS — 2026-08-25

`eleven_flash_v2_5` stays the default — it is still ElevenLabs' lowest-latency
model (~75 ms documented, 159 ms TTFB measured) and nothing supersedes it. One
branch is ready: `eleven_v3_conversational` breaks mid-turn on the HTTP service.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5431 — Omit previous_text for eleven_v3_conversational

  `ELEVENLABS_CONTEXT_UNSUPPORTED_MODELS` listed only `eleven_v3`, so
  `ElevenLabsHttpTTSService` sent `previous_text` for `eleven_v3_conversational`
  and every sentence after the first in a turn came back as
  `400 validation_error / unsupported_model: Providing previous_text or next_text
  is not yet supported with ...` — an `ErrorFrame` and no audio.

### To consider
- **Eleven v3 on the WebSocket service** (medium, since 2026-08-25) — `ElevenLabsTTSService` with `model="eleven_v3_conversational"` gets HTTP 403 from `/v1/text-to-speech/{voice}/multi-stream-input`, retries three times and marks itself unusable; the v3 models are served only by Text-to-Dialogue, which `ElevenLabsDialogueTTSService` (merged in #5353) wraps. — *Needs a call: refuse a v3 model id at construction, warn and point at the dialogue service, or leave it to the docs.*
- **`seed`** (low, since 2026-08-25) — ElevenLabs documents `seed` on both the multi-stream WebSocket (query parameter) and the HTTP body; neither `Settings` class has it. — *Needs a call: on the WebSocket class it is a URL field, so exposing it means adding it to `URL_FIELDS` and accepting a reconnect whenever it changes.*
- **`apply_language_text_normalization`** (low, since 2026-08-25) — an HTTP-body boolean that improves pronunciation, documented as Japanese-only and as heavily increasing latency; not in `ElevenLabsHttpTTSSettings`, and the WebSocket endpoint has no equivalent. — *Needs a call: whether to add a field that only one of the two classes can honor and that costs latency.*
- **`optimize_streaming_latency`** (low, since 2026-08-25) — ElevenLabs marks this query parameter deprecated in the API reference; `ElevenLabsHttpTTSSettings` still offers it with no deprecation marker. No removal date is published and requests still succeed. — *Needs a call: deprecate the field per the project's policy (which version, pointing at what) or just note it in the docstring.*

## Sources
- probe.py list-models --provider elevenlabs — the nine ids above; no Flash v3 and no new low-latency model
- probe.py sdk-versions --provider elevenlabs — no output: the `elevenlabs` extra pins no SDK, the services speak aiohttp/websockets directly, so there is no pin to fall behind
- https://elevenlabs.io/docs/models — Flash v2.5 ~75 ms and "optimized for real-time"; `eleven_v3_conversational` ~280 ms; `eleven_turbo_v2` and `eleven_turbo_v2_5` deprecated in favor of the Flash models (Pipecat defaults to neither)
- https://elevenlabs.io/docs/api-reference/text-to-speech/v-1-text-to-speech-voice-id-multi-stream-input — WebSocket query params; we send everything except `seed`, `sync_alignment` and `inactivity_timeout`, and no `generation_config`
- https://elevenlabs.io/docs/api-reference/text-to-speech/stream-with-timestamps — HTTP body/query; we send everything except `seed`, `next_text`, `previous_request_ids`/`next_request_ids` and `apply_language_text_normalization`; `optimize_streaming_latency` is marked deprecated
- https://elevenlabs.io/docs/api-reference/text-to-speech/convert — field descriptions: `apply_language_text_normalization` is Japanese-only and latency-heavy; `seed` is best-effort determinism
- GET https://api.elevenlabs.io/v1/models — `eleven_v3_conversational`: `requires_alpha_access: false`, `concurrency_group: standard_eleven_v3`, half the character cost of `eleven_v3`; so its WebSocket 403 is the endpoint, not account access
- POST /v1/text-to-speech/{voice}/stream/with-timestamps — 200 for `eleven_v3_conversational` on its own, 400 `unsupported_model` as soon as `previous_text` is included (same for `eleven_v3`)
- https://github.com/pipecat-ai/pipecat/pull/5353, /5398 — merged since the inventory snapshot: `eleven_v3` support now lives in `ElevenLabsDialogueTTSService` (`services/elevenlabs/dialogue/`) with the shared parts in `tts_base.py`, and the model→language gate covers the v3 language set. Research and the branch are against `origin/main`, which has both.
