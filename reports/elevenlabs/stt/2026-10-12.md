# ElevenLabs STT — 2026-10-12

Nothing to act on: `scribe_v2` and `scribe_v2_realtime` remain ElevenLabs'
current models for their endpoints, both transcribe through our classes
unchanged, and no Scribe model shipped since `scribe_v2_medical`. The only
provider movement this month is transcript editing, which needs a response-side
decision before it can be exposed.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`secondary_languages`** (medium, since 2026-09-01) — the realtime endpoint takes a set of additional language codes alongside `language_code`; `ElevenLabsRealtimeSTTSettings` has only `language`, so a bilingual agent cannot narrow Scribe to its two languages. — *Needs a call: whether a second language field belongs on the shared `STTSettings` shape or only on this class, and how it composes with `language`.*
- **Entity detection and redaction** (medium, since 2026-09-01) — batch takes `entity_detection`, `entity_redaction` and `entity_redaction_mode`, realtime takes `entity_detection` and answers with a `committed_transcript_entities` message; none of it is reachable, and that message still falls into the unknown-message branch of `_process_response`. — *Needs a call: detected entities and redacted text need a destination beyond `TranscriptionFrame.result`, and ElevenLabs bills a 30% surcharge for the feature.*
- **Zero-retention mode on the batch service** (medium, since 2026-09-01) — `ElevenLabsRealtimeSTTService` accepts `enable_logging`, but `ElevenLabsSTTService` never sends the query parameter, so the two classes disagree on whether an enterprise account can turn off transcript storage. — *Needs a call: match the realtime class's constructor argument, or make it a Settings field on both.*
- **`file_format=pcm_s16le_16`** (medium, since 2026-09-01) — ElevenLabs documents lower latency for raw 16-bit 16 kHz mono PCM than for an encoded waveform; `run_stt` receives a WAV from `SegmentedSTTService` and uploads it as-is. — *Needs a call: whether the segmented base class should hand down the raw PCM segment, and whether the saving justifies it.*
- **Diarization controls** (low, since 2026-09-01) — `diarize`, `num_speakers`, `diarization_threshold`, `detect_speaker_roles` and `use_speaker_library` are all missing from `ElevenLabsSTTSettings`. — *Needs a call: nothing in a Pipecat pipeline consumes per-speaker output today, so it is unclear who would use them.*
- **`temperature` and `seed`** (low, since 2026-09-01) — documented on the batch endpoint only; determinism is explicitly best-effort. — *Needs a call: whether fields only one of the two classes can honor are worth the asymmetry.*
- **The `warning` message** (low, since 2026-09-01) — it carries a warning string and is logged as an unknown message type. It is not an error, so it does not belong in the error tuple. — *Needs a call: log it at warning level, raise an event, or leave it.*
- **`previous_text` on the first realtime chunk** (low, since 2026-09-01) — the protocol accepts text context, but only on the first `input_audio_chunk`; sending it later is an error. — *Needs a call: first-chunk-only means tracking connection state across reconnects, and it is not obvious what text a pipeline would supply.*
- **The `no_verbatim` "scribe_v2 only" note** (low, since 2026-09-14) — the Settings docstring, and the docs page generated from it, say the field is supported by `scribe_v2` only; the capabilities page lists no-verbatim under Scribe v2, Scribe v2 Medical and Scribe v2 Realtime, while the batch API reference still carries the scribe_v2-only annotation. — *Needs a call: whether the docstring should name supporting models at all, given the list drifts with each Scribe variant and the provider's own pages disagree, or defer to the capabilities page.*
- **Transcript editing** (low, since 2026-10-12) — new on 2026-09-28: a `transcript_edit` instruction (max 2000 characters) on both endpoints, answered with `edited_transcript` carrying `text` and `edited_text`. Neither Settings class exposes it, and the realtime `edited_transcript` message lands in the unknown-message branch. ElevenLabs labels it experimental, bills a 30% premium, and rejects connections that also set `entity_detection`. — *Needs a call: the edited text arrives after its `committed_transcript` and may arrive out of order for consecutive segments, so like entities it has no destination in the current frame flow.*
- **`commit_strategy=turn_prediction`** (low, since 2026-10-12) — the realtime schema now lists a third strategy, and `CommitStrategy` offers only `manual` and `vad`, so the value cannot be passed. The schema restricts it to models that predict turns and no documented Scribe model does. — *Needs a call: nothing until ElevenLabs ships a turn-predicting Scribe; re-check then, including how it would compose with Pipecat's own VAD-driven commit.*

Two other realtime additions are deliberately not gaps: `keepalive_interval_ms`
duplicates the silence keepalive `WebsocketSTTService` already sends every 5 s,
and the single-use `token` parameter exists for browser clients that cannot hold
an API key.
