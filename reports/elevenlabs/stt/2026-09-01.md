# ElevenLabs STT — 2026-09-01

`scribe_v2` and `scribe_v2_realtime` are ElevenLabs' two current GA STT models
and are already our defaults. One branch is ready: three realtime error message
types are matched under names the API does not use, so those sessions fail
silently.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5555 — Fix the ignored realtime Scribe error messages and add a no_verbatim setting

  The AsyncAPI spec for `/v1/speech-to-text/realtime` names the messages
  `quota_exceeded`, `unaccepted_terms` and `invalid_request`;
  `_process_response` matched `quota_exceeded_error` and
  `unaccepted_terms_error` and had no case for `invalid_request`, so all three
  hit `logger.debug(f"Unknown message type: ...")` and nothing reached the
  pipeline — a session that runs out of quota just stops transcribing. The
  second commit adds `no_verbatim`, documented for both Scribe v2 and Scribe v2
  Realtime, as a pass-through Settings field on both classes.

### To consider
- **`secondary_languages`** (medium, since 2026-09-01) — the realtime endpoint takes a set of additional language codes alongside `language_code`; `ElevenLabsRealtimeSTTSettings` has only `language`, so a bilingual agent cannot narrow Scribe to its two languages. — *Needs a call: whether a second language field belongs on the shared `STTSettings` shape or only on this class, and how it composes with `language`.*
- **Entity detection and redaction** (medium, since 2026-09-01) — batch takes `entity_detection`, `entity_redaction` and `entity_redaction_mode`, realtime takes `entity_detection` and answers with a `committed_transcript_entities` message; none of it is reachable, and that message currently falls into the unknown-message branch. — *Needs a call: detected entities and redacted text need a destination beyond `TranscriptionFrame.result`, and ElevenLabs bills a 30% surcharge for the feature.*
- **Zero-retention mode on the batch service** (medium, since 2026-09-01) — `ElevenLabsRealtimeSTTService` accepts `enable_logging`, but `ElevenLabsSTTService` never sends the query parameter, so the two classes disagree on whether an enterprise account can turn off transcript storage. — *Needs a call: match the realtime class's constructor argument, or make it a Settings field on both.*
- **`file_format=pcm_s16le_16`** (medium, since 2026-09-01) — ElevenLabs documents lower latency for raw 16-bit 16 kHz mono PCM than for an encoded waveform; `run_stt` receives a WAV from `SegmentedSTTService` and uploads it as-is. — *Needs a call: whether the segmented base class should hand down the raw PCM segment, and whether the saving justifies it.*
- **Diarization controls** (low, since 2026-09-01) — `diarize`, `num_speakers`, `diarization_threshold`, `detect_speaker_roles` and `use_speaker_library` are all missing from `ElevenLabsSTTSettings`. — *Needs a call: nothing in a Pipecat pipeline consumes per-speaker output today, so it is unclear who would use them.*
- **`temperature` and `seed`** (low, since 2026-09-01) — documented on the batch endpoint only; determinism is explicitly best-effort. — *Needs a call: whether fields only one of the two classes can honor are worth the asymmetry.*
- **The `warning` message** (low, since 2026-09-01) — `ScribeWarning` carries a `warning` string and is logged as an unknown message type. It is not an error, so it does not belong in the error tuple. — *Needs a call: log it at warning level, raise an event, or leave it.*
- **`previous_text` on the first realtime chunk** (low, since 2026-09-01) — the protocol accepts text context, but only on the first `input_audio_chunk`; sending it later is an error. — *Needs a call: first-chunk-only means tracking connection state across reconnects, and it is not obvious what text a pipeline would supply.*

## Verification

| ------------------ | ----------------------------- | -- | ---------------- | ----------------------------------------------------------------------- |
| scribe_v2_realtime | ElevenLabsRealtimeSTTService  | ✅ | TTFB 507 ms      | main; full transcript, 7 interim frames                                  |
| scribe_v2_realtime | ElevenLabsRealtimeSTTService  | ✅ | TTFB 488 ms      | branch, `--setting no_verbatim=true`; connection accepted, transcript ok |
| scribe_v2          | ElevenLabsSTTService          | ✅ | 794 ms round trip | main, ad-hoc; probe.py cannot build the class (required `aiohttp_session`) |
| scribe_v2          | ElevenLabsSTTService          | ✅ | 567 ms round trip | branch, ad-hoc, `no_verbatim=True`; HTTP 200, transcript unchanged on a clip with no fillers |

`probe.py run --service ElevenLabsSTTService` fails at construction with
`missing 1 required keyword-only argument: 'aiohttp_session'`, so the two batch
rows come from an ad-hoc script in the scratch dir that calls `_transcribe_audio`
once per variant with the bundled 16 kHz clip.
