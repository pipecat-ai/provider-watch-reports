# ElevenLabs STT — 2026-11-23

ElevenLabs shipped **Scribe v3** and **Scribe v3 Live** on 2026-11-09 and names
them the successors to `scribe_v2` and `scribe_v2_realtime` — both of our
defaults. Neither bump is proposed: the account key answers 401 everywhere, so
no latency comparison could be made. The branch carries only the two docstring
corrections that need no probe.

Scribe v2 and Scribe v2 Realtime remain available with no retirement date, and
no allowlist in `stt.py` gates the model id, so a user can select `scribe_v3` or
`scribe_v3_live` today through `Settings(model=...)`. What they cannot reach are
the parameters the new models introduced: `numbers_format` and
`secondary_language_codes` on batch, `multilang_mode` and
`commit_strategy=turn_prediction` on realtime.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6964 — Correct the ElevenLabs STT docstrings for no_verbatim model support and the VAD silence threshold range

### To consider
- **Default `scribe_v2` → `scribe_v3`** (medium, since 2026-11-23) — the models overview calls `scribe_v2` "succeeded by `scribe_v3`"; the announcement claims 27% fewer word errors on FLEURS across 102 languages. — *Needs a call: nothing, except a working key — the bump wants a median-TTFB comparison and every probe this run answered 401.*
- **Default `scribe_v2_realtime` → `scribe_v3_live`** (medium, since 2026-11-23) — the realtime endpoint's `model_id` now accepts `scribe_v2_realtime` or `scribe_v3_live`, with the latter the declared successor and a reported 44% lower semantic word error rate. — *Needs a call: same missing key; v3 Live changes commit behavior and keyterm limits, so it deserves a real transcribe probe rather than a connect check.*
- **Entity detection and redaction** (medium, since 2026-09-01) — batch takes `entity_detection`, `entity_redaction` and `entity_redaction_mode`, realtime takes the two redaction parameters, and the realtime `committed_transcript_entities` and `redacted_transcript` messages land in the unknown-message branch of `_process_response`. — *Needs a call: detected entities and redacted text need a destination beyond `TranscriptionFrame.result`, and ElevenLabs bills a surcharge.*
- **Zero-retention mode on the batch service** (medium, since 2026-09-01) — `ElevenLabsRealtimeSTTService` accepts `enable_logging`, and the batch endpoint takes the same query parameter (default true, enterprise only), but `ElevenLabsSTTService` never sends it. — *Needs a call: match the realtime class's constructor argument, or make it a Settings field on both.*
- **`file_format=pcm_s16le_16`** (medium, since 2026-09-01) — ElevenLabs documents lower latency for raw 16-bit 16 kHz mono PCM than for an encoded waveform; `run_stt` receives a WAV from `SegmentedSTTService` and uploads it as-is. — *Needs a call: whether the segmented base class should hand down the raw PCM segment, and whether the saving justifies it.*
- **Scribe v3's `numbers_format` and `secondary_language_codes`** (medium, since 2026-11-23) — `numbers_format` picks `digits` or `words`; `secondary_language_codes` is the batch twin of the `secondary_languages` field the realtime class already has. Two optional form fields with no other logic. — *Needs a call: little, beyond a probe the 401 blocks — plus whether to send them at all when the selected model is not `scribe_v3`.*
- **`commit_strategy=turn_prediction`** (medium, since 2026-10-12) — no longer theoretical: `scribe_v3_live` commits a segment once a partial's `turn_probability` reaches 0.9, and every other model rejects the strategy with `invalid_request` and closes the connection. `CommitStrategy` still offers only `manual` and `vad`. — *Needs a call: how a server-side turn predictor should compose with Pipecat's VAD-driven manual commit, and a guard that only sends it to a turn-predicting model.*
- **Realtime diarization** (medium, since 2026-11-23) — the realtime endpoint takes `diarize` and answers with `diarized_transcript` and `speakers_merged`; neither is handled, and `ElevenLabsRealtimeSTTSettings` has no `diarize`. The batch class gained `diarize` and `speaker_format`, so the two classes now disagree on a feature the provider offers on both. — *Needs a call: whether realtime speaker runs map onto `TranscriptionSpeaker` as the batch ones do, given `speakers_merged` can relabel a speaker after their text was pushed.*
- **Diarization refinements** (low, since 2026-09-01) — `num_speakers`, `diarization_threshold`, `detect_speaker_roles`, `use_speaker_library` and `use_multi_channel` are still missing from `ElevenLabsSTTSettings`. — *Needs a call: whether a voice pipeline wants speaker-count tuning beyond the on/off switch `diarize` now gives it.*
- **`temperature` and `seed`** (low, since 2026-09-01) — documented on the batch endpoint only; determinism is explicitly best-effort. — *Needs a call: whether fields only one of the two classes can honor are worth the asymmetry.*
- **The `warning` message** (low, since 2026-09-01) — it carries a warning string and is logged as an unknown message type. It is not an error, so it does not belong in the error tuple. — *Needs a call: log it at warning level, raise an event, or leave it.*
- **`previous_text` on the first realtime chunk** (low, since 2026-09-01) — the protocol accepts text context on `input_audio_chunk`, but only on the first one. — *Needs a call: first-chunk-only means tracking connection state across reconnects, and it is not obvious what text a pipeline would supply.*
- **Transcript editing** (low, since 2026-10-12) — a `transcript_edit` instruction (max 2000 characters) on both endpoints, answered with an `edited_transcript` object or message. Experimental, 30% premium, rejected alongside `entity_detection`, `entity_redaction` or `use_multi_channel`. — *Needs a call: the edited text arrives after its `committed_transcript` and may arrive out of order, so like entities it has no destination in the current frame flow.*
- **`multilang_mode`** (low, since 2026-11-23) — a realtime boolean (default false) that Scribe v3 Live added for audio switching language mid-stream. — *Needs a call: how it interacts with `language_code` and `secondary_languages`, and whether it does anything on `scribe_v2_realtime`.*

Unchanged non-gaps: `keepalive_interval_ms` duplicates the silence keepalive
`WebsocketSTTService` already sends every 5 s; the single-use `token` parameter
exists for browser clients that cannot hold an API key; `ulaw_8000` as a realtime
`audio_format` has no caller, since frames reaching the service are already PCM;
`scribe_v3_live_medical` is ElevenAgents-only and not on the Speech to Text API.
Scribe v3 Live's 10,000-term keyterm library uses the same `keyterms` parameter
we already send, so it needs no code change.

Note on last run's reading of `no_verbatim`: the batch reference does carry a
model restriction, it is simply wider than our docstring says — `scribe_v2`,
`scribe_v2_medical` and `scribe_v3`, and explicitly "other models are not
supported". The branch states those three rather than dropping the note.
