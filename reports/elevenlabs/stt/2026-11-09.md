# ElevenLabs STT — 2026-11-09

Nothing to act on in the models: `scribe_v2` and `scribe_v2_realtime` are still
ElevenLabs' current choices for their endpoints and no new Scribe shipped. No
probe ran — the account key is rejected with 401 everywhere — so this run is a
documentation reconciliation only.

`secondary_languages` is no longer a gap: it landed in
`ElevenLabsRealtimeSTTSettings` and `_connect_websocket` (commits `5bf7eb2eb`,
`7a39c7df9`). The published docs page has not picked it up yet, which is a docs
repo lag rather than a code gap.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Entity detection and redaction** (medium, since 2026-09-01) — batch takes `entity_detection`, `entity_redaction` and `entity_redaction_mode`; on 2026-11-02 realtime gained the two redaction parameters as well, and now answers with a `redacted_transcript` message alongside `committed_transcript_entities`. None of it is reachable, and both messages fall into the unknown-message branch of `_process_response`. — *Needs a call: detected entities and redacted text need a destination beyond `TranscriptionFrame.result`, and ElevenLabs bills a surcharge for the feature.*
- **Zero-retention mode on the batch service** (medium, since 2026-09-01) — `ElevenLabsRealtimeSTTService` accepts `enable_logging`, and the batch endpoint takes the same query parameter, but `ElevenLabsSTTService` never sends it, so the two classes disagree on whether an enterprise account can turn off transcript storage. — *Needs a call: match the realtime class's constructor argument, or make it a Settings field on both.*
- **`file_format=pcm_s16le_16`** (medium, since 2026-09-01) — ElevenLabs documents lower latency for raw 16-bit 16 kHz mono PCM than for an encoded waveform; `run_stt` receives a WAV from `SegmentedSTTService` and uploads it as-is. — *Needs a call: whether the segmented base class should hand down the raw PCM segment, and whether the saving justifies it.*
- **Diarization controls** (low, since 2026-09-01) — `diarize`, `num_speakers`, `diarization_threshold`, `detect_speaker_roles` and `use_speaker_library` are all missing from `ElevenLabsSTTSettings`. — *Needs a call: nothing in a Pipecat pipeline consumes per-speaker output today, so it is unclear who would use them.*
- **`temperature` and `seed`** (low, since 2026-09-01) — documented on the batch endpoint only; determinism is explicitly best-effort. — *Needs a call: whether fields only one of the two classes can honor are worth the asymmetry.*
- **The `warning` message** (low, since 2026-09-01) — it carries a warning string and is logged as an unknown message type. It is not an error, so it does not belong in the error tuple. — *Needs a call: log it at warning level, raise an event, or leave it.*
- **`previous_text` on the first realtime chunk** (low, since 2026-09-01) — the protocol accepts text context on `input_audio_chunk`, but only on the first one; sending it later is an error. — *Needs a call: first-chunk-only means tracking connection state across reconnects, and it is not obvious what text a pipeline would supply.*
- **The `no_verbatim` "scribe_v2 only" note** (low, since 2026-09-14) — the provider's two pages now agree: the batch API reference has dropped the scribe_v2-only annotation, and the capabilities page lists no-verbatim under Scribe v2, Scribe v2 Medical and Scribe v2 Realtime. The `ElevenLabsSTTSettings` docstring, and the docs page generated from it, are the last places saying otherwise, so a `scribe_v2_medical` user is told a working field is unsupported. — *Needs a call: nothing, really — the claim is now plainly wrong and the fix is one docstring line; it is here rather than on a branch only because no probe could run this time.*
- **Transcript editing** (low, since 2026-10-12) — a `transcript_edit` instruction (max 2000 characters) on both endpoints, answered with an `edited_transcript` object carrying `kind`, `text` and `edited_text`. Neither Settings class exposes it, and the realtime message lands in the unknown-message branch. ElevenLabs labels it experimental, bills a 30% premium, and rejects requests that also set `entity_detection` or `entity_redaction`. — *Needs a call: the edited text arrives after its `committed_transcript` and may arrive out of order for consecutive segments, so like entities it has no destination in the current frame flow.*
- **`commit_strategy=turn_prediction`** (low, since 2026-10-12) — shipped 2026-10-12; `CommitStrategy` offers only `manual` and `vad`, so the value cannot be passed. The realtime endpoint accepts `scribe_v2_realtime` as its only `model_id` and no Scribe model documents turn prediction, so nothing would change if it could. — *Needs a call: nothing until ElevenLabs ships a turn-predicting Scribe; re-check then, including how it would compose with Pipecat's own VAD-driven commit.*
- **Stale `vad_silence_threshold_secs` range** (low, since 2026-11-09) — on 2026-10-26 ElevenLabs stopped raising sub-0.5 s values and lowered the accepted minimum to 0.192 s; the commit-strategies guide now documents 0.192-3.0. Both docstrings in `stt.py` (lines 200 and 493) still say 0.3-3.0. — *Needs a call: nothing, really — a two-line docstring correction, held back only by the missing probe.*
