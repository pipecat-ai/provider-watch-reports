## Notes

- Smallest has no `/models` endpoint (`GET /waves/v1/models` → 404), but the chat completions endpoint names the catalogue in its rejection message: `unknown model: electron-v2. Available models: electron`.
- An "Electron V2" blog post (2026-10-05) calls it "the next evolution of Electron" and defers API usage to a future page; no model ID is served yet. Re-check when one appears.
- Electron honours `max_completion_tokens` even though its supported-parameters page documents only `max_tokens` (probe below), so the `max_completion_tokens` the inherited OpenAI request builder sends is not silently dropped — no pop-the-parameter fix is needed here, unlike `sarvam/llm.py` and `nvidia/omni/llm.py`.
- Electron rejects only `n > 1` and `prompt_logprobs`; Pipecat sends neither. `supports_developer_role = False` matches the documented role set (system, user, assistant, tool).
- Enterprise zero-data-retention uses an `x-expire-content` request header, already reachable through the service's `default_headers` argument.
