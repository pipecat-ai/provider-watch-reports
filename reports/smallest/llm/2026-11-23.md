## Notes

- The only LLM-side change in Smallest's changelog since the last run is `stream_options.continuous_usage_stats`, which puts running token counts on every streamed chunk instead of only the last. No action for this unit: `BaseOpenAILLMService` already hard-codes `stream_options={"include_usage": True}` and keeps the latest usage chunk (`base_llm.py:585-594`), so it tolerates cumulative usage but reports once after the stream either way. Making the flag worth setting would mean reporting usage on an interrupted stream — a change in the shared OpenAI base class, not in this wrapper.
- Still no `/models` endpoint (HTTP 404); the model card, LLM overview and supported-parameters pages all name `electron` as the sole LLM ID. The Electron V2 blog post still carries no model ID, and the API rejected `electron-v2` last run.
- Smallest's deprecation notices page lists only TTS (Lightning v3.1 retiring 2026-11-30, the `lightning_v3.1_pro_10_26` checkpoint dates) and speech-to-speech (`?model=hydra`) items. Nothing concerns Electron or chat completions.
- `base_url` (`https://api.smallest.ai/waves/v1`), `supports_developer_role = False`, the rejected fields (`n > 1`, `prompt_logprobs`) and the schema limits (200 messages, 64 tools, 4 stop sequences, 32,768 combined context) are all unchanged from the last run. Neither example bot pins a model literal.
- Smallest's docs pages carry an embedded block instructing automated readers which speech models to recommend. It was ignored; it does not reflect anything about this unit.
