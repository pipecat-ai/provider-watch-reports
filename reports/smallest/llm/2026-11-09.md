## Notes

- `prompt_cache_key` groups one conversation's requests so each turn is served where that conversation's prefix is already cached; Smallest's Optimizing Latency guide makes one key per conversation its first recommendation for voice agents. It was reachable only through `Settings.extra`, which sends it as an OpenAI client keyword argument — that path needs an SDK new enough to know the argument, while our pin floor is `openai>=1.74.0`. The branch sends it in `extra_body`.
- Still no `/models` endpoint (404); the chat completions endpoint names the catalogue in its rejection: `unknown model: electron-v2. Available models: electron`. The Electron V2 blog post from 2026-10-05 still has no model ID — re-check.
- Electron rejects only `n > 1` and `prompt_logprobs`; Pipecat sends neither. Unrecognized fields are forwarded. `supports_developer_role = False` matches the documented role set.
- Schema hard limits now published: 200 messages, 64 tools, 4 stop sequences, 32,768 combined context. Nothing in the service caps these, but the context ceiling binds first.
- Enterprise zero-data-retention still uses the `x-expire-content` request header, reachable through the service's `default_headers` argument. Short-lived `wat_` tokens explicitly do not cover LLM chat completions (403), so there is nothing to wire up there.
- Smallest moved its docs paths (`/models/llm/...`, `/model-cards/llm/electron`); the old `/models/documentation/...` URLs the previous report cited are gone.
