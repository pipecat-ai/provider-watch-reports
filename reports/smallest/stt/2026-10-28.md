# Smallest STT — 2026-10-28

No new STT model and no retirement; `pulse` stays the right default. Both PRs the last report
tracked are in (`pulse-2` selection via #6018, `itn_normalize` / `no_format_delay` via #6154), so
only `eou_timeout_ms` is still outstanding on open PR #5518. Smallest's docs have since caught up
with the service: the endpointing page now names Pipecat's finalize-on-VAD pattern as correct for
both models, and the response-format page and the pulse-2 card agree that a client `finalize`
yields `from_finalize: true` and never `is_last`. That retires last run's pulse-2 finalization
worry. It also surfaces the opposite problem: the docs say a session ends with `close_stream` and a
final `is_last`, and claim Pipecat sends it — the service closes the socket instead.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5518 — Add eou_timeout_ms and itn_normalize to SmallestSTTService settings (open since 2026-08-31, untouched). Its `itn_normalize` half landed separately in #6154, so only `eou_timeout_ms` is left — and Smallest now says plainly not to send that parameter on `pulse-2`, where it "still takes effect and competes with end-of-turn detection". Worth gating on the model before merging.

### To consider
- **Language map vs. Pulse's streaming set** (high, since 2026-08-31) — 15 mapped codes are pre-recorded-only or undocumented on streaming; `language=pl` fails the WebSocket handshake and the user sees only a reconnection error. The streaming East Asian codes (`zh`, `yue`, `ja`, `ko`), `hi-dev` and the three aggregators are missing from the map; the aggregators are also the only way to reach Pulse's streaming language detection, and the East Asian four additionally require `wss://api.us.smallest.ai` rather than the default `base_url`. — *Needs a call: trimming the map breaks anyone passing those codes today, so choose between removing them, failing with a clear message, or documenting the streaming/batch and region split.*
- **No `close_stream` at session end** (medium, since 2026-10-28) — `_disconnect_websocket` closes the socket directly; Smallest documents `{"type":"close_stream"}` and a final `is_last: true` to wait for, and its endpointing page says the Pipecat service sends it. It doesn't, so the `is_last` branch in `_process_response` is dead code and its docstring is wrong. Both `pulse` probes, this run and the last, returned a final truncated mid-sentence while `pulse-2` returned the full utterance. — *Needs a call: whether `stop()` should send `close_stream` and await the final under a timeout, or whether the docstring should just be corrected.*
- **Finalize control** (medium, since 2026-08-31) — `finalize_on_words` and `max_words` are absent from `Settings`; Pulse documents `finalize_on_words=false` plus a per-turn client `finalize` as the agentic pattern, which the service already does, while pulse-2 tells clients not to send either. — *Needs a call: they change when finals arrive and must not reach pulse-2, so exposing them needs a stance on per-model gating.*
- **VAD events** (low, since 2026-08-31) — `vad_events=true` interleaves `speech_started` / `speech_ended` messages on the same socket for both models; `_process_response` reads only `transcript`, so they would be dropped. — *Needs a call: whether server VAD events should become frames at all, given the pipeline runs its own VAD.*
- **`numerals` is undocumented** (low, since 2026-08-31) — the service always sends `numerals=auto`, but neither the AsyncAPI bindings nor pulse-2's parameter table has such a parameter, and both point at `itn_normalize`, which is now in `Settings`. — *Needs a call: confirm with Smallest whether `numerals` is still honored before dropping the field.*
- **`punctuate` / `capitalize`** (low, since 2026-08-31) — the spec documents both (default `true`) alongside `format`, which is all `Settings` exposes and all the feature pages describe. — *Needs a call: whether the finer-grained pair earns two fields next to `format`.*
- **`external_session_id`** (low, since 2026-10-12) — documented on the pulse-2 card as a client-supplied id for correlating a session in your own logs; not reachable today. — *Needs a call: it is a per-session logging knob rather than a transcription setting, so decide whether it belongs in `Settings` or as a constructor argument.*
- **Keepalive sends billed silence** (low, since 2026-10-28) — the inherited `_send_keepalive` writes 100 ms of PCM silence on an idle socket and records it as STT usage; Smallest documents a free `{"type":"ping"}` / `pong` keep-alive that resets the 20-minute inactivity timer, plus a `timeout` URL parameter raising that window to 3 hours. — *Needs a call: `ping` does not reset the separate model-session idle timer that silence does, so swapping them is a trade, not a strict improvement.*
- **Pulse Pro** (low, since 2026-08-31) — GA, English-only, batch-only; the live endpoint rejects it with 400, so using it needs a class against `POST /waves/v1/stt/`. — *Needs a call: a new service class is outside provider-watch's remit; decide whether a batch Smallest STT service is wanted.*

Dropped since the last report: **pulse-2 selection and emotion/gender settings** (PR #6018 merged 2026-10-16) and **`itn_normalize`** (PR #6154 merged 2026-10-15) are both in the code. **Pulse-tuned finalization reaching pulse-2** no longer holds: the service sends none of the three parameters pulse-2 asks clients to drop, the endpointing page endorses the per-turn client `finalize` on both models, and the `is_last` contradiction is resolved in the service's favour by the new `from_finalize` field — the only live remnant is the review note on PR #5518 above.
