# Smallest STT — 2026-11-09

Nothing to act on: no new STT model, no STT deprecation, no new streaming parameter, and the one
open PR is closed because the code already has what it proposed. `pulse` stays the right default.

`eou_timeout_ms` reached `Settings` directly (commits `dc55360ba`, `9be51fd2a`), so PR #5518 was
closed on 2026-11-07 with "Closing eou_timeout_ms implemented already. Passing on itn_normalize
addition" — and `itn_normalize` had already landed via #6154. Neither half was declined on its
merits, so that gap is simply gone and no decision was recorded. Every other gap carries forward
unchanged; the docs this run match the last run's reading parameter for parameter.

The one thing worth re-reading is the `close_stream` item: a third consecutive probe of `pulse`
cut the final at the same mid-sentence point while `pulse-2` returned the whole utterance, which
is what dropping the tail at teardown would look like.

### To consider
- **Language map vs. Pulse's streaming set** (high, since 2026-08-31) — 15 mapped codes are pre-recorded-only or undocumented on streaming; `language=pl` fails the WebSocket handshake and the user sees only a reconnection error. The streaming East Asian codes (`zh`, `yue`, `ja`, `ko`), `hi-dev` and the three aggregators are missing from the map; the aggregators are also the only way to reach Pulse's streaming language detection, and the East Asian four additionally require `wss://api.us.smallest.ai` rather than the default `base_url`. — *Needs a call: trimming the map breaks anyone passing those codes today, so choose between removing them, failing with a clear message, or documenting the streaming/batch and region split.*
- **No `close_stream` at session end** (medium, since 2026-10-28) — `_disconnect_websocket` closes the socket directly; the response-format page documents `{"type":"close_stream"}` and an `is_last: true` final to wait for ("Do not close the WebSocket connection immediately after sending"), and the endpointing page says the Pipecat service sends it. It doesn't, so the `is_last` branch in `_process_response` is dead code and its docstring is wrong. Three `pulse` probes in a row returned a final truncated at the same point while `pulse-2` returned the full utterance. — *Needs a call: whether `stop()` should send `close_stream` and await the final under a timeout, or whether the docstring should just be corrected.*
- **Finalize control** (medium, since 2026-08-31) — `finalize_on_words` and `max_words` are absent from `Settings`; Pulse documents `finalize_on_words=false` plus a per-turn client `finalize` as the agentic pattern, which the service already does, while pulse-2 tells clients not to send either. — *Needs a call: they change when finals arrive and must not reach pulse-2, so exposing them needs a stance on per-model gating.*
- **VAD events** (low, since 2026-08-31) — `vad_events=true` interleaves `speech_started` / `speech_ended` messages on the same socket for both models; `_process_response` reads only `transcript`, so they would be dropped. — *Needs a call: whether server VAD events should become frames at all, given the pipeline runs its own VAD.*
- **`numerals` is undocumented** (low, since 2026-08-31) — the service always sends `numerals=auto`, but neither the AsyncAPI bindings nor pulse-2's parameter table has such a parameter, and both point at `itn_normalize`, which is in `Settings`. — *Needs a call: confirm with Smallest whether `numerals` is still honored before dropping the field.*
- **`punctuate` / `capitalize`** (low, since 2026-08-31) — the spec documents both (default `true`) alongside `format`, which is all `Settings` exposes and all the feature pages describe. — *Needs a call: whether the finer-grained pair earns two fields next to `format`, which overlaps them.*
- **`external_session_id`** (low, since 2026-10-12) — documented on the pulse-2 card as a client-supplied correlation id; not reachable today. — *Needs a call: it is a per-session logging knob rather than a transcription setting, and changing a setting reconnects the socket, so decide whether it belongs in `Settings` or as a constructor argument.*
- **Keepalive sends billed silence** (low, since 2026-10-28) — the inherited `_send_keepalive` writes 100 ms of PCM silence on an idle socket and records it as STT usage; Smallest documents a free `{"type":"ping"}` / `pong` keep-alive that resets the 20-minute inactivity timer, plus a `timeout` URL parameter raising that window to 3 hours. — *Needs a call: `ping` does not reset the separate model-session idle timer that silence does, so swapping them is a trade, not a strict improvement.*
- **Pulse Pro** (low, since 2026-08-31) — English-only and batch-only; the live endpoint rejects it with 400, so using it needs a class against `POST /waves/v1/stt/`. — *Needs a call: a new service class is outside provider-watch's remit; decide whether a batch Smallest STT service is wanted.*

Dropped since the last report: **`eou_timeout_ms` is not reachable from Settings** — the field is
in `SmallestSTTSettings` and `_connect_websocket` sends it only when set, so the server's
endpointing-dependent default still applies otherwise.
