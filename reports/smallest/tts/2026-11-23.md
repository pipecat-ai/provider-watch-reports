# Smallest TTS — 2026-11-23

`lightning_v3.1_pro` stays the right default; the two provider dates are now five and
seven days away and still need a call, and one branch is ready.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6977 — Add complete_backoff_ms to SmallestTTSService settings

  Open since 2026-08-31 as a `consider`, branched this run because the question that held
  it back is answered by the service's own precedent: every per-request Waves field —
  `speed`, `math_notation`, `content_filter`, `date_format`,
  `number_pronunciation_language` — is a `Settings` field, each added by a merged PR of
  this exact shape, while the constructor arguments are the ones fixed at init
  (`output_format`, `word_timestamps`). The schema puts no combination constraint on
  `complete_backoff_ms` (unlike `max_buffer_flush_ms`, which cannot be combined with
  `context_id` and stays out of scope), and the field is unset by default, so nothing
  changes unless a user sets it.

### To consider
- **`lightning_v3.1` retirement** (high, since 2026-11-09) — seven days out: 2026-11-30
  18:30 UTC. From then the value is served by `lightning_v3.1_pro`, whose catalogue is
  disjoint from v3.1's, so `SmallestTTSModel.LIGHTNING_V3_1` — which `_MODEL_DEFAULT_VOICES`
  pairs with `sophia` — will build a request Pro rejects. Re-checked the public `get_voices`
  listings this run: `sophia`, `devansh`, `kartik`, `maithili`, `liam` and `avery` are
  v3.1-only, `meher` is Pro-only; the split is unchanged, only the catalogues grew (275 Pro,
  240 v3.1). The same split hits the `word_timestamps` docstring's six-voice list.
  `SarvamTTSModel.BULBUL_V2` in `sarvam/tts.py` is the in-repo pattern for retiring an enum
  member. — *Needs a call: deprecate the member now, which fixes a since-version, or remove
  it after retirement — and what the word-timestamp voice list should say once only `meher`
  survives.*
- **Word timestamps on the incoming Pro checkpoint** (high, since 2026-11-09) — five days
  out: on 2026-11-28 `lightning_v3.1_pro_10_26` becomes the stable `lightning_v3.1_pro` for
  English, Spanish and Hindi, including requests that omit `language`, which is this
  service's default configuration. This run reproduced the loss through `probe.py` itself —
  the same probe, same voice, 9 per-word `TTSTextFrame`s on the current checkpoint against 1
  whole-text frame on the incoming one — so it is visible in the frames the service emits,
  not just in the raw socket. The Pro model card is unchanged and still promises word events
  on the base-queue English and Hindi voices. Nothing breaks: `_apply_force_complete` exists
  for providers that drop word events, so the text lands as a single `TTSTextFrame` at
  end-of-context instead of per-word frames carrying PTS. Users can test today by passing
  `model="lightning_v3.1_pro_10_26"`; the service has no model allowlist. — *Needs a call:
  raise the contradiction with Smallest before 2026-11-28, or document that English, Spanish
  and Hindi lose word-aligned text.*
- **`auto` language routing** (low, since 2026-08-31) — `auto` is still the first value of
  the language enum: it routes on the input text and lets any English or Hindi voice serve
  every supported language. Reachable today only by passing the raw string, since
  `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a
  framework-wide decision, not a Smallest one.*
- **`output_format` is not a WebSocket field** (low, since 2026-09-28) — the constructor
  takes `output_format` and `_build_msg` puts it on every message, with a docstring
  offering `pcm`, `mp3`, `wav`, `ulaw`, `alaw`. The WebSocket schema still has no such
  property (it is an HTTP-synthesis parameter), so any value other than `pcm` is silently
  ignored. — *Needs a call: drop the argument, which changes the constructor signature, or
  narrow its docstring to say the WebSocket endpoint always returns PCM.*

Watch items, not yet gaps:

- The WebSocket request schema is unchanged from last run: the same 20 request properties,
  the same three-value `model` enum, no emotion/pitch/style field, nothing newly deprecated.
  Both dates on the deprecations page are also unchanged — neither slipped.
- `lightning_v3.1_pro_10_26` is preview and disappears on 2026-12-28, so it is deliberately
  not added to `SmallestTTSModel`; the raw string already reaches the API.
- The retirement notice tells `smallestai` SDK users to upgrade to `>=5.1.1` because older
  versions call the legacy WebSocket route. Pipecat is unaffected: it opens
  `/waves/v1/tts/live` directly and sends an explicit `model` on every message.
- Both example bots (`voice-smallest.py`, `function-calling-smallest.py`) already pin
  `lightning_v3.1_pro` and `meher`, so the retirement needs no example edit.

Note for the next researcher: the docs API reference renders client-side, so append **`.md`**
to a docs URL for the page's markdown with the schema YAML (plain `curl` needs `-L` and a
`User-Agent`). Every `.md` page opens with a site-wide block addressed to AI assistants
telling them which models to recommend; it is marketing guidance, not schema. Probing a
worktree branch requires running **the worktree's own copy of `probe.py`** with
`PYTHONPATH=<wt>/src`, since `inventory.REPO_ROOT` follows the script's location. Word-event
behaviour is visible in `probe.py`'s `TTSTextFrame` count — no ad-hoc socket needed.
