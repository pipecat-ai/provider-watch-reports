# Smallest TTS — 2026-09-01

Nothing moved on Smallest's side; `lightning_v3.1_pro` is still the flagship default and the
language-map fix is sitting in open PR #5519. No new branch this run.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5519 — Match SmallestTTSService's language map to the Waves API (open since last run)

### To consider
- **Streaming continuation** (medium, since 2026-08-31) — the WebSocket API's `context_id` /
  `continue` / `context_close` group fragments into one utterance, priming each generation with
  audio from the previous one. The service sends each `run_tts()` as an independent request
  instead and reconstructs word-timestamp offsets by hand in
  `_advance_word_timestamp_request`. — *Needs a call: adopting contexts reshapes
  `run_tts`/`flush_audio` and the turn lifecycle; it is not a Settings pass-through.*
- **Buffering and turn-end timing knobs** (medium, since 2026-08-31) — `max_buffer_flush_ms`
  (0–1000, default 0), `max_buffer_delay_ms` (0–5000, default 3000) and `complete_backoff_ms`
  (0–10000, default 4000) are documented request fields and none is reachable.
  `complete_backoff_ms` is what holds the `complete` status back after the last audio chunk.
  — *Needs a call: `max_buffer_delay_ms` and `context_close` only mean anything inside a
  `context_id` continuation, so these follow the contexts decision above.*
- **Pronunciation and math controls** (low, since 2026-08-31) — `number_pronunciation_language`
  (read numerals in a language independent of the voice) and `math_notation` (read
  digit-flanked operators as words) are documented top-level fields; both would be straight
  pass-throughs in `_build_msg`. — *Needs a call: neither appears on the Lightning model cards,
  only in the WebSocket API reference, so confirm they are live on `lightning_v3.1_pro` first.*
- **`auto` language routing** (low, since 2026-08-31) — the API accepts `language: "auto"` for
  per-request detection and mid-sentence switching. Reachable today only by passing the raw
  string, since `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a
  framework-wide decision, not a Smallest one.*

Watch item, not yet a gap: Smallest's Lightning V3 blog post describes a **Lightning V3.2** with
instruction following (emotional register, pitch, volume, whisper). It has no model ID, no entry
in the models list and no request field in the WebSocket schema, so there is nothing to wire up
yet — re-check the models page next run.

No default-bump comparison: `lightning_v3.1_pro` is the latest release and `lightning_v3.1` is
the standard tier below it, not a successor. Language-code behavior was not re-probed — the
API reference still publishes exactly the 31-code enum plus `auto` that PR #5519 follows.

Carried over from the previous run and still true: `probe.py run` never returns for this
service. Synthesis and metrics succeed (the TTFB above is the service's own log under
`--verbose`), but the pipeline then hangs waiting for `EndFrame` because
`SmallestTTSService` sets `pause_frame_processing=True` and the probe pipeline has no output
transport to emit the `BotStoppedSpeakingFrame` that lifts the pause. Run these probes with
`--verbose` under an outer `timeout` and read the latency from the log.
