# Smallest TTS — 2026-08-31

`lightning_v3.1_pro` is still Smallest's flagship, so the default is right; the language map
is not, and a branch fixes it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5519 — Match SmallestTTSService's language map to the Waves API

### To consider
- **Streaming continuation** (medium, since 2026-08-31) — the WebSocket API's `context_id` /
  `continue` / `context_close` group fragments into one utterance. The service sends each
  `run_tts()` as an independent request instead and reconstructs word-timestamp offsets by
  hand in `_advance_word_timestamp_request`, because Smallest resets timestamps per request.
  — *Needs a call: adopting contexts reshapes `run_tts`/`flush_audio` and the turn lifecycle;
  it is not a Settings pass-through.*
- **Buffering and turn-end timing knobs** (medium, since 2026-08-31) — `max_buffer_flush_ms`,
  `max_buffer_delay_ms` and `complete_backoff_ms` are documented request fields and none is
  reachable. `complete_backoff_ms` defaults to 4000 ms and is what holds the `complete`
  status back after the last audio chunk, which the probe shows arriving ~3.5 s after
  synthesis starts. — *Needs a call: `max_buffer_delay_ms` and `context_close` only mean
  anything inside a `context_id` continuation, so these follow the contexts decision above.*
- **Pronunciation and math controls** (low, since 2026-08-31) — `number_pronunciation_language`
  (read numerals in a language independent of the voice) and `math_notation` (read operators
  as words) are documented top-level fields; both would be straight pass-throughs in
  `_build_msg`. — *Needs a call: neither appears on the Lightning model cards, only in the
  WebSocket API reference, so confirm they are live on `lightning_v3.1_pro` first.*
- **`auto` language routing** (low, since 2026-08-31) — the API accepts `language: "auto"` for
  per-request detection and mid-sentence switching. Reachable today only by passing the raw
  string, since `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a
  framework-wide decision, not a Smallest one.*

| lightning_v3.1_pro | SmallestTTSService | ❌ | TTFB 74 ms  | `language=he` rejected: "Language 'he' is not supported on the lightning_v3.1_pro model", and the error enumerates all 31 accepted codes plus `auto` |

No default-bump comparison was run: `lightning_v3.1_pro` is already the flagship and
`lightning_v3.1` is the smaller sibling, not a successor.

Note for the next run: `probe.py run` never returns for this service. Synthesis and the
metrics succeed (the numbers above come from the service's own TTFB logs under `--verbose`),
but the pipeline then hangs waiting for `EndFrame`. This is the harness, not the service —
`SmallestTTSService` sets `pause_frame_processing=True`, and the probe pipeline has no output
transport to emit the `BotStoppedSpeakingFrame` that lifts the pause. Roughly twenty TTS
services set that flag, so run these probes with `--verbose` under an outer `timeout` and read
the latency from the log.
