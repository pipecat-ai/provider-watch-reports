# Smallest TTS — 2026-10-28

`lightning_v3.1_pro` remains the flagship default; two new text-normalization /
filtering options appeared on the Waves WebSocket schema and a branch wires both up.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6431 — Wire SmallestTTSService up to the Waves date_format field and the redact content-filter action
- https://github.com/pipecat-ai/pipecat/pull/5936 — Add number_pronunciation_language to SmallestTTSService settings (open since 2026-09-28)

### To consider
- **`complete_backoff_ms`** (medium, since 2026-08-31) — a documented request field
  (0–10000 ms, default 4000) that is not reachable. It is what holds the `complete` status
  back after the last audio chunk, and `_receive_messages` calls `stop_all_metrics()` on that
  status. Its sibling `max_buffer_delay_ms` is already a constructor argument. The schema now
  states that `max_buffer_flush_ms` cannot be combined with `context_id`, which this service
  sends on every message, so that field — listed with this one in previous reports — is out of
  scope here. — *Needs a call: whether this follows `max_buffer_delay_ms` as a constructor
  argument or becomes a `Settings` field, and whether shortening it is safe given what it
  gates.*
- **`auto` language routing** (low, since 2026-08-31) — `auto` is still the first value of the
  language enum: it routes on the input text and lets any English or Hindi voice serve every
  supported language. Reachable today only by passing the raw string, since `Language` has no
  `AUTO` member. — *Needs a call: adding `Language.AUTO` is a framework-wide decision, not a
  Smallest one.*
- **`output_format` is not a WebSocket field** (low, since 2026-09-28) — the constructor takes
  `output_format` and `_build_msg` puts it on every message, with a docstring offering `pcm`,
  `mp3`, `wav`, `ulaw`, `alaw`. The WebSocket schema still has no such property (it is an
  HTTP-synthesis parameter), so any value other than `pcm` is silently ignored. — *Needs a call:
  drop the argument, which changes the constructor signature, or narrow its docstring to say the
  WebSocket endpoint always returns PCM.*

`date_format` (`EU` | `US`, omit for the API's `US` default) decides how an all-numeric date is
read out, independent of the synthesis voice — `05/03/2024` as "fifth March" or "May third". It
has no prose documentation page; the request schema is the only source. `content_filter.action`
gained `redact`, which drops the matched term and speaks the rest; text that is nothing but
matched terms still fails like `reject`, with `redacted_to_empty: true` on the error frame, which
the service's existing `status == "error"` branch already handles.

Closed since last run: `content_filter` reached `Settings` in
[#6142](https://github.com/pipecat-ai/pipecat/pull/6142), merged 2026-10-13.

Watch items, not yet gaps:

- Still only two TTS models, and the schema calls their concurrency and latency profiles
  identical. No **Lightning v3.2** model ID anywhere, and no emotion/pitch/style field in the
  WebSocket schema.
- The changelog's TTS-adjacent entries are unchanged from last run; nothing retires a Lightning
  TTS model. `lightning_v2` and `lightning-large` remain deprecated with no retirement date and
  appear in neither the service nor its examples.

No default-bump comparison: `lightning_v3.1_pro` is the top tier and `lightning_v3.1` is the
standard tier below it, not a successor.

The redaction path itself was not probed — it needs profanity in the request text, and the
rejected-when-empty case is documented and already covered by the service's `status == "error"`
branch.

Note for the next researcher: `probe.py run` now completes for this service (exit 0 with JSON).
Earlier reports' warning that it hangs waiting for `EndFrame` no longer holds. Probing a worktree
branch still requires running **the worktree's own copy of `probe.py`** with `PYTHONPATH=<wt>/src`,
since `inventory.REPO_ROOT` follows the script's location and would otherwise validate
`--setting` names against main's source. The API reference renders client-side, so append **`.md`**
to a docs URL to get the page's markdown with the schema YAML; every `.md` page carries a
site-wide preamble addressed to AI assistants that is documentation guidance, not schema.
