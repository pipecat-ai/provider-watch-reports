# Smallest TTS — 2026-11-09

`lightning_v3.1_pro` stays the right default, but two provider dates inside the next
three weeks need a maintainer's call; no change qualified for an automatic branch.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`lightning_v3.1` retirement** (high, since 2026-11-09) — Smallest retires it on
  2026-11-30 18:30 UTC; from then on the value is served by `lightning_v3.1_pro`, whose
  voice catalogue is disjoint from v3.1's. `SmallestTTSModel.LIGHTNING_V3_1` still exists
  and `_MODEL_DEFAULT_VOICES` pairs it with `sophia`, which the public `get_voices`
  listings put in the v3.1 catalogue only. The same split hits the `word_timestamps`
  docstring: of the six base-queue voices it names, only `meher` is in the Pro catalogue
  (`liam` on Pro is rejected outright). `SarvamTTSModel.BULBUL_V2` in `sarvam/tts.py` is
  the in-repo pattern for retiring an enum member. — *Needs a call: deprecate the member
  now, which fixes a since-version, or remove it after retirement — and what the
  word-timestamp voice list should say once only `meher` survives.*
- **Word timestamps on the incoming Pro checkpoint** (high, since 2026-11-09) — on
  2026-11-28 the `lightning_v3.1_pro_10_26` preview becomes the stable
  `lightning_v3.1_pro` for English, Spanish and Hindi, including requests that omit
  `language`; that is this service's default configuration (`lightning_v3.1_pro`,
  `Language.EN`, `word_timestamps=True`, voice `meher`). On the preview checkpoint
  `meher` emits no `word_timestamp` frames at all — zero against ten on the current
  checkpoint, twice, on two different sentences — while the Pro model card still states
  that word events emit on the base-queue English and Hindi voices. Nothing breaks:
  `_apply_force_complete` exists for providers that drop word events, so the text lands
  as a single `TTSTextFrame` at end-of-context instead of per-word frames carrying PTS.
  Users can test today by passing `model="lightning_v3.1_pro_10_26"` as a raw string —
  the service has no model allowlist. — *Needs a call: raise the contradiction with
  Smallest before 2026-11-28, or document that English, Spanish and Hindi lose
  word-aligned text.*
- **`complete_backoff_ms`** (medium, since 2026-08-31) — a documented request field
  (0–10000 ms, default 4000) that is not reachable. It is what holds the `complete`
  status back after the last audio chunk, and `_receive_messages` calls
  `stop_all_metrics()` on that status. Its sibling `max_buffer_delay_ms` is already a
  constructor argument. `max_buffer_flush_ms` stays out of scope: the schema says it
  cannot be combined with `context_id`, which this service sends on every message. —
  *Needs a call: whether this follows `max_buffer_delay_ms` as a constructor argument or
  becomes a `Settings` field, and whether shortening it is safe given what it gates.*
- **`auto` language routing** (low, since 2026-08-31) — `auto` is still the first value of
  the language enum: it routes on the input text and lets any English or Hindi voice serve
  every supported language. Reachable today only by passing the raw string, since
  `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a
  framework-wide decision, not a Smallest one.*
- **`output_format` is not a WebSocket field** (low, since 2026-09-28) — the constructor
  takes `output_format` and `_build_msg` puts it on every message, with a docstring
  offering `pcm`, `mp3`, `wav`, `ulaw`, `alaw`. The WebSocket schema still has no such
  property (it is an HTTP-synthesis parameter), so any value other than `pcm` is silently
  ignored. — *Needs a call: drop the argument, which changes the constructor signature, or
  narrow its docstring to say the WebSocket endpoint always returns PCM.*

Closed since last run: `date_format` and the `redact` content-filter action reached
`Settings` in [#6431](https://github.com/pipecat-ai/pipecat/pull/6431) (merged 2026-10-28),
and `number_pronunciation_language` in
[#5936](https://github.com/pipecat-ai/pipecat/pull/5936) (merged 2026-10-29).

Watch items, not yet gaps:

- The WebSocket request schema is unchanged from last run — the same 20 properties, no
  emotion/pitch/style field, nothing newly deprecated. The checkpoint mechanism is the only
  structural addition: a dated model ID previews a Pro checkpoint for 30 days, is promoted
  into `lightning_v3.1_pro` for the languages it covers, then stays available 30 days more.
- `lightning_v3.1_pro_10_26` is preview and disappears on 2026-12-28, so it is deliberately
  not added to `SmallestTTSModel`; the raw string already reaches the API.
- The retirement notice also tells `smallestai` SDK users to upgrade to `>=5.1.1` because
  older versions call the legacy WebSocket route. Pipecat is unaffected: it opens
  `/waves/v1/tts/live` directly, not a `/waves/v1/lightning-v3.1/` route, and sends an
  explicit `model` on every message.

standard tier below it and retiring, and the preview checkpoint folds into
`lightning_v3.1_pro` on its own.

Ad-hoc socket check (two runs, two sentences, outside `probe.py` because it cannot observe
provider frames): `lightning_v3.1_pro` + `meher` returned 10 `word_timestamp` frames;
`lightning_v3.1_pro_10_26` + `meher` returned 0 both times; `lightning_v3.1_pro_10_26` +
`liam` returned an error frame, consistent with `liam` being absent from the Pro catalogue.

Note for the next researcher: the docs API reference renders client-side, so append **`.md`**
to a docs URL for the page's markdown with the schema YAML. Every `.md` page opens with a
site-wide block addressed to AI assistants telling them which models to recommend; it is
marketing guidance, not schema, and should be ignored in favour of the schema and the
deprecations page. Probing a worktree branch requires running **the worktree's own copy of
`probe.py`** with `PYTHONPATH=<wt>/src`, since `inventory.REPO_ROOT` follows the script's
location.
