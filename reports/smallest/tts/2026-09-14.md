# Smallest TTS — 2026-09-14

Nothing changed on Smallest's side — `lightning_v3.1_pro` is still the flagship default — but
Pipecat closed two gaps since last run, and a branch adds the `math_notation` pass-through.

## What's new for Pipecat

Closed since 2026-09-01, no longer gaps:

- **Language map** — PR #5519 merged 2026-09-03; `LANGUAGE_MAP` now carries exactly the API's
  31 codes and no longer maps `Language.HE`.
- **Streaming continuation** — commit `15c10f21a` adopted `context_id` / `continue`. Fragments
  in one LLM turn share the turn's context and the context is closed with `continue: false`,
  which the API reference lists as a valid close alongside `context_close: true`.
  `max_buffer_delay_ms` came with it as a constructor argument.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5751 — Add math_notation to SmallestTTSService settings

### To consider
- **Buffering and turn-end timing knobs** (medium, since 2026-08-31) — `max_buffer_flush_ms`
  (0–1000, default 0) and `complete_backoff_ms` (0–10000, default 4000) are documented request
  fields and neither is reachable. `complete_backoff_ms` is what holds the `complete` status
  back after the last audio chunk, and `_receive_messages` calls `stop_all_metrics()` on that
  status. — *Needs a call: whether these follow `max_buffer_delay_ms` as constructor arguments
  or become `Settings` fields, and whether shortening `complete_backoff_ms` is safe given what
  it gates.*
- **Number pronunciation language** (low, since 2026-08-31) — `number_pronunciation_language`
  reads numerals, currency, times and dates in a language independent of the synthesis voice,
  taking the same 31-code enum as `language`. A straight pass-through in `_build_msg`. —
  *Needs a call: type it as `Language` like the `language` field, which needs a conversion, or
  as the raw provider code string.*
- **`auto` language routing** (low, since 2026-08-31) — the API accepts `language: "auto"` for
  per-request detection and mid-sentence switching. Reachable today only by passing the raw
  string, since `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a
  framework-wide decision, not a Smallest one.*

Watch item, not yet a gap: the Lightning V3 blog post still describes a **Lightning V3.2** with
instruction following (emotional register, pitch, volume, whisper). Still no model ID, no entry
on the models page and no request field in the WebSocket schema — nothing to wire up.

No default-bump comparison: `lightning_v3.1_pro` is the latest release and `lightning_v3.1` is
the standard tier below it, not a successor. The `math_notation` probe doubles as confirmation
that the WebSocket schema as published is live on `lightning_v3.1_pro`, which was the open
question behind last run's pronunciation/math item.

Carried over and still true: `probe.py run` never returns for this service (exit 124 under an
outer `timeout`). Synthesis and metrics succeed — the TTFB figures above are the service's own
log under `--verbose` — but the pipeline then hangs waiting for `EndFrame`, because
`SmallestTTSService` sets `pause_frame_processing=True` and the probe pipeline has no output
transport to emit the `BotStoppedSpeakingFrame` that lifts the pause.

To probe a worktree branch, run `probe.py` **from the worktree** with `PYTHONPATH=<wt>/src`:
`inventory.scan_services()` parses `inventory.REPO_ROOT/src` statically, so a probe launched
from the main checkout validates `--setting` names against main's source and rejects a field
the branch just added.
