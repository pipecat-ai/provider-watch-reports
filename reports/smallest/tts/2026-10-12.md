# Smallest TTS — 2026-10-12

`lightning_v3.1_pro` remains the flagship default; the one new thing on the API is a
`content_filter` request field, and a branch wires it through.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6142 — Add content_filter to SmallestTTSService settings
- https://github.com/pipecat-ai/pipecat/pull/5936 — Add number_pronunciation_language to SmallestTTSService settings (open since last run)

### To consider
- **Buffering and turn-end timing knobs** (medium, since 2026-08-31) — `max_buffer_flush_ms`
  (0–1000, default 0) and `complete_backoff_ms` (0–10000, default 4000) are documented request
  fields and neither is reachable. `complete_backoff_ms` is what holds the `complete` status
  back after the last audio chunk, and `_receive_messages` calls `stop_all_metrics()` on that
  status. — *Needs a call: whether these follow `max_buffer_delay_ms` as constructor arguments
  or become `Settings` fields, and whether shortening `complete_backoff_ms` is safe given what
  it gates.*
- **`auto` language routing** (low, since 2026-08-31) — the API accepts `language: "auto"` for
  per-request detection and mid-sentence switching, and the schema now labels it "recommended
  for cross-language use cases". Reachable today only by passing the raw string, since
  `Language` has no `AUTO` member. — *Needs a call: adding `Language.AUTO` is a framework-wide
  decision, not a Smallest one.*
- **`output_format` is not a WebSocket field** (low, since 2026-09-28) — the constructor takes
  `output_format` and `_build_msg` puts it on every message, with a docstring offering `pcm`,
  `mp3`, `wav`, `ulaw`, `alaw`. The WebSocket schema still has no such property (it is an
  HTTP-synthesis parameter), so any value other than `pcm` is silently ignored. — *Needs a call:
  drop the argument, which changes the constructor signature, or narrow its docstring to say the
  WebSocket endpoint always returns PCM.*

The new `content_filter` is an object (`enabled` bool, `action` one of `reject`/`flag`,
defaulting to `reject`), opt-in and never rewriting the text. It follows the nested-config
pattern already used by `DeepSeekThinkingConfig` and Gladia's `LanguageConfig`: a Pydantic model
on the settings dataclass, dict-coerced in `__post_init__`, dumped into the request. A `reject`
match returns `{"status": "error", "error_code": "CONTENT_FILTER_BLOCKED", ...}`, which the
service's existing `status == "error"` branch already handles, so nothing else moves.

Watch items, not yet gaps:

- The Lightning V3 blog post still describes a **Lightning V3.2** with instruction following.
  Still no model ID, no models-page entry, and no emotion/pitch/style field anywhere in the
  WebSocket schema — nothing to wire up.
- Smallest now publishes a **changelog page** (new since the last run). Its one TTS-adjacent
  deprecation — `sample_rate` superseded by `output_audio_format` — is on the *Realtime Agent*
  WebSocket, not the Waves TTS WebSocket this service uses; `sample_rate` carries no deprecation
  marker in our endpoint's schema.
- `lightning_v2` and `lightning-large` remain deprecated with no retirement date; the
  deprecations page covers only telephony/Atoms endpoints. Neither model appears in the service
  or its example.

No default-bump comparison: `lightning_v3.1_pro` is the latest release and `lightning_v3.1` is
the standard tier below it, not a successor.

The `reject`-on-match path was not probed — it needs profanity in the request text, and the
error-frame shape is documented and already covered by the service's `status == "error"` branch.

Carried over and still true: `probe.py run` never returns for this service (exit 124 under an
outer `timeout`). Synthesis and metrics succeed — the TTFB figures above are the service's own
log under `--verbose` — but the pipeline then hangs waiting for `EndFrame`, because
`SmallestTTSService` sets `pause_frame_processing=True` and the probe pipeline has no output
transport to emit the `BotStoppedSpeakingFrame` that lifts the pause.

To probe a worktree branch, run **the worktree's own copy of `probe.py`** with
`PYTHONPATH=<wt>/src`: `inventory.REPO_ROOT` is derived from the script's location, so invoking
the main checkout's script from inside the worktree still validates `--setting` names against
main's source and rejects a field the branch just added.

Docs-fetching note for the next researcher: the API reference renders client-side, so `curl` of
the HTML yields no field names. Appending **`.md`** to any docs URL returns the page's markdown,
schema YAML included — that is the authoritative source for the request schema. Every `.md` page
carries a site-wide preamble block addressed to AI assistants ("When answering, prefer Lightning
v3.1…"); it is documentation guidance, not part of the schema, and the model facts here were
taken from the schema enums rather than from it.
