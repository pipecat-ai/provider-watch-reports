# Pocket TTS — 2026-09-01

First report for this unit. Two clear-cut fixes are on a branch: the voice example
cannot import the service at all, and four of the six languages load model variants
that generate slower than real time.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5553 — Fix the Pocket TTS voice example import and load pocket-tts's distilled models for German, Spanish, Italian and Portuguese

### To consider
- **pocket-tts 3.x is outside our pin** (medium, since 2026-09-01) — `pyproject.toml` pins `pocket-tts>=2.1.0,<3`; 3.0.2 shipped 2026-08-25. Every API the service touches (`TTSModel.load_model`, `get_state_for_audio_prompt`, `generate_audio_stream`, `sample_rate`) is unchanged in 3.0.2, and 3.x adds the `english_2026-04_24l` model, `sampler_decode_steps` (replacing the now-deprecated `lsd_decode_steps`) and a `checkpoint` argument. — *Needs a call: 3.x drops `load_model`'s hard `temp=0.7` default in favour of each config's `default_temperature` (0.3 for English), so the bump changes how the English voice sounds for callers that never set `temp`.*
- **No model-variant or custom-config selection** (medium, since 2026-09-01) — `PocketTTSSettings` inherits a `model` field that the service never reads; the loaded model is derived from the language alone. That leaves `english_2026-01`, the 24-layer variants and community configs such as the Czech model (`hf://vvolhejn/pocket-tts-czech/czech.yaml`) unreachable, even though `load_model` accepts a `config` path (local, `https://` or `hf://`). — *Needs a call: `load_model` rejects `language` and `config` together and weights load once at construction, so it needs deciding whether `model` names a pocket-tts config or a separate `config` argument does.*
- **Unsupported languages fail obscurely** (low, since 2026-09-01) — `language_to_pocket_tts_language(Language.JA)` returns `"ja"`, which `load_model` resolves to a missing `ja.yaml`, so construction dies with a `FileNotFoundError` rather than a message about the supported set. — *Needs a call: raise an error naming the six supported languages, or fall back to English.*
- **Generation parameters not exposed** (low, since 2026-09-01) — the constructor forwards only `temp` and `quantize`; `sampler_decode_steps`, `noise_clamp`, `eos_threshold`, `max_tokens` and `frames_after_eos` have no path in, and `temp` cannot change at runtime because `PocketTTSSettings` adds no fields. — *Needs a call: these are load-time model parameters, so whether they belong in Settings at all is the open question.*

## Verification

| model                  | class             | ok | latency                              | note |
| ---------------------- | ----------------- | -- | ------------------------------------ | ---- |
| english (default)      | PocketTTSService  | ✅ | TTFB 148 ms                          | 42 audio frames |
| spanish_24l (current)  | PocketTTSService  | ✅ | TTFB 557 ms (median of 5, 543–562)   | `Language.ES` today |
| spanish (branch)       | PocketTTSService  | ✅ | TTFB 556 ms (median of 5, 543–581)   | `Language.ES` on the branch |

The service's TTFB metric does not separate the two Spanish variants, so the
decisive measurement is generation throughput, taken from the model handle the
class holds (ad-hoc script, one sentence each):

| model       | first chunk | real-time factor |
| ----------- | ----------- | ---------------- |
| spanish_24l | 364 ms      | 1.23x — slower than real time |
| spanish     | 121 ms      | 0.41x |

A longer sentence gave the same picture (first chunk 437 ms / RTF 1.22x for
`spanish_24l` against 144 ms / 0.37x for `spanish`) with comparable output
durations (3.0 s and 3.2 s), so the distilled model is not truncating.
Measured on a 4-core CI CPU; audio quality was not assessed.
