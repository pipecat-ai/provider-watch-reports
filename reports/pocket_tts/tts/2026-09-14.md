# Pocket TTS — 2026-09-14

Service is current and working; last run's branch merged as #5553, and the only
movement upstream is pocket-tts 3.1.0, which the pin still excludes.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **pocket-tts 3.x is outside our pin** (medium, since 2026-09-01) — `pyproject.toml` pins `pocket-tts>=2.1.0,<3`; 3.1.0 shipped 2026-09-03. Every API the service touches is unchanged in the 3.1.0 tarball, and 3.x adds the `english_2026-04_24l` model, `sampler_decode_steps` (replacing the deprecated `lsd_decode_steps`), a `checkpoint` argument, a configurable `append_terminal_punctuation`, and a sentence chunker that no longer splits inside decimals — relevant to voice agents that speak prices and figures. — *Needs a call: 3.x drops `load_model`'s hard `temp=0.7` default in favour of each config's `default_temperature` (0.3 for English), so the bump changes how the English voice sounds for callers that never set `temp`.*
- **No model-variant or custom-config selection** (medium, since 2026-09-01) — `PocketTTSSettings` inherits a `model` field the service never reads; the loaded model is derived from the language alone. That leaves `english_2026-01`, the 24-layer variants and the community models the README lists — Czech, and now Hindi and Korean — unreachable, even though `load_model` accepts a `config` path (local, `https://` or `hf://`). — *Needs a call: `load_model` rejects `language` and `config` together and weights load once at construction, so it needs deciding whether `model` names a pocket-tts config or a separate `config` argument does.*
- **Unsupported languages fail obscurely** (low, since 2026-09-01) — `language_to_pocket_tts_language(Language.JA)` returns `"ja"`, which `load_model` resolves to a missing `ja.yaml`, so construction dies with a `FileNotFoundError` rather than a message about the supported set. — *Needs a call: raise an error naming the six supported languages, or fall back to English.*
- **Generation parameters not exposed** (low, since 2026-09-01) — the constructor forwards only `temp` and `quantize`; `sampler_decode_steps`, `noise_clamp`, `eos_threshold`, `max_tokens` and `frames_after_eos` have no path in, and `temp` cannot change at runtime because `PocketTTSSettings` adds no fields. — *Needs a call: these are load-time model parameters, so whether they belong in Settings at all is the open question.*

Last run's two `action: pr` gaps — the broken example import and the 24-layer
models for German, Spanish, Italian and Portuguese — are closed by #5553
(merged 2026-09-02); `pocket_tts/tts.py` now maps those four languages to the
distilled models and both examples import `pipecat.services.pocket_tts.tts`.
