# Pocket TTS — 2026-11-09

Nothing is broken; the `<3` pin is the only real question, and pocket-tts 4.0.1
makes it a major version wide.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **pocket-tts 4.x is outside our pin** (medium, since 2026-09-01) — `pyproject.toml` pins `pocket-tts>=2.1.0,<3`; 4.0.0 shipped 2026-10-20 and 4.0.1 on 2026-10-21. Every API the service touches has an unchanged signature in the 4.0.1 tarball, and `get_state_for_audio_prompt("alba")` still works — 4.x resolves a bare predefined voice name to a per-language precomputed state, and the release script generates all 26 voices for every bundled config. Behind the pin sit 15 configs we do not have, retrained French/Italian/Dutch/German/Spanish/Portuguese weights, a `stop: threading.Event` on `generate_audio_stream` that would let an interruption end decoding instead of leaving the worker thread to finish the utterance, and a 5 ms fade-in on each chunk that removes the onset click. — *Needs a call: 3.x/4.x replace `load_model`'s hard `temp=0.7` with a per-config `default_temperature` of 0.3, and the `english` alias now points at `english_2026-10`, so the bump changes how every language sounds for callers that never set `temp`.*
- **French uses the 24-layer model; Dutch is unreachable** (medium, since 2026-10-12) — `language_to_pocket_tts_language` maps `Language.FR` to `french_24l`, and the comment above it explains that French has no distilled model. That is still true of the 2.1.0 the pin resolves to, but 3.2.0 added a distilled `french` and 3.3.0 added `dutch`, both retrained in 4.0.0. — *Needs a call: both configs exist only in 3.x/4.x, so this follows the pin decision above.*
- **No model-variant or custom-config selection** (medium, since 2026-09-01) — `PocketTTSSettings` inherits a `model` field the service never reads; the loaded model is derived from the language alone. 4.0 makes this more costly than it was: it added `english_18m_2026-10`, `english_7m_2026-10` and the experimental `english_2m_2026-10` (plus a `refl` variant of each), models built for exactly the small-CPU deployment this service targets, and none of them is selectable. The 24-layer variants and the 14 community configs the README lists (Czech, Hindi, Korean, Persian, Indonesian, Estonian, Welsh, Turkish, Polish, Greek, Japanese, Chinese, multilingual) are unreachable for the same reason, even though `load_model` accepts a `config` path (local, `https://` or `hf://`). — *Needs a call: `load_model` rejects `language` and `config` together and weights load once at construction, so it needs deciding whether `model` names a pocket-tts config or a separate `config` argument does.*
- **Unsupported languages fail obscurely** (low, since 2026-09-01) — `language_to_pocket_tts_language(Language.JA)` returns `"ja"`, which `load_model` resolves to a missing `ja.yaml`, so construction dies with a `FileNotFoundError` rather than a message about the supported set. — *Needs a call: raise an error naming the supported languages, or fall back to English.*
- **Generation parameters not exposed** (low, since 2026-09-01) — the constructor forwards only `temp` and `quantize`; `noise_clamp`, `eos_threshold`, the decode-step count, `max_tokens` and `frames_after_eos` have no path in, and `temp` cannot change at runtime because `PocketTTSSettings` adds no fields. — *Needs a call: these are load-time model parameters, so whether they belong in Settings at all is the open question.*
