# Pocket TTS — 2026-10-12

Nothing is broken; the open question is still the `<3` pin, and 3.2.0/3.3.0 make
it worth more than it was — a distilled French model and Dutch sit behind it.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **pocket-tts 3.x is outside our pin** (medium, since 2026-09-01) — `pyproject.toml` pins `pocket-tts>=2.1.0,<3`; 3.3.0 shipped 2026-09-24. Every API the service touches has an unchanged signature in the 3.3.0 tarball. Behind the pin sit six configs (distilled `french`, `dutch`, `dutch_24l`, `english_2026-09`, `english_2026-09_24l`, `english_2026-04_24l`), retrained German/Spanish/Italian/Portuguese weights, an `english` alias that is now a robustness fine-tune handling unpunctuated text and mid-word prompt cuts, and a `stop: threading.Event` on `generate_audio_stream` that would let an interruption end decoding instead of leaving the worker thread to finish the utterance. — *Needs a call: 3.x replaces `load_model`'s hard `temp=0.7` with a global `default_temperature` of 0.3, so the bump changes how every language sounds for callers that never set `temp`.*
- **French uses the 24-layer model; Dutch is unreachable** (medium, since 2026-10-12) — `language_to_pocket_tts_language` maps `Language.FR` to `french_24l`, and the comment above it explains that French has no distilled model. pocket-tts 3.2.0 added one, so French is no longer stuck on a variant the comment itself calls too slow for real time on a typical CPU; 3.3.0 added `dutch`, which the map has no entry for at all. — *Needs a call: both configs exist only in 3.x, so this follows the pin decision above.*
- **No model-variant or custom-config selection** (medium, since 2026-09-01) — `PocketTTSSettings` inherits a `model` field the service never reads; the loaded model is derived from the language alone. That leaves `english_2026-01`, the 24-layer variants and the community models the README lists (Czech, Hindi, Korean) unreachable, even though `load_model` accepts a `config` path (local, `https://` or `hf://`). — *Needs a call: `load_model` rejects `language` and `config` together and weights load once at construction, so it needs deciding whether `model` names a pocket-tts config or a separate `config` argument does.*
- **Unsupported languages fail obscurely** (low, since 2026-09-01) — `language_to_pocket_tts_language(Language.JA)` returns `"ja"`, which `load_model` resolves to a missing `ja.yaml`, so construction dies with a `FileNotFoundError` rather than a message about the supported set. — *Needs a call: raise an error naming the supported languages, or fall back to English.*
- **Generation parameters not exposed** (low, since 2026-09-01) — the constructor forwards only `temp` and `quantize`; `noise_clamp`, `eos_threshold`, the decode-step count, `max_tokens` and `frames_after_eos` have no path in, and `temp` cannot change at runtime because `PocketTTSSettings` adds no fields. — *Needs a call: these are load-time model parameters, so whether they belong in Settings at all is the open question.*
