# FunASR STT — 2026-11-09

Nothing new from the provider: `iic/SenseVoiceSmall` stays the default, and the four known gaps all still hold on funasr 1.4.23, the install gap first among them.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The `funasr` extra installs nothing that can run inference** (high, since 2026-09-01) — funasr 1.4.24 (2026-11-08) declares no torch, torchaudio or kaldi-native-fbank; only its `knf` extra pulls one. The repo's locked environment now holds funasr 1.4.23 and torch 2.15 (torch from `local-smart-turn`, not from this extra) and no fbank backend, so `probe.py run` loads the 936 MB checkpoint and then raises on the segment: *"torchaudio is not installed and neither is the kaldi-native-fbank fallback backend… or `pip install funasr[knf]`"*, from `funasr/utils/fbank.py`. Overlaying kaldi-native-fbank 1.23.0 on that same environment makes the probe transcribe the bundled clip correctly at TTFB 614 ms (median of 3, rtf 0.078). The pin `funasr>=1.1.0` is also unbounded downward in effect: it still admits 1.4.2, whose import fails outright without torchaudio, and 1.4.14, which caps `numpy<2`. The unit tests mock `funasr` entirely, so CI cannot see any of this, and the docs page documents `uv add "pipecat-ai[funasr]"` with no prerequisites. — *Needs a call: which fbank backend the extra should require (kaldi-native-fbank via `funasr[knf]`, or torchaudio pinned to torch the way `local-smart-turn` does), and whether the extra may pull torch itself.*
- **Emotion and audio-event emoji in transcripts** (medium, since 2026-09-01) — unchanged in 1.4.23: `emo_dict`/`event_dict` in `funasr/utils/postprocess_utils.py` still render SenseVoice's tags as emoji, so a `TranscriptionFrame` can read `🎼Play some music.` and that text goes into the LLM context and is liable to be spoken back. — *Needs a call: strip non-speech markers by default or put the stripping behind a setting, since those labels are part of why users pick SenseVoice.*
- **ModelScope-only downloads** (medium, since 2026-09-01) — `AutoModel`'s construction parameters include `hub="ms"|"hf"` (propagated to sub-models), `model_revision`, `ncpu` and `trust_remote_code`; the service passes only `model`, `device` and `disable_update`, so a user who can reach HuggingFace but not modelscope.cn cannot load a model. — *Needs a call: constructor argument next to `device`, or a Settings field, given the model is built once in `__init__`.*
- **Other FunASR models get SenseVoice-shaped calls** (low, since 2026-09-01) — nothing in the service blocks `Fun-ASR-Nano-2512`, `Fun-ASR-MLT-Nano-2512` (31 languages) or Paraformer, but Fun-ASR-Nano's toolkit path turns `language` into Chinese prompt text and reads `itn` rather than `use_itn`, its `hotwords` (and Paraformer's `hotword`) have no Settings field, `_FUNASR_LANGUAGES` collapses anything outside SenseVoice's five codes to `auto`, and the unconditional `rich_transcription_postprocess` is SenseVoice's. SenseVoiceSmall remains the recommended CPU model and is not deprecated, so the default does not move. — *Needs a call: a GPU probe before we point users at Nano, and a stance on per-model parameter handling versus documenting the service as SenseVoice-only.*

The eight releases since the last run (1.4.17–1.4.24) are all bug fixes in paths this service does not take: streaming punctuation, Paraformer timestamps and empty-token batches, VAD chunk boundaries, hotword batching, speaker clustering and import errors, and CIF/variance-normalization corrections. 1.4.24's normalization fix carries a re-evaluation note for checkpoints trained with `norm_means=True` and `norm_vars=True`; SenseVoiceSmall is not one, and the probe's transcript is correct. The model zoo is unchanged.
