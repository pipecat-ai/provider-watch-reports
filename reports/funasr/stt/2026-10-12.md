# FunASR STT — 2026-10-12

`iic/SenseVoiceSmall` stays the default and transcribes correctly on funasr 1.4.16; the install gap is unchanged in substance but has a new shape — the lock now resolves 1.4.16, so the import succeeds and the service fails per segment instead.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The `funasr` extra installs nothing that can run inference** (high, since 2026-09-01) — funasr 1.4.16 (2026-09-18) declares no torch, torchaudio or kaldi-native-fbank; only its `knf` extra pulls one. The repo's locked environment now holds funasr 1.4.16 and torch 2.14 (torch from `local-smart-turn`, not from this extra) and no fbank backend, so `probe.py run` loads the 936 MB checkpoint and then raises on the segment: *"torchaudio is not installed and neither is the kaldi-native-fbank fallback backend… or `pip install funasr[knf]`"*, from `funasr/utils/fbank.py`, the dispatcher 1.4.x added. Overlaying kaldi-native-fbank 1.22.3 on that same environment makes the probe transcribe the bundled clip correctly at TTFB 507 ms (median of 3). The pin `funasr>=1.1.0` is also unbounded downward in effect: it still admits 1.4.2, whose import fails outright without torchaudio, and 1.4.14, which caps `numpy<2`. The unit tests mock `funasr` entirely, so CI cannot see any of this, and the docs page documents `uv add "pipecat-ai[funasr]"` with no prerequisites. — *Needs a call: which fbank backend the extra should require (kaldi-native-fbank via `funasr[knf]`, or torchaudio pinned to torch the way `local-smart-turn` does), and whether the extra may pull torch itself.*
- **Emotion and audio-event emoji in transcripts** (medium, since 2026-09-01) — unchanged in 1.4.16: `emo_dict`/`event_dict` still render SenseVoice's tags as 😊 😔 😡 🎼 👏 😀, so a `TranscriptionFrame` can read `🎼Play some music.` and that text goes into the LLM context and is liable to be spoken back. — *Needs a call: strip non-speech markers by default or put the stripping behind a setting, since those labels are part of why users pick SenseVoice.*
- **ModelScope-only downloads** (medium, since 2026-09-01) — `AutoModel`'s documented construction parameters include `hub="ms"|"hf"` (propagated to sub-models), `model_revision`, `ncpu` and `trust_remote_code`; the service passes only `model`, `device` and `disable_update`, so a user who can reach HuggingFace but not modelscope.cn cannot load a model. — *Needs a call: constructor argument next to `device`, or a Settings field, given the model is built once in `__init__`.*
- **Other FunASR models get SenseVoice-shaped calls** (low, since 2026-09-01) — nothing in the service blocks `Fun-ASR-Nano-2512`, `Fun-ASR-MLT-Nano-2512` (31 languages) or Paraformer, but Fun-ASR-Nano's toolkit path turns `language` into Chinese prompt text and reads `itn` rather than `use_itn`, its `hotwords` (and Paraformer's `hotword`, and 1.4.16's new `postprocess_hotwords`) have no Settings field, `_FUNASR_LANGUAGES` collapses anything outside SenseVoice's five codes to `auto`, and the unconditional `rich_transcription_postprocess` is SenseVoice's. SenseVoiceSmall remains the recommended CPU model and is not deprecated, so the default does not move. — *Needs a call: a GPU probe before we point users at Nano, and a stance on per-model parameter handling versus documenting the service as SenseVoice-only.*

1.4.16's two functional changes do not reach this service: submodel device placement (`vad_kwargs`/`punc_kwargs`/`spk_kwargs`) only matters when `AutoModel` builds sub-models, which the service never does, and the new punctuation guidance confirms SenseVoice "outputs punctuation natively", so no `punc_model` is wanted.
