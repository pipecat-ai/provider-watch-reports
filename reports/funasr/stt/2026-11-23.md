# FunASR STT — 2026-11-23

The install gap is fixed in the repo, so a stock checkout now transcribes; nothing else moved, and `iic/SenseVoiceSmall` stays the default.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Emotion and audio-event emoji in transcripts** (medium, since 2026-09-01) — unchanged through funasr 1.4.29: `emo_dict`/`event_dict` in `funasr/utils/postprocess_utils.py` still render SenseVoice's tags as emoji, so a `TranscriptionFrame` can read `🎼Play some music.`, and that text enters the LLM context and is liable to be spoken back. SenseVoice's `ban_emo_unk` knob does the opposite (it bans the emotion *unknown* token so a concrete emotion is emitted), so the fix has to be ours. — *Needs a call: strip non-speech markers by default or put the stripping behind a setting, since those labels are part of why users pick SenseVoice.*
- **ModelScope-only downloads** (medium, since 2026-09-01) — `AutoModel`'s construction parameters include `hub="ms"|"hf"` (propagated to sub-models), `model_revision`, `ncpu` and `trust_remote_code`; the service passes only `model`, `device` and `disable_update`, so a user who can reach HuggingFace but not modelscope.cn cannot load a model. — *Needs a call: constructor argument next to `device`, or a Settings field, given the model is built once in `__init__`.*
- **Other FunASR models get SenseVoice-shaped calls** (low, since 2026-09-01) — nothing in the service blocks `Fun-ASR-Nano-2512`, `Fun-ASR-MLT-Nano-2512` (31 languages) or Paraformer, but Fun-ASR-Nano's toolkit path turns `language` into Chinese prompt text and reads `itn` rather than `use_itn`, its `hotwords` (and Paraformer's `hotword`) have no Settings field, `_FUNASR_LANGUAGES` collapses anything outside SenseVoice's five codes to `auto`, and the unconditional `rich_transcription_postprocess` is SenseVoice's. SenseVoiceSmall remains the recommended CPU model and is not deprecated, so the default does not move. — *Needs a call: a GPU probe before we point users at Nano, and a stance on per-model parameter handling versus documenting the service as SenseVoice-only.*

Resolved since the last run: the `funasr` extra now reads `funasr[knf]>=1.4.5` plus `torch>=2.5.0,<3` (commit 2850648a5, 2026-11-10), so the extra installs torch and the kaldi-native-fbank backend, and the floor is above the 1.4.2 release whose import fails. The repo's locked environment (funasr 1.4.23, torch 2.15.0, kaldi-native-fbank 1.23.0, numpy 2.5.4, no torchaudio) now runs `probe.py run` end to end with a correct transcript, where the same probe raised the fbank `ImportError` two weeks ago. `funasr/utils/fbank.py` carries its torchaudio/kaldi-native-fbank dispatcher as far back as v1.4.5, so the floor is consistent with the `knf` extra.

The five releases since the last run (1.4.25–1.4.29) are bug fixes, none in a path this service takes: Python 3.12 boolean argument parsing, Latin sentence timestamp spacing, HTTP `response_format=text`, word separators across VAD segments, Whisper batch feature lengths, symbol-token timestamps, SenseVoice event deduplication across text segments, and CIF timestamp fires. No model-weight, API or dependency change; the model zoo is identical to 1.4.24's and SenseVoiceLarge is still unreleased. Of SenseVoice's remaining `generate()` kwargs, `text_norm` duplicates `use_itn`, `output_timestamp` has no consumer in this service, and `ban_emo_unk` is covered above — none is worth a Settings field on its own.
