# FunASR STT — 2026-09-14

`iic/SenseVoiceSmall` stays the default and works on the current funasr with the `knf` backend; the open finding is unchanged and still the install — `pipecat-ai[funasr]` produces an environment that cannot transcribe.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The `funasr` extra installs nothing that can run inference** (high, since 2026-09-01) — funasr 1.4.15, released 2026-09-09, still declares neither torch nor a fbank backend, and FunASR's install guide puts `pip install torch torchaudio` before the toolkit. `probe.py run` against the repo's locked environment (funasr 1.4.2, torch 2.13, no torchaudio) fails at `ImportError: Missing module: No module named 'torchaudio'`. With funasr 1.4.15 plus its `knf` extra and no torchaudio at all, the same probe transcribes the bundled clip correctly at TTFB 816 ms, so `funasr[knf]>=1.4.15` is the version set that works. Two further reasons for that floor: 1.4.14 caps `numpy<2` (removed in 1.4.15) and today's `funasr>=1.1.0` can resolve it, pulling numpy back to 1.x; and from 1.4.15 a missing torch raises an actionable "FunASR requires PyTorch before using AutoModel" instead of a bare `ModuleNotFoundError`. The unit tests mock `funasr` entirely, so CI cannot see any of this. — *Needs a call: which fbank backend the extra should require (kaldi-native-fbank via `funasr[knf]`, or torchaudio pinned to torch the way `local-smart-turn` does), and whether the extra may pull torch itself.*
- **Emotion and audio-event emoji in transcripts** (medium, since 2026-09-01) — unchanged in 1.4.15: `emo_dict`/`event_dict` still render SenseVoice's tags as 😊 😔 😡 🎼 👏 😀, so a `TranscriptionFrame` can read `🎼Play some music.` and that text goes into the LLM context and is liable to be spoken back. — *Needs a call: strip non-speech markers by default or put the stripping behind a setting, since those labels are part of why users pick SenseVoice.*
- **ModelScope-only downloads** (medium, since 2026-09-01) — `AutoModel`'s documented construction parameters include `hub="ms"|"hf"` (propagated to sub-models), `model_revision`, `ncpu` and `trust_remote_code`; the service passes only `model`, `device` and `disable_update`, so a user who can reach HuggingFace but not modelscope.cn cannot load a model. — *Needs a call: constructor argument next to `device`, or a Settings field, given the model is built once in `__init__`.*
- **Other FunASR models get SenseVoice-shaped calls** (low, since 2026-09-01) — the model zoo now also lists `FunAudioLLM/Fun-ASR-MLT-Nano-2512` (31 languages) beside `Fun-ASR-Nano-2512`, and nothing in the service blocks either. But Fun-ASR-Nano's toolkit path turns `language` into Chinese prompt text and reads `itn` rather than `use_itn`, its `hotwords` (and Paraformer's `hotword`) have no Settings field, `_FUNASR_LANGUAGES` collapses anything outside SenseVoice's five codes to `auto`, and the unconditional `rich_transcription_postprocess` is SenseVoice's. SenseVoiceSmall remains the recommended CPU model and is not deprecated, so the default does not move. — *Needs a call: a GPU probe before we point users at Nano, and a stance on per-model parameter handling versus documenting the service as SenseVoice-only.*
