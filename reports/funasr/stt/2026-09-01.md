# FunASR STT — 2026-09-01

`iic/SenseVoiceSmall` is still the right default, but `pip install "pipecat-ai[funasr]"` produces an installation that cannot transcribe — that is the finding to act on.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **The `funasr` extra installs nothing that can run inference** (high, since 2026-09-01) — a dry-run resolve of `pipecat-ai[funasr]` brings funasr 1.4.11 and 108 packages with no torch, no torchaudio and no kaldi-native-fbank, because funasr declares none of them. Probed both failure modes: without a fbank backend every segment yields `FunASR transcription error: torchaudio is not installed and neither is the kaldi-native-fbank fallback backend`; and the version uv.lock currently holds (1.4.2, allowed by `funasr>=1.1.0`) imports torchaudio unconditionally, so `from funasr import AutoModel` raises `ModuleNotFoundError` before the service exists. FunASR guarded that import in 1.4.5. `funasr = ["funasr[knf]>=1.4.5", "torch>=2.5.0,<3"]` plus `uv lock` covers both. — *Needs a call: which fbank backend the extra should require (kaldi-native-fbank, or torchaudio pinned to torch the way `local-smart-turn` does), and whether the extra may pull torch itself.*
- **Emotion and audio-event emoji in transcripts** (medium, since 2026-09-01) — `rich_transcription_postprocess` maps SenseVoice's `<|HAPPY|>`, `<|Laughter|>`, `<|BGM|>`, `<|Applause|>` tags to 😊 😀 🎼 👏, so a `TranscriptionFrame` can read `🎼Play some music.` and that text goes into the LLM context and is liable to be spoken back. — *Needs a call: strip non-speech markers by default or put the stripping behind a setting, since those labels are part of why users pick SenseVoice.*
- **ModelScope-only downloads** (medium, since 2026-09-01) — `AutoModel` accepts `hub="hf"` and propagates it to VAD/punc/speaker sub-models; the service passes only `model`, `device` and `disable_update`, so a user who can reach HuggingFace but not modelscope.cn cannot load a model. — *Needs a call: constructor argument next to `device`, or a Settings field, given the model is built once in `__init__`.*
- **Fun-ASR-Nano-2512** (low, since 2026-09-01) — FunASR's new flagship (800M LLM-ASR, zh/en/ja plus dialects, 8.2% CER vs Paraformer's 10.18%) loads through the same `AutoModel(model=..., device=...)` call, so no allowlist or table blocks it, but it needs a GPU and the unconditional `rich_transcription_postprocess` is written for SenseVoice output. SenseVoiceSmall remains FunASR's recommended CPU model and is not deprecated, so the default does not move. — *Needs a call: a GPU probe before we point users at it, and whether the SenseVoice postprocess should stay unconditional.*
