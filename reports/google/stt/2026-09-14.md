# Google STT — 2026-09-14

Current: Google published nothing for Speech-to-Text since the last run (newest release note is still 2025-11-13), the SDK pin is still ahead of PyPI, and the four known gaps are unchanged. No branch this run.

## What's new for Pipecat

### PRs
Nothing.

The previous run's branch shipped: https://github.com/pipecat-ai/pipecat/pull/5536 merged 2026-09-03, so `denoiser_config` is now a `Settings` field and that gap is closed.

### To consider
- **Default `latest_long` is a V1 model tag** (medium, since 2026-09-01) — Google's V2 supported-models table lists `long`, `short`, `telephony*`, `chirp*` and the medical models; `latest_long` appears only in the V1 docs. The API still accepts it, and `long` returned a byte-identical transcript slightly faster. The V2 transcription-model page now describes `chirp_3` as "the latest generation", but Google names no successor to `latest_long` and has scheduled no retirement. — *Needs a call: whether `long` covers the same languages as the undocumented `latest_long` alias before changing the model under every existing deployment.*
- **Chirp 3 needs a regional location and drops interim results** (medium, since 2026-09-01) — `chirp_3` is GA in the `us` and `eu` multi-regions but does not exist in `global`, the service's default `location`, so a user who only changes the model gets a 400. At `location="us"` it transcribes (and reads the clip more accurately) but emitted no `InterimTranscriptionFrame`, so first output arrives at 4.2 s instead of 0.8 s. Not a default-bump candidate. The `examples/voice/voice-google*.py` and `examples/transcription/transcription-google.py` bots already pass `location="us"` next to their commented-out `model="chirp_3"` hint; the `location` docstring still says only "e.g., global, us-central1". — *Needs a call: whether the service should steer users (the `location` docstring, a location check) or leave Chirp 3 selection entirely to the caller.*
- **Streaming endpointing controls** (medium, since 2026-09-01) — `StreamingRecognitionFeatures.endpointing_sensitivity` and `.voice_activity_timeout` (speech start/end) sit next to the `enable_voice_activity_events` and `interim_results` the service already sets in `_connect`, and are not reachable. — *Needs a call: both need conversion (a sensitivity enum, Duration timeouts) and overlap with Pipecat's own VAD and turn strategies, so exposing them needs a stance on which layer owns endpointing.*
- **Remaining recognition features** (low, since 2026-09-01) — `diarization_config`, `multi_channel_mode`, `max_alternatives`, `transcript_normalization`, `translation_config`, `custom_prompt_config` and language-agnostic recognition via `language_codes=["auto"]`, which today is reachable only through the deprecated `language_codes` field (`Language` has no `auto` member). Chirp 3 restricts diarization to `Recognize`/`BatchRecognize`, so it is out of reach of this streaming service anyway. — *Needs a call: which of these a voice-agent pipeline actually consumes — most produce data no downstream processor reads today.*
