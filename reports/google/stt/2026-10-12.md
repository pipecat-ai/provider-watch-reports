# Google STT — 2026-10-12

Current: no Speech-to-Text release note since 2025-11-13, no new or retiring models, and the SDK's new release carries no API surface. The four known gaps are unchanged; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Default `latest_long` is a V1 model tag** (medium, since 2026-09-01) — the V2 supported-models table lists `long`, `short`, `telephony*`, `chirp*` and the medical models; `latest_long` appears only in the V1 docs. Today's probe shows the API still accepts it, with `long` returning an identical transcript slightly faster. Google names no successor to `latest_long` and has scheduled no retirement. — *Needs a call: whether `long` covers the same languages as the undocumented `latest_long` alias before changing the model under every existing deployment.*
- **Chirp 3 needs a regional location and drops interim results** (medium, since 2026-09-01) — `chirp_3` is GA in the `us` and `eu` multi-regions only, not in `global`, the service's default `location`, so a user who only changes the model gets a 400. At `location="us"` it transcribes but emitted no `InterimTranscriptionFrame` when measured on 2026-09-14, so first output arrives seconds late. Not a default-bump candidate. The `location` docstring still says only "e.g., global, us-central1" while the `examples/voice/voice-google*.py` bots already pass `location="us"` beside their commented-out `model="chirp_3"` hint. — *Needs a call: whether the service should steer users (the `location` docstring, a location check) or leave Chirp 3 selection entirely to the caller.*
- **Streaming endpointing controls** (medium, since 2026-09-01) — `StreamingRecognitionFeatures.endpointing_sensitivity` and `.voice_activity_timeout` (speech start/end) sit next to the `enable_voice_activity_events` and `interim_results` the service sets in `_connect`, and are not reachable. — *Needs a call: both need conversion (a sensitivity enum, Duration timeouts) and overlap with Pipecat's own VAD and turn strategies, so exposing them needs a stance on which layer owns endpointing.*
- **Remaining recognition features** (low, since 2026-09-01) — `diarization_config`, `multi_channel_mode`, `max_alternatives`, `transcript_normalization`, `translation_config`, `custom_prompt_config` (preview) and language-agnostic recognition via `language_codes=["auto"]`, which today is reachable only through the deprecated `language_codes` field (`Language` has no `auto` member). — *Needs a call: which of these a voice-agent pipeline actually consumes — most produce data no downstream processor reads today.*
