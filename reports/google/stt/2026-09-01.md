# Google STT — 2026-09-01

`GoogleSTTService` is functional and current; the default `latest_long` still transcribes but is a Speech-to-Text V1 model tag that Google's V2 model table no longer lists, and Chirp 3 (GA) is reachable only with a regional `location`.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5536 — Add a denoiser_config setting to GoogleSTTService

### To consider
- **Default `latest_long` is a V1 model tag** (medium, since 2026-09-01) — Google's V2 supported-models table lists `long`, `short`, `telephony*`, `chirp*` and the medical models; `latest_long` appears only in the V1 docs. The API still accepts it (probe ok), and `long` returned the same transcript slightly faster. — *Needs a call: whether `long` covers the same languages as the undocumented `latest_long` alias before changing the model under every existing deployment.*
- **Chirp 3 needs a regional location and drops interim results** (medium, since 2026-09-01) — `chirp_3` is GA in the `us` and `eu` multi-regions but does not exist in `global`, which is the service's default `location`, so a user who only changes the model gets a 400. At `location="us"` it transcribes (and read the clip more accurately) but emitted no `InterimTranscriptionFrame`, so first output arrives at 4.3 s instead of 1.3 s. Not a default-bump candidate. — *Needs a call: whether the service should steer users (docstring, examples, or a location check) or leave Chirp 3 selection entirely to the caller.*
- **Streaming endpointing controls** (medium, since 2026-09-01) — `StreamingRecognitionFeatures.endpointing_sensitivity` and `.voice_activity_timeout` (speech start/end) sit next to the `enable_voice_activity_events` and `interim_results` the service already sets, and are not reachable. — *Needs a call: both need conversion (a sensitivity enum, Duration timeouts) and overlap with Pipecat's own VAD and turn strategies, so exposing them needs a stance on which layer owns endpointing.*
- **Remaining recognition features** (low, since 2026-09-01) — `diarization_config`, `multi_channel_mode`, `max_alternatives`, `transcript_normalization`, `translation_config`, `custom_prompt_config` (Chirp 3, preview) and language-agnostic recognition via `language_codes=["auto"]`, which today is reachable only through the deprecated `language_codes` field (`Language` has no `auto` member). — *Needs a call: which of these a voice-agent pipeline actually consumes — most produce data no downstream processor reads today.*

## Verification

| model      | class            | ok | latency      | note                                                              |
| ---------- | ---------------- | -- | ------------ | ----------------------------------------------------------------- |
| latest_long | GoogleSTTService | ✅ | TTFB 1268 ms | default; location=global, 63 interim frames                       |
| long        | GoogleSTTService | ✅ | TTFB 1077 ms | location=global, identical transcript                             |
| chirp_3    | GoogleSTTService | ✅ | TTFB 4293 ms | location=us; no interim frames, most accurate transcript          |
| chirp_2    | GoogleSTTService | ❌ | —            | 400: model does not exist in location "us" (Chirp 2 is per-region) |
| chirp_3    | GoogleSTTService (branch) | ✅ | TTFB 4293 ms | `--setting denoiser_config={"denoise_audio": true}` accepted by the live API |
