# Google Interactions Vertex LLM — 2026-11-23

The default is settled: Vertex retired `gemini-3.6-flash` on 2026-11-19 with `gemini-3.8-flash` as its named replacement, so last run's question about the two Interactions classes disagreeing no longer applies here. What needs attention is the Gemini 4 family that landed on Vertex this month — `gemini-4-carbon` times out through this class because nothing sets its thinking level.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Gemini 4 models have no reasoning default** (high, since 2026-11-23) — `gemini-4-carbon` (GA 2026-11-10), `gemini-4-hydrogen` (GA 2026-11-12) and `gemini-4-neon` (GA 2026-11-18) are all on Vertex and all answer through this class, but none has a `_THINKING_DEFAULTS` entry, so the service sends no `thinking_level` and Google's default applies: HIGH for Hydrogen and Neon, MEDIUM for Carbon. Carbon then produced no token inside the service's 20 s stream idle timeout and failed with "LLM completion timeout"; with `thinking_level: low` it answered in TTFAT 2029 ms. Hydrogen's reasoning-prompt TTFAT drops from 3381 ms to 2008 ms the same way. Google documents LOW as the floor for every Gemini 4 model — `MINIMAL` and `thinking_budget` both return 400 — and `gemini-4-argon`'s existing entry is already `low`. — *Needs a call: `_THINKING_DEFAULTS` is shared by four Gemini units, so which one's PR carries it, and do all three models get `low`?*
- **gemini-4-hydrogen as the default** (medium, since 2026-11-23) — it is faster than the current default on a trivial prompt (TTFAT 1150 ms against 1573 ms, interleaved medians of 5), and Google's model page now calls `gemini-3.8-flash` "previous-generation". But Google names no Flash successor, 3.8 Flash retires no earlier than 2027-09-02, and aiewf-eval's medium-context leaderboard has no Gemini 4 row at all, so the quality condition for a bump cannot be checked. On a reasoning prompt Hydrogen is slower until it gets a reasoning default. — *Needs a call: propose the bump on the run where a `gemini-4-hydrogen` row reaches `gemini-3.8-flash`'s 99.9%, or hold until Google designates a Flash successor?*
- **No first-tier probe for this unit** (medium, since 2026-11-09) — unchanged: `probe.py`'s `build_kwargs` passes the base class's `api_key` from `GOOGLE_API_KEY`, which this subclass rejects, and looks for `GOOGLE_APPLICATION_CREDENTIALS` / `GOOGLE_PROJECT_ID` rather than the `GOOGLE_VERTEX_TEST_CREDENTIALS` / `GOOGLE_CLOUD_PROJECT_ID` that CI exports. Every probe below ran through a scratch wrapper. `google/vertex-llm` has the same gap from the same cause. — *Needs a call: should `build_kwargs` skip inherited parameters a subclass rejects, and should the names CI exports be the ones `probe.py` looks for?*

Closed since last run: the `google-genai` pin — the google extra moved to `google-genai>=3.2.0,<4`, and the current 3.6.1 (2026-11-18) is inside it. Dropped: "the default is the slower Flash, and the two Interactions classes disagree" — Vertex's model-versions table gives `gemini-3.6-flash` a retirement date of 2026-11-19 and names `gemini-3.8-flash` its replacement, so this class already ships the designated model (3.6 Flash still answered today, TTFAT 887 ms, and is still listed, but it is past its retirement date on Vertex and the Gemini-API side of the question belongs to `google/interactions-llm`).

Checked and not a gap: the docstring's "Gemini 3 models and later" holds — the Gemini 4 models answer through this class. Nothing this class names is deprecated. The lock sits on google-genai 3.2.0 while 3.6.1 is out, but nothing here gates on the SDK's Interactions model enum (3.2.0 sends `gemini-4-neon` and `gemini-4-carbon` as plain strings and Vertex accepts them), and 3.3–3.6's Interactions work is XHIGH thinking, Live Interactions and a continuation-merge fix. The Interactions deferred tier (GA 2026-11-16, 24-hour completion target) is for asynchronous work, not a voice loop, and `extra` reaches it anyway. `examples/function-calling/function-calling-google-interactions-vertex.py` pins no model, so it follows the default.
