# Google Gemini Live — 2026-10-12

Google shipped `gemini-3.8-live` GA on 2026-09-15 and Pipecat defaulted to it on
2026-10-01, which closes last run's two top items at once — the rejected
language codes and the preview-successor question. One branch left: three
docstrings still point at the model Google retires on 2026-11-17.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6132 — Point Gemini Live setting docstrings at gemini-3.8-live

### To consider

- **`proactivity` needs v1alpha** (medium, since 2026-10-12) — `proactivity={"proactive_audio":true}` on the default model closes the socket with `1007 ... Unknown name "proactivity" at 'setup': Cannot find field`; the service then retries and pushes a fatal error. Adding `http_options={"api_version":"v1alpha"}` makes the same call connect. `enable_affective_dialog=true` connects on the default api_version, so only `proactivity` is affected. The requirement is stated in the deprecated `InputParams` docstring and on docs.pipecat.ai, but not on `GeminiLiveLLMSettings`, which is where users of the canonical API look. — *Needs a call: should the service select v1alpha itself when `proactivity` is set, or fail fast with a clear message and document the requirement on `Settings`?*
- **Live transcription options** (medium, since 2026-09-01) — `input_audio_transcription` and `output_audio_transcription` are both built as bare `AudioTranscriptionConfig()`. The Live reference documents `languageCodes`, `customVocabulary`, `wordTimestamp`, `diarization` and `mode` (VERBATIM/SMART, where SMART does disfluency removal and formatting); google-genai 2.25.0 — the pin's new floor — carries all of them plus `language_auto`, `language_hints` and `adaptation_phrases`, so the SDK is no longer the blocker it was last run. `GeminiSTTService` reports the same gap from its side. — *Needs a call: one transcription settings shape shared with `GeminiSTTService`, or a Gemini-Live-only field?*
- **Deprecated `generation_config` wrapper** (medium, since 2026-10-12) — `_connect` assembles `LiveConnectConfig(generation_config=GenerationConfig(...))`, which google-genai deprecated: it warns on every connect that the field is "removed in the next major version (not before 7/31/2026)". That date has passed, so `google-genai<3` is the only thing keeping the service working, and the pin cannot move to the SDK's next major until this is migrated. The move is not purely mechanical: `response_modalities`, `temperature`, `top_p`, `top_k`, `max_output_tokens`, `seed`, `speech_config` and `media_resolution` all exist at the top level of `LiveConnectConfig`, but `frequency_penalty` and `presence_penalty` do not. — *Needs a call: where `frequency_penalty` and `presence_penalty` go once the wrapper is dropped — deprecate them on Settings, or keep the wrapper until the SDK offers a home?*
- **Hybrid VAD** (medium, since 2026-09-01) — unchanged. The capabilities guide's hybrid VAD (server VAD for speech start, client VAD sending `audio_stream_end` for immediate finalization instead of the server's silence timer) is unreachable: `audio_stream_end` is a real field on `LiveSendRealtimeInputParameters` but is sent nowhere in the service, leaving only server-VAD-only or fully manual `activity_start`/`activity_end` turns with pre-roll. `LiveConnectConfig.explicit_vad_signal` and the `VadSignalType` enum are still undocumented in the Live reference and still have no send-side counterpart. — *Needs a call: should the upstream VAD's stop signal drive `audio_stream_end`, given the service deliberately emits no turn frames of its own?*
- **`activity_handling`** (low, since 2026-09-01) — still the one `RealtimeInputConfig` field the SDK exposes and the service cannot. (The Live reference has since added `interimTranscriptTimestampEnabled` to that type, which google-genai 2.25.0 does not carry yet.) `NO_INTERRUPTION` disables server-side barge-in; unlike `turn_coverage` it changes who owns interruptions, since the pipeline's own VAD would still interrupt playback locally while the server keeps generating. — *Needs a call: how a server-side `NO_INTERRUPTION` should interact with `broadcast_interruption()` and the pipeline's interruption handling.*
- **`thinking_level` passed as a string** (low, since 2026-10-12) — `_DEFAULT_THINKING_LEVEL = "LOW"` is assigned to a field typed `Optional[ThinkingLevel]`, so every connect with a 3.8 thinking model emits a Pydantic serializer warning (10 of them in `tests/test_gemini_live_interaction_status.py`). The wire value is correct and the connect succeeds, so this is noise rather than breakage. The straightforward fix — import `ThinkingLevel` — would raise the effective google-genai floor, which `_resolved_thinking_config` deliberately avoids by feature-testing `ThinkingConfig.model_fields` instead. — *Needs a call: resolve `ThinkingLevel` defensively, or raise the google-genai floor?*
- **Stale default on docs.pipecat.ai** (low, since 2026-10-12) — the s2s/gemini page still gives `models/gemini-2.5-flash-native-audio-preview-12-2025` as the `model` default; everything else on it is current. The page is in the pipecat-docs repo, so no branch here. — *Needs a call: someone with the docs repo to make the one-word edit.*

Not carried forward: last run's "rejected language codes" (high) and
"gemini-3.1-flash-live-preview as the default" (medium) are both resolved by
the 2026-10-01 default bump — see Verification.
