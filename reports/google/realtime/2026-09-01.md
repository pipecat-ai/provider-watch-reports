# Google Gemini Live — 2026-09-01

The default model rejects 14 of the 30 language codes the service can send — a
connection failure, not a silent no-op — and Google has named
`gemini-3.1-flash-live-preview` its replacement. One branch adds `turn_coverage`.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5535 — Add a turn_coverage setting to GeminiLiveLLMService

### To consider

- **Rejected language codes** (high, since 2026-09-01) — `_connect` always sets `speech_config.language_code` from `Settings.language`, and the default model accepts only part of what `language_to_gemini_language` produces. Probing all 30 codes the map can emit, 14 close the socket with `1007 ... Unsupported language code`: `ar-XA`, `bn-IN`, `cmn-CN`, `en-AU`, `en-GB`, `en-IN`, `es-ES`, `fr-CA`, `gu-IN`, `kn-IN`, `ml-IN`, `mr-IN`, `ta-IN`, `te-IN`. So `Settings(language=Language.ES)` or `Language.EN_GB` never connects; the service retries three times and pushes a fatal error. `gemini-3.1-flash-live-preview` accepted all 31 codes probed, and the Live API guide says native-audio models choose the language themselves and "don't support explicitly setting the language code". — *Needs a call: narrow the map per model, omit `language_code` for native-audio models as the docs suggest, or let the default bump settle it?*
- **gemini-3.1-flash-live-preview as the default** (medium, since 2026-09-01) — the deprecations page lists the current default with `gemini-3.1-flash-live-preview` as its recommended replacement (no shutdown date). 3.1 Flash Live is Google's low-latency audio-to-audio model, connects through `GeminiLiveLLMService` unchanged, and takes every language code the service can emit. The service already carries the Gemini 3 branches (`_is_gemini_3`, `initial_history_in_client_content`, multi-part server events, the async-tool warning). The cost of the bump: it is a preview model, aiewf-eval's medium-context leaderboard has no realtime rows to compare pass rates with, and 3.1 drops three things Pipecat exposes — `enable_affective_dialog` (probed: connect fails with 1007), proactive audio, and NON_BLOCKING async function calling, which `examples/realtime/realtime-gemini-live-async-tool.py` demonstrates. Thinking also moves from `thinkingBudget` to `thinkingLevel` and turn coverage starts including all video frames. — *Needs a call: is a preview successor that loses affective dialog, proactivity and async tools an acceptable default, or does the bump wait for a GA Live model?*
- **Hybrid VAD** (medium, since 2026-09-01) — the capabilities guide describes hybrid VAD: keep server VAD on so speech starts are caught with prefix padding, and let the client's VAD send `audio_stream_end` at end of speech, which the server treats as an immediate finalization prompt instead of waiting out its ~800 ms silence timer. `audio_stream_end` is never sent by the service, so the only choices are server-VAD-only or fully manual `activity_start`/`activity_end` turns with pre-roll. — *Needs a call: should the upstream VAD's stop signal drive `audio_stream_end`, given the service deliberately emits no turn frames of its own?*
- **Live transcription options** (medium, since 2026-09-01) — `input_audio_transcription` and `output_audio_transcription` are both built as bare `AudioTranscriptionConfig()`, so nothing can bias or shape the transcripts the service turns into `TranscriptionFrame`s. `custom_vocabulary=["Pipecat"]` was accepted by both Live models; `language_codes` and `mode` sit on the same type. `GeminiSTTService` reports the same gap from its side. — *Needs a call: one transcription settings shape shared with `GeminiSTTService`, or a Gemini-Live-only field?*
- **`activity_handling`** (low, since 2026-09-01) — the other `RealtimeInputConfig` field; `NO_INTERRUPTION` disables server-side barge-in and was accepted by both Live models. Unlike `turn_coverage` it moves interruption ownership, which the service handles itself via the `interrupted` server event. — *Needs a call: how a server-side `NO_INTERRUPTION` should interact with `broadcast_interruption()` and the pipeline's interruption handling.*
