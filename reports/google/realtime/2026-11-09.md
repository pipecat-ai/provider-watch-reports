# Google Gemini Live — 2026-11-09

`models/gemini-3.8-live` is still Google's GA Live model with no successor and
no shutdown date, so the default stands. Two things changed under it: the
server now accepts `proactivity` on the default API version, closing last run's
top item, and google-genai 3.0.0 shipped a v1 default that 404s the Live
socket — the `<3` pin is what keeps that out.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6642 — Document Gemini 3.8 Live's proactivity and affective dialog behavior

### To consider

- **google-genai 3.0.0 and the v1 default** (medium, since 2026-11-09) — 3.0.0 (2026-11-06) makes `v1` the Gemini Developer API default where 2.x used `v1beta`. Connecting the default model with `api_version="v1"` is rejected with HTTP 404, retried three times and pushed as a fatal error; `v1beta` connects. Our pin is `google-genai>=2.25.0,<3` (with a `>=1.68.0,<3` fallback), so nobody is broken today, but the cap cannot move until the Live path names its API version. 3.0.0 also swaps httpx for httpx2, and the same extra feeds the other Google services. — *Needs a call: should `GeminiLiveLLMService` default `api_version` to v1beta so the pin can move, and who owns the cap across the other Google services?*
- **Live transcription options** (medium, since 2026-09-01) — `input_audio_transcription` and `output_audio_transcription` are both bare `AudioTranscriptionConfig()`. google-genai 2.34.0 carries eight fields on that type and 3.0.0 adds `source_text` with `SmartTranscriptionMode`; the capabilities guide pushes `custom_vocabulary` for proper nouns (up to 1,000 terms) and the API reference documents `mode: SMART` for disfluency removal, noting timestamps and diarization are incompatible with it. `GeminiSTTService` reports the same gap from its side. — *Needs a call: one transcription settings shape shared with `GeminiSTTService`, or a Gemini-Live-only field?*
- **Deprecated `generation_config` wrapper** (medium, since 2026-10-12) — `_connect` still assembles `LiveConnectConfig(generation_config=GenerationConfig(...))` and google-genai still warns on every connect. The SDK's 3.0.0 major came and went with the field and the warning intact, so last run's reading that `<3` is all that keeps the service working no longer holds — but the migration is still pending, and it is not mechanical: `response_modalities`, `temperature`, `top_p`, `top_k`, `max_output_tokens`, `seed`, `speech_config` and `media_resolution` all exist at the top level of `LiveConnectConfig`, while `frequency_penalty` and `presence_penalty` do not. — *Needs a call: where `frequency_penalty` and `presence_penalty` go once the wrapper is dropped — deprecate them on Settings, or keep the wrapper until the SDK offers a home?*
- **Hybrid VAD** (medium, since 2026-09-01) — unchanged. The capabilities guide's hybrid VAD (server VAD for speech start and as fallback, client VAD sending `audio_stream_end` so the server finalizes without its silence timer) is unreachable: `audio_stream_end` is a real field on `LiveSendRealtimeInputParameters` but is sent nowhere in the service, leaving only server-VAD-only or fully manual `activity_start`/`activity_end` turns with no pre-roll. — *Needs a call: should the upstream VAD's stop signal drive `audio_stream_end`, given the service deliberately emits no turn frames of its own?*
- **In-session context updates** (medium, since 2026-11-09) — when the effective system instruction changes or the context brings its own tools, `_handle_context` reconnects the session. google-genai 2.32.0 added `session.send_context_update(system_instruction=..., tools=...)`, which updates the preamble in order with the rest of the inputs and keeps the socket. The Live API reference has not published the underlying message, and the SDK notes the update invalidates the prefix cache, so this is a candidate to probe rather than a known win. — *Needs a call: is an in-session update worth probing as a replacement for the reconnect path, given the API reference has not published the message?*
- **`activity_handling` and interim transcript timestamps** (low, since 2026-09-01) — the two `RealtimeInputConfig` fields the service cannot express. `interim_transcript_timestamp_enabled` has landed on the SDK type since last run, so both are now reachable in principle. `NO_INTERRUPTION` disables server-side barge-in; unlike `turn_coverage` it changes who owns interruptions, since the pipeline's own VAD would still interrupt playback locally while the server keeps generating. — *Needs a call: how a server-side `NO_INTERRUPTION` should interact with `broadcast_interruption()` and the pipeline's interruption handling.*
- **`thinking_level` passed as a string** (low, since 2026-10-12) — `_DEFAULT_THINKING_LEVEL = "LOW"` is assigned to a field typed `Optional[ThinkingLevel]`, so every connect with a 3.8 thinking model emits a Pydantic serializer warning; this run's `gemini-3.8-live-extended-thinking` probe showed it again. The wire value is correct and the connect succeeds, so this is noise rather than breakage, and the obvious fix — importing `ThinkingLevel` — would raise the effective google-genai floor above the `>=1.68.0` fallback pin that `_resolved_thinking_config` works around by feature-testing `ThinkingConfig.model_fields`. — *Needs a call: resolve `ThinkingLevel` defensively, or raise the google-genai floor?*
- **Stale v1alpha note on docs.pipecat.ai** (low, since 2026-11-09) — the s2s/gemini page's Notes still say affective dialog and proactivity "require both a supporting model and API version (`v1alpha`)"; both connect on the default API version today, on the 3.8 and the 2.5 models alike. The page's model default is now correct, which closes last run's docs item. The page is in the pipecat-docs repo, so no branch here. — *Needs a call: someone with the docs repo to drop the v1alpha note.*

Not carried forward: last run's "`proactivity` needs v1alpha" (medium) — the
setting now connects on the default API version — and "stale default on
docs.pipecat.ai" (low), which the docs page has since fixed. Last run's PR
#6132 (retired model names in docstrings) merged on 2026-10-12.
