# Google Interactions LLM — 2026-11-09

First run for this class (added 2026-10-30, Vertex subclass 2026-11-04). It is current: `gemini-3.6-flash`, `gemini-3.8-flash`, `gemini-4-argon` and `gemini-omni-1.2-flash` all answer through it, nothing it names is retiring, and its thinking-defaults coverage is complete. Nothing is ready to merge; the decision to make is the default, which the Vertex subclass already answers differently.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **The default, and the disagreement with the Vertex subclass** (medium, since 2026-11-09) — this class defaults to `gemini-3.6-flash`, `GoogleInteractionsVertexLLMService` to `gemini-3.8-flash`. Through this class, interleaved medians of 5 on a trivial prompt put 3.6 Flash at TTFAT 988 ms against 1732 ms for 3.8 Flash, `thinking_ms` 2–3 and no failures either way. Quality points the other way: aiewf-eval medium-context has `gemini-3.8-flash (low)` at 99.9% / 1411 ms P50 and `gemini-3.6-flash (minimal)` at 95.1% / 808 ms. 3.8 Flash has no level below `low` — `MINIMAL` is a validation error on it — so the gap cannot be tuned away. Neither model has a shutdown date. — *Needs a call: should the two Interactions classes agree on one default, and is 99.9% over 95.1% worth ~750 ms of TTFAT?*
- **Deprecated sampling parameters are sent silently** (medium, since 2026-11-09) — `_build_request` warns once for `top_k`, `frequency_penalty` and `presence_penalty`, which the Interactions API has no field for, but puts `temperature` and `top_p` into `generation_config` without a word. google-genai marks both deprecated on the Interactions `GenerationConfig`, and Google's Gemini 3.8 Flash guide says the backend ignores them; a probe with both set still returns 200, so tuning them is silent in both directions. — *Needs a call: extend `_warn_unsupported` to the two on Gemini 3 models, or just document the deprecation on the Settings fields?*
- **google-genai 3.0.0 is outside our pin** (medium, since 2026-11-09) — released 2026-11-06 against a `<3` ceiling. What matters here is the Gemini Developer API default moving from `v1beta` to `v1`: Interactions features land on `v1beta`/`v1alpha` first, and the video blocks added to function results on 2026-11-05 are on those versions only. — *Needs a call: when does the google extra move to `<4`, and does this class then pin `api_version=v1beta`?*
- **`service_tier` Settings field** (low, since 2026-11-09) — priority inference is Interactions-only, targets second-level non-sheddable responses, and covers `gemini-3.6-flash`, `gemini-3.8-flash` and `gemini-4-argon`; it is in preview, costs 75–100% more and gets 0.3x the rate limits. `extra={"service_tier": "priority"}` already reaches it, and answered in the probe below. — *Needs a call: does a dedicated field earn its place while the tier is in preview and `extra` covers it?*
- **Multimodal function results** (low, since 2026-11-09) — since 2026-11-05 a `function_result` step takes document, audio and video blocks beside text and image, inline or by URI; Pipecat's function-call results are text/JSON. Shared with `google/llm`. — *Needs a call: does multimodal tool output belong in the universal `LLMContext` result shape first?*
- **Continuation hops are treated as failures** (low, since 2026-11-09) — google-genai resumes long decodes by default (`automatic_continuation=True`), and with `stream=True` each intermediate hop ends with an `interaction.completed` event whose status is `requires_continuation`. `_handle_event` logs "response incomplete" for it, and the usage it keeps is the last hop's, which the SDK documents as per-hop rather than cumulative. The 4096-token `max_tokens` default keeps this out of reach. — *Needs a call: skip `requires_continuation` and sum per-hop usage, or leave long decode out of scope for a voice pipeline?*

Checked and not a gap: thinking defaults are complete for every Interactions-capable model in the catalogue — the Gemini 2.5 entries are not reachable from here, because `_thinking_default(levels_only=True)` refuses a budget the Interactions API has no field for, so `google/llm`'s 2026-12-01 reroute item does not apply to this class; `gemini-3.8-flash` and `gemini-4-argon` sit at their documented floor of `low`, and `gemini-flash-latest` and friends are aliases that get none by design. `gemini-3.7-flash` scores 99.9% / 821 ms on aiewf-eval but is not a candidate: Google routes its API requests to 3.8 Flash. `gemini-omni-1.2-flash` (GA 2026-11-05 through the Interactions API) answers text through this class but is a video-generation model, not a Flash successor, and does not think. None of the six `*-interactions*` examples pins a model, so they all follow the default. `extra` passes any top-level request key through, so `cached_content`, `labels`, `background` and `service_tier` need no new field to be reachable. The Deep Research and Computer Use agents are addressed with `agent` rather than `model` and are minutes-scale, which is not this service's shape.
