# Google Interactions LLM — 2026-11-23

Three Gemini 4 models went GA in the last two weeks (Carbon 2026-11-10, Hydrogen 2026-11-12, Neon 2026-11-18) and none had a thinking default, so they answered at Google's `medium`/`high`; the branch gives all three the documented floor of `low` and roughly halves their TTFAT. Nothing this class names is retiring, and last run's google-genai pin gap is closed.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6962 — Send the Gemini 4 models the lowest thinking level they accept

### To consider
- **The default, now with a third candidate** (medium, since 2026-11-09) — this class defaults to `gemini-3.6-flash`, `GoogleInteractionsVertexLLMService` to `gemini-3.8-flash`, and Google's Gemini 4 Hydrogen guide documents migrating to `gemini-4-hydrogen` from 3.8 Flash and earlier Gemini 3 Flash models. On a trivial prompt through this class the three sit closer than before: 3.6 Flash TTFAT 1025 ms (median of 5), Hydrogen 1218 ms at `thinking_level: low` (median of 5), 3.8 Flash 1499 ms (median of 3). aiewf-eval's medium-context leaderboard is unchanged — 3.8 Flash (low) 99.9%, 3.6 Flash (minimal) 95.1% — and has no Gemini 4 row, so a Hydrogen bump has no quality evidence yet. No candidate has a shutdown date. — *Needs a call: wait for an aiewf-eval row for Hydrogen, or settle the 3.6-vs-3.8 split across the four Gemini LLM classes now?*
- **Deprecated sampling parameters are sent silently** (medium, since 2026-11-09) — `_build_request` warns once for `top_k`, `frequency_penalty` and `presence_penalty`, which the Interactions API has no field for, but puts `temperature` and `top_p` into `generation_config` without a word. Google's Hydrogen guide repeats the 3.8 Flash guide: those values are ignored and should be removed from requests. — *Needs a call: extend `_warn_unsupported` to the two on Gemini 3.8 and later, or just document the deprecation on the Settings fields?*
- **`service_tier` Settings field** (low, since 2026-11-09) — priority inference is Interactions-only and targets second-level non-sheddable responses; it is in preview, costs 75–100% more and gets 0.3x the rate limits. `extra={"service_tier": "priority"}` already reaches it. — *Needs a call: does a dedicated field earn its place while the tier is in preview and `extra` covers it?*
- **Multimodal function results** (low, since 2026-11-09) — a `function_result` step takes document, audio and video blocks beside text and image, inline or by URI, and since 2026-11-18 those payloads can be sliced and include Office formats; Pipecat's function-call results are text/JSON. Shared with `google/llm`. — *Needs a call: does multimodal tool output belong in the universal `LLMContext` result shape first?*
- **Tool retrieval** (low, since 2026-11-23) — preview since 2026-11-19 on Gemini 3.6 and later: `defer_loading: true` on a function tool plus a `{"type": "tool_search"}` tool keeps deferred schemas out of the prompt until the model asks for one by name. `to_provider_tools_format` builds function tools straight from the context's `ToolsSchema` with no room for per-tool flags, and the adapter has no form for the `tool_search_call` / `tool_search_result` steps a retrieved turn produces, so such a turn would not round-trip into the next request. — *Needs a call: is a tool-heavy agent a shape Pipecat wants to serve here, and should per-tool provider flags live in `ToolsSchema` rather than one adapter?*
- **Continuation hops are treated as failures** (low, since 2026-11-09) — google-genai resumes long decodes by default, and with `stream=True` each intermediate hop ends with an `interaction.completed` event whose status is `requires_continuation`; `_handle_event` logs "response incomplete" for it and keeps only that hop's usage. The 4096-token `max_tokens` default keeps this out of reach. — *Needs a call: skip `requires_continuation` and sum per-hop usage, or leave long decode out of scope?*

Closed since the last run: the google-genai pin. `pyproject.toml` now asks `google-genai>=3.2.0,<4` (commit c1bffe0d8, 2026-11-11) and the Gemini Developer API clients ask `v1beta` explicitly, so the Interactions features that ship there first stay reachable; the latest release, 3.6.1 (2026-11-18), is inside the pin.

Checked and not a gap: nothing this class names is retiring — `gemini-3.6-flash`, `gemini-3.8-flash` and all four Gemini 4 models carry "no shutdown date announced", and none of the six `*-interactions*` examples pins a model. With the branch, thinking-defaults coverage is complete again for every Interactions-capable model in the catalogue; the Gemini 2.5 entries stay unreachable from here because `_thinking_default(levels_only=True)` refuses a budget the Interactions API has no field for. `gemini-decision-1` (2026-11-11) belongs to the separate Decisions API and `genie-4` (GA 2026-11-19) is a WebRTC world-generation model, neither of which is this service's shape. `gemini-4-carbon` and `gemini-4-neon` answer through this class but are frontier reasoning models at 3.1 s and 1.8 s TTFAT, not voice defaults.
