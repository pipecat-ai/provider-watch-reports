# Google TTS — 2026-10-28

Our default `gemini-3.1-flash-tts-preview` now has a Gemini API shutdown date — November 17, 2026, three weeks away — and Cloud Text-to-Speech still serves no 3.8 model, so the one shared default can no longer be right for both backends. All three classes synthesize on both backends today.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6430 — Stop naming retiring Gemini TTS preview models in GeminiTTSService docs

### To consider
- **Default retires on the Gemini API on 2026-11-17** (high, since 2026-09-01) — Google's deprecations table gives `gemini-3.1-flash-tts-preview` a shutdown date of November 17, 2026 (earliest possible) with `gemini-3.8-flash-tts` / `gemini-3.8-flash-lite-tts` as the recommended replacements; last run the same item had a named successor but no date. Cloud TTS keeps serving the preview model with no deprecation notice, and says the 3.8 models "aren't available through the Cloud Text-to-Speech API". On the GenAI backend Flash-Lite is again roughly twice as fast (TTFB 407 ms against 911 ms, medians of 3). `_use_genai` defaults to whether an `api_key` was passed, so both paths are reachable with the shipped default. — *Needs a call before 2026-11-17: should `GeminiTTSService` pick its default from `use_genai` — `gemini-3.8-flash-lite-tts` on the Gemini API, `gemini-3.1-flash-tts-preview` or GA `gemini-2.5-flash-tts` on Cloud TTS — or stay on one name both accept?*
- **GenAI backend drops `multi_speaker`** (medium, since 2026-09-01) — `_warn_unsupported_genai_settings` warns it away and `_run_genai_tts` never sets it, but a two-speaker request through the pinned SDK synthesized audio on `gemini-3.8-flash-tts`. The API allows two speakers per request, prebuilt voices only, and every turn must carry a matching `speaker`. — *Needs a call: `speaker_configs` is `{speaker_alias, speaker_id}` over one undivided string, so the mapping needs a way to say which text each speaker speaks — what shape should the setting take?*
- **Chirp voices never get SSML** (medium, since 2026-09-01) — `GoogleHttpTTSService.run_tts` takes the plain-text branch for any voice whose name contains "chirp", and the class default is `en-US-Chirp3-HD-Charon`, so `pitch`, `rate`, `volume`, `emphasis` and `gender` do nothing out of the box. Chirp 3 HD accepts SSML on the synchronous endpoint. — *Needs a call: Chirp 3 HD rejects `interpret-as="expletive"`/`"bleep"` and Journey voices are untested, so removing the branch needs a stance on which voices keep the plain-text path.*
- **`custom_pronunciations`** (medium, since 2026-09-01) — Cloud TTS takes IPA/X-SAMPA pronunciation overrides on `SynthesisInput` and `StreamingSynthesizeConfig`; neither class exposes them, and they are the standard fix for brand and person names. — *Needs a call: the field is a nested proto (phrase, phonetic_encoding, pronunciation), so a Settings field needs a shape — a list of dicts converted in the request builder, or the proto exposed directly?*
- **`markup` input and `advanced_voice_options`** (low, since 2026-09-01) — both Cloud TTS classes always send text input. `markup` carries Chirp 3 pause tags and Gemini structured markup; `advanced_voice_options` carries `enable_textnorm`, `relax_safety_filters` and `safety_settings`. — *Needs a call: pause control and custom pronunciations are Preview on Chirp 3 HD and relaxed safety filters require a monthly-invoiced billing account — is a Settings field worth it for gated features?*
- **Hard-coded voice list is far behind the Voices API** (low, since 2026-10-12) — `AVAILABLE_VOICES` holds the 30 classic names; the Extended Voice Library is 150+ prebuilt and custom voices served from `GET /v1beta/voices`. Anything else logs "not in known voices list", and the custom-ID exemption only matches `voice_`, so the documented stateless `voicekey_...` IDs warn too. The voice is still sent either way. — *Needs a call: drop the list in favour of the Voices API, or just relax the warning?*
- **Gemini API audio format and sample rate** (low, since 2026-10-12) — the speech-generation reference documents `response_format.mime_type` (wav/l16/mulaw/alaw) and `sample_rate` (8/16/24 kHz); the class is fixed at 24 kHz PCM and those knobs are on Google's dedicated TTS surface, not the `generate_content` config the service uses. — *Needs a call: is a second GenAI request path worth 8 kHz mulaw for telephony?*
- **Pipecat docs page is stale** (low, since 2026-10-12) — it lists no 3.8 TTS model and still says the GenAI backend does not support `prompt`. — *Needs a call: the page lives in the docs repo — open a docs issue?*
