# Google TTS — 2026-09-01

`gemini-3.1-flash-tts-preview` is the right default and all three classes synthesize; the branch fixes `language` never reaching the Gemini API backend, and the remaining gaps are Cloud TTS request fields Settings cannot express.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5537 — Send the configured language to the Gemini API TTS backend
- https://github.com/pipecat-ai/pipecat/pull/5526 — Name the Gemini TTS models each backend accepts (open)

### To consider
- **GenAI backend drops `prompt` and `multi_speaker`** (medium, since 2026-09-01) — `_warn_unsupported_genai_settings` warns that the Gemini API supports neither, and `_run_genai_tts` sets neither. The API supports both: a two-speaker `MultiSpeakerVoiceConfig` against `gemini-3.1-flash-tts-preview` returned 168960 bytes of audio, and the documented style phrasing (`Say cheerfully: ...`, prefixed to the content) returned 184320 bytes. Style prompting is not unconditional though — `Say this in a slow, dramatic whisper: ...` came back with `STOP` and no audio. — *Needs a call: map `speaker_configs` onto `SpeakerVoiceConfig` and prefix `prompt` to the content, or keep the warning because prompt-as-content-prefix is unreliable?*
- **Chirp voices never get SSML** (medium, since 2026-09-01) — `GoogleHttpTTSService.run_tts` takes the plain-text branch for any voice whose name contains "chirp", and the class default is `en-US-Chirp3-HD-Charon`, so `pitch`, `rate`, `volume`, `emphasis` and `gender` do nothing unless the user picks a non-Chirp voice. Chirp 3 HD now accepts SSML on the synchronous endpoint: `<speak><prosody rate='slow'>…` synthesized 160416 bytes against 121004 for the same text sent as plain text. Streaming still has no SSML, so `GoogleTTSService` is unaffected. — *Needs a call: Chirp 3 HD rejects `interpret-as="expletive"`/`"bleep"` and Journey voices are untested, so removing the branch needs a stance on which voices keep the plain-text path.*
- **`custom_pronunciations`** (medium, since 2026-09-01) — Cloud TTS takes IPA/X-SAMPA pronunciation overrides on `SynthesisInput` (synchronous) and `StreamingSynthesizeConfig` (streaming); neither class exposes them, and they are the standard fix for brand and person names. Both paths accepted a `Pipecat` → `ˈpaɪpkæt` override with the default Chirp 3 HD voice. — *Needs a call: the field is a nested proto (phrase, phonetic_encoding, pronunciation), so a Settings field needs a shape — a list of dicts converted in the request builder, or the proto exposed directly?*
- **`markup` input and `advanced_voice_options`** (low, since 2026-09-01) — both classes always send `SynthesisInput(text=...)`. `markup` carries Chirp 3 pause tags and Gemini structured markup (`Ready. [pause] …` returned 197804 bytes vs 121004 plain), and `advanced_voice_options` carries `enable_textnorm`, `relax_safety_filters` and `safety_settings` (accepted). — *Needs a call: pause control and custom pronunciations are Preview on Chirp 3 HD and relaxed safety filters require a monthly-invoiced billing account — is a Settings field worth it for gated features?*
- **Preview model as the default** (low, since 2026-09-01) — `gemini-3.1-flash-tts-preview` is Google's newest TTS model, the only 3.x one, and the faster of the two on the Cloud TTS path (TTFB 634 ms vs 688 ms for GA `gemini-2.5-flash-tts`), but it is Preview on Cloud Text-to-Speech. The Gemini API publishes no GA TTS model at all, so the GenAI backend has no GA alternative. An unannounced `sonic-boom-tts` also appears in the Gemini API catalogue and synthesizes through the class. — *Needs a call: is a preview default acceptable while it is the only 3.x TTS model, or should the Cloud TTS path fall back to GA `gemini-2.5-flash-tts`?*
