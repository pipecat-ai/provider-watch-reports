# Google TTS — 2026-11-09

`gemini-3.1-flash-tts-preview` shuts down on the Gemini API on November 17, eight days out, and Cloud Text-to-Speech serves no Gemini 3.8 model — the branch makes the default follow the backend. Nothing else changed since the last run; the Pipecat docs page caught up and PR #6430 merged.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6643 — Default GeminiTTSService per backend

  `gemini-3.8-flash-lite-tts` on the Gemini API (Google's named replacement for the retiring preview model, and three times faster through our class), `gemini-3.1-flash-tts-preview` unchanged on Cloud Text-to-Speech, which rejects 3.8 with a 400 on the streaming endpoint. Two review points: on the 3.13/Linux leg of the `google-genai` pin the floor is 1.68.0, where `_check_genai_model_supported` pushes an INVALID_REQUEST error for any 3.8 model, so that environment goes from working to erroring on the Gemini API path — it breaks on November 17 either way; and the docs page states a single default, so it needs a follow-up.

### To consider
- **GenAI backend drops `multi_speaker`** (medium, since 2026-09-01) — `_warn_unsupported_genai_settings` warns it away and `_run_genai_tts` never sets it, but the Gemini API takes up to two prebuilt speakers per request with a `speech_metadata.speaker` on each turn, and a two-speaker request through the pinned SDK synthesized audio on `gemini-3.8-flash-tts`. — *Needs a call: `speaker_configs` is `{speaker_alias, speaker_id}` over one undivided string, so the mapping needs a way to say which text each speaker speaks — what shape should the setting take?*
- **Chirp voices never get SSML** (medium, since 2026-09-01) — `GoogleHttpTTSService.run_tts` takes the plain-text branch for any voice whose name contains "chirp", and the class default is `en-US-Chirp3-HD-Charon`, so `pitch`, `rate`, `volume`, `emphasis` and `gender` do nothing out of the box. Chirp 3 HD accepts SSML on the synchronous endpoint. — *Needs a call: Chirp 3 HD rejects `interpret-as="expletive"`/`"bleep"` and Journey voices are untested, so removing the branch needs a stance on which voices keep the plain-text path.*
- **`custom_pronunciations`** (medium, since 2026-09-01) — Cloud TTS takes IPA/X-SAMPA pronunciation overrides on `SynthesisInput` and `StreamingSynthesizeConfig`; neither class exposes them, and they are the standard fix for brand and person names. — *Needs a call: the field is a nested proto (phrase, phonetic_encoding, pronunciation), so a Settings field needs a shape — a list of dicts converted in the request builder, or the proto exposed directly?*
- **google-genai 3.0.0 is past our pin** (medium, since 2026-11-09) — released November 6; our extra pins `<3`. No TTS feature rides on it, but it moves the Gemini Developer API default from v1beta to v1 and the HTTP client to httpx2, and the Extended Voice Library lives at `GET /v1beta/voices`. — *Needs a call: the pin is shared by every google service and the 3.13/Linux leg still floors at 1.68.0 for vonage-video-connector — who owns raising it, and does any google service depend on v1beta behaviour?*
- **`markup` input and `advanced_voice_options`** (low, since 2026-09-01) — both Cloud TTS classes always send text input. `markup` carries Chirp 3 pause tags and Gemini structured markup; `advanced_voice_options` carries `enable_textnorm`, `relax_safety_filters` and `safety_settings`. — *Needs a call: pause control and custom pronunciations are Preview on Chirp 3 HD and relaxed safety filters require a monthly-invoiced billing account — is a Settings field worth it for gated features?*
- **Hard-coded voice list is far behind the Voices API** (low, since 2026-10-12) — `AVAILABLE_VOICES` holds the 30 prebuilt names; the Extended Voice Library is served from `GET /v1beta/voices`, and voice remixing (launched November 4) mints more `voice_...` IDs. Anything else logs "not in known voices list", and the custom-ID exemption only matches `voice_`, so the documented stateless `voicekey_...` IDs warn too. The voice is still sent either way. — *Needs a call: drop the list in favour of the Voices API, or just relax the warning?*
- **Gemini API audio format and sample rate** (low, since 2026-10-12) — the speech-generation reference documents `response_format.mime_type` (wav/l16/mulaw/alaw) and `sample_rate` (8/16/24 kHz); the class is fixed at 24 kHz PCM and those knobs are on the dedicated `interactions` TTS surface, not the `generate_content` config the service uses. — *Needs a call: is a second GenAI request path worth 8 kHz mulaw for telephony?*

Dropped since the last report: the docstring item (PR #6430 merged on 2026-10-28) and the stale-docs item — docs.pipecat.ai now lists both 3.8 models and documents `prompt` on the Gemini API backend for them.

Cloud TTS probes need the service-account JSON in `GOOGLE_APPLICATION_CREDENTIALS`, which is empty here; it was supplied to the probe process from `GOOGLE_TEST_CREDENTIALS`. Byte counts quoted in the Cloud TTS gaps are the 2026-09-01 probes and the multi-speaker figure the 2026-10-12 one; those request schemas are unchanged, so they were not repeated.
