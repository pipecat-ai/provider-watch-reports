# Google TTS — 2026-11-23

Both backends' defaults synthesize fine and no TTS model is retiring within the month; the only change since the last run is that Google pushed `gemini-3.1-flash-tts-preview`'s Gemini API shutdown from November 17 to December 18, which the class docstring still gets wrong — branch ready.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6966 — Record December 18, 2026 as the Gemini TTS preview shutdown date

### To consider
- **GenAI backend drops `multi_speaker`** (medium, since 2026-09-01) — `_warn_unsupported_genai_settings` warns it away and `_run_genai_tts` never sets it, but the Gemini API takes up to two prebuilt speakers per request with a `speech_metadata.speaker` on each turn, and a two-speaker request through the pinned SDK synthesized audio on `gemini-3.8-flash-tts`. — *Needs a call: `speaker_configs` is `{speaker_alias, speaker_id}` over one undivided string, so the mapping needs a way to say which text each speaker speaks — what shape should the setting take?*
- **Chirp voices never get SSML** (medium, since 2026-09-01) — `GoogleHttpTTSService.run_tts` takes the plain-text branch for any voice whose name contains "chirp", and the class default is `en-US-Chirp3-HD-Charon`, so `pitch`, `rate`, `volume`, `emphasis` and `gender` do nothing out of the box. Chirp 3 HD accepts SSML on the synchronous endpoint. — *Needs a call: Chirp 3 HD rejects `interpret-as="expletive"`/`"bleep"` and Journey voices are untested, so removing the branch needs a stance on which voices keep the plain-text path.*
- **`custom_pronunciations`** (medium, since 2026-09-01) — Cloud TTS takes IPA/X-SAMPA pronunciation overrides on `SynthesisInput` and `StreamingSynthesizeConfig`; neither class exposes them, and they are the standard fix for brand and person names. — *Needs a call: the field is a nested proto (phrase, phonetic_encoding, pronunciation), so a Settings field needs a shape — a list of dicts converted in the request builder, or the proto exposed directly?*
- **`markup` input and `advanced_voice_options`** (low, since 2026-09-01) — both Cloud TTS classes always send text input. `markup` carries Chirp 3 pause tags and Gemini structured markup; `advanced_voice_options` carries `enable_textnorm`, `relax_safety_filters` and `safety_settings`, and the top-level `relax_safety_filters` is now deprecated in its favour. — *Needs a call: pause control and custom pronunciations are Preview on Chirp 3 HD and relaxed safety filters require a monthly-invoiced billing account — is a Settings field worth it for gated features?*
- **Hard-coded voice list is far behind the Voices API** (low, since 2026-10-12) — `AVAILABLE_VOICES` holds the 30 prebuilt names; the Extended Voice Library is served from `GET /v1beta/voices`, and voice remixing mints more `voice_...` IDs. Anything else logs "not in known voices list", and the custom-ID exemption only matches `voice_`, so the documented stateless `voicekey_...` IDs warn too. The voice is still sent either way. — *Needs a call: drop the list in favour of the Voices API, or just relax the warning?*
- **Gemini API audio format** (low, since 2026-10-12) — `response_format.mime_type` (wav/l16/mulaw/alaw) and `sample_rate` (8/16/24 kHz) live on the dedicated `interactions` endpoint; the service streams `generate_content_stream` at 24 kHz and resamples, so telephony pays for a resample it could avoid. — *Needs a call: is a second GenAI request path worth 8 kHz mulaw?*
- **Docs page contradicts the shipped default** (low, since 2026-11-09) — the settings table on docs.pipecat.ai now gives both per-backend defaults, but the Notes below still call `gemini-3.1-flash-tts-preview` the default on both and repeat the superseded November 17 date. — *Needs a call: who fixes the Notes section in the docs repo?*
- **Runtime google-genai floor is below the extra's pin** (low, since 2026-11-23) — `_check_genai_model_supported` errors when `genai.types.SpeechMetadata` is missing (google-genai 2.25.0), and the extra now pins `>=3.2.0,<4`, so nobody installing `pipecat-ai[google]` can reach it. — *Needs a call: keep the guard for users who pin google-genai themselves, or drop it?*

Dropped since the last report: the retiring-default item (PR #6643 merged on 2026-11-09, the default is now per backend) and the google-genai 3.0.0 pin item (the extra moved to `google-genai>=3.2.0,<4`, and the lock resolves 3.2.0 on every leg).
