# Google TTS — 2026-10-12

Google made Gemini 3.8 Flash TTS and Flash-Lite TTS GA on the Gemini API and called Flash-Lite the replacement for our default `gemini-3.1-flash-tts-preview` — but Cloud Text-to-Speech still has no 3.8 model, so bumping the shared default would break the GCP backend. All three classes synthesize; no PR this run.

## What's new for Pipecat

### PRs
Nothing.

Gemini 3.8 TTS support landed in-tree since the last run (`4953582c7`, `f6dea6001`, `a4bcf91cd`): the GenAI path sends `prompt` as `speech_metadata.style`, strips the WAV header 3.8 returns, and reports an error at start when google-genai is older than 2.25.0. That closes the `prompt` half of the previous run's GenAI gap and makes the class docstring and `examples/voice/voice-google-gemini.py` current.

### To consider
- **Default is a preview model with a GA successor on one backend only** (high, since 2026-09-01) — Google's 2026-09-22 changelog makes `gemini-3.8-flash-tts` and `gemini-3.8-flash-lite-tts` GA and says Flash-Lite TTS "is meant to replace `gemini-3.1-flash-tts-preview` for high-throughput and real-time use"; the Cloud TTS Gemini page says the 3.8 models "aren't available through the Cloud Text-to-Speech API". On the GenAI backend Flash-Lite is roughly twice as fast (TTFB 411 ms against 845 ms, medians of 5), and the current default returned no audio on 1 of 10 runs. The Cloud TTS path still has only the same preview 3.x, with GA `gemini-2.5-flash-tts` as its fallback. — *Needs a call: one default cannot be right for both backends — should `GeminiTTSService` choose from `use_genai`, or stay on a name both accept?*
- **GenAI backend drops `multi_speaker`** (medium, since 2026-09-01) — `_warn_unsupported_genai_settings` still warns it away and `_run_genai_tts` never sets it, but a two-speaker request through the pinned SDK (`SpeechConfig.multi_speaker_voice_config` plus per-part `SpeechMetadata(speaker=...)`) synthesized 155874 bytes on `gemini-3.8-flash-tts`. The API allows two speakers per request, prebuilt voices only. — *Needs a call: `speaker_configs` is `{speaker_alias, speaker_id}` over one undivided string, so the mapping needs a way to say which text each speaker speaks — what shape should the setting take?*
- **Chirp voices never get SSML** (medium, since 2026-09-01) — `GoogleHttpTTSService.run_tts` takes the plain-text branch for any voice whose name contains "chirp", and the class default is `en-US-Chirp3-HD-Charon`, so `pitch`, `rate`, `volume`, `emphasis` and `gender` do nothing out of the box. Chirp 3 HD accepts SSML on the synchronous endpoint. — *Needs a call: Chirp 3 HD rejects `interpret-as="expletive"`/`"bleep"` and Journey voices are untested, so removing the branch needs a stance on which voices keep the plain-text path.*
- **`custom_pronunciations`** (medium, since 2026-09-01) — Cloud TTS takes IPA/X-SAMPA pronunciation overrides on `SynthesisInput` and `StreamingSynthesizeConfig`; neither class exposes them, and they are the standard fix for brand and person names. — *Needs a call: the field is a nested proto (phrase, phonetic_encoding, pronunciation), so a Settings field needs a shape — a list of dicts converted in the request builder, or the proto exposed directly?*
- **`markup` input and `advanced_voice_options`** (low, since 2026-09-01) — both Cloud TTS classes always send text input. `markup` carries Chirp 3 pause tags and Gemini structured markup; `advanced_voice_options` carries `enable_textnorm`, `relax_safety_filters` and `safety_settings`. — *Needs a call: pause control and custom pronunciations are Preview on Chirp 3 HD and relaxed safety filters require a monthly-invoiced billing account — is a Settings field worth it for gated features?*
- **Hard-coded voice list is far behind the Voices API** (low, since 2026-10-12) — `AVAILABLE_VOICES` holds the 30 classic names; `client.voices.list()` paged past 300 `prebuilt` entries with locale-scoped IDs. Anything else logs "not in known voices list", and the custom-ID exemption only matches `voice_`, so the documented stateless `voicekey_...` IDs warn too. The voice is still sent either way. — *Needs a call: drop the list in favour of the Voices API, or just relax the warning?*
- **Gemini API audio format and sample rate** (low, since 2026-10-12) — the speech-generation reference documents `response_format.mime_type` (wav/l16/mulaw/alaw) and `sample_rate` (8/16/24 kHz); the class is fixed at 24 kHz PCM and those knobs are on Google's dedicated TTS surface, not the `generate_content` config the service uses. — *Needs a call: is a second GenAI request path worth 8 kHz mulaw for telephony?*
- **Pipecat docs page is stale** (low, since 2026-10-12) — it lists no 3.8 TTS model and still says the GenAI backend does not support `prompt`. — *Needs a call: the page lives in the docs repo — open a docs issue?*
