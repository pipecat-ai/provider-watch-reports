# Google Gemini Live STT — 2026-11-23

`gemini-3.5-transcribe-live` is still the only live transcription model Google documents, and it works. The google-genai pin gap from last run is closed. The new finding is that `mode="SMART"`, which Pipecat already ships, returns a cumulative transcript the service pushes as if it were a per-turn final.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **SMART mode returns cumulative transcripts** (high, since 2026-11-23) — two utterances through one session, same clip split at the sentence boundary: in the default VERBATIM mode the finals were `The quick brown fox jumps over the lazy dog.` then `Hippocrat makes voice agents easy to build.`; with `mode="SMART"` they were `The quick brown fox jumps over the lazy dog.` then `The quick brown fox jumps over the lazy dog. Hippocud makes voice agents easy to build.` Google's Live transcription page states `input_transcription.text` "returns the entire cumulative session transcript so far on each turn rather than a per-segment delta" and that voice editing is enabled by default in SMART mode. `_handle_input_transcription` pushes each one as `TranscriptionFrame(..., finalized=True)`, so a context aggregator appends the whole conversation again every turn. The `mode` setting shipped in #6129, so this affects users today. — *Needs a call: diff SMART finals against what was already pushed, push a replacing frame, or document `mode="SMART"` as unsuitable for conversational pipelines?*
- **10-minute session cap** (high, since 2026-09-01) — Google still caps live transcription at 10 minutes per session. `_receive_handler` sees the close as an exception: it logs a warning, pushes an ErrorFrame, and reopens, so any call longer than 10 minutes gets a spurious error and a transcript gap. `go_away` and `session_resumption_update` are both dropped by `_handle_server_message`, and `_build_live_config` sets no `session_resumption`. `GeminiLiveLLMService` already does all of this. — *Needs a call: reuse the LLM service's session-resumption handling, or just stop reporting an expected expiry as an error?*
- **`custom_vocabulary`** (medium, since 2026-09-01) — the biasing field the Live transcription docs document (up to 1000 terms, best under ~100) has no Settings field; `_build_live_config` sends `adaptation_phrases`, which google-genai 3.2.0 still marks deprecated. Both fields still exist, so this is not urgent, but Pipecat would end up with two names for one wire parameter. — *Needs a call: rename `adaptation_phrases` with a deprecation, add `custom_vocabulary` alongside it, or keep the Settings name and send `custom_vocabulary` on the wire?*
- **Deprecated language config** (low, since 2026-09-01) — `_build_live_config` sends `LanguageHints(...)` and `LanguageAuto()`; google-genai 3.2.0 still carries both with "will be removed in a future version". — *Needs a call: `language_auto=False` (disable auto-detection without hints) has no equivalent under `language_codes`, so the migration drops a documented Settings behavior.*
- **Voice editing (`source_text`)** (low, since 2026-11-23) — Google shipped voice-driven editing for `gemini-3.5-transcribe` and `gemini-3.5-transcribe-live` on 2026-11-17; `AudioTranscriptionConfig.source_text` carries up to 64 KiB of text the speaker revises by voice, SMART mode only. It is a one-field pass-through on paper, but it is inseparable from `mode="SMART"` and so from the cumulative-transcript item above. — *Needs a call: does dictation-style voice editing belong in a conversational STT service?*

Last run's google-genai 3.0.0 gap is closed: the google extra now pins `google-genai>=3.2.0,<4` (commit c1bffe0d8) and `gemini_api_http_options` sets `api_version` to v1beta for Gemini Developer API clients (commit f99c81809), so the Live endpoint did not move when the pin rose.
