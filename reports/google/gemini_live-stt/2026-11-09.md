# Google Gemini Live STT — 2026-11-09

`gemini-3.5-transcribe-live` is still the only live transcription model Google documents, and it works. The transcription `mode` PR merged. The new item is google-genai 3.0.0, which lands outside our pin and would move the Live websocket from v1beta to v1.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **10-minute session cap** (high, since 2026-09-01) — Google still caps live transcription at 10 minutes per session. `_receive_handler` sees the close as an exception: it logs a warning, pushes an ErrorFrame, and reopens, so any call longer than 10 minutes gets a spurious error and a transcript gap. `go_away` and `session_resumption_update` are both dropped by `_handle_server_message`, and `_build_live_config` sets no `session_resumption`. `GeminiLiveLLMService` already does all of this. — *Needs a call: reuse the LLM service's session-resumption handling, or just stop reporting an expected expiry as an error?*
- **`custom_vocabulary`** (medium, since 2026-09-01) — the biasing field the Live transcription docs document (up to 1000 terms, best under ~100) has no Settings field; `_build_live_config` sends `adaptation_phrases`, which google-genai 3.0.0 still marks deprecated. Both fields still exist in 3.0.0, so this is not urgent, but Pipecat would end up with two names for one wire parameter. — *Needs a call: rename `adaptation_phrases` with a deprecation, add `custom_vocabulary` alongside it, or keep the Settings name and send `custom_vocabulary` on the wire?*
- **google-genai 3.0.0 outside the pin** (medium, since 2026-11-09) — released 2026-11-06; the google extra pins `>=2.25.0,<3` (with the `>=1.68.0,<3` fallback on Python 3.13 + Linux) and the lock resolves 2.34.0. Two breaking changes matter here: the Gemini Developer API now defaults to `v1` instead of `v1beta`, and httpx2 replaces httpx. `AsyncLive.connect()` builds the `BidiGenerateContent` websocket URI from the client's `api_version`, and `update_google_client_http_options` never sets one, so raising the pin would move this service's Live endpoint without any code change. 3.0.0 keeps every `AudioTranscriptionConfig` field we use and adds `source_text` (SMART-mode voice editing of a supplied text — not a conversational-STT knob). — *Needs a call: the pin is shared by every Google service, so bumping it to `<4` is a cross-service decision, and it should come with a stance on pinning `api_version` explicitly for Live.*
- **Deprecated language config** (low, since 2026-09-01) — `_build_live_config` sends `LanguageHints(...)` and `LanguageAuto()`; google-genai 3.0.0 still carries both with "will be removed in a future version", so the major release passed without removing them. — *Needs a call: `language_auto=False` (disable auto-detection without hints) has no equivalent under `language_codes`, so the migration drops a documented Settings behavior.*
