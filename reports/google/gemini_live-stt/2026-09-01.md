# Google Gemini Live STT — 2026-09-01

`gemini-3.5-transcribe-live` is the right default and works; the gaps are the unhandled 10-minute session cap and two transcription parameters Settings cannot express. No branch — every item needs a maintainer call.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **10-minute session cap** (high, since 2026-09-01) — Google caps live transcription at 10 minutes per session. `_receive_handler` sees the close as an exception: it logs a warning, pushes an ErrorFrame, and reopens, so any call longer than 10 minutes gets a spurious error and a transcript gap. `go_away` (which carries `time_left`) and `session_resumption_update` are both dropped by `_handle_server_message`, and `_build_live_config` sets no `session_resumption`. `GeminiLiveLLMService` already does all of this. — *Needs a call: reuse the LLM service's session-resumption handling, or just stop reporting an expected expiry as an error?*
- **`custom_vocabulary`** (medium, since 2026-09-01) — the documented Live API biasing field (up to 1000 terms) has no Settings field; the service sends `adaptation_phrases`, which google-genai marks deprecated. Both still work: with either set to `["Pipecat"]` the clip transcribed as "Pipecat makes voice agents easy to build" instead of "Pippa could make voice agent easy to build". `custom_vocabulary` needs google-genai >= 2.15.0. — *Needs a call: rename the Settings field with a deprecation or add `custom_vocabulary` alongside, and whether the google-genai floor can move to 2.15.0 given the vonage/pydantic conflict recorded in `pyproject.toml`.*
- **Transcription `mode`** (medium, since 2026-09-01) — `AudioTranscriptionConfig.mode` selects `VERBATIM` (default) or `SMART`, which strips disfluencies and formats the text. Verified accepted by `gemini-3.5-transcribe-live`. The field only exists in google-genai >= 2.20.0, while the class enforces 2.9.0 and the lock resolves 2.18.1 (2.8.0 on Python 3.13 + Linux). — *Needs a call: raise the google-genai floor to 2.20.0, or set the field only when the installed SDK has it?*
- **Deprecated language config** (low, since 2026-09-01) — `_build_live_config` sends `LanguageHints(...)` and `LanguageAuto()`, both of which google-genai documents as "will be removed in a future version" in favour of top-level `language_codes`. `language_codes` has existed since 2.9.0 — the floor the class already enforces — and the live model accepts it. Removal would come in google-genai 3.x, outside the `<3` pin. — *Needs a call: `language_auto=False` (disable auto-detection without hints) has no equivalent under `language_codes`, so the migration drops a documented Settings behavior.*
