# Google LLM — 2026-10-12

The 2.5 models went access-restricted on 2026-09-18 (prior users only), which turns the examples' `gemini-2.5-flash` pin from hygiene into a first-run failure for anyone with a new Google API key; a branch moves the six text examples to the service default. `gemini-3.6-flash` stays the default: 3.8 Flash has no aiewf-eval row and, unlike last run, now probes about twice as slow.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6131 — Use gemini-3.6-flash in the Google LLM examples

### To consider
- **voice-google-image.py pins gemini-2.5-flash-image** (high, since 2026-10-12) — same access restriction as the text examples, so a new key cannot run it, but there is no drop-in replacement: `gemini-nano-banana-2.1` went GA on 2026-10-06, `gemini-3.1-flash-image` was deprecated the same day, and the file already carries `gemini-3-pro-image-preview` as a commented-out "more powerful but slower" option. — *Needs a call: which image-output model should the example pin?*
- **gemini-3.8-flash as the default** (medium, since 2026-09-14) — still Google's New Stable Flash, with 3.6 Flash described as previous-generation, and 3.7 Flash now deprecated and routed to 3.8 (2026-10-08). Both of the bump's conditions fail today: aiewf-eval's medium-context leaderboard has no 3.8 Flash row (3.6 Flash minimal: 97.1% / 798 ms P50), and the latency win from last run has gone away — 3.8 is now ~2x slower at the median on both a trivial and a reasoning prompt, with `thinking_ms` 0 and its first chunk arriving whole, i.e. unreported server-side work rather than visible thinking. — *Needs a call: nothing, while both signals point the same way; re-check when aiewf-eval scores 3.8 Flash.*
- **Deprecated sampling parameters** (medium, since 2026-08-25) — Google's migration checklist says to remove `temperature`, `top_p` and `top_k` on Gemini 3.x and lists `candidate_count` as unsupported; the API accepts and ignores them, so a user tuning temperature on a Gemini 3 model gets silence from both the API and Pipecat. — *Needs a call: a per-model warning like `_warn_if_thinking_budget_ignored`, or just a docstring deprecation on the Settings fields?*
- **Interactions API** (low, since 2026-08-25) — Google's primary interface since GA on 2026-06-22; `generateContent` remains supported and still receives mainline models, but the guide points multi-turn at server-side `previous_interaction_id` and away from prefilled model turns. — *Needs a call: whether Pipecat tracks the Interactions API at all, and when.*
- **`media_resolution` Settings field** (low, since 2026-08-25) — documented for Gemini 3 vision/document input and already exposed on `GeminiLiveLLMService`; on `GoogleLLMService` only `extra` reaches it. — *Needs a call: does a dedicated field earn its place when `extra` covers it, and does a top-level field suffice when Gemini 3 also takes per-part resolutions?*

Closed since last run: the `gemini-3.8-flash` minimal-thinking-level failure, fixed by pipecat-ai/pipecat#5741 (merged 2026-09-14). Checked and not a gap: `gemini-3.7-flash` was deprecated on 2026-10-08 and routes to 3.8, and the `"gemini-3.7-flash": "low"` entry in `_LOWEST_MODEL_THINKING_LEVELS` keeps such requests valid; `gemini-3.5-flash` was deprecated the same day and routes to 3.6, which the service already treats correctly; thought signatures, the other Gemini 3 migration requirement, are handled in `gemini_adapter.py`.
