# Google LLM — 2026-08-25

`gemini-3.6-flash` should stay the default: `gemini-3.7-flash` is GA and positioned as its successor, but it was slower to first token in every probe. Nothing is broken; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **gemini-3.7-flash as the default** (medium, since 2026-08-25) — GA on 2026-08-13 and Google's flagship workhorse Flash model; Pipecat already carries its `"low"` thinking floor. But TTFAT measured 1487 / 14094 / 2631 ms against 1375 / 887 / 1282 ms for 3.6 Flash, with no thinking time in either case, so a bump would cost voice turns. — *Needs a call: is the coding/agentic gain worth a slower, much more variable first token, or does the bump wait for launch-period latency to settle?*
- **Deprecated sampling parameters** (medium, since 2026-08-25) — Google deprecated `temperature`, `top_p` and `top_k` on 2026-07-21 for Gemini 3.6+ and calls them unsupported on 3.7 Flash; the API accepts and ignores them today (probed: 200 with `temperature=0.7`, `top_p=0.9` on gemini-3.7-flash) and is expected to reject them in later model generations. `_build_generation_params` still forwards them, so a user tuning temperature on a Gemini 3 model gets silence. — *Needs a call: a per-model warning like `_warn_if_thinking_budget_ignored`, or just a docstring deprecation on the Settings fields?*
- **Interactions API** (low, since 2026-08-25) — GA since 2026-06-22 and now Google's primary interface; `generateContent` remains supported for mainline models but new agentic features (server-side turn state via `previous_interaction_id`) are Interactions-only. — *Needs a call: whether Pipecat tracks the Interactions API at all, and when.*
- **`media_resolution` Settings field** (low, since 2026-08-25) — documented for Gemini 3 vision/document input and already exposed on `GeminiLiveLLMService`; on `GoogleLLMService` it is reachable only through `extra` (probed working). — *Needs a call: does a dedicated field earn its place when `extra` covers it, and does a top-level field suffice when Gemini 3 also takes per-part resolutions?*
- **Examples pin gemini-2.5-flash** (low, since 2026-08-25) — four `examples/voice/voice-google*.py` bots pass `model="gemini-2.5-flash"` while the service defaults to `gemini-3.6-flash`; 2.5 Flash has no announced shutdown date, so this is hygiene. — *Needs a call: should the examples track the service default, or is the older, cheaper model deliberate?*
