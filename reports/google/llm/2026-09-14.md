# Google LLM — 2026-09-14

`gemini-3.8-flash` (GA 2026-09-02) cannot be used through `GoogleLLMService` at all — it rejects the `minimal` thinking level the service applies by default to Gemini 3 Flash models — and the one-line fix is on a branch. The default stays `gemini-3.6-flash`: 3.8 probes faster but aiewf-eval has not scored it.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5741 — Send gemini-3.8-flash the lowest thinking level it accepts

### To consider
- **gemini-3.8-flash as the default** (medium, since 2026-09-14) — GA on 2026-09-02 and labelled New Stable, with 3.7 and 3.6 Flash both re-described as previous-generation. Latency is no longer the obstacle it was for 3.7: with its `low` thinking floor, 3.8 beats the current default at the median on both a trivial and a reasoning prompt. What is missing is quality evidence — aiewf-eval's medium-context leaderboard still has no `gemini-3.8-flash` row, while `gemini-3.6-flash (minimal)` scores 97.1% pass / 798 ms TTFAT P50. — *Needs a call: hold until aiewf-eval scores 3.8 Flash at or above 3.6, or is Google's positioning plus the latency win enough without a quality number?*
- **Deprecated sampling parameters** (medium, since 2026-08-25) — Google's migration guidance says to strip `temperature`, `top_p` and `top_k` from generation configs on Gemini 3.x (and lists `candidate_count` as unsupported); the API accepts and ignores them today (probed: 200 with `temperature=0.7`, `top_p=0.9` on gemini-3.8-flash). `_build_generation_params` still forwards them, so a user tuning temperature on a Gemini 3 model gets silence. — *Needs a call: a per-model warning like `_warn_if_thinking_budget_ignored`, or just a docstring deprecation on the Settings fields?*
- **Interactions API** (low, since 2026-08-25) — GA since 2026-06-22 and now Google's primary interface; `generateContent` remains supported and still receives mainline models, but Google points multi-turn conversations at server-side `previous_interaction_id`. — *Needs a call: whether Pipecat tracks the Interactions API at all, and when.*
- **`media_resolution` Settings field** (low, since 2026-08-25) — documented for Gemini 3 vision/document input and already exposed on `GeminiLiveLLMService`; on `GoogleLLMService` it is reachable only through `extra`. — *Needs a call: does a dedicated field earn its place when `extra` covers it, and does a top-level field suffice when Gemini 3 also takes per-part resolutions?*
- **Examples pin gemini-2.5-flash** (low, since 2026-08-25) — three `examples/voice/voice-google*.py` bots pass `model="gemini-2.5-flash"` while the service defaults to `gemini-3.6-flash`; 2.5 Flash has no announced shutdown date, so this is hygiene. — *Needs a call: should the examples track the service default, or is the older, cheaper model deliberate?*

Dropped from the previous report: the `gemini-3.7-flash` default-bump item. Google now describes 3.7 Flash as previous-generation alongside 3.6, so it is no longer the designated successor; the question moves to 3.8 Flash above. The 3.8 Flash migration guide's requirement that `FunctionResponse` carry `call_id` and `name` is already met — the Gemini adapter builds `FunctionResponse(id=..., name=..., response=...)`.
