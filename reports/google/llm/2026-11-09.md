# Google LLM — 2026-11-09

`gemini-3.6-flash` stays the default; the one ready change is the image example, whose `gemini-2.5-flash-image` pin Google now gives a named replacement for. The item to watch is 2026-12-01, when the Gemini 2.5 models route away and the service's 2.5 thinking defaults start travelling to Gemini 3 models.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6641 — Use gemini-3.1-flash-lite-image in the Google image example

### To consider
- **Gemini 2.5 thinking defaults after the 2026-12-01 reroute** (high, since 2026-11-09) — `gemini-2.5-flash` and `gemini-2.5-pro` were deprecated on 2026-11-02 and are served by `gemini-3.5-flash-lite` and `gemini-3.8-flash` from 2026-12-01. `_THINKING_DEFAULTS` keys off the name the caller passes, so those requests keep sending `thinking_budget` 0 / 128 into the Gemini 3 family, which takes `thinking_level`; the service's own warning text says such a budget may be ignored or rejected. Removing the entries today would instead turn thinking on for the three weeks the real 2.5 models are still answering. — *Needs a call: drop the entries on the reroute date, or map the retired names to the successor's `thinking_level`?*
- **gemini-3.8-flash as the default** (medium, since 2026-09-14) — the benchmark condition flipped in 3.8's favour this run: aiewf-eval medium-context now lists `gemini-3.8-flash (low)` at 99.9% pass / 1411 ms TTFAT P50 against `gemini-3.6-flash (minimal)` at 95.1% / 808 ms. Latency did not: my probes put 3.8 at 1616 ms vs 1024 ms on a trivial prompt (median of 5) and 1890 ms vs 960 ms on a reasoning prompt (median of 3), `thinking_ms` 0 throughout, well outside the 10% band, and 3.8 Flash has no level below `low`. — *Needs a call: trade ~600 ms of TTFAT for the benchmark gain, or keep the faster default?*
- **google-genai 3.0.0 is outside our pin** (medium, since 2026-11-09) — released 2026-11-06; the `google` extra pins `<3`. The majors are the Gemini Developer API default moving to `v1` (the `-latest` aliases live only on `v1beta`) and httpx2 becoming the default HTTP client. — *Needs a call: raising the ceiling requires pinning `api_version` or accepting that `gemini-flash-latest` and friends stop resolving, across every Google service on this pin.*
- **Deprecated sampling parameters** (medium, since 2026-08-25) — Google's Gemini 3.8 Flash guide says `temperature`, `top_p` and `top_k` are ignored by the backend; `_build_generation_params` still forwards them, so tuning them on a Gemini 3 model is silent in both directions. `candidate_count`, `frequency_penalty` and `presence_penalty` now hard-error, but the service never sends them. — *Needs a call: a per-model warning like `_warn_if_thinking_budget_ignored`, or just a docstring deprecation on the Settings fields?*
- **Multimodal function responses** (low, since 2026-11-09) — since 2026-11-05 a function response may carry audio, video, Office/OpenDocument content or a file URI; Pipecat's function-call results are text/JSON only. — *Needs a call: does multimodal tool output belong in the universal `LLMContext` result shape first?*
- **`media_resolution` Settings field** (low, since 2026-08-25) — documented for Gemini 3 vision/document input and already exposed on `GeminiLiveLLMService`; here only `extra` reaches it. — *Needs a call: does a dedicated field earn its place when `extra` covers it, and does a top-level field suffice when Gemini 3 also takes per-part resolutions?*

Closed since last run: the six text examples pinned to `gemini-2.5-flash`, fixed by pipecat-ai/pipecat#6131 (merged 2026-10-12). Dropped: the Interactions API gap — Pipecat now ships `GoogleInteractionsLLMService` (and the Vertex variant), tracked as its own `google/interactions-llm` unit, so `GoogleLLMService` staying on `generateContent` is no longer a gap. Checked and not a gap: `gemini-4-argon` went GA on 2026-10-13 and its `_THINKING_DEFAULTS` entry (`low`) matches the documented floor, as does `gemini-3.8-flash`'s; `gemini-4-argon` is a flagship reasoning model, not a Flash successor, so it is not a default candidate; `store` (new in google-genai 2.33.0, and on by default for new paid projects since 2026-10-26) is reachable through `extra`.
