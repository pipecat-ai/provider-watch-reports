# Google Vertex LLM — 2026-09-14

`gemini-3.8-flash` is live on Vertex but unusable through this class — it rejects the `minimal` thinking level, exactly as on the Gemini API — and the shared fix is already on open PR #5741, which I verified against Vertex. The default stays `gemini-3.6-flash`: on Vertex, 3.8 Flash is the slower model.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5741 — Send gemini-3.8-flash the lowest thinking level it accepts (opened this run for `google/llm`; the fix is in the shared `GoogleLLMService`, and probing the branch shows it unblocks Vertex too)

### To consider
- **gemini-3.8-flash as the default** (medium, since 2026-09-14) — GA on Vertex since 2026-09-02 at global, us and eu, and reachable through the class once #5741 lands. Unlike on the Gemini API, where 3.8 beats 3.6 at the median, on Vertex it loses on both prompts: TTFAT 916 ms vs 718 ms (trivial, median of 5) and 1688 ms vs 692 ms (river-crossing, median of 3), with `thinking_ms` 0 throughout. aiewf-eval has no 3.8 Flash row either, while `gemini-3.6-flash (minimal)` scores 97.1% / 798 ms P50. — *Needs a call: Vertex latency rules the bump out today, so should this unit follow `google/llm`'s default whenever that moves, or keep its own literal (`services/google/vertex/llm.py:133`) and its own latency bar?*
- **Express-mode API-key auth** (medium, since 2026-09-01) — Vertex express mode authenticates with an API key and needs no project or location, and `google-genai` builds exactly that client from `Client(vertexai=True, api_key=...)`. `GoogleVertexLLMService` raises `ValueError` on `api_key` and requires `project_id`, so express-mode users have no path in. Unchanged since the last run. — *Needs a call: is the `api_key` guard deliberate protection against confusing this class with `GoogleLLMService`, or should it fall through to express mode when no service-account credentials are supplied?*
- **Vertex AI → Gemini Enterprise Agent Platform** (low, since 2026-09-01) — the class's `Reference:` URL redirects into the Agent Platform docs, the old Vertex pages are frozen, and Vertex's own error payloads now link to `docs.cloud.google.com/gemini-enterprise-agent-platform/...`. Endpoint, model IDs and auth are unchanged. — *Needs a call: refresh the docstring link and docs wording, or leave the "Vertex" naming until Google retires the endpoint?*
- **`location` docstring overstates global** (low, since 2026-09-14) — the docstring calls global "the only location that serves the Gemini 3 series"; `gemini-3.8-flash` answers at `location="us"` and the us/eu multi-regions list 3.7 and 3.8 Flash. Single regions really are 2.5-only: `gemini-3.6-flash` at `us-central1` still 404s. — *Needs a call: name the us and eu multi-regions in the docstring, or keep the simpler global-only guidance?*

Dropped from the previous report: the `gemini-3.7-flash` default-bump item. Google now describes 3.7 Flash as previous-generation alongside 3.6, so it is no longer a successor candidate; the question moves to 3.8 Flash above.
