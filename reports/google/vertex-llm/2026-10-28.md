# Google Vertex LLM — 2026-10-28

The default bump to `gemini-3.8-flash` landed on main; it costs roughly double the time to first answer token on Vertex and occasionally stalls, so the first item below is the one to read.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **The gemini-3.8-flash default is slow and sometimes stalls on Vertex** (high, since 2026-10-28) — commit `714573d00` (2026-10-20) made it the default. Interleaved medians of 5 on a trivial prompt: TTFAT 1210 ms against 685 ms for `gemini-3.6-flash`, `thinking_ms` 0 for both, and one 3.8 Flash run in five produced no chunk at all and hit the service's 20 s `stream_idle_timeout_secs` (the 2026-10-12 sweep saw the same tail as a 19.8 s outlier). The quality case is now real — aiewf-eval's medium-context leaderboard has `gemini-3.8-flash (low)` at 99.9% / 1411 ms P50 against `gemini-3.6-flash (minimal)` at 95.1% / 808 ms — but the retirement the commit cites is not corroborated anywhere: no Agent Platform release note announces a 2026-11-19 shutdown of 3.6 Flash, and the Gemini API deprecations page still says "No shutdown date announced". `GoogleLLMService` is still on `gemini-3.6-flash`, so the two units now disagree. — *Needs a call: keep 3.8 Flash for the benchmark score and accept the slower, occasionally stalling first token, or go back to 3.6 Flash until Google announces a shutdown date — and should `google/llm` move in step either way?*
- **Express-mode API-key auth** (medium, since 2026-09-01) — Vertex express mode authenticates with an API key and needs no project or location, and `google-genai` builds exactly that client from `Client(vertexai=True, api_key=...)`. `GoogleVertexLLMService` raises `ValueError` on `api_key` and requires `project_id`, so express-mode users have no path in. Code unchanged since the last run. — *Needs a call: is the `api_key` guard deliberate protection against confusing this class with `GoogleLLMService`, or should it fall through to express mode when no service-account credentials are supplied?*
- **No first-tier probe for this unit** (medium, since 2026-10-28) — `probe.py`'s `build_kwargs` now follows `**kwargs` into base classes (commit `23e5228d9`), finds `GoogleLLMService`'s required `api_key`, and passes `GOOGLE_API_KEY`; this subclass raises `ValueError` on it, and with the variable unset the probe exits 2 instead. Every probe below ran through a scratch wrapper that drops that one kwarg. — *Needs a call: should `build_kwargs` skip inherited parameters a subclass rejects, or should a registry entry's `include_params` be the whole list when it has one?*
- **Vertex AI → Gemini Enterprise Agent Platform** (low, since 2026-09-01) — the class's `Reference:` URL redirects into the Agent Platform docs and the old Vertex pages stay frozen behind their banner. Endpoint, model IDs and auth are unchanged. — *Needs a call: refresh the docstring link and docs wording, or leave the "Vertex" naming until Google retires the endpoint?*
- **`location` docstring overstates global** (low, since 2026-09-14) — Google's Gemini 3.8 Flash model table gives the supported regions as Global and Multi-region, Gemini 4 Argon's guide lists global, us and eu, and the default answers at `location="us"` (TTFAT 1194 ms). The docstring still calls global "the only location that serves the Gemini 3 series". — *Needs a call: name the us and eu multi-regions in the docstring, or keep the simpler global-only guidance?*

Closed since the last run: "gemini-3.8-flash supersedes the gemini-3.6-flash default" — the bump shipped in `714573d00`, and what remains of it is the latency question above.

Gemini 4 Argon reached GA on Vertex on 2026-10-13 and answers through this class, but it is a frontier Pro-class model whose guide offers a migration path from `gemini-3.1-pro-preview` and never mentions Flash, so it is not a default candidate. Its `_THINKING_DEFAULTS` entry in `services/google/llm.py` (`thinking_level: low`) matches the guide, which documents LOW, MEDIUM and HIGH and returns 400 for MINIMAL; the probe confirms Vertex accepts it. `gemini-3.8-flash`'s `low` entry is likewise the lowest level its model table documents.
