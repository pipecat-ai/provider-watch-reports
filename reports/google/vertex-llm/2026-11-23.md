# Google Vertex LLM — 2026-11-23

Three GA Gemini 4 models reached Vertex with no reasoning default, so they think at Google's level by default — branch ready; and Hydrogen, Google's designated replacement for the `gemini-3.8-flash` default, is already faster on Vertex but has no aiewf-eval row yet.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6967 — Send the Gemini 4 models their lowest thinking level

### To consider
- **The gemini-3.8-flash default is slow on Vertex** (high, since 2026-10-28) — fourth run running. Interleaved medians of 5, trivial prompt: TTFAT 1523 ms against 598 ms for `gemini-3.6-flash`; reasoning prompt: 1797 ms against 702 ms. `thinking_ms` is 0 in every run. Last run's one-in-five mid-stream stall did not recur — all 20 runs completed. The quality case still favours 3.8 (aiewf-eval medium-context: `gemini-3.8-flash (low)` 99.9% / 1411 ms P50 against `gemini-3.6-flash (minimal)` 95.1% / 808 ms), and the retirement cited by commit `714573d00` still has no source: `gemini-3.6-flash` is "No shutdown date announced". `GoogleLLMService` is still on `gemini-3.6-flash`. — *Needs a call: keep 3.8 Flash for the benchmark score, go back to 3.6 Flash until Google announces a shutdown date, or wait for a `gemini-4-hydrogen` leaderboard row — and should `google/llm` move in step?*
- **gemini-4-hydrogen is the designated successor and already faster** (medium, since 2026-11-23) — GA on Vertex 2026-11-12, its model guide carrying a migration guide "from Gemini 3.8 Flash and earlier Gemini 3 Flash models". At the branch's `thinking_level: low` it beats the current default on Vertex: interleaved medians of 5, TTFAT 965 ms against 1170 ms. aiewf-eval's `leaderboard-medium-context.md` has no row for any `gemini-4` model, so the quality half of a bump can't be checked; the leaderboard gets re-read next run. List price is about double `gemini-3.8-flash`'s 2026 rate. — *Needs a call: nothing until a leaderboard row exists — but is a doubled list price on its own a reason not to make a successor the default?*
- **Express-mode API-key auth** (medium, since 2026-09-01) — Vertex express mode authenticates with an API key and needs no project or location, and `google-genai` builds exactly that client from `Client(vertexai=True, api_key=...)`. `GoogleVertexLLMService` raises `ValueError` on `api_key` and requires `project_id`. Commit `f99c81809` taught `GoogleLLMService` to keep the SDK's Vertex default when `GOOGLE_GENAI_USE_VERTEXAI`/`GOOGLE_GENAI_USE_ENTERPRISE` is set, so express mode is reachable through *that* class via the environment — a workaround, not a path through this one. — *Needs a call: is the `api_key` guard deliberate protection against confusing this class with `GoogleLLMService`, or should it fall through to express mode when no service-account credentials are supplied?*
- **No first-tier probe for this unit** (medium, since 2026-10-28) — `probe.py`'s `build_kwargs` inserts `api_key` because `_init_parameters` follows `**kwargs` into `GoogleLLMService`, and this subclass rejects it; it also looks for `GOOGLE_APPLICATION_CREDENTIALS` (empty in CI) and `GOOGLE_PROJECT_ID`, while CI exports `GOOGLE_VERTEX_TEST_CREDENTIALS` and `GOOGLE_CLOUD_PROJECT_ID`, so the probe exits 2 first. Every probe below ran through a scratch wrapper. — *Needs a call: should `build_kwargs` skip inherited parameters a subclass rejects, and a registry entry's `include_params` be the whole list when it has one — or is a per-unit wrapper the accepted answer?*
- **`thinking_level` Literal lacks `xhigh`** (low, since 2026-11-23) — google-genai 3.3.0 added `XHIGH`, and the Hydrogen and Neon guides list LOW/MEDIUM/HIGH/XHIGH. The `Literal[...] | str` union at `google/llm.py:113` still accepts it, so only the type hint is behind. Shared with `google/llm` and `google/realtime`. — *Needs a call: add `xhigh` as one change across the Gemini services, or let the `| str` escape hatch carry new levels?*
- **Vertex AI docs folded into the Agent Platform** (low, since 2026-09-01) — the class's `Reference:` URL still takes two 301s to land on `docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/inference`. Endpoint, model IDs and auth are unchanged. — *Needs a call: refresh the docstring link and docs wording, or leave the "Vertex" naming until Google retires the endpoint?*
- **`location` docstring overstates global** (low, since 2026-09-14) — the docstring calls global "the only location that serves the Gemini 3 series; the regional endpoints serve the 2.5 series". The `us` multi-region answers (TTFAT 1123 ms), and the 2026-11-09 release note makes `gemini-3.8-flash` GA on the `northamerica-northeast1` and `asia-northeast1` regional endpoints; a probe there returned 404 for the probe project, which the error attributes to model *or* project access. Global remains the right default. — *Needs a call: name the multi-regions and the two single regions, or keep the simpler global-only guidance?*

The Vertex catalogue gained `gemini-4-carbon` (GA 2026-11-10), `gemini-4-hydrogen` (GA 2026-11-12) and `gemini-4-neon` (GA 2026-11-18) since the last run and lost nothing; no Gemini text model is deprecated or scheduled for shutdown. The google-genai pin gap is gone: commit `c1bffe0d8` moved the extra to `google-genai>=3.2.0,<4`, and the latest release, 3.6.1, is inside it.
