# Google Vertex LLM — 2026-09-01

`gemini-3.6-flash` works on Vertex at the default `location="global"` and stays the default; `gemini-3.7-flash` is reachable but slower and unbenchmarked. Nothing is broken; no branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **gemini-3.7-flash as the default** (medium, since 2026-09-01) — GA on 2026-08-13, listed and served at Vertex's global endpoint, and the class reaches it with no code change. But TTFAT was 4134 ms against 723 ms for `gemini-3.6-flash` in the same probe call, and aiewf-eval's medium-context leaderboard has no row for it, while `gemini-3.6-flash (minimal)` scores 97.1% / 798 ms P50. This mirrors the open item on `google/llm`; the two defaults are separate literals (`services/google/llm.py:270` and `services/google/vertex/llm.py:133`). — *Needs a call: wait for an aiewf-eval row for 3.7 Flash, or bump both services together once one exists?*
- **Express-mode API-key auth** (medium, since 2026-09-01) — Vertex express mode authenticates with an API key and needs no project or location; the installed `google-genai` builds exactly that client from `Client(vertexai=True, api_key=...)`. `GoogleVertexLLMService` raises `ValueError` on `api_key` and requires `project_id`, so express-mode users have no path in. — *Needs a call: is the `api_key` guard deliberate protection against confusing this class with `GoogleLLMService`, or should it fall through to express mode when no service-account credentials are supplied?*
- **Vertex AI → Gemini Enterprise Agent Platform** (low, since 2026-09-01) — Google folded Vertex AI into the Agent Platform and froze the old docs; the class's `Reference:` URL now redirects twice, and Vertex's own 404 payload points at `docs.cloud.google.com/gemini-enterprise-agent-platform/...`. Endpoint, model IDs and auth are unchanged. — *Needs a call: refresh the docstring link and docs wording, or leave the "Vertex" naming until Google retires the endpoint?*
