# Google Vertex LLM — 2026-11-09

Nothing new shipped on Vertex that this service needs, but the `gemini-3.8-flash` default is measurably worse on Vertex for the third run running — and this time it also failed a probe outright.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **The gemini-3.8-flash default is slow and sometimes never completes on Vertex** (high, since 2026-10-28) — interleaved medians of 5. Trivial prompt: TTFAT 1365 ms against 611 ms for `gemini-3.6-flash`. Reasoning prompt: 2782 ms (4/5 runs) against 724 ms (5/5), and the fifth 3.8 Flash run stopped mid-stream and tripped the service's 20 s `stream_idle_timeout_secs`, pushing `LLM completion timeout`. `thinking_ms` is 0 in every run, so reasoning time is not the explanation. The quality case still favours 3.8 — aiewf-eval medium-context: `gemini-3.8-flash (low)` 99.9% / 1411 ms P50 against `gemini-3.6-flash (minimal)` 95.1% / 808 ms — but the retirement commit `714573d00` cited still has no source: the deprecations page says `gemini-3.6-flash` has "No shutdown date announced", and no Agent Platform release note through 2026-11-06 retires a Gemini text model. `gemini-3.7-flash` is not a middle road: its leaderboard row matches 3.8 at 821 ms P50 but on Vertex it answers in 1270 ms (median of 3). `GoogleLLMService` is still on `gemini-3.6-flash`. — *Needs a call: keep 3.8 Flash for the benchmark score and accept first tokens that are several times slower and occasionally never arrive, or go back to 3.6 Flash until Google announces a shutdown date — and should `google/llm` move in step either way?*
- **google-genai 3.0.0 is outside our pin** (medium, since 2026-11-09) — released 2026-11-06; both `pyproject.toml` entries cap at `<3`. The release's headline break, the Gemini Developer API moving from `v1beta` to `v1` by default, explicitly spares Vertex clients; what the major costs here is `httpx2` becoming the default and required HTTP client (plain `httpx` moves behind an extra, SSL trust moves from `certifi` to the OS store). The blocker on moving the pin lives in `google/realtime`, whose deprecated `generation_config` wrapper has to go first. — *Needs a call: raise the cap to `<4` as one coordinated change across the Google services once the Live wrapper is migrated, or wait for a 3.0.x bugfix line?*
- **Express-mode API-key auth** (medium, since 2026-09-01) — Vertex express mode authenticates with an API key and needs no project or location, and `google-genai` builds exactly that client from `Client(vertexai=True, api_key=...)`. `GoogleVertexLLMService` raises `ValueError` on `api_key` and requires `project_id`, so express-mode users have no path in. Code unchanged since the last run. — *Needs a call: is the `api_key` guard deliberate protection against confusing this class with `GoogleLLMService`, or should it fall through to express mode when no service-account credentials are supplied?*
- **No first-tier probe for this unit** (medium, since 2026-10-28) — `probe.py`'s `build_kwargs` inserts `api_key` because `_init_parameters` follows `**kwargs` into `GoogleLLMService`, and this subclass rejects it; with `GOOGLE_API_KEY` unset the probe exits 2 instead. On top of that it looks for `GOOGLE_APPLICATION_CREDENTIALS` and `GOOGLE_PROJECT_ID`, while CI exports `GOOGLE_VERTEX_TEST_CREDENTIALS` and `GOOGLE_CLOUD_PROJECT_ID`. Every probe below ran through a scratch wrapper that drops the one kwarg and bridges the two names. — *Needs a call: should `build_kwargs` skip inherited parameters a subclass rejects, and a registry entry's `include_params` be the whole list when it has one — or is a per-unit wrapper the accepted answer?*
- **Vertex AI docs folded into the Agent Platform** (low, since 2026-09-01) — the class's `Reference:` URL now takes two 301s to land on `docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/inference`. Endpoint, model IDs and auth are unchanged. — *Needs a call: refresh the docstring link and docs wording, or leave the "Vertex" naming until Google retires the endpoint?*
- **`location` docstring overstates global** (low, since 2026-09-14) — Google's Gemini 3.8 Flash guide gives the supported regions as Global and Multi-region, and the default answers at `location="us"` (TTFAT 1013 ms). The docstring still calls global "the only location that serves the Gemini 3 series". — *Needs a call: name the us and eu multi-regions in the docstring, or keep the simpler global-only guidance?*

The Vertex catalogue gained `gemini-3.8-flash-tts`, `gemini-3.8-flash-lite-tts` (both GA 2026-10-26) and `gemini-omni-1.2-flash` (GA 2026-11-05) since the last run, and lost nothing; none is a text model this service would run. `_THINKING_DEFAULTS` needs no change: every reasoning text model Vertex serves has an entry, and `gemini-3.8-flash`'s `thinking_level: low` is still the lowest its model guide documents — `MINIMAL` returns a validation error.
