# Google Image — 2026-11-09

No breakage: the service generates images through `generate_content` as it stands. The open call is unchanged from last run — the default is deprecated and its named successor is slower, now by more than before — and google-genai has gone 3.0.0, outside our pin.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Default model deprecated** (high, since 2026-10-12) — Google deprecated `gemini-3.1-flash-image` on 2026-10-06 in favour of `gemini-nano-banana-2.1`, with no shutdown date; the deprecations page still names 2.1 as its replacement and the image-generation guide still tells new projects to use 2.1. The successor needs no code change, but today's re-probe puts it at 11.3 s median against 8.4 s for the current default over three interleaved rounds — wider than the ~20% measured on 2026-10-12, and well past the 10% bar an automatic bump has to clear. `gemini-3.1-flash-lite-image` remains undeprecated and is the fastest option, at lower quality and without multi-reference or grounding support. — *Needs a call: whether a ~35% slower generation is an acceptable price for moving off a deprecated default, or whether the much faster lite model is the better target for a still-frame bot.*
- **google-genai 3.0.0 outside the pin** (medium, since 2026-11-09) — 3.0.0 shipped on 2026-11-06; `pyproject.toml` pins `>=2.25.0,<3` and `>=1.68.0,<3`, so users cannot install it alongside the google extra. Nothing in the release notes touches image generation or `ImageConfig`; the breaking changes are shared — Gemini Developer API clients default to `v1` instead of `v1beta` (so `gemini-*-latest` aliases need `v1beta` or a pinned version) and `httpx2` replaces `httpx` as the default HTTP client. — *Needs a call: raising the pin affects every google service, so it is one decision taken across the provider, not in this unit.*
- **Remaining image controls not exposed** (low, since 2026-09-01) — `GoogleImageGenSettings` covers `aspect_ratio` and `image_size` (the latter merged in #6130). `types.ImageConfig` still has `person_generation`, `prominent_people`, `output_mime_type` and `output_compression_quality` with no counterpart, and the docs describe a `thinking_level` and Google Search grounding for image models — both expressible on `generate_content` via `thinking_config` and `tools` — that the service never sends. — *Needs a call: which of these users actually ask for; the thinking levels differ per model and are billed, so exposing them needs a stance on validation and on models that reject a value.*
- **Interactions is the documented surface** (low, since 2026-11-09) — the image-generation page now shows only `client.interactions.create` / `POST /v1beta/interactions`, with no generateContent tab left. This is positioning, not a retirement: the migration guide states generateContent "remains fully supported" and gives no date, and all six probe calls today went through `generate_content`. What the service cannot reach from where it stands is multi-turn editing via `previous_interaction_id`, video as image context, and `image_search` grounding. — *Needs a call: whether to stay on generate_content or plan a port to interactions, which is a rewrite of `run_image_gen` rather than a settings change.*

Previous run's `image_size` branch is accounted for: https://github.com/pipecat-ai/pipecat/pull/6130 merged on 2026-10-12 and the field is in `GoogleImageGenSettings`, so that gap is closed.
