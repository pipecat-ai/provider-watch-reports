# Google Image — 2026-10-12

The service is working again — the `generate_content` rewrite the last two reports asked for landed in `da1ce606b`, and a live call returns an image. The new question is the new default: Google deprecated `gemini-3.1-flash-image` six days ago, but its named successor probes about 20% slower.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6130 — Add an image_size setting to GoogleImageGenService

### To consider

- **Default model deprecated** (high, since 2026-10-12) — Google's changelog entry for 2026-10-06 ships `gemini-nano-banana-2.1` as GA and says in the same breath that "the `gemini-3.1-flash-image` model is deprecated (no shutdown date announced)", directing developers to migrate. The image-generation guide repeats it: Nano Banana 2.1 is the "primary high-efficiency workhorse" and new projects should use it over Nano Banana 2. The successor needs no code change — it works through the class exactly as it stands, `generate_content` with an `IMAGE` response modality — but it is slower: median wall clock 9.0 s against 7.5 s for the current default, over three interleaved rounds. That is past the 10% bar a default bump has to clear, so the branch above deliberately leaves the default alone. Worth weighing alongside: `gemini-3.1-flash-lite-image` is undeprecated and generated the same prompt in 2.6 s, at lower quality and without multi-reference or grounding support. No shutdown date means nothing is broken today. — *Needs a call: whether a ~20% slower generation is an acceptable price for leaving a deprecated default, or whether the much faster lite model is the better target for a still-frame bot.*
- **Remaining image controls not exposed** (low, since 2026-09-01) — `GoogleImageGenSettings` now covers `aspect_ratio`, and `image_size` is on the branch. `types.ImageConfig` still has `person_generation`, `prominent_people`, `output_mime_type` and `output_compression_quality` with no counterpart, and the image docs describe a `thinking_level` (billed by default) and Google Search grounding for image models that the service never sends. — *Needs a call: which of these users actually ask for; several are model-dependent, so exposing them needs a stance on models that reject the value.*
