# Google Image — 2026-09-01

`GoogleImageGenService` no longer works at all: Google retired the Imagen models on 2026-08-17 and the only replacement path is a different API call, so this needs a maintainer decision, not a default bump.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Imagen is shut down** (high, since 2026-09-01) — `imagen-4.0-generate-001`, the service default, was deprecated 2026-06-15 and shut down 2026-08-17; a live call returns `404 ... is not found for API version v1beta, or is not supported for predict`, and no `imagen-*` id remains in the Gemini API catalogue. Google names `gemini-3.1-flash-image` as the replacement, but it is a `generateContent` model: calling it through `generate_images` 404s the same way, and google-genai now warns that `generate_images` is deprecated (removal not before 2027-01-01). A probe confirms `generate_content(model="gemini-3.1-flash-image", config=GenerateContentConfig(response_modalities=["IMAGE"]))` returns an `inline_data: image/jpeg` part, so the fix is to read image bytes off the response parts instead of `response.generated_images`. — *Needs a call: the new path returns one image per request and has no negative prompt, so `number_of_images` and `negative_prompt` must be dropped, warned about, or emulated; the choice also decides whether `Settings` keeps its current shape.*
- **Image controls not exposed** (low, since 2026-09-01) — `types.ImageConfig` (`aspect_ratio`, `image_size`, `person_generation`, `output_mime_type`) has no counterpart in `GoogleImageGenSettings`. — *Needs a call: contingent on the rewrite above, since the config object differs between the two call paths.*

`probe.py run` does not support `image` units (it exits `EXIT_UNSUPPORTED` for anything outside llm/tts/stt/realtime), so the two calls above were ad-hoc scripts in the scratch dir, one request per row.
