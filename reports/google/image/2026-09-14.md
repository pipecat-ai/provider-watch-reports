## What's new for Pipecat

### To consider

- **Imagen is shut down** (high, since 2026-09-01) — `imagen-4.0-generate-001`, the service default, shut down 2026-08-17. A live call through the class today still yields `ErrorFrame: ... 404 NOT_FOUND ... models/imagen-4.0-generate-001 is not found for API version v1beta, or is not supported for predict`, and the catalogue still holds no `imagen-*` id. Google names `gemini-3.1-flash-image` as the replacement, but it is a `generateContent` model and `generate_images` calls `predict`; google-genai emits its own deprecation warning on `generate_images` pointing at `generate_content`. A probe confirms `generate_content(model="gemini-3.1-flash-image", config=GenerateContentConfig(response_modalities=["IMAGE"]))` returns an `inline_data: image/jpeg` part, so the fix is to read image bytes off the response parts instead of `response.generated_images`. Swapping only the model string would not help — it 404s on the same endpoint. — *Needs a call: the new path returns one image per request and has no negative prompt, so `number_of_images` and `negative_prompt` must be dropped, warned about, or emulated; the choice also decides whether `Settings` keeps its current shape.*
- **Image controls not exposed** (low, since 2026-09-01) — `types.ImageConfig` (`aspect_ratio`, `image_size`, `person_generation`, `prominent_people`, `output_mime_type`, `output_compression_quality`) has no counterpart in `GoogleImageGenSettings`. — *Needs a call: contingent on the rewrite above, since the config object differs between the two call paths.*
