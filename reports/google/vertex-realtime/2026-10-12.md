# Gemini Live Vertex (realtime) — 2026-10-12

The replacement the last two runs were waiting for exists: `gemini-3.8-live` went GA on
Vertex on 2026-09-24, and a branch moves the default onto it before
`gemini-live-2.5-flash-native-audio` retires on 2026-12-13.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6127 — Default GeminiLiveVertexLLMService to gemini-3.8-live

The Live API "Supported models" table now lists `gemini-3.8-live` first, generally
available and "Recommended"; Google published "Migrate from Gemini 2.5 Flash Live API
Native Audio to Gemini 3.8 Live", which names Pipecat as a supported client; and the
publisher catalogue in `us-central1` carries it with `launchStage: GA`. The base
`GeminiLiveLLMService` already defaults to `models/gemini-3.8-live` (#5689, 2026-10-01) and
its 3.x handling — version gates, thinking level, `interaction_status`, tool behavior —
needs nothing new for Vertex.

### To consider

- **`pipecat init` scaffold does not parse, and misuses `credentials`** (high, since
  2026-09-01) — unchanged: the `gemini_vertex_live_realtime` entry in
  `pipecat.cli.registry._configs.SERVICE_CONFIGS` (duplicated in
  `service_metadata.MANUAL_SERVICE_CONFIGS`) closes the constructor call twice, so the
  generated bot file raises `SyntaxError: unmatched ')'` — still the only one of the 101
  entries that fails `compile()`. Dropping the stray `    ),` line and re-indenting fixes
  the syntax; the snippet then still passes
  `credentials=os.getenv("GOOGLE_APPLICATION_CREDENTIALS")`, and `env.example.jinja2`
  documents that variable as `path/to/credentials.json`, so `_get_credentials` would call
  `json.loads` on a path. The keyword wanted is `credentials_path=`. — *Needs a call:
  whether to fix only the parens and the keyword, or also align the CLI's
  `GOOGLE_PROJECT_ID` / `GOOGLE_LOCATION` / `GOOGLE_APPLICATION_CREDENTIALS` (the scaffold
  and its `.env` template agree with each other) with the `GOOGLE_CLOUD_*` names the
  examples and docs use and the registry's `GOOGLE_VERTEX` env prefix.*
- **NON_BLOCKING tool suppression is obsolete on 3.8** (medium, since 2026-10-12) —
  `GeminiLiveVertexLLMService._supports_non_blocking_tools` returns False, added
  2026-05-08 because the 2.5 Vertex endpoint broke on the `behavior` and `scheduling`
  fields. Google's 3.8 migration guide documents both for Vertex, including a table for
  how `scheduling=interrupt` now behaves while the user is speaking, and a probe that
  lifted the override called the tool and spoke the result with no error. The practical
  cost of leaving it: `_tag_tool_behaviors` never runs on Vertex, so a synchronous tool is
  undeclared and takes 3.8's NON_BLOCKING server default, where the Gemini API class
  declares it BLOCKING — and the warning the base class logs for that case is inside the
  code path the override skips. A probe with a 5 s tool handler showed no filler audio
  before the result on either model, so the divergence did not surface in one call. —
  *Needs a call: whether to version-gate the override at 3.8 rather than drop it, and
  whether `scheduling=interrupt`'s changed meaning asks the service to send different
  values.*
- **Refused connections are silent** (medium, since 2026-09-01) — unchanged at
  19fca83d2: `GeminiLiveLLMService._connection_task_handler` awaits
  `client.aio.live.connect()` outside any `try`, so a server refusal surfaces as an
  unhandled-task log line instead of `push_error`, and the pipeline runs on with no
  session. This is why every probe below was read from the session log as well as from the
  probe's verdict. A retired model string — which this service's default becomes on
  2026-12-13 — an unavailable region, or `model=None` from an unset env var all land here.
  — *Needs a call: the fix belongs to the shared base class and needs a stance on which
  connection failures are fatal and whether to retry first.*
- **`history_config` suppression may be obsolete** (low, since 2026-09-01) —
  `_get_history_config()` returns None for Vertex (added 2026-03-27, "unsupported"), while
  the 3.8 migration guide tells Vertex users to set
  `HistoryConfig(initial_history_in_client_content=True)` to seed history with
  `send_client_content`. A Vertex 3.8 session recalled a seeded fact identically with the
  flag forced on and with it off. — *Needs a call: whether the flag helps the audio-input
  history-recall path the base class works around; both checks seeded text, not audio.*
