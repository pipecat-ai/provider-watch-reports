# Gemini Live Vertex (realtime) — 2026-11-23

Nothing to ship: `gemini-3.8-live` is still Vertex's GA "Recommended" live model, last run's
region branch merged, and the google-genai pin has moved onto 3.x. The same five items are
waiting on a maintainer.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`pipecat init` scaffold does not parse, and misuses `credentials`** (high, since
  2026-09-01) — unchanged: the `gemini_vertex_live_realtime` entry in
  `pipecat.cli.registry._configs.SERVICE_CONFIGS` (duplicated in
  `service_metadata.MANUAL_SERVICE_CONFIGS`) closes the constructor call twice, so the
  generated bot file raises `SyntaxError: unmatched ')'` — still the only one of the now
  110 entries that fails `compile()`, while the neighbouring `google_vertex_llm` and
  `google_interactions_vertex_llm` snippets are well formed. Dropping the stray `    ),`
  line and re-indenting fixes the syntax; the snippet then still passes
  `credentials=os.getenv("GOOGLE_APPLICATION_CREDENTIALS")`, and `env.example.jinja2`
  documents that variable as `path/to/credentials.json`, so `_get_credentials` would call
  `json.loads` on a path. The keyword wanted is `credentials_path=`. — *Needs a call:
  whether to fix only the parens and the keyword, or also align the CLI's
  `GOOGLE_PROJECT_ID` / `GOOGLE_LOCATION` / `GOOGLE_APPLICATION_CREDENTIALS` (the scaffold
  and its `.env` template agree with each other) with the `GOOGLE_CLOUD_*` names the
  examples and docs use and the registry's `GOOGLE_VERTEX` env prefix.*
- **NON_BLOCKING tool suppression is obsolete on 3.8** (medium, since 2026-10-12) —
  `_supports_non_blocking_tools` returns False, added 2026-05-08 because the 2.5 Vertex
  endpoint broke on the `behavior` and `scheduling` fields. The migration guide still
  documents both for Vertex 3.8, including the table for how `scheduling=interrupt` now
  waits for the user to finish. So on Vertex `_tag_tool_behaviors` never runs: a
  synchronous tool goes undeclared and takes the server default, where the Gemini API
  class declares it BLOCKING, and the warning the base class logs for that case sits
  inside the skipped path. — *Needs a call: whether to version-gate the override at 3.8
  rather than drop it, and whether `scheduling=interrupt`'s changed meaning asks the
  service to send different values.*
- **Live avatars are out of reach** (medium, since 2026-10-28) — Vertex's "Configure live
  avatars" page drives `gemini-3.8-live` with `response_modalities=["VIDEO"]` and
  `avatar_config=types.AvatarConfig(avatar_name=...)` (plus a per-session
  `customized_avatar` for allowlisted customers), and the Live API overview still lists
  "Live avatar" among 3.8's features with mp4 as an output modality. The affordance is
  Vertex-only — the Gemini Developer API's Live guide mentions avatars nowhere — and the
  installed google-genai has `AvatarConfig` and `LiveConnectConfig.avatar_config`. Pipecat
  cannot ask for it: `GeminiModalities` has only `TEXT` and `AUDIO`. — *Needs a call:
  whether a realtime LLM service should emit video at all; prebuilt avatars would still
  mean carrying mp4 through the pipeline, and custom avatars are allowlisted per customer.*
- **Custom voices are out of reach** (low, since 2026-11-09) — "Configure language and
  voice" documents a per-session replicated voice: `voice_config.replicated_voice_config`
  with a 10–20 s `audio/pcm;rate=24000` sample, nothing to upload or train in advance, and
  it pairs with the avatars above. `_connect` always builds
  `VoiceConfig(prebuilt_voice_config=PrebuiltVoiceConfig(voice_name=...))`, so only the 30
  prebuilt names are reachable, and `Settings.extra` is not read when the Live config is
  assembled, so there is no escape hatch either. — *Needs a call: a voice sample is bytes
  rather than a string, so exposing it needs a stance on how audio reaches a setting;
  Google also limits the feature to customers it allowlists.*
- **`history_config` suppression may be obsolete** (low, since 2026-09-01) —
  `_get_history_config()` returns None for Vertex (added 2026-03-27, "unsupported"), while
  the 3.8 migration guide still tells Vertex users to set
  `initial_history_in_client_content=True` to seed history with `send_client_content`. The
  2026-10-12 Vertex 3.8 session recalled a seeded fact identically with the flag forced on
  and with it off. — *Needs a call: whether the flag helps the audio-input history-recall
  path the base class works around; both checks seeded text, not audio.*

now names `us-central1` and warns that Live models reach a narrower set of regions than the
other Gemini models.

Also settled since last run: the google-genai pin moved to `>=3.2.0,<4` (commit c1bffe0d8),
so the SDK note the last report carried is gone — latest 3.6.1 is inside the pin, and
3.4.0's "resolve Vertex Live connect auth off the event loop" fix is reachable by upgrading.

environment makes google-genai build a Vertex client (commit f99c81809), since Vertex serves
no `v1beta`.
