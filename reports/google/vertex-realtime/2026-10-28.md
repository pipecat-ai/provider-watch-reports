# Gemini Live Vertex (realtime) — 2026-10-28

Nothing to ship: #6127 merged, so the service defaults to `gemini-3.8-live`, which Vertex
still lists as the GA "Recommended" live model and now dates to retire no sooner than
2027-09-25.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **`pipecat init` scaffold does not parse, and misuses `credentials`** (high, since
  2026-09-01) — unchanged: the `gemini_vertex_live_realtime` entry in
  `pipecat.cli.registry._configs.SERVICE_CONFIGS` (duplicated in
  `service_metadata.MANUAL_SERVICE_CONFIGS`) closes the constructor call twice, so the
  generated bot file raises `SyntaxError: unmatched ')'` — still the only one of the 104
  entries that fails `compile()`. Dropping the stray `    ),` line and re-indenting fixes
  the syntax; the snippet then still passes
  `credentials=os.getenv("GOOGLE_APPLICATION_CREDENTIALS")`, and `env.example.jinja2`
  documents that variable as `path/to/credentials.json`, so `_get_credentials` would call
  `json.loads` on a path. The keyword wanted is `credentials_path=`. — *Needs a call:
  whether to fix only the parens and the keyword, or also align the CLI's
  `GOOGLE_PROJECT_ID` / `GOOGLE_LOCATION` / `GOOGLE_APPLICATION_CREDENTIALS` (the scaffold
  and its `.env` template agree with each other) with the `GOOGLE_CLOUD_*` names the
  examples and docs use and the registry's `GOOGLE_VERTEX` env prefix.*
- **NON_BLOCKING tool suppression is obsolete on 3.8** (medium, since 2026-10-12) —
  `_supports_non_blocking_tools` returns False, added 2026-05-08 because the 2.5 Vertex
  endpoint broke on the `behavior` and `scheduling` fields. The migration guide still
  documents both for Vertex 3.8, including the table for how `scheduling=interrupt` now
  waits for the user to finish, and the Vertex asynchronous-function-calling page now
  states that asynchronous calling is enabled at the model level. So on Vertex
  `_tag_tool_behaviors` never runs: a synchronous tool goes undeclared and takes the
  server default, where the Gemini API class declares it BLOCKING, and the warning the
  base class logs for that case sits inside the skipped path. — *Needs a call: whether to
  version-gate the override at 3.8 rather than drop it, and whether `scheduling=interrupt`'s
  changed meaning asks the service to send different values.*
- **Refused connections are silent** (medium, since 2026-09-01) — unchanged at 9d03e5b42:
  `GeminiLiveLLMService._connection_task_handler` enters `client.aio.live.connect()`
  outside any `try`, so a server refusal surfaces as an unhandled-task log line instead of
  `push_error`, and the pipeline runs on with no session. An unavailable region or
  `model=None` from an unset env var both land here, which is why the probe below was read
  from the session log as well as from its own verdict. — *Needs a call: the fix belongs to
  the shared base class and needs a stance on which connection failures are fatal and
  whether to retry first.*
- **Live avatars are out of reach** (medium, since 2026-10-28) — Vertex's "Configure live
  avatars" page drives `gemini-3.8-live` with `response_modalities=["VIDEO"]` and
  `avatar_config=types.AvatarConfig(avatar_name=...)`, and the Live API model table lists
  "Live avatar" among 3.8's features with mp4 as an output modality. The affordance looks
  Vertex-only — the Gemini Developer API's Live guide never mentions avatars — and the
  installed google-genai already has `AvatarConfig` and `LiveConnectConfig.avatar_config`.
  Pipecat cannot ask for it: `GeminiModalities` has only `TEXT` and `AUDIO`. — *Needs a
  call: whether a realtime LLM service should emit video at all; prebuilt avatars would
  still mean carrying mp4 through the pipeline, and custom avatars are allowlisted per
  customer.*
- **`history_config` suppression may be obsolete** (low, since 2026-09-01) —
  `_get_history_config()` returns None for Vertex (added 2026-03-27, "unsupported"), while
  the 3.8 migration guide still tells Vertex users to set
  `initial_history_in_client_content=True` to seed history with `send_client_content`. Last
  run's Vertex 3.8 session recalled a seeded fact identically with the flag forced on and
  with it off. — *Needs a call: whether the flag helps the audio-input history-recall path
  the base class works around; both checks seeded text, not audio.*
