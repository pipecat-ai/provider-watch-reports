# Gemini Live Vertex (realtime) — 2026-09-14

Vertex's lifecycle table now gives our default model a retirement date — 2026-12-13 — with
an empty replacement column, and Vertex still publishes no other GA live model; the broken
`pipecat init` scaffold from last run is unchanged.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Default model retires 2026-12-13** (high, since 2026-09-14) — Vertex's model-versions
  lifecycle table lists `gemini-live-2.5-flash-native-audio` with release date
  2025-12-12, retirement date 2026-12-13 and no replacement model, while the Live API
  "Supported models" table still calls it the only generally available, "Recommended" live
  model. There is nothing to bump to: `gemini-3.1-flash-live-preview` has left the regional
  publisher catalogue and is refused with close 1008 on both a regional endpoint and
  `location="global"`; the only other live entries on Vertex are the public previews
  `gemini-3.5-live-translate-preview` (speech translation) and
  `gemini-3.5-transcribe-live-preview` (streaming STT), neither a conversational agent
  model. The GA half-cascade `gemini-live-2.5-flash` still connects through
  `location="global"` but is no longer listed on the Live API page and is not native audio.
  — *Needs a call: what this service defaults to before 2026-12-13 — keep watching for a
  Vertex GA live model each run, or tell users now.*
  (This subsumes the previous report's low-priority "No Vertex GA for Gemini 3.1 Flash Live"
  item, which is the reason the retirement has no answer.)
- **`pipecat init` scaffold does not parse, and misuses `credentials`** (high, since
  2026-09-01) — the `gemini_vertex_live_realtime` entry in
  `pipecat.cli.registry._configs.SERVICE_CONFIGS` (duplicated in
  `service_metadata.MANUAL_SERVICE_CONFIGS`) over-indents the constructor args and closes
  the call twice, so the generated bot file raises `SyntaxError: unmatched ')'` — still the
  only one of the 100 entries that fails `compile()`. Dropping the stray `    ),` line and
  re-indenting to 4 spaces fixes the syntax; the snippet then still passes
  `credentials=os.getenv("GOOGLE_APPLICATION_CREDENTIALS")`, and `env.example.jinja2`
  documents that variable as `path/to/credentials.json`, so `_get_credentials` would call
  `json.loads` on a path. The keyword wanted is `credentials_path=`. — *Needs a call:
  whether to fix only the parens and the keyword, or also align the CLI's
  `GOOGLE_PROJECT_ID` / `GOOGLE_LOCATION` / `GOOGLE_APPLICATION_CREDENTIALS` (the scaffold
  and its `.env` template agree with each other) with the `GOOGLE_CLOUD_*` names the
  examples and docs use and the registry's `GOOGLE_VERTEX` env prefix.*
- **Refused connections are silent** (medium, since 2026-09-01) — unchanged: probing
  `google/gemini-3.1-flash-live-preview` made Vertex close the websocket with 1008
  ("Publisher model ... was not found"), and the probe still reported `ok: true`.
  `GeminiLiveLLMService._connection_task_handler` awaits `client.aio.live.connect()`
  outside any `try`, so the exception surfaces as an unhandled-task log line instead of
  `push_error`, and the pipeline runs on with no session. A retired model string — which
  this service's default becomes on 2026-12-13 — an unavailable region, or `model=None`
  from an unset env var all land here. — *Needs a call: the fix belongs to the shared base
  class and needs a stance on which connection failures are fatal and whether to retry
  first.*
- **`history_config` suppression may be obsolete** (low, since 2026-09-01) —
  `_get_history_config()` returns None for Vertex (added 2026-03-27, "unsupported"), but
  google-genai serializes `history_config` for the Vertex backend and a Vertex session
  accepted `HistoryConfig(initial_history_in_client_content=True)` on the default model.
  Not re-probed this run; nothing in google-genai 2.19–2.23 changes it. — *Needs a call:
  whether the flag helps the 2.5 audio-input history-recall path the base class works
  around; the earlier check seeded text, not audio.*
