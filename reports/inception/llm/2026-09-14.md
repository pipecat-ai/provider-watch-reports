# Inception LLM — 2026-09-14

`mercury-2.5` is GA and Inception's docs have switched to it, but at the service's current settings it is 2-5x slower than `mercury-2`; the bump and the open `reasoning_effort` question are now one decision. No branch this run.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`mercury-2.5` supersedes the `mercury-2` default** (high, since 2026-09-14) — GA on 2026-09-08, 40% more capable per Inception, 260K context. Inception's quickstart and its realtime-voice cookbook both use it, and `mercury-2` has moved to the legacy group whose page says access goes through an Inception representative, so a new user following Pipecat's docs is pointed at a model Inception no longer promotes. But at our settings it is a clear latency regression (see Verification): 687 ms vs 353 ms median TTFAT trivial, 2000 ms vs 371 ms on a reasoning prompt. Setting `reasoning_effort=instant` brings it to 373 ms, parity with today's default. — *Needs a call: the bump is only safe bundled with a `reasoning_effort` default, and aiewf-eval's `aiwf_medium_context` has benchmarked neither model, so there is no quality evidence to weigh against the latency.*
- **Unset `reasoning_effort`** (medium, since 2026-09-01) — the service omits the parameter, so Inception's server-side `medium` applies. Inception's realtime-voice cookbook sets `"low"`; `examples/function-calling/function-calling-inception.py` already does. On `mercury-2` this costs a few hundred ms on hard turns; on `mercury-2.5` it costs over 1.5 s. — *Needs a call: a default of `low` buys tail latency on hard turns at some answer-quality cost, so the choice is a product decision, not a mechanical bump.*
- **Reasoning summaries** (low, since 2026-09-01) — `reasoning_summary` and `reasoning_summary_wait` are not in `InceptionLLMSettings`; they would pass through via `extra_body` like `realtime` does, but `BaseOpenAILLMService` never reads reasoning content out of stream deltas, so the summary would be dropped. — *Needs a call: whether Pipecat wants reasoning summaries surfaced at all is a base-class question, not an Inception one.*
- **Mercury Voice preview** (low, since 2026-09-14) — announced 2026-09-08, a dLLM built for voice agents with TTFT under 170 ms. Preview only: absent from the catalogue, no model ID in the API reference. — *Needs a call: nothing to decide until it is GA and has an ID; re-check next run.*

## Verification

| model       | class               | ok | latency                                   | note                                                    |
| ----------- | ------------------- | -- | ----------------------------------------- | ------------------------------------------------------- |
| mercury-2   | InceptionLLMService | ✅ | TTFAT 353 ms (median of 5), thinking 0 ms | defaults, trivial prompt; spread 280-1158 ms            |
| mercury-2.5 | InceptionLLMService | ✅ | TTFAT 687 ms (median of 5), thinking 0 ms | defaults, trivial prompt; spread 550-1037 ms            |
| mercury-2   | InceptionLLMService | ✅ | TTFAT 371 ms (median of 5), thinking 0 ms | defaults, reasoning-triggering prompt; spread 322-682 ms |
| mercury-2.5 | InceptionLLMService | ✅ | TTFAT 2000 ms (median of 5), thinking 0 ms | defaults, same prompt; spread 1072-2734 ms              |
| mercury-2.5 | InceptionLLMService | ✅ | TTFAT 564 ms (median of 3), thinking 0 ms | `reasoning_effort=low`, same prompt                      |
| mercury-2.5 | InceptionLLMService | ✅ | TTFAT 373 ms (median of 3), thinking 0 ms | `reasoning_effort=instant`, same prompt                  |

`mercury-2.5` accepts the service's `realtime=True` and `reasoning_effort` pass-through unchanged, so no code change is needed to use it — only the default differs. As on `mercury-2`, reasoning is never streamed as reasoning deltas (`thinking_ms` is 0 at every effort level); at `medium` the model writes its working into the answer text, which is what the 2000 ms figure reflects. `mercury-2.5` prefixes its first token with a blank line at `medium` and `low` effort, which sentence aggregation absorbs.
