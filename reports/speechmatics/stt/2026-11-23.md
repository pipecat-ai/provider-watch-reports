# Speechmatics STT — 2026-11-23

Nothing to review. The provider shipped no Agent STT change since Oct 29, the SDK pin is still at the newest agent-stt release, and Pipecat's own 1.16.0 diarization rework transcribes cleanly on the wire.

## What's new for Pipecat

The service changed on our side, not the provider's: commits d62368d3b…5c2fa5205 put the Speechmatics speaker label in `speaker.label` on the transcription frame, added the `speaker_format` template (`{speaker}`, `{speaker_number}`, `{text}`) and deprecated `speaker_active_format` as of 1.16.0. Probed live with `enable_diarization` on: the final transcript came back formatted from the new path with the provider's `S1` label. `user_id` is now the transport's user ID rather than the speaker.

Nothing new at the provider. `speechmatics-agent-stt` 0.3.0 (2026-10-19) is still the latest release and matches our `~=0.3.0` pin. The changelog has seven entries since the last run and none is Agent STT: Melia 1 and Oak 1 reached Realtime SaaS with diarization (Nov 10/12), Batch gained entity detection and PII redaction (Nov 20), and the Realtime Helm chart deprecated `operatingPoint` for `model` (Nov 17) — none of it reachable through the `/v2/agent` endpoint, whose only model remains `linden-1`. The documented `StartRecognition` schema is unchanged and the service still covers every field of it except `speaker_diarization_config.get_speakers`.

### PRs
Nothing.

### To consider
- **`punctuation_overrides` bricks the session** (high, since 2026-09-28) — the field is on `Settings`, documented on docs.pipecat.ai, and set into the Agent STT `TranscriptionConfig`; the endpoint still answers `additional properties 'punctuation_overrides' not allowed`, which the service treats as permanent, so the processor is marked unusable and no transcript arrives. It reaches our config only because the SDK shares `TranscriptionConfig` with Realtime, where the field is real. Unset by default, so only users who set it are affected. — *Needs a call: commit 5959c4e0c kept this field on Agent STT deliberately, so deprecating it versus waiting for the proxy to accept it is a vendor question.*
- **String `turn_detection_mode` crashes at StartFrame** (high, since 2026-09-28) — `Settings(turn_detection_mode="vad")` raises `AttributeError: 'str' object has no attribute 'value'` in `_handle_turn_detection_mode` and the session never opens; re-probed unchanged. `TurnDetectionMode` is a `StrEnum` and `Settings` is a dataclass with no coercion, and the vendor's own page passes this setting through `Settings`; `AgentTurnDetectionMode(mode)` would take both forms. — *Needs a call: whether enum-typed Settings fields coerce strings across the codebase, or the annotation is the contract and the fix is a clear error.*
- **Endpoint default** (medium, since 2026-08-31) — still `wss://eu2.rt.speechmatics.com/v2/agent`, so US and AU users get the EU unless they set `base_url`; SDK 0.3.0 keeps the same default in `agent_stt/_url.py`. — *Needs a call: keep the SDK's default or switch to `global`, which routes to the nearest region but has data-residency implications.*
- **Language and locale maps** (low, since 2026-08-31) — `ia` and the five bilingual packs are still on the provider's language page and still absent from `BASE_LANGUAGES`, and `LOCALES` covers only the three English locales, leaving Mandarin's Traditional/Simplified output locales unreachable. Unmapped codes pass through with a warning rather than being blocked. — *Needs a call: none of these has a `Language` enum member, so this is enum work rather than a table row.*
- **Speaker identifiers need a manual `GetSpeakers`** (low, since 2026-10-12) — the one documented schema field the service cannot express. A diarizing session returns `SpeakersResult` only with `get_speakers: true` or a `GetSpeakers` message, and the service sends neither, so the `on_speakers_result` handler it registers never fires on its own. SDK 0.3.0's `SpeakerDiarizationConfig` still has no `get_speakers` member, so it is not a pass-through. — *Needs a call: add a setting the SDK cannot yet express, or document the `send_message` route on the event handler.*
- **Vendor page documents the deprecated speaker API** (low, since 2026-11-23) — docs.speechmatics.com's Pipecat STT page still says the diarization label arrives as `user_id` and presents `speaker_active_format` as the way to format it; 1.16.0 moved the label to `speaker.label`, added `speaker_format` and deprecated `speaker_active_format` for removal in 2.0.0. docs.pipecat.ai is already current. — *Needs a call: the page is in the vendor's docs repo, so this is a note to Speechmatics rather than a change we can make.*
- **STT probe harness bursts audio** (low, since 2026-09-28) — the stock `probe.py` queues every 20 ms chunk back to back, so the external-mode `ForceEndOfUtterance` overtakes the engine and the server drops it; it reported "no TranscriptionFrame within 25s" against a healthy service again this run while the paced copy returned the full transcript. `_run_pipeline` already sleeps on a float in the frame list, so pacing is a couple of lines. — *Needs a call: pace STT probe audio in the harness, or leave it and have each Speechmatics run re-diagnose the false failure.*
