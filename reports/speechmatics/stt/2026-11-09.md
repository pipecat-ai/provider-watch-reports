# Speechmatics STT — 2026-11-09

Nothing to review. Agent STT shipped one server-side bug fix since the last run, the service and the SDK pin are unchanged, and the 8 kHz item is now settled upstream.

## What's new for Pipecat

No code change to `src/pipecat/services/speechmatics/` since 4d703856b (last run). `speechmatics-agent-stt` 0.3.0 is still the latest release and matches our `~=0.3.0` pin; the SDK releases since (tts 0.2.0, rt 1.3.0, batch 1.2.0 on Nov 6, all moving JWT auth to a new endpoint) do not touch agent-stt, and the transitive `speechmatics-rt` is already locked at 1.3.0.

The provider changelog has six entries since the last run (Oct 22 – Nov 3). Exactly one is Agent STT: the Oct 29 release fixes short words going missing in `vad` turn-detection mode, server-side. The rest are Realtime/Batch — Oak 1 reaching Realtime, English Enhanced term recognition, WAV misidentification fixes — none reachable through this service, whose only model remains `linden-1`. The documented Agent STT `StartRecognition` schema is unchanged, and the service still covers every field of it except `speaker_diarization_config.get_speakers`.

### PRs
Nothing.

### To consider
- **`punctuation_overrides` bricks the session** (high, since 2026-09-28) — the field is on `Settings`, documented on docs.pipecat.ai, and set into the Agent STT `TranscriptionConfig`; the endpoint still answers `Additional property punctuation_overrides is not allowed`, which the service treats as permanent, so the processor is marked unusable and no transcript arrives. Speechmatics' own Pipecat page documents every other transcription setting we expose and still omits this one. Unset by default, so only users who set it are affected. — *Needs a call: commit 5959c4e0c kept this field on Agent STT deliberately, so deprecating it versus waiting for the proxy to accept it is a vendor question.*
- **String `turn_detection_mode` crashes at StartFrame** (high, since 2026-09-28) — `Settings(turn_detection_mode="vad")` raises `AttributeError: 'str' object has no attribute 'value'` in `_handle_turn_detection_mode` and the session never opens; re-probed unchanged. `TurnDetectionMode` is a `StrEnum` and `Settings` is a dataclass with no coercion, and the vendor's own page passes this setting through `Settings`; `AgentTurnDetectionMode(mode)` would take both forms. — *Needs a call: whether enum-typed Settings fields coerce strings across the codebase, or the annotation is the contract and the fix is a clear error.*
- **Endpoint default** (medium, since 2026-08-31) — still `wss://eu2.rt.speechmatics.com/v2/agent`, so US and AU users get the EU unless they set `base_url`; the SDK keeps the same default in 0.3.0. — *Needs a call: keep the SDK's default or switch to `global`, which routes to the nearest region but has data-residency implications.*
- **Language and locale maps** (low, since 2026-08-31) — `ia` and the five bilingual packs are still on the provider's language page and still absent from `BASE_LANGUAGES`, and `LOCALES` covers only the three English locales, leaving Mandarin's Traditional/Simplified output locales unreachable. Unmapped codes pass through with a warning rather than being blocked. — *Needs a call: none of these has a `Language` enum member, so this is enum work rather than a table row.*
- **Speaker identifiers need a manual `GetSpeakers`** (low, since 2026-10-12) — the one documented schema field the service cannot express. A diarizing session returns `SpeakersResult` only with `get_speakers: true` or a `GetSpeakers` message, and the service sends neither, so the `on_speakers_result` handler it registers never fires on its own. SDK 0.3.0's `SpeakerDiarizationConfig` still has no `get_speakers` member. — *Needs a call: add a setting the SDK cannot yet express, or document the `send_message` route on the event handler.*
- **STT probe harness bursts audio** (low, since 2026-09-28) — the stock `probe.py` queues every 20 ms chunk back to back, so the external-mode `ForceEndOfUtterance` overtakes the engine and the server drops it; it reported "no TranscriptionFrame within 25s" against a healthy service this run while the paced copy returned the full transcript. The harness already interleaves float sleeps, so pacing is a couple of lines. — *Needs a call: pace STT probe audio in the harness, or leave it and have each Speechmatics run re-diagnose the false failure.*

### Closed since the last run
- **`sample_rate=16000` on an 8 kHz pipeline relabels PCM** — decided upstream and moved to `decisions.md`. pipecat-ai/pipecat#5717 was closed as completed on 2026-11-04 ("`SpeechmaticsSTTService` now supports 8 kHz audio alongside 16 kHz, so an 8 kHz telephony pipeline works as-is. Drop the `sample_rate=16000` override."), and the resampling PR #5719 closed unmerged the same day.
