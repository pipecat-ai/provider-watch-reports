# Speechmatics STT — 2026-09-28

Agent STT recovered: `SpeechmaticsSTTService` transcribes end to end again, and the previous run's blocking gap is gone. What remains is settings-level — setting `punctuation_overrides` still bricks the service.

## What's new for Pipecat

The provider-side rejection that made the service unusable at the last run has cleared; nothing in Pipecat changed to fix it. Probing the endpoint's schema also settles two carried gaps in the negative: Agent STT rejects the RT-era `TranscriptionConfig` fields outright, so there was never anything to expose.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5938 — Map Language.FIL and Language.TL onto Speechmatics' tl pack

### To consider
- **`punctuation_overrides` bricks the session** (high, since 2026-09-28) — the field is on `Settings`, documented on docs.pipecat.ai, and set into the Agent STT `TranscriptionConfig`; the endpoint answers `protocol_error: Additional property punctuation_overrides is not allowed`, which the service treats as permanent, so the processor is marked "can no longer do its job" and no transcript arrives. Unset by default, so only users who set it are affected. — *Needs a call: commit 5959c4e0c kept this field on Agent STT deliberately, so deprecating it versus waiting for the proxy to accept it is a vendor question.*
- **Sample rate is inherited, never converted** (high, since 2026-09-12) — pipecat-ai/pipecat#5717, still open. Agent STT accepts exactly 16 kHz (`audio_format.sample_rate does not match: 16000`), but the service takes the pipeline's rate when `sample_rate` is omitted, so an 8 kHz transport is rejected outright and setting `sample_rate=16000` relabels the same 8 kHz PCM. — *Needs a call: validate at setup, resample in the service, or document the conversion boundary — all three go beyond changing a value.*
- **String `turn_detection_mode` crashes at StartFrame** (high, since 2026-09-28) — `Settings(turn_detection_mode="vad")` raises `AttributeError: 'str' object has no attribute 'value'` in `_handle_turn_detection_mode` and the session never opens. `TurnDetectionMode` is a `StrEnum` and `Settings` is a dataclass with no coercion, so the string form is an easy mistake; `AgentTurnDetectionMode(mode)` would take both. — *Needs a call: whether enum-typed Settings fields coerce strings across the codebase, or the annotation is the contract and the fix is a clear error.*
- **Endpoint default** (medium, since 2026-08-31) — the default is still the undocumented `wss://eu2.rt.speechmatics.com/v2/agent`. Unlike at the last run, `global`, `eu`, `us` and `au` all now transcribe on `/agent`, so regional routing works and US/AU users simply get the EU unless they set `base_url`. — *Needs a call: keep the SDK's default or switch to `global`, which routes to the nearest region but has data-residency implications.*
- **Language and locale maps** (low, since 2026-08-31) — with `tl`/`fil` handled on the branch, what is left is `ia` and the bilingual packs (`ar_en` and friends, one of which Agent STT accepted on the wire), plus `LOCALES` covering only the three English locales. Unmapped codes pass through with a "not verified" warning rather than being blocked. — *Needs a call: none of these has a `Language` enum member, so this is enum work rather than a table row.*
- **STT probe harness bursts audio** (low, since 2026-09-28) — `probe.py` queues every 20 ms chunk back to back, so the external-mode `ForceEndOfUtterance` overtakes the engine and the server drops it; the probe reports "no TranscriptionFrame within 30s" against a perfectly healthy service. Real-time pacing makes the same probe pass. — *Needs a call: pace STT probe audio in the harness, or leave it and have each Speechmatics run re-diagnose the false failure.*

### Closed since the last run
- **Agent STT rejects every session** (was high) — resolved provider-side; a default session now starts and returns a final transcript. The changelog's 2026-09-16 Realtime entry touching `ForceEndOfUtterance` is the only nearby note, and no incident was published.
- **Documented regional endpoints do not serve `/agent`** (was part of the endpoint gap) — `eu`, `us`, `au` and `global` all transcribe now.
- **`max_delay` / `max_delay_mode` unreachable** (was medium) — not a gap: Agent STT rejects both (`Additional property max_delay is not allowed`). Exposing them would break every session that set them.
- **Unset `TranscriptionConfig` fields have no route** (was low) — not a gap: `enable_entities`, `streaming_mode`, `channel_diarization_labels` and `audio_filtering_config` are each rejected by the Agent STT schema. The SDK's dataclass is shared with the RT client; only a subset is valid here.
