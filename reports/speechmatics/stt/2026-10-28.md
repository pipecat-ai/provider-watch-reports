# Speechmatics STT — 2026-10-28

Nothing to review: Agent STT has shipped nothing since 2026-10-09 and the two gaps that were actionable last run both landed. What remains needs maintainer calls, not code.

## What's new for Pipecat

Both medium gaps from last run closed in the code. pipecat-ai/pipecat#6144 merged, exposing `transcript_filtering_config`; commit 4d703856b (from Speechmatics) added `emit_sentences`, bumped the pin to `speechmatics-agent-stt~=0.3.0` — which is the latest release — and made an unsupported `sample_rate` fail permanently with a message naming 8000 and 16000.

With those in, the service covers every field of the documented Agent STT `StartRecognition` schema except `speaker_diarization_config.get_speakers`, which the SDK dataclass still cannot express.

The provider changelog has six entries since the last run (Oct 13–27), all Realtime SaaS, Batch SaaS or Containers: Melia 1 in Realtime with 56-language auto-detection, the new Oak 1 medical model, `output_locale` accepting a list. None touches Agent STT, whose only model remains `linden-1`. Oak 1 and Melia 1 are Batch/Realtime models and are not reachable through this service by design.

### PRs
Nothing.

### To consider
- **`punctuation_overrides` bricks the session** (high, since 2026-09-28) — the field is on `Settings`, documented on docs.pipecat.ai, and set into the Agent STT `TranscriptionConfig`; the endpoint still answers `Additional property punctuation_overrides is not allowed`, which the service treats as permanent, so the processor is marked unusable and no transcript arrives. Speechmatics' Pipecat page now documents every other transcription setting we expose and still omits this one. Unset by default, so only users who set it are affected. — *Needs a call: commit 5959c4e0c kept this field on Agent STT deliberately, so deprecating it versus waiting for the proxy to accept it is a vendor question.*
- **String `turn_detection_mode` crashes at StartFrame** (high, since 2026-09-28) — `Settings(turn_detection_mode="vad")` raises `AttributeError: 'str' object has no attribute 'value'` in `_handle_turn_detection_mode` and the session never opens; re-probed unchanged. `TurnDetectionMode` is a `StrEnum` and `Settings` is a dataclass with no coercion, and the vendor's own page passes this setting through `Settings`; `AgentTurnDetectionMode(mode)` would take both forms. — *Needs a call: whether enum-typed Settings fields coerce strings across the codebase, or the annotation is the contract and the fix is a clear error.*
- **An explicit `sample_rate` that contradicts the pipeline still relabels** (medium, since 2026-09-12) — 8 kHz inherited transcribes in full and an unsupported rate now fails cleanly, so this is all that survives of the 8 kHz work: `sample_rate=16000` over 8 kHz audio passes the new guard and degrades the transcript quietly instead of failing. — *Needs a call: close #5717/#5719 as provider-resolved, or still guard a `sample_rate` that contradicts the pipeline's.*
- **Endpoint default** (medium, since 2026-08-31) — still `wss://eu2.rt.speechmatics.com/v2/agent`, so US and AU users get the EU unless they set `base_url`; the SDK keeps the same default in 0.3.0. — *Needs a call: keep the SDK's default or switch to `global`, which routes to the nearest region but has data-residency implications.*
- **Language and locale maps** (low, since 2026-08-31) — `ia` and the five bilingual packs are still on the provider's language page and still absent from `BASE_LANGUAGES`, and `LOCALES` covers only the three English locales, leaving Mandarin's Traditional/Simplified output locales unreachable. Unmapped codes pass through with a warning rather than being blocked. — *Needs a call: none of these has a `Language` enum member, so this is enum work rather than a table row.*
- **Speaker identifiers need a manual `GetSpeakers`** (low, since 2026-10-12) — the one documented schema field the service cannot express. A diarizing session returns `SpeakersResult` only with `get_speakers: true` or a `GetSpeakers` message, and the service sends neither, so the `on_speakers_result` handler it registers never fires on its own. SDK 0.3.0's `SpeakerDiarizationConfig` still has no `get_speakers` member. — *Needs a call: add a setting the SDK cannot yet express, or document the `send_message` route on the event handler.*
- **STT probe harness bursts audio** (low, since 2026-09-28) — `probe.py` queues every 20 ms chunk back to back, so the external-mode `ForceEndOfUtterance` overtakes the engine and the server drops it; the probe reports "no TranscriptionFrame within 30s" against a healthy service. The harness already interleaves float sleeps, so pacing is a couple of lines. — *Needs a call: pace STT probe audio in the harness, or leave it and have each Speechmatics run re-diagnose the false failure.*
