# Speechmatics STT — 2026-10-12

Agent STT moved: 8 kHz input is now accepted, and two new transcription options shipped. A branch exposes one of them; the two settings-level crash paths from last run are unchanged.

## What's new for Pipecat

The 2026-10-09 Agent STT release accepts `audio_format.sample_rate` of 8000 as well as 16000. An 8 kHz pipeline that lets the service inherit the rate now transcribes end to end, which removes the session rejection behind pipecat-ai/pipecat#5717 and makes the open resampling fix pipecat-ai/pipecat#5719 unnecessary.

Two transcription options appeared in the API reference that the service has no route to: `transcript_filtering_config` (`remove_disfluencies`, `replacements`), which the installed SDK already carries, and `emit_sentences`, which needs speechmatics-agent-stt 0.2.0.

`punctuation_overrides` is still rejected and is now absent from both the Agent STT WebSocket reference and Speechmatics' own Pipecat page.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6144 — Expose Speechmatics transcript filtering

### To consider
- **`punctuation_overrides` bricks the session** (high, since 2026-09-28) — the field is on `Settings`, documented on docs.pipecat.ai, and set into the Agent STT `TranscriptionConfig`; the endpoint still answers `Additional property punctuation_overrides is not allowed`, which the service treats as permanent, so the processor is marked unusable and no transcript arrives. The provider's own schema and its Pipecat page both omit the field now. Unset by default, so only users who set it are affected. — *Needs a call: commit 5959c4e0c kept this field on Agent STT deliberately, so deprecating it versus waiting for the proxy to accept it is a vendor question.*
- **String `turn_detection_mode` crashes at StartFrame** (high, since 2026-09-28) — `Settings(turn_detection_mode="vad")` raises `AttributeError: 'str' object has no attribute 'value'` in `_handle_turn_detection_mode` and the session never opens; re-probed unchanged. `TurnDetectionMode` is a `StrEnum` and `Settings` is a dataclass with no coercion, so the string form is an easy mistake; `AgentTurnDetectionMode(mode)` would take both. — *Needs a call: whether enum-typed Settings fields coerce strings across the codebase, or the annotation is the contract and the fix is a clear error.*
- **8 kHz is supported now, so #5717 and #5719 are stale** (medium, since 2026-09-12) — the inherited-rate path works at 8 kHz as of the provider's 2026-10-09 release. The surviving half is that `sample_rate=16000` on an 8 kHz pipeline relabels rather than converts, and the transcript degrades quietly instead of failing. — *Needs a call: close #5717/#5719 as provider-resolved and document 8 kHz, or still guard a mismatched `sample_rate`.*
- **`emit_sentences` and the SDK pin** (medium, since 2026-10-12) — `emit_sentences` makes each segment one sentence instead of the largest coherent chunk; the endpoint accepts it, but the `TranscriptionConfig` member arrives in speechmatics-agent-stt 0.2.0 and our pin is `~=0.1.0`. — *Needs a call: the Settings field is a one-line pass-through, but it rides on bumping the pin and relocking.*
- **Endpoint default** (medium, since 2026-08-31) — the default is still the undocumented `wss://eu2.rt.speechmatics.com/v2/agent`, so US and AU users get the EU unless they set `base_url`. — *Needs a call: keep the SDK's default or switch to `global`, which routes to the nearest region but has data-residency implications.*
- **Language and locale maps** (low, since 2026-08-31) — `ia` and the five bilingual packs (`ar_en` and friends, one of which Agent STT accepted on the wire) are missing, and `LOCALES` covers only the three English locales. Unmapped codes pass through with a "not verified" warning rather than being blocked. — *Needs a call: none of these has a `Language` enum member, so this is enum work rather than a table row.*
- **Speaker identifiers need a manual `GetSpeakers`** (low, since 2026-10-12) — a diarizing session returns `SpeakersResult` only with `get_speakers: true` or a `GetSpeakers` message, and the service sends neither, so the `on_speakers_result` handler it registers never fires on its own. `send_message(ClientMessageType.GET_SPEAKERS, final=True)` works; the SDK's `SpeakerDiarizationConfig` has no `get_speakers` member. — *Needs a call: add a setting the SDK cannot yet express, or document the `send_message` route on the event handler.*
- **STT probe harness bursts audio** (low, since 2026-09-28) — `probe.py` queues every 20 ms chunk back to back, so the external-mode `ForceEndOfUtterance` overtakes the engine and the server drops it; the probe reports "no TranscriptionFrame within 30s" against a healthy service. The provider now warns once per session about faster-than-real-time audio, which names the same condition. — *Needs a call: pace STT probe audio in the harness, or leave it and have each Speechmatics run re-diagnose the false failure.*

### Closed since the last run
- **`Language.FIL` / `Language.TL`** — pipecat-ai/pipecat#5938 merged on 2026-09-28; both map onto the `tl` pack in the code today.
- **8 kHz session rejection** (was part of the sample-rate gap) — resolved provider-side on 2026-10-09; what is left is the relabelling half, carried above at medium.
