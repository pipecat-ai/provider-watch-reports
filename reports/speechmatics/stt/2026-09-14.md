# Speechmatics STT — 2026-09-14

`SpeechmaticsSTTService` cannot transcribe: since the 1.10 migration to Agent STT the provider rejects every session, and the vendor's own SDK fails the same way, so there is nothing to fix in Pipecat.

## What's new for Pipecat

The service was rewritten onto `speechmatics-agent-stt~=0.1.0` (PR #5631, authored by Speechmatics), replacing `speechmatics-voice~=0.2.8`. That closes four gaps from the last run and opens the two high-priority ones below.

### PRs
Nothing.

### To consider
- **Agent STT rejects every session** (high, since 2026-09-14) — `StartRecognition` on `/v2/agent` comes back as an API JSON-schema validation error; the rejected payload is the proxy's own expansion of our config (`operating_point: enhanced`, `max_delay: 2.0`, `conversation_config`, …), not what the service sends, which is just `{"language": "en", "model": "linden-1"}`. It reproduces on eu2 and on global, and with `speechmatics-agent-stt` 0.1.0 alone using the SDK's default config. A plain `speechmatics-rt` session on the same key starts fine, so the key, the account and the RT service are healthy. — *Needs a call: this is server-side, so it needs Speechmatics to say whether Agent STT is broken, account-gated, or expects a newer SDK than 0.1.0.*
- **Sample rate is inherited, never converted** (high, since 2026-09-12) — pipecat-ai/pipecat#5717: Agent STT requires 16 kHz, but the service takes the pipeline's rate when its `sample_rate` argument is omitted, so an 8 kHz transport opens the session with `sample_rate=8000` and is rejected; setting `sample_rate=16000` relabels the same 8 kHz PCM. — *Needs a call: validate at setup, resample in the service, or document the conversion boundary — all three go beyond changing a value.*
- **`max_delay` / `max_delay_mode`** (medium, since 2026-09-14) — Agent STT's `TranscriptionConfig` accepts both; the service sets neither, `_check_deprecated_args` maps the old `max_delay` constructor argument to `None`, and the migration removed the `extra_params` route that used to reach them. — *Needs a call: the pass-through field is obvious, but the PR bar wants a live probe and no Agent STT session can be opened today.*
- **Endpoint default** (medium, since 2026-08-31) — the service defaults to `wss://eu2.rt.speechmatics.com/v2/agent`, which is the SDK's own default but not a documented host; the documented ones are `global`, `eu`, `us` and `au` (added 2026-09-08). `eu.rt.speechmatics.com/v2` fails the websocket handshake on the `/agent` path, so only eu2 and global answer at all. — *Needs a call: SDK default or documented hosts, given that regional Agent STT is effectively unavailable and global routing has residency implications.*
- **Unset TranscriptionConfig fields** (low, since 2026-08-31) — `enable_entities`, `audio_filtering_config`, `transcript_filtering_config`, `channel_diarization_labels` and `streaming_mode` are on the config object but are never populated and have no escape hatch. — *Needs a call: the Agent STT proxy rewrites the transcription config, so it is unclear which of these it honours.*
- **Language and locale maps** (low, since 2026-08-31) — `BASE_LANGUAGES` still omits `tl`, `ia` and the five bilingual packs, and `LOCALES` covers only the three English locales. linden-1's supported languages are undocumented, so the RT-era list may be wrong in both directions now. — *Needs a call: the bilingual codes have no `Language` enum member, and linden-1's language set has to come from Speechmatics.*

### Closed since the last run
- `split_sentences` crash and `include_results` — PR #5568 merged 2026-09-03. The Agent STT migration then removed `include_results`: word-level results are not part of the Agent STT `Segment` shape.
- `operating_point` → `model` — the service now takes `model`, resolves it against the deprecated `operating_point` alias, and defaults to the SDK's `linden-1`.
- `speech_segment_config` clobbering, and the VAD / smart-turn / end-of-turn sub-configs — moot: Agent STT's `TurnConfig` carries only `turn_detection_mode`, and its docstring states the VAD is not tunable from the client.
- `TurnDetectionMode` presets — Agent STT defines exactly `vad` and `external`, and the service mirrors both.
