# Speechify TTS — 2026-11-09

Nothing new from the provider since 2026-10-21, and last run's branch merged, so
this is the same four-item list as 2026-10-28 minus `pronunciations`: all of it
is simba-3.5 fallout that needs a maintainer's call rather than a mechanical
change.

## What's new for Pipecat

### PRs

Nothing.

pipecat-ai/pipecat#6436 merged on 2026-10-28, so `pronunciations` is reachable
from `SpeechifyTTSSettings` and that gap is closed. No new branch this run: each
remaining item is a design question, not a value to change.

### To consider
- **Word marks collapse in scripts without spaces** (medium, since 2026-10-28) — `_SpeechMarkAccumulator` joins marks that abut in the source text and releases a word only when the next character is whitespace or the text ends. Speechify's marks for Japanese, Chinese, Thai and the other scriptio-continua languages `simba-3.5` speaks abut throughout, so a whole utterance arrives as one mark at the first word's time. Re-probed below: 14 word frames for a 14-word English sentence, 1 for a two-sentence Japanese one, audio fine in both. `add_word_timestamps` feeds bot-speaking text sync and word-level interruption tracking, so those are what degrade. Pipecat has handled the same problem twice — `CartesiaTTSService` and the ElevenLabs services both read the language setting and pass `includes_inter_frame_spaces=True` for Chinese and Japanese — but both stop at those two scripts, and this service's defect is the merge rule rather than per-character tokens. — *Needs a call: whether to follow the Cartesia/ElevenLabs CJK precedent and how far it should reach, since `simba-3.5` also speaks Thai, Burmese and Lao.*
- **The language map covers 6 of 48 languages** (medium, since 2026-09-14) — `language_to_speechify_language` maps DE, EN, ES, FR, IT and PT, which were `simba-3.0`'s routes. `simba-3.5` speaks 48; every `Language` outside the six falls through `resolve_language` to its BCP-47 string and logs `not verified` — confirmed again for `ja`, `zh`, `es-MX`, `en-GB`, `th` and `ko`. Synthesis is unaffected, so the cost is a wrong warning on 42 documented languages, plus a Pipecat docs page that still lists six. — *Needs a call: which tag each language gets — identity is right for es-MX and for the bare codes `simba-3.5` lists, but en-GB or pt-PT would be a locale substitution onto en-US/pt-BR and needs a stance.*
- **WebSocket streaming text input** (medium, since 2026-10-12) — `GET /v1/audio/stream/ws`, added 2026-10-08, accepts text as it is produced (`input.text`, `input.flush`, `input.close`) and speaks each completed sentence, where the HTTP class re-POSTs per aggregated utterance. With `speech_marks=true` word marks carry absolute times on one session timeline, which is what `_SpeechMarkAccumulator`'s `_cumulative_time` offsetting exists to reconstruct. Settings are query-string parameters with the HTTP endpoint's names, so `_build_payload`'s logic transfers. The class name `SpeechifyHttpTTSService` already reserves the slot for a sibling. — *Needs a call: whether to add a websocket class at all, and what reconnect behavior the session caps (one concurrent request, 60 s idle close, 5-minute hard close) imply for a long call.*
- **Pinned version has no override and no owner** (low, since 2026-09-28) — `SPEECHIFY_API_VERSION` is the module constant `2026-09-30`, which is still Speechify's newest version; a workspace that must stay on an older one cannot opt out, and the constant advances only when someone edits it. — *Needs a call: whether the pin should be overridable at all, and who advances it as Speechify mints versions.*

`simba-3.5` is still the right default: `GET /v1/audio/models` marks it
`recommended` and nothing else, no model carries `deprecated: true`, and
`simba-3.0` remains the API's default only for requests that omit `model`, which
this service never does. The one dated commitment on the horizon, 21 November
2026, ends `simba-3.5`'s introductory pricing — it retires nothing.
`examples/voice/voice-speechify-http.py` already pins `simba-3.5`.
