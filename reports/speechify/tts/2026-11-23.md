# Speechify TTS — 2026-11-23

Speechify shipped English `pronunciations` on `simba-3.5` on 2026-11-17, which
makes one sentence of our `pronunciations` docstring wrong; a branch fixes it.
Everything else is the same four-item list as last run.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/6978 — Document that Speechify applies pronunciations in English

The docstring told users that Speechify applies `pronunciations` "in every
language it lists under `pronunciation_languages` in `GET /v1/audio/models`,
which excludes English". Since 2026-11-17 the live catalogue lists `en` among
`simba-3.5`'s 48 `pronunciation_languages`, and an English request carrying both
an `ipa` and an `alias` entry synthesized normally in the probe below — so the
docstring now steers users away from a capability they have. Docstring and
changelog fragment only; no behavior changes. The docs.pipecat.ai page repeats
the same "excludes English" sentence, so it needs the same correction wherever
that page is authored.

### To consider
- **Word marks collapse in scripts without spaces** (medium, since 2026-10-28) — `_SpeechMarkAccumulator` joins marks that abut in the source text and releases a word only when the next character is whitespace or the text ends. Speechify's marks for Japanese, Chinese, Thai and the other scriptio-continua languages `simba-3.5` speaks abut throughout, so a whole utterance arrives as one mark at the first word's time. Re-probed below: 13 word frames for a 13-word English sentence, 1 for a two-sentence Japanese one, audio fine in both. `add_word_timestamps` feeds bot-speaking text sync and word-level interruption tracking, so those are what degrade. Pipecat has handled the same problem twice — `CartesiaTTSService` and the ElevenLabs services both read the language setting and pass `includes_inter_frame_spaces=True` for Chinese and Japanese — but both stop at those two scripts, and this service's defect is the merge rule rather than per-character tokens. — *Needs a call: whether to follow the Cartesia/ElevenLabs CJK precedent and how far it should reach, since `simba-3.5` also speaks Thai, Burmese and Lao.*
- **The language map covers 6 of 48 languages** (medium, since 2026-09-14) — `language_to_speechify_language` maps DE, EN, ES, FR, IT and PT, which were `simba-3.0`'s routes. `simba-3.5` speaks 48; every `Language` outside the six falls through `resolve_language` to its BCP-47 string and logs `not verified`, as the Japanese probe did again this run. Synthesis is unaffected, so the cost is a wrong warning on 42 documented languages, plus a Pipecat docs page that still lists six. — *Needs a call: which tag each language gets — identity is right for es-MX and for the bare codes `simba-3.5` lists, but en-GB or pt-PT would be a locale substitution onto en-US/pt-BR and needs a stance.*
- **WebSocket streaming text input** (medium, since 2026-10-12) — `GET /v1/audio/stream/ws`, added 2026-10-08, accepts text as it is produced (`input.text`, `input.flush`, `input.close`) and speaks each completed sentence, where the HTTP class re-POSTs per aggregated utterance. With `speech_marks=true` word marks carry absolute times on one session timeline, which is what `_SpeechMarkAccumulator`'s `_cumulative_time` offsetting exists to reconstruct. Settings are query-string parameters with the HTTP endpoint's names, so `_build_payload`'s logic transfers. The class name `SpeechifyHttpTTSService` already reserves the slot for a sibling. — *Needs a call: whether to add a websocket class at all, and what reconnect behavior the session caps (one concurrent request, 60 s idle close, 5-minute hard close) imply for a long call.*
- **Pinned version has no override and no owner** (low, since 2026-09-28) — `SPEECHIFY_API_VERSION` is the module constant `2026-09-30`, which is still Speechify's newest version; every entry since, the three new ones included, says no version change is needed. A workspace that must stay on an older version cannot opt out, and the constant advances only when someone edits it. — *Needs a call: whether the pin should be overridable at all, and who advances it as Speechify mints versions.*

`simba-3.5` is still the right default: the live catalogue marks it
`recommended` and nothing else, no model carries `deprecated: true`, and
`simba-3.0` remains the API's default only for requests that omit `model`, which
this service never does. The 21 November dates that have now passed — the end of
`simba-3.5`'s introductory pricing, and Simba 1.6 being served by current models
— retire nothing we send. The class docstring's claim about the legacy ids still
holds at our pinned version: a `simba-english` request returned `model_retired`
in the probe below, since the 2026-11-10 fallback applies only to workspaces
pinned before `2026-09-21`. `examples/voice/voice-speechify-http.py` pins
`simba-3.5`.
