# Speechify TTS — 2026-10-28

The default is already `simba-3.5` and that is the right model; the work it
creates is that the service's language handling and word-mark assembly were
written for a six-language English-and-Europe model, and `simba-3.5` speaks 48
languages including ones with no spaces between words.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6436 — Add a pronunciations setting to SpeechifyHttpTTSService

Speechify's 2026-10-18 entry shipped `simba-3.5` and, with it, a
`pronunciations` array on `/v1/audio/speech`, `/v1/audio/stream` and
`/v1/audio/stream/with-timestamps` — the last being this service's endpoint.
Each entry names the `text` to match and exactly one of `ipa` (phones from the
model's set, one word) or `alias` (replacement text), with an optional
`case_sensitive`; up to 200 entries, not billed, and speech marks still index
the original input. The branch adds the array to `SpeechifyTTSSettings`, unset
by default, and copies it into the payload when set. Verified live below: a
Spanish turn with an IPA entry and an alias entry synthesizes normally, and a
phone outside the model's set comes back as `validation_failed` naming
`pronunciations[0].ipa`, which is what shows the field reaches the request body.

Speechify applies the array on `simba-3.5` only, and only in the languages
listed as `pronunciation_languages` in `GET /v1/audio/models` — all 47
non-English ones today. Sending it for English or on `simba-3.2` is rejected
with `pronunciations_unsupported`, both probed below; that is the provider's own
validation and the class passes the field through either way, as it does
`safety_identifier`.

### To consider
- **Word marks collapse in scripts without spaces** (medium, since 2026-10-28) — `_SpeechMarkAccumulator` joins marks that abut in the source text and releases a word only when the next character is whitespace or the text ends. Speechify's marks for Japanese, Chinese, Thai and the other scriptio-continua languages `simba-3.5` speaks abut throughout, so a whole utterance comes out as one mark at the first word's time. Probed: 12 marks for a 12-word English sentence, 1 for a two-sentence Japanese one, with audio fine in both. `add_word_timestamps` feeds bot-speaking text sync and word-level interruption tracking, so those are what degrade. — *Needs a call: what counts as a word boundary when the script has none — release each mark for those scripts, a script-aware rule, or state that CJK word tracking is unsupported.*
- **The language map covers 6 of 48 languages** (medium, since 2026-09-14) — `language_to_speechify_language` maps DE, EN, ES, FR, IT and PT, which were `simba-3.0`'s routes. `simba-3.5` speaks 48; every `Language` outside the six falls through `resolve_language` to its BCP-47 string and logs `not verified`. Synthesis is unaffected — `ja-JP` probed fine — but the warning is wrong for 42 documented languages, and the Pipecat docs page still lists the six. This is the earlier es-MX item, widened by `simba-3.5`. — *Needs a call: which tag each language gets — identity is right for es-MX and for the bare codes `simba-3.5` lists, but en-GB or pt-PT would be a locale substitution onto en-US/pt-BR and needs a stance.*
- **WebSocket streaming text input** (medium, since 2026-10-12) — `GET /v1/audio/stream/ws`, added 2026-10-08, accepts text as it is produced (`input.text`, `input.flush`, `input.close`) and speaks each completed sentence, where the HTTP class re-POSTs per aggregated utterance. With `speech_marks=true` word marks carry absolute times on one session timeline, which is what `_SpeechMarkAccumulator`'s `_cumulative_time` offsetting exists to reconstruct today. Settings are query-string parameters with the HTTP endpoint's names, so `_build_payload`'s logic transfers. The class name `SpeechifyHttpTTSService` already reserves the slot for a sibling. — *Needs a call: whether to add a websocket class at all, and what reconnect behavior the session caps (one concurrent request, 60 s idle close, 5-minute hard close) imply for a long call.*
- **Pinned version has no override and no owner** (low, since 2026-09-28) — `SPEECHIFY_API_VERSION` is the module constant `2026-09-30`; a workspace that must stay on an older version cannot opt out, and the constant advances only when someone edits it. Every version-gated behavior documented so far favors the current pin. — *Needs a call: whether the pin should be overridable at all, and who advances it as Speechify mints versions.*

Last run's `safety_identifier` gap is closed: pipecat-ai/pipecat#6143 merged on
2026-10-12. The default bump to `simba-3.5` came from a maintainer, not this
skill (9de5cf635, 2026-10-21), and matches Speechify's own recommendation —
`GET /v1/audio/models` marks `simba-3.5` `recommended` and nothing else.
`simba-3.0` stays the API's default when a request omits `model`, which this
service never does.

Three other October entries need nothing. Regional hosts (2026-10-17):
`eu.api.speechify.ai` and `us.api.speechify.ai` are optional, the `base_url`
constructor argument already reaches them, and the legacy `api.sws.speechify.com`
that stops serving on 2027-01-19 is not the default. SSML (2026-10-20):
`<prosody pitch>` and `<prosody volume>` are now applied on `simba-3.0`/`3.2`/`3.5`,
but they live inside `input` alongside the text, so no setting expresses them;
`<emphasis>` and emotion are still accepted and ignored. Character limits
(2026-10-14): the stream endpoints' 20,000-character ceiling now counts spoken
text only, and this service sends sentence-sized chunks.
