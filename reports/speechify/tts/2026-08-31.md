# Speechify TTS — 2026-08-31

Current: `simba-3.2` is Speechify's recommended English model, the whole
`/v1/audio/stream/with-timestamps` request schema is already reachable from
`Settings`, and nothing we ship is retiring. One item to consider.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **No pinned API version** (medium, since 2026-08-31) — the class posts to `/v1/audio/stream/with-timestamps` without a `Speechify-Version` header, which the versioning guide asks raw HTTP integrations to send; the server then uses the workspace's stored default, or the oldest supported version if the workspace has none, so two users on the same Pipecat version can get different shapes. Neither retirement now on the calendar (Simba 1.6 at version `2026-09-21` / switch-off 2026-11-21, voice-cloning consent at `2026-09-13`) affects this class. — *Needs a call: which date to pin, whether to let users override it, and who bumps it as Speechify mints new versions.*

| --------- | ------------------------ | -- | --------------- | ------------------------------------------------------------- |
| simba-3.2 | SpeechifyHttpTTSService  | ✅ | TTFB 359/499 ms | current default, `geffen_32`; audio and word marks both arrive |
| simba-3.0 | SpeechifyHttpTTSService  | ✅ | TTFB 345/335 ms | multilingual model, same curated voice, accepted              |
| simba-3.2 | SpeechifyHttpTTSService  | ✅ | TTFB 362 ms     | `loudness_normalization=True`, `text_normalization=True`      |
| simba-3.2 | SpeechifyHttpTTSService  | ✅ | TTFB 1114 ms    | `language=Language.FR` with an English voice is accepted, not a 400 |

Two interleaved rounds per model rather than a median of five: no default bump
is on the table, so the numbers only show both models work and neither is
anomalous. `probe.py run` cannot drive this class — it has no way to supply the
required `aiohttp_session` — so these came from an ad-hoc script in the scratch
directory that reuses `probe.py`'s pipeline harness.

## Sources
- https://docs.speechify.ai/build/guides/concepts/models — simba-3.2 recommended (English, curated voices), simba-3.0 the API default and multilingual, Simba 1.6 pair legacy
- `GET https://api.speechify.ai/v1/audio/models` — live catalogue: simba-3.2 `recommended`, simba-3.0 `default`, simba-english/simba-multilingual `deprecated` with `retired_at 2026-09-21` / `sunset_at 2026-11-21` and no `/v1/audio/stream/with-timestamps` in their `endpoints`
- https://docs.speechify.ai/build/api-reference/v1/audio/stream/with-timestamps — request schema is `input`, `voice_id`, `language`, `model`, `options.{loudness_normalization,text_normalization}`, `output_format`; the class builds all six, and its PCM rate tuple matches the `pcm_*` enum exactly. Emotion, pitch and rate are SSML in `input`, not request fields
- https://docs.speechify.ai/build/changelog/2026/9/21 — Simba 1.6 retired at version 2026-09-21, switched off 2026-11-21; migration is to simba-3.2 or simba-3.0
- https://docs.speechify.ai/build/changelog/2026/8/18, .../2026/8/17 — mp3 default bitrate and new `mp3_*_160` formats; PCM-only integrations unaffected
- https://docs.speechify.ai/build/changelog/2026/8/12 — synthesis text is screened, `400 content_policy_violation` before any audio
- https://docs.speechify.ai/build/changelog/2026/7/25 — canonical `Speechify-*` header names; legacy `X-` spellings work until 2027-07-24
- https://docs.speechify.ai/build/guides/concepts/api-versioning — `Speechify-Version` resolution order and the advice to send it from raw HTTP integrations
- probe.py sdk-versions — no SDK: the `speechify` extra is empty, the service talks HTTP through aiohttp
- probe.py list-models — exit 0 with "no model catalogue known for 'speechify'"; the catalogue above came from the live endpoint
