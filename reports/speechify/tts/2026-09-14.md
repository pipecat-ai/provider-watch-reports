# Speechify TTS — 2026-09-14

Current: no code change is warranted. Speechify's one new change since the last
run — `simba-3.2` dropping its registered-voice restriction — works through the
class untouched, and the two open items are hygiene.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **No pinned API version** (medium, since 2026-08-31) — the class posts to `/v1/audio/stream/with-timestamps` without a `Speechify-Version` header, which the versioning guide asks raw HTTP integrations to send; the server then uses the workspace's stored default, or the oldest supported version if the workspace has none, so two users on the same Pipecat version can get different response shapes. The endpoint itself is safe under an old pin — the guide lists "new endpoint or new path" as additive — and the Simba 1.6 retirement (version `2026-09-21`, switch-off 2026-11-21) covers models this endpoint never accepted. — *Needs a call: which date to pin, whether to let users override it, and who bumps it as Speechify mints new versions.*
- **`es-MX` not in the language map** (low, since 2026-09-14) — `simba-3.0`'s catalogue entry lists `en, de-DE, es-ES, es-MX, fr-FR, it-IT, pt-BR`; `language_to_speechify_language` maps only the six base codes, so `Language.ES_MX` falls through `resolve_language` to the identical string `es-MX` with a spurious `not verified` warning. Synthesis is unaffected (probed below). — *Needs a call: whether the map should carry regional keys at all — es-MX is an identity mapping, but the same question for en-GB or pt-PT is a substitution onto en-US/pt-BR and needs a stance.*
