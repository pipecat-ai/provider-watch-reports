# Simli video — 2026-09-01

Still nothing broken or retiring: the SDK, the pin and the service are unchanged, and the
one new finding is that Simli's session events never reach Pipecat.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **`enable_logging` does nothing** (medium, since 2026-08-31) — the constructor and the deprecated `InputParams` both take it and the docs page advertises it, but it is never passed to `SimliConfig` or `SimliClient`. simli-ai 2.x has no logging flag at all; the SDK logs through the stdlib logger named `simli_client`. — *Needs a call: deprecate the argument, or honour it by configuring that logger.*
- **Avatar model is not selectable** (medium, since 2026-08-31) — `SimliConfig.model` takes `SimliModels.fasttalk` (default) or `SimliModels.artalk`, and the value is posted to `/compose/token`. The service builds `SimliConfig` with only `faceId`, `maxSessionLength` and `maxIdleTime`, and pins `ServiceSettings(model=None)`, so artalk is unreachable. — *Needs a call: whether `Settings.model` maps onto the enum, and what a runtime settings update means when the config is built once in `__init__`.*
- **Session events are not wired up** (medium, since 2026-09-01) — `SimliClient.registerEventCallback` is documented for START, STOP, ERROR, SILENT and SPEAK; `SimliVideoService` registers none of them. Errors are caught only around `start()` and the `send`/`clearBuffer` calls, so a session Simli ends or errors mid-call just terminates the two stream iterators: the video stops, nothing is pushed upstream, and application code has no handler to hook. — *Needs a call: which events become Pipecat event handlers versus an internal `push_error` on ERROR/STOP, and whether SPEAK/SILENT add anything over the TTS frames the service already pushes.*
- **`handleSilence` is not reachable** (low, since 2026-08-31) — documented on `SimliConfig` and in the `/compose/token` body; off, the avatar freezes rather than idling when the buffer drains. — *Needs a call: same construction-time problem as the model setting.*
- **Transport and retry options are fixed** (low, since 2026-08-31) — `enableSFU=True` is hard-coded; `transport_mode` (P2P/LIVEKIT), `retry_count` and `retry_timeout` are not exposed. — *Needs a call: whether the LiveKit transport is wanted at all from Pipecat, which already owns the WebRTC leg.*
- **Simli's Pipecat page is stale** (low, since 2026-08-31) — it shows `SimliVideoService(SimliConfig(...))`, which the current constructor rejects. — *Needs someone to file it with Simli; the page is in their docs.*
