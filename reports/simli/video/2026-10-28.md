# Simli video — 2026-10-28

Simli's biggest release since the service was written: Trinity-2 avatars, framing and live
asset controls in the API, and simli-ai 2.1 on 2026-10-27. Open PR #6400 (opened the same day)
already carries the pin bump and the two integration gaps Simli's own docs call out; review it
rather than opening anything new.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6400 — Trinity-2 framing, OpenAI Live audio, video from connect, and simli-ai 2.1 (open since 2026-10-27, supersedes #5033)

### To consider
- **Trinity-2's live controls are not reachable** (medium, since 2026-10-28) — the API lets a running session move the camera (`CAM_`), swap a background (`BG_`) and a foreground (`FG_`), and simli-ai 2.1 wraps all three as `setCamera(CameraSetting, lerp_seconds=...)`, `setBackground(id)` and `setForeground(id)`. PR #6400 adds the session's *starting* framing only, so once the session is up none of it can change. — *Needs a call: whether a mid-session control becomes a frame, a method, or both; these are the first Simli controls that act during a session, and AGENTS.md prefers a frame.*
- **`enable_logging` does nothing** (medium, since 2026-08-31) — the constructor and the deprecated `InputParams` both take it, but it is never passed to `SimliConfig` or `SimliClient`. simli-ai 2.1's reference documents no logging option; the SDK logs through the stdlib logger named `simli_client`. — *Needs a call: deprecate the argument, or honour it by configuring that logger.*
- **Session events are not wired up** (medium, since 2026-09-01) — 2.1 improves the edges the service already guards: `start()` raises Simli's own reason (invalid API key, unknown face ID, no minutes) instead of `Failed To Initialize SimliClient`, and `send()`/`sendImmediate()` raise rather than logging, so both reach `push_error`. What is still silent is a session Simli ends or errors *mid-call*: no `registerEventCallback` is registered for START/STOP/ERROR/SILENT/SPEAK, the new `stopReason` and `error` properties are unread, and the two stream iterators simply end — the avatar freezes with nothing upstream. — *Needs a call: which events become Pipecat event handlers versus an internal `push_error` on ERROR/STOP, and whether SPEAK/SILENT add anything over the audio frames the service already pushes.*
- **`handleSilence` is not reachable** (low, since 2026-08-31) — documented on `SimliConfig` and in the `/compose/token` body (default `true`); off, the avatar freezes rather than idling when the buffer drains. — *Needs a call: whether it joins the constructor the way PR #6400's `framing=` does, both being fixed at session start.*
- **Transport and retry options are fixed** (low, since 2026-08-31) — `enableSFU=True` is hard-coded; `transport_mode` (P2P/LIVEKIT) and `retry_count` are not exposed. `retry_timeout` has stopped mattering: 2.1 deprecates and ignores it in favour of exponential backoff with jitter. — *Needs a call: whether the LiveKit transport is wanted at all from Pipecat, which already owns the WebRTC leg.*

### Resolved since the last run
- **Avatar model is not selectable** (was medium, since 2026-08-31) — dropped. simli-ai 2.1 marks `SimliConfig.model` "Deprecated, ignored by the server. Every session runs fasttalk", and `StartStreamingSessionRequest` still has no `model` property. `artalk` is unreachable because Simli retired it, not because the service hard-codes `model=None`.
- **Simli's Pipecat page documents a constructor we no longer have** (was low, since 2026-08-31) — dropped. The page was rewritten for the Trinity-2 release and now uses `SimliVideoService(api_key=..., face_id=..., max_session_length=..., max_idle_time=...)`, which matches the class.
