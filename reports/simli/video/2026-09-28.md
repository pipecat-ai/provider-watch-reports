# Simli video — 2026-09-28

Nothing is retiring and nothing changed on either side: simli-ai is still 2.0.3 and
`src/pipecat/services/simli/video.py` is untouched since 2026-08-11. One new gap: the SDK's
connect retry imports `livekit`, which `pipecat-ai[simli]` does not install.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **The SDK's connect retry needs livekit** (medium, since 2026-09-28) — `SimliClient.start()` catches a P2P connect failure, flips `transport_mode` to `LIVEKIT` and calls itself; `simli/transports/livekit_transport.py` raises `RuntimeError("livekit not installed, please uv add \"simli-ai[livekit]\" ...")` at import. Our extra is `simli-ai~=2.0.1` with no livekit, and pipecat only pulls livekit in for its own `livekit`/`heygen` extras, so any transient P2P failure reaches `_start_connection`'s handler as a missing-dependency message and the real reason is lost. — *Needs a call: require `simli-ai[livekit]` in the extra (a livekit wheel in a video-only install), or pass `retry_count=1` so the P2P failure is reported as itself.*
- **`enable_logging` does nothing** (medium, since 2026-08-31) — the constructor and the deprecated `InputParams` both take it and the docs page still advertises it, but it is never passed to `SimliConfig` or `SimliClient`. simli-ai 2.0.3 has no logging flag; the SDK logs through the stdlib logger named `simli_client` (`simli/logger.py`). — *Needs a call: deprecate the argument, or honour it by configuring that logger.*
- **Avatar model is not selectable** (medium, since 2026-08-31) — `SimliConfig.model` defaults to `SimliModels.fasttalk` and also accepts `artalk`; the service builds `SimliConfig` with only `faceId`, `maxSessionLength` and `maxIdleTime` and pins `ServiceSettings(model=None)`, so artalk is unreachable. The SDK does post the whole config (`self.config.__dict__`) to `/compose/token`, but Simli's published `StartStreamingSessionRequest` schema has no `model` property, so whether the server acts on it is unverified. — *Needs a call: confirm with Simli that `/compose/token` honours `model`, then decide whether `Settings.model` maps onto the enum and what a runtime settings update means when the config is built once in `__init__`.*
- **Session events are not wired up** (medium, since 2026-09-01) — `registerEventCallback` is documented for START, STOP, ERROR, SILENT, SPEAK and more; `SimliVideoService` registers none. Errors are caught only around `start()` and the `send`/`clearBuffer` calls, so a session Simli ends or errors mid-call just terminates the two stream iterators: video stops, nothing goes upstream, no handler for app code. — *Needs a call: which events become Pipecat event handlers versus an internal `push_error` on ERROR/STOP, and whether SPEAK/SILENT add anything over the TTS frames the service already pushes.*
- **`handleSilence` is not reachable** (low, since 2026-08-31) — documented on `SimliConfig` and in the `/compose/token` body; off, the avatar freezes rather than idling when the buffer drains. — *Needs a call: same construction-time problem as the model setting.*
- **Transport and retry options are fixed** (low, since 2026-08-31) — `enableSFU=True` is hard-coded; `transport_mode` (P2P/LIVEKIT), `retry_count` and `retry_timeout` are not exposed. — *Needs a call: whether the LiveKit transport is wanted at all from Pipecat, which already owns the WebRTC leg.*
- **Simli's Pipecat page is stale** (low, since 2026-08-31) — it still shows `SimliVideoService(SimliConfig(...))`, which the current constructor rejects; the repo's own `examples/video-avatar/video-avatar-simli-video-service.py` uses the correct `api_key`/`face_id` form. — *Needs someone to file it with Simli; the page is in their docs.*
