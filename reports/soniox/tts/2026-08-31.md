# Soniox TTS — 2026-08-31

Current: `tts-rt-v2` is Soniox's only active TTS model and the one we ship; a branch adds the one config field the API has and we lack, and the idle-reconnect churn is the finding worth a maintainer's eyes.

## What's new for Pipecat

### PRs
- `provider-watch/soniox-tts-reduce-silence` — review: `git show provider-watch/soniox-tts-reduce-silence` — Add a reduce_silence setting to SonioxTTSService

### To consider
- **Idle connections churn** (medium, since 2026-08-31) — Soniox closes a connection that has not started a stream about 10s after connect, and says keepalives do not authenticate it; a bare socket sending only `{"keep_alive": true}` was closed at 11.1s with 1001 "going away". `SonioxTTSService` connects in `setup()` and sends the first config only when a turn context is created, so a bot that idles before (or between) speaking runs a connect → 11s → "connection closed by server" → reconnect cycle for as long as it stays quiet. Synthesis after the idle still works, and the 10s lifetime is above the quick-failure floor (5s) so the service is never marked unusable — the cost is churn, warning-level log noise, and a reconnect that can land while a turn is starting (`_disconnect_websocket` clears the active audio context and `_configured_contexts`). — *Needs a call: the fix is a lifecycle change — open the socket on the first stream instead of in `setup()`, or hold a stream open — not a settings pass-through.*
- **Compressed audio formats** (low, since 2026-08-31) — Soniox takes `bitrate` alongside `sample_rate` for mp3/opus/aac; `audio_format` is a constructor argument that accepts those values, but `bitrate` is never sent. — *Needs a call: the receive path wraps Soniox bytes in `TTSAudioRawFrame` with no decoding, so compressed output is unusable downstream regardless; the choice is exposing `bitrate` or rejecting non-PCM formats.*
- **`client_reference_id`** (low, since 2026-08-31) — a documented optional string recorded with the request in Soniox's usage logs, with no Settings field or constructor argument. — *Needs a call: whether per-request usage tagging is something Pipecat should carry.*
- **Docs name a v1-only voice** (low, since 2026-08-31) — the Pipecat docs page for the service uses `Maya` as its voice example; `Maya` is in the `tts-rt-v1` catalogue only, not `tts-rt-v2`. — *Needs a call: the page lives in the docs repo, so it is a separate change from anything here.*

Ad-hoc checks (`.pw-scratch/`): a bare WebSocket sending only keepalives was closed by Soniox at 11.1s; the real service, idled 25s before its first `TTSSpeakFrame`, logged two "connection closed by server" reconnect cycles and then synthesized normally. `GET https://api.soniox.com/v1/tts-models` supplied the catalogue, voice lists and capability flags. All 63 `tts-rt-v2` language codes are produced by `language_to_soniox_tts_language`; nothing is unreachable.
