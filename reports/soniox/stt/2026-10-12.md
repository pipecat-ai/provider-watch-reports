### To consider
- **Real-time translation** (medium, since 2026-08-25) — v5 does transcription and translation on one stream via a `translation` config object (`one_way` with `target_language`, or `two_way` with `language_a`/`language_b`); `SonioxSTTSettings` has no field for it and `_connect_websocket` never sends the key. It is still the only documented key in the WebSocket config reference the service does not send. — *Needs a call: translation tokens arrive interleaved with the originals, are distinguished only by `translation_status`, and carry no `start_ms`/`end_ms`, so `_receive_messages` would have to decide whether they become their own frames or are dropped from the transcript — not a pass-through field.*

Soniox now marks the start request's `api_key` field deprecated and will refuse connections that authenticate only that way from 15 January 2027. `SonioxSTTService` already sends the key in the `Authorization` header on connect and never puts it in the config message, so nothing is affected — noted so a future run does not re-derive it.
