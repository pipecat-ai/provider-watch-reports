# Soniox STT — 2026-09-01

Current: `stt-rt-v5` is still Soniox's recommended real-time model, nothing is retiring, and the only proposed change is the docstring correction last run's PR cap held back.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5566 — Describe Soniox context by its two accepted forms

### To consider
- **Real-time translation** (medium, since 2026-08-25) — v5 does transcription and translation on one stream via a `translation` config object (`one_way` with `target_language`, or `two_way` with `language_a`/`language_b`); `SonioxSTTSettings` has no field for it and `_connect_websocket` never sends the key. — *Needs a call: translation tokens arrive interleaved with the originals and are distinguished only by `translation_status`, with no timestamps, so `_receive_messages` would have to decide whether they become their own frames or are dropped from the transcript — not a pass-through field.*

The context-docstring branch is the same change last run left; it carried `capped: true` and was never published, and no branch or PR for it survives, so it is rebuilt on today's `main`. Probes below settle both forms of `context` against `stt-rt-v5`, so the string branch in `_connect_websocket` stays and only the wording changes.
