# Soniox STT — 2026-11-09

Current: Soniox released stt-rt-v6 on 2026-11-03 and Pipecat adopted it on 2026-11-05 (default model, `enable_agent_text_input`, `enable_echo_cancellation`, `agent_text_lead_ms`), so the headline item from the last run is closed in code and no branch is proposed.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Real-time translation** (medium, since 2026-08-25) — v6 does transcription and translation on one stream via a `translation` config object (`one_way` with `target_language`, or `two_way` with `language_a`/`language_b`); `SonioxSTTSettings` has no field for it and `_connect_websocket` never sends the key. It remains the only documented WebSocket config key the service does not send. — *Needs a call: translation tokens arrive interleaved with the originals, are distinguished only by `translation_status`, carry no timestamps, and the docs offer no way to put them on a separate channel or suppress the originals, so `_receive_messages` would have to decide whether they become their own frames or are dropped from the transcript — not a pass-through field.*
- **Pipecat docs page is a release behind** (low, since 2026-11-09) — https://docs.pipecat.ai/api-reference/server/services/stt/soniox still gives `stt-rt-v5` as the default and its Settings table stops at `client_reference_id`, so the v6 agent-text settings are undocumented. — *Needs a call: the page is in the docs repo, outside this one, so somebody has to carry the edit there.*

`stt-rt-v5` is deprecated with removal on 2026-12-15, after which requests route to v6 automatically. Pipecat's default is already v6; v5 appears only in `tests/test_soniox_stt.py`, where it stands for "a model without agent text input" and never reaches the network, so the removal date needs no change here.

The start request's `api_key` field stays deprecated, with connections authenticating only that way refused from 2027-01-15. `SonioxSTTService` sends the key in the `Authorization` header on connect and never puts it in the config message, so nothing is affected — noted again so a future run does not re-derive it.
