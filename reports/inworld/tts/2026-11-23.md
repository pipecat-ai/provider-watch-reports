# Inworld TTS — 2026-11-23

Nothing to review: `inworld-tts-2` stays the default, both classes work, and Inworld has shipped no TTS API change since the 2026-10-28 Reasoning post. The eight carried gaps all wait on a maintainer's call.

## What's new for Pipecat

PR 6654 merged on 2026-11-09, so `enhance_generation` is now an `InworldTTSSettings` field and that gap is closed. The catalogue is unchanged (`inworld-tts-2` flagship, `inworld-tts-2-flash`), the release notes still end at 2026-09-11, and the HTTP and WebSocket request schemas read the same as last run.

The only provider news since is research, not API: Inworld open-sourced its Voice Isolator and SAVA turn-detection models on 2026-11-18 and published the TTS-2 technical report. Neither touches these classes.

This run quantified last run's headline gap. Reasoning is live on the streaming endpoint and returns the instruction it wrote, but it costs roughly 0.4 s of extra time to first audio on a line Inworld has not seen before — the number that matters in a realtime pipeline, since every line in a conversation is new. Repeating the same text with the same `reasoningContext` returns the identical instruction at baseline latency, so Inworld caches the generated instruction.

One thing for the next researcher: the WebSocket reference describes how `languageSettings`, `synthesisContext` and `pronunciationDictionarySettings` behave "in `updateConfig`" without defining that message anywhere. If it is real and documented later, it is the way to change settings mid-call — `InworldTTSService._update_settings` currently disconnects and reconnects the socket on any settings change.

Nothing.

### To consider
- **Reasoning** (medium, since 2026-11-09) — `synthesisContext.reasoning: REASONING_ON` has Inworld write the delivery direction for each line itself, with `reasoningContext` (≤600 characters) describing the scene or character and the instruction returned as `reasoningInstruction`. Measured cost on a fresh line: 661 ms and 700 ms to first audio against 242 ms and 364 ms with reasoning off. HTTP endpoints only; the WebSocket create config has no reasoning field. — *Needs a call: whether a realtime TTS service should offer a pre-synthesis model step that adds about 0.4 s to the first audio of every new line, and how it should sit against the inline `[tags]` the expression adapter emits, which override it.*
- **Synthesis context** (medium, since 2026-09-01) — `synthesisContext.previousRequests`, a chronological list of up to 5 earlier texts (2,000 characters combined), which Inworld says improves quality "especially for short or ambiguous input text". Documented on both transports; neither class sends it. — *Needs a call: where the history lives and how far back it goes; this is service state, not a pass-through field.*
- **Text normalization on the HTTP class** (medium, since 2026-09-14) — `applyTextNormalization` is documented on both transports, but only `InworldTTSService` sends it; `InworldHttpTTSService` has no way to reach it. — *Needs a call: match the WebSocket class with a constructor argument, or move both onto the shared `InworldTTSSettings`; a Settings field alone would give the WebSocket class two ways to set the same thing.*
- **Workspace pronunciation dictionaries** (medium, since 2026-11-09) — `pronunciationDictionarySettings.dictionaries` (1–3 workspace resource names, in priority order) and `enableCustomPronunciation`, both `inworld-tts-2` with a `language` set. Pipecat's inline-IPA path still works, so this is an alternative rather than a hole. — *Needs a call: a shape for a nested list of workspace resource names, plus a stance on the documented mutual exclusion between the two fields.*
- **Language candidates** (low, since 2026-11-09) — the WebSocket create config takes `languageSettings.candidates`, up to 10 BCP-47 tags to constrain auto-detection; the service sends a single `language` or nothing. — *Needs a call: whether a WebSocket-only language shortlist belongs on the shared Settings beside the existing single `language`, and whether it takes `Language` values or raw tags.*
- **Docs page model list** (low, since 2026-09-01) — docs.pipecat.ai still offers `inworld-tts-1.5-max` and `inworld-tts-1.5-mini`, both deprecated at Inworld, and does not mention `inworld-tts-2-flash`. — *Needs a call: the page lives in the docs repo, so someone with access there has to update it.*
- **Inert `temperature` in the examples** (low, since 2026-09-01) — `realtime-ultravox-text.py` passes `temperature=1.1` as a constructor argument the service does not have, so `**kwargs` swallows it; `voice-inworld.py` sets it through `Settings`, where it reaches the request but Inworld documents `temperature` as ignored on `inworld-tts-2`. Either way the examples suggest a knob that does nothing. — *Needs a call: whether to drop `temperature` from both examples rather than move the first onto `Settings`.*
- **`bitRate` and character timestamps** (low, since 2026-09-01) — `audioConfig.bitRate` is not settable for the compressed encodings `encoding=` already allows, and `timestampType` is hard-coded to `WORD` though the API also offers `CHARACTER`. — *Needs a call: whether either is worth surfacing, given word timestamps are what the word-timestamp plumbing consumes.*

## Verification

| model               | class                 | ok | latency                | note                                    |

| inworld-tts-2       | InworldTTSService     | ✅ | TTFB 148 ms            | `probe.py run`, single sample           |
| inworld-tts-2-flash | InworldTTSService     | ✅ | TTFB 110 ms            | same call, works unchanged              |
| inworld-tts-2       | InworldHttpTTSService | ✅ | TTFB 185 ms / 198 ms   | two samples, scratch harness            |

No default bump is proposed, so these are single samples rather than medians.

Behind the Reasoning numbers: four direct calls to the streaming endpoint, two sentences × reasoning off/on. Off — 242 ms and 364 ms to first audio. On, first time for that text — 661 ms and 700 ms, each returning a `reasoningInstruction` (for instance "Matter-of-fact and observant, like a librarian sharing a useful tip."). Repeating the first sentence with the same `reasoningContext` returned the identical instruction at 248 ms, so the instruction is cached per text and context.

`probe.py` still cannot construct `InworldHttpTTSService`, which has a required `aiohttp_session`; the HTTP rows come from a scratch wrapper around `probe.py`'s `_run_pipeline`.
