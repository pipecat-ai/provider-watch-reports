# Inworld TTS — 2026-09-01

`inworld-tts-2` remains the model to default to; the branch picks up Inworld's new `instruction` steering field and retires `inworld-tts-1` from an example.

## What's new for Pipecat

Inworld shipped `inworld-tts-2-flash` (GA 2026-08-09, 20 ms server-side P90 TTFB, no steering or professional cloning) and a request-level `instruction` field for steering (2026-08-06). Flash needs no code change — neither class gates the model string, and both synthesized with it on the first try. Flash is the cheap/fast variant, not a successor: Inworld still positions `inworld-tts-2` as the quality model, so the default stays.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5542 — Add an `instruction` Settings field to the Inworld TTS services and drop a retired model string from an example

### To consider
- **Synthesis context** (medium, since 2026-09-01) — the HTTP endpoints accept `synthesisContext.previousRequests`, a chronological list of the text already synthesized in this conversation, which Inworld says improves quality "especially for short or ambiguous input text" — the sentence-at-a-time traffic a pipeline produces. Neither class sends it. — *Needs a call: where the history lives and how far back it goes; this is service state, not a pass-through field.*
- **`enhanceGeneration`** (low, since 2026-09-01) — a boolean that denoises the synthesized audio, documented on the HTTP synthesize endpoints and defaulting to false, with no Settings field. — *Needs a call: whether a second HTTP-only field on the shared `InworldTTSSettings` is acceptable, given the WebSocket API does not document it.*
- **Docs page model list** (low, since 2026-09-01) — docs.pipecat.ai still offers `inworld-tts-1.5-max` and `inworld-tts-1.5-mini`, both deprecated at Inworld, and does not mention `inworld-tts-2-flash`. — *Needs a call: the page lives in the docs repo, so someone with access there has to update it.*
- **Dropped `temperature` in the Ultravox example** (low, since 2026-09-01) — `realtime-ultravox-text.py` passes `temperature=1.1` to `InworldTTSService`, which has no such constructor argument; `**kwargs` swallows it and the setting stays `None`. — *Needs a call: the fix is to move the call to `settings=InworldTTSService.Settings(...)`, which changes what the example does (temperature would start applying) rather than just correcting a value.*
- **`bitRate` and character timestamps** (low, since 2026-09-01) — `audioConfig.bitRate` is not settable for the compressed encodings `encoding=` already allows, and `timestampType` is hard-coded to `WORD` though the API also offers `CHARACTER`. — *Needs a call: whether either is worth surfacing, given word timestamps are what the word-timestamp plumbing consumes.*

## Verification

| model                              | class                  | ok | latency      | note                                                          |
| ---------------------------------- | ---------------------- | -- | ------------ | ------------------------------------------------------------- |
| inworld-tts-2                      | InworldTTSService      | ✅ | TTFB 83 ms   | single sample                                                  |
| inworld-tts-2-flash                | InworldTTSService      | ✅ | TTFB 160 ms  | works unchanged; single sample                                 |
| inworld-tts-2                      | InworldHttpTTSService  | ✅ | TTFB 113 ms  | single sample                                                  |
| inworld-tts-2-flash                | InworldHttpTTSService  | ✅ | TTFB 277 ms  | works unchanged; single sample                                 |
| inworld-tts-2 + `instruction`      | InworldHttpTTSService  | ✅ | TTFB 152 ms  | branch build; `"speak loudly and urgently"` accepted, audio returned |

No default bump is proposed, so these are single samples rather than medians.

Two harness notes, neither a finding about Inworld: `probe.py run --service InworldTTSService` synthesizes and reports TTFB but never exits — with no transport in the probe pipeline, no `BotStoppedSpeakingFrame` arrives to lift the `pause_frame_processing=True` pause, so `EndFrame` never traverses (about twenty other TTS services set the same flag). And `probe.py` cannot construct `InworldHttpTTSService` at all, since it has a required `aiohttp_session`; the HTTP rows above come from a wrapper in the scratch dir that reuses `probe.py`'s harness and supplies the session.
