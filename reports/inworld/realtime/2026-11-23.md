# Inworld Realtime — 2026-11-23

A branch exposes Inworld's four session generation controls, reasoning effort included, which
also unblocks the `low`-effort configuration the default-model decision turns on. That decision
itself is still open, and its latency case changed: `openai/gpt-6-luna:fast` now measures 13%
*faster* than the current default, reversing last run's reading. One new gap: back-channel audio
can be turned on today through the `provider_data` pass-through and is then silently dropped.
`LLMMessagesAppendFrame` is no longer a gap — commit 7909249f0 lets it pass through and the
service answers the appended message from the context.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6970 — Expose Inworld Realtime's session generation controls

### To consider
- **Default retires 2027-01-14** (high, since 2026-11-09) — OpenAI schedules `gpt-4.1-mini-2025-04-14` for shutdown on 2027-01-14 with `gpt-6-luna` as the replacement, and Inworld's router removes models once upstream retires them. Re-measured this run: median TTFAT 692 ms for `openai/gpt-4.1-mini` (5 turns), 868 ms for `openai/gpt-6-luna` (3 turns), 604 ms for `openai/gpt-6-luna:fast` (5 turns). The `:fast` variant is now inside the band and in fact ahead of the default, where last run it measured +19%; the contradiction is between runs on the same method, and the fresher figure has the larger sample. aiewf-eval still ranks `gpt-6-luna (low)` at 91.8% against `gpt-4.1-mini` at 81.8% and has no row for `:fast`. The branch on this run makes `low` effort selectable, so the benchmarked configuration is now reachable. `examples/realtime/realtime-inworld-locally-driven-turns.py` pins the same model string. — *Needs a call: take `openai/gpt-6-luna` and accept ~25% more first-token latency for the benchmarked quality gain, or take `openai/gpt-6-luna:fast` on measured latency without a benchmark row.*
- **Text-only output is silent** (high, since 2026-11-09) — re-confirmed: with `output_modalities=["text"]` the server streamed `response.output_text.delta` ×7 and `response.output_text.done`, and no audio-transcript deltas. Neither type is in `_server_event_types`, so `parse_server_event` returns `None`, the receive loop logs them as unhandled, and `_push_output_transcript_text_frames` is never reached — the pipeline sees no `LLMTextFrame` and no `TTSTextFrame`. The fix is an event model for the two types plus a dispatch branch. — *Needs a call: whether a text-only session should push `TTSTextFrame` alongside `LLMTextFrame`, as the audio path does, when there is no audio to aggregate against.*
- **Back-channel audio dropped** (medium, since 2026-11-23) — Inworld's back-channel feature interjects short acknowledgements ("uh-huh") while the user speaks. It is opt-in through `providerData.backchannel.enabled`, which a user can already set through the merged `provider_data` pass-through — a probe turned it on and the server accepted and echoed the config. The audio arrives on `response.backchannel.audio.delta` / `.done` / `.skipped`, grouped by `backchannel_id` and none of them modelled, so it is dropped on the floor. — *Needs a call: how a second, concurrent audio stream reaches the output transport, given Pipecat has no back-channel bucket and the interjection plays over the user's own speech.*
- **`response.speak` unreachable** (medium, since 2026-11-09) — supply text and the session's TTS speaks it verbatim, no LLM call, with optional `force_uninterruptible` and `metadata`. Pipecat already has the frame for this, `TTSSpeakFrame`, and the service ignores it. — *Needs a call: whether a realtime LLM service should consume `TTSSpeakFrame` at all (none does today), and how `force_uninterruptible` squares with Pipecat's own `interruptible` flag.*
- **Images unreachable** (medium, since 2026-09-14) — `conversation.item.create` takes `input_image` parts (data URL or URL, `detail` low/high/auto). `ItemContent.type` is a closed `Literal` with no image member, there are no `image_url`/`detail` fields, and `llm.py` has no image path. — *Needs a call: whether a realtime service consumes `InputImageRawFrame` directly or takes images only from the `LLMContext`, and whether an image append should trigger a response.*
- **Per-modality usage dropped** (low, since 2026-09-01) — `response.done` carries `usage.llm.model`, `usage.tts`, `usage.input_token_details` (`cached_tokens`, `cache_write_tokens`) and `usage.output_token_details`; `_handle_evt_response_done` reads only the three totals. — *Needs a call: which Pipecat metric a cascaded realtime service reports TTS/STT seconds and cached tokens under.*
- **Idle timeout has no effect in the pipeline** (low, since 2026-11-09) — `TurnDetection.idle_timeout_ms` is settable, but the server's `input_audio_buffer.timeout_triggered` is unmodelled and dropped, so arming the timer changes nothing downstream. `input_audio_buffer.turn_suggestion` / `.turn_suggestion_revoked`, `output_audio_buffer.*`, `rate_limits.updated` and `conversation.item.deleted` / `.retrieved` / `.truncated` are unmodelled too. — *Needs a call: which Pipecat frame an idle timeout becomes, given the service already proposes turn boundaries.*
- **Generic `LLMSettings` names still warn** (low, since 2026-09-01) — with the branch applied the controls are reachable under Inworld's names on `SessionProperties`, but a user who sets the inherited `max_tokens`, `top_p`, `top_k`, penalties or `seed` still gets an unhandled-setting warning and no effect. — *Needs a call: map the generic names onto Inworld's, or document them as unsupported for this service.*

`probe.py run` is connect-only for a realtime class and reports no latency, so the latency rows
were measured ad-hoc: one text turn per connection, models interleaved, timed from
`response.create` to the first text delta, with the same session properties the service sends.
`probe.py run --setting session_properties=...` cannot drive this unit — the probe passes the
JSON through as a plain dict and the Settings dataclass does not coerce it — which is why the
branch's wire bytes were checked by serializing `SessionUpdateEvent` from the worktree and
sending that.
