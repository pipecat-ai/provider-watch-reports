# Cerebras LLM — 2026-10-12

Nothing to change: the catalogue, the recommended model and the service are all unchanged since the last run; the one new fact is an aiewf-eval row for `qwen-3.8-27b` that makes it a real, if slower, default candidate.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **qwen-3.8-27b as a default candidate** (medium, since 2026-09-14) — the medium-context leaderboard now has `qwen3.8-27b (thinking off, FP8)` at 98.2% / 649 ms P50 against `gpt-oss-120b (groq)` at 86.3% / 98 ms, so the quality case that was missing last run exists. Against it: Cerebras names qwen-3.8-27b as `gemma-4-31b`'s replacement and still recommends `gpt-oss-120b`, which is not deprecated; Cerebras serves qwen with reasoning `high` by default while every benchmarked row is thinking-off; and on Cerebras it is slower than the current default on both prompts (500 ms vs 128 ms trivial, 323 ms vs 148 ms reasoning, medians of 5), 217 ms with reasoning disabled. — *Needs a call: whether 12 points of pass rate is worth roughly 90 ms of TTFAT, and whether a bump would have to pin `reasoning_effort="none"` to match the benchmarked configuration.*
- **Cerebras-only fields need the `extra_body` nesting** (low, since 2026-09-14) — a bare Cerebras-only key in `Settings.extra` still raises `TypeError` before the request leaves; the same key under `extra={"extra_body": {...}}` reaches the API. Now also covers `min_completion_tokens`/`min_tokens`, which the API reference documents as Cerebras-specific. — *Needs a call: the behavior is inherited from the shared OpenAI base class, so the fix belongs to the openai/llm unit, not here.*

The previous report's trivial-prompt latency ordering did not reproduce; both measurements are recorded above and in the table rather than flipping the verdict.
