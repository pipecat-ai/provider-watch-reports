# Cerebras LLM — 2026-10-28

Nothing to change: `gpt-oss-120b` stays the default. The one new fact is on the benchmark side — aiewf-eval withdrew the current default's row, which changes the shape of the qwen-3.8-27b question rather than answering it.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **qwen-3.8-27b as a default candidate** (medium, since 2026-09-14) — the leaderboard comparison that made this an item has lost one side: `gpt-oss-120b (groq)` was archived on 2026-10-17 at the maintainer's request (last published 86.3% / 98 ms, with the archive flagging an unresolved cohort mapping behind the latency), and the qwen rows were rescored down to 96.0% (FP8, Baseten) and 95.1% (NVFP4, local). Cerebras still calls qwen-3.8-27b the replacement for `gemma-4-31b`, not for `gpt-oss-120b`, which is neither deprecated nor superseded. The previous report's latency objection does not survive re-measurement: two repeat-5 runs minutes apart put the models on opposite sides of each other on the trivial prompt, and the reasoning prompt is a tie — Cerebras's shared tier is too noisy here to rank them. — *Needs a call: whether a bump may proceed against a default whose benchmark row has been withdrawn while the provider names no successor, and whether it would have to pin `reasoning_effort="none"` to match the benchmarked configuration.*
- **Cerebras-only fields need the `extra_body` nesting** (low, since 2026-09-14) — a bare Cerebras-only key in `Settings.extra` still raises `TypeError` before the request leaves; the same key under `extra={"extra_body": {...}}` reaches the API. — *Needs a call: the behavior is inherited from the shared OpenAI base class, so the fix belongs to the openai/llm unit, not here.*
