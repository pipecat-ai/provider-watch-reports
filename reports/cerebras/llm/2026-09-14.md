# Cerebras LLM — 2026-09-14

Nothing to fix: Cerebras retired `gemma-4-31b` from public endpoints on 2026-09-03, but nothing in Pipecat referenced it, and the default `gpt-oss-120b` is still the model Cerebras recommends.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **qwen-3.8-27b as a default candidate** (low, since 2026-09-14) — Cerebras added it on 2026-09-03 as `gemma-4-31b`'s replacement, not `gpt-oss-120b`'s; the deprecation page still names `gpt-oss-120b` as the recommended model. It works as-is through the thin wrapper and is faster on a trivial prompt (TTFAT 186 ms vs 438 ms, medians of 5) but not on a reasoning prompt (385 ms vs 339 ms, medians of 3). — *Needs a call: aiewf-eval's medium-context leaderboard has no `qwen-3.8-27b` row, so there is no quality evidence for a bump; the leaderboard gets re-read next run.*
- **Cerebras-only fields need the `extra_body` nesting** (low, since 2026-09-14) — `Settings.extra` is merged into the OpenAI SDK's `create()` kwargs, so a bare Cerebras-only key raises `TypeError` before the request leaves; the same key under `extra={"extra_body": {...}}` reaches the API. This covers `reasoning_format`, `clear_thinking`, `prompt_cache_key`, `queue_threshold`, `service_tier` and `prediction`. — *Needs a call: the behavior is inherited from the shared OpenAI base class, so the fix belongs to the openai/llm unit, not here.*

Dropped from the previous report: "gemma-4-31b may be the better voice default" — the model 404s on the public endpoint as of this run, so the question is moot.
