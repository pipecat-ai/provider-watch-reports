# AWS Polly TTS — 2026-08-31

Nothing is retired or broken and the class synthesizes fine; the locale PR is open and the rest of the gap list is Polly's newer engines being held back by our own buffered request path.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5510 — Map Language.EN_IE and Language.EN_SG for AWS Polly (open)

### To consider
- **Buffered response read** (medium, since 2026-08-31) — `run_tts` calls `await stream.read()` before yielding any frame, so TTFB equals full synthesis time. An ad-hoc probe against `SynthesizeSpeech` measured the first chunk of generative audio at 182 ms against 1193 ms for the full read; through the class, generative TTFB is 671 ms (median of 5) versus 239 ms for standard. — *Needs a call: yielding partial audio changes when the first `TTSAudioRawFrame` appears and how the resampler is fed, so it is a rework of `run_tts`, not a value change.*
- **Bidirectional streaming API** (medium, since 2026-08-31) — `StartSpeechSynthesisStream` (GA 2026-03-19, generative engine) keeps an HTTP/2 connection open, takes text as it is produced and returns audio as it is synthesized. botocore carries the model but strips the operation off the Polly client (`remove_polly_start_speech_synthesis_stream` in `botocore/handlers.py`), so aiobotocore cannot reach it; AWS publishes the smithy client `aws_sdk_polly` 0.11.0 instead. — *Needs a call: this is a new service class plus a new SDK dependency, the same shape as the `aws-nova-sonic` extra.*
- **Default engine is standard** (medium, since 2026-08-31) — with `engine` unset Polly uses the standard concatenative engine. Neural is the same latency in our probe (242 ms vs 239 ms, medians of 5) and Joanna supports it, but it costs $16 per 1M characters against $4. — *Needs a call: changing the default multiplies every user's Polly bill and standard-only voices would start erroring.*
- **LanguageCode not exposed** (low, since 2026-08-31) — bilingual voices (Aditi, Kajal, Hala, Zayd) select their language from the request's `LanguageCode`; the service only wraps text in an SSML `<lang>` tag. — *Needs a call: whether the existing `language` setting should also drive `LanguageCode`, or a separate field is added that can disagree with it.*
- **PCM caps output at 16 kHz** (low, since 2026-08-31) — `OutputFormat` is fixed to `pcm`, whose only valid sample rates are 8000 and 16000; neural, long-form and generative voices are natively 24 kHz and only deliver that through mp3/ogg. Polly also added `mulaw`/`alaw` output on 2026-03-25, which telephony pipelines could take directly. — *Needs a call: 24 kHz means decoding mp3 or ogg inside the service.*
- **No speech marks** (low, since 2026-08-31) — `SpeechMarkTypes` would give word timestamps, but only from a separate `json`-format request. — *Needs a call: whether a second billed synthesis per utterance is acceptable.*
