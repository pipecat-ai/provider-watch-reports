# AWS Polly TTS — 2026-10-28

Nothing to act on: Polly's one change this period is 10 new generative voices plus a GovCloud region (2026-10-21/22), and probes confirm the new voices synthesize through `AWSPollyTTSService` with no code change.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Buffered response read** (medium, since 2026-08-31) — `run_tts` calls `await stream.read()` before yielding any frame, so TTFB equals full synthesis time. Measured 2026-08-31: first chunk of generative audio at 182 ms against 1193 ms for the full read; this run's generative probes sit at 723-834 ms TTFB against 226 ms for the standard default. — *Needs a call: yielding partial audio changes when the first `TTSAudioRawFrame` appears and how the resampler is fed, so it is a rework of `run_tts`, not a value change.*
- **Bidirectional streaming API** (medium, since 2026-08-31) — `StartSpeechSynthesisStream` (GA 2026-03-19, generative engine) keeps an HTTP/2 connection open, takes text as it is produced and returns audio as it is synthesized; it reached AWS GovCloud (US-West) on 2026-10-22, for nine regions in total. botocore carries the model but strips the operation off the Polly client (`remove_polly_start_speech_synthesis_stream` in `botocore/handlers.py`), so aiobotocore cannot reach it; AWS publishes the smithy client `aws_sdk_polly` instead. — *Needs a call: this is a new service class plus a new SDK dependency, the same shape as the `aws-nova-sonic` extra.*
- **Default engine is standard** (medium, since 2026-08-31) — with `engine` unset Polly uses the standard concatenative engine; the standard-voices page, re-read this run, still carries no end-of-support notice. Neural was the same latency in the 2026-09-28 probe (242 ms vs 239 ms, medians of 5), but it costs $16 per 1M characters against $4. — *Needs a call: changing the default multiplies every user's Polly bill and standard-only voices would start erroring.*
- **LanguageCode not exposed** (low, since 2026-08-31) — bilingual voices select their language from the request's `LanguageCode`; the service only wraps text in an SSML `<lang>` tag. The 2026-10-21 generative voices Arjun and Kiara are bilingual (en-IN and hi-IN), alongside the existing Aditi, Kajal, Hala and Zayd. — *Needs a call: whether the existing `language` setting should also drive `LanguageCode`, or a separate field is added that can disagree with it.*
- **PCM caps output at 16 kHz** (low, since 2026-08-31) — `OutputFormat` is fixed to `pcm`, whose only valid sample rates are 8000 and 16000; generative voices are natively 24 kHz and only deliver that through mp3/ogg. Polly also added `mulaw`/`alaw` output on 2026-03-25, which telephony pipelines could take directly. — *Needs a call: 24 kHz means decoding mp3 or ogg inside the service.*
- **No speech marks** (low, since 2026-08-31) — `SpeechMarkTypes` would give word timestamps, but only from a separate `json`-format request, and the generative engine does not support them at all. — *Needs a call: whether a second billed synthesis per utterance is acceptable.*

The three new voices are absent from the installed botocore's `VoiceId` enum (botocore 1.43.106 lists 106 members, none of them the 2026-10-21 additions) and synthesize anyway: botocore does not validate enum membership client-side, and `AWSPollyTTSService` passes `voice` straight into `SynthesizeSpeech`. So no allowlist, table or SDK floor gates new Polly voices — the control probe shows the rejection comes from the service, not from us.
