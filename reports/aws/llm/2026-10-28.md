# AWS Bedrock LLM — 2026-10-28

Both of last run's live items shipped; what is new is that the `effort` setting that shipped with them has no default behind it, so a Bedrock reasoning model picked by a user waits 12 seconds before its first token. Nothing in the repo pins a retired model, and no branch is warranted — every open item needs a decision first.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **No reasoning defaults** (high, since 2026-10-28) — `AWSBedrockLLMService` keeps no `_THINKING_DEFAULTS` table, so a reasoning model runs at whatever Bedrock defaults to. `us.xai.grok-4.7` took TTFAT 11936 ms on "What is the capital of France?" and 3127 ms with `effort=low`; on a self-reference puzzle it outran the probe's 30 s wait and produced its first text at 104 s. Bedrock's `effort` landed in #5934 last run, so the setting to apply exists; what is missing is the per-model table CONTRIBUTING.md asks every LLM service for. — *Needs a call: what a Bedrock table keys on, since model ids carry region and vendor prefixes (`us.xai.grok-4.7`), and what to do for models whose reasoning control is vendor-specific — Claude's `thinking` block in `additionalModelRequestFields` — rather than Converse's `effort`.*
- **`latency="optimized"` almost never applies** (medium, since 2026-08-31) — unchanged this run: the latency-optimized page is still a preview covering Nova Pro, Llama 3.1 70B/405B and Claude 3.5 Haiku, and Claude 3.5 Haiku is retired, so no current Claude model can accept it. The docstring offers it as a plain "standard or optimized" mode. — *Needs a call: whether to name the supported models in the docstring, validate before sending, or drop the field as Bedrock narrows the preview.*
- **Nova 2 Lite as the default** (medium, since 2026-08-31) — the latency objection is gone: TTFAT medians of 5 are 563 ms for `us.amazon.nova-lite-v1:0` against 586 ms for `us.amazon.nova-2-lite-v1:0`, inside the 10% band, where the three previous runs had Nova 2 Lite 15–20% slower. The default is still ACTIVE with no EOL date, so there is no deadline. — *Needs a call: aiewf-eval still has no Amazon Nova row of any generation, so the benchmark condition for a default bump cannot be met yet.*
- **Structured output, now that Bedrock has shipped it for Claude** (medium, since 2026-08-31) — AWS announced structured outputs for Anthropic Claude on both endpoints on 2026-10-18 and documents per-model support on the model cards, so Converse's `outputConfig.textFormat` is a real capability for the models Pipecat users reach for. The service still leaves `supports_response_schema` False — `run_inference(response_schema=...)` logs "response_schema is not supported and is ignored" — and `run_inference`'s own docstring states that "Bedrock's Converse API has no reply schema", which is no longer true. `LLMService.model_supports_response_schema` is the hook for a per-model answer; Nova rejects `outputConfig` outright, and AWS warns that some geographic inference profiles do not support it either. — *Needs a call: whether to claim response-schema support and gate it per model, and how a model that rejects `outputConfig` should behave.*
- **Strict tool use** (medium, since 2026-10-28) — Bedrock's structured-outputs page documents `strict: true` on a Converse tool definition as the way to make tool names and arguments conform to the input schema, and botocore's `ToolSpecification` shape carries `strict`. The Bedrock adapter emits `toolSpec` with name, description and inputSchema only, so Pipecat function calls are never schema-validated by the provider. — *Needs a call: whether strict tool use should be on for everyone, a Settings opt-in, or decided per tool, and what a model that rejects `strict` should do.*
- **Guardrails** (medium, since 2026-08-31) — ConverseStream's `guardrailConfig` (`guardrailIdentifier`, `guardrailVersion`, `trace`, `streamProcessingMode`) has no Settings field and is never sent. Guardrails kept moving this run — contextual grounding checks gained a Standard tier on 2026-10-19 — and none of it is reachable. — *Needs a call: no guardrail exists in the probe account to verify a pass-through against, and guardrail interventions arriving mid-stream need a stance on what the pipeline should see.*
- **`serviceTier` and `Tool.systemTool`** (low, since 2026-08-31) — AWS positions the priority tier as its fastest, which would matter for voice, but the probe account cannot use it: both `us.amazon.nova-lite-v1:0` and `us.anthropic.claude-haiku-5-5` reject `serviceTier` with "The provided service tier is not supported for this model". Like `effort`, `serviceTier` is a top-level Converse member, so `additional_model_request_fields` cannot carry it. `Tool.systemTool` is how Nova 2's built-in web grounding and code interpreter are requested, and the adapter emits `toolSpec` tools only. — *Needs a call: whether to add fields the probe account cannot exercise, or leave both until a model that accepts them is in reach.*
- **The service reaches far more than Nova and Claude** (low, since 2026-09-01) — nothing in the class gates the model and Bedrock's text catalogue is 86 model ids; new since the last run are `anthropic.claude-haiku-5-5`, `anthropic.claude-sonnet-5-5`, `openai.gpt-6.1-sol`, `openai.gpt-6.1-terra`, `xai.grok-4.7`, `zai.glm-5.3` and `twelvelabs.pegasus-1-5-v1:0`. The class docstring and docs.pipecat.ai still describe the service as Nova and Claude support, and the docs page's example pins `us.anthropic.claude-sonnet-4-5-20250929-v1:0`, which Bedrock now marks LEGACY. — *Needs a call: whether to widen the wording, and whether the docs change belongs in this repo or in the docs repo.*

Closed since the last run: `outputConfig.effort` shipped as a Settings field (#5934, merged 2026-09-28) and `reasoningContent` deltas now become `LLMThought*` frames (commit `f550b2d83`, with `tests/test_aws_bedrock_llm_thinking.py` covering both the delta path and Nova's `<thinking>` tags). The `top_k`/`seed` item is dropped: docs.pipecat.ai now documents both as "Not sent by this service, so it has no effect", which was the whole of the gap.

Nothing in the repo pins a retired Bedrock model. `us.anthropic.claude-sonnet-4-6` (six examples), `us.anthropic.claude-haiku-4-5-20251001-v1:0` (the flows example) and `us.amazon.nova-pro-v1:0` (the two SageMaker examples) are all ACTIVE; newly LEGACY this run are `anthropic.claude-sonnet-4-5-20250929-v1:0`, `writer.palmyra-x4-v1:0`, `writer.palmyra-x5-v1:0` and `twelvelabs.pegasus-1-2-v1:0`, and `anthropic.claude-sonnet-4-20250514-v1:0` and both AI21 Jamba models have left the catalogue — none of them appear in the repo.
