# AWS Bedrock LLM — 2026-09-28

Bedrock's Converse API now takes a cross-model reasoning `effort` level that halves TTFAT on `us.xai.grok-4.6` and that Pipecat has no way to send; a branch adds it as a Settings field. Nothing retired, and the other eight items are the same ones waiting on a maintainer's call.

## What's new for Pipecat

### PRs

- https://github.com/pipecat-ai/pipecat/pull/5934 — Pass Bedrock's reasoning effort level through Settings

Bedrock added `outputConfig.effort` to Converse and ConverseStream (`low`, `medium`, `high`, `xhigh`, `max`; capped at `high` when extended thinking is disabled). It is the only route to it: `outputConfig` is a top-level Converse member, so `additional_model_request_fields` cannot carry it — sending `{"outputConfig": {"effort": "low"}}` that way is accepted and has no effect (grok-4.6 spent its whole 128-token budget on reasoning and emitted no answer), and so is `{"reasoning_effort": "low"}`. The field is unset by default; set on a model that does not support it, the request fails with `ValidationException`, which is why that case is in the table below.

### To consider

- **Reasoning output is dropped** (medium, since 2026-08-31) — `_process_context` reads `delta["text"]` and `delta["toolUse"]` only, so `delta.reasoningContent` never becomes an `LLMThinking*` frame and never lands in thinking metrics. This run makes the cost concrete: `us.xai.grok-4.6`, GA on Bedrock and reasoning by default, streams `reasoningContent` ahead of its text on every call, and the class reports `thinking_ms` 0 with TTFAT 2712 ms — the reasoning that accounts for most of that wait is invisible to the pipeline. — *Needs a call: whether Bedrock reasoning should map onto the LLMThinking frames the Anthropic service emits, including whether reasoning blocks must be echoed back in later requests and whether the service should ever set a thinking config of its own.*
- **`latency="optimized"` almost never applies** (medium, since 2026-08-31) — the setting sends `performanceConfig`, which Bedrock still previews for Nova Pro, Llama 3.1 70B/405B and Claude 3.5 Haiku only, and Claude 3.5 Haiku is retired, so no Claude model can accept it. Setting it on the default model fails the request with `ValidationException`, while the docstring offers it as a plain "standard or optimized" mode. — *Needs a call: whether to name the supported models in the docstring, validate before sending, or drop the field as Bedrock narrows the preview.*
- **Nova 2 Lite as the default** (medium, since 2026-08-31) — GA 2025-12-02, works through the class untouched, but slower for the third run running: TTFAT medians of 5 are 603 ms for `us.amazon.nova-lite-v1:0` against 725 ms for `us.amazon.nova-2-lite-v1:0`. The default is still ACTIVE with no EOL date, so there is no deadline. — *Needs a call: aiewf-eval still has no Amazon Nova row of any generation, so the benchmark condition for a default bump cannot be met yet.*
- **Guardrails** (medium, since 2026-08-31) — ConverseStream's `guardrailConfig` (`guardrailIdentifier`, `guardrailVersion`, `trace`, `streamProcessingMode`) has no Settings field and is never sent. — *Needs a call: no guardrail exists in the probe account to verify a pass-through against, and guardrail interventions arriving mid-stream need a stance on what the pipeline should see.*
- **Structured output, and what `run_inference` tells callers about it** (medium, since 2026-08-31) — Converse takes `outputConfig.textFormat` as `OutputFormat {type: "json_schema", structure.jsonSchema}`, so Bedrock does have a reply schema, but the service leaves `supports_response_schema` False: `run_inference(response_schema=...)` logs "response_schema is not supported and is ignored" and sends the request unconstrained. Honouring it is not a one-liner — Nova rejects `outputConfig` outright ("This model doesn't support the outputConfig field"), so the service would need to know which models can enforce a schema. — *Needs a call: whether Bedrock should claim response-schema support given that only some models accept `outputConfig`, and how a model that rejects it should behave.*
- **Newer Converse request fields** (low, since 2026-08-31) — `serviceTier` (priority/default/flex/reserved) and `Tool.systemTool`, which is how Nova 2's built-in web grounding and code interpreter are requested — the Bedrock adapter emits `toolSpec` tools only. — *Needs a call: whether either matters for real-time voice, or belongs in `additional_model_request_fields`.*
- **`top_k` and `seed` are silently ignored** (low, since 2026-08-31) — `_build_inference_config` sends only what Bedrock's `InferenceConfiguration` accepts (maxTokens/stopSequences/temperature/topP), but docs.pipecat.ai lists both among the service's settings, so setting them looks supported and does nothing. — *Needs a call: whether to route `top_k` through `additionalModelRequestFields` or drop the two from the documented settings.*
- **The service reaches far more than Nova and Claude** (low, since 2026-09-01) — nothing in the class gates the model, and Bedrock's text catalogue is 86 model IDs; new since the last run are `openai.gpt-5.4`, `openai.gpt-5.5`, `openai.gpt-6-luna`, `openai.gpt-6-sol`, `anthropic.claude-opus-5-5` and `moonshotai.kimi-k3`. The class docstring and docs.pipecat.ai still describe the service as Nova and Claude support. — *Needs a call: whether to widen the wording, and whether the docs change belongs in this repo or in the docs repo.*

Nothing in the repo pins a retired Bedrock model: the default and every example (`us.anthropic.claude-sonnet-4-6` in the four AWS examples, `us.anthropic.claude-haiku-4-5-20251001-v1:0` in the flows example, `us.amazon.nova-pro-v1:0` in the SageMaker example) is ACTIVE.

Branch probes ran `scripts/provider-watch/probe.py run` from the worktree with `PYTHONPATH` pointing at the worktree's `src`, so the new field was exercised through the real class. Ad-hoc scripts left in `.pw-scratch`: `bedrock_catalogue.py` (ListFoundationModels / ListInferenceProfiles, us-east-1 and us-west-2), `bedrock_shape.py` (the installed botocore Converse shapes), `bedrock_effort.py` and `bedrock_effort2.py` (one `converse_stream` call per case, printing the delta kinds or the exception).
