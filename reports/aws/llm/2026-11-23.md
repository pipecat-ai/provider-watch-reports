# AWS Bedrock LLM — 2026-11-23

Nothing moved: `src/pipecat/services/aws/llm.py` and the Bedrock adapter are untouched since the last run, botocore still describes the same Converse request shape, and the two Bedrock doc-history entries since 2026-11-09 are about watermarking and AWS Marketplace. Fresh evidence sharpens two carried items, and one new low item appears. No branch — every item still needs a decision.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **No reasoning defaults** (high, since 2026-10-28) — `AWSBedrockLLMService` keeps no `_THINKING_DEFAULTS` table, so a reasoning model runs at whatever Bedrock defaults to. `us.openai.gpt-6.2-sol`, new in the catalogue this run, answers the barber-paradox prompt in TTFAT 1111 ms untouched against 737 ms with `effort=low` — a third model after Kimi K3.1 (3048/1238 ms) and Grok 4.7 (9007/5351 ms) measured last run. Bedrock's `effort` is already a Settings field, so the control exists; what is missing is the per-model table CONTRIBUTING.md asks every LLM service for. — *Needs a call: what a Bedrock table keys on, since model ids carry region and vendor prefixes (`us.openai.gpt-6.2-sol`), and what to do for models whose reasoning control is vendor-specific — Claude's `thinking` block in `additionalModelRequestFields` — rather than Converse's `effort`.*
- **`latency="optimized"` almost never applies** (medium, since 2026-08-31) — unchanged: the latency-optimized page is still a preview covering Nova Pro, Llama 3.1 70B/405B and Claude 3.5 Haiku, and Claude 3.5 Haiku has left the catalogue entirely, so no current Claude model can accept it. The docstring offers it as a plain "standard or optimized" mode. — *Needs a call: whether to name the supported models in the docstring, validate before sending, or drop the field as Bedrock narrows the preview.*
- **Nova 2 Lite as the default** (medium, since 2026-08-31) — the latency gap widened: TTFAT medians of 5 are 627 ms for `us.amazon.nova-lite-v1:0` against 747 ms for `us.amazon.nova-2-lite-v1:0`, 19% behind, where last run measured 525/588 ms (12%) and the run before 563/586 ms. Three runs in a row have put Nova 2 Lite slower, so this is not sampling noise. The default is still ACTIVE with no EOL date, so there is no deadline. — *Needs a call: aiewf-eval still has no Amazon Nova row of any generation, so the benchmark condition for a default bump cannot be met yet.*
- **Structured output, now that Bedrock has shipped it for Claude** (medium, since 2026-08-31) — unchanged since the 2026-10-18 GA: Converse's `outputConfig.textFormat` is a real capability for the Claude models Pipecat users reach for, but the service leaves `supports_response_schema` False, so `run_inference(response_schema=...)` logs "response_schema is not supported and is ignored", and `run_inference`'s own docstring states that "Bedrock's Converse API has no reply schema". `LLMService.model_supports_response_schema` is the hook for a per-model answer; Nova rejects `outputConfig` outright, and the docs point at the model cards for which models qualify. — *Needs a call: whether to claim response-schema support and gate it per model, and how a model that rejects `outputConfig` should behave.*
- **Strict tool use** (medium, since 2026-10-28) — Bedrock documents `strict: true` on a Converse tool definition as the way to make tool names and arguments conform to the input schema, and botocore's `ToolSpecification` carries `strict`. The Bedrock adapter emits `toolSpec` with name, description and inputSchema only, so Pipecat function calls are never schema-validated by the provider. — *Needs a call: whether strict tool use should be on for everyone, a Settings opt-in, or decided per tool, and what a model that rejects `strict` should do.*
- **Guardrails** (medium, since 2026-08-31) — ConverseStream's `guardrailConfig` (`guardrailIdentifier`, `guardrailVersion`, `trace`) has no Settings field and is never sent. — *Needs a call: no guardrail exists in the probe account to verify a pass-through against, and guardrail interventions arriving mid-stream need a stance on what the pipeline should see.*
- **`serviceTier` and `Tool.systemTool`** (low, since 2026-08-31) — AWS positions the priority tier as its fastest, which would matter for voice, but the probe account cannot use it: both `us.amazon.nova-lite-v1:0` and `us.anthropic.claude-haiku-5-5` rejected `serviceTier` with "The provided service tier is not supported for this model", and nothing in the catalogue suggests that changed. Like `effort`, `serviceTier` is a top-level Converse member, so `additional_model_request_fields` cannot carry it. `Tool.systemTool` is how Nova 2's built-in web grounding and code interpreter are requested, and the adapter emits `toolSpec` tools only. — *Needs a call: whether to add fields the probe account cannot exercise, or leave both until a model that accepts them is in reach.*
- **The service reaches far more than Nova and Claude** (low, since 2026-09-01) — nothing in the class gates the model and Bedrock's text catalogue is 95 model ids; new since the last run are `openai.gpt-6.2-astra` and `openai.gpt-6.2-sol`, both of which answer through the class untouched. The class docstring still describes the service as Nova and Claude support, and docs.pipecat.ai scopes it the same way while its Basic Setup example pins the LEGACY `us.anthropic.claude-sonnet-4-5-20250929-v1:0`. — *Needs a call: whether to widen the wording, and whether the docs change belongs in this repo or in the docs repo.*
- **LEGACY Llama 3.3 70B in the turn-completion manifest** (low, since 2026-11-23) — `evals/turn-completion/manifest.yaml` runs its no-tools row on `us.meta.llama3-3-70b-instruct-v1:0`, which the catalogue marks LEGACY. It still answers (TTFAT 520 ms) and AWS has published no EOL date, but Bedrock's lifecycle policy withdraws a LEGACY model from an account after 15 days of inactivity, so the row can fail without warning. Every Meta Llama on Bedrock is LEGACY, so there is no same-family replacement. — *Needs a call: which model takes over the manifest's no-tools row, given that no ACTIVE Meta Llama remains on Bedrock.*

Nothing in the shipped service or in `examples/` pins a retired or LEGACY Bedrock model: `us.anthropic.claude-sonnet-4-6` (seven places), `us.amazon.nova-pro-v1:0`, `us.amazon.nova-lite-v1:0` and `us.anthropic.claude-haiku-4-5-20251001-v1:0` are all ACTIVE.

`amazon.nova-premier-v1:0` has dropped out of `ListFoundationModels` again while `us.amazon.nova-premier-v1:0` remains a listed inference profile — the same flapping the 2026-09-28 run saw. Nothing in the repo uses it.
