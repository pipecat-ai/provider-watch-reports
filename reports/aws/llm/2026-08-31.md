# AWS Bedrock LLM — 2026-08-31

The default model is healthy and nothing the service ships is retiring, but one example bot cannot start because its Bedrock model is past end of life; branch ready.

## What's new for Pipecat

### PRs

- `provider-watch/aws-llm-example-retired-haiku` — review: `git show provider-watch/aws-llm-example-retired-haiku` — Use an available Bedrock Haiku in the LLM switching example

### To consider

- **Reasoning output is dropped** (medium, since 2026-08-31) — `_process_context` reads `delta["text"]` and `delta["toolUse"]` only, so `delta.reasoningContent` never becomes an `LLMThinking*` frame and never lands in thinking metrics. A Nova 2 Lite turn with `reasoningConfig` enabled emits reasoning blocks that the pipeline never sees. — *Needs a call: whether Bedrock reasoning should map onto the LLMThinking frames the Anthropic service emits, including whether reasoning blocks must be echoed back in later requests and whether the service should ever set a thinking config of its own.*
- **`latency="optimized"` almost never applies** (medium, since 2026-08-31) — the setting sends `performanceConfig`, which Bedrock previews for Nova Pro and Llama 3.1 only. Setting it on the service's own default model, or on current Claude models, fails the request outright with `ValidationException`, while the docstring offers it as a plain "standard or optimized" mode. — *Needs a call: whether to name the supported models in the docstring, validate before sending, or drop the field as Bedrock narrows the preview.*
- **Nova 2 Lite as the default** (medium, since 2026-08-31) — GA 2025-12-02, one-million-token context, reasoning off by default, and it works through the class untouched. It is not faster: TTFAT 609 ms against 520 ms for the current default (medians of 5), with one 12 s outlier in the Nova 2 samples. The current default `amazon.nova-lite-v1:0` is still ACTIVE with no EOL date, so there is no deadline. — *Needs a call: aiewf-eval has not benchmarked any Amazon Nova model and this run's latency is 17% worse, so neither condition for a default bump is met.*
- **Guardrails** (medium, since 2026-08-31) — ConverseStream's `guardrailConfig` (`guardrailIdentifier`, `guardrailVersion`, `trace`, `streamProcessingMode`) has no Settings field and is never sent. — *Needs a call: no guardrail exists in the probe account to verify a pass-through against, and guardrail interventions arriving mid-stream need a stance on what the pipeline should see.*
- **Newer Converse request fields** (low, since 2026-08-31) — `serviceTier` (priority/default/flex/reserved), `outputConfig`, and `Tool.systemTool`, which is how Nova 2's built-in web grounding and code interpreter are requested; the Bedrock adapter emits `toolSpec` tools only. — *Needs a call: whether any of these matter for real-time voice, or belong in `additional_model_request_fields`.*
- **`top_k` and `seed` are silently ignored** (low, since 2026-08-31) — `_build_inference_config` sends only what Bedrock's `inferenceConfig` accepts, but docs.pipecat.ai lists both among the service's settings, so setting them looks supported and does nothing. — *Needs a call: whether to route `top_k` through `additionalModelRequestFields` or drop the two from the documented settings.*

Dropped since the earlier run of this date: "Sonnet 5+ thinking is on by default on Bedrock". Two direct stream inspections — a trivial prompt and a step-by-step reasoning prompt — show `us.anthropic.claude-sonnet-5` emitting `delta.text` only, with no `reasoningContent` block, so there is no Bedrock counterpart to the Anthropic service's thinking-off default. Sonnet 5 is still slower than Sonnet 4.6 through this class (TTFAT 1406 ms vs 911 ms, medians of 5), which is the model, not the service.

Probes need `AWS_BEARER_TOKEN_BEDROCK` unset: the runner exports it empty, botocore then signs Bedrock requests as bearer auth, and the service rejects them. Not a Pipecat defect, but it is what a first failing probe on this unit looks like.

`.pw-scratch/bedrock_delta_kinds*.py` are the ad-hoc scripts behind the reasoning findings: one `converse_stream` call per model, counting event and delta kinds. `us.anthropic.claude-sonnet-5` produced `delta.text` only on both a trivial and a reasoning prompt; `us.amazon.nova-2-lite-v1:0` with `additionalModelRequestFields={"reasoningConfig": {"type": "enabled", "maxReasoningEffort": "low"}}` produced `delta.reasoningContent` blocks ahead of its text.
