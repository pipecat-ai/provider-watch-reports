# AWS Bedrock LLM — 2026-08-31

Nothing in the service is retiring, but Claude Sonnet 5 on Bedrock doubles TTFAT through this class and its reasoning output is thrown away; no change is safe enough to branch this run.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Sonnet 5+ thinking is on by default** (high, since 2026-08-31) — `us.anthropic.claude-sonnet-5` streams `reasoningContent` before its answer with no thinking config requested, and measures TTFAT 1826 ms (median of 3) against 920 ms for `us.anthropic.claude-sonnet-4-6` on a trivial prompt. `AnthropicLLMService._maybe_disable_thinking` already sends `thinking: {"type": "disabled"}` for Sonnet 5 and later; `AWSBedrockLLMService` has no equivalent, so the only way out is hand-rolling `additional_model_request_fields`. — *Needs a call: how to recognize reasoning-on-by-default models from a Bedrock model id, and whether the fix is a `thinking`-style Settings field or an implicit default like the Anthropic service's.*
- **Reasoning output is dropped** (medium, since 2026-08-31) — `_process_context` reads `delta["text"]` and `delta["toolUse"]` only, so `delta.reasoningContent` never becomes an `LLMThinking*` frame and never lands in thinking metrics. A Nova 2 Lite turn with `reasoningConfig` enabled can be reasoningContent-only, which reaches the pipeline as an empty response. — *Needs a call: whether Bedrock reasoning should map onto the LLMThinking frames the Anthropic service emits, including whether reasoning blocks must be echoed back in later requests.*
- **Nova 2 Lite as the default** (medium, since 2026-08-31) — GA 2025-12-02, one-million-token context, reasoning off by default; `us.amazon.nova-2-lite-v1:0` works through the class untouched at TTFAT parity (601 vs 624 ms trivial, 528 vs 490 ms reasoning prompt, medians of 5). The current default `amazon.nova-lite-v1:0` is still ACTIVE with no EOL date, so there is no deadline. — *Needs a call: aiewf-eval has not benchmarked any Amazon Nova model, so the leaderboard cannot confirm parity on `aiwf_medium_context`.*
- **Guardrails** (medium, since 2026-08-31) — ConverseStream's `guardrailConfig` (`guardrailIdentifier`, `guardrailVersion`, `trace`, `streamProcessingMode`) has no Settings field and is never sent. — *Needs a call: no guardrail exists in the probe account to verify a pass-through against, and guardrail interventions arriving mid-stream need a stance on what the pipeline should see.*
- **Newer Converse request fields** (low, since 2026-08-31) — `serviceTier` (priority/default/flex/reserved), `outputConfig`, and `Tool.systemTool`, which is how Nova 2's built-in web grounding and code interpreter are requested; the Bedrock adapter emits `toolSpec` tools only. — *Needs a call: whether any of these matter for real-time voice, or belong in `additional_model_request_fields`.*
- **`top_k` and `seed` are silently ignored** (low, since 2026-08-31) — `_build_inference_config` sends only what Bedrock's `inferenceConfig` accepts, but docs.pipecat.ai lists both among the service's settings, so setting them looks supported and does nothing. — *Needs a call: whether to route `top_k` through `additionalModelRequestFields` or drop the two from the documented settings.*

Probes needed `AWS_BEARER_TOKEN_BEDROCK` unset: the runner exports it empty, and botocore then signs Bedrock requests as bearer auth and the service rejects them. Not a Pipecat defect, but it is what a first failing probe on this unit looks like.

`.pw-scratch/probe_bedrock_reasoning.py` is the ad-hoc script behind the reasoning findings: one `converse_stream` call per model, counting event and delta kinds. It showed `delta.reasoningContent` for `us.anthropic.claude-sonnet-5` with no thinking config, none for `us.amazon.nova-2-lite-v1:0`, and reasoning-only output for Nova 2 Lite with `additionalModelRequestFields={"reasoningConfig": {"type": "enabled", "maxReasoningEffort": "low"}}`.
