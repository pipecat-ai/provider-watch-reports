# AWS Nova Sonic (realtime) — 2026-11-09

Current and unchanged: `amazon.nova-2-5-sonic` is still AWS's latest Sonic model, it connects, and
nothing in the bidirectional event schema or the service has moved since the last run. No branch;
the five open gaps all carry over.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/4356 — open since 2026-04-23, still unmerged: adds an
  `InputTextRawFrame` handler to `AWSNovaSonicLLMService` that forwards typed text as an interactive
  `USER` text event, which is the cross-modal gap this unit carries.

### To consider
- **The first-generation code path outlives the model** (medium, since 2026-08-31) —
  `_is_first_generation_sonic_model()` still gates the `ready.wav` assistant-response-trigger hack,
  `AWAIT_TRIGGER_ASSISTANT_RESPONSE_INSTRUCTION`, `trigger_assistant_response()` and the
  "endpointing_sensitivity is not supported" downgrade. A probe of `amazon.nova-sonic-v1:0` is still
  rejected at connect with "The provided model identifier is invalid", so none of it can run. —
  *Needs a call: deprecate the first-generation path (and the bundled `ready.wav`) for removal in
  2.0.0, or delete it outright?*
- **Only static IAM keys can authenticate** (medium, since 2026-09-14) — `access_key_id`,
  `secret_access_key` and `region` are required constructor arguments and `create_client()` hardcodes
  `StaticCredentialsResolver()` with a SigV4-only `auth_schemes` map, so an EC2/ECS/EKS role, a named
  profile or a Bedrock API key cannot be used. The Nova 2.5 Sonic model card still tells new users to
  set `AWS_BEARER_TOKEN_BEDROCK`, and the bidirectional-stream operation in the installed SDK 0.9.0
  already offers `smithy.api#httpBearerAuth`. (Commit 8c9807212, "Let AWS sessions renew credentials
  from the default chain", touched the aiobotocore-based AWS services, not this one.) — *Needs a
  call: which auth modes to support, and how to keep the existing required arguments working?*
- **SDK pin stops below the rename** (low, since 2026-08-31) — `pyproject.toml` pins
  `aws_sdk_bedrock_runtime>=0.6.0,<0.10` (0.9.0 resolves); PyPI's latest is 0.12.0 (2026-10-08),
  unchanged this cycle. The ceiling is deliberate — 0.10.0 renamed `Config` to
  `AsyncBedrockRuntimeConfig` and `BedrockRuntimeClient` to `AsyncBedrockRuntimeClient`, which
  `create_client()` imports by the old names. — *Needs a call: do the rename migration (plus a
  re-probe of a full session), or hold until the SDK reaches 1.0?*
- **`SYSTEM_SPEECH` role missing** (low, since 2026-08-31) — the input-events reference still lists
  `role: "SYSTEM_SPEECH"` on a text `contentStart` to choose the transcription script for Hindi
  code-switching (Latin / Devanagari / mixed). `Role` in
  `src/pipecat/adapters/llm/services/aws_nova_sonic_adapter.py` has only SYSTEM, USER, ASSISTANT,
  TOOL. — *Needs a call: is Hindi script selection worth a user-facing knob, and what would it be
  called?*
- **`endpointing_sensitivity` is a free-form `str`** (low, since 2026-08-31) — AWS documents exactly
  `HIGH` / `MEDIUM` / `LOW`; a typo reaches the API instead of failing at construction. — *Needs a
  call: narrow the type now, or keep it open for values AWS may add?*

Not a gap: the Nova 2.5 Sonic model card is byte-for-byte the same story as two weeks ago — model ID
`amazon.nova-2-5-sonic`, launched 2026-10-05, lifecycle Active, EOL no sooner than 2027-10-05,
Standard tier only, in-Region in us-east-1/us-west-2/eu-north-1/ap-northeast-1, 20 concurrent
bidirectional sessions per account per Region. The input-event schema is unchanged: the same
`inferenceConfiguration` trio, `endpointingSensitivity` HIGH/MEDIUM/LOW, the `interactive` text
`contentStart`, the same 16 voice IDs (all pass through, since `Settings.voice` is a free-form
`str`), and 8/16/24 kHz audio. The Nova 2 user guide's release notes and doc history still end at
the May 2026 Nova 2 Sonic refresh and the 2026-06-22 doc change, and no Sonic announcement appeared
in November. Nova 2 Sonic is still Active with EOL date N/A; its "EOL no sooner than 2026-12-02"
marker passes next month but, with a legacy period of at least six months and no announced EOL, it
retires nothing — and it is no longer our default either way.

The ❌ row doubles as the control the last run used a bogus ID for: the connect-only probe still
surfaces a rejected model as an ErrorFrame, so the ✅ rows are real acceptances by Bedrock.

`probe.py run` still cannot fill AWS credentials on its own — the `aws_nova_realtime` registry entry
has `include_params=[]` and `manual_config=True`, so `build_kwargs` never looks up
`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_REGION` and the constructor raises `TypeError`.
All three probes above passed those with `--kwarg`. Adding the three names to that entry's
`include_params` would let future runs probe this unit unattended (provider-watch tooling, not a
service gap).

`probe.py list-models --provider aws` reports no OpenAI-compatible catalogue, so `models_seen` comes
from the model cards plus the probes above.
