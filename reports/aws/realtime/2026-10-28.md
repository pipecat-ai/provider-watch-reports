# AWS Nova Sonic (realtime) — 2026-10-28

The default is now `amazon.nova-2-5-sonic` and that is the right value: AWS launched Nova 2.5 Sonic
GA on 2026-10-05 with the same bidirectional API, the same four Regions and the same event schema,
and a probe connects. No branch this run; the five open gaps are all carried over.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/4356 — open since 2026-04-23, still unreviewed: adds an
  `InputTextRawFrame` handler to `AWSNovaSonicLLMService` that forwards typed text as an interactive
  `USER` text event, which is the cross-modal gap this unit has been carrying.

Closed since the last report: https://github.com/pipecat-ai/pipecat/pull/5935 merged 2026-09-28, so
the first-generation guidance gap is gone from the list.

### To consider
- **The first-generation code path outlives the model** (medium, since 2026-08-31) —
  `_is_first_generation_sonic_model()` still gates the `ready.wav` assistant-response-trigger hack,
  `AWAIT_TRIGGER_ASSISTANT_RESPONSE_INSTRUCTION`, `trigger_assistant_response()` and the
  "endpointing_sensitivity is not supported" downgrade. A probe of `amazon.nova-sonic-v1:0` still
  fails at connect with "The provided model identifier is invalid", so none of it can run. — *Needs a
  call: deprecate the first-generation path (and the bundled `ready.wav`) for removal in 2.0.0, or
  delete it outright?*
- **Only static IAM keys can authenticate** (medium, since 2026-09-14) — `access_key_id`,
  `secret_access_key` and `region` are required constructor arguments and `create_client()` hardcodes
  `StaticCredentialsResolver()` with a SigV4-only `auth_schemes` map, so an EC2/ECS/EKS role, a named
  profile or a Bedrock API key cannot be used. The installed SDK 0.9.0 already lists
  `smithy.api#httpBearerAuth` alongside `aws.auth#sigv4` on the bidirectional-stream operation, and
  the Nova 2.5 Sonic model card tells new users to set `AWS_BEARER_TOKEN_BEDROCK`. — *Needs a call:
  which auth modes to support, and how to keep the existing required arguments working?*
- **SDK pin stops below the rename** (low, since 2026-08-31) — `pyproject.toml` pins
  `aws_sdk_bedrock_runtime>=0.6.0,<0.10` (0.9.0 resolves); PyPI's latest is now 0.12.0 (2026-10-08).
  The ceiling is deliberate — 0.10.0 renamed `Config` to `AsyncBedrockRuntimeConfig` and
  `BedrockRuntimeClient` to `AsyncBedrockRuntimeClient`, which `create_client()` imports by the old
  names. — *Needs a call: do the rename migration (plus a re-probe of a full session), or hold until
  the SDK reaches 1.0?*
- **`SYSTEM_SPEECH` role missing** (low, since 2026-08-31) — the input-events reference still lists
  `role: "SYSTEM_SPEECH"` on a text `contentStart` to choose the transcription script for Hindi
  code-switching (Latin / Devanagari / mixed). `Role` in
  `src/pipecat/adapters/llm/services/aws_nova_sonic_adapter.py` has only SYSTEM, USER, ASSISTANT,
  TOOL. — *Needs a call: is Hindi script selection worth a user-facing knob, and what would it be
  called?*
- **`endpointing_sensitivity` is a free-form `str`** (low, since 2026-08-31) — AWS documents exactly
  `HIGH` / `MEDIUM` / `LOW`; a typo reaches the API instead of failing at construction. — *Needs a
  call: narrow the type now, or keep it open for values AWS may add?*

Not a gap: the default bump landed outside provider-watch (commit b29521805, PR #6077, 2026-10-07)
and checks out — the Nova 2.5 Sonic model card gives the model ID as `amazon.nova-2-5-sonic`,
lifecycle Active, launched 2026-10-05, EOL no sooner than 2027-10-05, Standard tier only, in-Region
in us-east-1/us-west-2/eu-north-1/ap-northeast-1, and AWS positions it as the successor to Nova 2
Sonic ("improved reasoning, instruction following, and tool calling accuracy over Nova 2 Sonic, along
with lower latency"). The input-event schema is identical for both generations: the same
`inferenceConfiguration` trio, `endpointingSensitivity` (HIGH/MEDIUM/LOW), the `interactive` text
`contentStart`, and the same 16 voice IDs, all of which pass through because `Settings.voice` is a
free-form `str`. Asynchronous tool calling, which the 2.5 model card advertises, "works out of the
box" with no client-side configuration. Nova 2 Sonic remains Active (EOL N/A), so nothing is
retiring. `docs.pipecat.ai` already documents `amazon.nova-2-5-sonic` as the default.

The control row matters because `AWSNovaSonicLLMService` now connects during setup rather than on
`StartFrame` (commit 5088d76e5); it shows the connect-only probe still surfaces a bad model ID as an
ErrorFrame, so the ✅ on `amazon.nova-2-5-sonic` is a real acceptance by Bedrock and not a probe that
stopped looking.

`probe.py run` still cannot fill AWS credentials on its own: the `aws_nova_realtime` registry entry
has an empty `include_params`, so `build_kwargs` never looks up `AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY` / `AWS_REGION` and the constructor raises `TypeError`. All four probes above
passed those with `--kwarg`. Adding `access_key_id`, `secret_access_key` and `region` to that entry's
`include_params` would let future runs probe this unit unattended (provider-watch tooling, not a
service gap).

`probe.py list-models --provider aws` reports no OpenAI-compatible catalogue, and the Bedrock control
plane (`ListFoundationModels`) is not reachable with this run's credentials, so `models_seen` comes
from the model cards plus the probes above.
