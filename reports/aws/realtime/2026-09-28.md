# AWS Nova Sonic (realtime) — 2026-09-28

First-generation `amazon.nova-sonic-v1:0` is gone from Bedrock — a connect probe in `us-east-1`
now fails with "The provided model identifier is invalid" where it succeeded on 2026-09-14 — and a
branch removes the docstring and example guidance that still pointed at it. `amazon.nova-2-sonic-v1:0`
is Active, unchanged, and connects cleanly.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5935 — Document only Nova 2 Sonic for AWS Nova Sonic
- https://github.com/pipecat-ai/pipecat/pull/4356 — open since 2026-04-23, still unreviewed: adds an
  `InputTextRawFrame` handler to `AWSNovaSonicLLMService` that forwards typed text as an interactive
  `USER` text event, which is the cross-modal gap this unit has been carrying.

The branch trims the constructor docstring to one region set and one voice reference, and drops the
commented-out `trigger_assistant_response()` / `AWAIT_TRIGGER_ASSISTANT_RESPONSE_INSTRUCTION` blocks
from `examples/realtime/realtime-aws-nova-sonic.py` and
`examples/persistent-context/persistent-context-aws-nova-sonic.py`. The persistent-context example's
region comment, a leftover from the first-generation model ("as of 2025-05-06, us-east-1 is the only
supported region"), is corrected to the four Regions Nova 2 Sonic actually serves.

### To consider
- **The first-generation code path outlives the model** (medium, since 2026-08-31) —
  `_is_first_generation_sonic_model()` still gates the `ready.wav` assistant-response-trigger hack,
  `AWAIT_TRIGGER_ASSISTANT_RESPONSE_INSTRUCTION`, `trigger_assistant_response()` and the
  "endpointing_sensitivity is not supported" downgrade. With the model ID rejected at connect, none
  of it can run: a user who sets it gets Bedrock's "invalid model identifier" instead. — *Needs a
  call: deprecate the first-generation path (and the bundled `ready.wav`) for removal in 2.0.0, or
  delete it outright?*
- **Only static IAM keys can authenticate** (medium, since 2026-09-14) — `access_key_id`,
  `secret_access_key` and `region` are required constructor arguments and `create_client()` hardcodes
  `StaticCredentialsResolver()` with a SigV4-only `auth_schemes` map, so an EC2/ECS/EKS role, a named
  profile or a Bedrock API key cannot be used. This is no longer gated on the SDK pin: the installed
  0.9.0 lists `smithy.api#httpBearerAuth` alongside `aws.auth#sigv4` in the bidirectional-stream
  operation's `effective_auth_schemes`, and both Sonic model cards tell new users to set
  `AWS_BEARER_TOKEN_BEDROCK`. — *Needs a call: which auth modes to support, and how to keep the
  existing required arguments working?*
- **SDK pin stops below the rename** (low, since 2026-08-31) — `pyproject.toml` now pins
  `aws_sdk_bedrock_runtime>=0.6.0,<0.10` (0.9.0 resolves); PyPI's latest is 0.11.0 (2026-08-24). The
  ceiling is deliberate — 0.10.0 renamed `Config` to `AsyncBedrockRuntimeConfig` and
  `BedrockRuntimeClient` to `AsyncBedrockRuntimeClient`, which `create_client()` imports by the old
  names — so this is now a migration question rather than a stale pin. — *Needs a call: do the rename
  migration (plus a re-probe of a full session), or hold until the SDK reaches 1.0?*
- **`SYSTEM_SPEECH` role missing** (low, since 2026-08-31) — the input-events reference still lists
  `role: "SYSTEM_SPEECH"` on a text `contentStart` to choose the transcription script for Hindi
  code-switching (Latin / Devanagari / mixed). `Role` in
  `src/pipecat/adapters/services/aws_nova_sonic_adapter.py` has only SYSTEM, USER, ASSISTANT, TOOL.
  — *Needs a call: is Hindi script selection worth a user-facing knob, and what would it be called?*
- **`endpointing_sensitivity` is a free-form `str`** (low, since 2026-08-31) — AWS documents exactly
  `HIGH` / `MEDIUM` / `LOW`; a typo reaches the API instead of failing at construction. — *Needs a
  call: narrow the type now, or keep it open for values AWS may add?*

Not a gap: no newer Sonic model exists — the Nova 2 release notes still end at the May 2026 in-place
refresh and the doc history's newest Sonic entry is still 2026-06-22. Nova 2 Sonic's model card has
lifecycle Active, "EOL no sooner than 2026-12-02", no EOL date, and Standard as its only service
tier, so there is nothing to pass through there. The input-event schema is unchanged: the same
`inferenceConfiguration` trio, `endpointingSensitivity`, and 16 voice IDs, all of which pass through
because `Settings.voice` is a free-form `str`. AWS's own pages lag the removal: the legacy lifecycle
table still lists `amazon.nova-sonic-v1:0` with EOL 2026-09-14 and its model card still says
"Legacy", while the API already rejects it.

`probe.py run` still cannot fill AWS credentials on its own: the `aws_nova_realtime` registry entry
has an empty `include_params`, so `build_kwargs` never looks up `AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY` / `AWS_REGION` and the constructor raises `TypeError`. All three probes above
passed those with `--kwarg`. Adding `access_key_id`, `secret_access_key` and `region` to that entry's
`include_params` would let future runs probe this unit unattended (provider-watch tooling, not a
service gap).

`probe.py list-models --provider aws` reports no OpenAI-compatible catalogue; `models_seen` comes from
Bedrock's model cards and the probe above, which is why the retired first-generation ID is no longer
listed.
