# AWS Nova Sonic (realtime) — 2026-09-14

`amazon.nova-2-sonic-v1:0` is Active, still the right default, and connects cleanly; the urgent item is
that first-generation `amazon.nova-sonic-v1:0` hits its Bedrock EOL *today* while the service still
branches on it. No branch this run — every open item needs a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/4356 — open since 2026-04-23, unreviewed: adds an
  `InputTextRawFrame` handler to `AWSNovaSonicLLMService` that forwards typed text as an interactive
  `USER` text event, which is exactly the cross-modal gap this unit has been carrying.

Closed since last run: https://github.com/pipecat-ai/pipecat/pull/5508 merged 2026-09-03, so the
docstring and example now list `eu-north-1`; that gap is dropped.

### To consider
- **First-generation Nova Sonic reaches EOL today** (high, since 2026-08-31) — Bedrock's legacy
  lifecycle table still lists `amazon.nova-sonic-v1:0` as Legacy since 2026-03-13 with EOL
  2026-09-14 and no public-extended-access date; after it, requests fail and the model is removed
  from all Regions "on, or soon after the EOL date". A connect probe in `us-east-1` still succeeded
  today, so the removal is imminent rather than done. `AWSNovaSonicLLMService` still branches on the
  model: `_is_first_generation_sonic_model()` gates the `ready.wav` assistant-response-trigger hack,
  `AWAIT_TRIGGER_ASSISTANT_RESPONSE_INSTRUCTION` and the "endpointing_sensitivity is not supported"
  downgrade, and the constructor docstring plus `examples/realtime/realtime-aws-nova-sonic.py`
  explain how to run the older model. — *Needs a call: deprecate-and-remove the first-generation path
  (and `ready.wav`) for 2.0.0, or only strip the guidance from docstrings and examples?*
- **SDK pin is seven releases behind, and 0.11.0 renames what we import** (medium, since 2026-08-31) —
  `pyproject.toml` pins `aws_sdk_bedrock_runtime~=0.4.0` (2026-02-24); PyPI's latest is 0.11.0
  (2026-08-24). Inspecting the 0.11.0 wheel: `Config` is gone, replaced by
  `AsyncBedrockRuntimeConfig` (an `AsyncAwsConfig` subclass), and `BedrockRuntimeClient` is now
  `AsyncBedrockRuntimeClient` — so `create_client()`'s imports break outright. The static-credential
  fields and the `invoke_model_with_bidirectional_stream` input/`DuplexEventStream` shapes survive,
  with a new `plugins` argument. — *Needs a call: do the migration (import renames plus a re-probe of
  a full session), or hold the pin until the SDK reaches 1.0?*
- **Only static IAM keys can authenticate** (medium, since 2026-09-14) — `access_key_id`,
  `secret_access_key` and `region` are required constructor arguments and `create_client()` hardcodes
  `StaticCredentialsResolver()` with a SigV4-only `auth_schemes` map, so an EC2/ECS/EKS role, a named
  profile or a Bedrock API key cannot be used. The Nova 2 Sonic model card now presents the Bedrock
  API key (`AWS_BEARER_TOKEN_BEDROCK`) as the documented getting-started credential, and
  aws_sdk_bedrock_runtime 0.11.0 declares `aws.auth#sigv4` plus `smithy.api#httpBearerAuth` at the
  service level (0.4.0 does not). — *Needs a call: which auth modes to support, and how to keep the
  existing required arguments working — it is gated on the SDK pin above.*
- **`SYSTEM_SPEECH` role missing** (low, since 2026-08-31) — the input-events reference still lists
  `role: "SYSTEM_SPEECH"` on a text `contentStart` to choose the transcription script for Hindi
  code-switching (Latin / Devanagari / mixed). `Role` in
  `src/pipecat/adapters/services/aws_nova_sonic_adapter.py` has only SYSTEM, USER, ASSISTANT, TOOL.
  — *Needs a call: is Hindi script selection worth a user-facing knob, and what would it be called?*
- **`endpointing_sensitivity` is a free-form `str`** (low, since 2026-08-31) — AWS documents exactly
  `HIGH` / `MEDIUM` / `LOW`; a typo reaches the API instead of failing at construction. — *Needs a
  call: narrow the type now, or keep it open for values AWS may add?*

Not a gap: the Nova 2 Sonic release notes still end at the May 2026 in-place refresh and the Nova 2
doc history's newest Sonic entry is still 2026-06-22. The model card gives Nova 2 Sonic "EOL no
sooner than 2026-12-02" with a 6-month legacy period and no EOL date set, and supports only the
Standard service tier, so there is nothing to pass through there. Voices (16, including the Polly
matches) and locales pass through unchanged, since `Settings.voice` is a free-form `str`. Bedrock
split its lifecycle policy on 2026-09-07: models launched before that date, both Sonic models
included, are governed by the new "Model lifecycle (Legacy)" page, which is where the EOL table now
lives.

`probe.py run` still cannot fill AWS credentials on its own: the `aws_nova_realtime` registry entry
has an empty `include_params`, so `build_kwargs` never looks up `AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY` / `AWS_REGION` and the constructor raises `TypeError`. Both probes above
passed once those were supplied with `--kwarg`. Adding `access_key_id`, `secret_access_key` and
`region` to that entry's `include_params` would let future runs probe this unit unattended
(provider-watch tooling, not a service gap).

`probe.py list-models --provider aws` reports no OpenAI-compatible catalogue; `models_seen` comes from
Bedrock's lifecycle and regional-availability tables.
