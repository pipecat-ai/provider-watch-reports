# AWS Transcribe STT — 2026-08-31

Nothing is retiring and no source file changed since the last run; the open work is the two language PRs, plus a sample-rate path that mislabels audio it claims to convert.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5509 — Map the full AWS Transcribe streaming language set. Open; main still maps 53 of the 99 streaming codes.
- https://github.com/pipecat-ai/pipecat/pull/2849 — Add language options in AWS Transcribe STT Service; adds `identify_language`, `identify_multiple_languages` and `language_options`. Open since 2025-10-14 and untouched since 2025-10-16; it rewrites much of `stt.py`, so it will conflict with #5509.

### To consider

- **Sample rate is relabelled, not converted** (high, since 2026-08-31) — `_connect_websocket` clamps anything that is not 8000 or 16000 Hz to 16000 and warns "Converting from 24000 Hz to 16000 Hz", but nothing converts: no resampler sits between the pipeline and `run_stt`, which sends the pipeline's bytes as they are. A probe with a 24 kHz clip logged that warning and AWS then read 24 kHz PCM as 16 kHz; the same mismatch at a 2× ratio (16 kHz audio declared 8000) dropped the second half of the transcript, so the mislabelling does degrade recognition. The clamp is not needed at all — presigned URLs declaring 24000 and 48000 Hz were both accepted, and `MediaSampleRateHertz` is documented as 8000-48000. — *Needs a call: pass the pipeline rate through when it is in range, or resample to 16 kHz the way `OpenAIRealtimeSTTService` already does with `create_stream_resampler`.*
- **Streaming request parameters unreachable** (medium, since 2026-08-31) — `AWSTranscribeSTTSettings` declares no fields. Out of reach: custom vocabulary and vocabulary filter (`get_presigned_url` already takes `vocabulary_name` and `vocabulary_filter_name`, and the service never passes them), `vocabulary-filter-method`, PII redaction/identification with `pii-entity-types`, `language-model-name`, speaker labels, channel identification, and `partial-results-stability` — pinned to `"high"`, which AWS calls the fastest and least accurate of the three. — *Needs a call: which subset to expose first, and whether `"high"` stays the default. None of them can be probed end to end without account-side resources, so they cannot ride an automatic PR.*
- **Reconnects lose the session** (medium, since 2026-08-31) — the presigned URL carries neither `session-id` nor `session-resume-window`, so when `WebsocketSTTService` reconnects, AWS treats it as a brand-new stream and the in-flight segment is gone. AWS supports resuming within a 1-300 minute window. — *Needs a call: whether resume earns the state it adds, given how short a voice turn is.*
- **Nine streaming codes have no `Language` member** (low, since 2026-08-31) — `en-AB`, `en-WL`, `ckb-IQ`, `ckb-IR`, `kab-DZ`, `fa-AF`, `sw-BI`, `sw-RW`, `sw-UG`. `Language.KU` is Kurmanji and does not stand in for Sorani. — *Needs a call: whether `pipecat.transcriptions.language` should carry dialects only AWS distinguishes.*

## Sources
- https://docs.aws.amazon.com/transcribe/latest/APIReference/API_streaming_StartStreamTranscription.html — full request shape. `language-code` or `identify-language`/`identify-multiple-languages`, `media-encoding` and `sample-rate` are required; `MediaSampleRateHertz` is 8000-48000; everything else (vocabularies, PII, custom language model, session id and resume window, speaker labels, partial-results stability) is optional. No parameter is marked deprecated.

Main's `language_to_service_language` maps 53 of them.
