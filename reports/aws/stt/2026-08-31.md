# AWS Transcribe STT — 2026-08-31

Nothing is retiring. Two things bite users today: 46 streaming languages the map never learned (branch ready) and a sample-rate path that silently mislabels audio.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5509 — Map the full AWS Transcribe streaming language set
- https://github.com/pipecat-ai/pipecat/pull/2849 — Add language options in AWS Transcribe STT Service; adds `identify_language`, `identify_multiple_languages` and `language_options`. Open since 2025-10-14 and untouched since 2025-10-16; it rewrites much of `stt.py`, so it will conflict with the language-map branch.

### To consider

- **Sample rate is relabelled, not converted** (high, since 2026-08-31) — `_connect_websocket` clamps anything that is not 8000 or 16000 Hz to 16000 and logs "Converting from 24000 Hz to 16000 Hz", but nothing converts: `run_stt` forwards the pipeline's bytes as they are, so AWS decodes 24 kHz audio as 16 kHz. AWS does not require the clamp — an ad-hoc connect declaring 24000 Hz was accepted and returned transcripts, and `MediaSampleRateHertz` is documented as 8000-48000. — *Needs a call: pass the pipeline rate through when it is in range, or resample to 16 kHz the way `OpenAIRealtimeSTTService` already does with `create_stream_resampler`.*
- **Streaming request parameters unreachable** (medium, since 2026-08-31) — `AWSTranscribeSTTSettings` declares no fields. Out of reach: custom vocabulary and vocabulary filter (`get_presigned_url` already takes `vocabulary_name` and `vocabulary_filter_name`, and the service never passes them), `vocabulary-filter-method`, PII redaction/identification with `pii-entity-types`, `language-model-name`, speaker labels, channel identification, and `partial-results-stability` — pinned to `"high"`, which AWS calls the fastest and least accurate of the three. — *Needs a call: which subset to expose first, and whether `"high"` stays the default. None of them can be probed end to end without account-side resources, so they cannot ride an automatic PR.*
- **Reconnects lose the session** (medium, since 2026-08-31) — the presigned URL carries neither `session-id` nor `session-resume-window`, so when `WebsocketSTTService` reconnects, AWS treats it as a brand-new stream and the in-flight segment is gone. AWS supports resuming within a 1-300 minute window. — *Needs a call: whether resume earns the state it adds, given how short a voice turn is.*
- **Nine streaming codes have no `Language` member** (low, since 2026-08-31) — `en-AB`, `en-WL`, `ckb-IQ`, `ckb-IR`, `kab-DZ`, `fa-AF`, `sw-BI`, `sw-RW`, `sw-UG`. `Language.KU` is Kurmanji and does not stand in for Sorani. — *Needs a call: whether `pipecat.transcriptions.language` should carry dialects only AWS distinguishes.*

## Sources
- https://docs.aws.amazon.com/transcribe/latest/APIReference/API_streaming_StartStreamTranscription.html — full request shape. `language-code` or `identify-language`/`identify-multiple-languages`, `media-encoding` and `sample-rate` are required; `MediaSampleRateHertz` is 8000-48000; everything else (vocabularies, PII, custom language model, session id and resume window, speaker labels, partial-results stability) is optional. No parameter is marked deprecated.
- https://docs.aws.amazon.com/transcribe/latest/dg/supported-languages.html — the "Data input" column gives 99 codes with streaming; the asterisked ones are unavailable in af-south-1, ap-northeast-1, ap-southeast-5, ap-southeast-7 and cn-northwest-1.
- Live `languageCode` enum returned in an AWS validation error during a probe — exactly the same 99 codes as the docs table, which is what the branch maps against.
- https://docs.aws.amazon.com/transcribe/latest/dg/doc-history.html — nothing after 2025-01 touches streaming; the 2026 entries (2026-05-01, 2026-05-22, 2026-07-01) all extend PII redaction for *batch* jobs. No retirements.
- https://docs.aws.amazon.com/transcribe/latest/dg/streaming.html — streaming media formats (PCM/FLAC/Ogg-Opus), 50-200 ms chunk guidance, `LimitExceededException` causes.
- https://docs.pipecat.ai/api-reference/server/services/stt/aws — what we publish today: the 8000/16000 Hz clamp and "partial results stabilization enabled with high stability" are documented behaviour, so changing either is a docs change too.
- probe.py sdk-versions — `aiobotocore` pinned `>=3,<4`, latest 3.9.0 (2026-08-01): inside the pin. Transcribe streaming is reached over a hand-signed websocket, not the SDK, so the pin does not gate this unit.
- probe.py list-models --provider aws — no catalogue; Transcribe streaming has no model selector, which is why `default_model` is null.
- `gh pr list --search "aws transcribe language"` — surfaced the open community PR #2849.
