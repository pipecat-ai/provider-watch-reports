# AWS Transcribe STT — 2026-10-28

Current: no streaming change from AWS since the last run, the 99 streaming language codes are all mapped, and a live probe confirms the service still transcribes after the credential-chain rework in #6212. The sample-rate clamp stays the one high-priority gap.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/2849 — Add language options in AWS Transcribe STT Service; adds `identify_language`, `identify_multiple_languages` and `language_options`. Open since 2025-10-14, untouched since 2025-10-16, and it still conflicts with the merged language work in #5509.

### To consider

- **Sample rate is relabelled, not converted** (high, since 2026-08-31) — `_connect_websocket` clamps anything that is not 8000 or 16000 Hz to 16000 and warns "Converting from {rate} Hz to 16000 Hz", but nothing converts: no resampler sits between the pipeline and `run_stt`, which sends the pipeline's bytes as they are. The 2026-08-31 run measured the damage — a 24 kHz clip declared as 16000 produced 15 interims instead of 10, and 16 kHz audio declared as 8000 lost the second half of the transcript. The clamp is not needed: presigned URLs declaring 24000 and 48000 Hz were both accepted, and `MediaSampleRateHertz` is documented as 8000-48000. docs.pipecat.ai was corrected since the last run and now states the audio is not resampled, so only the service's own docstring and warning text still claim a conversion. — *Needs a call: pass the pipeline rate through when it is in range, or resample to 16 kHz the way `OpenAIRealtimeSTTService` already does with `create_stream_resampler`.*
- **Remaining streaming request parameters unreachable** (medium, since 2026-08-31) — out of reach are custom vocabulary and vocabulary filter (`get_presigned_url` already takes `vocabulary_name` and `vocabulary_filter_name`, and the service never passes them), `vocabulary-filter-method`, PII redaction/identification with `pii-entity-types`, `language-model-name`, speaker labels and channel identification. — *Needs a call: which subset to expose first. None of them can be probed end to end without account-side resources, so they cannot ride an automatic PR.*
- **Reconnects lose the session** (medium, since 2026-08-31) — the presigned URL carries neither `session-id` nor `session-resume-window`, so when `WebsocketSTTService` reconnects, AWS treats it as a brand-new stream and the in-flight segment is gone. AWS supports resuming within a 1-300 minute window. — *Needs a call: whether resume earns the state it adds, given how short a voice turn is.*
- **`transcript-format` unreachable, and probably unimplemented over websocket** (low, since 2026-09-14) — the endpoint accepts an unknown value for it while validating known parameters, which is how the 2026-09-14 run concluded it is ignored on the websocket path; a Settings field would be a silent no-op. Not re-probed this run, since neither the API reference nor the service changed. — *Needs a call: whether to ask AWS if `transcript-format` reaches the websocket endpoint at all, before spending the signer plumbing.*
