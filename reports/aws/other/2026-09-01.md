# AWS AgentCore — 2026-09-01

No change on either side: `agent_core.py` is untouched since June, AgentCore's release notes stop at August 2026, and the bundled service model is identical. The five known gaps stand as they were; none qualifies for a branch, because each would add constructor arguments or change default behaviour.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `AWSAgentCoreProcessor.process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. `runtimeSessionId` (the `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` header) is what pins invocations to one microVM and one conversation; AWS's invoke guide makes session management the mechanism for maintaining context across requests and recommends a UUID. The default payload transformer sends only the latest user message, so the agent gets no continuity from either side. — *Needs a call: where the ID comes from (a constructor argument, or one generated per conversation — botocore's `SessionType` is min 33 / max 256 characters), and whether teardown should call `StopRuntimeSession`.*
- **JWT/OAuth runtimes are unreachable** (medium, since 2026-09-01) — a runtime created with `authorizerConfiguration.customJWTAuthorizer` accepts only a bearer token on a raw HTTPS POST to `/runtimes/<escaped-arn>/invocations`; AWS states plainly that boto3 does not support bearer-token invocation. The processor only ever goes through aiobotocore's SigV4 client, and a runtime supports either SigV4 or JWT, not both, so users who deployed with an IdP authorizer cannot use this processor. — *Needs a call: whether a bearer-token HTTP path belongs here, since it means a second transport plus token refresh.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint), `runtimeUserId` (per-user scoping for AgentCore Identity/Memory), `accountId` (cross-account runtime addressed by agent ID), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are optional members of botocore's `InvokeAgentRuntimeRequest`; only `agentRuntimeArn` and `payload` are required. — *Needs a call: the processor has no `Settings` class, so this is a new params object or several constructor arguments; `runtimeUserId` additionally requires the separate `bedrock-agentcore:InvokeAgentRuntimeForUser` IAM action.*
- **409 RetryableConflictException is not retried** (medium, since 2026-08-31) — because no `Config` is passed, botocore's legacy retry mode is in force, covering `ThrottlingException` (429) and `InternalServerException` (500) with up to 5 attempts. It does not cover the 409, whose shape carries `retryable: {throttling: false}` — a trait only the `standard`/`adaptive` modes honour — so the turn is dropped as an `ErrorFrame` with category `UNKNOWN`. — *Needs a call: switching the client to `retries={"mode": "standard"}` is a default-behaviour change (extra backoff inside a voice turn), so it is a decision rather than a pass-through.*
- **No in-repo example or test** (low, since 2026-08-31) — AgentCore samples live in `pipecat-examples`; this repo has only `tests/test_aws_credentials.py`, and `examples/` has no AgentCore bot. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*
