# AWS AgentCore — 2026-10-28

Current: `InvokeAgentRuntime` is byte-identical to last run, October's release notes are Gateway/Memory/Evaluations plus a container-side FUSE feature, and the only change on our side was the October credential-chain fix. The five known gaps carry forward; none qualifies for a branch, because each would add constructor arguments or change default behaviour.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `AWSAgentCoreProcessor.process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. AWS's session guide tells applications to generate a session ID of at least 33 characters per user or conversation and pass it on every related invocation, and warns that without a consistent ID each request may land on a new microVM with cold-start latency. The default payload transformer sends only the latest user message, so the agent gets continuity from neither side. The response returns `runtimeSessionId`, so the processor could adopt the service-assigned ID after the first turn instead of minting one — but it reads no response headers today. — *Needs a call: where the ID comes from (a constructor argument, one generated per conversation — the request header is min 33 / max 256 characters — or the echoed response value), and whether teardown should call `StopRuntimeSession`.*
- **JWT/OAuth runtimes are unreachable** (medium, since 2026-09-01) — a runtime created with `authorizerConfiguration.customJWTAuthorizer` accepts only a bearer token on a raw HTTPS POST to `/runtimes/<escaped-arn>/invocations`; the API reference states that an OAuth-integrated agent cannot be invoked through the AWS SDK. The processor only ever goes through aiobotocore's SigV4 client, and a runtime supports either SigV4 or JWT, not both, so users who deployed with an IdP authorizer cannot use this processor. — *Needs a call: whether a bearer-token HTTP path belongs here, since it means a second transport plus token refresh.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint), `runtimeUserId` (per-user scoping for AgentCore Identity/Memory), `accountId` (address a runtime by agent ID rather than full ARN), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are optional members of `InvokeAgentRuntimeRequest`; only `agentRuntimeArn` and `payload` are required. — *Needs a call: the processor has no `Settings` class, so this is a new params object or several constructor arguments; `runtimeUserId` additionally requires the separate `bedrock-agentcore:InvokeAgentRuntimeForUser` IAM action.*
- **409 RetryableConflictException is not retried** (medium, since 2026-08-31) — because no `Config` is passed, botocore's legacy retry mode is in force; its `__default__` policy set matches socket errors, 500/502/503/504 and the throttling family, with up to 5 attempts, and does not cover the 409 whose shape carries the modeled retryable trait. The session guide pins down when it happens — a second operation against a session that is being provisioned or torn down — and says to retry with short exponential backoff, so today that turn is simply dropped. — *Needs a call: switching the client to `retries={"mode": "standard"}` is a default-behaviour change (extra backoff inside a voice turn), so it is a decision rather than a pass-through.*
- **Nothing exercises an invocation** (low, since 2026-08-31) — `tests/test_aws_credentials.py` now builds an `AWSAgentCoreProcessor` to assert its client signs with renewed default-chain credentials, but no test or example drives a context frame through `process_frame`; the runnable AgentCore samples live in `pipecat-examples`. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*
