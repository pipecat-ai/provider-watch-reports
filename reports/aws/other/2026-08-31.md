# AWS AgentCore — 2026-08-31

Nothing is retiring; the processor still never sends a runtime session ID, the single change most likely to affect users today. No branch: every item needs a shape decision first (the processor has no `Settings`, so each would add constructor arguments).

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `AWSAgentCoreProcessor.process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. The `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` header is what pins invocations to one microVM: AWS warns that "without a consistent session ID, each request may be routed to a new microVM, which may result in additional latency due to cold starts", and context is preserved only between invocations to the same session. Pipecat's own docs say the AgentCore agent receives only the last user message and manages its own memory — the session ID is the mechanism that would let it do so, and we don't send one. — *Needs a call: where the ID comes from (a constructor argument, or one generated per conversation — botocore's `SessionType` is min 33 / max 256 characters), and whether teardown should call `StopRuntimeSession`.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint rather than DEFAULT), `runtimeUserId` (per-user scoping for AgentCore Identity/Memory), `accountId` (cross-account runtime), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are plain optional members of botocore's `InvokeAgentRuntimeRequest`; only `agentRuntimeArn` and `payload` are required. — *Needs a call: the processor has no `Settings` class, so this is either a new params object or several constructor arguments.*
- **No retry for documented transient errors** (medium, since 2026-08-31) — `InvokeAgentRuntime` lists `RetryableConflictException` (409) and `ThrottlingException` (429) among its errors, and the model's own documentation for the former recommends exponential-backoff retry logic in the client. The processor does neither, and the base `FrameProcessor` converts the exception into a generic `ErrorFrame` with category `UNKNOWN`, dropping the turn. — *Needs a call: whether retry belongs in the processor given a voice turn's latency budget, and which errors should map to a rate-limit category.*
- **No in-repo example or test** (low, since 2026-08-31) — AgentCore samples live in `pipecat-examples`; this repo has only `tests/test_aws_credentials.py`, and `examples/` has no AgentCore bot. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*
