# AWS AgentCore — 2026-08-31

Nothing is retiring, but the processor never sends a runtime session ID — the single change most likely to affect users today. No branch: every item needs a shape decision first.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `AWSAgentCoreProcessor.process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. AWS documents that the `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` header is what pins invocations to one microVM: "Without a consistent session ID, each request may be routed to a new microVM, which may result in additional latency due to cold starts", and context is preserved only "between invocations to the same session". Pipecat's own docs say the AgentCore agent "does not receive the full conversation context after each user turn, only the last user message, and it is up to the AgentCore agent to decide whether and how to manage its own memory" — the session ID is the mechanism that would let it do so, and we don't send one. — *Needs a call: where the ID comes from (a constructor argument, or one generated per conversation — AgentCore requires 33+ characters), and whether teardown should call `StopRuntimeSession`.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint rather than DEFAULT), `runtimeUserId` (per-user scoping for AgentCore Identity/Memory), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are plain members of botocore's `InvokeAgentRuntime` input shape. — *Needs a call: the processor has no `Settings` class, so this is either a new params object or several constructor arguments.*
- **No retry for documented transient errors** (medium, since 2026-08-31) — AgentCore returns 409 `RetryableConflictException` while a session is being provisioned or torn down and tells clients to "Retry with short exponential backoff"; 429 `ThrottlingException` is the rate-limit path. The processor does neither, and the base `FrameProcessor` converts the exception into a generic `ErrorFrame` with category `UNKNOWN`, dropping the turn. — *Needs a call: whether retry belongs in the processor given a voice turn's latency budget, and which errors should map to a rate-limit category.*
- **No in-repo example or test** (low, since 2026-08-31) — AgentCore samples live in `pipecat-examples`; this repo has only `tests/test_aws_credentials.py`. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*

## Sources
- https://docs.aws.amazon.com/bedrock-agentcore/latest/APIReference/API_InvokeAgentRuntime.html — full request shape: only `agentRuntimeArn` and `payload` are required; `runtimeSessionId`, `qualifier`, `runtimeUserId`, `contentType`, `accept`, `mcp*` and the trace headers are all optional and all unused by us. Errors include 409 `RetryableConflictException` and 429 `ThrottlingException`.
- https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html — session semantics: 33-character minimum ID, context preserved only within a session, cold-start warning when no consistent ID is sent, 8 h microVM / 14 d instance lifetimes, `StopRuntimeSession`.
- https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html — 2026 changes are all deployment-side (Instances compute type Aug 2026, interactive shells Jun 2026, Node.js direct code deploy, VPC egress, custom header passthrough, quota increases to 1,000 TPS data plane). Nothing deprecated or renamed on `InvokeAgentRuntime`.
- botocore 1.43.56 bundled `bedrock-agentcore/2024-02-28/service-2.json` — confirms the API version we call and the parameter/header names above.
- probe.py sdk-versions — `aiobotocore` pin `>=3,<4`, latest 3.9.0 (2026-08-01), which is exactly what the lock resolves; no SDK gap for this unit. (`aws_sdk_bedrock_runtime` is pinned `~=0.4.0` against a 0.11.0 latest, but that SDK belongs to the Nova Sonic unit, not this one.)
