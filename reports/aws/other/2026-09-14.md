## What's new for Pipecat

### PRs

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `AWSAgentCoreProcessor.process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. `runtimeSessionId` is what pins invocations to one microVM and one conversation; AWS's invoke guide makes session management the mechanism for maintaining context across requests and recommends a UUID. The default payload transformer sends only the latest user message, so the agent gets no continuity from either side. The response also returns `runtimeSessionId`, so the processor could adopt the service-assigned ID after the first turn instead of minting one — but it reads no response headers today. — *Needs a call: where the ID comes from (a constructor argument, one generated per conversation — the request header is min 33 / max 256 characters — or the echoed response value), and whether teardown should call `StopRuntimeSession`.*
- **JWT/OAuth runtimes are unreachable** (medium, since 2026-09-01) — a runtime created with `authorizerConfiguration.customJWTAuthorizer` accepts only a bearer token on a raw HTTPS POST to `/runtimes/<escaped-arn>/invocations`; the API reference states that an OAuth-integrated agent cannot be invoked through the AWS SDK. The processor only ever goes through aiobotocore's SigV4 client, and a runtime supports either SigV4 or JWT, not both, so users who deployed with an IdP authorizer cannot use this processor. — *Needs a call: whether a bearer-token HTTP path belongs here, since it means a second transport plus token refresh.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint), `runtimeUserId` (per-user scoping for AgentCore Identity/Memory), `accountId` (address a runtime by agent ID rather than full ARN), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are optional members of `InvokeAgentRuntimeRequest`; only `agentRuntimeArn` and `payload` are required. — *Needs a call: the processor has no `Settings` class, so this is a new params object or several constructor arguments; `runtimeUserId` additionally requires the separate `bedrock-agentcore:InvokeAgentRuntimeForUser` IAM action.*
- **409 RetryableConflictException is not retried** (medium, since 2026-08-31) — because no `Config` is passed, botocore's legacy retry mode is in force, covering `ThrottlingException` (429) and `InternalServerException` (500) with up to 5 attempts. It does not cover the 409, whose shape carries the modeled retryable trait that only `standard`/`adaptive` honour, so the turn is dropped as an `ErrorFrame` with category `UNKNOWN` even though AWS documents the error as temporary and recommends backoff. — *Needs a call: switching the client to `retries={"mode": "standard"}` is a default-behaviour change (extra backoff inside a voice turn), so it is a decision rather than a pass-through.*
- **No in-repo example or test** (low, since 2026-08-31) — AgentCore samples live in `pipecat-examples`; in this repo AgentCore appears only in the service module itself. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*
