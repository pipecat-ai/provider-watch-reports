# AWS AgentCore — 2026-11-23

Current: `InvokeAgentRuntime`'s request shape has not moved, November's release notes (now 31 entries, all V2/Instances/Gateway platform work) need nothing client-side, and `src/pipecat/services/aws/agent_core.py` is unchanged since October's credential-chain fix. The five known gaps carry forward; none qualifies for a branch, because each needs a new params object, new constructor arguments, or a change to default retry behaviour.

## What's new for Pipecat

### PRs
Nothing.

### To consider

- **Runtime session ID is never sent** (high, since 2026-08-31) — `process_frame` calls `invoke_agent_runtime(agentRuntimeArn=..., payload=...)` and nothing else. The guide still tells applications to generate an ID of at least 33 characters per user or conversation, reuse it for every related invoke, and capture the one the response returns; without a consistent ID each request may land on a new microVM with cold-start latency, and the agent loses the state it kept between turns. Two V2 features added this month key off the same ID — session pinning (the session is bound to the identity that created it) and `{runtimeSessionId}` in an S3 mount prefix for per-session storage — so the ID is now load-bearing for more than stickiness. The default payload transformer sends only the latest user message, so there is no continuity from the Pipecat side either. — *Needs a call: where the ID comes from (a constructor argument, one generated per conversation — the request header is 33–256 characters — or the echoed response value), and whether teardown should call `StopRuntimeSession`.*
- **JWT/OAuth runtimes are unreachable** (medium, since 2026-09-01) — a runtime created with `authorizerConfiguration.customJWTAuthorizer` accepts only a bearer token on a raw HTTPS POST to `/runtimes/<escaped-arn>/invocations`; the API reference states that an OAuth-integrated agent cannot be invoked through the AWS SDK. The processor only ever goes through aiobotocore's SigV4 client, and a runtime supports either SigV4 or JWT, not both, so users who deployed with an IdP authorizer cannot use this processor. — *Needs a call: whether a bearer-token HTTP path belongs here, since it means a second transport plus token refresh.*
- **Other InvokeAgentRuntime parameters unreachable** (medium, since 2026-08-31) — `qualifier` (target a versioned endpoint), `runtimeUserId` (per-user scoping for Identity/Memory, and the header that makes a V2 session pinned), `accountId` (address a runtime by agent ID rather than full ARN), `contentType`/`accept`, and the tracing headers `traceId`/`traceParent`/`traceState`/`baggage`. All are optional members of `InvokeAgentRuntimeRequest`; only `agentRuntimeArn` and `payload` are required. — *Needs a call: the processor has no `Settings` class, so this is a new params object or several constructor arguments; `runtimeUserId` additionally requires the separate `bedrock-agentcore:InvokeAgentRuntimeForUser` IAM action.*
- **409 RetryableConflictException is not retried** (medium, since 2026-08-31) — because no `Config` is passed, botocore's legacy retry mode is in force; its `__default__` policy set matches socket errors, 500/502/503/504 and the throttling family, with up to 5 attempts, and does not cover the 409 whose shape carries the modeled retryable trait. The session guide pins down when it happens — a second operation against a session being provisioned or torn down — and says to retry with short exponential backoff, so today that turn is simply dropped. — *Needs a call: switching the client to `retries={"mode": "standard"}` is a default-behaviour change (extra backoff inside a voice turn), so it is a decision rather than a pass-through.*
- **Nothing exercises an invocation** (low, since 2026-08-31) — `tests/test_aws_credentials.py` builds an `AWSAgentCoreProcessor` to assert its client signs with renewed default-chain credentials, but no test or example drives a context frame through `process_frame`; the runnable AgentCore samples live in `pipecat-examples`. — *Needs a call: whether an AgentCore example belongs here, since running one requires a deployed agent runtime.*
