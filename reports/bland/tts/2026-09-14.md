## Notes

- **Nothing new from the provider.** The changelog's newest entry is still Adaptive Resumption
  (2026-08-03), a call-agent pacing feature with no TTS API surface; the last TTS entries remain
  BTTS Experimental (2026-04-30) and the Bland Speech launch (2026-03-11). The only Bland
  publication since the last run is a streaming-TTS developer guide (2026-09-05, updated
  2026-09-07) that describes existing behaviour and announces nothing.
- **Model list unchanged.** `GET /v2/tts-models` still lists `btts-3` ("prefer `btts-3` or
  newer"; controls calibrated for it, 48 kHz native) and `btts-2` (legacy, controls untuned).
  The model is a property of the voice rather than a request field, so `default_model: null`
  stays correct.
- **Request schema still fully covered.** HTTP `/v2/tts` takes `text` (≤ 5,000 chars),
  `voice`, `audio.{encoding,sample_rate,container}` and `controls.{expressiveness,stability}`;
  the WebSocket `init` takes `voice`, `audio` and the same two controls, with `speak`,
  `end_of_turn`, `cancel` and `close` as the client messages. `BlandTTSSettings` plus the
  request builders cover all of it. The only documented value not sent is
  `audio.encoding: mulaw`, which Pipecat cannot use — `TTSAudioRawFrame` carries linear PCM and
  telephony serializers do the μ-law conversion at the wire.
- **No SDK.** The `bland` extra has no dependencies; both classes speak HTTP/WebSocket
  directly, so there is no pin to fall behind.
