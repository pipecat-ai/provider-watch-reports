# Bland TTS — 2026-11-23

Nothing to ship: Bland's v2 TTS schema, model list, limits and endpoint set are unchanged since
the 2026-11-09 run, and both classes still send every field the API reads. Still unverified live.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Turn length cap** (low, since 2026-10-12) — Bland caps a realtime turn at 4,000 characters
  cumulatively across one `context_id` and rejects the overflow with `context_overflow`; `/v2/tts`
  caps a request at 5,000. `BlandTTSService` streams tokens into a single `context_id` for the
  whole bot turn and never counts them, so a long-form response ends mid-sentence with an
  ErrorFrame, and `BlandHttpTTSService` gets a 400 for an over-long text. Rare for conversational
  turns, reachable for read-aloud use.
  — *Needs a call: whether the service should open a fresh `context_id` when a turn approaches the
  cap (changes turn semantics and billing granularity) or the cap should simply be documented on
  the class.*

## Notes

- **Nothing new from the provider.** The changelog's newest entry is still Adaptive Resumption
  (2026-08-03); the last TTS entries remain BTTS Experimental (2026-04-30) and the Bland Speech
  launch (2026-03-11).
- **Tofu-1 is not this unit.** Bland opened a gated research preview of Tofu-1, a full-duplex
  *speech-to-speech* model, on 2026-11-15. It is not a TTS model, has no `/v2/tts` surface and no
  published API, so it changes nothing for these classes; a speech-to-speech unit would be where
  it lands if it ships.
- **Model list unchanged.** `GET /v2/tts-models` still lists `btts-3` ("Prefer `btts-3` or newer",
  48 kHz native, controls calibrated for it) and `btts-2` (still synthesizes, controls untuned),
  with identical rates, encodings and containers and no deprecation on either. The model is a
  property of the voice — resolved model comes back in the `x-model` response header, there is no
  request field — so `default_model: null` stays correct.
- **Request schema still fully covered.** HTTP `/v2/tts` takes `text` (≤5,000 chars), `voice`,
  `audio.{encoding,sample_rate,container}` and `controls.{expressiveness,stability}`; the
  WebSocket `init` takes `voice`, `audio` and the same two controls, with `speak`, `end_of_turn`,
  `cancel` and `close` as the client messages, the same 23 error codes, and the voice fixed for the
  life of the connection. No language, speed, style, seed or model field anywhere. The only
  documented value not sent is `audio.encoding: mulaw`, which Pipecat cannot use —
  `TTSAudioRawFrame` carries linear PCM and telephony serializers convert at the wire.
- **`auto_formatting` is still not in the public reference.** The setting is sent top-level on both
  transports, but neither `/api-v2/post/tts`, `/api-v2/post/tts-ws` nor Writing for Speech
  documents it; that page's nearest content is a "what is normalized for you" list (emails, URLs,
  smart quotes, repeated punctuation) with no request field. Unset by default, so no user is
  exposed unless they opt in; worth re-checking against the reference each run.
- **No expression markup.** Delivery is `controls` plus in-text punctuation, CAPITALS and the
  `<|N|>` pause marker (0.1–10.0 s). The `<vocal burst>` string on the Writing for Speech page is
  still only a spacing illustration with no syntax or supported list, so the model performs no
  sounds or deliveries and needs no expression adapter.
- **Concurrency limits unchanged.** Still a flat default of 1 concurrent generation per
  organization across every speech surface, raised by emailing Bland rather than by topping up a
  wallet. Admission failure surfaces as `rate_limited`, which `_connect_websocket` already reports
  from the non-`ready` reply.
- **Voices unchanged.** Karen (`29158307-…`, the service and examples' default), Matthew and River
  are still the built-ins; the example literals are current. Clones cover "17+ languages" but no
  language request field exists.
- **No Python SDK.** `docs.bland.ai/sdks/bland-tts` documents `bland-tts`, an npm package for
  Node 20+ built on the legacy `/v1/speak` endpoint. The `bland` extra has no dependencies and both
  classes speak HTTP/WebSocket directly, so there is no pin to fall behind.
