## Notes

- **No model to default to.** Bland's `GET /v2/tts/models` lists `btts-2` and `btts-3`, but
  the model is not a request field — "You do not choose a model — the voice you pass decides
  it", returned as the `x-model` response header. `default_model: null` is correct, and
  `BTTS_V3` (`btts-3`) is what the code's default voice and its `expressiveness`/`stability`
  calibration target, matching Bland's current recommendation.
- **Request schema is fully covered.** HTTP `/v2/tts` takes `text`, `voice`, `audio`
  (`encoding`, `sample_rate`, `container`) and `controls` (`expressiveness`, `stability`);
  the WebSocket `init` takes `voice`, `audio` and the same `controls`, with `speak`,
  `end_of_turn`, `cancel` and `close` as the client messages. `BlandTTSSettings` plus the
  request builders cover all of it. The one documented value the service does not send is
  `audio.encoding: mulaw`, which Pipecat cannot use: `TTSAudioRawFrame` carries linear PCM
  and the telephony serializers do the μ-law conversion at the wire, so an 8 kHz PCM render
  is already the right path.
- **Endpoints are current.** `wss://api.bland.ai/v2/tts/ws` and `https://api.bland.ai/v2/tts`
  are the endpoints Bland documents today. The older `/v1/speak` surface still exists (it is
  what the `bland-tts` CLI/Node SDK uses) but returns a stored-sample URL rather than a
  stream, so it is not the right target for a voice agent.
- **No SDK.** The `bland` extra has no dependencies; both classes speak HTTP/WebSocket
  directly, so there is no pin to fall behind.
- **Text-level features need no code.** Inline pauses (`<|0.8|>`) and Speech Studio
  performance tags travel inside `text` and already work through both classes.
