# Tavus video — 2026-11-09

Nothing to fix or bump: Tavus's 10-29 changelog entry documents Pipecat's new emotion control as shipped and its emotion vocabulary matches `TavusEmotion` exactly, and the exact payload `TavusApi.create_conversation` sends still returns 200.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **PAL/Face rename** (medium, since 2026-08-31) — the create-conversation reference lists only `face_id`/`pal_id`, Tavus's Pipecat integration page passes `face_id=os.getenv("TAVUS_FACE_ID")` which our constructor rejects, and the echo-mode guide routes users through a PAL with `pipeline_mode: "echo"`. The legacy names still work and carry no removal date, so this stays a naming/docs divergence rather than breakage. — *Needs a call: adding a `face_id`/`pal_id` alias means a new constructor parameter and a registry env-var change, plus a stance on deprecating `replica_id`.*
- **Conversation creation fields** (medium, since 2026-08-31) — the create call sends only `replica_id` and `persona_id`, so users cannot set `properties.max_call_duration` (3600 s cap), `participant_absent_timeout`, `apply_greenscreen`, the recording fields, or the top-level `policy: "eu"` and `audio_only`. — *Needs a call: which knobs to expose and where, since the conversation is created once in `setup()` from constructor args and the value must thread through three layers.*
- **Faces that can't show emotion** (low, since 2026-11-09) — the new emotion path sends `conversation.set_emotion` for any face, but Tavus scopes expression to Pro Phoenix-4/4.5 faces and says nothing about what an older face does with the event; nothing in the service, the example or our reference tells the user their face has to be one. — *Needs a call: whether a docstring note is enough, or the client should read the face's generation and warn at setup.*
