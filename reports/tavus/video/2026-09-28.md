# Tavus video — 2026-09-28

Nothing to fix or bump: the exact payload `TavusApi.create_conversation` sends still returns 200, and the two months of Tavus feature work all lands in the PAL/CVI layers that persona `pipecat0` bypasses.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **PAL/Face rename** (medium, since 2026-08-31) — the create-conversation reference lists only `pal_id`/`face_id`, and Tavus's Pipecat integration page passes `face_id=os.getenv("TAVUS_FACE_ID")`, which our constructor rejects. The legacy names are undocumented on that endpoint but still accepted (200 today) and carry no removal date, so this remains a naming/docs divergence rather than breakage. — *Needs a call: adding a `face_id`/`pal_id` alias means a new constructor parameter and a registry env-var change, plus a stance on deprecating `replica_id`.*
- **Conversation creation fields** (medium, since 2026-08-31) — the create call sends only `replica_id` and `persona_id`, so users cannot set `properties.max_call_duration` (3600 s cap), `participant_absent_timeout`, `apply_greenscreen` (useful when compositing the avatar into the bot's own video out), the recording fields, or the top-level `policy: "eu"` for EU-resident conversations. — *Needs a call: which knobs to expose and where, since the conversation is created once in `setup()` from constructor args and the value must thread through three layers.*
