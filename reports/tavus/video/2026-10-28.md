# Tavus video — 2026-10-28

Nothing to fix or bump: the exact payload `TavusApi.create_conversation` sends still returns 200, `pipecat0` is still an echo-mode persona, and Tavus's two changelog items since the last run (Sparrow-2 turn detection, the 10-15 feature batch) land outside echo mode.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **PAL/Face rename** (medium, since 2026-08-31) — the create-conversation reference lists only `face_id`/`pal_id`, Tavus's Pipecat integration page passes `face_id=os.getenv("TAVUS_FACE_ID")` which our constructor rejects, and the echo-mode guide routes users through a PAL with `pipeline_mode: "echo"` instead of a shared persona id. Both names take the same ids — `face_id` + `pal_id` returned 200 today with the values we pass as `replica_id` + `persona_id` — and the legacy names carry no removal date, so this stays a naming/docs divergence rather than breakage. — *Needs a call: adding a `face_id`/`pal_id` alias means a new constructor parameter and a registry env-var change, plus a stance on deprecating `replica_id`.*
- **Conversation creation fields** (medium, since 2026-08-31) — the create call sends only `replica_id` and `persona_id`, so users cannot set `properties.max_call_duration` (3600 s cap), `participant_absent_timeout`, `apply_greenscreen` (useful when compositing the avatar into the bot's own video out), the recording fields, or the top-level `policy: "eu"` and `audio_only`. — *Needs a call: which knobs to expose and where, since the conversation is created once in `setup()` from constructor args and the value must thread through three layers.*
