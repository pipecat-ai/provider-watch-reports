# Tavus video — 2026-08-31

Nothing to fix: the echo/interrupt app-message protocol the service speaks matches Tavus's current schema field for field, and the legacy `replica_id` / `/v2/personas` names it uses are still live.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **PAL/Face rename** (medium, since 2026-08-31) — Tavus's API and docs now say `pal_id`/`face_id`; `TavusVideoService` exposes `replica_id` (and the runner registry `TAVUS_REPLICA_ID`), so Tavus's own Pipecat integration guide, which passes `face_id=os.getenv("TAVUS_FACE_ID")`, fails with a TypeError against our constructor. Legacy names remain supported aliases on the API with no announced removal. — *Needs a call: adding a `face_id`/`pal_id` alias means a new constructor parameter and a registry env-var change, plus a stance on deprecating `replica_id`.*
- **Conversation properties** (medium, since 2026-08-31) — `create_conversation` sends only `replica_id` and `persona_id`, so users cannot set `properties.max_call_duration` (defaults to a 3600 s hard cap), `participant_absent_timeout`, `apply_greenscreen` (useful when compositing the avatar into the bot's own video out), or recording fields. — *Needs a call: which knobs to expose and where, since the conversation is created once in `setup()` while `Settings` are runtime-updatable, and the value must thread through three layers.*

## Sources
- https://docs.tavus.io/sections/event-schemas/conversation-echo — echo schema (`modality`, `text`, `audio`, `sample_rate`, `inference_id`, `done`) matches what `TavusTransportClient.encode_audio_and_send` sends; `done` must stay false until the last chunk, which the send task does
- https://docs.tavus.io/sections/event-schemas/conversation-interrupt — `conversation.interrupt` is still `{message_type, event_type, conversation_id}`, exactly what `send_interrupt_message` sends
- https://docs.tavus.io/api-reference/conversations/create-conversation — request body is now `pal_id`/`face_id` with a `properties` object (`max_call_duration` 3600, `participant_absent_timeout` 300, `apply_greenscreen`, `languages`, `recording_storage`); `language` and the S3 recording fields are deprecated, none of which Pipecat sends
- https://docs.tavus.io/api-reference/faces/list-faces — "`/v2/replicas` and `replica_id` / `replica_ids` remain supported as aliases"
- https://docs.tavus.io/api-reference/pals/get-pal — PAL objects report `pal_name`; the legacy persona route still reports `persona_name` (probed)
- https://docs.tavus.io/sections/integrations/pipecat — Tavus documents `TavusVideoService(face_id=...)` and `TAVUS_FACE_ID`, which our constructor does not accept
- https://docs.tavus.io/sections/changelog/changelog — 2026 entries are PAL-pipeline work (tavus-gemma-4 default, sparrow-2, Raven-1, Magic Canvas); none touch echo mode, which bypasses the CVI layers
- probe.py list-models / sdk-versions — no catalogue for tavus and no direct SDK; the `tavus` extra pulls `pipecat-ai[daily]`, and daily-python 0.32.0 (2026-08-19, installed) sits inside the `>=0.29.0,<1` pin
