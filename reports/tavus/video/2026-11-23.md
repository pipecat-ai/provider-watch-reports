# Tavus video — 2026-11-23

Nothing to bump or patch in the service; the one dated item is external — Tavus retires Phoenix-3 on 2026-12-14, and the replica this watch environment uses is a Phoenix-3 face.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Phoenix-3 retirement on 2026-12-14** (high, since 2026-11-23) — Tavus's 11-19 changelog sets the date. Pipecat hard-codes no replica, so the fix is configuration and documentation: `GET /v2/replicas/{TAVUS_REPLICA_ID}` here reports `model_name: phoenix-3`, which is what the Tavus example and the release-eval manifest entry run against, and the service says nothing about which face generations Tavus serves. Conversations with that replica still return 200 today. — *Needs a call: move the eval/CI replica to a Phoenix-4.5 face, and decide whether the service docstring and example should state the face-generation requirement.*
- **PAL/Face rename** (medium, since 2026-08-31) — the create-conversation reference lists only `face_id`/`pal_id`, and Tavus's Pipecat page passes `face_id=os.getenv("TAVUS_FACE_ID")`, which our constructor rejects. Tavus's new speech-to-speech page documents the workaround ("Pipecat's Tavus transport still takes a `replica_id` argument. Pass your Tavus Face ID there."), and the aliases carry no removal date, so this stays a naming divergence rather than breakage. — *Needs a call: adding a `face_id`/`pal_id` alias means a new constructor parameter and a registry env-var change, plus a stance on deprecating `replica_id`.*
- **Conversation creation fields** (medium, since 2026-08-31) — the create call sends only `replica_id` and `persona_id`, so users cannot set `properties.max_call_duration` (3600 s cap), `participant_absent_timeout`, `apply_greenscreen`, the recording fields, the top-level `policy: "eu"` and `audio_only`, or the new `callback_url`/`callback_secret`. — *Needs a call: which knobs to expose and where, since the conversation is created once in `setup()` from constructor args and the value must thread through three layers.*
- **Faces that can't show emotion** (low, since 2026-11-09) — the emotion path sends `conversation.set_emotion` for any face, while Tavus scopes expression to Phoenix-4/4.5 and recommends Pro faces; nothing in the service, the example or our reference tells the user their face has to be one. — *Needs a call: whether a docstring note is enough, or the client should read the face's generation and warn at setup.*
