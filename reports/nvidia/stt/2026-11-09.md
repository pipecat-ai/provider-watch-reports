# NVIDIA STT — 2026-11-09

Quiet month: NIM Speech is still on 26.10.0, the Riva client's ASR proto is unchanged, and both gRPC classes transcribe correctly and about 2–3× faster than on 2026-10-12. No branch this run.

## What's new for Pipecat

Nothing from the provider. The release-notes page's latest entry is still **26.10.0** (page last touched 2026-11-06, no new release behind it). `nvidia-riva-client` **2.28.0** shipped on 2026-11-06, inside our `>=2.25.1,<3` pin, and its `riva/client` package — helpers and generated protos alike — is byte-identical to the 2.27.0 we have installed, so it adds no affordance to expose.

Two previously open items are closed:

- The SageMaker docstring fix shipped as [#6140](https://github.com/pipecat-ai/pipecat/pull/6140) (merged 2026-10-13); `_send_session_config` now documents the served model name it sends.
- docs.pipecat.ai's NVIDIA STT page now gives `b0e8b4a5-217c-40b7-9b96-17d84e666317` for `NvidiaSegmentedSTTService`, matching the code, so the stale function id gap is gone.

`nemotron-transcribe` joins `models_seen`: it is in 26.10.0 and in the support matrix, but NVIDIA serves it through a separate OpenAI-compatible HTTP API rather than the gRPC or realtime interfaces our classes speak. It was missing from the previous report's list.

### PRs
Nothing.

### To consider
- **Streaming class skips the locale map** (medium, since 2026-09-01) — `language_to_nvidia_nemotron_speech_language` exists in `nvidia/stt.py` but only `NvidiaSegmentedSTTService` wires it into `language_to_service_language`, so the streaming class sends the enum's bare value. `language=en` still transcribes fine on the hosted endpoint (TTFB 439 ms), so what remains is structural: the support matrix names locales only, and `Language.PT` → `pt` or `Language.FR` → `fr` is a code a self-hosted multilingual NIM has no entry for. — *Needs a call: sign-off on the behavior change, since base codes would start resolving to locales (`EN`→`en-US`, `PT`→`pt-BR`, `ES`→`es-ES`) for deployments that rely on today's pass-through.*
- **Locale map covers 13 of 40 locales** (medium, since 2026-09-01) — Nemotron ASR Streaming's `type=multi` transcribes 40 locales in three tiers (19 transcription-ready, 13 broad-coverage, 8 adaptation-ready). The map has ar-AR, de-DE, en-GB, en-US, es-ES, es-US, fr-FR, hi-IN, it-IT, ja-JP, ko-KR, pt-BR and ru-RU; nl-NL, fr-CA, pt-PT, tr-TR, uk-UA and vi-VN are transcription-ready and unmapped, and both lower tiers fall back to a bare base code. — *Needs a call: verification requires a self-hosted multi-type NIM — the hosted NVCF deployment is en-US only (see the de-DE row below), so added entries cannot be probed from here.*
- **`Settings.model` never reaches the request** (medium, since 2026-09-14) — the streaming `_create_recognition_config` pins `model=""` and the segmented one omits the field, so on a self-hosted NIM with several models loaded the model name is documentation only and the server default wins. It cannot simply be passed through: the hosted Canary deployment answered `INVALID_ARGUMENT: Model canary-1b-asr is not available on server` when the name was sent. — *Needs a call: whether to send `Settings.model` only when the caller overrode it or only when `server` is not the NVCF endpoint — either way it needs a rule for telling the two deployment shapes apart.*
- **Diarization settings are a no-op on the segmented service** (medium, since 2026-09-01) — `speaker_diarization` and `diarization_max_speakers` are inherited into `NvidiaSegmentedSTTSettings`, but the segmented `_create_recognition_config` never calls `riva.client.add_speaker_diarization_to_config`. Setting them changes nothing and logs nothing. The streaming class does pass them through, so 26.10.0's eight-speaker ceiling is already reachable there. — *Needs a call: whether hosted Canary supports offline diarization at all; if not, the fields belong on the streaming settings class rather than the shared base.*
- **Rejected configs retry forever instead of erroring** (medium, since 2026-09-01) — `_response_handler` turns every `grpc.RpcError` into a drop reason and `_handle_stream_drop` answers it with `_request_reconnect()`. The `language=de-DE` probe below produced no transcript in 30 s and no `ErrorFrame`, so a misconfigured pipeline is indistinguishable from a silent user. — *Needs a call: which gRPC status codes should be fatal rather than retried, and whether that belongs here or in `STTService`'s reconnect policy.*
- **SageMaker settings expose nothing** (medium, since 2026-10-12) — `NvidiaSageMakerSTTSettings` still adds no fields beyond the base `model` and `language`, and `_send_session_config` hard-codes `enable_automatic_punctuation: true`. NIM's realtime `transcription_session.update` also accepts `max_alternatives`, `enable_word_time_offsets`, `enable_profanity_filter`, `enable_verbatim_transcripts`, `speaker_diarization`, `word_boosting` and a full `endpointing_config` — every one of which the gRPC classes already expose, so SageMaker users get strictly less control over the same NIM. — *Needs a call: a deployed SageMaker endpoint to probe the pass-through against; none is configured here.*
- **SageMaker SDK pin three releases behind** (medium, since 2026-10-12) — `sagemaker = ["aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10"]` excludes 0.10.0 (2026-08-20), 0.11.0 (2026-08-24) and 0.12.0 (2026-10-08); nothing newer shipped this month. The package calls itself experimental with breaking changes expected before 1.0, so a conservative pin is reasonable, but it has not moved since August. — *Needs a call: whether `services/aws/sagemaker/bidi_client.py` still works on 0.12 — there is no SageMaker endpoint here to run it against.*
- **Default word-boost score above the documented range** (low, since 2026-10-12) — 26.10.0 widened word-boosting scores to −200…200 for CTC models and Nemotron ASR Streaming but kept 0.5…2.0 for other RNNT and TDT models. Both services default `boosted_lm_score` to 4.0, in range only on the hosted default; the probe below confirms Nemotron still accepts it. — *Needs a call: whether to lower the default or document it per model — observing the out-of-range case needs a self-hosted Parakeet TDT or RNNT NIM.*
- **Nemotron Transcribe is out of reach** (low, since 2026-11-09) — NVIDIA's instruction-driven offline ASR (40 languages, translation to and from English) is served only over `/v1/audio/transcriptions` and `/v1/chat/completions`; the gRPC and realtime references that our three classes implement explicitly exclude it. A self-hosted deployment is already reachable through `OpenAISTTService(base_url=...)`. — *Needs a call: whether it deserves a class or a documented recipe, or nothing at all.*
