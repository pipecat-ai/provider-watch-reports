# NVIDIA STT — 2026-11-23

NVIDIA retired the hosted `canary-1b-asr` API at 09:00 UTC today, so `NvidiaSegmentedSTTService`'s shipped default fails outright; the branch moves it to `parakeet-1.1b-rnnt-multilingual`.

## What's new for Pipecat

The build.nvidia.com page for `canary-1b-asr` carries a **Deprecated** badge and the notice "This API will be deprecated on 11/22/2026. It will no longer be supported from 11/23/2026 at 1:00 AM PT (09:00 UTC)." Our probe matches: both attempts at the shipped default returned gRPC `NOT_FOUND` for function `b0e8b4a5-217c-40b7-9b96-17d84e666317`, while the same account reaches the streaming function fine. No hosted Canary successor exists (`canary-1b-v2`, `canary-1b-flash`, `canary-qwen-2_5b` have no page; `canary-0-6b-turbo-asr` is deprecated too), so the branch picks the closest hosted offline model: `parakeet-1.1b-rnnt-multilingual` (function `71203149-d3b7-4460-8231-1be2543a1fca`), 27 locales in the support matrix against Canary's multilingual coverage, and faster than the English-only `parakeet-ctc-1.1b-asr` alternative (687 ms vs 1318 ms). Translation (`task:translate` through `custom_configuration`) was Canary-only and goes away with the hosted deployment either way.

Otherwise quiet: NIM Speech is still on **26.10.0** (release-notes page last touched 2026-11-06), `nvidia-riva-client` is still 2.28.0 inside our `>=2.25.1,<3` pin, and the ASR support matrix is unchanged.

One previously open item is closed by code: the segmented service now calls `riva.client.add_speaker_diarization_to_config`, so `speaker_diarization` / `max_speakers` are no longer silently dropped (`d62368d3b`..`d68ad2985`). The hosted deployment accepts them; what it returns is the new low-priority item below.

### To consider
- **Docs page points at the retired Canary default** (medium, since 2026-11-23) — docs.pipecat.ai's NVIDIA STT page gives `canary-1b-asr` / `b0e8b4a5-217c-40b7-9b96-17d84e666317` as `NvidiaSegmentedSTTService`'s defaults; that function stopped serving today, so the page's copy-paste example fails. — *Needs a call: the page lives in the docs repo and needs the same change as the branch once it merges.*
- **Streaming class skips the locale map** (medium, since 2026-09-01) — `language_to_nvidia_nemotron_speech_language` exists in `nvidia/stt.py` but only `NvidiaSegmentedSTTService` wires it into `language_to_service_language`, so the streaming class sends the enum's bare value. The hosted endpoint tolerates `en`, so what remains is structural: the support matrix names locales only, and `Language.PT` → `pt` is a code a self-hosted multilingual NIM has no entry for. — *Needs a call: sign-off on the behavior change, since base codes would start resolving to locales (`EN`→`en-US`, `PT`→`pt-BR`, `ES`→`es-ES`) for deployments that rely on today's pass-through.*
- **Locale map covers 13 of 40 locales** (medium, since 2026-09-01) — Nemotron ASR Streaming's `type=multi` transcribes 40 locales in three tiers; the map has ar-AR, de-DE, en-GB, en-US, es-ES, es-US, fr-FR, hi-IN, it-IT, ja-JP, ko-KR, pt-BR and ru-RU. nl-NL, fr-CA, pt-PT, tr-TR, uk-UA and vi-VN are transcription-ready and unmapped. The branch's new segmented default covers 27 locales, 13 of which the map names — its "prompt" type list is exactly the mapped set. — *Needs a call: verification requires a self-hosted multi-type NIM — the hosted streaming deployment is en-US only, so added entries cannot be probed from here.*
- **`Settings.model` never reaches the request** (medium, since 2026-09-14) — the streaming `_create_recognition_config` pins `model=""` and the segmented one omits the field, so on a self-hosted NIM with several models loaded the model name is documentation only and the server default wins. It cannot simply be passed through: a hosted deployment answers `INVALID_ARGUMENT` for a model name it does not serve. — *Needs a call: whether to send `Settings.model` only when the caller overrode it or only when `server` is not the NVCF endpoint — either way it needs a rule for telling the two deployment shapes apart.*
- **SageMaker settings expose nothing** (medium, since 2026-10-12) — `NvidiaSageMakerSTTSettings` adds no fields beyond the base `model` and `language`, and `_send_session_config` hard-codes `enable_automatic_punctuation: true`. NIM's realtime `transcription_session.update` also accepts `max_alternatives`, `enable_word_time_offsets`, `enable_profanity_filter`, `enable_verbatim_transcripts`, `speaker_diarization`, `word_boosting` and a full `endpointing_config` — every one of which the gRPC classes already expose. — *Needs a call: a deployed SageMaker endpoint to probe the pass-through against; none is configured here.*
- **SageMaker SDK pin five releases behind** (medium, since 2026-10-12) — `sagemaker = ["aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10"]` now excludes 0.10.0, 0.11.0, 0.12.0 and 0.13.0/0.13.1 (2026-11-18). The package calls itself experimental with breaking changes expected before 1.0, so a conservative pin is reasonable, but it has not moved since August. — *Needs a call: whether `services/aws/sagemaker/bidi_client.py` still works on 0.13 — there is no SageMaker endpoint here to run it against.*
- **Default word-boost score above the documented range** (low, since 2026-10-12) — 26.10.0 keeps word-boosting scores at 0.5…2.0 for RNNT and TDT models while widening CTC and Nemotron ASR Streaming to −200…200; both services default `boosted_lm_score` to 4.0. The hosted RNNT Parakeet accepts 4.0 and the boost works (it turned "Pitpacut" into "Pipecat"), so no deployment has rejected it yet. — *Needs a call: whether to lower the default or document it per model — observing the out-of-range case needs a self-hosted Parakeet TDT or RNNT NIM.*
- **Hosted offline diarization returns untagged words** (low, since 2026-11-23) — with `speaker_diarization=true` and `max_speakers=2`, an ad-hoc Riva `offline_recognize` against the hosted multilingual Parakeet returned 18 words all carrying `speaker_tag` 0, which the service reads as "no speaker" and emits the segment whole. The clip has one speaker, so this may be a correct result rather than a missing diarizer. — *Needs a call: a multi-speaker clip or a self-hosted NIM with the Sortformer diarizer profile to tell the two apart.*
- **Nemotron Transcribe is out of reach** (low, since 2026-11-09) — NVIDIA's instruction-driven offline ASR (40 languages, translation to and from English) is served only over `/v1/audio/transcriptions` and `/v1/chat/completions`; the gRPC and realtime references our three classes implement explicitly exclude it. A self-hosted deployment is already reachable through `OpenAISTTService(base_url=...)`. — *Needs a call: whether it deserves a class or a documented recipe, or nothing at all.*
