# NVIDIA STT — 2026-10-12

NIM Speech 26.10.0 shipped since the last run and asks nothing of us; the one clear-cut fix is the SageMaker docstring, now that NVIDIA's own mapping table confirms the default model string.

## What's new for Pipecat

NIM Speech **26.10.0** (Nemotron ASR Streaming container 1.4.0) adds eight-speaker Sortformer diarization, `batch_size=512` profiles, configurable beam search for cache-aware streaming RNNT, and processed-audio duration in HTTP and realtime responses. Nothing is deprecated and no model was added or renamed. The diarization ceiling needs no code change — `diarization_max_speakers` already reaches `max_speaker_count` through `riva.client.add_speaker_diarization_to_config` — and the duration field is on the HTTP and realtime paths, not the gRPC one our classes use.

The 2026-09-14 report's open question about the SageMaker default is **resolved**: NVIDIA's "Container Image to Served Model Mapping" table gives `cache-aware-parakeet-rnnt-en-US-asr-streaming-sortformer` as the served name of the `nemotron-asr-streaming` container, so the string the code sends is current and the docstring naming the container was the thing that was wrong.

### To consider
- **Streaming class skips the locale map** (medium, since 2026-09-01) — `language_to_nvidia_nemotron_speech_language` exists in `nvidia/stt.py` but only `NvidiaSegmentedSTTService` wires it into `language_to_service_language`, so the streaming class sends the enum's bare value. Downgraded from high this run: `language=en` now transcribes on the hosted endpoint (TTFB 1012 ms), where the same probe on 2026-09-14 produced no transcript, so the demonstrated silent failure is gone. What remains is structural — the support matrix names locales only, so `Language.PT` → `pt` or `Language.FR` → `fr` is still a code a self-hosted multilingual NIM has no entry for. — *Needs a call: sign-off on the behavior change, since base codes would start resolving to locales (`EN`→`en-US`, `PT`→`pt-BR`, `ES`→`es-ES`) for deployments that rely on today's pass-through.*
- **Locale map covers 13 of 40 locales** (medium, since 2026-09-01) — Nemotron ASR Streaming's `type=multi` transcribes 40 locales in three tiers (19 transcription-ready, 13 broad-coverage, 8 adaptation-ready). The map has ar-AR, de-DE, en-GB, en-US, es-ES, es-US, fr-FR, hi-IN, it-IT, ja-JP, ko-KR, pt-BR and ru-RU; Dutch, fr-CA, pt-PT, Turkish, Ukrainian, Vietnamese and both lower tiers fall back to a bare base code. — *Needs a call: verification requires a self-hosted multi-type NIM, so the table cannot be extended on probe evidence from the hosted endpoint.*
- **`Settings.model` never reaches the request** (medium, since 2026-09-14) — the streaming `_create_recognition_config` pins `model=""` and the segmented one omits the field, so on a self-hosted NIM with several models loaded the model name is documentation only and the server default wins. It cannot simply be passed through: the hosted Canary deployment answered `INVALID_ARGUMENT: Model canary-1b-asr is not available on server` when the name was sent. — *Needs a call: whether to send `Settings.model` only when the caller overrode it or only when `server` is not the NVCF endpoint — either way it needs a rule for telling the two deployment shapes apart.*
- **Diarization settings are a no-op on the segmented service** (medium, since 2026-09-01) — `speaker_diarization` and `diarization_max_speakers` are inherited into `NvidiaSegmentedSTTSettings`, but the segmented `_create_recognition_config` never calls `riva.client.add_speaker_diarization_to_config`. Setting them changes nothing and logs nothing. The streaming class does pass them through, so 26.10.0's eight-speaker ceiling is already reachable there. — *Needs a call: whether hosted Canary supports offline diarization at all; if not, the fields belong on the streaming settings class rather than the shared base.*
- **Rejected configs retry forever instead of erroring** (medium, since 2026-09-01) — `_response_handler` funnels every `grpc.RpcError` into `_request_reconnect()`. The `language=de-DE` probe below sat silent for 25 s and pushed no `ErrorFrame`, so a misconfigured pipeline is indistinguishable from a silent user. — *Needs a call: which gRPC status codes should be fatal rather than retried, and whether that belongs here or in `STTService`'s reconnect policy.*
- **SageMaker settings expose nothing** (medium, since 2026-10-12) — `NvidiaSageMakerSTTSettings` adds no fields beyond the base `model` and `language`, and `_send_session_config` hard-codes `enable_automatic_punctuation: true`. NIM's realtime `transcription_session.update` also accepts `max_alternatives`, `enable_word_time_offsets`, `enable_profanity_filter`, `enable_verbatim_transcripts`, `speaker_diarization` (1–8 speakers on Nemotron), `word_boosting` and a full `endpointing_config` — every one of which the gRPC classes already expose, so SageMaker users get strictly less control over the same NIM. — *Needs a call: a deployed SageMaker endpoint to probe the pass-through against; `NVIDIA_SAGEMAKER_STT_ENDPOINT_NAME` is not configured here.*
- **SageMaker SDK pin three releases behind** (medium, since 2026-10-12) — `sagemaker = ["aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10"]` excludes 0.10.0 (2026-08-20), 0.11.0 (2026-08-24) and 0.12.0 (2026-10-08). The package calls itself experimental with breaking changes expected before 1.0, so a conservative pin is reasonable, but it has not moved since August. (The 2026-09-14 report recorded this SDK as inside the pin; it was not.) — *Needs a call: whether `services/aws/sagemaker/bidi_client.py` still works on 0.12 — there is no SageMaker endpoint here to run it against.*
- **Stale function id in the published docs** (low, since 2026-09-01) — docs.pipecat.ai's NVIDIA STT page still gives `ee8dc628-76de-4acc-8595-1836e7e857bd` for `NvidiaSegmentedSTTService`; the code ships `b0e8b4a5-217c-40b7-9b96-17d84e666317`, which transcribed successfully again this run. — *Needs a call: the fix lives in the docs repo, not this one.*
- **Default word-boost score above the documented range** (low, since 2026-10-12) — 26.10.0 widened word-boosting scores to −200…200 for CTC models and Nemotron ASR Streaming but kept 0.5…2.0 for other RNNT and TDT models. Both services default `boosted_lm_score` to 4.0, in range only on the hosted default; the probe below confirms Nemotron accepts it. — *Needs a call: whether to lower the default or document it per model — observing the out-of-range case needs a self-hosted Parakeet TDT or RNNT NIM.*
