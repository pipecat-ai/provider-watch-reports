# NVIDIA STT — 2026-09-14

Nothing to bump — both hosted defaults transcribe and no NIM release landed since 26.07.0 — but `NvidiaSTTService` with `Language.EN` is silently dead on the hosted endpoint, and that is now reproducible.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Streaming class skips the locale map** (high, since 2026-09-01) — `language_to_nvidia_nemotron_speech_language` exists in `nvidia/stt.py` but only `NvidiaSegmentedSTTService` wires it into `language_to_service_language`. The streaming class inherits `STTService`'s base, which returns the enum unchanged, so `Language.EN` goes out as `en` where Riva wants `en-US`. Probed both ways this run: `language=en` transcribes on the segmented service (TTFB 613 ms) and yields no transcript at all on the streaming one; `language=en-US` works on both. Passing the plain `Language.EN` is the obvious thing for a user to do, and the pipeline just goes quiet. — *Needs a call: sign-off on the behavior change, since base codes would start resolving to locales (`EN`→`en-US`, `PT`→`pt-BR`, `ES`→`es-ES`) for deployments that rely on today's pass-through.*
- **Locale map covers 13 of 40 locales** (medium, since 2026-09-01) — Nemotron 3.5 ASR Streaming's multilingual type transcribes 40 language-locales. The map has ar-AR, de-DE, en-GB, en-US, es-ES, es-US, fr-FR, hi-IN, it-IT, ja-JP, ko-KR, pt-BR and ru-RU; Dutch, fr-CA, pt-PT, Turkish, Ukrainian, Vietnamese and the whole broad-coverage tier fall back to a bare base code the NIM rejects. — *Needs a call: verification requires a self-hosted multi-type NIM, so the table cannot be extended on probe evidence from the hosted endpoint.*
- **`Settings.model` never reaches the request** (medium, since 2026-09-14) — the streaming `_create_recognition_config` pins `model=""` and the segmented one omits the field, so on a self-hosted NIM with several models loaded the model name is documentation only and the server default wins. It cannot simply be passed through: an ad-hoc gRPC call against the hosted Canary deployment with `model="canary-1b-asr"` set came back `INVALID_ARGUMENT: Model canary-1b-asr is not available on server`, while the same call with `model=""` was accepted. — *Needs a call: whether to send `Settings.model` only when the caller overrode it or only when `server` is not the NVCF endpoint — either way it needs a rule for telling the two deployment shapes apart.*
- **Diarization settings are a no-op on the segmented service** (medium, since 2026-09-01) — `speaker_diarization` and `diarization_max_speakers` are inherited into `NvidiaSegmentedSTTSettings`, but the segmented `_create_recognition_config` never calls `riva.client.add_speaker_diarization_to_config`. Setting them changes nothing and logs nothing. — *Needs a call: whether hosted Canary supports offline diarization at all; if not, the fields belong on the streaming settings class rather than the shared base.*
- **Rejected configs retry forever instead of erroring** (medium, since 2026-09-01) — `_response_handler` funnels every `grpc.RpcError` into `_request_reconnect()`. Both failing language probes below produced a permanent `INVALID_ARGUMENT` and no `ErrorFrame`, so a misconfigured pipeline is indistinguishable from a silent user. — *Needs a call: which gRPC status codes should be fatal rather than retried, and whether that belongs here or in `STTService`'s reconnect policy.*
- **Stale function id in the published docs** (low, since 2026-09-01) — docs.pipecat.ai's NVIDIA STT page still gives `ee8dc628-76de-4acc-8595-1836e7e857bd` for `NvidiaSegmentedSTTService`; the code ships `b0e8b4a5-217c-40b7-9b96-17d84e666317`, which transcribed successfully again this run. — *Needs a call: the fix lives in the docs repo, not this one.*
- **SageMaker default model string unverified** (low, since 2026-09-01) — `cache-aware-parakeet-rnnt-en-US-asr-streaming-sortformer` names the NIM profile behind the SageMaker wrapper. NVIDIA superseded the cache-aware Parakeet streaming line with Nemotron 3.5 ASR Streaming on 2026-06-04, so the string may have moved with it. — *Needs a call: a deployed SageMaker endpoint name to probe against; `NVIDIA_SAGEMAKER_STT_ENDPOINT_NAME` is not configured here.*
- **SageMaker session-config docstring contradicts the code** (low, since 2026-09-14) — `_send_session_config`'s docstring says it specifies `"model": "nemotron-asr-streaming"` in `input_audio_transcription`; the code sends `self._settings.model`, whose default is the cache-aware Parakeet string. — *Needs a call: which of the two strings is right depends on the unresolved SageMaker default above, and there is no endpoint to probe the fix against.*
