# NVIDIA TTS — 2026-10-12

Speech NIM moved from 26.07.0 to 26.10.0 but the release is entirely ASR; the TTS models, their request schema and the shipped default are unchanged, and PR #5580 remains the only open work.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5580 — Add a custom_configuration setting to NvidiaTTSService (open since last run)

### To consider
- **Word timestamps** (medium, since 2026-09-01) — `enable_word_time_offsets` returns per-word start/end times in `SynthesizeSpeechResponse.meta.words` for Magpie Multilingual and Zeroshot. `_build_base_request` never sets the flag and `_process_responses` reads only `item.audio`, so the service cannot emit word timestamps. — *Needs a call: wiring Riva's streaming response metadata into `TTSService`'s word-timestamp API is more than a request-field pass-through.*
- **Zero-shot prompt transcript** (low, since 2026-09-01) — `zero_shot_data.transcript` is accepted by riva-client 2.27.0 next to the prompt audio, but the service only sets `audio_prompt`, `encoding` and `quality`. — *Needs a call: the transcript belongs with the constructor's `zero_shot_audio_prompt_file`, so exposing it means a new constructor parameter.*

## Checked and current

- Provider: 26.10.0 (Oct 2026) ships only Nemotron ASR Streaming 1.4.0; no TTS container, feature, parameter or deprecation in it. Magpie Multilingual (12 languages), Magpie Zeroshot and Chatterbox Multilingual are as documented at 26.07.0, and nothing on the default is deprecated.
- Default: hosted function id `877104f7-…` with voice `Magpie-Multilingual.EN-US.Aria` still synthesizes against `grpc.nvcf.nvidia.com:443` (probe below).
- Request schema: `SynthesizeSpeechRequest` in riva-client 2.27.0 (still the latest) is unchanged — `text`, `language_code`, `encoding`, `sample_rate_hz`, `voice_name`, `zero_shot_data`, `custom_dictionary`, `custom_configuration`, `enable_word_time_offsets`, `id`; the service covers all but the three listed gaps.
- Magpie's emotional voice variants (e.g. `Magpie-Multilingual.FR-FR.Pascal.Calm`) are just voice names, and voice/language/model are pass-through strings with no allowlist or per-model table to fall behind.
- Examples: `voice-nvidia.py`, `voice-nvidia-segmented.py`, `function-calling-nvidia.py` and `update-settings/tts/tts-nvidia.py` all construct the service with its defaults, so no model string can go stale there.
- SDKs: `nvidia-riva-client` 2.27.0 (latest) sits inside the `>=2.25.1,<3` pin; `protobuf` 7.36.2 is outside the deliberate `>=6.31.1,<7` pin because riva-client requires protobuf 6.x.
- SageMaker classes ship `model="magpie"` as an endpoint label and their bodies mirror the deployed NIM wrapper, so there is no provider schema to fall behind. The `aws_sdk_sagemaker_runtime_http2>=0.6.0,<0.10` cap (latest 0.12.0) is the shared AWS SageMaker client used by every `sagemaker` service, not NVIDIA's — it belongs to the aws unit.
- Pipecat side: `src/pipecat/services/nvidia/tts.py` is untouched since the last report; `sagemaker/tts.py` only gained session-failure classification (d57520a9a), which does not affect the provider surface.
