# NVIDIA TTS — 2026-11-09

Nothing changed on NVIDIA's TTS surface this cycle; the `custom_configuration` PR merged, and the two remaining gaps are unchanged and both need a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5580 — merged 2026-10-28; `NvidiaTTSSettings.custom_configuration` now forwards Magpie's streaming controls and Chatterbox's `exaggeration_factor`, so that gap is closed.

### To consider
- **Word timestamps** (medium, since 2026-09-01) — `enable_word_time_offsets` returns per-word start/end times in `SynthesizeSpeechResponse.meta.words` for Magpie Multilingual and Zeroshot, and the customization docs still document it. `_build_base_request` never sets the flag and both the stitched and per-sentence response loops read only `item.audio`, so the service cannot emit word timestamps. — *Needs a call: wiring Riva's streaming response metadata into `TTSService`'s word-timestamp API is more than a request-field pass-through.*
- **Zero-shot prompt transcript** (low, since 2026-09-01) — `ZeroShotData.transcript` and `ZeroShotData.sample_rate_hz` are accepted next to the prompt audio, but the service only sets `audio_prompt`, `encoding` and `quality`. — *Needs a call: the transcript belongs with the constructor's `zero_shot_audio_prompt_file`, so exposing it means a new constructor parameter; hosted zero-shot models also need NVIDIA approval, so the change could not be probed.*

## Checked and current

- Provider: Speech NIM is still 26.10.0 (page refreshed 2026-11-06) and its only containers are Nemotron ASR Streaming 1.4.0 and Nemotron Transcribe 1.0.0 — no TTS container, feature, parameter or deprecation. Magpie Multilingual (12 languages), Magpie Zeroshot and Chatterbox Multilingual (23 languages, emotion exaggeration) are as documented at 26.07.0.
- Request schema: `SynthesizeSpeechRequest` in riva-client 2.28.0 is byte-identical to 2.27.0 (compared the generated file descriptors of both wheels); the whole 2.28.0 release touches only `package_info.py`. The service covers every field but the two listed gaps.
- Customization docs list exactly the knobs we now reach: `flush`, `chunk_len_threshold`, `max_chunk_threshold`, `exaggeration_factor` via `custom_configuration`, plus SSML `<phoneme>`/`<say-as>` and the pronunciation dictionary — and `enable_word_time_offsets`, the gap above.
- Default: the hosted NVCF function id `877104f7-…` with `Magpie-Multilingual.EN-US.Aria` synthesizes against `grpc.nvcf.nvidia.com:443` at TTFB 133 ms, faster than the 232 ms seen a month ago. No successor is positioned: `magpie-tts-flow` is an older cloning model whose NGC container is marked no longer supported, and the August 2026 open-weights Magpie release is the same 12-language Multilingual model already shipped in 26.07.0.
- Voice, language and model stay pass-through strings with no allowlist or per-model table, so emotional voice variants (`Magpie-Multilingual.FR-FR.Pascal.Calm`) and new languages need no code change.
- SDKs: `nvidia-riva-client` 2.28.0 (2026-11-06, latest) sits inside the `>=2.25.1,<3` pin; `protobuf` 7.36.2 stays outside the deliberate `>=6.31.1,<7` pin because riva-client requires protobuf 6.x. `aws_sdk_sagemaker_runtime_http2` 0.12.0 above the `<0.10` cap and `aiobotocore` 3.10.0 inside `>=3,<4` belong to the shared SageMaker/AWS units, not here.
- Pipecat side since the last report: `nvidia/tts.py` gained the merged `custom_configuration` setting plus a fix that fetches the synthesis config off the event loop (d3e36a024); neither changes the provider surface. Examples (`voice-nvidia.py`, `voice-nvidia-segmented.py`, `function-calling-nvidia.py`, `update-settings/tts/tts-nvidia.py`) construct the service with its defaults, so no model string can go stale.
- SageMaker classes still ship `model="magpie"` as an endpoint label over a deployed NIM wrapper — no provider schema to fall behind.
- docs.pipecat.ai already documents `custom_configuration`, `synthesis_mode` and `quality`, so the docs are in step with the code.
