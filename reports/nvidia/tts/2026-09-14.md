# NVIDIA TTS — 2026-09-14

Nothing changed on either side this fortnight: NVIDIA's latest Speech NIM is still 26.07.0, the shipped default synthesizes fine, and the only open work is PR #5580.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5580 — Add a custom_configuration setting to NvidiaTTSService (open since last run)

### To consider
- **Word timestamps** (medium, since 2026-09-01) — TTS NIM 26.07.0 added `enable_word_time_offsets`, returning per-word start/end times in `SynthesizeSpeechResponse.meta.words` for Magpie Multilingual and Zeroshot. `_build_base_request` never sets the flag and `_process_responses` reads only `item.audio`, so the service cannot emit word timestamps. — *Needs a call: wiring Riva's streaming response metadata into `TTSService`'s word-timestamp API is more than a request-field pass-through.*
- **Zero-shot prompt transcript** (low, since 2026-09-01) — `zero_shot_data.transcript` is accepted by riva-client 2.27.0 next to the prompt audio, but the service only sets `audio_prompt`, `encoding` and `quality`. Lower value now that Magpie TTS Flow (the model that required a prompt transcript) is unsupported in favour of Zeroshot. — *Needs a call: the transcript belongs with the constructor's `zero_shot_audio_prompt_file`, so exposing it means a new constructor parameter.*

## Checked and current

- Provider: no Speech NIM release after 26.07.0 (July 2026); the three TTS containers, their locales and voices are unchanged, and nothing on Magpie Multilingual is deprecated.
- Default: `model_function_map` function id `877104f7-…` with voice `Magpie-Multilingual.EN-US.Aria` still synthesizes against `grpc.nvcf.nvidia.com:443` (probe below).
- Request schema: `SynthesizeSpeechRequest` in riva-client 2.27.0 exposes exactly `text`, `language_code`, `encoding`, `sample_rate_hz`, `voice_name`, `zero_shot_data`, `custom_dictionary`, `custom_configuration`, `enable_word_time_offsets`, `id` — the service covers all but the three listed gaps (`id` is a request correlation id, not user-facing).
- No gates to fall behind: voice, language and model are pass-through strings; there is no allowlist or per-model table in the service.
- SDKs: `nvidia-riva-client` 2.27.0 (latest) is inside the `>=2.25.1,<3` pin; `protobuf` 7.36.1 is outside the `>=6.31.1,<7` pin but riva-client itself requires protobuf 6.x, so the pin is correct.
- SageMaker classes ship `model="magpie"` as an endpoint label; their request bodies mirror the deployed NIM wrapper, so there is no provider schema to fall behind.
- Pipecat side: no commit has touched `src/pipecat/services/nvidia/{tts.py,sagemaker/tts.py}` since the last report.
