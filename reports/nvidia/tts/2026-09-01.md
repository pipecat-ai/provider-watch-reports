# NVIDIA TTS — 2026-09-01

Magpie TTS Multilingual is still NVIDIA's current hosted model and the shipped default works; the one clear-cut gap (per-request `custom_configuration`) is on a branch, word timestamps need a maintainer's call.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5580 — Add a custom_configuration setting to NvidiaTTSService

### To consider
- **Word timestamps** (medium, since 2026-09-01) — TTS NIM 26.07.0 added `enable_word_time_offsets`, returning per-word start/end times in `SynthesizeSpeechResponse.meta.words` for Magpie Multilingual and Zeroshot. `_build_base_request` never sets the flag and `_process_responses` reads only `item.audio`, so the service cannot emit word timestamps. — *Needs a call: wiring Riva's streaming response metadata into `TTSService`'s word-timestamp API is more than a request-field pass-through.*
- **Zero-shot prompt transcript** (low, since 2026-09-01) — `zero_shot_data.transcript` is accepted by riva-client 2.27.0 next to the prompt audio, but the service only sets `audio_prompt`, `encoding` and `quality`. Lower value now that Magpie TTS Flow (the model that required a prompt transcript) is deprecated in favour of Zeroshot. — *Needs a call: the transcript belongs with the constructor's `zero_shot_audio_prompt_file`, so exposing it means a new constructor parameter.*

## Checked and current

- Hosted default: `model_function_map` function id `877104f7-…` and voice `Magpie-Multilingual.EN-US.Aria` still synthesize against `grpc.nvcf.nvidia.com:443`.
- Languages: all twelve Magpie locales (including the new `ko-KR`, `ar-XA`, `pt-BR`) come out of `str(Language.X)` unchanged, so no mapping table is missing.
- Magpie TTS Flow's deprecation touches nothing: no Pipecat source or example references it.
- SDKs: `nvidia-riva-client` 2.27.0 (latest) is inside the `>=2.25.1,<3` pin; the extra's `protobuf>=6.31.1,<7` matches riva-client's own `protobuf==6.33.5` requirement.
- SageMaker classes ship `model="magpie"` as an endpoint label; their request bodies mirror the deployed NIM wrapper, so there is no provider schema to fall behind.
