# NVIDIA Omni LLM — 2026-11-09

Nothing to ship: `nemotron-3-nano-omni-30b-a3b-reasoning` is still the only audio-input model NIM serves, carries no deprecation notice, and the service's audio turn, transcript split, and tool calling all work against the live endpoint.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Omni reasons on every spoken turn, with no Settings field to stop it** (medium, since 2026-11-09) — the model card says reasoning is on by default. Probed, that costs 472 ms of thinking before the first answer token on a trivial prompt (TTFAT 680 ms) and 1445 ms on an arithmetic one (TTFAT 1593 ms); in audio input mode that time lands between the user stopping and TTS starting. NVIDIA's switches work on the cloud endpoint: `chat_template_kwargs.enable_thinking=false` answered in 183 ms with no `LLMThought*` frames, and `reasoning_budget=16` cut thinking to 14 deltas (413 ms TTFAT under `chat_template_kwargs`, 348 ms as a top-level `extra_body` key — the endpoint honors both nestings, so `run_multimodal_inference`'s `reasoning_budget` argument does reach the model). None of it is reachable except through the nested `extra={"extra_body": {...}}` form, and `examples/voice/voice-nvidia-omni.py` sets neither. — *Needs a call: a pass-through field has to define what happens when a user also sets `extra_body` directly (nvidia/llm tracks the same question for super-120b), and nothing benchmarks what capping Omni's reasoning costs in quality.*
- **No TTFAT metric in audio input mode** (low, since 2026-11-09) — `service_metadata_frame()` reports the service as realtime so the user aggregator waits for the transcript; `LLMService.reports_ttfat` derives from that same flag, so `_push_llm_text` never closes the TTFAT measurement. The default configuration therefore emits TTFB (which ends at the first reasoning token) but no TTFAT, while `audio_input=False` reports both. — *Needs a call: whether the realtime flag should keep gating TTFAT for a service that answers in text rather than audio.*

The default stays: no omni successor exists. NVIDIA's Nemotron 3.5 wave added `nemotron-3.5-super-vl-120b-a12b` (vision-language) and `nemotron-3.5-bolt-e4b` (text-only) to the catalogue since the last NVIDIA run, and neither takes audio. Other catalogue churn — `minimaxai/minimax-m3.1-flash`, `mistralai/mistral-large-4-1t-a52b`, `stepfun-ai/step-5-preview`, the two `nemotron-3.5-embed` models added; `meta/llama-3.2-11b-vision-instruct`, `moonshotai/kimi-k3`, `z-ai/glm-5.3` gone — touches nothing this service or its example names. The service's sampling defaults (temperature 0.6, top_p 0.95) match the model card's thinking-mode recommendation, and the WAV the service builds for each turn is inside the documented audio limits (wav/mp3, 8 kHz or higher, up to 1 hour).
