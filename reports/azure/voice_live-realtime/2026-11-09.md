# Azure Voice Live realtime — 2026-11-09

Nothing broke since last month: `2026-07-15` is still the newest API version and the service pins it. The default `gpt-4o-mini` remains on Foundry's Deprecated lifecycle (retires 2027-04-14), and one new gap appeared — the noise-suppression allowlist rejects the two suppression modes Microsoft added to this API version. Still no Voice Live credential here, so no probe and no branch.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Default `gpt-4o-mini` is deprecated** (high, since 2026-10-12) — Voice Live still lists it (Standard tier), but the Foundry retirement schedule marks `gpt-4o-mini` 2024-07-18 **Deprecated** (blocked for new customers) with retirement **2027-04-14** and no declared replacement. Standard-tier Voice Live successors: `gpt-5.6-luna` (GA, retires 2028-01-11), `gpt-5-mini` (GA, retirement moved out to 2027-07-13), or the native-audio `gpt-realtime-2.1-mini` (GA, 2027-06-25). The table newly lists `gpt-6.1-sol` (Pro) and `gpt-6-luna` (Lite), neither of which has a lifecycle entry yet. — *Needs a call: Microsoft names no replacement, and the candidates split between a cascaded text model (same Azure-TTS voice behaviour as today) and a native-audio one (which changes voice handling); no credential was available to probe either.*
- **`reasoning_effort` and `parallel_tool_calls` unreachable** (medium, since 2026-10-12) — both are top-level `RealtimeRequestSession` fields. `SessionProperties` keeps Pydantic's default `extra="ignore"`, so passing them validates and then serialises to nothing (re-checked locally: the `model_dump(exclude_none=True)` is `{}`). The reference documents `reasoning_effort` as none/minimal/low/medium/high/xhigh, which matters now that Voice Live offers the GPT-5 and GPT-6 families. — *Needs a call: a live session to confirm the fields are accepted, which needs a Foundry resource credential.*
- **Noise-suppression allowlist blocks two documented modes** (medium, since 2026-11-09) — `InputAudioNoiseReduction.type` is `Literal["near_field", "far_field", "azure_deep_noise_suppression"]`, but api-version 2026-07-15 also documents `azure_deep_noise_suppression_headset` (keeps the close speaker, suppresses background speech) and `azure_personal_noise_suppression` (target-speaker only). Both raise a `ValidationError` today; widening the Literal is one line. — *Needs a call: the docs say both modes require deployment support, and confirming the service accepts them needs a Voice Live credential, which this environment has none of.*
- **Interim responses not configurable** (medium, since 2026-10-12) — Voice Live can speak filler while a tool runs or latency passes a threshold, via `interim-response` (`static-interim-response` or `llm-interim-response`) on the session, and `interim_response` per response. — *Needs a call: whether Pipecat should surface a provider-side filler mechanism, given pipelines usually handle this themselves.*
- **`end_of_utterance_detection` field mismatch** (medium, since 2026-10-12) — the API documents `threshold_level` (`low`/`medium`/`high`/`default`); `EndOfUtteranceDetection` exposes `threshold: float`, so the documented knob is unreachable and the float goes out under a name the schema does not list. — *Needs a call: whether `threshold` is still accepted, since renaming it breaks anyone setting it today.*
- **Foundry Agent Service sessions unsupported** (medium, since 2026-10-12) — an agent-backed session connects with `agent_id` and `project_id` instead of `model`, and rejects `instructions`, which the service always syncs into the session. — *Needs a call: this needs new constructor arguments and a branch in the session payload, so whether agent-backed Voice Live is in scope.*
- **Input sample rate forwarded unchecked** (medium, since 2026-10-12) — `_ensure_audio_config` forces PCM and sets `input_audio_sampling_rate` to the transport's rate; the how-to lists 16000 and 24000 as the supported PCM values, so an 8 kHz telephony transport configures an undocumented rate. The output path already clamps to 24 kHz with a warning; the input path does not. — *Needs a call: confirmation that Voice Live rejects rather than resamples 8000 Hz input before adding a resample-or-warn path.*
- **Provider-hosted tools only as raw dicts** (low, since 2026-11-09) — the reference documents `MCPTool` and `FoundryAgentTool` next to function tools. They can be declared, since `VoiceLiveTool` falls back to `dict`, but `parse_server_event` models none of `mcp_list_tools`, `mcp_call`, `mcp_approval_request` or `foundry_agent_call`, and there is no client event for `mcp_approval_response` — so with the default `require_approval: always` the call never completes. — *Needs a call: whether provider-hosted tools belong in a Pipecat realtime service, since the approval round-trip needs new client events rather than a settings field.*
- **`avatar`, `animation`, `output_audio_timestamp_types`, `metadata` unreachable** (low, since 2026-10-12) — all dropped by `SessionProperties`. The avatar config has since grown photo avatars (`vasa-1`/`vasa-2`) and a `scene` object; avatar and animation also need their server events modelled, which `parse_server_event` returns None for. — *Needs a call: whether avatar video output belongs in this service or a separate processor, before the plain pass-through fields are worth adding alone.*
- **Image input not modelled** (low, since 2026-10-12) — `ItemContent.type` has no `input_image`, which the reference documents as `RealtimeRequestImageContentPart` with `image_url` and `detail`. — *Needs a call: whether a realtime service should accept vision frames, and which Voice Live models support them.*
