### To consider

- **Default `gpt-4o-mini` is deprecated** (high, since 2026-10-12) — the retirement schedule (refreshed 2026-11-18) still marks `gpt-4o-mini` 2024-07-18 **Deprecated** with retirement **2027-04-14** and no replacement, while Voice Live still lists it (Standard tier). Standard-tier successors: `gpt-5.6-luna` (GA, 2028-01-11), `gpt-5-mini` (GA, 2027-07-13), or the native-audio `gpt-realtime-2.1-mini` (GA, now 2027-07-31). `gpt-6.1-sol` and `gpt-6-luna` now have lifecycle entries (both GA to 2028-03-11) but sit in the Pro and Lite tiers respectively. — *Needs a call: Microsoft names no replacement, and the candidates split between a cascaded text model (same Azure-TTS voice behaviour as today) and a native-audio one (which changes voice handling); no credential was available to probe either.*
- **`reasoning_effort` and `parallel_tool_calls` unreachable** (medium, since 2026-10-12) — both are top-level `RealtimeRequestSession` fields. `SessionProperties` keeps Pydantic's default `extra="ignore"`, so passing them validates and then serialises to nothing (re-checked offline: the `model_dump(exclude_none=True)` is `{}`). `ReasoningEffort` is none/minimal/low/medium/high/xhigh. — *Needs a call: a live session to confirm the fields are accepted, which needs a Foundry resource credential.*
- **Noise-suppression allowlist blocks two documented modes** (medium, since 2026-11-09) — `InputAudioNoiseReduction.type` is `Literal["near_field", "far_field", "azure_deep_noise_suppression"]`, but the how-to and the reference both document `azure_deep_noise_suppression_headset` (keeps the close speaker, suppresses background speech) and `azure_personal_noise_suppression` (target-speaker only). Both raise a `ValidationError` today; widening the Literal is one line. — *Needs a call: the docs say both modes require deployment support, and confirming the service accepts them needs a Voice Live credential, which this environment has none of.*
- **Interim responses not configurable** (medium, since 2026-10-12) — Voice Live can speak filler while a tool runs or latency passes a threshold, via `interim-response` on the session (`static-interim-response` with `texts`, or `llm-interim-response` with its own `model`/`instructions`) and `interim_response` per response. — *Needs a call: whether Pipecat should surface a provider-side filler mechanism, given pipelines usually handle this themselves.*
- **`end_of_utterance_detection` field mismatch** (medium, since 2026-10-12) — the API documents `threshold_level` (`low`/`medium`/`high`/`default`); `EndOfUtteranceDetection` exposes `threshold: float`, so the documented knob is unreachable and the float goes out under a name the schema does not list. — *Needs a call: whether `threshold` is still accepted, since renaming it breaks anyone setting it today.*
- **Foundry Agent Service sessions unsupported** (medium, since 2026-10-12) — an agent-backed session connects with `agent_id` and `project_id` instead of `model`, and rejects `instructions`, which the service always syncs into the session. — *Needs a call: this needs new constructor arguments and a branch in the session payload, so whether agent-backed Voice Live is in scope.*
- **Input sample rate forwarded unchecked** (medium, since 2026-10-12) — `_ensure_audio_config` forces PCM and sets `input_audio_sampling_rate` to the transport's rate; the how-to lists 16000 and 24000 as the supported PCM values, so an 8 kHz telephony transport configures an undocumented rate. The output path already clamps to 24 kHz with a warning; the input path does not. — *Needs a call: confirmation that Voice Live rejects rather than resamples 8000 Hz input before adding a resample-or-warn path.*
- **Provider-hosted tools only as raw dicts** (low, since 2026-11-09) — the reference documents `MCPTool` and `FoundryAgentTool` next to function tools, and hosted `web_search_call` / `file_search_call` items. They can be declared, since `VoiceLiveTool` falls back to `dict`, but `parse_server_event` models none of the hosted-call events, and there is no client event for `mcp_approval_response` — so with the default `require_approval: always` the call never completes. — *Needs a call: whether provider-hosted tools belong in a Pipecat realtime service, since the approval round-trip needs new client events rather than a settings field.*
- **`avatar`, `animation`, `output_audio_timestamp_types`, `metadata` unreachable** (low, since 2026-10-12) — all dropped by `SessionProperties`. The avatar config covers video and photo avatars (`vasa-1`/`vasa-2`) with `scene`, `output_protocol` and `output_audit_audio`; avatar and animation also need their server events modelled, which `parse_server_event` returns None for. — *Needs a call: whether avatar video output belongs in this service or a separate processor, before the plain pass-through fields are worth adding alone.*
- **Image input not modelled** (low, since 2026-10-12) — `ItemContent.type` has no `input_image`, which the reference documents as `RealtimeRequestImageContentPart` with `image_url` and `detail`; the how-to notes `microsoft-realtime-flash-1` does not accept images, so support is per-model. — *Needs a call: whether a realtime service should accept vision frames, and which Voice Live models support them.*
- **Transcription allowlist carries undocumented and retired models** (low, since 2026-11-23) — `InputAudioTranscription.model` allows `azure-mrs`, `mai-transcribe-1`, `mai-transcribe-1.5` and `mai-transcribe-medical`, none of which appear in the how-to's current transcription table; `MAI-Transcribe-1` retired on 2026-09-15 per the Foundry schedule. — *Needs a call: whether the undocumented values still work on older deployments, since dropping them from the Literal breaks anyone passing one.*
