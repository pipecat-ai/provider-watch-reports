# Azure Voice Live realtime — 2026-10-12

No urgent breakage, but the default `gpt-4o-mini` now sits on Foundry's Deprecated lifecycle with a 2027-04-14 retirement, and a handful of documented session properties are silently dropped before the request is built. Nothing could be probed: no Voice Live credential is configured here.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Default `gpt-4o-mini` is deprecated** (high, since 2026-10-12) — Voice Live still lists it, but the Foundry retirement schedule marks `gpt-4o-mini` 2024-07-18 **Deprecated** (blocked for new customers) with retirement **2027-04-14** and no declared replacement. Standard-tier Voice Live successors: `gpt-5.6-luna` (GA, retires 2028-01-11), `gpt-5-mini` (GA, 2027-02-09), or the native-audio `gpt-realtime-2.1-mini` (GA, 2027-06-25). — *Needs a call: Microsoft names no replacement, and the candidates split between a cascaded text model (same Azure-TTS voice behaviour as today) and a native-audio one (which changes voice handling); no credential was available to probe either.*
- **`reasoning_effort` and `parallel_tool_calls` unreachable** (medium, since 2026-10-12) — both are top-level `RealtimeRequestSession` fields. `SessionProperties` keeps Pydantic's default `extra="ignore"`, so passing them validates and then serialises to nothing (verified locally: `SessionProperties(reasoning_effort="low", parallel_tool_calls=False).model_dump(exclude_none=True)` is `{}`). `reasoning_effort` matters now that Voice Live offers the GPT-5 family. — *Needs a call: a live session to confirm the fields are accepted, which needs a Foundry resource credential.*
- **Interim responses not configurable** (medium, since 2026-10-12) — Voice Live can speak filler while a tool runs or latency passes a threshold, via `interim-response` (`static-interim-response` or `llm-interim-response`) on the session. — *Needs a call: whether Pipecat should surface a provider-side filler mechanism, given pipelines usually handle this themselves.*
- **`end_of_utterance_detection` field mismatch** (medium, since 2026-10-12) — the API documents `threshold_level` (`low`/`medium`/`high`/`default`); `EndOfUtteranceDetection` exposes `threshold: float`, so the documented knob is unreachable and the float goes out under a name the schema does not list. — *Needs a call: whether `threshold` is still accepted, since renaming it breaks anyone setting it today.*
- **Foundry Agent Service sessions unsupported** (medium, since 2026-10-12) — an agent-backed session connects with `agent_id` and `project_id` instead of `model`, and rejects `instructions`, which the service always syncs into the session. — *Needs a call: this needs new constructor arguments and a branch in the session payload, so whether agent-backed Voice Live is in scope.*
- **Input sample rate forwarded unchecked** (medium, since 2026-10-12) — `_ensure_audio_config` sets `input_audio_sampling_rate` to the transport's rate; the docs list 16000 and 24000 as the supported PCM values, so an 8 kHz telephony transport configures an undocumented rate. The output path already clamps to 24 kHz with a warning; the input path does not. — *Needs a call: confirmation that Voice Live rejects rather than resamples 8000 Hz input before adding a resample-or-warn path.*
- **`avatar`, `animation`, `output_audio_timestamp_types`, `metadata` unreachable** (low, since 2026-10-12) — all dropped by `SessionProperties`. The first two also need their server events modelled; `parse_server_event` returns None for `response.video.delta`, `session.avatar.*`, `response.animation_viseme.*` and `response.audio_timestamp.*`. — *Needs a call: whether avatar video output belongs in this service or a separate processor, before the plain pass-through fields are worth adding alone.*
- **Image input not modelled** (low, since 2026-10-12) — `ItemContent.type` has no `input_image`, which the API documents with `image_url` and `detail`. — *Needs a call: whether a realtime service should accept vision frames, and which Voice Live models support them.*
