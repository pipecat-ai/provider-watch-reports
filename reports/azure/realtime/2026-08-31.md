# Azure Realtime — 2026-08-31

The class tracks Azure's GA v1 realtime surface; what is out of date is everything around it — the example bot and the `pipecat init` scaffold build the service without naming a deployment, and the scaffold's transcription config is silently discarded. No live probe was possible: the run environment's Azure resource no longer exists.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Deployment name never set** (high, since 2026-08-31) — `examples/realtime/realtime-azure.py` and the `azure_realtime` CLI scaffold construct `AzureRealtimeLLMService` with no `Settings(model=...)`, so the base class appends OpenAI's default `?model=gpt-realtime-2.1`. On Azure that query parameter names the user's *deployment*, so a fresh bot connects only if the deployment happens to carry that name. — *Needs a call: which env var names the deployment (the scaffold's env template emits only `AZURE_REALTIME_API_KEY` and `AZURE_REALTIME_BASE_URL`), and whether the service should refuse to connect when no deployment is named.*
- **Scaffold's transcription config is dropped** (medium, since 2026-08-31) — the `azure_realtime` scaffold emits `SessionProperties(input_audio_transcription=InputAudioTranscription(model="whisper-1"))`; that field is not on `SessionProperties`, pydantic ignores it (`model_dump(exclude_none=True)` → `{'type': 'realtime'}`), and generated bots get no user transcription. The accepted shape is `audio=AudioConfiguration(input=AudioInput(transcription=...))`. — *Needs a call: on Azure the transcription model is itself a deployment name, so fixing the shape still leaves `whisper-1` working only by coincidence.*
- **Reasoning stripped on Azure** (medium, since 2026-08-31) — `_strip_unsupported_reasoning` recognizes reasoning-capable models by substring on `Settings.model`, which on Azure is an opaque deployment name; a `gpt-realtime-2.1` deployment named anything else loses its `Reasoning(effort=...)` before `session.update`. — *Needs a call: whether Azure should skip the capability check entirely or gate it on something explicit.*
- **Transcription/translation sessions** (low, since 2026-08-31) — Azure ships `gpt-realtime-translate`, `gpt-realtime-whisper` and `gpt-live-transcribe` behind a translation flow (`/openai/v1/realtime/translations`) and `session.type = "transcription"`; neither is reachable from this class. — *Needs a call: these are arguably a separate realtime STT/translation service, not this LLM class.*
- **No API-reference page** (low, since 2026-08-31) — the unit's `docs_url` covers only `AzureLLMService`, and `s2s/azure` 404s, so nothing on docs.pipecat.ai tells users that `Settings.model` is the deployment name or that dated `api-version` URLs don't work. — *Needs a call: the docs site is a separate repo, so this needs an owner there.*

Not gaps, checked this run: Azure's retirement schedule lists `gpt-realtime-2.1` and `gpt-realtime-2.1-mini` (both preview, 2026-07-07), so the inherited default names a real Azure model — it is still the wrong thing to send, because the parameter is a deployment name; `gpt-realtime-2` (2026-05-06 preview) retires 2026-08-31 and `gpt-realtime-mini` 2025-10-06 on 2026-09-21, but Pipecat hard-codes neither for Azure; the Entra ID scope in the docstring (`https://ai.azure.com/.default`), the `api-key` header, the `/openai/v1/realtime` path and the preview-URL warning all match Azure's current guidance ("use the GA endpoint format with `/openai/v1` in the URL"); the `azure` extra pins only `azure-cognitiveservices-speech` (1.51.2 latest, inside `>=1.47.0,<2`), which the realtime path does not use.
