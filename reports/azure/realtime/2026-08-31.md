# Azure Realtime — 2026-08-31

The class itself tracks Azure's GA v1 realtime surface; what is out of date is everything around it — the example bot and the `pipecat init` scaffold still build the service without naming a deployment, so a fresh Azure realtime bot connects as `?model=gpt-realtime-2.1` and fails. No live probe was possible: the run environment's Azure resource no longer exists.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Deployment name never set** (high, since 2026-08-31) — `examples/realtime/realtime-azure.py` and the `azure_realtime` CLI scaffold construct `AzureRealtimeLLMService` with no `Settings(model=...)`, so the base class appends OpenAI's default `?model=gpt-realtime-2.1`. Azure has no such model (its newest is `gpt-realtime-2`, 2026-05-07) and the query parameter must name the user's deployment, as the 1.8 changelog for PR #5363 shows. — *Needs a call: which env var names the deployment (the scaffold's env template emits only `AZURE_REALTIME_API_KEY` and `AZURE_REALTIME_BASE_URL`), and whether the service should refuse to connect when no deployment is named.*
- **Scaffold's transcription config is dropped** (medium, since 2026-08-31) — the `azure_realtime` scaffold emits `SessionProperties(input_audio_transcription=InputAudioTranscription(model="whisper-1"))`; that field is gone from the GA event model, pydantic ignores it (`model_dump(exclude_none=True)` → `{'type': 'realtime'}`), and generated bots get no user transcription. The GA shape is `audio=AudioConfiguration(input=AudioInput(transcription=...))`. — *Needs a call: on Azure the transcription model is itself a deployment name, so fixing the shape still leaves `whisper-1` working only by coincidence.*
- **Reasoning stripped on Azure** (medium, since 2026-08-31) — `_strip_unsupported_reasoning` recognizes reasoning-capable models by substring on `Settings.model`, which on Azure is an opaque deployment name; a `gpt-realtime-2` deployment named anything else loses its `Reasoning(effort=...)` before `session.update`. — *Needs a call: whether Azure should skip the capability check entirely or gate it on something explicit.*
- **Transcription/translation sessions** (low, since 2026-08-31) — Azure ships `gpt-realtime-translate`, `gpt-realtime-whisper` and `gpt-live-transcribe` behind a translation flow (`/openai/v1/realtime/translations`) and `session.type = "transcription"`; neither is reachable from this class. — *Needs a call: these are arguably a separate realtime STT/translation service, not this LLM class.*

Not gaps, checked this run: the Entra ID scope in the docstring (`https://ai.azure.com/.default`) matches Azure's realtime WebSocket quickstart; the `api-key` header, the `/openai/v1/realtime` path and the preview-URL warning all match Azure's current guidance ("use the GA endpoint with `/openai/v1` in the URL. Don't use date-based API versions"); the `azure` extra pins only `azure-cognitiveservices-speech`, which the realtime path does not use (it speaks WebSocket directly).
