# Azure TTS — 2026-11-23

Nothing to do: both classes probe clean against `218a7f836`, no voice or SSML element Pipecat uses is retiring, and no change qualifies for a PR.

## What's new for Pipecat

- **A version-pinned HD base model, `DragonHDV3Neural`.** The HD voices page (updated 2026-11-17) now tells users to write `en-US-Ava:DragonHDV3Neural` "to access all features in the V3 model". It is absent from the voices list, but it is real: it synthesizes through `AzureTTSService` at 424 ms TTFB with 13 word boundaries, while the control `en-US-Ava:DragonHDV9Neural` is rejected with "Unsupported voice". Pipecat needs no change — `_voice_expression_adapter()` keys on `":DragonHD" in voice`, so a V3 voice already gets the HD expression adapter and its markers are consumed as markup rather than spoken.
- **The HD page was rewritten.** Dragon HD Omni is now described as 700+ voices with automatic style prediction, and the expressive style tags moved under the Dragon HD section with an `express-as` example on V3. The two per-family style tables still differ, which keeps the adapter item below open — and they differ in both directions now, since the Omni table dropped `whispering`.
- **Catalogue unchanged**: 1015 voices in `eastus` across 154 locales, the same family and status counts as 2026-11-09. `en-US-SaraNeural` is still GA; `en-GB-MiaNeural` is still the one `Deprecated` voice and appears nowhere in the repo.
- **SDK 1.53.1** (2026-11-15) fixes licensed speech *recognition* model loading only; no TTS change. The MAI voices page (2026-10-01) and the SSML voice markup page (2026-08-18) are the ones the last run read, and `<voice>` still takes `name`, `effect` and `parameters`, all three exposed by `AzureTTSSettings`.

### PRs
Nothing.

### To consider
- **No text frames on MAI voices** (medium, since 2026-08-31) — `AzureTTSService` derives its `TTSTextFrame`s from Azure word boundary events (`push_text_frames=False`); re-probed today with Pipecat's exact SSML, `en-US-Harper:MAI-Voice-2.1-Flash` returned 0 word boundaries against 13 for the default voice and 13 for both DragonHD base models, so bot transcripts and word-timed UI all but disappear for the MAI family while audio still plays. — *Needs a call: a "no word boundary arrived, push the sentence" fallback changes timing semantics for every voice, so it has to be either unconditional or keyed to the voice family.*
- **Custom voice deployments** (medium, since 2026-08-31) — `AzureSTTService` accepts `endpoint_id` and sets it on the `SpeechConfig`; the TTS classes offer only `private_endpoint`, so a fine-tuned (professional) voice deployment cannot be addressed. — *Needs a call: it is a constructor argument, not a runtime setting, so the shape is a maintainer's decision.*
- **SDK floor** (medium, since 2026-08-31) — `azure-cognitiveservices-speech>=1.47.0` allows versions without the 1.50 TTS connection-race fix, the 1.51 REST token-credential fix, the 1.48.2 CRL fix Microsoft required by 2026-07-01, the 1.51.2 SIGABRT-during-synthesis fix, and the compressed-audio TTS crash fixes in 1.52 and 1.53. Fresh installs resolve to 1.53.1, so only a pinned or stale lockfile is exposed. — *Needs a call: whether provider-watch may raise dependency floors (same item as azure/stt).*
- **Personal voice** (low, since 2026-08-31) — instant voice cloning is addressed with `<mstts:ttsembedding speakerProfileId='...'>` around the text, documented for every MAI model; the SSML builder has no element for it. — *Needs a call: the feature is behind Azure's Limited Access Review, so it is worth deciding whether Pipecat carries SSML most users cannot use.*
- **Token-level text streaming** (low, since 2026-08-31) — Azure's websocket v2 `TextStream` request type consumes LLM tokens directly instead of waiting for Pipecat's sentence aggregation. — *Needs a call: that path takes no SSML at all (voice name and output format only), so every setting this class exposes would be dropped on it.*
- **Sentence-boundary silence** (low, since 2026-08-31) — the 20 ms `<mstts:silence>` is hard-coded; Azure's other silence types and values are unreachable. — *Needs a call: 20 ms is a deliberate low-latency default, so exposing it means fixing what stays default and which types earn a field.*
- **Unlisted sample rates** (low, since 2026-08-31) — `sample_rate_to_output_format` quietly falls back to 24 kHz while frames carry the pipeline's rate, so a pipeline at, say, 32 kHz plays distorted audio rather than erroring. — *Needs a call: raise, resample, or keep the silent fallback.*
- **One adapter for two HD families** (low, since 2026-11-09) — `AzureHDExpressionAdapter` serves every non-Flash `:DragonHD*` voice, but six of its styles (`ecstatic`, `joking`, `proud`, `relieved`, `shocked`, `terrified`) sit only in the Omni table and `whispering` sits only in the DragonHD table. Markers are consumed as markup on every HD family — word boundary counts do not change — so the cost is a delivery that may silently do nothing. Last run's duration evidence does not reproduce: plain `DragonHDV3Neural` ran 3.33, 3.47 and 3.87 s across three calls, a spread wider than any marker's effect. — *Needs a call: splitting the adapter per family means a second capabilities list and a second class.*
- **MAI styles unreachable from expressive tags** (low, since 2026-11-23) — `get_expression_adapter()` has no adapter for the MAI family, so expression tags are stripped there, while Azure documents `mstts:express-as style` for every MAI voice. The static `style` setting does work (`style=happy` on `en-US-Harper:MAI-Voice-2.1-Flash` synthesized fine), but each voice has its own style list and an off-list value is fatal: `style=happiness`, the value in Azure's own MAI example, returned `Bad MAI Request ... invalid_request`. — *Needs a call: declare only the styles every MAI voice shares, or carry a per-voice table.*
