# Azure TTS — 2026-10-12

`en-US-SaraNeural` is GA and nothing is retiring, but the `effect` field that #5744 added is missing from both classes' `__init__` defaults, so every Azure TTS pipeline logs `AzureTTSSettings: the following fields are NOT_GIVEN: effect` at startup; the branch adds the two missing lines.

## What's new for Pipecat

PR #5744 merged on 2026-09-14, so `effect` is in the code and on the docs page — but only in the `Settings` dataclass. Both `__init__`s build their settings store field by field and never set `effect`, which violates the store-mode invariant `validate_complete()` checks in `AIService.start()`. The synthesized SSML is unaffected (`NOT_GIVEN` is falsy, so no `effect` attribute is emitted), so this is noise rather than breakage — but it is an ERROR line on every start for every user of either class, and it is the reason the previous run's own PR shows up as a new gap.

Azure's catalogue grew from 779 to 958 voices in `eastus`:

- **`MAI-Voice-2.1` and `MAI-Voice-2.1-Flash`** (89 preview voices each, 23 languages), documented 2026-09-30 and announced 2026-10-01. The docs page that used to describe MAI-Voice-2 now describes 2.1. They need no code change — `voice` is a free string and `en-US-Harper:MAI-Voice-2.1-Flash` synthesized through `AzureHttpTTSService` unchanged — but they emit no word boundaries, so they extend the existing MAI gap rather than closing it.
- The docs' expressive example for 2.1 uses `style="happiness"`, which Azure rejects (the voice table lists `happy`); `style=happy` through Pipecat's exact SSML synthesizes fine, so `style` works for the family as-is.
- `DragonHDOmniLatestNeural` went 15 → 16 voices and two more `DragonHDLatestNeural` voices went GA. `DragonLatestNeural` (12 preview voices) is still absent from every docs page.

The HD voices page (updated 2026-09-24) now documents expressive style tags and paralinguistics (`laughter`, `sighing`, …) for both HD families, usable either through `mstts:express-as` — which `style` already emits — or as inline `[excited]` tags in the text itself, which users can type today. No new code affordance there.

The catalogue's one `Deprecated` voice, `en-GB-MiaNeural`, still appears nowhere in `src/`, `examples/` or `tests/`.

### To consider
- **No text frames on MAI voices** (medium, since 2026-08-31) — `AzureTTSService` derives its `TTSTextFrame`s from Azure word boundary events (`push_text_frames=False`); re-probed today, `en-US-Harper:MAI-Voice-2.1-Flash` and `en-US-Harper:MAI-Voice-2.1` each returned 0 word boundaries against 10 for the default voice, so bot transcripts and word-timed UI disappear for the whole MAI family while audio still plays. The 2.1 family doubles the affected voice count and is the one Microsoft points at real-time voice agents. — *Needs a call: a "no word boundary arrived, push the sentence" fallback changes timing semantics for every voice, so it has to be either unconditional or keyed to the voice family.*
- **Custom voice deployments** (medium, since 2026-08-31) — `AzureSTTService` accepts `endpoint_id` and sets it on the `SpeechConfig`; the TTS classes offer only `private_endpoint`, so a fine-tuned (professional) voice deployment cannot be addressed. — *Needs a call: it is a constructor argument, not a runtime setting, so the shape is a maintainer's decision.*
- **SDK floor** (medium, since 2026-08-31) — `azure-cognitiveservices-speech>=1.47.0` allows versions without the 1.50 TTS connection-race fix, the 1.51 REST token-credential fix, the 1.48.2 CRL fix Microsoft required by 2026-07-01, the 1.51.2 SIGABRT-during-synthesis fix, and now 1.52's two compressed-audio TTS crash fixes. Fresh installs resolve to 1.52.0, so only a pinned or stale lockfile is exposed. — *Needs a call: whether provider-watch may raise dependency floors (same item as azure/stt).*
- **Personal voice** (low, since 2026-08-31) — instant voice cloning is addressed with `<mstts:ttsembedding speakerProfileId='...'>` around the text, now documented for every MAI model including 2.1; the SSML builder has no element for it. — *Needs a call: the feature is behind Azure's Limited Access Review, so it is worth deciding whether Pipecat carries SSML most users cannot use.*
- **Token-level text streaming** (low, since 2026-08-31) — Azure's websocket v2 `TextStream` request type consumes LLM tokens directly instead of waiting for Pipecat's sentence aggregation. — *Needs a call: that path takes no SSML at all (voice name and output format only), so every setting this class exposes would be dropped on it.*
- **Sentence-boundary silence** (low, since 2026-08-31) — the 20 ms `<mstts:silence>` is hard-coded; Azure's other silence types and values are unreachable. — *Needs a call: 20 ms is a deliberate low-latency default, so exposing it means fixing what stays default and which types earn a field.*
- **Unlisted sample rates** (low, since 2026-08-31) — `sample_rate_to_output_format` quietly falls back to 24 kHz while frames carry the pipeline's rate, so a pipeline at, say, 32 kHz plays distorted audio rather than erroring. — *Needs a call: raise, resample, or keep the silent fallback.*
