# Azure TTS — 2026-09-14

Both classes are current — `en-US-SaraNeural` is GA, no TTS retirement is scheduled — and the one new item is a branch: Azure's documented `<voice effect>` attribute (`eq_car`, `eq_telecomhp8k`) had no `Settings` field.

## What's new for Pipecat

PR #5522 merged on 2026-09-03, so `voice_parameters` is in the code and in the docs page; that gap is gone from this list.

Azure's published pages have not moved since last run (HD voices 2026-07-07, MAI 2026-07-23, SSML voice 2026-08-18, TTS release notes end at MAI-Voice-2-Flash in July 2026), but the live catalogue has: `eastus` is now 779 voices, up from 763.

- A new family, **`DragonLatestNeural`** (12 preview voices: `en-US-Andrew`, `en-US-Ava`, `de-DE-Seraphina`, `fr-FR-Denise`, `fr-FR-Remy`, `hi-IN-Diya`, `it-IT-Alessio`, `it-IT-Isabella`, `pt-BR-Francisca`, `pt-BR-Macerio`, `zh-CN-Xiaoqi`, `zh-CN-Yunfan`). It appears in no docs page — the only public mention ties `DragonLatestNeural` to personal-voice base models. Not a gap: `voice` is a free string, and `en-US-Ava:DragonLatestNeural` synthesized through `AzureHttpTTSService` unchanged and emitted word boundaries normally. Worth re-checking when Microsoft documents it.
- `DragonHDLatestNeural` grew from 69 to 73 voices and 11 of its preview voices went GA (now 55 GA + 18 Preview).

The catalogue's one `Deprecated` voice, `en-GB-MiaNeural`, still appears nowhere in `src/`, `examples/` or `tests/`.

### PRs
- https://github.com/pipecat-ai/pipecat/pull/5744 — Add an effect setting to the Azure TTS services

  Azure documents `effect` as an optional `<voice>` attribute alongside `parameters`: `eq_car` for enclosed vehicles and `eq_telecomhp8k` for narrowband telephony, the latter explicitly meant for 8 kHz output — the rate Pipecat's telephony transports run at. The change is one `Settings` field and two lines in `_construct_ssml`; unset, the emitted SSML is byte-identical to today's.

### To consider
- **No text frames on MAI voices** (medium, since 2026-08-31) — `AzureTTSService` derives its `TTSTextFrame`s from Azure word boundary events (`push_text_frames=False`); re-probed today, `en-US-Ethan:MAI-Voice-2-Flash` returned 0 word boundaries against 9 each for the default voice and the new `DragonLatestNeural` family, so bot transcripts and word-timed UI disappear for the whole MAI family while audio still plays. — *Needs a call: a "no word boundary arrived, push the sentence" fallback changes timing semantics for every voice, so it has to be either unconditional or keyed to the voice family.*
- **Custom voice deployments** (medium, since 2026-08-31) — `AzureSTTService` accepts `endpoint_id` and sets it on the `SpeechConfig`; the TTS classes offer only `private_endpoint`, so a fine-tuned (professional) voice deployment cannot be addressed. — *Needs a call: it is a constructor argument, not a runtime setting, so the shape is a maintainer's decision.*
- **SDK floor** (medium, since 2026-08-31) — `azure-cognitiveservices-speech>=1.47.0` allows versions without the 1.50 TTS connection-race fix, the 1.51 REST token-credential fix, the 1.48.2 CRL fix Microsoft required by 2026-07-01, and now the 1.51.2 fix for a SIGABRT crash *during speech synthesis*. Fresh installs resolve to 1.51.2, so only a pinned or stale lockfile is exposed — which is why this is raised from low this run rather than to high. — *Needs a call: whether provider-watch may raise dependency floors (same item as azure/stt).*
- **Personal voice** (low, since 2026-08-31) — instant voice cloning is addressed with `<mstts:ttsembedding speakerProfileId='...'>` around the text; the SSML builder has no element for it. — *Needs a call: the feature is behind Azure's Limited Access Review, so it is worth deciding whether Pipecat carries SSML most users cannot use.*
- **Token-level text streaming** (low, since 2026-08-31) — Azure's websocket v2 `TextStream` request type consumes LLM tokens directly instead of waiting for Pipecat's sentence aggregation. — *Needs a call: that path takes no SSML at all (voice name and output format only), so every setting this class exposes would be dropped on it.*
- **Sentence-boundary silence** (low, since 2026-08-31) — the 20 ms `<mstts:silence>` is hard-coded; Azure's other silence types and values are unreachable. — *Needs a call: 20 ms is a deliberate low-latency default, so exposing it means fixing what stays default and which types earn a field.*
- **Unlisted sample rates** (low, since 2026-08-31) — `sample_rate_to_output_format` quietly falls back to 24 kHz while frames carry the pipeline's rate, so a pipeline at, say, 32 kHz plays distorted audio rather than erroring. — *Needs a call: raise, resample, or keep the silent fallback.*
