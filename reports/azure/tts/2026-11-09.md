# Azure TTS — 2026-11-09

Nothing to do: last run's `effect` branch merged as #6126, both classes probe clean, and the provider shipped no retirement, no SSML change and no new `<voice>` attribute since 2026-10-12.

## What's new for Pipecat

- **#6126 merged** on 2026-10-12. Both `__init__`s now set `effect=None`, and today's probes start without the `NOT_GIVEN` settings error.
- **Expression tags on HD voices** landed outside provider-watch (`7cfdfb526`, 2026-10-28): `AzureHDExpressionAdapter` plus `_split_style_markers` in `AzureTTSService`, so HD style and paralinguistic markers are performed and reported as single bracketed words. That covers the expressive-tag affordance the 2026-10-12 report described as "no new code affordance"; what it leaves is the per-family style-list mismatch listed below.
- **Catalogue: 958 → 1015 voices in `eastus`**, all shuffling inside preview families. `DragonLatestNeural` jumped 12 → 63 preview voices and is still absent from every docs page; `DragonHDLatestNeural` lost 10 preview voices (73 → 63) while its 57 GA voices are untouched; both MAI 2.1 families went 89 → 97. No voice Pipecat names in `src/`, `examples/` or `tests/` disappeared, and `en-US-SaraNeural` is still GA. The one `Deprecated` voice, `en-GB-MiaNeural`, appears nowhere in the repo.
- **`en-US-Ava:DragonHDOmniLatestNeural`**, which `examples/expressive-conversation/expressive-conversation-azure.py` uses, is listed in the catalogue only as `en-us-ava:…`; the example's mixed case synthesizes fine, so voice names are matched case-insensitively.
- **SDK 1.53** (2026-10-21) adds another compressed-audio TTS crash fix and opt-in IPv6; nothing a pipeline has to call. The docs pages for HD voices (2026-09-24), MAI voices (2026-10-01) and SSML voice markup (2026-08-18) are byte-for-byte the ones the last run read.

### To consider
- **No text frames on MAI voices** (medium, since 2026-08-31) — `AzureTTSService` derives its `TTSTextFrame`s from Azure word boundary events (`push_text_frames=False`); re-probed today with Pipecat's exact SSML, `en-US-Harper:MAI-Voice-2.1-Flash` returned 0 word boundaries against 11 for the default voice and 11 for both HD families, so bot transcripts and word-timed UI disappear for the MAI family while audio still plays. — *Needs a call: a "no word boundary arrived, push the sentence" fallback changes timing semantics for every voice, so it has to be either unconditional or keyed to the voice family.*
- **Custom voice deployments** (medium, since 2026-08-31) — `AzureSTTService` accepts `endpoint_id` and sets it on the `SpeechConfig`; the TTS classes offer only `private_endpoint`, so a fine-tuned (professional) voice deployment cannot be addressed. — *Needs a call: it is a constructor argument, not a runtime setting, so the shape is a maintainer's decision.*
- **SDK floor** (medium, since 2026-08-31) — `azure-cognitiveservices-speech>=1.47.0` allows versions without the 1.50 TTS connection-race fix, the 1.51 REST token-credential fix, the 1.48.2 CRL fix Microsoft required by 2026-07-01, the 1.51.2 SIGABRT-during-synthesis fix, and the compressed-audio TTS crash fixes in 1.52 and 1.53. Fresh installs resolve to 1.53.0, so only a pinned or stale lockfile is exposed. — *Needs a call: whether provider-watch may raise dependency floors (same item as azure/stt).*
- **Personal voice** (low, since 2026-08-31) — instant voice cloning is addressed with `<mstts:ttsembedding speakerProfileId='...'>` around the text, documented for every MAI model; the SSML builder has no element for it. — *Needs a call: the feature is behind Azure's Limited Access Review, so it is worth deciding whether Pipecat carries SSML most users cannot use.*
- **Token-level text streaming** (low, since 2026-08-31) — Azure's websocket v2 `TextStream` request type consumes LLM tokens directly instead of waiting for Pipecat's sentence aggregation. — *Needs a call: that path takes no SSML at all (voice name and output format only), so every setting this class exposes would be dropped on it.*
- **Sentence-boundary silence** (low, since 2026-08-31) — the 20 ms `<mstts:silence>` is hard-coded; Azure's other silence types and values are unreachable. — *Needs a call: 20 ms is a deliberate low-latency default, so exposing it means fixing what stays default and which types earn a field.*
- **Unlisted sample rates** (low, since 2026-08-31) — `sample_rate_to_output_format` quietly falls back to 24 kHz while frames carry the pipeline's rate, so a pipeline at, say, 32 kHz plays distorted audio rather than erroring. — *Needs a call: raise, resample, or keep the silent fallback.*
- **Omni-only styles declared for DragonHD** (low, since 2026-11-09) — one `AzureHDExpressionAdapter` serves both HD families, and six of the styles it advertises (`ecstatic`, `joking`, `proud`, `relieved`, `shocked`, `terrified`) sit only in the Omni table on Azure's HD voices page. Probed on `en-US-Ava:DragonHDLatestNeural`, `[ecstatic]` is absorbed rather than spoken (2.80 s, identical to no marker), so the cost is a delivery that silently does nothing. — *Needs a call: splitting the adapter per family means a second capabilities list and a second class, for a style that is ignored rather than broken.*
