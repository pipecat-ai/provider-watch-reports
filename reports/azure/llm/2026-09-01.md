# Azure LLM — 2026-09-01

No change: `AzureLLMService` answers on the live resource, nothing in the code or examples names a retiring model, and the same three items are open — all needing a maintainer rather than a branch.

## What's new for Pipecat

### PRs

Nothing.

### To consider

- **Default model is "Legacy" on Azure** (medium, since 2026-08-31) — Azure's retirement schedule (page date still 2026-08-26) lists `gpt-4.1` (2025-04-14) as **Legacy**, retiring 2027-04-14, Replacement column empty. aiewf-eval's `aiwf_medium_context` leaderboard is unchanged — `gpt-5.1` 98.0% / 739 ms, `gpt-5.6-terra` (medium) 97.8% / 927 ms, `gpt-5.5` (none) 97.4% / 875 ms, `gpt-5.6-sol` 96.6% / 1098 ms against `gpt-4.1` 96.3% / 536 ms — so every quality-parity candidate is still well past the 10% TTFAT allowance and none qualifies for an automatic bump. Azure treats the `model` string as a deployment name, so the default only helps users who name deployments after models. — *Needs a call: which GA tier, whether the slower first token is acceptable, and that `openai/llm` and `openai/responses-llm` share this default; the test resource has no gpt-5.x deployment, so the latency comparison cannot be run on Azure.*
- **No Azure Responses API path** (medium, since 2026-08-31) — Azure's v1 API guidance recommends the Responses API for Azure OpenAI models. `OpenAIResponsesHttpLLMService` already works against Azure when `base_url` is the resource's `/openai/v1/` endpoint (probed live on 2026-08-31: TTFAT 1157 ms against 1860 ms for `AzureLLMService`'s chat completions on the same deployment). What is missing is an Azure entry point: no Entra ID token-provider path, and the WebSocket Responses class hardcodes `wss://api.openai.com/v1/responses`. — *Needs a call: an Azure Responses subclass plus docs, or documentation pointing Azure users at `base_url`.*
- **Azure-only request fields reachable only via `extra`** (low, since 2026-08-31) — `data_sources` (On Your Data) and `user_security_context` (Defender for Cloud) are Azure extensions to the chat-completions body with no named `Settings` field. `extra` is merged into the request verbatim in `base_llm`, so they are reachable; not probed, because `data_sources` needs a provisioned AI Search index. — *Needs a call: whether `extra` stays the documented answer for Azure-only fields.*
