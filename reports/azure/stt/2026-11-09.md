# Azure STT — 2026-11-09

Post-stream refinement reached GA in both monolingual and multilingual modes in October; the monolingual pass-through probes clean and no slower than today's behavior, so there is a branch for it. Nothing is retiring.

## What's new for Pipecat

### PRs
- https://github.com/pipecat-ai/pipecat/pull/6667 — Add post_processing_option to AzureSTTService settings

### To consider
- **Streaming model selection** (medium, since 2026-08-31) — `speech_config.model = "mai-transcribe-2-streaming"` selects Azure's new low-latency streaming model. The probe environment has moved to SDK 1.53.0, so the attribute now exists locally, but the model is still public preview and served from four regions only, none of which is this account's — so it remains unprobed. `AzureSTTSettings` inherits a `model` field that the class silently drops. — *Needs a call: the `azure` extra still allows 1.47, below the 1.52 that introduced `SpeechConfig.model`, so wiring the field means raising the floor or guarding on the attribute, and shipping a preview path we cannot verify is a product decision.*
- **Explicit audio-boundary commit** (medium, since 2026-10-12) — Azure documents `PushAudioInputStream.commit()` (preview, enabled with `setfeature=forcecommit`) for turn-based voice agents: commit after the user's last audio and the matching `recognized` event carries the `commit_token`, instead of waiting out the segmentation silence timeout. Python has had `commit()` since 1.52 and the format limits are all satisfied here. — *Needs a call: it is not a pass-through field — the service has to observe turn-stop to call `commit()` — and it carries the same SDK floor question.*
- **Semantic segmentation** (medium, since 2026-08-31) — `Speech_SegmentationStrategy="Semantic"` ends phrases at sentence-ending punctuation instead of on silence; mechanically one more `set_property`, and the confidence-score/NBest loss Azure warns about is free here because the class reads only `result.text`. — *Needs a call: Azure scopes Semantic to dictation and captioning rather than interactive agents, and it is locale-limited, so it needs a stance plus a latency measurement on agent-length turns.*
- **Automatic language detection** (medium, since 2026-08-31) — the recognizer is always constructed with one locale; Azure's open-range `AutoDetectSourceLanguageConfig` would let a session switch language per utterance, and `_on_handle_recognized` already reads `result.language`. It is also what unlocks multilingual post-stream refinement, GA since October. — *Needs a call: it takes a second recognizer construction path and a decision on what `Settings.language` means once detection is on.*
- **Phrase lists** (medium, since 2026-08-31) — `PhraseListGrammar` biasing for names and domain terms has no route into the service; Azure allows 2,000 phrases generally and 200 phrases / 3,200 characters on the multilingual refinement path, with `set_weight` in 0.0–2.0. — *Needs a call: it attaches to the recognizer rather than the config, so someone has to decide where re-application on reconnect lives.*
- **SDK floor** (low, since 2026-08-31) — the `azure` extra allows 1.47.0, below both the 1.48.2 Microsoft required for Linux/Android CRL checking by 2026-07-01 and the 1.52.0 the model selector and commit boundary need. Fresh resolves land on 1.53.0, so only installs pinned to old versions are exposed. — *Needs a call: whether provider-watch may raise dependency floors.*
- **`en-Latn-IN` locale** (low, since 2026-11-09) — October's romanized-Indic real-time model is selected by the `en-Latn-IN` locale, which `Language` does not carry; a raw string in `Settings(language=...)` reaches Azure today, so only the typed path is missing. — *Needs a call: `Language` is shared by every service, so adding a member is a cross-service decision.*

## Verification

| setting                              | class           | ok | latency                                 | note |
| ------------------------------------ | --------------- | -- | --------------------------------------- | ---- |
| (default, no post-processing option) | AzureSTTService | ✅ | TTFB 2229 ms (median of 3, 2214–2251)   | baseline on `24761a4c6`; 13 interim frames |
| `post_processing_option=PostRefinement` | AzureSTTService | ✅ | TTFB 2096 ms (median of 3, 2095–2261) | from the branch; final transcript differed from baseline on the ambiguous brand word, 6 interim frames |
| `post_processing_option=TrueText`    | AzureSTTService | ✅ | TTFB 2272 ms                            | from the branch; single run, transcript identical to baseline |

STT `ttfb_ms` here is speech end → finalized transcript, and tracks the bundled clip more than the service, so read the three rows against each other rather than as absolute numbers: refinement is not slower than the default path. Azure's claim that interim results keep streaming held, though the refinement run produced about half as many of them. `mai-transcribe-2-streaming` could not be probed: it serves from four regions and this account's region is not one.
