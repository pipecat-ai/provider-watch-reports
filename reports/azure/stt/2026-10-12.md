# Azure STT — 2026-10-12

Nothing is broken or retiring, but Speech SDK 1.52 reopened two things this class could use — a streaming model selector and a turn-boundary commit — and both wait on the SDK floor question.

## What's new for Pipecat

### PRs
Nothing.

### To consider
- **Streaming model selection** (medium, since 2026-08-31) — SDK 1.52 added `speech_config.model`, and `mai-transcribe-2-streaming` is the first model behind it: public preview, four serving regions, multilingual auto-detection over 60 languages, no detected language / confidence / word timestamps in streaming results. `AzureSTTSettings` inherits a `model` field that this class silently drops, so the plumbing gap is now visible to users. — *Needs a call: `SpeechConfig.model` does not exist below 1.52 (the probe environment runs 1.51.2), so wiring it means raising the `azure` floor or guarding on the attribute, and shipping a preview model path is a product decision.*
- **Explicit audio-boundary commit** (medium, since 2026-10-12) — Azure documents `PushAudioInputStream.commit()` (SDK 1.52, preview, enabled with `setfeature=forcecommit`) specifically for turn-based voice agents: commit after the user's last audio and the matching `recognized` event carries the `commit_token`, instead of waiting out the segmentation silence timeout. The format limits (PCM/A-law/mu-law/G.711, no Microsoft Audio Stack) are all satisfied here. — *Needs a call: it is not a pass-through field — the service has to observe turn-stop to call `commit()` — and it carries the same 1.52 floor question.*
- **Semantic segmentation** (medium, since 2026-08-31) — `Speech_SegmentationStrategy="Semantic"` ends phrases at sentence-ending punctuation instead of on silence; mechanically one more `set_property` next to the merged `segmentation_silence_timeout_ms`, the SDK 1.41 floor is met, and the confidence-score/NBest loss Azure warns about is free here because the class reads only `result.text`. — *Needs a call: Azure scopes Semantic to dictation and captioning and says it is not for interactive scenarios — which is what Pipecat is — and it is locale-limited, so it needs a stance plus a latency measurement on agent-length turns.*
- **Automatic language detection** (medium, since 2026-08-31) — the recognizer is always constructed with one locale; Azure's open-range `AutoDetectSourceLanguageConfig` (25 languages) would let a session switch language per utterance, and `_on_handle_recognized` already reads `result.language`. — *Needs a call: it takes a second recognizer construction path and a decision on what `Settings.language` means once detection is on.*
- **Phrase lists** (medium, since 2026-08-31) — `PhraseListGrammar` biasing for names and domain terms has no route into the service; Azure documents it for real-time transcription with a 2,000-phrase cap and a `set_weight` range of 0.0–2.0. — *Needs a call: it attaches to the recognizer rather than the config, so someone has to decide where re-application on reconnect lives.*
- **Post-stream refinement** (low, since 2026-08-31) — `SpeechServiceResponse_PostProcessingOption=PostRefinement` is GA for monolingual sessions across 29 locales and advertised as latency-neutral. — *Needs a call: Azure says short phrases often come back unchanged, so measure it on agent-length turns before exposing it.*
- **SDK floor** (low, since 2026-08-31) — the `azure` extra allows 1.47.0, below both the 1.48.2 Microsoft required for Linux/Android CRL checking by 2026-07-01 and the 1.52.0 the two new features need. Fresh resolves land on 1.52.0, so only installs pinned to old versions are exposed. — *Needs a call: whether provider-watch may raise dependency floors.*
